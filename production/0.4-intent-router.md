## 核心产品决策

**呈现权与触发正交**：命中后插件如何占用返回区，和「query 算不算命中」是两个独立维度。

| surface | 含义 |
|---|---|
| `inline` | 混排，按 score 排序 |
| `priority` | 置顶（score 抬高），但保留其他引擎结果 |
| `takeover` | 独占，跳过本地引擎 |
| `auto`（默认） | 无参 → priority / 带参 → takeover |

`auto` 默认规避了短词 keyword（如 `note`）误屏蔽搜索结果的问题。

**向后兼容**：旧 manifest `exclusive: true` → `Auto`；`false` → `Inline`。

## 后续做什么

### 0.4.x — Context 层（环境感知，优先做）

MVP §13.7 定义的 Context 层是 Blink 从「启动器」跃迁到「统一操作层」的核心一跃。0.4.x 聚焦**唤起时快照**，不做持续监控：

| 维度 | 采集方式 | 优先级 | 用途 |
|---|---|---|---|
| **前台应用** | `GetForegroundWindow` + 进程名/窗口标题 | P0 | route 判定（如 IDE 在前台时提升「打开终端」权重） |
| **剪贴板文本** | `GetClipboardData`（CF_UNICODETEXT） | P1 | 唤起时快照，空 query 下推荐「粘贴/搜索剪贴板内容」 |
| **选中文本** | UI Automation / `GetGUIThreadInfo` 辅助 | P2 | 浏览器/编辑器中选中内容 → 唤起时自动带入 query |
| **系统状态** | 时间、网络连通性 | P2 | 插件上下文增强（如离线时不建议查天气） |

**设计约束**
- **低频采集 + 唤起快照**：不持续监控，只在唤起瞬间取一次快照，兼顾性能与隐私
- **敏感内容不落盘**：剪贴板/选中文本仅驻留内存，不入 SQLite
- **按权限下发**：未来插件按 `permissions` 声明订阅 context 字段（当前自用阶段不强制）
- **Proactive Suggestion 雏形**：空 query 时按 context 产出 Top-N 建议（如剪贴板是 URL → 「用浏览器打开」）

### 更远期

| 阶段 | 方向 |
|---|---|
| **0.5+** | 文件搜索（FileEngine）+ 更多 builtin 动作（见 `0.5-search-builtin.md`） |
