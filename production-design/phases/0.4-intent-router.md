### 0.4.2 Context 层（环境感知）

MVP §13.7 定义的 Context 层：唤起瞬间采集系统环境快照。

| 模块 | 内容 |
|---|---|
| `src/context/mod.rs` | `ContextSnapshot` + `ForegroundAppInfo` 数据结构 |
| `src/context/windows.rs` | Windows 平台实现：前台应用（进程名/窗口标题/exe路径） + 剪贴板文本采集 |
| `src/search/service.rs` | 快照存储：`Arc<RwLock<ContextSnapshot>>`，写仅唤起时一次，读可并行 |
| `src/plugin/protocol.rs` | `PluginQueryContext` 扩展：`foreground_app`/`window_title`/`clipboard_text` |
| `src/window/windows.rs` | 采集时机：`window::invoke()` 中在 `show()` 之前采集 |

**核心设计决策**：
- 先采集再 show → 确保拿到 Blink 唤起前的前台应用
- 只读剪贴板（OpenClipboard + GetClipboardData），不修改系统剪贴板
- 敏感内容仅驻留内存，不入 SQLite
- 失败静默降级：字段返回 None，不中断主流程

### 0.4.3 BuiltinEngine（内置动作引擎）

纯 Rust 实现，无需插件进程，响应最快。

| 模块 | 内容 |
|---|---|
| `src/search/builtin_engine.rs` | `BuiltinEngine` 实现 `SearchEngine` trait，走 sync lane |

| `launch_app` 扩展 | 识别 `__BLINK_ACTION_XXX__` 特殊路径，执行对应动作而非打开文件 |

**已实现内置动作**：
- 🖥️ 打开设置 / sz
- 🔒 锁定电脑 / 锁屏 / sd
- ⏻️ 关机 / gj
- 🔄 重启 / cq
- 😴 睡眠 / sm
- 🗑️ 清空搜索历史

## 核心产品决策

**呈现权与触发正交**：命中后插件如何占用返回区，和「query 算不算命中」是两个独立维度。

| surface | 含义 |
|---|---|
| `inline` | 混排，按 score 排序 |
| `priority` | 置顶（score 抬高），但保留其他引擎结果 |
| `takeover` | 独占，跳过本地引擎 |
| `auto`（默认） | 无参 → priority / 带参 → takeover |

`auto` 默认规避了短词 keyword（如 `note`）误屏蔽搜索结果的问题。

**向后兼容**：旧 manifest `exclusive: true` → `Auto`；`false` → `Inline`。

## 没做什么

| 项 | 归属 | 理由 |
|---|---|---|
| manifest `surface` 字段升级 | 推迟 | 0.x 不发布，不做产品化基础设施（CLAUDE.md §7 已记） |
| `Intent` 语义枚举 | P3 | 0.4 只需「呈现调度」`Route`，语义分类等 VectorRouter 有消费者再做 |
| VectorRouter / AIRouter | P3 | zvec SDK 极新，AI Provider 接口待建 |
| 空 query 历史 top-N | 跳过 | 产品角度非必要 |
| 热重载 / 流式 / attachments | 更远 | 非 0.4 主题 |
| 上下文感知路由 | 0.4.x | RuleRouter 尚未使用 snapshot，纯 keyword 匹配 |
| Context 层选中文本采集 | 0.6 | UI Automation 复杂度高，优先级较低 |
