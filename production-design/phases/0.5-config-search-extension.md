# Blink 0.5 — 配置架构 + 文件搜索 + 扩展系统

> **范围**: 统一配置持久化架构（核心+引擎+插件+Context）+ FileEngine（Everything + 本地扫描兜底）+ 扩展 Tab UI 联调。
> **关系**: 承接 0.2「配置化优先」原则，服务于 0.3 插件系统、0.4 意图引擎、P3 Context/AI。
> **技术栈**: Rust 2024 + Tauri 2.x + WebView2。
>
> **设计修订（20260625 评审）**: 原 §2.4 `PluginConfig` 含 `triggers`/`surface` 字段，与 0.4 已落地的 `RuleRouter`+`Surface` 模型（`intent.rs`）冲突——trigger 双源合并未定义、surface 概念重复、且 `RuleRouter` 无热更新 API（0.2 §3.7 B5 的 `remove/clear` 未实现）。本修订**砍掉 `triggers`/`surface`**（trigger 继续由 manifest 单一来源），`PluginConfig` 收敛为 `{enabled, settings}`；并**新增 settings 透传协议**（§2.4 子节，原设计完全漏了「存了却送不到插件进程」）。详见各节修订标注。

## 一、0.5 总体目标

### 1.1 要解决的核心问题（来自产品）

| 问题 | 0.5 方案 |
|------|----------|

| 设置页结构散乱 | 6 Tab 统一布局：通用/快捷键/扩展/上下文/存储/调试 |

### 1.2 0.5 三层交付物

| 层级 | 内容 |
|------|------|
| **数据层** | SQLite `config` 表分层 KV 架构 + 自动迁移 |

| **UI 层** | 扩展 Tab 联调（文件搜索 + 插件卡片） + 上下文 Tab |

## 二、配置持久化架构

### 2.1 表结构：单表 KV（保留现有，零迁移成本）

```sql
CREATE TABLE IF NOT EXISTS config (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,          -- JSON / plain string
    updated_at INTEGER NOT NULL   -- unix timestamp ms
);
```

| key 命名空间 | 说明 | value 格式 | 示例 |
|--------------|------|-----------|------|
| `app_config` | 核心应用配置（**100% 保留 0.4 结构，向后兼容**） | JSON | `{"hotkey": {...}, "tap_threshold": 300}` |
| `engine:{id}` | 内置引擎独立配置 | JSON | `engine:file_search`, `engine:builtin` |
| `plugin:{id}` | 单个插件独立配置（id = manifest.id） | JSON | `plugin:builtin.ip`, `plugin:builtin.echo` |
| `context:{key}` | Context 层配置 | JSON / string | `context:blacklist`, `context:clipboard_enabled` |

**为什么不分表？**: 0.x 不过度工程，单表足够支撑到产品化；多表迁移复杂，新增类型要改 schema。

### 2.4 PluginConfig：插件独立配置

> **20260625 评审修订**：原设计含 `triggers`/`surface` 字段，与 0.4 已落地的 `RuleRouter`+`Surface` 模型（`intent.rs`）冲突——trigger 双源合并未定义、surface 概念重复、且 `RuleRouter` 无热更新 API（0.2 §3.7 B5 的 `remove/clear` 未实现）。修订后**只保留 `enabled` + `settings`**；trigger/surface 继续由 manifest 单一来源驱动（`main.rs:137-172` 启动时注入 `RuleRouter`）。trigger 自定义、per-plugin surface override 推迟到有第三方插件/冲突解决需求时（0.6+）。

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct PluginConfig {
    pub enabled: bool,
    #[serde(default)]
    pub settings: serde_json::Value,   // 插件自定义 JSON blob（manifest 声明 schema，core 只存不解释）
}
```

**IP 插件示例**:
```json
{
  "enabled": true,
  "settings": {
    "cache_ttl_seconds": 300,
    "use_ipv6": false,
    "geo_provider": "ip-api.com"
  }
}
```

- `enabled=false`：`PluginEngine::query_subset` 跳过该插件（不查询）；`main.rs` 注入 `RuleRouter` 规则时也跳过（不响应其 keyword）。trigger 来源不变，仍读 `manifest.triggers`，与 `enabled` 正交。

#### settings 透传协议（settings 如何送达插件进程）

> **原设计空白**：0.5 初版只设计「存」`settings`，完全没设计「怎么送到插件进程」。这是「插件可配置」能力闭环的关键一环，本节补齐。

用户改的 `PluginConfig.settings` 存 SQLite 后，需送达插件进程参与查询决策。两条路：

| 方案 | 做法 | 取舍 |
|---|---|---|
| init 握手 | 进程启动后 core 先推 `{type:"config",settings}`，就绪态再收 query | 只传一次；但改 settings 要重推或重启进程；引入「启动→config→ready→query」时序，增首次 query 延迟 |
| **query 内联（采用）** | `PluginRequest::Query` 加 `settings: Option<Value>`，每次查询携带 | 零时序、天然热更新；settings 极小重复传可接受 |

**采用 query 内联**：① 不引入握手就绪态，与现有懒启动流程（`process.rs` query 来了才拉起）一致；② settings 热更新零成本（用户改完下次 query 自动最新，无需重推/重启）；③ 插件走 async lane，不在首批 <20ms 热路径；④ 向后兼容（老插件 serde 忽略未知字段）。

```rust
// src/plugin/protocol.rs —— PluginRequest::Query 加 settings 字段
pub enum PluginRequest {
    Query {
        id: String,
        query: String,
        #[serde(default)]
        context: PluginQueryContext,
        #[serde(default, skip_serializing_if = "Option::is_none")]
        settings: Option<serde_json::Value>,  // ← 0.5.1 新增：该插件的 PluginConfig.settings
    },
    Cancel { id: String },
}
```

- **core 侧**：`PluginEngine::query_subset` 按 `plugin_id` 取该插件 `settings` 注入请求（无配置传 `None`）。
- **插件侧**：从 `query.settings` 读配置（ip 取 `use_ipv6`/`cache_ttl`/`geo_provider`）；老插件忽略该字段无影响。
- **语义正交**：`query`=文本、`context`=环境（前台/剪贴板）、`settings`=配置，三者平级，**不混入 context**。
- **数据流**：`update_plugin_config`(DB) → `PluginEngine` 内存 config map 更新 enabled → 下次 `query_subset` 读最新 settings 注入。settings 无需主动同步内存（每次现读），enabled 需内存跳过判定。

### 2.6 插件配置 schema（settings_schema，驱动设置页 UI）

> 插件在 manifest 声明每个配置项的元数据(`settings_schema`),设置页据此**自动渲染表单控件**——而非让用户手写裸 JSON。VSCode `contributes.configuration` / Raycast preferences 的同款机制,让插件配置对普通用户可用。0.5.1 已落地。

**manifest 声明示例**(ip 插件):
```jsonc
"settings_schema": [
  { "key": "use_ipv6", "type": "boolean", "title": "查询 IPv6 地址",
    "description": "额外显示本机 IPv6 出口（需 IPv6 环境）", "default": false },
  { "key": "geo_provider", "type": "enum", "title": "定位服务", "default": "ip-api.com",
    "options": [{"value":"ip-api.com","label":"ip-api.com（推荐）"},{"value":"none","label":"不查询定位"}] }
]
```

**type → 控件映射**(最小集,覆盖 90% 场景):

| `type` | 前端控件 | 备注 |
|---|---|---|
| `boolean` | toggle 开关 | 开/关二态 |
| `string` | 文本输入框 | API key、路径等 |
| `number` | 数字输入(`min`/`max` 可选) | 数值类 |
| `enum` | 下拉选择(`options` 带 `label`) | 枚举值 |

复杂控件(color/file/app-picker)按需后加,0.x 不提前造。

**i18n 预留(关键设计)**:`title`/`description`/`options[].label` 类型为 `LocalizableText`——serde `#[serde(untagged)]`,**同一字段既接受纯字符串也接受多语言对象**:
```jsonc
"title": "查询 IPv6"                          // 现状:Plain
"title": {"zh":"查询 IPv6","en":"Query IPv6"} // 未来 i18n:Localized
```
**Rust 类型与前端渲染均无需改动**,未来加语言只升级 manifest 数据(零 breaking change)。当前 `resolve()` 对 Localized 取 `zh` 回退首个可用。

**与配置层的关系**:
- `default_settings()` 从 schema 的 `default` 生成默认 settings JSON(`init_configs` 用,替代原先 null)。
- `list_plugins` 返回 resolve 后的 schema(title/description/label 转字符串)供前端渲染。
- 无 `settings_schema` 的插件(echo)→ 前端显示「该插件无可配置项」(降级)。
- `PluginConfig.settings` 的存储/透传机制不变(schema 只是渲染层 + 默认值来源)。

## 三、配置热生效机制

### 3.1 可热生效（不重启）

| 配置项 | 热生效方式 | 完成状态 |
|--------|-----------|----------|
| `log_level` | tracing reload handle | ✅ 0.4 已实现 |
| `file_search.*` | FileEngine 内部 ArcSwap | 待实现 |
| `plugin:* enabled` | query_subset 跳过 + 启动时规则不注入 RuleRouter | ✅ 0.5.1 |
| `plugin:* settings` | 每次 query 注入请求字段（§2.4 透传协议），天然热更新 | ✅ 0.5.1 |

> **已知限制（enabled 热生效）**:`enabled` 关闭对查询即时生效(`query_subset` 跳过),但 **RuleRouter 规则启动时一次性注入、运行时不动态移除**(无 remove API,见 0.2 §3.7 B5)。故**运行时**禁用的插件,其 keyword 仍被路由命中 → Takeover 分支查询返回空 → 该次输入窗口短暂空白。彻底解决需 RuleRouter 支持规则增删(0.6+)。**启动时**已禁用的插件不受影响(规则压根不注入)。
| `context_*` | ContextService 内部开关 | 待实现 |
| `surface_takeover_enabled` | IntentService 内部开关 | 待实现 |
| `tap_threshold` / `grace_period` | HotkeyService 内存值更新 | 待实现 |

### 3.2 不可热生效（需提示重启）

| 配置项 | 原因 |
|--------|------|
| `hotkey` | 全局 hook 重新注册有瞬时冲突风险（可做，0.5 暂不做） |
| `auto_start` | 注册表操作本身立即生效，但当前状态要下次启动验证 |

## 六、迁移策略（0.4 → 0.5 平滑升级）

### 6.1 自动迁移步骤（启动时执行）

```rust
async fn migrate_config_0_4_to_0_5(pool: &SqlitePool) {
    // 1. 读旧 app_config
    let old_config = get_config(pool).await;

    // 2. 迁移 file_search 到 engine:file_search（如果不存在）
    if get_config(pool, "engine:file_search").await.is_none() {
        let file_search_json = serde_json::to_string(&old_config.file_search).unwrap();
        set_config(pool, "engine:file_search", &file_search_json).await;
        tracing::info!("迁移 file_search 到 engine:file_search");
    }

    // 3. 为每个已发现的插件写默认配置（如果不存在）
    //    plugin_id = manifest.id（如 builtin.ip）；trigger 不写入 config，
    //    继续由 manifest 单一来源提供（RuleRouter 直接读 manifest.triggers）。
    for (plugin_id, manifest) in discover_plugins() {
        let key = format!("plugin:{}", plugin_id);
        if get_config(pool, &key).await.is_none() {
            let default_config = PluginConfig {
                enabled: true,
                settings: manifest.default_settings.clone().unwrap_or_default(),
            };
            set_config(pool, &key, &serde_json::to_string(&default_config).unwrap()).await;
            tracing::info!("初始化插件配置: {}", plugin_id);
        }
    }

    // 4. app_config 新增字段由 serde default 自动补全
}
```

### 6.2 兼容层设计（避免 breaking change）

```rust
// 0.5 兼容层，0.6 移除 deprecated 字段
pub async fn get_file_search_config(pool: &SqlitePool) -> FileSearchConfig {
    // 1. 优先读新 key

        if let Ok(cfg) = serde_json::from_str(&json) {
            return cfg;
        }
    }
    // 2. 降级读旧 app_config.file_search
    let app_config = get_config(pool).await;
    app_config.file_search
}
```

## 七、FileEngine 文件搜索实现

### 7.1 三层回退架构

| 层 | 实现 | 状态 |
|----|------|------|
| **Everything HTTP** | HTTP GET `http://localhost:{port}/?search={query}&json=1` | ✅ 已完成，待联调 |
| **Windows Search COM** | ISearchQueryHelper + ADO/OLE DB | ⏸️ 跳过，0.5 不做（复杂度高收益低） |
| **本地目录扫描** | StartMenuEngine 范式：后台预扫 + 内存 fuzzy | 📋 0.5.1 做 |

### 7.2 Everything 集成要点

- **探测时机**: 启动时后台异步探测 + 用户手动探测按钮
- **结果解析**: Everything 返回 JSON 格式，`results` 数组含 `name` / `type` / `path`
- **路径拼接**: `path` 字段是目录，`name` 是文件名，完整路径 = `path + name`（注意 Windows 反斜杠）
- **状态反馈**: 扩展 Tab 显示「可用/不可用/探测中」三色 badge

### 7.3 本地目录扫描（0.5.1）

复刻 StartMenuEngine 范式：
```
启动时后台预扫 Desktop / Documents / Downloads
└→ 深度 3 层，node_modules / .git 等自动跳过
└→ 结果存内存 fuzzy 索引
└→ 定时刷新 + 根目录 mtime 失效
```

## 九、右键上下文菜单（0.5.3）

> 完整产品设计见 `product-interaction.md` §3.4。本节记录 0.5 落地范围与实现要点。

**背景**:主窗口右键现为 WebView2/Edge 原生浏览器菜单(刷新/另存为/打印/检查/表情符号等),
与「快捷入口」定位割裂。0.5.3 抑制原生菜单,提供产品化自定义右键,按区域 + 结果类型
给差异化动作。

### 9.1 落地范围

| 项 | 本期 | 说明 |
|---|---|---|
| 抑制 WebView2 原生菜单 | ✅ | 前端 `contextmenu` preventDefault + 自定义 DOM 菜单 |
| 分区域菜单(输入框/空白/结果项) | ✅ | 输入框=粘贴剪切复制全选;空白=打开设置/刷新索引/退出 |
| 结果项按 source 动态动作 | ✅ | file / app / calc / plugin |
| 重置该项记录 | ✅ | history 表清零/删除(复用现有表) |
| 优先级置底 | ⏸️ 0.5.x | 需降权/黑名单新表,非简单清历史(详见 product-interaction.md §3.4.4) |
| 「原生菜单」展开入口 | ❌ | 抑制后无 API 唤起,全自定义已覆盖 |

### 9.2 结果项动作清单（按 source）

| source | 动作 |
|---|---|
| **file** | 打开 / 打开所在文件夹 / 复制路径 / 复制文件名 / 重置该项记录 |
| **app** | 打开 / 打开所在文件夹 / 复制路径 / 以管理员运行 / 重置该项记录 |
| **calc** | 复制结果 / 复制完整表达式 |
| **plugin** | manifest 声明的 actions 透传(复用 0.4 surface 模型) |

### 9.3 实现要点

- **类型识别**:后端 `SearchItem.source` 已有,前端 `<li>` 需新增 `dataset.source` 透传
  (现 `results.js` 的 `createItem` 未存该字段)。
- **菜单分发**:复用 `actions.js` 的 `activateItem`;新增动作(打开所在文件夹 / 重置记录)
  走独立 command。
- **打开所在文件夹**:`explorer.exe /select,<path>`;注意 §5 约束——lnk_path 不可归一化改写,
  透传原路径字符串。
- **重置记录**:history 表 `hit_count` 清零或删除该行(新增 history 方法,不影响其他项权重)。

### 9.4 后端命令需求

- `open_containing_folder(path)`:explorer /select 定位(新增)。
- `reset_item_history(lnk_path)`:history 清零/删除(新增)。
- 复制路径/文件名:前端 `navigator.clipboard`,不经后端。

## 十、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 配置 JSON 结构变更解析失败 | 配置丢失 | 所有字段 `#[serde(default)]` + 解析失败回退默认值 + warn 日志 |
| 多 Tab 同时保存读写冲突 | 配置丢失 | 命令串行执行 + SQLite 事务 |
| Everything HTTP 端口改了不生效 | UX 问题 | 改完端口后引擎自动重新探测，状态实时刷新 |
| 插件配置与 manifest 不一致 | 插件行为异常 | manifest 字段加 default，不认识的字段忽略 |
