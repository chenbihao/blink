# Blink 0.5 — 配置架构 + 文件搜索 + 扩展系统

> **范围**: 统一配置持久化架构（核心+引擎+插件+Context）+ FileEngine（Everything）+ 扩展系统联调。
> **关系**: 承接 0.2「配置化优先」原则，服务于 0.3 插件系统、0.4 意图引擎、P3 Context/AI。
> **技术栈**: Rust 2024 + Tauri 2.x + WebView2。
> **状态**: 0.5.0~0.5.3 已全部完成。§13 评分重构为后续待办。

---

## 一、0.5 总体目标

### 1.1 要解决的核心问题（来自产品）

| 问题 | 0.5 方案 |
|------|----------|
| 单 JSON blob 全量读写，性能差易冲突 | 分层 KV：`app_config` / `engine:{id}` / `plugin:{id}` |
| 插件无用户可配置能力 | 每个插件独立配置卡片（enabled + settings_schema 自动表单） |
| FileSearch 硬编码端口，无法配置 | 引擎配置 + 状态探测 UI |
| Context 层无开关/黑名单 | 新增「上下文」Tab，细粒度控制 |
| 设置页结构散乱 | 6 Tab 统一布局：通用/快捷键/扩展/上下文/存储/调试 |

### 1.2 0.5 三层交付物 ✅

| 层级 | 内容 | 状态 |
|------|------|------|
| **数据层** | SQLite `config` 表分层 KV 架构 + 自动迁移 | ✅ 0.5.0~0.5.1 |
| **业务层** | EngineConfig / PluginConfig / ContextConfig 统一 API | ✅ 0.5.0~0.5.2 |
| **UI 层** | 扩展 Tab（文件搜索 + 插件卡片） + 上下文 Tab + 右键菜单 | ✅ 0.5.0~0.5.3 |

## 二、配置持久化架构

### 2.1 表结构：单表 KV（保留现有，零迁移成本）

```sql
CREATE TABLE IF NOT EXISTS config (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,          -- JSON / plain string
    updated_at INTEGER NOT NULL   -- unix timestamp ms
);
```

| key 命名空间 | 说明 | value 格式 | 示例 |
|--------------|------|-----------|------|
| `app_config` | 核心应用配置（**100% 保留 0.4 结构，向后兼容**） | JSON | `{"hotkey": {...}, "tap_threshold": 300}` |
| `engine:{id}` | 内置引擎独立配置 | JSON | `engine:file_search`, `engine:builtin` |
| `plugin:{id}` | 单个插件独立配置（id = manifest.id） | JSON | `plugin:builtin.ip`, `plugin:builtin.echo` |
| `context:{key}` | Context 层配置 | JSON / string | `context:blacklist`, `context:clipboard_enabled` |

**为什么不分表？**: 0.x 不过度工程，单表足够支撑到产品化；多表迁移复杂，新增类型要改 schema。

### 2.2 AppConfig 核心配置（0.5 新增字段）

```rust
pub struct AppConfig {
    // ── 0.4 已有字段，100% 保留 ──
    pub hotkey: HotkeyConfig,
    pub tap_threshold: u64,
    pub grace_period: u64,
    pub auto_start: bool,
    pub language: String,
    pub log_level: String,
    pub surface_takeover_enabled: bool,

    // ⚠️ 兼容层：保留但标记 deprecated，0.6 移除
    #[serde(default)]
    pub file_search: FileSearchConfig,

    // ── 0.5 新增字段 ──
    #[serde(default = "default_theme")]
    pub theme: String,                     // "auto" / "light" / "dark"

    #[serde(default = "default_true")]
    pub search_history_enabled: bool,      // 是否记录搜索历史

    #[serde(default = "default_30")]
    pub search_history_days: u32,          // 历史保留天数，默认 30

    #[serde(default = "default_20")]
    pub max_results: u32,                  // 最多显示结果数，默认 20

    #[serde(default = "default_false")]
    pub proactive_enabled: bool,           // 主动建议（空 query 历史 top-N）

    #[serde(default = "default_5")]
    pub empty_query_topn: u32,             // 空 query 显示历史常用数，默认 5
}
```

### 2.3 EngineConfig：内置引擎独立配置

每个引擎（FileSearch / Builtin / Calc）自包含配置，core 只负责存/取 JSON blob。

#### FileSearchEngine 配置
```json
{
  "enabled": true,
  "provider": "everything",           // everything / local（Windows Search 暂不实现）
  "everything_port": 80,
  "local_paths": ["Desktop", "Documents", "Downloads"],
  "local_depth": 3,
  "result_limit": 20
}
```

#### BuiltinEngine 配置
```json
{
  "enabled": true,
  "enabled_actions": [
    "open_settings", "lock", "shutdown", "restart", "sleep",
    "clear_history", "exit_blink", "open_logs", "open_data_dir"
  ]
}
```

#### CalcEngine 配置
```json
{
  "enabled": true,
  "copy_on_enter": true,              // 回车自动复制结果
  "precision": 10,                    // 计算精度（小数位数）
  "angle_unit": "radian"              // radian / degree（sin/cos 用）
}
```

### 2.4 PluginConfig：插件独立配置 ✅

> **已完成 0.5.1**。原设计含 `triggers`/`surface` 字段，评审后砍掉——trigger 继续由 manifest 单一来源驱动，`PluginConfig` 收敛为 `{enabled, settings}`。采用 **query 内联** 透传 settings（`PluginRequest::Query` 携带），零时序、天然热更新。

```rust
pub struct PluginConfig {
    pub enabled: bool,
    pub settings: serde_json::Value,  // manifest 声明 schema，core 只存不解释
}
```

- `enabled=false` → `SearchService.filter_route` 跳过（Takeover 降级 Mixed，Mixed 候选剔除）
- settings 每次 query 按 `plugin_id` 注入请求，改完即时生效无需重启

### 2.5 ContextConfig：环境感知配置 ✅

> **已完成 0.5.2**。`context:config` 存 SQLite，含 `enabled`/`clipboard_enabled`/`sensitive_apps` 等字段。设置页「上下文」Tab 已联调。

### 2.6 插件配置 schema（settings_schema） ✅

> **已完成 0.5.1**。manifest 声明 `settings_schema`（`key`/`type`/`title`/`description`/`default`），设置页自动渲染表单控件（boolean→toggle, string→输入框, number→数字, enum→下拉）。`title`/`description` 类型为 `LocalizableText`（接受纯字符串或 `{zh,en}` 对象），i18n 零 breaking change。`default_settings()` 从 schema 自动生成默认 settings JSON。

## 十、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 配置 JSON 结构变更解析失败 | 配置丢失 | 所有字段 `#[serde(default)]` + 解析失败回退默认值 + warn 日志 |
| 多 Tab 同时保存读写冲突 | 配置丢失 | 命令串行执行 + SQLite 事务 |
| Everything HTTP 端口改了不生效 | UX 问题 | 改完端口后引擎自动重新探测，状态实时刷新 |
| 插件配置与 manifest 不一致 | 插件行为异常 | manifest 字段加 default，不认识的字段忽略 |

## 十二、插件查询快速失败 + 输入节流 ✅

> **已完成 0.5.1**。三层防护：① 前端 IME 感知（`compositionstart/end`，组字中不派发）；② manifest `min_arg_length` 快速失败（参数太短直接返回空）；④ `timeout_ms` 收敛（weather 5000→2500）。③ 插件自查暂缓（① 拦中间态后非必要）。

## 十三、搜索评分重构

> **承接 0.4 Phase 4.4「搜索排序优化」**。

### 13.1 已完成 ✅

**P0 统一历史加权**：`fuzzy_score_entries` 去掉内联的 `ln(hit+1)*100`，改为归一化后调用 `scorer::apply_history`（与 Builtin/Calc/File/Plugin 共用同一公式 `ln(hit+1)*0.3`，上限 0.8）。所有引擎共享同一个历史加权旋钮。

**P1 增强 source boost**：`bake_source_boost` 系数从 0.01 提升到 0.2（calc +0.8, builtin +0.6, start_menu +0.4, file +0.2），来源优先级在排序中有足够区分度。

**P2 前后端排序统一**：前端 `appendNew` 去掉冗余的 `sourceRank` + epsilon 比较，只按 `score` 降序排序（source 优先级已由后端 bake 进 score）。
