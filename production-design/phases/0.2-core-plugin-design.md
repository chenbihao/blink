# Blink 0.2 — 核心与插件架构设计

> **定位**:核心服务化 + 多路搜索 + 插件系统的架构蓝图

---

## 设计决策

### 1. 核心服务化

| 决策 | 选择 | 理由 |
|---|---|---|
| 服务模型 | `Service` trait + `AppContext` | 统一生命周期（start/stop），显式依赖，不是 actor 模型 |
| 通信方式 | 请求-响应 `async` + 通知 `broadcast` | 不引入全局 Event Bus，避免过度设计 |
| async trait | 用 `async-trait` crate | 2024 原生 `async fn in trait` 对象安全受限，复杂度收益不对等 |
| 全局状态 | 收敛到单一 `HotkeyRuntime` | Win32 hook 回调必须访问，不再四散 |

---

### 2. 多路搜索

| 决策 | 选择 | 理由 |
|---|---|---|
| 搜索引擎 | `SearchEngine` trait，每引擎独立缓存 | 引擎职责单一，缓存归引擎内部，`SearchService` 只做路由+融合 |
| 渐进式 | sync/async 双 lane，内建设计 | sync lane 本地引擎，async lane 插件/慢引擎，首批 < 20ms |
| 取消机制 | `seq` 序号校验 + `cancel` 消息传播 | 用户已输入下一个 query 时旧结果丢弃 |

---

### 3. 插件系统

| 决策 | 选择 | 理由 |
|---|---|---|
| 进程模型 | 独立进程，stdio JSONL 协议 | 语言无关，懒启动，崩溃隔离 |
| 通信协议 | newline-delimited JSON | 99% 是文本，可 `cat jq` 调试 |
| 路由独占 | `exclusive` 默认 true | keyword 是明确意图信号，独占更简单 |
| 权限模型 | **自用阶段不实现** | 产品化时补声明式+确认 |
| builtin 插件 | 随 app 打包，默认 enabled | 与第三方走同一协议，无特权代码路径 |

## 关键架构约束

1. **Service 只是模块 + 生命周期**，不是 actor，不跑独立调度器
2. **缓存是引擎内部能力**，`SearchService` 不持有缓存
3. **渐进式是内建设计**，不是接插件时打的补丁
4. **plugin 权限自用阶段跳过**，产品化时补
