## 一、插件系统骨架(设计 §3 第一切片)

### 已完成 ✅

端到端跑通一条插件链路:core 拉起独立插件进程 → JSONL stdio 协议往返 → `PluginEngine` 接入 async lane(渐进式增量) → 前端 merge。输入 `echo <text>` 触发 builtin echo 插件,结果增量追加到搜索列表。

**模块(`src/plugin/`)**

| 文件 | 职责 |
|---|---|
| `manifest.rs` | JSON manifest 解析(`schema_version`/`id`/`runtime.{exec,timeout_ms}`/`triggers`/`capabilities`);exec 相对 manifest 目录解析;schema_version 兼容校验(超 `SUPPORTED` 拒载);permissions **不解析**(自用阶段,§3.6) |
| `protocol.rs` | JSONL 协议 struct:`PluginRequest{Query,Cancel}` / `PluginResponse{id,items,error}` / `PluginItem{title,subtitle,score,action}` / `PluginAction{Copy,Open}`(tagged enum);本切片实现 `query→response` 单行 + core→插件 `cancel`(best-effort),流式/attachments 未实现 |
| `process.rs` | `PluginProcess`(tokio 子进程 + stdin/stdout/stderr 三路并发 reader + pending oneshot 按 id 路由)+ `PluginHandle`(懒启动 + 常驻复用,崩溃重启);`kill_on_drop`;Windows `CREATE_NO_WINDOW` 防控制台弹窗;超时 `tokio::time::timeout` + `send_cancel` |
| `engine.rs` | `PluginEngine`(实现 `SearchEngine`,lane=Async,id="plugin"):keyword 精确/前缀匹配(复用 `search::to_pinyin_initials` 支持中文首拼)→ 命中插件 query → 结果转 `SearchItem` |
| `mod.rs` | `load_builtin_plugins` 扫 `plugins/builtin/*/manifest.json`;debug 指向仓库内目录,release 指向资源目录 |

**示例插件(`plugins/examples/echo/`)** — workspace member,Rust exe,阻塞式 stdio(读一行 JSON 请求 → 写一行 JSON 响应)。回显输入,验证协议。`windows_subsystem=windows` 防闪黑窗。

**builtin manifest(`plugins/builtin/echo/manifest.json`)** — `exec` 开发期指向 `../../../target/debug/blink-plugin-echo.exe`;timeout 2s;trigger `keyword:"echo"`。

**接入点**
- `src/main.rs`:`build_engines(&app)` 构造引擎列表,加 PluginEngine。
- `src/search/service.rs`:PluginEngine 进 async lane,完成后 `emit("blink://results",{seq,items})`。

### 关键设计决策(本切片拍板)

1. **插件动作透传前端**:`SearchAction`/`AppEntry.Action` 带 payload(text 等),前端 `actions.js` 优先读 payload → 插件能真正「复制结果/打开 URL/执行自定义动作」(echo 示例已验证 Copy 复制)。
2. **keyword 不独占**:命中只决定「是否查该插件」,sync lane 照常出应用/计算,插件结果随 async lane 追加。独占语义留给 **RuleRouter**(§4.3),不侵入 SearchService 抽象。
3. **`SearchItem.source` 改 `String`**:插件 id 是运行时 String(`&'static str` 容纳不了),顺势统一所有引擎。
4. **进程懒启动 + 常驻复用 + 并发查询**:`PluginProcess` 用 `Mutex<Child>`(使 `is_alive` 可 `&self`),`query` 不持 process 锁到底 → 多 in-flight query 并发。
5. **查询超时 cancel**:超时后 best-effort `send_cancel`(200ms,插件可忽略)+ 删 pending,避免孤儿响应堆积。

### 已知问题 / 后续优化点

- **Query 并发**:已修(`Mutex<Child>`),但单插件内查询仍受 stdin/stdout 单管道约束(同插件串行写 stdin),跨插件天然并发。
- **超时孤儿**:超时后 `send_cancel`(200ms best-effort)+ 删 pending;插件不响应则其响应自然变孤儿丢弃。
- **dev 环境 watchdog 误隐藏**:`cargo run` 带 PowerShell 终端,焦点切到终端时 watchdog 正确隐藏(release 无终端,不发生)。看门狗已按 PID 判定(同进程窗口不算"别人")。

## 二、热键触发判定重构(根治 Alt+Space 残留误触发)

### 背景:旧方案的病

旧触发状态机维护一份「累积按键镜像」(`pressed_modifiers`/`pressed_keys` 靠 down 事件 push、up 事件 retain 移除),被系统注入的合成事件打乱后**无法自愈**。已有的 `SYNTHETIC_EVENT_THRESHOLD`、`merge_physical_modifiers`、AltGr `lctrl` 移除都是「打地鼠」补丁。

**实测确诊 bug**:快捷键设为 `Alt+空格`(Windows 系统保留组合),系统注入额外 `lalt` 事件 → 状态机残留 `lalt` → 之后单按空格也匹配 `lalt+空格` → 误触发 toggle。

### 新方案:物理态查询(第一性原理)

Windows 已维护权威的键物理态(`GetAsyncKeyState`)。**不在应用层再累积镜像**,只在主键 down/up 边界现查修饰键物理态。状态机仅 3 字段(`down_since`/`armed_key`/`aborted`),不依赖任何需要 down/up 配对的累积量。

**判定流程**
1. 主键 keydown + 修饰键此刻物理态精确满足(`GetAsyncKeyState` 现查)→ `armed`
2. armed 后任何异键 down → `aborted`(判 hold)
3. 主键 keyup + 未 aborted + 时长达标(tap ≤ threshold)→ 触发 Tap
4. 修饰键**只在 arm 时查、keyup 不复查**(避免快速松手时修饰键略早释放导致漏触发)

**精确 bitmask 匹配**(`modifiers_mask_satisfies_config`):配置修饰键「消耗」物理按下的位,最后要求无剩余位 → `Ctrl+Alt+空格` 不会误触发 `Alt+空格`。通用名(`alt`)= 左右任一侧(但不允许多余)。

**AltGr 修正**(`apply_altgr_correction`):`RAlt+LCtrl` 同按时视 LCtrl 为合成、从 mask 去掉(代价:真实 `LCtrl+RAlt+key` 无法触发,极少见)。

**删除**:7 字段镜像、`SYNTHETIC_EVENT_THRESHOLD`、`merge_physical_modifiers`、`is_hotkey_match`、`normalize_modifier(_generic)`。

**测试**:8 个纯函数单测(mask 映射 / 精确匹配边界 / AltGr 修正 / standalone 判定),含「`Ctrl+Alt+空格` 不匹配 `Alt+空格`」核心安全断言。`cargo test` 41 全过。

**范围**:只动 `src/hotkey/windows.rs`。`recorder.rs` / `mod.rs` / `config.rs` 零改动(录制是独立路径)。

## 三、穿插修的其它 bug(插件测试中暴露)

- **前端 merge 在本地无结果时误 bail**(`results.js`):`!allItems.length` 守卫导致纯插件结果(本地无匹配)永不显示。
- **render/merge seq 竞态**:`render([])` 和 `emit` 增量到达顺序不定 → 插件结果被空 render 冲掉。改为同 seq 内无论谁先到都合并、新 seq 才重置。
- **watchdog `fg=NULL` 误隐藏**:焦点真空(子进程拉起等瞬态)不该判失焦,跳过本轮。
- **快速按组合键漏触发**:keyup 复查修饰键过严,去掉。
- **白闪优化**:结果刷新时 DOM 节点按 key 复用(`liCache`),图标 img 不重建。
