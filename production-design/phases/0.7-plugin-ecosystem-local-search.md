## 二、本地搜索 Fallback（0.7.1）

**策略**：Everything HTTP → 本地目录遍历（walkdir）

**配置项**：
```toml
[engine:file_search]
fallback_enabled = true
fallback_dirs = ["Desktop", "Documents", "Downloads", "StartMenu"]
fallback_max_depth = 3
fallback_cache_ttl_sec = 300
fallback_max_results = 50
```

**实现要点**：spawn_blocking 包装 walkdir、内存缓存 5 分钟、nucleo 模糊匹配、source="file_local" 标识。

## 五、图标缓存持久化（0.7.4）

**两层架构**：
1. 内存 LRU（200 条）→ 命中即返回
2. SQLite BLOB → 命中读入内存返回
3. 未命中 → 提取图标 → 写入两层缓存

**失效策略**：mtime 变化失效、超 2000 条淘汰最旧 500 条、30 天未访问自动清理

## 六、搜索缓存增量 + 权重衰减（0.7.5）

### 历史权重时间衰减

**公式**：`bonus = ln(hit_count + 1) * 0.3 * e^(-λ * days_since_last_use)`

半衰期 14 天（λ = ln(2)/14），上限 0.8。

### 搜索缓存增量更新

**策略**：
- mtime 无变化 → 直接用缓存
- mtime 有变化 → 增量扫描（仅增删变化项）
- 连续 10 次增量 → 强制全量扫描兜底
- 每 2 小时 → 后台静默全量刷新

## 八、插件 HTTP 代理协议（0.7.6 新增）

**问题**：ip/weather 等网络插件各自编译 ureq + TLS stack，每个 1.4MB（echo 才 177KB），且企业环境无法共享全局代理配置。

**解决方案**：插件不直接联网，通过 core 统一代理 HTTP 请求。

### 协议扩展

**上行（插件→core）**：新增 `http_request` 消息类型
```json
{
  "type": "http_request",
  "id": "http_123",
  "method": "GET",
  "url": "https://api.open-meteo.com/...",
  "timeout_ms": 10000
}
```

**下行（core→插件）**：新增 `http_response` 消息类型
```json
{
  "type": "http_response",
  "id": "http_123",
  "status": 200,
  "body": "{...}",
  "error": null
}
```

### 插件侧数据流

1. 收到 `query` → 立即发起 `http_request`
2. stdin listener 收到 `http_response` → 解析并回 `response`
3. 异步多阶段：weather 先 geocoding（城市→坐标）再 weather（坐标→天气）

### 体积优化效果

| 插件 | 优化前（独立 ureq） | 优化后（core 代理） | 减少 |
|------|---------------------|---------------------|------|
| echo | 177KB | 177KB | - |
| ip | 1.4MB | **217KB** | **-85%** |
| weather | 1.4MB | **234KB** | **-83%** |

### 额外收益

- **代理统一**：core 的全局代理配置自动生效，插件零感知
- **网络管控**：企业环境可审计/限流所有 outbound 请求
- **证书信任**：复用系统证书链，无自建 CA 兼容问题
- **连接复用**：所有插件共享 reqwest Client 的连接池
