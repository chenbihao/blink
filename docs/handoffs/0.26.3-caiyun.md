## 3. 官方依据与必须核验的事实

2026-10-15 已通过 Context7 和官方页面核对以下内容。实施时读完整原文，字段、账号权限和示例有差异时记录证据，不混用 v2.5/v2.6/v3。

- **认证**：v2.6 App Key 在路径，App Secret 用于 HMAC；请求携带 `x-cy-nonce`、`x-cy-timestamp`、`x-cy-signature`。nonce 每次唯一且满足长度要求；query 排序并编码后参与签名。官方示例的 URL-safe Base64 保留 `=`，不能凭经验改成 NO_PAD。[认证文档](https://docs.caiyunapp.com/weather-api/v2/v2.6/auth.html)
- **综合接口**：`https://api.caiyunapp.com/v2.6/{app_key}/{longitude},{latitude}/weather`；请求经度在前，响应 location 数组纬度在前。本版只消费 realtime/daily；明确请求 dailysteps=7，但天数可能被套餐截短。hourlysteps 文档范围从 1 起，不擅自传 0 关闭小时数据；不启用 alert 或解析额外产品能力。[综合接口](https://docs.caiyunapp.com/weather-api/v2/v2.6/6-weather.html)
- **坐标**：v2.x 大陆请求 GCJ-02，大陆以外（含港澳台）使用 WGS84；原始 WGS84 大陆坐标需要派生转换。[坐标规则](https://docs.caiyunapp.com/weather-api/q.html)
- **逐日**：temperature/wind/precipitation/skycon 分字段数组，按 date 关联；skycon 是主导现象，不能解释为 WMO 最严重天气或全天持续。day/night 是单独时段。[逐日接口](https://docs.caiyunapp.com/weather-api/v2/v2.6/4-daily.html)、[天气现象](https://docs.caiyunapp.com/weather-api/v2/v2.6/tables/skycon.html)
- **单位**：选择并明确发送支持的单位制，按该版本规范归一。尤其检查 metric 各版本的风速/概率含义，不能照另一家或旧示例习惯转换。本次单位表抓取超时，实施 agent 必须补读原文并以样本/真实响应核验。[单位表](https://docs.caiyunapp.com/weather-api/v2/v2.6/tables/unit.html)
- **错误**：400 可包含凭据/签名/版本问题，401 权限，403 禁用/IP 白名单，422 参数；429 同时可能是额度耗尽或 QPS 限制。可能返回非 JSON 网关错误，不能只看 status 字符串。不能把所有 429 当瞬时限流、所有 400 当城市参数错。[错误信息](https://docs.caiyunapp.com/weather-api/v2/v2.6/tables/errors.html)
- **费用/权限**：当前公开计费页将具体套餐/价格引向控制台。真实免费额度、有效期、7 天与接口权限须记录账号核验结果，不沿用历史价格单承诺固定次数。[计费](https://docs.caiyunapp.com/weather-api/billing.html)

缺真实账号时继续完成纯逻辑与 mock/fixture 验证，明确留下账号待验；不以示例 Token 访问服务、不要求用户购买套餐才能继续编码、不把受限数据补成 7 天。

## 4. 小阶段 A — 配置、签名与 HTTP 边界

1. 增加 `default_provider=caiyun`，缺省仍为 open_meteo，存量设置不改。增加平铺 `caiyun_app_key`、`caiyun_app_secret`，两者按凭据处理，声明 secret:true，复用 CM/掩码/清除。不能将 App Key 因“Key 名称”视为普通公开配置。
2. 复用现有配置事务：同序 CAS 在 CM 修改之前；两字段一起更新失败可恢复；清其中一个推进 revision，下一调用明确未配置，不使用一新一旧快照。空框=未修改、明确清除=删除，保存不丢 default_location 或其他供应商设置。
3. 签名为独立可测纯函数：调用方注入 nonce/秒级 timestamp；生产层每次生成新的安全随机 nonce，时钟/随机来源可测试。不用毫秒时间戳或时间戳本身充当随机 nonce，不重复使用样本值。
4. canonical query 与实际 URL query 只生成一次，按官方规则排序、编码；路径（包含 App Key 和最终请求坐标）同样只构造一次。方法/路径/query/Key/nonce/timestamp 都以实际发送值签名，不能签 WGS84 坐标却发送转换坐标、签完再被 URL builder 二次编码。
5. 用官方固定输入做 golden test；官方示例预期签名是 `KfHsk3z2XfX6Yxox4Uf_VgyM0wHk6bWEyRqZ9QOJUYw=`。从认证文档提取输入，补无 query、顺序变化、中文/空格/加号/百分号/保留字符、padding 测试；不能用被测函数自己生成期望值。
6. 依赖仅加必要的 Rust HMAC/SHA256/Base64/随机来源，先查 workspace 已有依赖与版本，复用后定向验证；不在前端签名，不引入 SDK/新 crate 框架。
7. 宿主 `is_sensitive_header` 当前只识别 Authorization/X-QW-Api-Key/Proxy-Authorization，**尚未覆盖 x-cy-*，不能假设和风重定向保护自动覆盖彩云**。带彩云签名的请求应拒绝改变已签名 URL 的重定向（包括同 Host 改路径/query），不能把路径 App Key 或认证头交给其他目的地，也不在 HTTP 层自动重新签名。
8. URL 固定为官方 HTTPS 服务，不增加可编辑彩云 Host；Key 按允许格式/安全路径段处理，不允许斜杠、查询等注入路径。stdout 只发协议，stderr/宿主错误/结果/测试报告不出现 App Key/Secret、签名串、认证头或完整敏感 URL。

**节点产出**：配置保存/清除与回滚回归、官方签名向量和编码测试、实际 HTTP 重定向拒绝测试、脱敏检查。纯签名通过不等于真实鉴权已通过。

## 5. 小阶段 B — 坐标适配与信息不足闭环

1. 坐标适配独立于名称搜索和 DTO。以 ResolvedLocation 的原值为准，返回派生请求坐标及坐标系；换源、重复查询、响应回读都不覆盖原始 default_location，不累积转换误差。
2. 大陆 WGS84 → GCJ-02，非大陆 WGS84 → 原值直传，已经明确支持的 GCJ-02 输入不得再转换。需要转换时核验算法/来源/适用范围与基准点，测试数值容差；不能直接把 WGS84 标成 gcj02。
3. **区域判断不能用粗矩形当精确国界**：矩形会覆盖邻国及港澳台，也不能仅凭中文名、Asia/Shanghai、系统语言、IP、country 文本或来源 ID 判断。采用有依据的行政元信息/明确用户声明；信息不足或边界不确定要拒绝猜测并提供可操作的补充入口。
4. 当前解析/保存/工具 schema 只支持 WGS84，且外部 location 元数据视为未验证输入；和风候选国家码也可能为空。必须说明区域证据来源和可信程度，不能为绕过校验伪造 country_code。
5. 推荐最小实现继续保存 WGS84 原始地点，给信息不足的地点提供“大陆/大陆以外”的明确确认，提示与该地点绑定，显式 location 调用也能携带相应声明；不要设全局“所有坐标都是大陆”开关。字段名称/存储位置由实施时小设计确定，保存与执行验证、schema、前端收集/清除和地点更换时的提示失效必须同步。其他可达方案也可，但要在报告说明，不能只报错而没有修正入口。
6. 若决定开放 gcj02 输入，先交代它在 Open-Meteo/和风切换时的兼容策略，再同步宿主/插件/schema/UI/测试；不能只改彩云端接受值，把其他来源传错坐标。完整 GIS 库、地图 SDK 或反向地理网络调用不是本版默认前置。
7. 有限/范围/具名经纬度校验保持；测试零值、负值、极值、广州/北京转换基准、港澳台/海外原样、邻国/边界不确定、手工缺信息、重复调用不变、请求与响应数组顺序不同。响应 location 只作诊断，不据此偷偷移动已保存地点。

**节点产出**：坐标纯函数与区域决策测试、手工地点的可修正流程、跨来源保持原值。错误用既有 invalid_arguments 等明确说明；没有城市候选时不能伪造 needs_location 候选或天气。

## 6. 小阶段 C — 综合天气 DTO 与服务接入

1. 新增 `providers/caiyun.rs`；同一调用冻结 provider、settings_revision、两项凭据、原始/派生位置与单位，签名后发一个综合 weather 请求，纳入现有逻辑查询/子请求表及剩余预算。
2. 保持默认坐标直查、city 走现有 resolver、歧义不自动选首项。彩云未配置不影响其他来源；没有和风凭据时仍能使用 Open-Meteo 地点路径。彩云错误不静默切换供应商。
3. 检查 HTTP、顶层 status/API 版本、realtime/daily 子块 status 与可用内容；顶层 ok 不保证两块完整。非 JSON/空体/异常数值明确分类。HTTP/网关错误走既有安全文案，不原样透出可能回显路径凭据的 error。
4. realtime 温度/风速/skycon、daily 温度/风最大值/概率/主导现象转换到统一模型。按声明单位归一为 Celsius、km/h、百分比；缺失保留空，不补 0/晴，也不将超范围概率无声截成合法值。
5. daily 以可验证当地日期为键关联各数组，处理乱序、不等长、字段缺失、重复/非法日期与无时区日期；不能 zip 同下标、不以电脑当地日期解释海外数据。server_time 是服务时间，不能直接冒充观测时间；保留时间语义与来源。
6. skycon 字符串使用彩云命名空间与描述映射，未知代码显示未知并保留原值；不转换成 WMO/和风代码。日级主导 skycon 需要相应模型/展示语义，不能硬塞成“白天”，也不能把其他供应商的 `day_night_split` 套给彩云全日值。最小兼容扩展即可，不重做通用富卡片。
7. 完整实况+实际 7 天满足要求才 ok；仅实况、仅预报、字段不全或不足 7 天按统一契约返回 partial、实际天数/缺失原因。两块均无有效数据返回错误。未经明确证据，少于 7 天只能说明不足，不断言一定是套餐；确认权限限制后才说明相应原因。
8. 综合响应可能附带 minutely/hourly/AQI/forecast_keypoint，本版不扩成新能力，也不把分钟降雨提示当逐日天气说明。请求参数尽量精简、合法，不为了未交付能力增加计费调用。
9. 400/401/403/422/429 与响应有限白名单原因映射到 authentication_failed/provider_not_configured/invalid_arguments/quota_exceeded/rate_limited 等既有分类；未知错误保守反馈，不从任意文本猜类型。当前 HTTP JSONL 未传响应头，不能虚构 Retry-After；若为精确分类新增可选元信息，应有兼容测试，不无故扩成全局重试框架。
10. 取消/超时/重复或迟到响应只释放所属查询，最多回复一次；签名/解析失败也释放槽位。多个来源不互相取消，不延长总 deadline，不自动重试计费请求。不要把未来缓存当成本阶段可靠性补丁。

**节点产出**：完整/部分/缺失/错误样本、单位/日期/skycon 测试、状态机和取消/超时回归，真实插件二进制构建通过。

主 phase 只更新 0.26.3 的准确状态和实施记录，§6.4 真实账号项未经实测不勾选；不自动勾掉前序人工待验，不进入 0.26.4、不自动 commit/push/发布。最终保留 diff 交回原 agent，报告须包含：

1. HEAD/文件列表、五个阶段产出及与其他 agent 改动的边界。
2. 实际配置/schema/坐标提示与模型/raw 变化；默认 `{}`、显式地点/单位的无凭据调用示例。
3. 官方签名向量、编码/padding、坐标证据/基准点/原值不变、单位/日期/部分结果测试与相关回归结果。
4. HTTP 重定向/脱敏、两字段 CM 失败恢复/CAS、换/清凭据后一致快照的验证证据。
5. mock/真实网络/实机分列；真实额度/期限/权限、实际天数/状态、请求数/延迟，未跑项明确说明。
6. 三家切换、无和风配置使用彩云、地点取消/清除/冲突/重启、禁用/IME/快输与各出口的人工记录。
