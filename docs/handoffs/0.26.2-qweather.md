## 1. 任务与交付边界

实现 **0.26.2 和风天气适配**，使用户配置自己的 API Host + API Key 后，可手动选择和风查询当前天气与 7 天预报，并用和风搜索、确认地点。复用 0.26.1 的默认坐标、设置编辑器、Capability、配置与密钥体系。

## 4. API 依据与实施前复核

2026-10-15 已用 Context7 与官方文档核对如下。实施时再读原文及真实响应，不能用记忆中的 v7 DTO 替代坐标版字段。

- 使用账号独立 API Host；公共旧 Host 正在退出。用户输入格式、HTTPS 规范化与地址校验要有清晰提示。[API Host](https://dev.qweather.com/docs/configuration/api-host/)
- API Key 通过 `X-QW-Api-Key` header 发送，不放 URL。官方仍支持 Key 调用 API；文档提示自 2027-01-01 起限制 Key 每日请求量，本版按已定 Key 方案实现，记录将来 JWT 评估项，不扩大本次认证范围。[身份认证](https://dev.qweather.com/docs/configuration/authentication/)
- GeoAPI：`GET /geo/v2/city/lookup`；名称参数 location，行政限定 adm，国家限定 range，number 为 1–20。GeoAPI 的坐标参数顺序是“经度,纬度”；响应 name/id/lat/lon/adm1/adm2/country/tz/type/rank 等字段，不能拿 rank 决定唯一地点。[城市搜索](https://dev.qweather.com/docs/api/geoapi/city-lookup/)
- 实况：`GET /weather/v1/current/{latitude}/{longitude}`；纬度在前，坐标最多两位小数。响应 condition/temperature/wind 等是嵌套对象，数值带单位，metadata 有 attributions。[实时天气](https://dev.qweather.com/docs/api/weather/weather-current/)
- 逐日：`GET /weather/v1/daily/{latitude}/{longitude}`，本版明确请求 days=7；可请求 localTime。响应 days/forecastStartTime/forecastEndTime、温度与 day/night 分段。风速和概率须按返回单位/范围归一化，日期按地点时间解释。[每日预报](https://dev.qweather.com/docs/api/weather/weather-daily-forecast/)
- 按实际 HTTP 与受支持错误结构分类。403 可能是额度、Host、权限等问题，429 也可能是月限额；不能一概报 Key 错误。GeoAPI 旧 code 结果与天气新 error 对象分别解析。[错误码](https://dev.qweather.com/docs/resource/error-code/)
- 实际代理链路验证压缩响应；归因随数据展示且能打开，不能只写设置页或埋在 AI 看不到的 desc。[Gzip](https://dev.qweather.com/docs/best-practices/gzip/)、[注明来源](https://dev.qweather.com/docs/terms/attribution/)

免费额度以实施时定价和账号控制台为准；设置不写死次数，也不从文档推断当前账号可用权限。取得真实 Host/Key 后核验城市、实况、7 天权限与实际错误。缺账号不能以 mock 标记真实联调完成。

## 5. 建议按这五个小阶段实施

### A. 配置与鉴权请求边界

1. 增加 `default_provider: open_meteo | qweather`，缺省继续 open_meteo，存量来源不改。增加平铺 `qweather_api_host`、`qweather_api_key`，Key 声明 secret:true，复用掩码/明确清除与 CM。
2. Host 使用固定服务根地址，不接受任意路径/查询/用户信息/碎片；规范化策略统一在保存与执行边界验证。限定官方账号 Host 的受支持域名形式，防止伪后缀；HTTPS 及重定向规则落实到实际 HTTP 执行，不能只验证首个 URL。对带 Key 的请求禁止非预期重定向，测试确认 Key 不会发到另一个目的地。
3. 维持“空 Key=未修改、明确清除=删除”的区别。缺失/非法配置可编辑可纠正，选择和风执行时给明确 provider_not_configured/参数错误；鉴权失败不自动换源。
4. 写入、清 Key、切换来源/改 Host 仍推进现有 revision，并保持 default_location。复核 `settings.rs` 与宿主 `weather_config.rs` 两处白名单，不只改 manifest/UI。
5. 核验宿主 reqwest 压缩功能与实际 Gzip 解码；公共 HTTP 改动保持其他插件行为，避免顺带全局客户端重构。

**节点产出**：配置可保存/回读/清除，Host 校验与鉴权代理可验证，CAS/密钥回滚不退化；定向测试通过后自审。

### B. 和风地点解析及来源选择

1. 新增 `location/qweather.rs`，转换为同一 ResolvedLocation，ID 使用 `qweather:<id>` 命名空间。保持用户坐标与来源元数据，不将 Location ID 当 adcode。
2. 两个解析器遵循同一候选契约和歧义规则。只有明确名称/可靠别名且无合理歧义才能自动查；结果达到上游数量上限，不把局部过滤后的一条当作完整唯一。
3. 明确 country/admin 的支持与可靠性。和风示例 country 是本地化名称，未提供 country_code；不要伪造所有候选的国家码或从时区猜国家。可以使用有依据的上游限定/元信息，缺失则保持可空；不能静默丢弃用户限定。GeoAPI type 未必能区分区县/城市，kind 不凭 rank 或名字后缀冒充已确认类型。
4. 给 `search_locations` 增加向后兼容的显式解析器选项（建议 `resolver: auto | open_meteo | qweather`，省略=auto）；同步 schema、设置 IPC、插件解析与 UI。该字段只选择内建解析器，不接受临时 Host/Key。get_weather 仍从配置取天气来源。
5. auto 只在和风配置可用时优先和风；选中来源请求失败须可见。显式 qweather 缺配置明确报错，显式 open_meteo 不依赖和风。名称查询用当前解析器策略；明确坐标/默认地点不再搜索。
6. 面板切换解析器立即使旧候选/请求租约失效；选候选不写配置，保存才确认。已有默认地点不因换解析器改动。

**节点产出**：两个 resolver 能复用地点面板与 Capability；北京/辽宁朝阳、广州/天河、海外同名/空结果有样本验证，手工坐标继续独立可用。

### C. 并行天气与统一结果

1. 新增 `providers/qweather.rs`，按本次配置快照派生请求坐标/headers；只在请求处处理两位小数，保留默认地点原精度，测试零值、负值、边界及经纬顺序。
2. current/daily 同时发出，在单请求总预算内聚合，任一完成顺序均正确。0.26.1 的 pending 按 HTTP ID 存一段；并行后要分开“逻辑查询状态”和“子请求关联”，不能把两个子请求算成两个用户查询，也不能第一份响应就移除整条查询。维持原 4 查询槽、宿主 HTTP 上限及 busy 语义。
3. 取消、超时、重复 ID、迟到/重复响应、进程代次都不能续发或二次回复。部分请求超时而另一项已成功时，在总期限内返回可解释 partial；不无限等待、不重置 deadline、不自动重试计费请求。
4. current/daily 分别解析并保留缺失，温度归一 Celsius、风速 km/h、概率百分比，未知/不受支持单位不能直接当正确数值。按当地日期关联，不能用本机日期或直接截 UTC 日期。白天与夜间天气按明确语义展示，不冒充 WMO 全天最严重现象。
5. **模型/展示需要真实适配**：当前 condition_code 为 WMO 数值，展示映射也是 Open-Meteo；和风代码不能直接套此表。保留供应商原始 code/text/来源，必要时以兼容新增字段或内部类型扩展，旧 Open-Meteo raw 字段不破坏。当前 attributions 为 `Vec<&'static str>`，动态归因要调整类型，不能泄漏字符串获得 static 生命周期。
6. 完整返回 ok；一项失败/不足 7 天返回 partial 与准确 warnings/availability；两项都无可用数据才错误。只有预报时 temp 可空且标“仅预报”。现有 `status()` 只看 warnings，须复核空数据不会误报 ok。没有上游有效时间就保持缺失，不能拿 fetched_at 伪造观测时间。
7. 对齐天气新错误结构与 GeoAPI code，映射既有错误分类，必要时保留有界、安全的诊断原因。原始响应 detail 不直接透给日志/UI，防止回显凭据/URL。

**节点产出**：响应样本、单位/日期与状态机测试，顺序无关聚合、partial/取消/deadline 可验证，Open-Meteo 回归通过。

### D. 设置、来源声明与各出口

1. 来源/Host/Key/单位与地点保持既有显式保存语义，普通设置 patch 不丢结构化位置。保存成功之后才反映配置成功；外部更新不覆盖地点草稿，冲突重读并保留明确“未应用”反馈。
2. 禁用插件仍能编辑配置/手工地点，候选网络请求与天气执行遵循启用门禁。改解析器/Host 后旧候选不回流；当前编辑草稿怎样使用已保存凭据要明确，不把未保存配置偷偷当已生效。
3. metadata.attributions 与 GeoAPI 来源/许可按需要进入统一模型/raw，天气结果展示来源并提供可打开的声明链接；保留 Copy 摘要与 partial/缺失信息。链接使用既有 open_url/ResultAction 路径并校验允许的协议，不另造执行出口。
4. Query / ToolCall / 设置固定桥接共用服务；AI/CLI/MCP 仍通过 Capability policy，不新建各自的和风逻辑。新增字段的 projection 与两工具 envelope 保持一致，status/归因/缺失不能只藏在 desc。

**节点产出**：完整设置与结果展示，可用真实前端模块+内存 IPC 先走查，再做 Tauri 实机验证；明确区分 mock、真实网络与真实应用记录。
