## 二、背景与动机

### 2.1 为什么做

- **设置页关闭按钮**：设置窗口 `decorations(false)`（`src/infra/platform/window/windows.rs:3623`）且无自定义标题栏，唯一关闭路径是 ESC；用户反馈不知道怎么关。前端监听已存在（`frontend/js/settings/index.js:687` 对 `#close-btn` 的 optional-chaining 绑定）但元素从未创建——本就是预留坑位，本版补上。
- **编辑器关闭确认**：`handleCancel()`（`frontend/js/content-editor/main.js:362-373`）用两按钮对话框（ok=放弃更改 / cancel=继续编辑），没有「保存」出口；而 `handleSave()` 已具备「隐藏 → 后台保存 → 失败回显」闭环，接第三按钮成本很低。
- **chord 全局快捷键**：chord 独占吞键的门禁 `chord_exclusive_eligible()`（`src/infra/platform/hotkey/state.rs:759`）要求主窗可见，本质是窗口内快捷键；高频动作（截图/便签/剪贴板历史等）值得有不依赖主窗的全局入口。
- **引导向导**：welcome 页只有快捷键列表 + 开始按钮，没有功能开关与引擎引导；OCR backend 默认 `auto` 意味着 PP-OCR 装完即自动生效，缺一个把「Win OCR 中文弱 → 一键下载 17MB 增强」讲清楚的首启路径。

### 2.2 明确"不是问题的"（避免误改）

- 设置窗口 **hide 而非 close** 是刻意的复用/预热设计，关闭按钮只 hide，不引入销毁语义。
- `confirmDialog` 两按钮 boolean 契约本身没有 bug，约 25 处调用点依赖它；问题仅在编辑器场景缺第三出口，扩展必须向后兼容。
- chord 门禁要求主窗可见是 0.18 输入状态流转重构的刻意设计；0.22.12 **不改 chord 模式本身**，只增加平行入口。
- OCR 默认路由 `auto` 已保证「PP-OCR 装完自动生效」，向导只负责下载，不做引擎选择 UI。
- WinRT OCR 永久保留为零安装 fallback（0.22 §2.2），向导文案定位是「增强」不是「替换」。

## 三、核心设计与决策

### 3.1 全局快捷键选型 —— RegisterHotKey 有条件启用（已定，2026-09-06）

**定案**：被提升的全局快捷键是**独立组合键**（任意修饰键组合，默认建议 `Ctrl+Alt` 前缀降低冲突面），经 `RegisterHotKey` 注册到既有 message-only 窗口 `BlinkInputWindow`，`WM_HOTKEY` 进既有无锁 effect 通道 → `HotkeyService` → 复用 `ChordRegistry::trigger`（含 `disabled_chord_actions` 门禁），符合 spec-architecture §A3.5「多协议入口，单一原子执行语义」。

**理由**：

- `RegisterHotKey` **注册即冲突探测**（`ERROR_HOTKEY_ALREADY_REGISTERED`），这是 hook 路线给不了的能力；
- 若走 LL hook 全局吞 `Alt+字母`：无法探测冲突 + 全局吞系统修饰键组合，双重违反「热键默认不吞键」铁则；
- 复用 effect 通道与 trigger 链路，注册逻辑归 `infra/platform/hotkey`，domain 不碰 Win32，分层不破。

**决策范围修订（落地时回写，需用户确认）**：`docs/product.md` 取舍表与 `docs/phases/0.10-voice-agent.md`「为何不用 RegisterHotKey」的否决**仅针对主热键**（Alt+Space 体验与 fallback 顾虑），次级可提升快捷键以「可探测冲突」换「系统注册」，是对该决策的补充而非推翻。

**已知局限（UI 需明示）**：`RegisterHotKey` 只能探测到同样走系统注册的软件；Snipaste/QQ 截图等用 LL hook 实现的快捷键探测不到，冲突反馈文案定位为「尽力而为」。

### 3.2 冲突探测两层（已定）

- **OS 级**：保存配置与启动注册时试注册，失败即报「组合键已被占用」，配置保留但标记未生效；
- **内部**：扩展 `ChordRegistry::binding_conflicts()`（`src/domain/chord/mod.rs:574`）覆盖「全局键互相冲突」「全局键 vs 主热键」，并顺带补上现有缺口「chord 键 vs 主热键」跨检查。

### 3.3 共享对话框三态扩展 —— 向后兼容（已定）

`showCustomDialog()`（`frontend/js/shared/tauri.js:113-206`）增加可选第三动作；不传第三动作时返回值与现有 boolean 语义完全一致，约 25 处既有调用零改动。

### 3.4 向导不复制引擎逻辑（已定）

向导只做编排：开关走 `set_config`，下载复用引擎页同一条 install 命令与 `blink://local-engine-status` / `install-stage` 事件，深链复用 `open_settings_tab`；不在 welcome 侧实现第二套下载/校验逻辑。

## 五、按子版本展开

### 0.22.11 设置页关闭按钮 + 编辑器关闭确认三态化

**A. 设置页关闭按钮**

- 现状：无自定义标题栏，拖拽区由左上 `.logo` 与各面板 `h2` 承担；`#close-btn` 监听空转。
- 方案：content 区顶部右上角补关闭按钮（X 图标用 SVG sprite，样式走 token），点击走既有 `hideSettingsWindow()`（与 ESC 同语义：hide）；按钮区域不落在拖拽区。
- 不改窗口创建逻辑（`open_settings` / 预热路径均不动）。

**B. 编辑器关闭确认三态化**

- 目标对话框：**保存并关闭**（主按钮，Enter，走 `handleSave()`）/ **放弃更改**（现有 ok 路径）/ **继续编辑**（Esc，现有 cancel 路径）。
- `showCustomDialog` 扩展可选第三动作；`handleCancel()` 改三按钮分支；保存失败时 `handleSave` 既有的回显路径保证内容不丢。
- i18n：`zh.js`/`en.js` 增 key（如 `editor.saveAndClose`），旧 key 视其他复用情况清理。
- 三个关闭入口（标题栏 X、Esc、Alt+F4 `onCloseRequested`）都收敛到同一三态确认。

### 0.22.12 chord 提升为全局快捷键

**配置形态**：chord 动作卡新增可选「全局快捷键」——开关 + 组合键 + 冲突状态；`ChordBinding` 增加 per-action 全局键字段（具体结构实现时定，存 `app.chord` 分片），chord 原绑定不动（提升 = 增加入口，非替换）。

**注册与分派**：`infra/platform/hotkey` 新增 RegisterHotKey 注册模块（挂 `BlinkInputWindow` 收 `WM_HOTKEY`），进 effect 通道新变体 → `HotkeyService` 按 chord action id 分派 → `ChordRegistry::trigger`；全局键并入 `InputConfigSnapshot` 经 `refresh_input_config` 推送。

**生命周期**：配置变更即重注册（先注旧再注册新）；单键注册失败不阻塞其他键，投影「未生效 + 原因」；应用退出注销。

**UI**：chord tab 动作卡展开区加全局快捷键区；录制组件复用 `record_hotkey` 链路但需泛化——现有前端校验强制 Alt+字母（`frontend/js/settings/tabs/chord.js:505-530`）；保存时执行 3.2 两层冲突检查并回显结果。

**文档回写**：按 3.1 修订 `product.md` 取舍表与 0.10 记录的范围说明（经用户确认后落笔）。

### 0.22.13 首次引导向导

**结构（4 步，步步可跳过/后退）**：

1. **欢迎 + 核心快捷键**：现有内容（主热键 + chord 列表）。
2. **常用开关**：开机自启、悬浮球、chord 总开关等高频项，直接 `set_config` 写入并即时生效。
3. **引擎增强**：
   - OCR：提示「系统 Win OCR 对中文识别较弱」，一键下载 PP-OCRv6（≈17MB：ORT DLL ~11MB + 模型 ~6MB，供应链真源 `resources/ocr/paddleocr-onnx/asset-lock.json`）；下载完成即自动生效（backend 默认 `auto`），不做引擎选择 UI；welcome 侧做 mini 进度组件（复用 install 命令 + 进度事件）。
   - 语音：FunASR 三模型（237MB~954MB）只做介绍 + 「去引擎页下载」深链（`open_settings_tab`），不进默认下载路径。
4. **完成**：置 `first_run=false`。

**边界**：下载失败/跳过不阻塞完成；旧用户（`first_run=false`）零影响；welcome 窗口尺寸随分步内容适当加宽。
