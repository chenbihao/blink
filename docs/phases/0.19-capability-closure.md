# Blink 0.19 — 能力闭环（从“有能力”走向“真实可用”）

> **范围**：补齐窗口、图片、便签和轻量文本闭环；统一 command/Capability 重叠语义；解耦图片编辑；开放受控自然语言设置；收敛 AI 设置、对话能力模式、Skill、MCP client 生命周期与 Blink MCP Server 主进程出口。
>
> **状态**：✅ 已完成（0.19.1–0.19.17 全部完成）。
>
> **动机**：0.18 已有基础感知与执行能力，0.19 把高频链路收敛到可完成、可续读、可复用、可理解，并关闭窗口与 MCP 并发可靠性缺口。
>
> **前置**：0.18（含 0.18.7/0.18.8）。
>
> **原则**：用户入口与 AI 入口共享业务语义但保留各自协议；大数据走引用或分页；设置只开放显式白名单；纯对话只影响 Blink AI Agent 装配，不削弱其他 Capability 出口；Blink MCP Server 必须消费主进程的实时能力与运行时状态，不再复制最小运行时。

## 二、背景与动机

本版解决的核心问题是：能力虽然存在，但跨调用数据无法续接、便签与文本场景不完整、UI/AI 入口语义可能漂移、设置与扩展边界难以理解，窗口和 MCP 连接还存在并发重复创建。

### 2.1 明确不是问题的

| 项 | 结论 |
|---|---|
| 所有 command 都必须经 CapabilityRegistry | UI 状态机可保留 command；重叠业务语义必须共享实现。 |
| 大文本必须先建 TextStash | 可重放文件用绝对路径 + 有界分页更直接。 |
| 图片编辑必须立即 Capability 化 | 先解耦用户编辑会话；AI 编辑协议另行设计。 |
| 自然语言设置等于任意 KV | 只暴露稳定白名单，不开放 secret 或原始配置分片。 |
| 纯对话应关闭所有 Capability 出口 | 只改变 Blink AI Agent；CLI、内部调用与 Blink MCP Server 不变。 |
| MCP 状态读取可以顺便补连 | 状态与 tool pool 查询必须无副作用；连接只由明确意图触发。 |
| stdio 子进程是 MCP Server 的协议要求 | stdio 只是 transport 之一；它适合自包含 server，但不适合需要复用 Blink 实时插件、搜索、窗口和图片状态的主程序出口。 |
| Streamable HTTP 与 SSE 完全无关 | Streamable HTTP 可在单次响应中使用 SSE 流；本版不实现的是已废弃的独立 HTTP+SSE transport。 |
| 首次 Chord 失败是 Windows 第一次没有键盘 Hook | Hook 已存在；真实原因是 `tao` 聚焦 fallback 注入 LAlt down/up，注入态覆盖了 Blink 已确认的物理 Alt 状态。 |
| 主窗口必须靠启动预热才能正确进入 Chord | 正确性由输入状态机保证；主窗口激活预热是竞态补丁，0.19.17 删除，不再参与正确性。 |

## 三、核心设计与决策

### 3.1 Capability 边界

图片生产者与消费者正交；`CapabilityEnv` 只暴露便签、pin 等必要的最小窗口桥接。Capability 不直接操纵 DOM、前端事件流或模态交互，但可产生打开路径、显示便签/pin 等操作系统级窗口副作用。通用约束见 `spec-architecture.md §A4`。

### 3.2 图片与文本数据流

- `ImageStash` 保持进程内、可复用、固定 15 分钟 TTL；最多 16 项、总计 64 MiB、单项 32 MiB。图片 Capability 的 canonical 结果仍是 Blob，agent 投影返回 `image_ref`，消费者统一解析引用/字节二选一输入。
- `read_text_file` 只接受绝对路径，提供 `metadata/range/head/tail`，正文按行有界读取；单次约 2,000 token 软预算、约 4,000 token 与 32 KiB 硬上限，返回行号、EOF、截断状态和续读游标。拒绝目录、二进制、非 UTF-8 与超长单行。

### 3.3 便签与重叠入口

便签更新用单调 `updated_at` 做乐观并发；不存在、已回收和版本冲突结构化区分。回收同时写库、关闭普通或 spare 窗口并刷新管理器；单纯隐藏/显示由独立 `set_sticky_visibility` 表达，不改变回收状态。`list_sticky` 明确返回 `visible/visibility`。剪贴板、pin、便签与 OCR 的公共校验/平台调用下沉为共享语义，command 与 Capability 只保留协议和 UI 会话差异。

### 3.4 设置与 AI 扩展

自然语言设置只开放 11 个高频可逆字段；写入携带预览旧值并做乐观并发，每次重新确认且不可记忆授权。设置页按“AI 供应商 / AI 对话设置 / AI 扩展”分区，移除没有真实运行时消费的开关；模型请求与 Capability deadline 统一使用 20 秒默认硬超时。

### 3.5 对话能力模式与 Skill

对话能力模式分为“全能力 / 主窗口仅对话 / 全局仅对话”，默认全能力；模式按 `ConversationKind` 决定是否装配内置 Capability、MCP client 工具和 Skill，并纳入 Agent cache key，不影响其他 Capability 出口。主窗口模型可跟随轻量档、主档或固定自选模型。原路由档泛化为超轻档，供标题命名等低成本短任务使用，标题默认绑定超轻档。Skill 总开关和单 Skill 禁用同时覆盖摘要、自动触发、`/skill` 显式激活及输入提示，配置变化即时清理运行时缓存。

### 3.6 窗口与 MCP 并发

- 所有静态窗口按 label 共用 `get_or_create` single-flight；“窗口对象存在”与“前端 ready”分开处理，首个 payload 使用 pending/pull 兜底。右键菜单预热与首次唤起也走同一入口。
- `McpClientManager` 按 server name 维护 generation、唯一连接任务、等待者通知和 30 秒自动失败冷却；不同 server 最多 3 个并发，单次握手/拉工具 15 秒，prompt 最多等待 5 秒。配置变化先推进 generation，旧 transport 不得提交；状态与工具快照查询保持只读。

### 3.7 Blink MCP Server 主进程化 —— Streamable HTTP（已定）

**定案**：Blink MCP Server 由常驻主进程托管，采用 MCP Streamable HTTP transport，在 `127.0.0.1:{port}/mcp` 提供单一 endpoint。旧 `blink mcp-server` 的“另起一个最小 Blink 进程”路径退出生产架构；0.19.13 不实现旧版 HTTP+SSE transport。

**理由**：独立 CLI 进程会重新构造数据库连接、CapabilityRegistry 与不完整的 `TauriDomainEnv`，无法共享主进程中的动态插件 Capability、`PluginEngine`、`SearchService`、窗口/便签状态与 `ImageStash`。主进程托管可让外部 Agent 调用用户当前正在使用的那一个 Blink，同时避免每个 MCP client 各启动一套运行时。

具体约束：

- **协议**：启用 rmcp 的 `transport-streamable-http-server`，复用现有 `BlinkMcpServer` handler、Capability → MCP 投影、暴露清单双重门禁与 `mcp_external` 审计；不自造 JSON-RPC/SSE 编解码。
- **监听边界**：socket 必须显式绑定 IPv4 loopback `127.0.0.1`，不得绑定 `0.0.0.0`、IPv6 wildcard 或局域网地址。首版按本机可信工具场景不引入 token/OAuth，但不配置宽泛 CORS，并校验 `Host`；请求带 `Origin` 时只接受 loopback 来源，降低 DNS rebinding 风险。
- **端口**：`McpServerModeConfig` 增加持久化端口字段，提供稳定默认值并允许用户修改；端口必须位于 `1024..=65535`。端口占用时进入可观察的错误状态，不得静默切换随机端口导致外部 client 配置漂移。
- **生命周期**：新增主进程 `McpServerRuntime`，在 CapabilityRegistry、插件引擎、搜索服务和 `TauriDomainEnv` 完成注入后按配置启动。设置页启停、修改端口与应用退出分别触发串行化 start/restart/stop；重复操作不得创建多个 listener，旧 generation 不得覆盖新状态。
- **实时暴露清单**：listener 使用主进程唯一 CapabilityRegistry。`exposed_capabilities` 更新后立即重建共享 tool snapshot，`tools/list` 与 `tools/call` 必须读取同一代快照并保留 call-time 二次校验；仅修改清单不重绑端口。
- **可观察性**：设置页展示 `disabled/starting/listening/error`、实际 endpoint、暴露 tool 数量和最近错误，并提供复制 Streamable HTTP 配置的入口。状态查询只读，不得隐式启动 listener。
- **CLI 边界**：`search/run/capabilities/config/chat` 是否保留独立 CLI 运行时不由本子版本决定；旧 `mcp-server` 子命令不得继续静默启动能力缩水的 server，应移除公开入口或返回指向主进程 HTTP endpoint 的明确迁移错误。stdio → HTTP 兼容桥若确有 client 兼容需求，后续独立设计。

### 3.8 Windows Alt/Chord 与 Hook 恢复 —— 状态机根治（已定）

**定案**：物理 `Down` / `InferredDown` 的证据优先于 `InjectedDown`，`tao` 为抢前台注入的 Alt down/up 不得清除用户仍按住的真实 Alt；删除主窗口启动激活预热。主键边界以 Windows 物理修饰键快照纠正 stale level，所有 Raw/控制事件统一发布 reducer effect，确保 Modifier、Chord 与前端 UI revision 同步。锁屏/解锁通过 reducer 的会话重置事件原子清理 modifier、gesture 与 chord；周期心跳只提交重装请求，普通心跳仅在输入 idle 且主窗口隐藏时执行，解锁或手动恢复在安全门禁满足后优先执行。安装失败按短间隔退避持续恢复，`ManualRecovery`、`SessionRecovery`、`Heartbeat` 按优先级合并且不可互相覆盖。

`Blink Print Debug Info` 是长期保留的通用运行时诊断动作，输出带 schema/profile 的可复制文本；0.19.17 的 `windows_input` profile 重点记录物理修饰键、状态机、Chord、UI projection、Hook/WTS/Raw 注册状态和脱敏事件环。`Blink Debug InitHook` 在打印同一份现场信息后提交显式恢复请求；物理修饰键全部松开且 voice/recorder idle 后，reducer 清理易失输入状态，再安全重装 Hook。两者均可通过 `debug` 搜索召回，后续版本可在不改变动作定位的前提下扩展 Storage、Search、Plugin 等通用 section。

**边界**：0.19.17 不实现 Raw Input 与 LL Hook 事件匹配式健康探针，不依赖 `WTS_SESSION_DESKTOP_READY`，不为 Win32 失败测试引入大型 backend trait。voice/recorder 活跃时由 reducer 发取消 effect 交给应用层收尾，不直接伪造业务态为 Idle；WTS 通知注册与注销必须配对。

### 5.1 0.19.13 实施顺序

1. **协议与配置底座**：为 rmcp 启用 Streamable HTTP server feature；扩展 `McpServerModeConfig` 的端口字段、默认值、反序列化兼容与校验，保留现有 `enabled/exposed_capabilities` 数据。
2. **handler 实时化**：让 `BlinkMcpServer` 共享可热更新的 exposure snapshot，移除单实例静态 `cached_tools/config` 造成的旧会话漂移，并为 `tools/list` / `tools/call` 钉住同代双重门禁。

### 5.2 0.19.14 截图后处理性能优化 + 控件吸附修复

**性能优化**：通过日志实测定位并解决了四个瓶颈——Tauri IPC JSON 序列化、逐字节 R↔B swap、overlay hide DWM 重组、session_png lazy 编码。四轮优化后全屏 pin 336ms（3.8x）、有标注复制 699ms（5.1x）、快路径 copy 67ms（4.5x）。剩余瓶颈（PNG 编解码往返）待 raw BGRA 协议优化。

## 六、验收结论

- 图片可沿“截图/剪贴板 → `image_ref` → OCR/pin/写剪贴板”连续调用，引用有固定资源上限。
- 便签可完成创建、读取、带版本更新和可恢复回收；文本文件可按模式有界续读。
- 截图与剪贴板图片进入同一编辑核心，输出后正确结束各自会话。
- 自然语言设置不越过白名单，逐次确认且与设置页运行时状态一致。
- 纯对话不装配工具或 Skill；disabled Skill 不出现在 `/skill` 输入提示中。
- MCP 同名并发连接只提交一个 generation；禁用、删除、覆盖配置不会留下旧工具快照。
- 自动化基线以本版收尾 review 的 `cargo test --bin blink`、前端相关 `.test.mjs`、JS 语法检查、`cargo check --bin blink` 与 `git diff --check` 结果为准；GUI/Win32 行为按最短手动链路验证。
