# Blink 0.19 — 能力闭环（补齐 AI 感知与执行缺口，消除双入口债）

> **范围**：补齐图片获取、窗口感知、便签与 pin 能力，收编 OCR 用户入口，建立图片跨 Capability 引用闭环，并清理 capability alias 与双实现技术债。
>
> **状态**：🚧 进行中（0.19.1–0.19.4 已完成）。
>
> **动机**：0.18 后 AI 仍缺少窗口、剪贴板图片、便签和 pin 的完整感知与执行链路，同时存在多条双入口/双实现债。
>
> **前置**：0.18（含 0.18.7/0.18.8）完成。
>
> **原则**：图片来源与消费能力正交；用户与 AI 入口共用 Capability；`Blob` 保留完整二进制语义；图片跨调用只传进程内不透明引用，不让大字节经过 LLM channel。

## 二、背景与动机

0.19 关闭三类缺口：AI 无法感知窗口和剪贴板图片、无法创建便签或 pin 图片，以及用户入口与 AI Capability 使用不同实现。0.19.1–0.19.3 已建立统一入口、图片与窗口感知、窗口副作用执行三段基础链路；复核发现 `CapabilityResult::Blob` 在模型出口只投影为尺寸摘要，原始字节不会进入下一轮 tool call，因此“读取图片 → OCR/pin”的 AI 链路仍未真正闭合，0.19.4 负责补上这一段。

### 2.1 明确不是问题的

| 项 | 结论 |
|---|---|
| 截图 overlay 的 copy/save/cancel command | 属于 UI 状态机指令，不进入 CapabilityRegistry。 |
| pin 拖拽/缩放与便签窗口内编辑 command | 属于窗口内交互，不因能力化而收编。 |
| `ocr_image` 保持纯图片输入 | 图片获取与 OCR 消费继续正交。 |
| `screenshot { op: crop }` 依赖 SESSION | 这是 Alt+A 交互语义；AI 使用 capture/window，不改 crop。 |
| `ocr_diagnose` 直调 backend | 仅提供诊断信息，不属于 OCR 识别能力的双入口。 |
| `CapabilityResult::Blob` 保留原始字节 | Blob 是 AI、CLI、MCP、前端共用的通用二进制协议，不应为 ImageStash 清空 `bytes` 或改成图片专用结果。 |

## 三、核心设计与决策

### 3.1 图片来源与消费者正交（已定）

截图、剪贴板、历史记录等能力只负责产出图片；OCR、pin 等能力只负责消费图片。这样避免为每组来源和消费者增加复合能力。

### 3.2 窗口副作用通过最小桥接暴露（已定）

`CapabilityEnv` 只暴露创建便签、读取便签服务和显示 pin 窗口所需的最小方法，不向 Capability 开放完整 `DomainEnv`。窗口类能力继续增加时再评估抽取 `WindowOps`。

### 3.3 Capability 的 UI 边界（已定）

Capability 不直接操作前端 DOM、事件流或模态交互，但可以产生打开路径、显示便签/pin 等操作系统级窗口副作用。通用约束以 `spec-architecture.md §A4` 为准。

### 3.4 风险与敏感性分开判定（已定）

便签与 pin 的窗口副作用可逆，因此是 `Safe`；读取或写入用户内容的能力另标 `sensitive: true`。`set_sticky_geometry` 只保存几何数据，已显示窗口要到下次显示时才应用新位置。

### 3.5 用户入口统一经 CapabilityRegistry（已定）

`open_url` 和 `ocr_image` 用户 command 已改为调用对应 Capability，使用户与 AI 共用实现。OCR command 的返回类型不变；错误统一映射为 `internal_error`，原始消息保留。

### 3.6 截图能力扩展（已定）

`screenshot` 增加按 `hwnd` 截取窗口和直接写入剪贴板两种操作。前者不依赖 SESSION；后者在 Rust 内完成大图片搬运，只向 AI 返回完成摘要。

### 3.7 引入 ImageStash 修复图片引用闭环（0.19.4 修订，已定）

**定案**：增加应用进程级 `ImageStash`。图片 Capability 仍返回完整 `Blob { mime, bytes, desc }`；模型出口在投影 `image/*` Blob 时把字节移入 stash，并返回机器可读的 `{ kind, image_ref, mime, size_bytes, expires_in_seconds }`。后续工具只传 `image_ref`，不把图片编码进 LLM 上下文。

**理由**：原“图片在 LLM channel 传递”的假设不成立，当前 `to_rig_tool_result()` 只产生尺寸摘要。引用应属于模型出口的传输策略，而不是图片生产者的业务语义；若让生产者清空 `Blob.bytes` 并填 `image_ref`，会破坏 CLI/MCP/前端对通用 Blob 的既有契约，也迫使截图等能力感知 AI 运行时。

### 3.8 引用可复用、固定过期且有硬内存上限（已定）

`get(image_ref)` 为非消费读取，同一图片可以先 OCR 再 pin；不采用一次性 `take`，避免 AI 为复用图片重新截图或重读剪贴板。引用自创建起固定 **15 分钟**过期，读取不续期；这与单次工具默认 20 秒 deadline 是两套概念，15 分钟用于覆盖多轮推理、敏感能力确认和用户停顿。

stash 同时限制为 **最多 16 项、总计 64 MiB、单项 32 MiB**。每次 put/get 先清理过期项，put 超限时按最早创建顺序淘汰；不启后台线程。TTL 只负责时间边界，内存上限才是常驻内存 `< 300MB` 的硬保护。引用使用不可猜测的进程内 token，不持久化、不写入日志，应用重启后失效。

### 3.9 保留原始二进制接口，消费者兼容双输入（已定）

`CapabilityResult::Blob` 继续作为截图、音频、文件等未来能力的原始二进制接口。0.19.4 不增加 `image_ref` 字段，也不把 `bytes` 改为空数组。

`pin_image`、`ocr_image` 和 `write_clipboard` 图片模式新增可选 `image_ref`，并保留现有 `png` / `image_bytes` 参数供用户 command、CLI、MCP 直调及未来原生多模态投影使用。运行时要求引用与原始字节二选一；同时提供或都不提供均返回 `InvalidArgs`，不做静默优先级。公共解析与 MIME/PNG 校验收敛为一个 helper，避免三个消费者各自实现。

图片生产者 `read_clipboard`、`read_clipboard_history_image` 和 `screenshot { capture/crop/window }` 的 Capability schema 与 invoke 返回不变；只调整 AI/MCP agent 投影层。`capture_to_clipboard` 返回 `Done`，不参与 stash。

## 四、复用与范围边界

### 4.1 已复用的基础设施

| 既有能力 | 复用结果 |
|---|---|
| 窗口枚举与 DWM rect | 支撑 `list_windows` 与窗口截图。 |
| 剪贴板 DIB 解码、图片历史库 | 支撑当前图片读取、历史图片列表与按 id 读取。 |
| `StickyService` 与窗口创建函数 | 通过 `CapabilityEnv` 支撑便签和 pin。 |
| `CapabilityRegistry` command 调用范式 | 收敛 `open_url` 与 OCR 用户入口。 |
| 截图 SESSION、编码和剪贴板写入 | 支撑窗口截图及 `capture_to_clipboard`。 |

### 4.2 不进当前范围的项

| 项 | 理由 |
|---|---|
| 完整多模态投影 | 依赖 Provider 多模态能力，后置。 |
| 持久化或跨进程图片引用 | 0.19.4 只做应用进程内短期 bearer ref；重启失效，不落盘。 |
| 便签 update/delete/trash 能力 | 本阶段只建立创建、列表和几何设置能力。 |
| 文件图片读取、剪贴板文件列表 | 场景频率待验证。 |
| 主窗口 ContextSnapshot、外部 subagent、WebDAV 同步 | 属其他阶段范围。 |

## 五、分子版本展开

### 5.1 0.19.1 — 入口与债务收敛

删除 `capture_screen`/`crop_image` alias；`open_url` 与 OCR 用户 command 改经 CapabilityRegistry，与 AI 共用实现。职责不同的资源管理器 commands 和诊断专用 `ocr_diagnose` 保持独立。
同期收敛静态窗口预热与用户唤起的初始化竞态：同 label 创建统一走 single-flight `get_or_create`，并区分窗口已创建与前端 ready，避免重复 build 阻塞后续热键；跨版本铁则见 `spec-frontend.md §1.4`。相关产品技术债状态同步回写。

### 5.2 0.19.2 — 图片与窗口感知闭环

`read_clipboard` 支持返回图片 Blob，并新增历史图片列表和按 id 读取能力；新增敏感窗口列表能力，`screenshot` 支持按 `hwnd` 截取窗口且不依赖 SESSION。

### 5.3 0.19.3 — 便签与 pin 执行闭环

通过最小 `CapabilityEnv` 桥接新增便签创建、几何设置、列表与 `pin_image`；`screenshot` 增加 `capture_to_clipboard`，避免大图片经过 LLM channel。Capability 窗口副作用边界、产品技术债和 roadmap 状态随实现统一回写。

### 5.4 0.19.4 — ImageStash 图片引用闭环

- [x] 新建 `ImageStash`，由 `TauriDomainEnv` 持有并经 `CapabilityEnv` 只读访问；最小运行时可返回 `None`。
- [x] 增加带 stash 上下文的 canonical agent 投影：内部 AI 与 MCP 共用；非图片 Blob 和无 stash 运行时保持现有摘要降级。
- [x] 图片生产者继续只返回完整 Blob，不接触 stash；投影层负责把图片移入 stash 并生成结构化 `image_ref`。
- [x] `pin_image`、`ocr_image`、`write_clipboard` 的引用/字节双输入校验有 schema 与 invoke 单测。
- [x] `read_clipboard` 与 `screenshot` 获取用户私有数据，补齐 `sensitive` 审查。
