## 二、背景、现状与审查结论

### 2.1 用户流程

| 任务 | 本版最短流程 |
|---|---|
| 使用插件 | 找到官方插件 → 查看所需资源/配置 → 安装 → 补齐配置 → 打开插件/主窗入口 |
| 翻译 | 输入或显式采纳选区 → 查看方向 → 本次改目标 → 复制或打开翻译插件窗口 |
| 查词 | 明确查词 → 离线摘要 → 独立词典窗口看详情 → 必要时显式转翻译 |
| 跨设备配置 | 填 WebDAV 地址/用户/密码 → 自动创建 blink 目录 → 比较/合并固定范围 → 应用并显示需本机处理的项目 |
| GIF 分享 | 框选 → 录制/暂停/停止 → 必要修剪/节奏调整 → 导出 GIF/复制文件 |

### 2.2 代码侧必须补齐的接线

规划前静态审查识别的接线缺口——插件集合固定不可动态安装/撤销、能力注册缺 owner 替换/撤销、adapter/AI tool/Agent 持旧快照缺代次失效、tool id 碰撞未校验、CLI 无插件环境、插件窗口无真实 IPC/来源/资源边界、配置导入带运行时副作用、连续截图无录制时钟/压缩素材/时间轴——已分别在 0.28.1–0.28.7 落地解决，落点见 §七。

### 2.3 保留的设计

- 复用 JSONL、懒启动、总期限/取消、并发上限、配置 revision/CAS、凭据托管、纯 data 与展示投影。
- 原生后端进程拥有当前用户权限；官方来源验证、目录划分和页面 ACL 不等于 OS 沙箱。
- 插件独立窗口不意味着每个插件拥有独立 EXE、WebView2 浏览器环境或永久常驻进程；后台运行时可选，页面可独立存在。
- WebDAV 管理宿主配置；GIF 采集和高频素材管线属于宿主服务，不为插件化复制系统能力。
- 0.27 在途修复不迁入本版，也不被本次文档更新覆盖。

## 三、已定产品方案与工程契约

### 3.1 决策汇总（已定）

| 事项 | 定案 |
|---|---|
| 分发 | 只分发官方插件；开发者可用显式开发模式调试本地包，生产不接任意来源/社区投稿 |
| 旧插件 | 保持 IP/天气/翻译现状与稳定身份，继续随包；新增词典和大词库可按需获取 |
| 界面 | 插件携带自己的 index.html 和资源，由宿主创建各自独立窗口；重复唤起复用该插件窗口 |
| 翻译 | 中英互译、自由切目标、本次覆盖；本版不做“译文再译回原语”的回译检查 |
| 词典 | 英汉、基础汉英反查、词形/短语；词根词源为可选增强；发音后置 |
| 同步范围 | 固定范围全部同步，不提供按设备/配置组勾选；设备相关内容作为明确本机覆盖 |
| 秘密 | API key、token、secret、WebDAV 密码及 CM 引用不漫游，已有本机密钥不被缺字段清空 |
| WebDAV 设置 | 地址、用户名、密码三项；自动在指定位置建立 blink 同步目录，不要求先选厂商或额外同步口令 |
| GIF | 短演示；显示光标，支持修剪/删帧/速度/停留/循环与导出预设；点击高亮后置 |
| 发布 | 接受分批交付；背单词仅在 roadmap 记录，不进入本版实现 |

### 3.2 插件 index.html、独立窗口与宿主管理（已定）

此前“工作台”指统一的宿主窗口管理/SDK 服务，不是必须使用一个聚合窗口。本版按独立插件窗口实现：

- 一个插件包可有根 index.html 或 manifest 明确声明的相对入口，并携带 CSS/JS/图片等静态资源。不能用插件返回的 HTML 字符串注入主窗口。
- 以宿主管理的 plugin_id/page_id 为逻辑窗口身份；翻译、词典等窗口可以同时存在。默认每个插件一个主窗口，重复打开 show/focus；首版不做同一页面无限多实例。
- 插件窗口数量动态，按需创建并复用，不把所有已安装插件窗口加入启动预热。已有静态系统窗口继续遵守预热规范；创建仍须 single-flight，初始 payload 使用 ready/pull。
- 关闭先隐藏并保留有界会话状态；空闲回收 WebView 时可保留有限草稿，重开恢复。重启默认不保存翻译正文；GIF 未交付素材按单独恢复策略处理。卸载/更新撤销旧页面会话。
- 独立窗口可以共享浏览器环境；不默认每插件一个 WebView2 数据目录。遵循现有 IME 隔离边界（0.28.8 实测确认共享浏览器环境可行），不把“独立窗口”与“独立浏览器进程组”绑定。
- 窗口数/缓存/整组内存有预算；优先回收隐藏且空闲的窗口，仍不足时提示关闭其他插件窗，不抢关可见的未交付会话。窗口预算已在 0.28.2 定为 6，不能随安装数无界增长。
- 宿主控制窗口创建/销毁、权限、来源和资源协议；插件页面只消费有限 SDK。插件不能自行宣称另一个 plugin_id 或直接获得任意窗口/DOM/事件/路径权限。
- 业务操作复用 Capability，页面展开/选择/输入等状态留在 Interaction。主窗摘要与独立页面使用同一业务实现；打开页面仅返回已启动，不声称任务完成。
- 插件中心在现有管理中提供“已安装/获取”；安装、启用、就绪分开呈现，缺密钥/运行时/词库给明确修复入口。AI/MCP 授权继续使用功能目录的真源，不随安装自动放行。

Tauri 的独立 WebviewWindow/窗口标签权限可以承载此形态；来源、实际 IPC 可达性与资源隔离仍由实现和验收保证。[官方窗口文档](https://v2.tauri.app/learn/window-customization/)

### 3.3 插件包、目录、生命周期与兼容

插件可声明 query、Capability、页面、数据包的合法组合；页面可没有后端进程，页面动作不会自动变成 AI tool。

| 契约 | 必含内容 |
|---|---|
| 清单/协议 | plugin_id；清单 schema、宿主兼容范围、进程协议、数据格式版本分开；平台/架构、可选 runtime/pages/tools/datasets |
| 身份/入口 | 保持已发布 tool id；校验最终映射碰撞、保留命名空间、字符/长度；关键词冲突不抢占既有入口 |
| 安装状态 | 来源、已验证摘要、包/词库版本、有效 generation、启用与就绪原因；包、数据、缓存、数据包分目录 |
| 页面会话 | 宿主绑定的 plugin/page/generation/session/request_id；ready/pull、取消/关闭、载荷上限、响应版本 |
| 操作进度 | operation_id、阶段/真实状态、完成量/总量、可否取消、结构化错误/产物 ref；事件丢失可 pull |
| SDK | v1 插件不被强发不认识的初始化帧；v2 在启动/握手传目录与能力；有限自有/宿主能力调用，不暴露通用 dispatcher |

生命周期要求：

1. 校验来源/归档/兼容性 → 暂存验证 → 安装提交 → 待配置/可用；半成品不进入执行目录。
2. 更新先准备新版本，待在途操作/页面可切换后发布新代次；新增调用复核活动代次，旧确认/旧 schema 不授权新实现。
3. 禁用/卸载先阻止新调用，按有界策略结束在途调用、撤销页面/路由/所有出口，再回收文件；Windows 占用记待清理，不假报物理删除。
4. 数据格式不兼容、没有可靠迁移/恢复时拒绝激活新包，保留旧可用版；包回滚不等于用户数据回滚。
5. GUI 与 CLI 同读安装记录时定义活动版本复核/旧版本使用期，不能只凭进程内锁宣称跨进程一致。
6. 连续崩溃有重启预算/退避；缓存、pending、日志量与旧进程 reader 有上限。
7. 同一稳定 id 只有一个有效来源；官方用户更新覆盖随包版，卸载覆盖版可回退随包版，保留设置与授权。
8. 配置/秘密由宿主现有机制管理；学习数据库不提前创建，未来学习记录不能绑定可重建词库的临时行号。

### 3.4 翻译与词典闭环

**翻译**：人工本次目标 > 当前插件窗口会话目标 > 已保存默认。默认配置不因一次反向操作被修改；中英互译与固定目标分别表达，建议和执行共用策略。源语言未知时如实表达，不把启发式猜测当可靠检测。

保留 translate 文本与 translate_batch 有序数组等旧消费者；页面需要方向/引擎元数据时，使用结构化入口或结果适配，但内层只有一次翻译实现。切目标/引擎/关闭页面使旧响应失效，正文不进入默认日志和跨重启历史。本版没有回译按钮。

**词典**：独立官方插件，主窗摘要、独立窗口详情；明确查词关键词走确定路由，普通单词的混排/划词建议不能抢占应用搜索。依次处理精确词头/词形、短语、前缀/有限拼写建议；多词性/多义不压成单个译文。基础汉英需要中文索引，不能只建英文词头索引后宣称支持。

缺词库给安装入口，无命中给显式转翻译入口，词源缺失如实显示；不自动联网或以 AI 生成填充事实字段。结果操作可携带文本在查词/翻译间切换，目标缺失时保留输入再获取。查词主操作打开详情、次操作复制释义；翻译保持快速复制。

**词库**：构建期裁剪并生成只读索引，基础包与词源增强包独立版本化；保留来源、许可、上游/构建版本和兼容范围。词形还原与词根/历史词源分开。基础查询优先原生进程与本地数据库，不引入必须另装 Python/Node 的门槛；不照搬网络插件 500ms 防抖。数据源已定 ECDICT（MIT）+ wordroot 词源包（见 0.28.4）。

### 3.5 固定范围跨设备同步（已定）

**固定范围不是整个 DB**：所有设备使用同一份已定义的可移植字段清单，不按设备或配置组选择。内部仍按稳定配置项/关联对象进行比较和事务协调，这是合并粒度，不是用户可选同步组。

| 固定共享范围 | 内容 |
|---|---|
| 外观/交互/搜索偏好 | 主题、语言、透明度、结果与建议偏好、可移植功能开关 |
| 快捷键与入口 | 主热键、Chord/全局绑定、可移植禁用/排序和触发词配置 |
| 插件 | 稳定身份、期望启用态、触发词、明确可移植的非秘密设置；不含安装结果和资源路径 |
| AI 与用户配置资产 | Provider/模型非秘密配置与档位/参数，提示词库，超链/自定义搜索；关联引用保持完整 |

默认留本机：API key/secret/token/CM 引用、WebDAV 登录信息、代理、系统自启/日志/引导状态、机器路径、STT/OCR 模型安装/硬件设备、显示器/窗口位置、实际安装状态。AI/MCP 执行授权和确认记忆也不自动漫游，避免把另一台机器的权限当作本机授权。

历史、剪贴板、对话、便签、词库与插件用户数据/学习数据不属于配置同步。新字段按 schema/可移植性明确纳入，不能遍历原始 KV 自动上传；旧客户端必须保留兼容格式中不认识的远端扩展字段，不将其当删除。

“非秘密参数”按类型化白名单导出，不复制任意 JSON/HTTP headers 或只靠字段名猜秘密。系统凭据/秘密字段不导出；提示词正文属于用户明确选择启用的固定配置资产，不承诺对任意正文自动识别并删除用户自行粘贴的秘密。

#### 多设备如何应用同一份配置

- 共享配置表示用户意图，本机有效值可有明确设备覆盖：例如热键被另一程序占用时保留本机可用唤起键，并显示共享值未生效；不能反向把这个自动回退上传成新的全局偏好。
- 未装插件先保留已验证设置为待应用，用户明确安装后接续；缺密钥提示本机填写，不用空字段清空已有密钥，不自动下载或授权。
- 用户显式修改共享范围的设置视为新的共享意图；仅为设备适配生成的覆盖必须带来源/原因，不参加共享差异计算。
- 同步结果列出已生效、待安装、待填密钥、需本机适配和失败可恢复项。共享版本已接收不等于每项均在本机生效，必须如实展示。

#### 内容冲突：共同基线 + 三方合并

每台设备保留共同基线 B，比对本机 L 与远端 R；时间戳仅展示，不决定覆盖顺序。

| 情况 | 处理 |
|---|---|
| 只有本机改了 | 采用本机变更 |
| 只有远端改了 | 采用远端变更 |
| 双方改成相同值 | 自动合并 |
| 修改不同字段/不同稳定 id 项 | 自动合并，完整校验关联约束 |
| 同一字段改成不同值 | 显示本机/远端差异，用户选择；可批量偏向一侧 |
| 删除与修改冲突 | 显式选择保留/删除，不用缺字段猜删除 |
| 同一有序列表双方改顺序 | 作为顺序冲突处理，不盲目按数组位置拼接 |

Provider/模型引用等跨字段约束合并后不合法时提升为关联对象冲突，不能拼出不可用组合。首版有未解决冲突时不提交覆盖，保留双方快照并允许退出/稍后处理；本地正常使用不受影响。首次连接没有共同基线时展示两端状态，显式选择初始化方向/合并。

#### 版本冲突：区分三种版本

1. **应用版本**：设备应用版本不同不自动判冲突；只要快照格式/数据 schema 兼容即可同步。
2. **数据格式/schema 版本**：能无损迁移则在临时快照迁移并验证；兼容新增字段要保留。遇到高于本机支持范围的格式/必需字段时，暂停该设备写入、保留远端，提示升级，禁止把新配置降成旧版覆盖；本地旧版仍可正常用。
3. **远端内容 revision/ETag**：上传前必须校验读到的远端版本。变化时重读、重新三方合并；无冲突可有界重试，有冲突重新展示，不能重放旧确认或按设备时钟强盖。

配置快照要表达稳定 id、缺项/删除记录、schema、内容 revision 和来源设备；同时记录作用字段的本地 revision，预览后本地又修改时重做计划。删除记录的保留/离线设备过旧后的重新初始化策略在 0.28.6 固定，防止复活已删项。

#### WebDAV 连接与目录

设置仅为地址、用户名、密码，以及“测试连接/立即同步/启用”等操作。密码托管在本机凭据存储；同源认证重试，非预期跨域重定向不转发认证。

将地址规范化为用户指定根目录，自动创建其下 blink/；若已明确指向该目录不重复叠加。使用 WebDAV 集合创建/查询，目录存在正常复用；若同名是文件或已有不识别格式，明确报错而不是覆盖。认证失败、无写权限、配额/目录创建失败分别反馈，不要求用户选择具体厂商。

远端布局：规范化根目录下自动建立 `blink/`，`head.json` 指向 `snapshots/<revision>.json` 不可变快照并记录格式/摘要；只能访问/清理本应用约定的该目录。保存有限远端历史与本地备份，不将快照目录当用户任意文件同步。

**首版保护边界**：用户明确不漫游密钥，并要求仅填三项连接信息。本版采用 HTTPS 传输、凭据本机托管，远端保存不含秘密的配置快照；不额外要求独立解密口令，不声称端到端加密，也不从 WebDAV 密码偷偷派生长期数据密钥。HTTP 仅在用户显式配置时提示未加密，不从 HTTPS 静默降级。快照可能含提示词等用户配置资产，首次启用说明固定范围；端到端加密/恢复口令后续另立需求。

#### 提交与失败恢复

预读/校验双方 → 三方合并/解决冲突 → 本地预检/备份并冻结计划 → 上传不可变候选 → 按 ETag 条件更新 head → 复核并应用本地计划 → 成功后推进共同基线。

- 首次创建 head 使用不存在前置条件；并发更新使用已读强 ETag。真实服务器不提供可靠条件写时明确降级备份/恢复，不承诺安全双向同步。
- 网络超时导致结果未知，先读 head 判断候选是否已提交，不盲目重传/推进基线；孤儿候选可受控回收。
- 远端成功而本地版本变化/应用失败，标记远端已提交、本机待重合并/恢复，不强盖本机，不回滚可能已被其他设备读取的远端版本。
- 数据库事务不能回滚的热键等系统副作用由应用协调补偿；同步和本地 UI 共用校验/保存服务，失败不假报全成功。
- 首版先完成手动同步；任何自动触发都复用同一状态机，默认关闭，需验证防抖/退避/自身事件回环后再启用。

协议依据：[RFC 4918 §8.6](https://www.rfc-editor.org/rfc/rfc4918.html#section-8.6)、[RFC 9110 §13.1.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1)。标准协议桩与真实 WebDAV 环境分别验收。

### 3.6 GIF：边录制边压缩素材，编辑后再编码成品

#### ScreenToGif 源码调研结论

ScreenToGif 官方仓库源码核对结论：“边录制边压缩”可行——录制期后台任务消费帧队列并压缩缓存（写盘后释放原始帧），与最终 GIF 编码（独立任务按帧/延时编码）是两个阶段；其采集路径不止一种后端，且缓存队列构造未指定容量。本版借鉴流水线与素材分离，不照搬其实现，并必须自加容量/字节上限。

#### 本版实现策略

~~~text
屏幕采集 → 有界帧队列 → 后台无损压缩/写入素材块 → 释放原始帧缓冲
                                      ↓
                          有界缩略图/按需解码 → 预览与非破坏编辑
                                      ↓
                       冻结时间轴 → 流式 GIF 编码 → 完整成品提交
~~~

- 优先复用当前连续 GDI 采集，先验证短演示预算；不满足采集/光标/CPU 目标时再比较 DXGI/WGC，不因参考 ScreenToGif 就直接引入大套新后端。
- 专用可停止采集 worker 复用 thread_local GDI 资源；压缩与写盘在后台，不在热键线程/前端/异步核心 worker 上阻塞。
- **录制期压缩**使用快速无损素材编码；压缩块可独立解码并有版本/长度/索引/时间戳，不能为了连续压缩比而让随机预览必须从头解整段。压缩库、块大小和落盘策略由阶段原型确定。
- **编辑期**通过 frame_ref、duration、timeline_revision 和编辑命令/撤销表示，分页缩略图、按需解压。原始帧不经 JSONL/前端 IPC，不进入聊天图片 stash，不为撤销复制整段帧。
- **导出期**才做 GIF 调色板、重复帧/差分区域优化和编码；逐帧写目标临时文件，不把所有原始帧或整个成品无界放进内存。录制期直接产出的 GIF 不能作为唯一可编辑素材。
- 静态画面可能压缩较好，但高熵/持续变化画面不能假设压缩率。1280×720×4×15×30 的未压缩帧约 1.54 GiB；压缩不能替代内存/队列/磁盘/时长硬上限。
- 队列按帧数与字节有界；压缩/磁盘跟不上时按明确过载策略合并完全重复帧、受控降采样并累计展示时长，仍不足则停止并保留完整素材，不无界排队或偷偷丢失总时长。
- 单调时钟记录有效播放时间；暂停不入成品。帧时长量化、末帧、丢帧与重复帧合并都保持总时长语义；编辑与编码需冻结同一时间轴 revision。
- 基本功能：固定区域/窗口吸附选区、倒计时、暂停/继续/停止、光标显示、首尾修剪/删帧/撤销、整体速度/关键帧停留/循环、尺寸/FPS/质量预设、进度与取消。点击高亮/跟随移动窗口/按键提示后置。
- 独立全局停止入口不全局吞被录应用 ESC；控制条不入成品。混合 DPI/负坐标、锁屏/休眠/显示器变化、磁盘不足和截图/长截图冲突有可见行为；Alt+Space 主链路仍可用。
- 停止后排空有界队列再交接素材；崩溃不完整尾块可识别，已完成块受限保留并提示恢复。取消导出删除不完整目标，失败保留有限素材可重试，默认不覆盖已有成品。
- 交付真实 GIF 文件并独立解码核对帧序/总时长/循环；复制文件保留动画，不承诺任意目标应用能直接粘贴动画。

### 3.7 工程准入与责任（不是待答产品问卷）

产品方向确定后，各子版本的工程准入项（清单/SDK 字段与撤销时序、页面 IPC 来源与窗口回收上限、词库质量/许可/可重复构建与冷暖时延、同步固定清单与真实服务器 CAS 行为、GIF 采集正确性与队列/内存/磁盘/时长上限及过载行为）由对应阶段自主验证落定，不反复询问用户；结论见各子版本验收。测试矩阵仅为输入，未验结论不写成产品能力。

## 五、子版本实施方案

每阶段都含设计准入、实现、验证、恢复和文档状态更新。以下各子版本按 spec-phase §六 精简规则收敛为结论与关键踩坑；逐项实施流水账、测试名与验收细节留 git log 与各测试模块。

### 0.28.1 — 插件运行时与独立存储

**目标与输入**：基于现有 JSONL/Capability，建立可安装、可激活、可撤销、数据可保留的官方插件运行时。

**实现总结（2026-10-26 完成自动化验收；真机 GUI/CLI 手测已随 0.28.8 收口）**：

- 契约与协议：`domain/plugin/contract.rs` 冻结 manifest 身份/能力并做集合级 tool id/关键词碰撞校验（保留旧 builtin id、不抢占既有入口、支持纯页面插件）；协议 v2 增 `Initialize` 握手帧（仅 v2 插件收到，v1 零变化）。
- 存储与安装：`infra/plugin_storage/` 按 installed/data/cache/datasets/staging 分目录 + `registry.json` 原子安装记录；安全解压拒绝路径穿越/符号链接/超量；安装状态机以 registry 写入为提交点，失败更新保持旧版可用，卸载占用记 `PendingRemove` 不假报删除，启动 `recover()` 清残留。
- 运行时发布：`PluginEngine.plugins` 改快照（`RwLock<Arc<PluginSet>>`），发布器按 owner 准备/发布/撤销并联动路由/hints/配置/AI tool 池/MCP/待确认；**代次复核用 Arc 指针比对而非 generation 数值**——重复发布不产生虚假失效，被替换句柄必然失效；Agent 缓存指纹改为 allowlist ∩ 注册表实际条目；迟到确认仍过代次复核；连续崩溃 3 次进 30s 冷却。
- 接线：安装/卸载/列表命令、插件禁用/启用联动撤出口与路由、CLI `run/capabilities` 只读最小插件环境（stdio MCP 不复活）。
- 已知边界：schema 变化不强制重新确认（tool id 稳定是契约要求）；Windows 真实占用场景手测归 0.28.8。

### 0.28.2 — 独立插件窗口与已安装管理

**目标与输入**：插件自己的 index.html 运行于独立窗口，宿主负责管理与有限 SDK。

**实现总结（2026-10-26 完成自动化验收；多窗中文 IME/Alt+Space/ESC 与整组资源实测已随 0.28.8 收口）**：

- 资源协议 `blink-plugin` 只服务当前快照活跃句柄的包内文件（lexical + canonicalize 双校验、10MB 上限、no-store），插件页带专属 CSP，全局 csp 保持 null 对既有窗口零影响；`@host` 注入面提供 sdk.js（init/invoke/设置/剪贴板/关闭/payload 订阅）与主题 CSS。
- 窗口编排 `app/plugin_surface.rs`：label 归一 + `on_navigation` 白名单（外部跳转拒绝）、关闭=隐藏（会话保留在页面内存）、single-flight 复用 infra `get_or_create_window`、未 ready 载荷 pending 保留最新、更新/禁用/卸载钩子关窗；窗口预算 6，超限回收隐藏且最久未开窗口、不抢关可见窗口。
- 受限桥接 `commands/plugin_ui.rs`：invoke 只放行 manifest 声明且 owner 仍注册的 tool（30s 兜底）；**会话身份以调用窗口 label（Tauri 注入）反查，不信页面自报**；设置返回脱敏版、剪贴板/载荷有上限；安装/卸载/配置写入入口拒绝插件窗口。
- ACL `capabilities/plugin-windows.json` 仅 `core:default`，关闭/隐藏全由宿主执行。已知边界：app 自定义 command 不经 Capability ACL，除已加门禁的入口外，其余隔离依赖“官方来源插件内容可信”。

### 0.28.11 — 词典窗口体验增强：拼写候选召回 + 窗口内双击取词

**目标与输入**：用户两个需求，明确限定**纯插件侧**（宿主/协议/SDK 零改动）：① 词典窗口输入无命中时给模糊匹配提示列表——链路（输入 250ms 防抖即查 → not_found 渲染可点候选行）自 0.28.4 已端到端存在，实际不可用的根因在候选生成质量：拼写候选池是**全库词频前 60 名**（the/of/and 级超高频词），真实拼错的中频目标词根本进不了池，前缀候选又只能命中同前缀词头；② 结果区的英文义项/例句里双击选词，词旁悬浮小卡速查释义。

**实施**：

- **拼写候选池重构**（dict.rs）：池 SQL 由 `ORDER BY freq LIMIT 60`（全库）改为**首字母 LIKE 前缀 + 词长邻域**（`length BETWEEN len-2 AND len+2`——编辑距离 ≤2 的必要条件）+ 词频序 `LIMIT 1000`；`LIMIT_SPELL_POOL` 60 → 1000。索引面 `idx_entries_word` 前缀范围 + `idx_entries_freq` 排序均为现成索引，真库单查询毫秒级（进程级 178ms 含启动+开库，与仅握手基线 179ms 持平）。门槛（3..=24 纯 ascii 小写）、输出 ≤4、spell 优先于 prefix 的合并去重（lookup 管道）不变，主窗快查候选自动同源受益。
- **候选排序改距离优先**：原实现按池遍历序（= 词频序）凑满 4 条提前 break，真库实测 `aple` 会凑满 all/able/age/apply（dist≤2 但更常用）而**挤掉 dist=1 的 apple**。改为全池收集 (dist, freq) 后按距离升序、同距离词频升序取前 4；`edit_distance_within` 布尔判定改 `edit_distance_at_most` 返回实际距离（early-exit 保留）。
- **双击取词浮卡**（page.js/page.css/index.html）：document 级 `dblclick`（排除输入框与浮卡自身）读选区，`/^[A-Za-z][A-Za-z'-]{1,39}$/` 门控单英文词（双击中文文本自然忽略，反查场景不弹卡）；复用 `Blink.invoke("dictionary_lookup")`，独立 `tipEpoch` 竞态守卫（主查询发起/输入/窗口重置即令其在途响应失效）；fixed 定位贴选区下方 6px、溢出视口翻转上方、左右 clamp；内容三态——命中（词头+音标+前 3 行中文释义，空则回退英文义项，附「完整词条/复制」按钮）、未收录（≤3 候选可点回查）、失败（含并发=1 与主查询互斥时的「插件忙」，2s 自动收起）；关闭四途径（卡外 pointerdown / Esc / 任意滚动 capture / 新主查询），Esc 在浮卡打开时只关浮卡不隐藏窗口。样式全语义 token（surface/surface-2/radius-md/shadow-modal/z-dropdown），双主题自动适配；footer 键位提示补「双击取词」。
- manifest version 0.1.0 → 0.2.0；dev 产物已重编（`cargo build -p blink-plugin-dictionary` 刷 target/debug，0.28.10 追加四教训）；`cargo xtask plugins` release 产物同步刷新（builtin/bin 不入 git，发布管线自产）。

### 0.28.12 — 插件中心元数据、卸载系统与 dev 本地目录源

**目标与输入**：插件中心升级为一等分发渠道，为 0.28.13 词典线上化铺基座。三个缺口：① **目录展示元数据不足**——manifest 已有 name/description 双语与 version，catalog 尚无名称/描述/独立页面/稳定度展示字段；包大小复用已有 `asset.bytes`。② **卸载入口与后端时序均需补齐**——已有 `uninstall` 文件清理及 PendingRemove 机制，但 app 命令当前先删文件、再撤运行时，不能只加前端按钮；还需定义数据集保留及随包覆盖版回退。③ **dev 本地目录源缺失**——已有带 dev 门禁的 `install_plugin_package`，尚无 UI 调用方，也不能从本地 pack 产物完成目录到安装的闭环。词典本子版本仍随包不动，线上化在 0.28.13 原子切换。

**实现总结（2026-10-28 实现完成、自动化验证通过；真机 GUI 验收待做）**：

- **manifest/catalog 元数据**：manifest 增 `channel`（stable|beta，缺省 stable、未知值拒绝——静态产物不猜意图）；`CatalogPluginEntry` 增可选 name/description（`LocalizableText`，为此补 PartialEq）、has_pages、channel、updated_at（pack 不填——本机无可靠发布时间，不把文件 mtime 当发布时间；读取侧校验字符集/长度）。大小只消费 `asset.bytes`。旧目录缺省 = 前端回退 plugin_id、无描述行、页面信息未知不显示成"无页面"、channel 按 stable。

- **卸载事务（顺序反转）**：app 命令原顺序"先删文件（进程持 exe 锁高概率占用）→ 后撤运行时"反转为：`begin_uninstall`（registry 写锁内标 PendingRemove——**门禁是命令内第一个操作**，新安装即刻被 PendingRemoveBusy 拒、`active_version_dir` 为 None 启动不复活；data 是否清除的意图**冻结进 pending_paths**，是崩溃/占用后 recover 重试删除的唯一真源，重复调用幂等沿用首次意图）→ 关窗 + publish 撤运行时（杀进程；失败保持不可调用、报可重试错误、**不继续删文件**）→ `complete_uninstall` 清文件（占用更新 pending_paths 如实报告）。原 `uninstall()` 保留为 begin+complete 组合（外部语义不变）。
- **数据保留与随包回退**：确认复用 `choiceDialog` 三选一（默认"卸载（保留数据与词库）" / 第三动作"卸载并清除数据与词库" / 取消），不新造复选框组件；勾选清除时逐条卸载已登记数据集 + 清 datasets 根目录覆盖遗留挂载，占用如实计数并入 pending_files。随包目录存在时按当前启用态重新发布随包句柄（"移除更新并恢复随包版"；配置与授权保留，发布失败不回滚卸载、重启自然恢复）；仅随包插件卸载返回 `bundled_no_install` 结构化错误（前端对无安装记录的插件本就不渲染卸载入口）。随包目录解析从 main.rs 提取 `bundled_plugins_root` 单一真源（debug=仓库源码、release=resource_dir）。
- **待清理可查询**：`get_plugin_surface_status` 对 PendingRemove 记录（已撤出引擎集合、原本不可见）追加占位行；前端渲染"待清理（重启后完成）"行——卸载中断不留隐形状态。
- **dev 本地目录源**：`get_plugin_catalog`/`install_plugin_from_catalog`/`install_dataset_from_catalog` 增 `local_dir` 参数。显式本地源最高优先（不受线上/磁盘缓存遮挡）、加载失败如实报错不静默回线上、**不进两级官方缓存**（每次直读文件，重跑 pack 立即可见）；自动模式降级链补末位本地 pack 产物（仅 debug、默认 target/plugin-dist）；`CatalogResponse` 增 `source`（online/cache/local）。本地资产解析 `resolve_local_asset` 按资产 URL **文件名**定位 catalog 同目录 zip（pack 仍产 HTTPS URL，无需改线上协议）：纯文件名（拒路径分隔/`.`/`..`）、`symlink_metadata` 拒符号链接与目录、canonicalize 前缀拒越界、实际 bytes 须与目录声明一致。`install_local_catalog_zip`（插件与数据集两侧）校验 sha256 后以 **LocalDev 来源**提交（不冒充 Official）；`builtin.*` 命名空间对本地目录源仅 debug 放开（`validate_and_commit` 增 `trusted_namespace` 参数；手选包通道仍 false）——0.28.13 后 dev 可本地装/卸词典做全链路验证。生产门禁三处：命令层 `reject_production_local_source` + 域层 cfg 兜底 + 前端隐藏入口；目录路径只存 localStorage 不落配置 DB（生产不消费 debug 留下的本地源设置）。

#### 实施顺序与数据源准入

1. **先核验真实源文件**：2026-10-28 审查时，上游 [1.0.28 Release 资产列表](https://github.com/skywind3000/ECDICT/releases/expanded_assets/1.0.28)没有现有 CI 所引用的 `ecdict_csv.7z`，不能继续把该 URL 或“约 50MB”作为可用输入。优先验证完整 commit SHA 对应的 `ecdict.csv` 与 `wordroot.txt` raw 地址；[固定 commit 的 CSV](https://github.com/skywind3000/ECDICT/blob/8defb761f7c7ad1818ca94290a1844d7b33d6b23/ecdict.csv)只是候选，不代表已通过本项目质量验收。源锁定记录包含原始 HTTPS URL、完整上游修订、sha256、实际 bytes、格式与许可；同一候选的镜像必须返回相同字节。禁用 master/latest 等可变引用；release tag 地址也必须由期望哈希约束。
2. **再完成下载 → 构建 → 校验 → 挂载原型**：复用词典 exe 的 `--build-basic/--build-ety` 与质量样本，在真实锁定源上验证基础库/可选词源库、来源记录和可重复内容摘要；记录下载量、构建耗时、整组峰值内存及磁盘峰值（源文件/解压/SQLite 临时文件/新旧库/安装暂存均计入）。旧源的约 107MB DB/45s 构建仅为历史参考。未达到质量或限额要求时先调整源/剖面，不先裁掉随包和旧获取链路。
3. **最后原子切换分发**：协议与宿主操作管理验收后，tauri.conf bundle 裁掉词典、manifest `builtin: true` → false、manifest+web 与 examples 源码 crate 合并为自包含插件目录，同步 workspace/xtask 打包扫描及 dev 加载约定。manifest 的 `host.min_version` 与 catalog 的 `host_min_version` 同步抬到支持新协议的宿主版本，插件自身版本也递增，避免同版本资产含不同协议。发布 CI 仅产插件 zip/catalog，不再生成或发布数据包条目。

#### 协议三件套与宿主边界（v2 扩展）

- **能力协商**：新宿主在 initialize 中声明资源获取、数据集构建/挂载相关能力；仅对声明支持的插件启用新流程。init 是握手后的独立操作，不能把分钟级构建放进 initialized 应答；旧 v1/v2 插件不接收未知业务帧。宿主版本预检与运行时能力检查均需成立，缺能力返回结构化不支持。
- **`FetchResource`**：插件提交资源 id，宿主按当前已校验插件版本随包的源锁定声明解析 URL/hash/bytes，不能由运行时消息任意改写期望值。宿主流式下载到该操作的插件 cache 子目录，二进制不经过 http_proxy 文本帧；仅返回宿主生成的资源 ref/受限相对路径，不接受插件任意指定落盘绝对路径。HTTPS、实际写入限额、sha256 校验成功后才交给构建器。
- **镜像与限额**：候选机制覆盖 GitHub release 和 raw 源，保留代理配置；校验失败的候选不得进入构建，最终失败保留分类原因并可重试。下载与解压分别执行限额；基线为单文件 128MiB/总 512MiB，源文件真实大小在准入时复核，不能拿压缩包大小代替展开大小。若需解压，另限条目数、展开量、路径/链接及 CPU/内存预算；每次操作独立目录，失败及时清理。
- **`InstallDataset`**：新增带调用方上下文的宿主入口，复用安装器内部的有界复制、逐文件校验、版本目录和 active.json 提交。插件身份来自所属进程/活动句柄，不信消息自报的 plugin_id；dataset_id 必须在该 manifest 声明中，且 `dataset.json.plugin_id/dataset_id` 与之相符。源目录必须是该插件该操作的受管构建输出，校验真实路径及链接边界；不接任意文件系统路径。记录派生来源（插件版本/源修订与摘要/构建版本及剖面），不复用 `install_dir` 硬编码的 LocalDev 来源，也不冒充官方预构建数据包。
- **提交与失败**：调用与 active.json 提交前均复核操作未取消、插件已启用且代次仍有效；最后复核与提交须同禁用/更新/卸载撤销互斥，避免“检查通过后被卸载、迟到挂载又成功”。失败保留旧可用库；同版本重装与 Windows 旧 DB 占用沿用安装器的隔离/恢复语义。
- **init/修复触发**：安装后已启用或由禁用切为启用时，宿主对声明数据集检查 `missing/corrupt/outdated`，任一成立即进入获取/修复流程；禁用状态不启动后台下载/构建。页面按钮使用同一宿主 begin 入口，不依赖词典已经 ready，也不放宽现有“插件页禁止调用任意安装命令”的门禁。全部兼容时直接就绪，不重复下载/构建。基础库为必备，可选词源单独显示获取状态/重试，失败不撤销已就绪基础库。

#### 长任务、取消与恢复

- **操作模型**：宿主 begin 快速返回 operation_id，后续下载/构建/校验/挂载/完成使用事件与可查询快照；快照包含插件代次、数据集、真实阶段/完成量/总量、可否取消及结构化错误。进度可复用 PLUGIN_CENTER_PROGRESS 与页面 payload 通道，但不依赖窗口一直打开，也不伪造构建百分比。页面隐藏/重开按 operation_id 查询恢复；插件已安装但词库准备中不能显示成“查词已可用”。
- **互斥与撤销**：同一插件/数据集的重复自动 init、按钮重试与多窗口触发合并为一个在途操作；更新/禁用/卸载先阻止新操作并撤销当前代次，再取消下载与构建。宿主管理构建 worker 的进程句柄和有界终止，不允许只杀 JSONL 服务却留下 `--build-*` 子进程；旧代次进度/完成不得污染新会话。跨进程实例不得同时提交同一数据集。
- **cache 与恢复**：源、临时 DB、构建产物位于 `PluginDirs.cache` 下独立 operation 目录；不在 tokio worker/热键线程做重 IO 或 SQLite 构建。取消/失败清理本次临时目录，重启清理孤儿操作后可重试；清扫不得删除仍活跃操作的目录。提交后才能报成功，终态不明确时按 active.json/安装记录核对，不凭页面事件猜测。安装/构建均有总时限与资源预算，发布前记录实测阈值与超限行为。
- **解压决策（工程准入，尚未定案）**：先按真实源格式决定是否需要解压；若固定 raw CSV 已满足准入，不为不存在的 7z 资产引入依赖。确需 7z 时再评估纯 Rust 实现的二进制增量与展开资源；体积可接受则按用户倾向归主应用 infra，反之由插件承载构建所需解压。解压必须显式声明格式，不按文件后缀自动执行；无论归属何处均受宿主任务撤销与预算约束。

**产出与验收（规划）**：

- [ ] 锁定的真实源可下载且 hash/bytes/许可可复核；真实构建通过既有词库质量样本、逐文件与内容摘要校验，性能/磁盘峰值有记录并满足准入预算
- [ ] 全新生产环境：插件中心装词典 → 自动拉源构建挂载 → 查询可用，全程免进入设置页手动装词库；准备中/就绪/失败分别如实显示
- [ ] missing/corrupt/outdated 均可修复；兼容保留库重装跳过构建，旧库低于新 min_version 时能升级；可选词源失败仍可基础查词并单独重试
- [ ] 断网/镜像失败/哈希不符/超量/磁盘满均有分类错误且不提交半成品；源/构建/挂载失败不破坏旧可用库，中断和重启后可重跑
- [ ] 重复 init/多窗口按钮仅产生一个在途任务；隐藏/重开窗口可查询恢复进度；禁用/更新/卸载发生在下载、构建和提交边界时，旧代次不能挂载/复活，受管 worker 退出、活跃目录不被误清扫
- [ ] 跨插件 id/未声明 dataset/任意路径/链接逃逸/伪造资源锁定值请求被拒绝；自举产物来源可追溯且非 LocalDev，现有插件页安装命令门禁不放宽
- [ ] 老宿主被 catalog 与 manifest 兼容预检拦截；v1/旧 v2 插件行为不变。生产禁止 debug 本地安装源，同时允许受管客户端构建挂载及 HTTPS 镜像降级，两者不混用
- [ ] 卸载按 0.28.12 事务清进程/页面/能力/缓存，词库按用户选择保留或清除；词典已无随包回退，重新安装无残留旧代次
- [ ] 发布 CI 仅产插件 zip/catalog（不拉全量 ECDICT、无数据集条目），fixture 构建/查询回归继续保留；锁定真实源与质量样本在发布准入中独立验证；dev 可通过显式本地目录完成装/卸/自举
