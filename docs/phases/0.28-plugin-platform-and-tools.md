# Blink 0.28 — 插件与工具增强（语言工具、配置同步、GIF 与托管媒体引擎）

> **范围**：官方插件运行时、独立窗口与分发，双向翻译、离线词典及客户端自举词库，WebDAV 配置同步，短 GIF 录制/编辑与体验收尾；追加可选 FFmpeg 托管运行时、共享媒体任务与无声 MP4 导出。

## 二、背景与保留的设计

本版将固定插件集合扩展为可安装、可撤销、带独立页面与数据集的官方工具体系，并补齐配置同步和短动图工作流。

追加批次解决同一段录制只能导出 GIF 的限制：现有 BGRA 无损素材与时间轴可以复用，以按需安装的 FFmpeg 提供首个 MP4 出口，并为后续音频转换、媒体信息和抽帧提供共享调用入口。录音机与视频预览尚未立项；FFmpeg 安装成功不代表这些功能已交付。

保留 JSONL、懒启动、总期限/取消、配置 revision/CAS、凭据托管以及纯 data 与展示投影分离。独立插件窗口不要求独立 EXE、WebView2 环境或永久常驻进程；页面可无后端。WebDAV 配置协调与 GIF 高频采集仍由宿主承担，不为插件化复制系统能力。

跨版本规则已归入 [spec-architecture §A7.5](../specs/spec-architecture.md)（调用方、资源与提交边界）、[spec-backend §4.6/§7.7/§十](../specs/spec-backend.md)（生命周期、同步与长任务）、[spec-frontend §1.4](../specs/spec-frontend.md)（动态窗口与主题）；以下只留本版取舍与维护要点。

## 三、核心决策与维护要点

### 3.1 官方分发与插件生命周期

- 生产仅接官方目录；IP/天气/翻译保留稳定身份并随包，词典自 0.28.13 起成为可选线上插件。**0.28.4 的随包词典与 0.28.5 的托管词库包方案已被 0.28.13 客户端自举取代**；插件与词库仍独立版本化。
- 官方更新可覆盖随包版，卸载更新可恢复随包版，保留配置/授权；词典无随包回退。卸载默认保留数据与词库，也可显式清除。PendingRemove 记录冻结首次清理意图，占用和中断在重启恢复。
- 目录信任模型为固定官方 HTTPS 端点与包 sha256，尚无独立目录签名。目录不可达可显示带 stale 标记的缓存，安装不使用 stale 目录。显式 dev 本地源不混入官方缓存，资产经路径/大小/摘要校验，来源如实记 LocalDev；生产拒绝本地安装通道。
- 发布使用独立 `plugins-catalog` Release，与应用 `latest.json` 分开。`cargo xtask pack` 当前生成四款插件及 catalog，不再构建/发布词库包。
- 运行时有效代次通过活动 Arc 句柄身份复核，避免重复发布造成虚假失效；AI 工具缓存取授权集合与实际注册条目的交集。tool id 稳定是契约，schema 变化本身不强制重新确认。

### 3.2 独立窗口、主题与会话

每插件默认一个主窗口，按需 single-flight 创建并复用，窗口预算为 6；超限优先回收隐藏且最久未开的窗口，不抢关可见窗口。ready 前保留最新载荷，更新/禁用/卸载撤销页面。

关闭隐藏时页面内存暂留；翻译/词典**每次唤起均重置为新查询**，带载荷时再预填，正文不跨重启保存。这是 0.28.10 对早期“重开恢复会话”方案的最终收窄。声明 pages 的插件可由主窗触发词空参回车直达首页，缺密钥/词库时仍允许开窗显示修复引导；无页面与空参自答插件保持原语义。IP 的独立页面已移除。

`blink-plugin` 服务活动包内资源，`@host` 提供 SDK、完整语义 token、有效主题及公共滚动条；页面独立 CSP，全局 CSP 保持原设置。`auto` 必须先解析为 light/dark，开发模式需资产直读兜底。曾因只注入主题层、请求不存在的 auto.css 而整窗失去样式，不能只验证静态 CSS 文件存在。

**隔离边界**：页面身份取实际调用窗口 label；自定义 app command 不自动受 core ACL 隔离，除明确门禁外仍依赖官方页面内容可信，不能将当前机制描述为完整沙箱。

### 3.3 翻译方向与会话

方向优先级为人工本次覆盖 → 当前窗口会话 → 已保存默认。0.28.14 将缺省统一为 auto（中→英、其他→中）；配置加载时一次性将旧默认 zh 升级为 auto 并记录版本，之后人工保存的固定目标及原有 en/ja/ko 保留。唤起时方向与引擎重置到默认，新载荷和旧请求以 epoch 隔离，不回写设置。query、单次 tool 与有序 batch 共用翻译实现，旧返回形态保留；未知源语不伪装为可靠检测，无回译检查。

### 3.4 词典、数据源与客户端自举

词典保持 `builtin.dictionary` 身份，源码/页面/构建器收在 `plugins/dictionary/`。ECDICT（MIT）提供英汉、基础汉英、词形/短语，wordroot 提供可选词源；数据源锁定、许可、剖面、质量样本与摘要真源见 [DATASETS.md](../../plugins/dictionary/DATASETS.md) 和同目录 `bootstrap.json`，不在 phase 重复哈希表。

源采用固定 commit 的 raw CSV/wordroot，不依赖不存在的 `ecdict_csv.7z` Release 资产，也不引入 7z 解压依赖。宿主锁定下载与操作管理，插件进程工作线程构建，宿主以 `active.json` 原子挂载，来源记 Managed；握手不承载长构建。启用后按 missing/corrupt/outdated 自动准备，兼容保留库跳过构建，“重建”可强制修复；可选词源失败不阻塞基础查词。

查询走“查词/dict”确定路由，不抢占普通应用搜索。精确词头/词形、短语优先，再给有限拼写/前缀候选；拼写池按首字母与词长窗召回，排序距离优先、同距离再按词频，避免高频远词挤掉 apple 等更近候选。中文反查只覆盖有频率信号的常用概念，长尾如实为空；词源缺失不以 AI 填事实。双击英文义项/例句可弹速查浮卡，独立 epoch 防止旧响应覆盖新查询。

主窗每插件最多一个在途 query 与一个最新待查输入，合并丢弃旧输入；Takeover/Mixed 共用，ToolCall 并发门禁不变。词典前缀候选走词头索引范围，无需重建词库。

**开发与验证坑**：每帧 JSONL 必须 flush，词典曾因 BufWriter 未 flush 而恒超时，直调单测未覆盖真实 stdio。随包 Rust 插件 dev 加载 `target/debug/`，改源码必须重编 debug 产物；已安装包不能被工作区旧 debug exe 覆盖，开发启动也不应把词典源码目录当成已安装插件。

### 3.5 固定范围 WebDAV 配置同步

采用手动同步，设置只有地址、用户名、密码，自动建立/复用 `blink/`。共享外观/交互/搜索偏好、快捷键/入口、插件可移植设置、Provider/模型非秘密参数、提示词库与超链；准确字段以 `config_sync/portable.rs` 为准。秘密、授权、设备状态和用户内容留本机；远端含提示词等配置资产，首版不提供端到端加密或额外恢复口令。

实现按稳定 item id 与独立 `$order` 做三方合并，维护共同基线及本机覆盖；插件分片删除不传播，卸载属本机状态，未装插件设置休眠待接续。远端采用不可变 `snapshots/<revision>.json` 与条件更新的 `head.json`，本地保留 10 份备份；纯追赶不重写远端，弱 ETag 不作 CAS 依据，真实服务器能力不足时如实降级。

WebDAV 客户端位于 domain 的 `config_sync/webdav.rs`，避免 infra 反向依赖域协议类型；本地应用走既有配置保存链。**提示词库实际在 AI 库**，同步服务需分 config/AI 双池；曾因读错库触发 `no such table`，不得静默当空配置，否则会被三方合并解释为批量删除。密码使用固定长度掩码，不能沿用泄漏长度/片段的 API key hint。

### 3.6 GIF 素材、时间轴与导出

采集/过载/素材/编码落 `infra/gif/`，domain 只保留非破坏时间轴；控制条与编辑器是独立系统窗口。采集与压缩使用两条 OS 线程和有界队列，逐帧 zstd-1 独立块写入 spool，索引 flush 后释放原始帧；启动清理超过 72h 的素材，不复用聊天图片 stash。

时间戳决定帧时长，暂停不入成品；过载合并重复帧/受控降采样，仍不足即停并保留素材。编辑以参数投影支持修剪、删帧、速度、停留、循环及 undo/redo；**删帧同时移除对应时长**。导出冻结时间轴，再做调色板/差分矩形优化、流式写临时文件与原子提交；取消删除临时成品，已有文件不覆盖。

两段式准备/录制允许拖动选区，控制条不入成品；GDI 区域与光标统一使用虚拟屏物理坐标。编辑器静默预载并虚拟化连续缩略条。**高熵画面压缩比可能为 1.00×**，压缩不能替代时长/帧数/队列/磁盘硬限；`gif_start_recording` 必须 async，避免同步建窗与 WebView2 初始化互等；IPC 字段采用 camelCase。

### 3.7 FFmpeg —— 可选托管媒体运行时（0.28.17 已落地）

**定案**：设置页展示为“FFmpeg 媒体引擎”，内部扩展 `managed_runtime` 的锁定分发与安装机制；安装一次供宿主媒体功能共用，任务执行时启动独立进程，空闲不常驻。不接入带 STT/OCR 模型契约的 `EngineDefinition`，不创建伪模型、HTTP 服务或常驻 worker。

现有 `managed_runtime` 仍有 Everything 专用的种类判断、PE 自检与许可落地，不能仅追加一条锁文件。按本次两个运行时的需要拆出种类、自检与许可策略，保留 Everything 原行为；不顺带重构脚本解释器、ONNX 和全部下载器。

首版锁定 Windows x64 的一个经验证构建，包含 `ffmpeg` 与同构建的 `ffprobe`，不带 `ffplay`，不回退系统 PATH。0.28.17 验收前须确定发布源、版本/构建身份、URL、摘要、下载及解压预算、exe 相对路径、许可与对应源码获取信息；不运行时追随 latest。安装、更新、修复在 staging 完成校验与实际执行自检后提交，失败保留旧可用版；同版本修复也创建新的产物代次再原子切换，不就地覆盖活动文件。

状态区分未安装、安装中、已安装、校验失败及活动任务数；版本和所需软件编码器的实测决定是否可导出。普通 status 不启动进程，自检由安装、显式诊断或实际任务准备触发并缓存到构建身份；硬件编码支持另行探测，不能以列表存在断言本机可用。未安装不影响既有 GIF、语音输入或未来基础 WAV 录音。

### 3.8 媒体任务 —— 共享适配与有界进程（追加规划已定）

infra 负责受控参数生成、进程/管道、帧输入、编码与验证；app 负责会话、任务身份、调用方、运行时租约和 UI 事件桥接。业务入口调用有限、类型化的操作；首批只落地 MP4 编码及所需元数据/解码验证，不预建所有转换工具。独立原子操作如对外暴露仍遵循 Capability 唯一入口；编辑器内部导出保持 Interaction 协议，不额外向 AI/MCP 开放任意命令行、路径或 FFmpeg 参数。

首版全局至多一个重型媒体任务，不设无界等待队列，冲突返回 busy；帧逐张解压并经有界管道输入，不生成整段原始视频或全量 PNG 中间帧。编码与滤镜线程数显式限制，Windows 子进程隐藏运行；准备、写管道、编码、收尾和验证都计入可配置的总预算。默认时限、帧缓冲、输出/临时磁盘预算在 0.28.18 以最大素材及长停留样例实测定稿，未定稿不标记完成。

任务以 job_id、session_id、revision 与 runtime 构建身份关联，进度与终态可查询，迟到事件不覆盖新任务。取消、超时、调用方结束与应用退出均走同一清理路径：停止输入，终止并等待回收本任务进程，排空/关闭管道，删除临时成品，保留录制素材；stderr 持续读取且只保存有界、脱敏诊断。原子提交前复核取消和覆盖策略，提交成功后如实报告完成，不因迟到取消删除已提交成品。

每个任务固定解析到一个安装版本并持有使用租约；更新可准备新版本，切换不改动在途任务所用路径。卸载期间拒绝新任务，已有任务占用时返回 busy；跨 GUI/CLI 进程也需保护活动产物，旧版和残留仅在无人使用时清理。媒体任务限流与产物使用租约分别管理，不借用 Everything 的独占常驻实例锁。进度读取 FFmpeg 的 `-progress` 结构化输出，不解析人类可读 stderr 百分比；参数语义以 [FFmpeg 官方文档](https://ffmpeg.org/ffmpeg.html) 为准。

### 3.9 MP4 —— 复用素材、按格式适配时间轴（追加规划已定）

首版提供 **GIF / MP4（H.264、无声、单次播放）**。复用框选、GDI/光标、spool、暂停、修剪/删帧/变速/停留与 undo/redo，不改变录制期 120s、帧数和 512MB 素材等预算。MP4 成品更小不能作为放宽素材预算的理由。

新增冻结 revision 的格式中立快照，保留有效帧索引和毫秒时长；GIF 适配器继续执行既有百分之一秒量化、循环、调色板和差分优化，保证旧导出行为不漂移。MP4 直接读取原始素材，禁止先编码 GIF 再转视频。

MP4 首版选 **30fps 恒定输出帧率**，由累计有效时间定位素材帧后流式输入 FFmpeg；停留会重复输出，同一输出时刻只取一张素材帧，短于输出节拍的帧可能不单独出现。不得对每张源帧分别取整后累加；总时长误差至多一个输出帧（约 33.34ms），尾部按累计总时长补足输出节拍，至少输出一帧。输出采样和总时长预算必须考虑变速与长停留，不只按源帧数估算。可变帧率与硬件编码自动择优后置，首版锁定构建内的软件 H.264 编码器提供统一基线。

缩放保持宽高比，采用兼容的 YUV420 像素格式；奇数尺寸补边到偶数且保留有效画面，颜色范围/矩阵显式约定并验证。输出尺寸超编码器能力时明确提示用户缩小，不静默降画质。MP4 仅播放一次，循环选项仅用于 GIF；格式选择联动后缀、文件过滤器、画质预设、进度阶段和统计，禁止把 GIF 采样质量参数或调色板进度直接套到 MP4。

输出到目标目录的唯一临时文件，显式指定 MP4 容器；进程成功退出、元数据与完整解码验证通过后，复用既有文件提交工具原子提交，默认不覆盖。MP4 按输出采样计划验证尺寸、编码、帧数和总时长，不与源素材帧数硬比较；验证阶段也支持取消/超时。安装引导保留当前编辑会话，安装完成后刷新就绪，由用户重新发起导出，避免自动使用已变化的旧编辑参数。
