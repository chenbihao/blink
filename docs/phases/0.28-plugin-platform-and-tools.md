> **范围**：官方插件运行时、独立窗口与分发，双向翻译、离线词典及客户端自举词库，WebDAV 配置同步，录制/编辑与体验收尾；追加 FFmpeg 托管与媒体任务、截图工具栏收纳与二维码分类操作，以及统一截图/录制浮栏、实时涂画、最近录制恢复、音频设备与电平、长录制、空间预估与 60fps。

> **前置**：复用 0.25/0.26 的插件执行、配置/凭据与托管资源，以及 0.27 网络策略；0.27 的修复与验收仍归原 phase。
>
> **原则**：原子执行走 Capability，持续流程属于 Interaction；静态页面无运行时构建；资源有界、失败可恢复；测试不触碰真实用户数据与凭据。

## 二、背景与保留的设计

本版将固定插件集合扩展为可安装、可撤销、带独立页面与数据集的官方工具体系，并补齐配置同步和短动图工作流。

追加批次解决同一段录制只能导出 GIF 的限制：现有 BGRA 无损素材与时间轴可以复用，以按需安装的 FFmpeg 提供首个 MP4 出口，并为后续音频转换、媒体信息和抽帧提供共享调用入口。录音机与视频预览尚未立项；FFmpeg 安装成功不代表这些功能已交付。

0.28.22 解决截图右侧功能持续增加造成的拥挤，并补齐“截图 → 二维码内容 → 复制/浏览器打开/本地文件管理器操作”。现有默认 OCR 阅读图层继续承担直接选字入口，因此默认仅将 OCR 文本面板、二维码识别、翻译并钉图收进“更多”；其余按钮保留现有常驻布局与相对顺序。OCR 预热关闭、引擎不可用或未识别到文字时，不能假定阅读图层存在，仍保留显式 OCR 入口及原有引导/错误反馈。

0.28.23–0.28.25 将短动图工具扩展为“先录制素材 → 编辑 → 按格式导出”的录制工作流。现有准备态复用截图浮栏，开录后换独立控制条，用户可明显感知跳变；暂停/继续和移动区域已有底层能力，重点是统一操作宿主与状态表达。现有帧素材本身可用于视频导出，不需要先生成 GIF 再转视频；涂画先由用户手动管理并直接合成入帧，不建立可编辑标注事件轨。音频、长录制与 60fps 分阶段接入，不能仅删除限额而保留全量预载和旧导出瓶颈。

保留 JSONL、懒启动、总期限/取消、配置 revision/CAS、凭据托管以及纯 data 与展示投影分离。独立插件窗口不要求独立 EXE、WebView2 环境或永久常驻进程；页面可无后端。WebDAV 配置协调与 GIF 高频采集仍由宿主承担，不为插件化复制系统能力。

跨版本规则已归入 [spec-architecture §A7.5](../specs/spec-architecture.md)（调用方、资源与提交边界）、[spec-backend §4.6/§7.7/§十](../specs/spec-backend.md)（生命周期、同步与长任务）、[spec-frontend §1.4](../specs/spec-frontend.md)（动态窗口与主题）；以下只留本版取舍与维护要点。

## 三、核心决策与维护要点

### 3.1 官方分发与插件生命周期

- 生产仅接官方目录；IP/天气/翻译保留稳定身份并随包，词典自 0.28.13 起成为可选线上插件。**0.28.4 的随包词典与 0.28.5 的托管词库包方案已被 0.28.13 客户端自举取代**；插件与词库仍独立版本化。
- 官方更新可覆盖随包版，卸载更新可恢复随包版，保留配置/授权；词典无随包回退。卸载默认保留数据与词库，也可显式清除。PendingRemove 记录冻结首次清理意图，占用和中断在重启恢复。
- 目录信任模型为固定官方 HTTPS 端点与包 sha256，尚无独立目录签名。目录不可达可显示带 stale 标记的缓存，安装不使用 stale 目录。显式 dev 本地源不混入官方缓存，资产经路径/大小/摘要校验，来源如实记 LocalDev；生产拒绝本地安装通道。
- 发布使用独立 `plugins-catalog` Release，与应用 `latest.json` 分开。`cargo xtask pack` 当前生成四款插件及 catalog，不再构建/发布词库包。
- 运行时有效代次通过活动 Arc 句柄身份复核，避免重复发布造成虚假失效；AI 工具缓存取授权集合与实际注册条目的交集。tool id 稳定是契约，schema 变化本身不强制重新确认。

### 3.2 独立窗口、主题与会话

每插件默认一个主窗口，按需 single-flight 创建并复用，窗口预算为 6；超限优先回收隐藏且最久未开的窗口，不抢关可见窗口。ready 前保留最新载荷，更新/禁用/卸载撤销页面。

关闭隐藏时页面内存暂留；翻译/词典**每次唤起均重置为新查询**，带载荷时再预填，正文不跨重启保存。这是 0.28.10 对早期“重开恢复会话”方案的最终收窄。声明 pages 的插件可由主窗触发词空参回车直达首页，缺密钥/词库时仍允许开窗显示修复引导；无页面与空参自答插件保持原语义。IP 的独立页面已移除。

`blink-plugin` 服务活动包内资源，`@host` 提供 SDK、完整语义 token、有效主题及公共滚动条；页面独立 CSP，全局 CSP 保持原设置。`auto` 必须先解析为 light/dark，开发模式需资产直读兜底。曾因只注入主题层、请求不存在的 auto.css 而整窗失去样式，不能只验证静态 CSS 文件存在。

**隔离边界**：页面身份取实际调用窗口 label；自定义 app command 不自动受 core ACL 隔离，除明确门禁外仍依赖官方页面内容可信，不能将当前机制描述为完整沙箱。

### 3.3 翻译方向与会话

方向优先级为人工本次覆盖 → 当前窗口会话 → 已保存默认。0.28.14 将缺省统一为 auto（中→英、其他→中）；配置加载时一次性将旧默认 zh 升级为 auto 并记录版本，之后人工保存的固定目标及原有 en/ja/ko 保留。唤起时方向与引擎重置到默认，新载荷和旧请求以 epoch 隔离，不回写设置。query、单次 tool 与有序 batch 共用翻译实现，旧返回形态保留；未知源语不伪装为可靠检测，无回译检查。

### 3.4 词典、数据源与客户端自举

词典保持 `builtin.dictionary` 身份，源码/页面/构建器收在 `plugins/dictionary/`。ECDICT（MIT）提供英汉、基础汉英、词形/短语，wordroot 提供可选词源；数据源锁定、许可、剖面、质量样本与摘要真源见 [DATASETS.md](../../plugins/dictionary/DATASETS.md) 和同目录 `bootstrap.json`，不在 phase 重复哈希表。

源采用固定 commit 的 raw CSV/wordroot，不依赖不存在的 `ecdict_csv.7z` Release 资产，也不引入 7z 解压依赖。宿主锁定下载与操作管理，插件进程工作线程构建，宿主以 `active.json` 原子挂载，来源记 Managed；握手不承载长构建。启用后按 missing/corrupt/outdated 自动准备，兼容保留库跳过构建，“重建”可强制修复；可选词源失败不阻塞基础查词。

查询走“查词/dict”确定路由，不抢占普通应用搜索。精确词头/词形、短语优先，再给有限拼写/前缀候选；拼写池按首字母与词长窗召回，排序距离优先、同距离再按词频，避免高频远词挤掉 apple 等更近候选。中文反查只覆盖有频率信号的常用概念，长尾如实为空；词源缺失不以 AI 填事实。双击英文义项/例句可弹速查浮卡，独立 epoch 防止旧响应覆盖新查询。

主窗每插件最多一个在途 query 与一个最新待查输入，合并丢弃旧输入；Takeover/Mixed 共用，ToolCall 并发门禁不变。词典前缀候选走词头索引范围，无需重建词库。

**开发与验证坑**：每帧 JSONL 必须 flush，词典曾因 BufWriter 未 flush 而恒超时，直调单测未覆盖真实 stdio。随包 Rust 插件 dev 加载 `target/debug/`，改源码必须重编 debug 产物；已安装包不能被工作区旧 debug exe 覆盖，开发启动也不应把词典源码目录当成已安装插件。

### 3.5 固定范围 WebDAV 配置同步

采用手动同步，设置只有地址、用户名、密码，自动建立/复用 `blink/`。共享外观/交互/搜索偏好、快捷键/入口、插件可移植设置、Provider/模型非秘密参数、提示词库与超链；准确字段以 `config_sync/portable.rs` 为准。秘密、授权、设备状态和用户内容留本机；远端含提示词等配置资产，首版不提供端到端加密或额外恢复口令。

实现按稳定 item id 与独立 `$order` 做三方合并，维护共同基线及本机覆盖；插件分片删除不传播，卸载属本机状态，未装插件设置休眠待接续。远端采用不可变 `snapshots/<revision>.json` 与条件更新的 `head.json`，本地保留 10 份备份；纯追赶不重写远端，弱 ETag 不作 CAS 依据，真实服务器能力不足时如实降级。

WebDAV 客户端位于 domain 的 `config_sync/webdav.rs`，避免 infra 反向依赖域协议类型；本地应用走既有配置保存链。**提示词库实际在 AI 库**，同步服务需分 config/AI 双池；曾因读错库触发 `no such table`，不得静默当空配置，否则会被三方合并解释为批量删除。密码使用固定长度掩码，不能沿用泄漏长度/片段的 API key hint。

### 3.6 GIF 素材、时间轴与导出

以下为已实现基线；0.28.23 规划统一浮栏与定位交互，0.28.24 接入音轨，0.28.25 规划替换全量预载策略，并以分段素材与空间保护替换固定短录制限额。实施前仍按现有限额执行，详见 §5.7–§5.9。

采集/过载/素材/编码落 `infra/gif/`，domain 只保留非破坏时间轴；控制条与编辑器是独立系统窗口。采集与压缩使用两条 OS 线程和有界队列，逐帧 zstd-1 独立块写入 spool，索引 flush 后释放原始帧；启动清理超过 72h 的素材，不复用聊天图片 stash。

时间戳决定帧时长，暂停不入成品；过载合并重复帧/受控降采样，仍不足即停并保留素材。编辑以参数投影支持修剪、删帧、速度、停留、循环及 undo/redo；**删帧同时移除对应时长**。导出冻结时间轴，再做调色板/差分矩形优化、流式写临时文件与原子提交；取消删除临时成品，已有文件不覆盖。

两段式准备/录制允许拖动选区，控制条不入成品；GDI 区域与光标统一使用虚拟屏物理坐标。编辑器静默预载并虚拟化连续缩略条。**高熵画面压缩比可能为 1.00×**，压缩不能替代时长/帧数/队列/磁盘硬限；`gif_start_recording` 必须 async，避免同步建窗与 WebView2 初始化互等；IPC 字段采用 camelCase。

### 3.7 FFmpeg —— 可选托管媒体运行时（0.28.17 已落地）

**定案**：设置页展示为“FFmpeg 媒体引擎”，内部扩展 `managed_runtime` 的锁定分发与安装机制；安装一次供宿主媒体功能共用，任务执行时启动独立进程，空闲不常驻。不接入带 STT/OCR 模型契约的 `EngineDefinition`，不创建伪模型、HTTP 服务或常驻 worker。

现有 `managed_runtime` 仍有 Everything 专用的种类判断、PE 自检与许可落地，不能仅追加一条锁文件。按本次两个运行时的需要拆出种类、自检与许可策略，保留 Everything 原行为；不顺带重构脚本解释器、ONNX 和全部下载器。

首版锁定 Windows x64 的一个经验证构建，包含 `ffmpeg` 与同构建的 `ffprobe`，不带 `ffplay`，不回退系统 PATH。0.28.17 验收前须确定发布源、版本/构建身份、URL、摘要、下载及解压预算、exe 相对路径、许可与对应源码获取信息；不运行时追随 latest。安装、更新、修复在 staging 完成校验与实际执行自检后提交，失败保留旧可用版；同版本修复也创建新的产物代次再原子切换，不就地覆盖活动文件。

状态区分未安装、安装中、已安装、校验失败及活动任务数；版本和所需软件编码器的实测决定是否可导出。普通 status 不启动进程，自检由安装、显式诊断或实际任务准备触发并缓存到构建身份；硬件编码支持另行探测，不能以列表存在断言本机可用。未安装不影响既有 GIF、语音输入或未来基础 WAV 录音。

### 3.8 媒体任务 —— 共享适配与有界进程（追加规划已定）

infra 负责受控参数生成、进程/管道、帧输入、编码与验证；app 负责会话、任务身份、调用方、运行时租约和 UI 事件桥接。业务入口调用有限、类型化的操作；首批只落地 MP4 编码及所需元数据/解码验证，不预建所有转换工具。独立原子操作如对外暴露仍遵循 Capability 唯一入口；编辑器内部导出保持 Interaction 协议，不额外向 AI/MCP 开放任意命令行、路径或 FFmpeg 参数。

首版全局至多一个重型媒体任务，不设无界等待队列，冲突返回 busy；帧逐张解压并经有界管道输入，不生成整段原始视频或全量 PNG 中间帧。编码与滤镜线程数显式限制，Windows 子进程隐藏运行；准备、写管道、编码、收尾和验证都计入可配置的总预算。默认时限、帧缓冲、输出/临时磁盘预算在 0.28.18 以最大素材及长停留样例实测定稿，未定稿不标记完成。

任务以 job_id、session_id、revision 与 runtime 构建身份关联，进度与终态可查询，迟到事件不覆盖新任务。取消、超时、调用方结束与应用退出均走同一清理路径：停止输入，终止并等待回收本任务进程，排空/关闭管道，删除临时成品，保留录制素材；stderr 持续读取且只保存有界、脱敏诊断。原子提交前复核取消和覆盖策略，提交成功后如实报告完成，不因迟到取消删除已提交成品。

每个任务固定解析到一个安装版本并持有使用租约；更新可准备新版本，切换不改动在途任务所用路径。卸载期间拒绝新任务，已有任务占用时返回 busy；跨 GUI/CLI 进程也需保护活动产物，旧版和残留仅在无人使用时清理。媒体任务限流与产物使用租约分别管理，不借用 Everything 的独占常驻实例锁。进度读取 FFmpeg 的 `-progress` 结构化输出，不解析人类可读 stderr 百分比；参数语义以 [FFmpeg 官方文档](https://ffmpeg.org/ffmpeg.html) 为准。

### 3.9 MP4 —— 复用素材、按格式适配时间轴（追加规划已定）

以下保留 0.28.19 的无声/30fps/短素材实现结论；有声音轨及 60fps/长素材分别由 0.28.24、0.28.25 规划扩展，尚未落地。

首版提供 **GIF / MP4（H.264、无声、单次播放）**。复用框选、GDI/光标、spool、暂停、修剪/删帧/变速/停留与 undo/redo，不改变录制期 120s、帧数和 512MB 素材等预算。MP4 成品更小不能作为放宽素材预算的理由。

新增冻结 revision 的格式中立快照，保留有效帧索引和毫秒时长；GIF 适配器继续执行既有百分之一秒量化、循环、调色板和差分优化，保证旧导出行为不漂移。MP4 直接读取原始素材，禁止先编码 GIF 再转视频。

MP4 首版选 **30fps 恒定输出帧率**，由累计有效时间定位素材帧后流式输入 FFmpeg；停留会重复输出，同一输出时刻只取一张素材帧，短于输出节拍的帧可能不单独出现。不得对每张源帧分别取整后累加；总时长误差至多一个输出帧（约 33.34ms），尾部按累计总时长补足输出节拍，至少输出一帧。输出采样和总时长预算必须考虑变速与长停留，不只按源帧数估算。可变帧率与硬件编码自动择优后置，首版锁定构建内的软件 H.264 编码器提供统一基线。

缩放保持宽高比，采用兼容的 YUV420 像素格式；奇数尺寸补边到偶数且保留有效画面，颜色范围/矩阵显式约定并验证。输出尺寸超编码器能力时明确提示用户缩小，不静默降画质。MP4 仅播放一次，循环选项仅用于 GIF；格式选择联动后缀、文件过滤器、画质预设、进度阶段和统计，禁止把 GIF 采样质量参数或调色板进度直接套到 MP4。

输出到目标目录的唯一临时文件，显式指定 MP4 容器；进程成功退出、元数据与完整解码验证通过后，复用既有文件提交工具原子提交，默认不覆盖。MP4 按输出采样计划验证尺寸、编码、帧数和总时长，不与源素材帧数硬比较；验证阶段也支持取消/超时。安装引导保留当前编辑会话，安装完成后刷新就绪，由用户重新发起导出，避免自动使用已变化的旧编辑参数。

### 3.10 截图工具栏 —— 常驻高频流程、按需展开与自定义（0.28.22 已完成）

**定案**：默认仅将 OCR 文本面板、二维码识别、翻译并钉图收进单层“更多”菜单；翻译、长截图、录制、保存、问 AI、钉图维持现有常驻顺序。新增“更多”位于钉图之后，复制截图、取消固定在最右侧；OCR 诊断保持原有位置与开关控制。支持用户主动调整右侧功能顺序和常驻位置，具体交互与边界以 §5.6 为准。

**理由**：默认 OCR 阅读图层已承担直接选字，文本面板不必再占常驻位置；二维码和翻译并钉图按需展开，其他入口保留既有使用习惯。常驻项按用户选择固定，不按使用频率自动重排；窄屏临时收纳只改变当次呈现，不回写用户布局。

二维码在本地解码，结果框沿用 OCR 面板的视觉与定位交互，但保留独立结果状态；识别与打开目标是两次显式操作。解码接入 Capability，内容分类复用公共 URL/路径判定并应用二维码入口白名单，执行复用 `open_url` / `open_path` / `reveal_in_explorer`；不借道主窗口建议排序。截图拖选与结果框生命周期仍归 Interaction，具体动作见 §5.6.3。

### 3.11 录制交互 —— 同一浮栏宿主与手动涂画（0.28.23 已实现，待验收）

**定案**：截图标注、录制准备、录制中、已暂停共用一个可复用浮动工具栏窗口，在原位置切换内容；截图底图、实时透明涂画层和录制范围框独立管理。开始录制后隐藏静态截图底图，保留同一浮栏，不另起可见录制状态栏。涂画直接合成进采集帧，用户手动撤销/擦除/清空，不保存独立标注时间戳或事后编辑标注轨。

**实施取舍（2026-11-03）**：「可复用浮动工具栏窗口」最终由截图 overlay（`chord-screenshot`）本身承担——录制期间 overlay 不隐藏而转为透明叠层，同一 `#toolbar` 宿主在截图标注 / 录制准备 / 录制中 / 已暂停四面之间原地切换，`#annot-canvas` 直接作为实时涂画层。未新建独立浮栏窗口：标注引擎与工具栏的直接函数调用零跨窗口通信，定位/拖动/缩放一套机制贯穿；代价是「操作桌面」模式需后端以 16ms 轮询按命中矩形切换整窗鼠标穿透（§5.7.5）。原 `gif-control` / `gif-region` / `gif-region-handle` 三窗已删除。

**理由**：同一宿主才能保持位置、拖动、菜单和焦点交互连续；仅统一样式仍会留下两套控制条。实时涂画先满足演示中的标记与清理，后续是否增加标注时间轴或录后修改另行决策。播放定位所需的素材时间与音画同步时间继续保留。

编辑器同时提供“最近录制”与主窗口注册入口，恢复尚未过期的素材及已保存编辑进度；沿用临时素材清理语义，不建立永久媒体库，详见 §5.7.4。

### 3.12 音频 —— 双源素材、同一有效时间轴（0.28.24 规划已定）

**定案**：录制准备态选择无声、麦克风、系统声音或双源，声音设备默认使用系统默认设备并允许自选，准备/录制态按来源显示竖向电平。两类声音独立采集和保存；采集静音不保存真实声音，编辑器静音只影响回放/导出。画面与音频共同开始、暂停、继续和停止，异常暂停允许更换同类设备并显式恢复，剪辑使用同一有效时间映射；MP4 可携带声音，GIF 导出明确不含声音且不删除原音轨。详细静音、设备与恢复规则见 §5.8。

**理由**：保留独立来源便于录后调音，并避免把暂停、剪切或变速后的声音与画面错开；音频素材不经过 STT 文本处理链，也不顺带建立独立录音机。

### 3.13 长录制 —— 空间可见、资源有界与 60fps（0.28.25 规划已定）

**定案**：取消固定录制时长、帧数和 512MiB 素材限额，展示实际临时占用与剩余空间；导出显示成品大小估算和目标磁盘空间。同步改造素材/索引、编辑和导出，移除对应短素材限额，并增加 60fps 采集与 MP4 输出。队列、缓存、单次解码及并发保持有界，低磁盘空间自动暂停并保留素材，用户处理后手动继续或停止。

**理由**：可录制长度由实际资源决定；长素材不能全量预载，60fps 也不能只增加前端选项。估算是范围提示，不是磁盘预留或最终大小承诺，执行时仍须检查实际空间与写入结果。

长素材改造覆盖帧源、索引、编辑命令返回、撤销/快照、恢复与导出，不只限制图片缓存；画面/双源音频按共同提交边界恢复。后台估算可被正式导出抢占，必须等旧进程与租约回收后交接，不能让估算导致用户导出收到 busy。

## 四、复用与范围边界

复用插件 JSONL/Capability/路由与配置 CAS/凭据托管、托管存储的暂存校验/原子指针、窗口 single-flight/ready/主题、GDI 截图/框选及 xtask。插件/词库不强套 EngineId，GIF 不强套插件页面协议，插件发布不套用应用更新清单。

0.28.1–0.28.16 未包含 MP4；追加批次仅按 §3.7–§3.9 纳入可选托管 FFmpeg 与无声 MP4 导出。复用 `managed_runtime` / `InstallReporter` / 下载源与网络策略、GIF 素材与时间轴、`commit_file` 和既有设置页，不引入 Rust FFmpeg FFI 或运行时前端构建。

0.28.17–0.28.21 原批次不含录音机、剪贴板音频历史、多格式音频/视频转录导入、外部视频缩略图/预览播放、通用转码工具 UI、长录屏/录屏音轨/摄像头/多轨特效、自动硬件编码、用户自选 FFmpeg/PATH 与任意来源安装。其中录屏音轨、长录制现由 0.28.24/0.28.25 追加立项，其余仍排除；FFmpeg 本身不为 WebView2 安装解码器。

词汇学习/生词本/记忆曲线课程、回译检查/发音/AI 词源兜底、社区市场/任意来源生产安装/通用 OS 沙箱/自动依赖安装、全量内容或密钥同步/自动安装授权/端到端加密继续排除。GIF 点击高亮、跟随移动窗口与按键提示后置；WebDAV 自动同步未实现。

0.28.22 复用截图/图片编辑会话取图、OCR 面板定位与缩放、现有配置存储、图标/i18n/键位提示、公共 URL/路径判定及三类打开/定位 Capability。首版不重排左侧标注工具、不新增二维码生成/条形码识别/摄像头扫码、不自动执行支付/Wi-Fi/应用专用协议、不自动上传识别内容；不新增独立识别窗口或自动扫码常驻任务。普通截图与历史图片编辑纳入识别入口；长图仅在原图裁剪与资源预算可保证时开放，否则明确禁用并提示，不为扫码无界编码整张长图。

0.28.23–0.28.25 复用标注工具/渲染逻辑、浮栏定位与缩放、录制状态机、区域移动、素材租约、时间轴编辑和共享媒体服务；为实际多来源需要拆出可实例化的标注状态与格式中立素材入口，不复制截图与录制两套实现。保留静态前端与 Capability/Interaction 边界，新增内部控制协议只服务受限会话，不暴露任意窗口/事件/编码参数分派。

最近录制复用素材目录、`gif_list_sessions` / 会话读取/删除、编辑器 single-flight 与 TTL/租约；现有列表逐项打开完整索引的策略不能直接沿用到长素材列表。新增轻量摘要与编辑草稿，不复用文本编辑器的正文模型、不另存一份画面；素材、草稿、设备身份、电平和临时历史均不进入 WebDAV 可移植配置同步。

本次不含录后标注轨编辑、自动清空/消退、帧内容重绘、独立录音机、STT 转录、任意视频文件导入、摄像头、多轨剪辑台及固定画面继续讲解模式。动态 WebP 作为后续格式出口保留方向，不占 0.28.23–0.28.25 的交付承诺；GIF/MP4 先完成上述能力。中间素材编码、音画同步容差、空间预留阈值与高帧率支持矩阵在对应版本实施时实测定稿，不先宣称性能达标。

### 5.6 0.28.22 — 截图工具栏收纳、自定义布局与二维码识别（已完成）

#### 5.6.1 默认布局与更多菜单

```text
[左侧标注工具…] │ 翻译  长截图  录制  保存  问 AI  钉图  更多… │ 复制截图  取消
```

| 位置 | 默认顺序与行为 |
|---|---|
| 常驻功能 | 翻译 → 长截图 → 录制（GIF / MP4）→ 保存为文件 → 问 AI → 钉图；保持现有相对顺序及启动、完成和退回语义。“更多”置于钉图之后；OCR 诊断保留现有位置与开关控制，默认隐藏，不移入更多。 |
| 更多菜单 | 默认功能项仅为提取文字（OCR 文本面板）→ 识别二维码 → 翻译并钉图；底部分隔后为“自定义工具栏…”。翻译、保存等其他功能仅在用户主动自定义或窄屏临时溢出时才进入更多。 |
| 固定完成/退出区 | 复制截图 → 取消，不允许隐藏、移入更多或重排；双击选区及已有快捷键继续可用。 |

- 默认 OCR 预热、静默阅读图层和直接选字体验保持原有设置与行为。“提取文字”只改变入口位置，继续负责展开/关闭 OCR 文本面板；不能把收纳解释为关闭 OCR，也不能把二维码结果混入 OCR/翻译图层。
- “更多”点击切换，点击外部或执行普通菜单项后关闭；一次只开一个工具菜单。菜单显示图标、名称、已有快捷键及必要的禁用原因，不再叠加横向第二排或级联子菜单。
- 菜单支持键盘进入、方向键移动及 Enter 执行；Esc 先关闭当前菜单或结果面板并把焦点还给合理入口，再按才进入原有截图退出链。文本输入、标注、录制准备等现有 Esc 优先级不能被通用菜单监听抢走。
- 普通截图、历史图片编辑、长图编辑、录制准备等状态沿用各动作原有可用性规则；收纳或排序不改变权限和任务门禁。混合 DPI/靠屏幕边缘时按视觉尺寸换向、钳制，菜单过高时内部滚动。

#### 5.6.2 自定义顺序与常驻位置

- “更多 → 自定义工具栏…”在截图内打开布局面板，分为“常驻工具栏”和“更多菜单”，支持拖动排序、跨区移动、键盘可用的上移/下移及移入另一分区；只编辑右侧功能，左侧标注与固定完成/退出区保持既有布局。
- 编辑时不触发真实动作、不修改选区或标注。提供保存、取消、恢复默认；恢复默认只更新待保存布局，保存成功再生效，失败保留编辑内容并提示。关闭布局面板后返回当前截图，不跳转设置窗口打断会话。
- 设置页现有截图配置处提供同一布局的编辑入口，复用布局模型与配置写入逻辑。布局持久化到截图配置分片，使用稳定动作 id 与两个有序分区，不以 DOM 顺序或 localStorage 作为真源；配置变更走现有广播与并发写入保护。
- 每个可配置动作恰好处于一个分区；诊断、自定义入口不参与用户排序。旧配置缺字段时使用默认布局；重复/未知 id 清理，缺失及升级新增动作按稳定默认次序追加到“更多”，不覆盖用户原有排序。
- 常驻项可按喜好增加；当前屏幕放不下时，从用户常驻顺序末尾开始临时收进“更多”，保留相对顺序，并始终保证更多、复制截图、取消可见。可用宽度按目标显示器与实际缩放计算，临时收纳不写回配置、不随鼠标悬浮反复跳动；返回足够宽的显示器后恢复用户布局。

#### 5.6.3 二维码识别与文本结果框

- 从当前选区的原始图片像素解码，排除标注、OCR/译文嵌图和工具栏。普通截图复用后端会话裁剪，历史图片复用图片编辑会话；禁止为取图把全屏 RGBA/PNG/Base64 经 JSON 回传后端。解码器及输入像素、结果数量/字节、并发与超时预算在实施时以样例验证定稿，不增加模型下载或云端依赖。
- 点击“识别二维码”显示识别中状态；结果框显示完整原始文本、数量和复制操作。多个结果按画面从上到下、从左到右排列，同内容去重，可切换逐项查看/复制；首版文本区可选择但只读，长内容内部滚动，不截断实际复制内容。
- 结果框复用 OCR 面板的定位、拖动、缩放、主题与屏幕边界机制，独立保存二维码结果，不携带翻译/嵌图设置。OCR 与二维码结果面板同时只展示一个，切换不清除有效识别缓存，也不关闭已有 OCR 阅读图层。
- 内容分类复用公共 URL/路径判定与类型化动作描述，前后端执行相同的二维码来源白名单；不复制判定逻辑、不经过主窗口建议召回/排序。公共 `is_url` 认可的 FTP、`file://` 等不能一律投影成浏览器按钮，不改变其他调用方的协议契约。

  | 内容 | 结果框动作与执行 |
  |---|---|
  | HTTP/HTTPS | 显示完整原文及解析后的真实目标域名；“浏览器打开”调用 `open_url`。 |
  | 本地绝对目录路径 | “打开文件夹”调用 `open_path`。 |
  | 本地绝对文件路径 | “在文件管理器中定位”调用 `reveal_in_explorer`；首版不提供直接执行/默认程序打开文件。 |
  | 本地 `file://` URI | 按 URI 规则校验并解码为本地绝对路径，再按文件/目录投影；保留原文用于展示和复制，不靠剥前缀/字符串替换猜路径。 |
  | 其他 URI、网络路径或普通文本 | 展示、复制；不增加自动唤起或网络探测。 |

- 原始内容按文本渲染，不拼入 HTML。域名猜测、裸地址补协议、FTP/支付/Wi-Fi/应用专用协议及远程 `file://` authority 不进入首版打开范围；本地路径类型/存在性核验在阻塞隔离任务中完成，执行时复核。不可用路径保留复制并显示原因；URI 百分号、中文/空格、转义和盘符必须按解析结果处理。
- 打开/定位必须由用户点击，经对应 Capability 执行；系统成功受理后收起截图层并清理会话，失败保留结果和选区并反馈。成功受理不宣称目标页面已加载或文件管理器已完成定位。该链路既有 command/Capability 的诊断日志也须屏蔽二维码正文、完整 URL/路径，仅记录动作类型与错误码等必要信息。
- 未识别到二维码是正常空结果，提示调整选区后重试；引擎错误、资源超限分别反馈。再次点击入口切换结果框显隐，同会话同选区复用结果；保留显式重新识别操作。
- 在途识别绑定自有图片快照/资源引用、编辑会话 epoch、选区 revision 与请求 id；重新框选、切换图片、重新识别、关闭结果框或退出使相关展示请求失效，旧结果/错误不回填新会话。限制重复并发，关闭窗口后不再读取旧 DOM/Canvas；内容不进入日志或自动持久化。

| 已暂停 | 保留工具与区域，明确显示“已暂停”、计时停止，暂停按钮原位改为“继续录制”；可整理涂画和移动区域。 |
| 停止/取消 | 停止等待素材收尾后收起浮栏、打开录制编辑器；取消按现有丢弃语义清理，不把暂停或关闭小菜单当取消。 |

- 开录和暂停不创建第二条可见状态栏；原正式录制控制条及区域独立抓手入口收敛到统一浮栏，范围框/绘图层可以保留独立窗口。工具栏位置和用户拖动位置连续，内容宽度按固定锚点变化并钳制到目标屏，状态/结束操作尽量保持稳定位置；弹层统一跟随宿主。
- 工具栏抓手只移动工具栏；“移动录制区域”按钮按住拖动采集范围，尺寸固定，松手保持拖动前的录制/暂停状态。录制中移动会进入成品，用户可先暂停再移动以跳过过程，不隐式自动续录。
- 准备态返回截图保留选区与标注；同一录制会话的准备/录制/暂停转换保留有效涂画，结束后释放，新会话不串内容。现有截图输出和录制启动/停止语义保持，显隐及状态按后端成功结果提交。
- 浮栏与画面窗口通过带会话身份、epoch/revision 的快照与受限指令协作，前端 ready/pull 兜底事件先到；启动/停止/切换期间的迟到消息不得复活旧 UI 或重复启动。绘图/采集资源有自身生命周期，不依赖已隐藏或清理的截图 DOM/Canvas。
- 独立宿主按现有 single-flight/预热规则复用，避免永久保留新旧两套控制窗；点击设置、文字输入和关闭弹层后焦点返回正确目标，操作桌面模式不持续抢焦点。Esc 按文本输入/弹层、准备态返回、录制会话的各自规则分派，不从任意子控件直接丢弃整段录制。

#### 5.7.2 手动管理的实时涂画

- **先验证通路再拆窗口**：在浮栏与标注引擎大改前，以当前捕获实现验证透明显示层、采集排除与帧合成通道；桌面持续更新、进行中笔画入帧、半透明仅合成一次、工具栏/边框/文字输入框不入帧同时成立后，才扩大改造。记录通路与资源基线，后续替换捕获后端时复验同一契约。
- 复用截图的工具描述、按钮/分组、颜色/粗细/字体设置与绘制逻辑，拆出可实例化画布和会话状态；不复制一份录制专用引擎。首批支持画笔、箭头、矩形/椭圆、文字、数字、高亮、仅擦标注的橡皮及撤销/重做/清空；模糊、马赛克、放大镜等依赖实时底图的效果待独立验证适配，不用旧截图底图覆盖实时画面。
- 截图中已有受支持标注转换为录制区域局部坐标；存在模糊/马赛克等未适配效果时，明确列出并阻止开始录制，用户须返回截图主动清除或替换。准备态返回截图仍保留原标注；不得静默丢弃效果或让用户误认为原遮挡继续生效。
- 默认操作桌面模式鼠标穿透，已有涂画继续显示；切到涂画模式后透明绘图层接收指针，退出涂画后恢复穿透。文字输入只在编辑文字期间取得焦点，输入框、工具栏、范围边框不进入录制成品。
- 涂画直接、且仅一次合成进实时采集帧，进行中的笔画也应被记录。用户不清空则持续显示，清空/撤销仅改变之后的画面，已录画面不追溯修改；暂停期间的修改在继续后的画面生效。图层坐标相对录制区域，移动区域时跟随。
- 本版不存独立标注事件轨、标注时间戳、自动消退或录后标注编辑；画面帧时间戳继续服务正常播放与后续音画同步。透明显示层与采集合成的具体通道需验证预览/成品一致，避免重复捕获叠层；不经 JSON 持续回传整幅原始帧。

#### 5.7.3 录制编辑器与交互进度条

- 窗口标题、页面标题、会话标题及中英用户文案统一为“录制编辑器 / Recording Editor”，覆盖 GIF/MP4；内部历史文件名、窗口 label 和 IPC 不为改名机械迁移。
- `play-progress` 改为可聚焦的滑动定位控件，提供可抓取播放头、当前时间/总时长与足够的点击热区。单击定位，按住拖动连续浏览，拖动开始暂时停止播放，松手提交位置并恢复拖动前的播放状态；键盘支持方向键和 Home/End，保留逐帧步进与空格播放。
- 悬浮在进度条上显示小窗目标帧与时间，不改变当前播放、播放头或编辑多选集合；离开后关闭。播放定位与编辑选择分开维护，定位不隐式执行编辑操作。

- 悬浮/拖动按需取帧、合并连续请求，优先最新目标；先显示已有缩略图再补清晰图，缓存与在途解码有界，按会话/编辑 revision/请求序号丢弃旧回流。0.28.24 加音轨后拖动预览保持静音，提交定位才同步声音位置；全量预载与长索引改造归 0.28.25。

### 5.8 0.28.24 — 录屏音频采集、编辑回放与导出（规划）

#### 5.8.1 来源与素材生命周期

| 声音模式 | 采集与呈现 |
|---|---|
| 不录声音 | 默认保留无声录制流程。 |
| 麦克风 | 默认系统默认输入设备，可展开自选；显示实际设备名、竖向电平与启用状态。 |
| 系统声音 | 默认系统默认播放设备，可展开自选，采集其系统输出并显示来源/竖向电平；首版不做单应用声音隔离。 |
| 麦克风 + 系统声音 | 两路分别选择设备、采集/保存与显示竖向电平；预览与导出按各自编辑静音/音量混合。 |

- “系统默认设备”是选择策略，每次开始录制解析为实际设备并完成就绪核验；保留无声为默认声音模式，不强迫用户每次选设备。设备选择只在准备态及异常暂停恢复态开放，正常录制中不热切换；默认设备变化或原设备失效时不静默改源，提示实际状态并在需要重建采集时进入异常暂停。指定设备不可用不能悄悄回退默认设备。
- 画面或任一路声音采集失败，由宿主统一协调在共同有效时间边界暂停全部来源，排空或裁定边界外在途缓冲，保留已录素材并记录原因；部分启动/恢复失败应回收本轮已打开资源并保持暂停/准备态，不能出现一源继续、一源已停而 UI 显示录制中的状态。允许在异常暂停态重试原设备或选择同类替代设备，记录设备/格式/时间分段；全部来源核验成功后用户手动继续，不可恢复时可停止进入编辑器。
- 录制浮栏的“采集静音”按来源生效：按统一时钟边界切分音频块，静音区间不写入真实声音，只丢弃该区间的在途样本并记录静音区间，以静音占位保持音画连续；取消静音只影响之后采集，录后不能恢复该区间原声。编辑器的静音是可撤销混音设置，只影响预览/导出，不删除已录原声；二者使用明确文案与独立状态。
- 准备态在用户选择有声模式后进行设备试音/电平检测，离开准备/退出时释放；录制浮栏显示每个已启用来源的独立紧凑竖向电平条与峰值/过载提示，双源不以一条总电平替代。电平来自实际采集并按采集静音门控后的样本，后端聚合 RMS/峰值、节流发送数值，前端平滑衰减；不经 JSON 传音频样本。正常无声、采集静音、暂停与设备异常使用独立状态，暂停/失效清除旧峰值或置灰，不把残留动画显示成持续采集中。
- 音频底层可复用既有设备抽象，素材与 STT 文本处理及语音输入会话分开；协调设备资源冲突，不抢停现有语音任务。素材、设备句柄与在途缓冲由录制会话持有，结束/取消/退出统一收尾，不把音频正文写入日志。
- 麦克风与系统声音分别保留未作编辑混音的源音轨，采集静音区间只保留静音描述；记录采样率、声道和可映射到同一时钟的时间，统一开始、暂停、继续、停止。暂停不保留音频空段，采样延迟和时钟漂移需要校正，不能靠帧序号推算音频位置。
- 录制状态/声音状态复用 0.28.23 的同一浮栏，音轨调节与回放放录制编辑器内；不引入另一条声音控制栏或独立录音机。当前素材目录、租约与清理保护同时覆盖画面和声音，失败/缺引擎仍保留可重试素材。

#### 5.8.2 音画编辑与输出规则

- 编辑器支持音画同步播放/暂停/定位，每路音量/静音即时影响预览和下一次导出；悬浮帧预览及拖动试听默认不发声。播放主时钟统一调度声音与画面，不能独立使用两套互不校正的计时器。
- 修剪/删帧按对应原始时间区间同步剪掉声音，撤销/重做恢复同一映射。先处理帧时长：延长停留时保留原音频并为新增时长补静音；缩短时保留对应区间前段、裁掉剩余声音。再应用全局变速，音频跟随且默认保持音调，不复制人声填充停留。
- MP4 增加有声导出，按编辑后的音画快照冻结音量/静音/时间映射；全静音或无声来源仍可导出无声音轨的 MP4。GIF 明确提示“此次导出不包含声音”，不删除素材中的音轨；循环次数继续只影响动图。
- 检查托管运行时实际音频编码/混音能力，采用类型化参数和既有媒体任务服务，不暴露任意参数。成功条件同时验证音视频流、时长、同步及解码，失败/取消只清理本次临时成品，不破坏素材或已有目标文件。
- 首版同步容差和静音/混音/变速样例在实施时以自动产物分析及用户试听定稿并记录；沿用录制限额，扩大时长与空间能力统一在 0.28.25 实施。

#### 5.8.3 音画契约与异常素材恢复

- 接音轨前确定格式中立帧源、可分页索引、原始时间→有效时间区间映射及编辑 revision/增量查询契约，兼容旧 spool；0.28.24 可在现有限额内实现，但音频不得绑定全量 `frames[]`、前端帧序号或为每张画面帧复制一段音轨/滤镜。0.28.25 在同一契约下替换存储/索引，不重做声音语义。
- 每路素材记录时间范围、格式、提交状态及来源分段，宿主维护共同可恢复边界。异常恢复默认以画面与所有应有非静音音轨均有效覆盖的共同边界为终点，保留已提交前缀；显式采集静音区间按静音覆盖计算，设备失败或未提交音频不能冒充正常静音。越过共同边界的尾数据隔离保留供诊断/后续重试，首版不自动拼接出一段伪完整音画。
- 恢复必须在取得租约并确认无活动写入器后进行，校验索引/长度/时间单调与草稿素材身份；缺失/半写尾块不污染完整前缀，共同边界之后的编辑定位按确定规则钳制并提示。最近录制显示异常/已恢复及截断边界，经用户打开后才能进入可编辑态；无有效画面前缀时明确不可恢复。

### 5.9 0.28.25 — 长录制、空间预估与 60fps（规划）

#### 5.9.1 取消短素材限额并打通全链路

| 截至 0.28.21 的限制 | 本版目标 |
|---|---|
| 录制 120 秒、帧数按 fps × 120 秒封顶、素材 512MiB | 取消固定产品限额，不按录制时长/累计帧数/固定素材体积强制结束，按真实空间和处理能力运行。 |
| 选区最大 2560×1600、录制最高 30fps | 取消无依据的固定最大选区限制，按捕获/编码能力和资源校验；增加 60fps，实际支持矩阵以实测记录为准。 |
| MP4 最多 3600 源帧、编辑后 10 分钟、成品 256MiB | 同步移除短素材限制，以分段/流式处理及实际目标空间判断，不能录完才被旧门禁挡住。 |
| MP4 固定 30fps、导出固定总期限 30 分钟 | 支持输出 60fps；总期限按任务规模合理计算并保留无进展检测/取消，持续工作的长任务不受旧固定期限截断。 |

- 取消固定产品限额不取消合法尺寸/整数溢出、损坏素材校验，以及内存、队列、解码块、并发和进程保护；单帧限额随已验证尺寸和资源预算重评，不能只放开前端尺寸而被后台旧 16MiB 帧上限拒绝。
- 采用分段素材与可增量读取索引，帧源兼容现有素材及后续编码视频分段；中间编码以长录制/高动态/60fps 的 CPU、磁盘和画质实测选择，保留原有无托管引擎 GIF 路径，新增路径的依赖如实提示。标注仍在采集阶段合成，不因此新增标注轨。
- 编辑器只加载可见缩略图、播放头附近和悬浮定位所需帧，取消全量缩略图/全尺寸预览预载；索引分页/分段，编辑命令返回 revision/增量和可分页视图，不再每次序列化完整有效帧表。撤销采用有界增量/共享结构，导出冻结轻量不可变视图，草稿增量或分块持久化，避免每次复制整段大状态；批量选择/删除也不在 IPC 展开无界帧号数组。导出逐段读取、增量采样，不把整段原始图像或所有输出采样点展开到内存。
- 时间、计数与尺寸计算使用可检查的足够位宽，录制有效时间/暂停排除/音画时间映射跨段连续。录制、编辑、导出期间的素材租约覆盖全部分段，清理不得移除活动或编辑中的素材；保留完整段及可收尾数据供失败后重试。
- 分段提交先落素材/索引，再原子发布含画面与各音轨时间范围的检查点；写满、编码失败或异常退出后按 §5.8.3 的共同边界恢复，不只判断文件是否存在。故障覆盖视频已提交/音频尾段未提交及反向次序、检查点半写、缺段和重启；旧单文件素材沿用原尾块恢复适配，不强制原地迁移。

#### 5.9.2 临时占用、磁盘空间与不足处理

| 位置 | 显示内容 |
|---|---|
| 录制准备态 | 临时素材所在磁盘与当前可用空间。 |
| 录制中/已暂停 | 紧凑显示本次素材实际占用、磁盘剩余空间，展开可看画面/声音占用及近期增长速度；未稳定时不伪造可录剩余时长。 |
| 导出面板 | 当前参数下预计成品大小范围、目标磁盘可用空间、预计额外空间需求；临时素材盘与目标盘分开判断，同盘合并计算需求。 |
| 导出中/完成 | 实际已写入成品大小与可取消状态，成功后显示真实成品大小。 |

- 实际占用计入画面、音频、索引和在途临时文件，按节流快照更新，不在 UI 热路径递归扫描整段目录。磁盘可用空间反映其他程序的实际占用变化；跨盘、盘符不可用和空间查询失败均如实反馈。
- 低空间时先告警；达到预留阈值自动暂停画面与声音，保留收尾空间和已录素材，用户释放空间后手动继续或停止进入编辑器，不自动续录、不删除当前素材。阈值结合写入速度、在途缓冲及分段收尾需求实测定稿；突然写满/设备移除时尽力收尾可用段并明确报告失败边界。
- 导出启动及执行中复核目标空间，估算不作为空间预留；编码/验证临时占用按真实提交策略计算。失败/取消保留录制素材，已有导出文件保护及原子提交规则继续有效，不自动删除用户成品。

#### 5.9.3 导出大小估算与帧率

- 修改格式、有效时长、输出尺寸、帧率、画质或音量/音轨设置后更新估算。有码率目标时由时间与码率估计；内容相关编码采用有界的代表片段抽样，动图兼顾帧变化和调色板等因素。显示“预计范围/估算中/暂无法估算”，不把压缩素材大小直接当成品大小。
- 抽样复用媒体任务限流和运行时租约，作为低优先级可抢占任务；正式导出到达时取消估算，等待该估算进程/管道回收及租约释放后再取得任务槽，交接等待有界且可取消，不靠 busy 让用户反复点击。正式任务在途时新估算直接跳过，多个正式任务仍沿用现有冲突规则；不扩大重型任务并发或增加无界队列。参数连续变化合并计算，按会话/编辑 revision/导出参数代次撤销旧估算，结果不串会话；估算不能完整导出一次，也不阻塞正常导出。
- 帧率选项扩展为 10/15/24/30/60fps，保留原默认值；采集节拍、预算判定、状态、素材元数据、预览和导出全部接通 60fps。显示目标帧率与实际采集表现，过载降速/停止明确反馈，不能静默声称保持 60fps。
- MP4 默认匹配素材名义帧率，允许显式选择支持的输出帧率，包含 60fps；采样按累计时间计算，不用固定整数毫秒逐帧累加。GIF 保留独立的帧率/延时适配，UI 不承诺所有格式都能无损表达相同时间精度。
- 本版必须完成长时间真实采集/编辑/导出和 60fps 测量，检验当前捕获实现是否足够；必要的采集/素材适配在本版内完成，具体后端选型不提前写成已交付结果。持续录制的 CPU/磁盘、空闲回落、主窗口输入及取消响应均纳入验收。

#### 5.9.4 内部实施与验收关卡

1. **长素材底座**：先沿用既有产品限额验证 §5.8.3 契约的分段读写/恢复、分页索引、增量编辑/撤销/草稿和逐段导出；核对所有格式及历史列表不再依赖全量帧表。
2. **空间保护**：接入实际占用、双盘空间和低空间共同暂停/收尾，故障测试通过后才统一移除短素材门禁，不提前放开录制却留下导出旧限额。
3. **60fps**：在扩大 UI 选项前验证采集、合成、中间存储及导出吞吐。1080p60 原始 BGRA 流量约 475MiB/s，仅作通路预算参考，不等同实际落盘量；静态与高动态分别实测，达不到支持矩阵时调整捕获/中间编码路径后再验收。
4. **大小估算**：最后接入有界抽样、导出抢占与误差展示，复验长会话和 P0 主链路。四关均属于 0.28.25，不单独分配测试/验收版本；中间关卡通过不等于本版全部完成。

- [ ] 准备态与录制浮栏显示各来源独立竖向电平及峰值/过载，双源不合并为一条；用合成静音/已知幅值样例验证数值与门控，前端仅接节流数值。正常无声、采集静音、暂停、失效可区分，旧峰值不伪装继续采集；试音和退出后释放设备。
- [ ] 采集静音区间含在途样本均不保存真实声音，取消静音后仅恢复后续采集、原声不可录后恢复；编辑器静音/音量可撤销且一致影响预览/MP4。双源独立素材、混音设置及编辑草稿可重启恢复；切会话/停止/取消/退出释放设备/缓冲，画面与声音均受租约保护。
- [ ] 任一来源失效时全部来源在共同有效边界暂停，部分启动/恢复失败回收本轮资源；拔出设备后可在异常暂停态重试或选择同类替代设备，核验后手动继续或停止保留素材，不静默热切换/续录，不出现单源继续而 UI 显示正常录制。
- [ ] 用可检测的画面标记/音频脉冲样例核对开始、中段、末尾及多轮暂停恢复后的偏差；记录并满足实施时定稿的同步容差，不按帧数推算声音位置。
- [ ] 修剪、删帧、撤销/重做、延长/缩短停留和全局变速按 §5.8.2 处理对应音频，累计时长正确，新增停留不重复人声；seek/拖动后播放位置一致，悬浮预览不发声。
- [ ] 接入音轨前评审分页帧源、原始/有效时间区间及增量编辑契约，音频不依赖全量前端帧表、不按每帧复制音轨/滤镜；旧 spool/无声音轨兼容。画面与音轨尾部提交不同步、缺失/半写音轨、显式静音及设备异常样例按共同边界恢复，不把缺失声音补成未告知的正常静音；历史入口显示恢复范围及草稿定位回退。
- [ ] MP4 实际包含预期音视频流，混音、静音、保音调变速、时长与解码验证通过；GIF 明示不含声音且原音轨保留，无声旧素材仍可编辑导出。
- [ ] 编码能力缺失、混音/编码失败、取消、磁盘写入失败及旧导出快照回流有自动化覆盖，保留源素材和已有目标文件；不把原始声音或识别正文写入日志。
- [ ] 用户人工试听麦克风、系统声音和双源混音，复验实际播放器的同步、拖动与末尾；旧 GIF/无声 MP4、语音输入和编辑器听写回归结果单独记录。

### 6.8 0.28.25 长录制、空间与 60fps 验收（待实施）

- [ ] 录制/素材/编辑/采样/导出全链路不再以 120 秒、fps × 120 帧、512MiB、3600 源帧、10 分钟、256MiB 或旧固定 30 分钟导出期限作产品拒绝条件；仍拒绝损坏/溢出数据，取消及按规模设置的任务期限有效。
- [ ] 隔离素材测试越过旧时长/帧数/体积边界，跨段暂停/恢复、剪辑、seek 与音画映射正确；索引/查询分页、编辑返回增量、批量编辑有界、撤销/快照/草稿不逐次复制全段，导出增量采样。内存与队列不随总时长线性堆积，不全量预载或展开所有源/输出帧；最近录制列表仅分页摘要与可见缩略图。
- [ ] 素材/索引/共同检查点提交顺序及原子发布有故障测试：视频段已提交但音轨尾段未提交、反向次序、检查点半写、缺段及重启恢复；完整前缀可打开/导出，异常尾部隔离、截断范围如实提示，活动写入器与清理不能并发破坏恢复，旧素材无需原地迁移。
- [ ] 准备/录制/暂停/导出中的实际占用、剩余空间、增长速度、额外空间需求正确区分素材盘/目标盘；模拟其他程序占用、空间查询失败、低空间、写满及盘符失效时按约定暂停/收尾并保留可用素材，不填满真实用户磁盘做测试。
- [ ] 大小估算随格式/尺寸/帧率/画质/音轨/有效时长更新，抽样有界且可取消，旧结果不覆盖新设置；静态/滚动/高动态、有声/无声样例记录估算区间与实际大小的误差，不以估算代替执行期空间检查。
- [ ] 估算运行中立即发起导出可取消估算并在其进程/管道/租约回收后有界交接，不返回由估算造成的 busy、不并行启动两个重型任务；交接取消/失败可重试。正式任务中估算跳过，多个正式任务仍受原有门禁；迟到估算不覆盖正式任务状态。
- [ ] 10/15/24/30/60fps 从准备态到元数据/状态/预览/导出一致；MP4 可实际输出 60fps，累计采样无固定整数毫秒漂移；过载真实帧率/降速反馈准确，GIF 使用自身延时适配。
- [ ] 完成至少 30 分钟录制→编辑定位→导出的真实长会话，以及 1080p 30/60fps 和高动态/较大选区的支持矩阵；记录实际帧率、音画偏差、CPU/内存/磁盘增长及导出峰值，未达目标时调整捕获/素材路径后再验收，不把仅有 60fps 按钮视为交付。
- [ ] §5.9.4 四道内部关卡分别记录结果：底座通过后接空间保护，空间/全链路门禁通过后放开限额，60fps 通路验证后开放选项，最后验收估算抢占及误差；全部通过前不标记本子版本完成。
- [ ] 低空间暂停后的手动继续/停止、取消/失败重试、当前素材不被清理、旧素材读取和无托管引擎 GIF 路径回归通过；活动任务结束后资源回落，无残留写盘进程。
- [ ] 真实窗口/播放器与主窗口唤起输入由用户验收；自动化验证空间决策、索引/时间映射、产物和限流，应用版本仅在对应实现与约定验收完成后同步。
