# Blink 0.18 — 增强与 Chord 体验（Enhancement: Chord）

> **范围**：bug 修复合集；pin 图翻译捷径；截图控件级智能吸附（UIA）；便签即时预览编辑（IR）；托盘菜单重组；命令执行（`> ` 前缀调起终端）；NSIS 卸载清理收敛；Alt/Chord 键值底层状态流转重构；截图多屏混合 DPI 坐标收敛。
>
> **状态**：✅ 已完成。
>
> **动机**：0.17 后日常使用暴露多处交互断点（AI 右键复制、AI 失焦关窗、pin 右键失效、便签隐藏断链），同时 chord 能力的"快"尚未充分释放（截图翻译三步、缺命令直达）。0.18 在不引入大架构变更的前提下补全这些断点。
>
> **前置**：0.17（Cherry Markdown 统一、主窗口 AI 架构）；0.15（截图重设计、pin 图）；0.16（剪贴板图片、共享 Markdown）。
>
> **原则**：0.18.0～0.18.6 不做大架构变更；0.18.7 是为解决 Alt/Chord 多真源状态异常追加的输入基础设施重构；命令执行 MVP 只做"调起终端"不做内联终端（PTY）。

## 二、背景与动机

### 2.1 为什么 0.18 做这件事

0.17 闭环后日常深度使用暴露四类问题：AI 交互断点（右键无复制、输出后失焦关窗）、pin 图断链（右键 CSS bug、翻译需三步）、便签编辑形态退回纯文本（需按 IR 形态重做）、chord 入口零散（托盘菜单扁平、缺命令直达）。0.18.7 是安装后发现 Alt/Chord 前后端四套状态互相补偿不可靠，追加的输入基础设施重构。0.18.8 是多屏混合 DPI 下截图坐标偏移的修复。

### 2.2 明确"不是问题"的（避免误改）

| 项 | 结论 |
|---|---|
| 便签"关闭只隐藏、删除才移除"语义 | **有意设计**（0.16.8）。0.18 只修"隐藏按钮"的副作用断链，不改语义 |
| pin 不做完整 word 拖选阅读模式 | **有意设计**。要 word 交互需重新 Alt+A 截图 |
| annotation-engine 与截图 overlay 的耦合 | **已解耦**（独立引擎，命令栈驱动）。pin 编辑复用需先抽容器接口 |

## 三、核心设计 / 决策

### 3.1 pin 图：翻译捷径 + 右键修复

- **pin 右键失效根因**：`pin.css` 的 `#ctx-menu` 基础规则写成 `display:none`，ID 选择器特异性压过 `.hidden` 类。改 `display:flex` 一行修复。
- **翻译捷径**：截图工具栏"翻译"右侧加"翻译并 pin"按钮。流程：OCR + 翻译嵌图 → 等翻译完成 → `doPinSelection`（内部已含选区+标注+overlay 合成）。保留原文/译文 tab 联动（活图优于死图）。

### 3.2 便签：即时预览编辑 IR（0.18.3）

- **IR ≠ WYSIWYG**：IR（Typora 式）输入 markdown 语法实时渲染、存储 markdown 文本；WYSIWYG 语法完全隐藏、存储 HTML。Blink 要的是 IR。
- **选型 Tiptap**：Cherry 全系不支持 IR（spike-A 确认）。Tiptap（ProseMirror 底层）通过 inputRules + `@tiptap/markdown` 实现 IR 体验 + markdown 存储。esbuild 自打包 IIFE 单文件放 `vendor/`，运行时零构建（同 `cargo xtask icons` 性质，详见 spec-frontend §1.5）。

### 3.3 托盘菜单重组（0.18.4）

重组后结构：显示主窗口 / 便签管理 + AI 对话窗口 / 设置 + 关于 / 退出。不做自定义样式窗口（性价比低）。

### 3.4 NSIS 卸载清理收敛（0.18.5）

- **PREUNINSTALL → POSTUNINSTALL**：Blink 清理是"补删默认模板删不到的目录"，放 POST 更顺。
- **守卫**：`$UpdateMode`（升级跳过）+ `$DeleteAppDataCheckboxState`（勾选才删），复用 Tauri 默认模板变量。
- **目录错配**：Tauri 默认删 `com.blink.launcher`，实际数据在 `blink`，需钩子补删。
- **凭据清理**：keyring crate 改用 `.blink` 后缀后，`findstr` 从 `"blink/"` 改为 `"blink"` 覆盖新旧命名。
- **版本耦合**：此结论基于 tauri 2.11.5，升级时需复核模板变量定义。

### 3.5 命令执行 MVP（0.18.6）

- **MVP 范围**：`> ` 前缀 + 命令 → 调起外部终端执行（wt.exe 优先，cmd.exe fallback），不在主窗口内联渲染。不维持 shell 会话。
- **命令模式状态机**：`> ` 出现 → 进入命令模式（停搜索、停 ghost、显示 hint）；退格删 `>` → 恢复搜索。模式切换铁则：不互相污染。
- **内联终端推迟**：xterm.js + conPTY 工作量大、与无 bundler 铁则有张力、对常驻内存有威胁。MVP 先验证产品价值。

### 3.6 截图控件级智能吸附（0.18.2）

- **降级链**：控件吸附（UIA）→ 窗口吸附（Win32 现状）→ 纯手拖。控件优先于窗口 hit-test。
- **遮挡绕开**：用 `ElementFromHandle(fg_hwnd)` 而非 `ElementFromPoint`（后者返回 overlay 自己）。
- **超时 + 深度双重约束**：1000ms deadline + 15 层深度，替代白名单。逐层 BFS（`TreeScope_Children`）而非一把 `TreeScope_Subtree`——COM 调用无法 cancel，subtree 超时后后台仍在跑。放宽至 15 层 / 1000ms 是因 WPF/Office 常需 3-4 层、Electron 第 5 层仍是 chrome 容器，原 3 层 / 200ms 过于保守。
- **配置驱动默认关闭**：`control_snap: bool`（default: false），`false` 时不发起后端调用，零回归。

### 3.7 键值底层状态流转重构（0.18.7）

以单线程 `InputStateMachine` 统一 Raw Input、WH_KEYBOARD_LL、tap/hold timer、窗口 visible 和主窗口视图上下文；后端成为 Alt 与 Chord Session 的唯一真源。

- **单线程输入引擎**：Hook 线程同时承载 LL Hook + message-only window + Raw Input + Timer + 纯 reducer。Hook 回调无锁、无 DB、无 Tauri、无 await。
- **双源采集**：Hook 是动作边沿 Pass/Swallow 唯一权威；Raw Input 只校正修饰键 level。同一 Win32 时间域做乱序过滤。
- **四类独立 ID**：`gesture_id`（down→up）、`chord_session_id`、`window.revision`（show/hide 乱序）、`ui_revision`（前端去重），互不串用。
- **Chord Session 后端拥有**：前端只上报离散上下文，不反向修改物理状态。
- **Voice 集成**：`VoicePhase` 三态（Idle/Starting/Recording）替代独立 atomic。~~generation-aware wiring~~（gesture_id 硬编码 0，乱序防护未接入；单用户无已知 bug，不做）。
- **配置快照**：Hook 线程持有不可变 `InputConfigSnapshot`，配置更新统一调 `refresh_input_config` 推送。`state.rs` 不依赖 domain/Tauri/Win32。

### 3.8 截图多屏混合 DPI 坐标收敛（0.18.8）

**dpr 用法四类分类**（关键知识，改截图 dpr 必读）：

| 类 | 用途 | 处理 |
|---|---|---|
| **A** | 屏幕坐标换算（CSS↔物理） | 按屏查 dpr（`dprAtCss`/`cssToScreen`） |
| **B** | 输出裁剪尺寸（CSS→物理尺寸） | `cssSizeToPhysical` |
| **C** | 主 canvas bitmap 映射 | **保留 overlay dpr**（物理上无法按屏分段） |
| **D** | canvas 绘制粗细/线宽 | **保留直读** `devicePixelRatio` |

其他：跨 dpr 边界选区 clamp 到起点屏；pin 拖拽去掉多余 `* dpr`（PerMonitorV2 下 `screenX/Y` 已是物理像素）；剪贴板钉图居中改 `GetCursorPos`+`MonitorFromPoint`。

## 四、复用与范围边界

### 4.1 不进 0.18 的项

| 项 | 理由 |
|---|---|
| 主窗口内联终端（xterm.js + conPTY） | 工作量大、无 bundler 张力、常驻内存威胁。MVP 先调起外部终端 |
| pin 图复用 annotation 编辑 | annotation-engine 需先抽容器接口，工作量超预算 |
| 截图翻译"译文烧进图"静态方案 | 不可逆、丢联动。已选保留联动的活图方案 |
| 便签隐藏/删除语义重设计 | 现有语义有意设计，只修副作用断链不改语义 |
| 托盘菜单自定义样式窗口 | 性价比低 |
