# Blink 0.21 — Capability 唯一执行入口与统一功能目录（Execution Unification & Feature Catalog）

> **范围**：建立调用来源、运行时要求与出口策略类型墙；把旧 `execution::Action` 全量分流为 Capability / Interaction / descriptor；统一 Search、Chord、菜单、AI、CLI、MCP 的原子执行落点；提供面向用户的功能目录和独立 AI/MCP 授权管理；最终删除 Action 执行链路与双 Registry fallback。
>
> **状态**：📋 规划中。
>
> **动机**：0.14 已保证 AI 只经 Capability，但本地搜索和 Chord 仍保留 Action 体系，造成入口 metadata、真实执行目标、危险策略和设置页状态可能漂移。0.21 完成物理收敛：Capability 是唯一原子执行入口，持续人机流程留在所属 Interaction，入口只保存 descriptor/binding。
>
> **前置**：0.14（Capability 协议与投影）、0.17.8（AI 确认记忆）、0.19（便签/pin/ImageStash 能力闭环）、0.20.0（统一可见错误反馈）。不依赖 0.20 的剪贴板、截图或颜色后续子版本。
>
> **原则**：每个子版本保持编译和现有入口可用；先建立策略类型墙再迁业务；原子能力不合并成巨型 dispatcher；功能/Capability/binding id 分栏；代码级出口策略是硬上限；用户授权不能绕过风险确认；MCP 首版禁止 Dangerous；插件不得取得通用 Blink UI 控制权；完成迁移前不得删除旧链路。

## 二、当前基线与问题

### 2.1 当前物理状态

- `Capability` 仍复用 `execution::DangerClass`。
- `InvokeContext` 只有 `env + deadline`，不能表达调用来源和 GUI/headless 运行时。
- `CapabilityError` 仍包含 `ExecError` 转换。
- `ActionRegistry` 注册 13 个内置 Action。
- `ChordRegistry` 注册 6 个同时实现 `Action` 的 ChordAction。
- `BuiltinEngine::ACTIONS` 同时承担关键词/Context metadata 与旧 action id 映射。
- `run_builtin_action` 存在 ActionRegistry/CapabilityRegistry fallback。
- AI 构建时可以从 Registry 装配全量 Capability，缺少用户单项 allowlist。
- MCP 已有 `exposed_capabilities` 和 list/call 双门禁，应保留为外部授权真源。

### 2.2 目标边界

| 概念 | 唯一职责 | 不负责 |
|---|---|---|
| Capability | 稳定 id、有限参数、明确结果的一次原子调用 | 持续等待用户拖选/输入 |
| Interaction | 截图、取色、编辑、录音等持续会话 | 第二套通用原子执行 Registry |
| Binding descriptor | Search/Chord/Menu 的触发、按键、呈现、target | 业务执行与风险真源 |
| ResultAction | Copy/Preview 等展示短路径，或 Capability 参数绑定 | 重复实现 Open/Reveal 等副作用 |
| FeatureCatalog | 面向用户聚合身份、标题、分组、来源、target 和状态投影 | 复制 Capability schema/风险策略 |

### 2.3 完成定义

只有同时满足以下条件才算完成：

1. 所有原子副作用最终只调用 `CapabilityRegistry::invoke`。
2. Interaction 状态只存在于所属领域服务。
3. Search/Chord/Menu 不实现重复业务逻辑。
4. AI/MCP/local 在 invoke-time 都经过来源和策略门禁。
5. `src/domain/execution/` 旧 Action 类型和双 fallback 删除。

## 三、核心类型与安全决策

### 3.1 调用来源与运行时能力（已定）

```rust
pub enum InvocationOrigin {
    LocalSurface,
    LocalCommand,
    LocalAi,
    Cli,
    Mcp,
}

pub enum RuntimeRequirement {
    Headless,
    Gui,
    MainProcess,
}

pub struct RuntimeCapabilities<'a> {
    pub surface: Option<&'a dyn SurfacePort>,
}

pub struct InvokeContext<'a> {
    pub env: &'a dyn CapabilityEnv,
    pub origin: InvocationOrigin,
    pub runtime: RuntimeCapabilities<'a>,
    pub deadline: Option<Instant>,
}
```

- `LocalSurface`：搜索、Chord、菜单等用户直接入口。
- `LocalCommand`：Tauri command 的兼容/Interaction 内部编排。
- `LocalAi`：主窗口 AI 和独立对话窗口，确认粒度仍按现有模式区分。
- `Cli`：无 GUI 默认环境。
- `Mcp`：外部 MCP server 调用，即使 server 运行在主进程也不能伪装成本地用户入口。

### 3.2 CapabilityPolicy 是静态硬上限（已定）

```rust
pub struct CapabilityPolicy {
    pub allowed_origins: OriginSet,
    pub runtime_requirement: RuntimeRequirement,
    pub danger: DangerClass,
    pub sensitive: bool,
    pub ai_default: AiDefault,
    pub mcp_default: McpDefault,
    pub confirmation: ConfirmationPolicy,
}
```

- `Capability::policy()` 是风险、出口和运行时要求的唯一真源。
- `CapabilitySchema.sensitive` 兼容期从 policy 投影；完成后不得保存第二份可漂移值。
- Registry 在实际 invoke 前检查 origin、runtime 和用户授权；UI 隐藏/tool list 过滤只是第一层。
- `DangerClass` 从 `execution` 迁到 capability policy/trust 模块，AI 确认与审计消费同一类型。

### 3.3 SurfacePort 最小权限（已定）

GUI Capability 只获得语义化端口，例如：

```rust
trait SurfacePort {
    fn open_settings(&self) -> Result<(), SurfaceError>;
    fn open_sticky_manager(&self) -> Result<(), SurfaceError>;
    fn open_chat(&self, prefill: Option<&str>) -> Result<(), SurfaceError>;
    fn open_clipboard_mode(&self) -> Result<(), SurfaceError>;
    fn start_region_capture(&self) -> Result<(), SurfaceError>;
    fn start_image_editor(&self, source: EditorSourceRef) -> Result<(), SurfaceError>;
    fn start_content_editor(&self, request: ContentEditorRequest) -> Result<(), SurfaceError>;
}
```

禁止向所有 Capability 暴露 `emit(event)`、任意 window label、完整 `DomainEnv` 或 Tauri handle。插件 Capability 永远拿不到 SurfacePort。

### 3.4 AI 推荐 allowlist（已定）

首次升级且不存在 AI 单项配置时，生成并持久化“推荐” allowlist：

- 代码允许 `LocalAi` 且 `DangerClass::Safe` 的普通生产能力默认开启。
- Safe + sensitive 的普通读取能力也默认开启，但调用时仍走现有 sensitive 确认；“允许进入 tool 池”不等于免确认。
- Dangerous、仅本地、诊断信息采集和诊断恢复类默认关闭；诊断类是上述 Safe 默认规则的显式例外。
- 用户修改后以持久化的 capability id 集合为真源；未来新增 Capability 不自动进入已有用户的 allowlist，需显式启用。
- 纯对话模式仍为空 tool 池。

配置：

```json
{
  "schema_version": 1,
  "profile": "recommended",
  "enabled_capabilities": ["..."]
}
```

`profile` 只记录初始化来源，不在每次启动重新套默认；一旦持久化，后续只读 `enabled_capabilities`。

### 3.5 MCP 首版禁止 Dangerous（已定）

- `McpServerModeConfig.exposed_capabilities` 继续是 MCP 单 Capability 授权真源，默认空。
- 代码级不允许 `InvocationOrigin::Mcp` 调用 Dangerous Capability；设置 UI 显示不可用 `—`，不能被配置强行打开。
- Safe + sensitive 可由用户显式暴露；显式加入 MCP allowlist 即该出口授权，仍记录审计，但 0.21 不设计逐次 GUI 确认。
- GUI/attention-changing Capability 默认不允许 MCP；若未来开放，需单独决策，不能仅因 server 运行在主进程就获得 GUI 权限。

### 3.6 功能、能力、binding 身份分栏（已定）

```rust
FeatureId("blink.region_capture")
CapabilityId("start_region_capture")
BindingId("chord.screenshot")
```

- 旧 chord 配置键 `screenshot` 作为 binding migration alias 保留，不与既有 headless `screenshot` Capability 冲突。
- 一个 Feature 可包含一个 Capability target 和多个 local bindings。
- 本地列展示 binding 聚合状态；AI/MCP 列展示 Capability id 授权状态。
- FeatureCatalog 不假设三类 id 同名。

### 3.7 本地开关保留各 binding 真源（已定）

为避免统一 UI 反而破坏入口语义，0.21 不强行把搜索禁用、Chord 键位、Context binding、插件生命周期写进一个新总开关：

- 搜索内置动作继续迁移并保留原 disabled id 的兼容存储。
- Chord enabled/key 继续由 chord config 管理。
- Context binding 继续按 binding key 管理。
- 插件 enabled 继续由插件页管理。
- 功能目录的“本地”状态是这些 binding 的聚合投影；组/行级操作调用各 binding store 的批量 adapter。
- 部分启用显示三态，不制造覆盖上游插件生命周期的第二份总开关。

## 四、复用、存量分流与范围边界

### 4.1 内置 Action（13 项）

| 旧 id | 目标 | AI 推荐默认 | MCP | 备注 |
|---|---|---|---|---|
| `open_settings` | Safe GUI Capability | 开 | 禁止 | 打开设置即完成 |
| `sticky_manager` | Safe GUI Capability | 开 | 禁止 | 打开管理器即完成 |
| `edit_clipboard_image` | Safe GUI Capability → ImageEditor Interaction | 开 | 禁止 | 返回“已启动、等待用户” |
| `lock` | Dangerous Capability | 关 | 禁止 | AI 启用后仍逐次确认 |
| `shutdown` | Dangerous Capability | 关 | 禁止 | 逐次确认，不可记忆 |
| `restart` | Dangerous Capability | 关 | 禁止 | 逐次确认，不可记忆 |
| `sleep` | Dangerous Capability | 关 | 禁止 | 逐次确认，不可记忆 |
| `clear_history` | Dangerous Capability | 关 | 禁止 | 返回实际删除数 |
| `exit_blink` | Dangerous local-only Capability | 关 | 禁止 | 代码级仅 local |
| `open_logs` | Safe GUI Capability | 开 | 禁止 | 需 MainProcess/GUI |
| `open_data_dir` | Safe GUI Capability | 开 | 禁止 | 需 MainProcess/GUI |
| `blink_print_debug_info` | sensitive 诊断 Capability | 关 | 默认关、可显式开 | 返回结构化诊断，复制属 ResultAction |
| `blink_debug_inithook` | local-only 诊断恢复 Capability | 关 | 禁止 | 只允许明确本地入口 |

系统操作必须逐项保留稳定 id、参数、确认和审计，禁止合并为 `system_operation { operation }`。

### 4.2 Chord Action（6 项）

| 旧 binding | 目标 | 说明 |
|---|---|---|
| `voice_input` | binding descriptor + Voice Interaction | 删除空 Action；Alt hold 状态机仍属 chord/voice |
| `chat` | `open_chat` GUI Capability + binding | 打开窗口即完成，可由本机 AI 推荐开启 |
| `screenshot` | `start_region_capture` GUI Capability + binding | 与 headless `screenshot` 明确分离 |
| `clipboard_history` | `open_clipboard_mode` GUI Capability + binding | 打开模式即完成 |
| `edit` | `start_content_editor` GUI Capability + binding | 结构化 prefill；不把保存当作已完成 |
| `sticky` | 绑定既有 `create_sticky` Capability | 删除重复创建实现 |

`ChordAction` 重构为纯 descriptor/binding trait，不再有 `execute()`，也不继承 Capability。

### 4.3 SearchAction / ItemAction

| 当前变体 | 目标 |
|---|---|
| `SearchAction::Open` | `InvokeCapability { open_path/open_url, args }` |
| `SearchAction::Copy` | 保留纯 ResultAction Copy |
| `SearchAction::LazyCopy` | 保留受控展示短路径，或绑定 `read_*` 后再 Copy；不得进入 AI tool |
| `SearchAction::RunAction` | 改为显式 Capability/Interaction target，不再 action id fallback |
| `ItemAction::OpenFile/OpenUrl/Reveal` | 逐步投影为 `Invoke { capability_id, args }` |
| `ItemAction::Copy/Preview` | 保留展示层专用变体 |

兼容 wire 枚举名可以暂留一版，但后端执行必须落到 Capability，禁止复制 Open/Reveal 业务实现。

### 4.4 不进入 0.21

| 项 | 理由 |
|---|---|
| MCP Dangerous 逐次确认协议 | 首版代码级禁止，未来有真实需求再设计 session/确认通道 |
| 任意插件控制 Blink 窗口/事件 | 违反最小权限和信任边界 |
| 把所有本地 binding 配置迁入单一总开关 | 会丢失 Search/Chord/Context 各自语义 |
| 巨型 `system_operation` / `open` Capability | 会损失单项授权、确认和审计粒度 |
| 运行时把 descriptor 动态包装为 AI tool | AI tool 只能来自代码允许且用户授权的 Capability |
| 重命名所有兼容 IPC/wire 枚举 | 可保留协议壳，但内部执行必须先收敛 |

## 五、分子版本实施方案

### 5.1 0.21.0 — 策略类型墙与门禁

1. 新建 `capability/policy.rs`，落地 origin、policy、runtime、confirmation。
2. 迁移 DangerClass，提供短期 re-export 减少一次性 churn。
3. 扩展 InvokeContext，并逐个更新 AI、MCP、CLI、本地 command、测试 fake 构造点。
4. 建立只读 SurfacePort 注入；无 GUI runtime 为 None。
5. Registry invoke 前执行代码级 origin/runtime 门禁，新增 `Unsupported` 或明确 `Permission/InvalidState` 错误，禁止 getter panic。
6. 增加测试矩阵：每种 origin × runtime × policy。

**退出条件**：尚未迁旧 Action，但所有 Capability 调用都已携带真实来源并经过门禁；现有入口行为不变。

### 5.2 0.21.1 — 内置 Action 迁移

1. 按 §4.1 为 13 项逐文件建立 Capability；共享底层 service，不共享巨型 dispatcher。
2. 先让旧 Action `execute()` 仅调用新 Capability，作为短期兼容桥；禁止保留第二份平台逻辑。
3. 每项补 schema、policy、真实平台错误传播、Done/结构化结果测试。
4. `blink_print_debug_info` 从“执行并复制”拆为结构化 CapabilityResult + 本地 Copy ResultAction。
5. 系统调用不得忽略返回值；Dangerous confirmation 不可由本地/AI入口分叉实现。

**退出条件**：13 个 Action 文件内没有独立业务实现，只剩兼容适配；CapabilityRegistry 可单独完成全部原子调用。

### 5.3 0.21.2 — Chord 分流

1. 新建 `ChordBindingDescriptor { binding_id, default_key, label, surface, target }`。
2. 为 chat/region capture/clipboard/content editor 建 GUI starter Capability；sticky 绑定既有 create_sticky。
3. Voice 保持 Interaction-only，descriptor target 明确为 Interaction starter，不制造空 Capability。
4. `ChordRegistry` 只保存 binding；触发器根据 target 调 Capability 或领域 Interaction service。
5. 迁移旧 chord screenshot alias，验证用户键位不丢失。

**退出条件**：不存在 `ChordAction: Action` supertrait；6 个 Chord 行为与键位保持一致。

### 5.4 0.21.3 — 结果操作与 fallback 收敛

1. 为 Search/Item 结果增加明确 `InvokeCapability` target。
2. OpenFile/OpenUrl/Reveal 统一走既有 Capability。
3. `BuiltinEngine::ACTIONS` 拆成仅搜索/Context descriptor 数据，标题来自 FeatureCatalog/descriptor，不读 ActionRegistry。
4. `run_builtin_action` 兼容 command 直接查 descriptor target；删除 Action-first/Capability-fallback。
5. 全仓列出所有 `SearchAction`/`ItemAction` 构造与消费点，逐项验证。

**退出条件**：不存在“先查哪个 Registry 决定语义”；同一 open 操作只有一份业务实现。

### 5.5 0.21.4 — FeatureCatalog 后端

目录项至少包含：

```text
feature_id, localized title/description, group, source,
target, binding summaries, capability projection,
availability, unavailable_reason
```

1. 新建六组：应用/文件与链接；剪贴板与文本；图片与颜色；便签与内容；窗口与系统；Blink 管理与诊断；无法归类的插件进入“其他插件能力”。
2. builtin descriptor、Chord binding、builtin/plugin Capability 聚合为目录项。
3. 标题/说明必须本地化；插件优先使用 manifest 本地化字段，缺失时回退 schema description。
4. capability schema、danger、sensitive、policy 只投影，不复制存储。
5. 插件 disabled 时显示来源不可用；invoke-time 仍复核插件生命周期。重新启用后恢复原 AI/MCP 授权。
6. 本地状态从各 binding store 聚合；行/组批量操作通过 adapter 写回原真源。
7. 未知/已移除 id 保留为可诊断残留，不阻断目录初始化。

**退出条件**：同一产品功能只有一个目录身份；feature/capability/binding id 均可在诊断详情查看。

### 5.6 0.21.5 — AI allowlist 与 MCP 策略

1. 增加 `AiCapabilityAccessStore`；配置缺失时按 §3.4 生成推荐集合并持久化。
2. `build_agent_tools` 只包装 policy 允许且用户 enabled 的 Capability。
3. AgentCacheKey 增加 `ai_capability_epoch` 或稳定 allowlist fingerprint；配置热更新递增 epoch，使旧 Agent 不持有已撤销工具。
4. 主窗口与对话窗口共用 allowlist，纯对话模式继续强制空池。
5. MCP ExposureSnapshot 构建时同时过滤 policy；call-time 再检查 policy + exposed list + runtime。
6. Dangerous 对 MCP 永远拒绝；GUI starter 对 MCP 显示不可用。
7. tools/listChanged、AI cache invalidation、授权审计使用 capability id 和 origin。

**退出条件**：修改 AI/MCP 配置后无需重启；旧 Agent/session 不能绕过撤销；两份授权互不联动。

### 5.7 0.21.6 — 设置页功能目录

1. 设置侧边栏“搜索”改为“功能”，入口为引擎、插件、能力与操作。
2. 引擎页只管召回源和运行环境；移除内置动作卡片。
3. 插件页只管安装、启停、版本和插件配置。
4. 能力与操作页按六组显示名称、说明、来源、本地/AI/MCP 状态和风险标记。
5. 支持搜索及来源、危险、敏感、已开放过滤；组级开关为全开/全关/部分启用。
6. Interaction-only 的 AI/MCP 显示 `—`；代码禁止的出口不可点击，不伪装成关闭。
7. 默认页面使用面向用户的词汇；id、runtime、policy 放入高级详情。
8. MCP Server 页只保留 enabled、端口、Endpoint、状态、“已暴露 N/M”和目录深链。

**退出条件**：设置页不存在第二份完整 MCP 清单或内置动作清单；所有开关落到现有授权/binding 真源。

### 5.8 0.21.7 — 删除遗留与文档切换

1. 删除 `execution::Action`、ActionRegistry、ActionContext、ActionOutcome、ExecError、ActionSchema 和兼容适配。
2. 删除 `BuiltinEngine::ACTIONS` 中已被 descriptor/catalog 接管的重复展示元数据。
3. 删除 `CapabilityError <- ExecError`、`Capability -> execution::DangerClass` 等反向依赖。
