# Blink 0.17.10 — Capability 投影层收敛重构（Projection Responsibility Refactor）

> **范围**：将 projection（pointer 字段挑选）从 `invoke` 链路移出、回归展示出口，使 AI 出口天然拿到完整 raw data；对齐 ip / weather 插件；weather 数据源补全多天预报。
>
> **状态**：✅ 已完成（0.17.10 本体 + 0.17.10a + 0.17.10b + 0.17.10c 全部合入）。
>
> **动机**：0.14 把 projection 放进 `PluginCapabilityAdapter::invoke`（capability.rs:154），导致 pointer 同时背负"给 AI 挑纯净数据"和"给展示挑字段"两个互相冲突的职责。ip / weather 的 pointer 配置配窄了，AI 丢失地理位置 / 天气状况等语义信息。这是 0.14 改造时 ip/weather 没跟上的回归，根因是 projection 的职责错位。
>
> **前置**：0.14（Capability 协议 / ProjectionRule / 轨道 A）；0.17.6（主窗口 AI 架构统一，`to_rig_tool_result` 成为 AI 唯一出口）。
>
> **原则**：架构收敛优先于补丁——不加 `raw` 字段做旁路，而是把 projection 移到它该在的位置（展示出口）；AI 出口与展示出口职责彻底分离；invoke 回归"纯数据获取 + 形态规范化"，不碰展示逻辑。

## 二、背景与动机

### 2.1 为什么 0.17.10 做这件事

**触发**：对话窗口调用 `get_ip` tool 时，AI 收到的是 `["198.18.0.1","154.64.224.103"]` 纯字符串数组，丢失了"本地/公网"类型和"城市, 国家"地理位置。AI 因此无法回答"公网 IP 在哪"，甚至误报"该工具本应返回位置信息但本次未附带"。

**根因链**（从现象到根因）：

1. 插件层没丢——`raw_result.data` 是 `[{ip, type:"公网 IP · 北京, 中国"}, ...]` 完整对象数组。
2. projection 层做了拆解——`project_items` 按 manifest 的 `item_pointer:"$.ip"` 把每项的 ip 取为 `ItemResult.data`，按 `item_desc_pointer:"$.type"` 把 type 取为 `ItemResult.desc`。到这一步位置信息还在（在 desc 里）。
3. **AI 出口主动丢弃 desc**——`items_to_llm_json`（result.rs:135）只序列化 `ItemResult.data`，注释写"desc 是给人看的副标题，对 AI 是噪音"。
4. 结果：AI 只拿到被 `item_pointer` 挑过的裸字段，丢失 `type` 里的语义信息。

**根因本质**：0.14 把 projection（pointer 挑字段）放在了 `invoke` 链路里（capability.rs:154 `project(&raw.data, projection)`），让 pointer 同时服务两个互相冲突的职责：

- "给 AI 挑纯净数据"（manifest 配 `item_pointer` 挑 ip 字段）
- "给展示挑标题字段"（manifest 配 `item_pointer` 挑展示主标题）

pointer 配宽了 AI 拿到展示噪音，配窄了 AI 丢语义信息。ip 配 `$.ip`（配窄了）→ AI 丢地理位置；weather 配 `$.temp`（配窄了）→ AI 丢天气状况/风速/城市。translate 逃过一劫纯属侥幸——它的 data 本身是裸字符串，`pointer:"$"` 取整体，没字段可丢。

**0.14 改造前后的对比**（git 证据，提交 `df85f91`）：

| 阶段 | AI 拿到什么 | pointer 角色 |
|---|---|---|
| 0.14 前（0.9.3~0.13） | `payload`（插件直填的完整 JSON，core 不挑字段） | 不存在（插件自填 title/subtitle/payload） |
| 0.14 后 | `ItemResult.data`（manifest pointer 从 raw 挑出的子字段） | "给 AI 挑纯净数据" + "给展示挑字段"（冲突） |
| **0.17.10（本 phase）** | **完整 raw data**（invoke 不挑字段） | **纯展示投影**（只给展示出口用） |

### 2.2 明确"不是问题"的（避免误改）

| 项 | 结论 |
|---|---|
| translate 的 `desc:"译文"` 对 AI 隐藏 | **合理**。translate 是 desc 设计正确的基准——译文在 data 主路径（`pointer:"$"` 取整体），desc 是纯 UI 标签，丢弃不影响 AI。用户印象中"translate 是噪音 desc 的根源"实际上反了。 |
| 主窗口搜索流（query 路径）丢信息 | **不受影响**。query 路径走独立的旧 `PluginItem{title, subtitle}` 协议（protocol.rs），插件直填，不碰 projection。本 phase 只涉及 tool-call（AI）路径。 |
| `items_to_llm_json` 丢弃 desc | **根因不在它**。它是"AI 只读 data"设计的忠实执行者。问题在于 data 被 pointer 砍窄了，而不是 desc 该不该进 AI。本 phase 让 data 恢复完整，desc 自然不需要进 AI。 |
| open-meteo 只能查当天 | **是配置 bug，不是 API 限制**。open-meteo `/v1/forecast` 默认返回 7 天预报，最长 16 天（`forecast_days` 参数）。blink 当前代码（weather/src/main.rs:380-382）只请求了 `current=` 字段，没请求 `daily=`。0.17.10c 修这个配置。 |

## 三、核心设计 / 决策

### 3.1 projection 职责重定义：从"AI 数据净化器"还原为"展示层投影"（已定）

**定案**：projection（pointer / desc / item_pointer / item_desc_pointer）的职责收敛为**纯展示投影**——从完整 data 里挑哪个字段当主标题、哪个当副标题。AI 出口不再经过 projection，直接拿完整 data。

**理由**：0.14 当初把 projection 放进 invoke 的动机是"旧 `ItemResult{title,subtitle,payload}` 把 UI 文案和语义数据焊在一起，AI 受噪音干扰"（phase doc §五）。但这个动机指向的修正应该是"让 AI 别碰 UI 文案"，而不是"给 AI 的数据加一层 pointer 挑字段"——因为：

1. raw data 本身已经是干净的（ip/weather/translate 吐的 raw 全是纯语义，没有 emoji 或"按 Enter 复制"）。噪音只存在于旧 PluginItem 协议的 title/subtitle（query 路径），0.14 在干净的数据上又加了一层可能砍错字段的投影。
2. pointer 的天然职责就是展示投影。"从对象里挑哪个字段当标题"是纯 UI 关注点，跟 AI 无关。把 AI 混进来，pointer 配置就同时背负两个互相冲突的职责。
3. 让 AI 直接拿 raw data，pointer 回归展示语义，两个职责各有唯一安放位置，不再冲突。

### 3.2 invoke 回归"数据获取 + 形态规范化"，不再调 project()（已定）

**定案**：`PluginCapabilityAdapter::invoke`（capability.rs:154）不再调用 `project()`。改为调用新的 `normalize()` 函数，只做形态规范化（raw JSON → CapabilityResult），**不挑字段**。

**规范化规则**（`normalize(data, rule) -> CapabilityResult`）：

| result_shape | raw data 形态 | 规范化结果 |
|---|---|---|
| Items | 数组 | `Items{ items: [ItemResult{ data: 完整元素, desc: None, actions: from rule }...] }` |
| Items | 非数组 | 兜底为单元素列表 |
| Text | 任意 | `Text{ content: value_to_string(data), desc: None }` |
| Done | 任意 | `Done{ summary: value_to_string(data) }` |
| Blob | 任意 | `Done{ summary }` 兜底（插件通过 JSONL 不传二进制） |

关键：规范化时 **`ItemResult.data` = 完整元素对象**（不做 `item_pointer` 挑选），`desc` 设 None（展示出口动态投影）。`actions` 仍从 rule 的 `item_actions` 映射（动作声明不是数据挑选，保留在规范化阶段）。

**`normalize` vs 旧 `project` 的区别**：

| | 旧 `project` | 新 `normalize` |
|---|---|---|
| `item_pointer` | 挑字段 → `ItemResult.data` | **不读**（data 保留完整元素） |
| `item_desc_pointer` | 挑字段 → `ItemResult.desc` | **不读**（desc = None，展示出口投影） |
| `pointer`（Text） | 挑字段 → `content` | **不读**（content = value_to_string(data)） |
| `items_pointer` | 取数组根 | **保留读**（确定数组位置） |
| `item_actions` | 映射动作 | **保留读**（动作声明） |
| `result_shape` | 决定形态 | **保留读**（决定形态） |

**理由**：invoke 是 Capability trait 的核心方法，语义应纯粹——"入参 → 出参（数据）"。展示投影是消费方关注点，不该在数据获取层做。这与 Capability "不碰 UI" 铁则（mod.rs:86）一致。

### 3.3 Capability trait 加 `projection()` 方法（已定）

**定案**：`Capability` trait 加一个提供投影规则的方法：

```rust
fn projection(&self) -> Option<ProjectionRule> { None }  // default None
```

- `PluginCapabilityAdapter` override 返回 manifest 的 `projection` 字段。
- builtin capability（search_files / read_clipboard 等）默认 None——它们走轨道 B（直接构造 ItemResult），不需要 manifest 投影。

**projection 成为能力的静态属性**（和 `schema()` / `danger_class()` 同类），不再每次塞进 result。展示出口通过 `cap.projection()` 获取规则。

**理由**：展示出口（`to_display_text`）需要 projection 规则来挑展示字段。与其把 projection 塞进 CapabilityResult（让 result 变胖且语义混乱），不如让它挂在 Capability 上——projection 是"这个能力的结果怎么展示"的元信息，属于能力定义而非单次调用结果。

### 3.4 展示出口 `to_display_text` 加 projection 参数（已定）

**定案**：`to_display_text` 签名从 `(&self) -> String` 改为 `(&self, projection: Option<&ProjectionRule>) -> String`。

展示投影逻辑内联在 `to_display_text` 内：

- **Items 形态**：对每项 `ItemResult.data`（完整对象），用 `projection.item_pointer` 取主标题、`item_desc_pointer` 取副标题。pointer 缺失时用 `derive_title(data)` 兜底。
- **Text 形态**：直接用 `content`（不做 pointer 投影）。详见 §3.5。
- 其他形态不变。

**调用点适配**（仅 2 处）：
- `src/cli/commands.rs:234` — `result.to_display_text()` → `result.to_display_text(cap.projection())`
- `src/app/commands/search.rs:192` — 同上

**AI 出口 `to_rig_tool_result` 不变**：它已经读 `ItemResult.data`（规范化后是完整对象），天然正确。`items_to_llm_json` 序列化完整 data JSON。

### 3.5 Text 形态不再支持 pointer 投影；weather 迁移到 Items 形态（已定）

**定案**：Text 形态的 `pointer` / `desc_pointer` 在新架构下**不再生效**。`content = value_to_string(raw data)`，展示出口直接用 content。

**影响分析**：

| 插件 | 形态 | data 类型 | pointer | 影响 |
|---|---|---|---|---|
| translate（单次） | Text | 字符串 `"你好"` | `"$"` | **无影响**。content = value_to_string("你好") = "你好"。pointer="$" 取整体，等价。 |
| weather | Text | 对象 `{city,temp,...}` | `"$.temp"` | **pointer 失效**。content 变成 JSON 字符串。展示不友好。→ 需迁移到 Items 形态（§3.6）。 |

**weather 迁移到 Items 形态**（0.17.10b）：
- raw_data 从对象 `{city, temp, ...}` 改为单元素数组 `[{city, temp, ...}]`。
- manifest projection 从 `{result_shape:"text", pointer:"$.temp", desc_pointer:"$.city"}` 改为 `{result_shape:"items", items_pointer:"$", item_pointer:"$.temp", item_desc_pointer:"$.city"}`。
- 这样 AI 拿到 `[{city,temp,condition,wind_speed,region}]` 完整对象，展示用 item_pointer 取 temp 作主标题、item_desc_pointer 取 city 作副标题。

**理由**：Text 形态的语义是"纯文本结果"（译文、OCR 文本），展示时整体呈现，不需要字段级投影。需要字段级展示投影的场景（如天气的"从对象里取温度当标题"）应使用 Items 形态。这让两个形态的职责更清晰：Text = 整体文本，Items = 可逐项投影的结构化列表。

### 3.6 各插件效果（本体合入后，零 manifest 改动即修复 AI 回归）

| 插件 | AI 拿到（修后） | 展示（with projection） | 改了什么 |
|---|---|---|---|
| ip | `[{ip,type},...]` 完整 ✅ | 标题=ip（item_pointer），副标题=type（item_desc_pointer） | 本体（manifest 不变） |
| translate 单次 | `"你好"` 完整 ✅ | content="你好" | 无变化 |
| translate_batch | `["译文1","译文2"]` 完整 ✅ | derive_title 兜底（无 item_pointer） | 无变化 |
| weather | **0.17.10b 改 Items 后**：`[{city,temp,...}]` 完整 ✅ | 标题=temp，副标题=city | 0.17.10b（形态迁移） |

#### 文件 2：`src/domain/capability/projection.rs`

- **新增 `normalize` 函数**（不做 pointer 挑选的规范化）：

```rust
/// 把 raw data 规范化为 CapabilityResult（0.17.10 收敛）。
///
/// 与旧 `project` 的关键区别：不读 pointer / item_pointer / item_desc_pointer，
/// data 保留完整原始值。展示字段挑选由展示出口（to_display_text）用 projection 动态完成。
///
/// 保留读：result_shape（形态）、items_pointer（数组根）、item_actions（动作声明）。
pub fn normalize(data: &serde_json::Value, rule: &ProjectionRule) -> CapabilityResult {
    let shape = rule.result_shape.unwrap_or_else(|| infer_shape(data));
    match shape {
        ResultShape::Text => CapabilityResult::Text {
            content: value_to_string(data),
            desc: None,
        },
        ResultShape::Items => {
            let array = rule.items_pointer.as_deref()
                .and_then(|p| jsonpath_query(data, p))
                .unwrap_or_else(|| data.clone());
            let elements: Vec<serde_json::Value> = match &array {
                serde_json::Value::Array(arr) => arr.clone(),
                other => vec![other.clone()],
            };
            let items: Vec<ItemResult> = elements.iter().map(|elem| ItemResult {
                data: elem.clone(),           // 完整元素，不挑字段
                desc: None,                    // 展示出口动态投影
                actions: rule.item_actions.iter()
                    .map(action_def_to_item_action).collect(),
            }).collect();
            CapabilityResult::Items { items }
        }
        ResultShape::Blob => /* 同旧 project_blob 逻辑 */,
        ResultShape::Done => /* 同旧 project_done 逻辑 */,
    }
}
```

- **废弃旧 `project` / `project_items` / `project_text` 函数**：invoke 不再调用。可删除或标记 `#[deprecated]`。如果展示出口的逻辑完全内联到 `to_display_text`，这些函数可安全删除。保留 `ProjectionRule` / `ResultShape` / `ActionDef` / `jsonpath_query` / `value_to_string` / `derive_title` / `infer_shape` / `action_def_to_item_action`（工具函数和结构定义）。
- **更新单测**：原 `project_items_*` / `project_text_*` 测试改为测 `normalize`（断言 data 保留完整对象、不挑字段）。新增"normalize 不丢字段"单测。

#### 文件 3：`src/domain/capability/result.rs`

- **`to_display_text` 签名加 projection 参数**：

```rust
pub fn to_display_text(&self, projection: Option<&ProjectionRule>) -> String {
    match self {
        CapabilityResult::Text { content, .. } => content.clone(),
        CapabilityResult::Items { items } => {
            if items.is_empty() { return "（无结果）".to_string(); }
            items.iter().enumerate().map(|(i, item)| {
                // 展示投影：从完整 data 用 pointer 取主标题/副标题
                let title = projection
                    .and_then(|r| r.item_pointer.as_deref())
                    .and_then(|p| jsonpath_query(&item.data, p))
                    .map(|v| value_to_string(&v))
                    .unwrap_or_else(|| derive_title(&item.data));
                let desc = projection
                    .and_then(|r| r.item_desc_pointer.as_deref())
                    .and_then(|p| jsonpath_query(&item.data, p))
                    .map(|v| value_to_string(&v))
                    .or_else(|| item.desc.clone());  // builtin capability 手填的 desc 兜底
                match desc {
                    Some(d) if !d.is_empty() => format!("{}. {} — {}", i + 1, title, d),
                    _ => format!("{}. {}", i + 1, title),
                }
            }).collect::<Vec<_>>().join("\n")
        }
        CapabilityResult::Blob { .. } => self.blob_summary(),
        CapabilityResult::Done { summary } => format!("✓ {summary}"),
    }
}
```

  > 注意：`jsonpath_query` / `value_to_string` / `derive_title` / `ProjectionRule` 需要 `use` 引入（可能在 projection.rs，确保 result.rs 能访问——检查模块可见性）。
