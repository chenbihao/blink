# Blink 0.27 — AI 交互增强（提示词资产化、斜杠命令与多模态进出对话）

> **范围**：文件选中感知、代理接线与更新检查降级、提示词库、编辑器整理预设、斜杠命令框架（含 /compact、/prompt）、@ 附件面板（含最近复制文件）与文本文件附件、图片输入（Vision）与剪贴板发送到聊天及「问 AI」动作、OpenAICompatible 路由核验修复、Cap 输出瘦身、Windows 多窗口 IME 隔离规避；rig 0.45 升级、OpenAI-compatible 方言接线与跨 Provider 思考语义收敛。
>

>
> **动机**：0.25 架构收敛后，把「能聊」推进到「捕获内容 → 带入任务 → 处理并交付」的工作流——提示词沉淀为资产，文件与图片经原生入口进入对话，网络与协议先补齐可靠性。

>
> **原则**：不影响 Alt+Space 后立即输入；附件仅在明确附加的请求中注入，持久历史只留展示徽标；不引入 embedding/向量；沿用 rig classic agent 和现有记忆策略，升级只增加必要的 SDK 接缝，不引入 rig-harness/Bevy 执行后端；多模态收在 domain::ai 适配层。

## 二、背景与「不是问题」的澄清

要解决的缺口：提示词无资产入口；命令入口分散（/skill 硬编码、压缩埋在告警条）；内容流转不闭环（文件靠模型自读路径、图片进不了聊天、附件无失败重试）；地基缺口（OpenAICompatible 未显式路由、AI client 无统一代理、更新检查无降级）。2026-10-25 经用户授权追加 rig 0.45 升级（0.27.13）、方言接线（0.27.14）、跨 Provider 思考（0.27.15）三项协议地基，均在 0.43 现状核验后按 0.45 真实行为实施（现状修正见 §5.14）。

**刻意设计，勿改**：

- 保留现有 memory/水位/FTS5/摘要策略和 SQLite 数据归属；0.45 移除旧记忆 trait 后只迁 SDK 接缝，不将 Blink 历史改存为 rig session，不丢弃旧会话。
- **历史不落附件原文 / base64 是刻意设计**——避免自动逐轮重放与持久化原始附件；会话内有界重试快照已补（§6.2）。
- 截图 SESSION 不作素材仓库——overlay 关闭即结束，最近截图从剪贴板历史签新 ref。
- OCR 双档保真——LLM 默认 text 瘦输出、overlay 显式 full，两分支共享投影。
- 编辑器「范围 × 预设、只预填 Chat」对齐 product.md §2.9 既有决策。

## 三、核心决策（定案结论）

**3.1 OpenAICompatible 显式 Chat 路由**：`build_openai_client` 显式 `openai::Route::Chat`（rig 的 OpenAI 方言默认 Responses）。方法论「不把配置字段断言当协议验收、用 wire 捕获桩钉回归」已沉淀至 [spec-backend §二](../specs/spec-backend.md)。

**3.2 文件选中感知**：IShellWindows 定位冻结视图取 SelectedItems，桌面走 `FindWindowSW(SWC_DESKTOP)`；不模拟 Ctrl+C。show 前冻结来源 HWND/generation，show 后 STA worker 异步采集，回写前四重复核。坑：**桌面回退必须校验 matched_hwnd**——Explorer 窗口无选中时不得落入桌面视图（0.27.12 修复）；COM 调用不可中止，单次时限用「drop guard + 惰性看门狗」实现。

**3.3 附件——有界引用、单次注入、可恢复重试**：封闭类型 `audio/text_file/image`，前端任意 path **不是授权凭据**——资源仅由可信 picker / 选中确认 / 剪贴板历史链签发，owner 后端推导，`transfer_owner` 按 expected owner CAS。文本限额：单文件 256KiB 硬拒、≤4000 tokens 全文 / 超限截 ≤2000 UTF-8 安全前缀、最多 8 项、合计 ≤8000 tokens，逐项报错不静默丢。续读走窄用途 Capability `read_attachment_text`。下轮不重放：Persistent 靠预写 + 位置去重，Ephemeral 靠**围栏剥离**（`<<<blink-attachments-begin/end>>>`）。失败轮持久化：messages 表 `status/error_text` 列，模型上下文加载不读此列。

**3.4 Vision——显式能力、真实预算**：`ModelCapability::Vision` 旧配置缺省关；目录 supports_vision 只对**新建**模型预填，用户值优先；前后端双校验。限额：单图 8MiB / 合计 16MiB（base64 展开计）/ 24MP / 长边 2048、PNG/JPEG 白名单、EXIF 方向归一化。坑一：**24MP 校验必须在解码（大分配）前**（0.27.12 修复）。坑二：**wire 用 base64 变体不用 raw**——rig 转换器对 `image_raw` 直接报错，`image_base64` 是三家通行路径（0.27.12 修复）。HTTP 日志对图片 base64 与 URI 凭据参数（Gemini `?key=`）脱敏。

**3.5 代理——显式网络策略**：infra net 工厂管不可变快照 + network generation + 按请求类别复用 client。**空配置 = 完全显式直连**（忽略环境变量/系统代理）；loopback（含带方括号的 IPv6，坑见 0.27.12）恒直连。无效配置不覆盖旧快照不推进 generation；Provider fingerprint 追加 `|n{generation}` 使缓存失效，在途流持旧 client 不打断；MCP 按连接生命周期重连。`build_client` 失败兜底用 no_proxy 直连重建（不能退回 `Client::default()`——它会读环境变量）。

**3.6 更新检查降级**：主链 GitHub API releases → 失败经镜像 latest.json 只判版本返回 degraded；镜像全失败报检查失败不报「已是最新」；两层共用 15s 总预算，同走网络策略。

**3.7 提示词库**：blink_ai.db `prompt_library` 表，内置条目稳定 ID + override_content + revision CAS；种子幂等；内置删除后端双重拒绝、scope 不可变。清空覆盖经 IPC 须用 double_option 反序列化（serde 把 JSON null 与缺省都解成 None，`Some(None)` 不可表达——0.27.12 修复的坑）。变更广播 `blink://prompt-library-changed`。

**3.8 /compact 手动摘要**：手动边界保留最近两轮完整 user turn；全局关闭时手动可生成，成功写 `manual_summary` 标记，memory 按「全局开 ∨ 手动标记」注入——旧会话不被隐式开启。提交 CAS 冻结高水位；任务全程持 `summary_in_flight` 单活跃（guard 经 disarm 移交 spawn 任务——0.27.12 修复）。

**3.9 编辑器预设**：三内置映射库稳定 ID（迁移逐字节一致验证）；请求冻结 preset 正文，在途不随库变化；互译自动方向按 CJK 占比 ≥1/2 判。

**3.10 composer 弹层协调**：`/` 面板、`@` 面板、模型/思考下拉、提示词面板经 `composer-popups.js` 统一互斥；composer 单调 `inputRevision`，异步回写前核对防过期。键盘路由：Tab/Enter 采纳、Esc 只关面板不清输入、Shift+Enter 恒换行、IME 组合中不处理。坑（0.27.12）：**面板触发按钮须 `stopPropagation`**（否则冒泡开即关）；**adoptRow 首参在命令名与条目 kind 两个命名空间复用**——条目 kind 用独立名 `prompt_entry`。

**3.11 消息重试锚定（0.27.12）**：`chat:retry` 携带消息锚点——assistant 锚点取其前最近 user、user 锚点取自身，经 handleEditMessage 截断重发；DOM 绑定稳定消息标识与 DB `message_id` 贯通（R3 修复），不依赖渲染项计数。

**3.12 补充项边界**：保留四种协议级 `ProviderKind`，方言只表达兼容协议差异，不按厂商增加平行 Agent/Provider 实现。思考的「请求意图、模型支持、实际编码、输出展示」分别表达，控件形态不充当协议能力证明。未知网关保留通用行为与显式覆盖；两个出口（RigFactory 主窗 / AgentProvider 对话窗）共用同一解析与合并逻辑。

### 5.14 0.27.14 — OpenAI-compatible 方言接线（✅）

- **方言解析单一真源**：`domain/ai/compat_dialect.rs`——`ProviderEntry.compat_dialect`（`CompatDialect` 闭集：Auto/Generic/DeepSeek/Moonshot，serde default Auto 旧配置零迁移）。Auto 仅按解析后 hostname **精确匹配**官方端点表，未知网关/解析失败一律 Generic，不用 URL 子串、显示名或模型名；`url_host` 手写解析（domain 层不引 url crate）。
- **双调用链接线**：`build_openai_client(key, base_url, compat)` 经 `with_key(&Dialect, key)` 选 rig `wire::DEEPSEEK/MOONSHOT`，随后恒 `.with_base_url(用户地址)`（方言只改协议行为不改端点）+ `Route::Chat` + `LoggingHttpClient`；RigFactory 与 AgentProvider 共用。
- **thinking 判定统一**：`base_url` 子串启发替换为 `ResolvedCompatDialect`，消除「wire 走 DeepSeek rewrite 而 thinking 发 reasoning_effort」的分裂；模型名 `deepseek` 前缀启发保留（第三方代理既有语义）。
- **fingerprint/cache key**：方言段（`|dg|ds|ms`）进 `compute_provider_fingerprint`——显式切换方言（base_url 不变）也失效缓存，在途请求持旧快照。
- **前端**：provider modal「兼容方言」下拉（仅 OpenAICompatible 显示），读写保序、非 OAICompatible 保留原值。
- **rig 0.45 现状修正**（规划过时项）：0.43 的 `Dialect/Quirks` 在 0.45 重构为 `providers::openai::wire` 常量；DeepSeek rewrite 为「思考中 drop forced tool choice」，Moonshot 为「拒指定单工具 + required 降级引导」。wire 测试钉住：两方言 × 三 base_url 形态保 Chat 路由且请求打用户地址、DeepSeek 思考×工具回放不丢内容、Moonshot 降级与拒绝、Generic 零 rewrite、`prompt_cache_hit_tokens` 在 Generic 下同样读入（共享解析，非方言专属收益）。

### 5.15 0.27.15 — 跨 Provider 思考模式适配（✅，含 review 修正）

- **能力快照单一真源**：`ThinkingCapability`（shape：Levels/Switch/Unsupported/Unknown + levels/can_disable/can_enable_default/budget/default_effort/unknown），`resolve_thinking_capability` 经 rig 0.45 内置目录（`ModelFacts::default().for_model`，含快照后缀归一）。**身份门槛与方言同哲学**：OpenAICompatible+Generic 仅 `api.openai.com` 精确匹配查 openai 目录，未知网关一律 Unknown（默认 omit + 显式覆盖透传）；Gemini 目录 miss 按家族启发（3.x 等级/2.5 预算/<2.5 不支持）；`thinking_supports_effort` 改为能力投影。
- **意图层**：`ThinkingIntent`（FollowDefault/Disable/EnableDefault/Effort）——「默认」omit ≠ 关闭；主窗口「默认关」按能力分派（等级型 omit、开关型显式关、不可关模型降级 FollowDefault 不硬失败）。
