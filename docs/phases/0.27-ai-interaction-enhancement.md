## 二、背景与动机

### 2.1 为什么 0.27 做这件事

- **提示词缺少资产入口**：用户无法保存、复用常用指令。提示词库由 Chat 插入和 Editor 预设消费；产品预设与内部 system/title/summary prompt 各有职责，不做全部混成一张用户可编辑表的“统一”。
- **命令入口分散**：已有 /skill 硬编码提示，压缩埋在告警条。统一键盘入口，同时补齐真实工具池和连接状态的可发现性。
- **内容流转不闭环**：文件需要模型自行读路径，图片无法进入聊天。附件不仅需要发送，还需要失败重试、过期反馈、继续追问和草稿保护。
- **地基存在实际缺口**：OpenAICompatible 未显式覆盖 rig 默认路由；AI client 没有统一代理接线；更新检查缺少可用降级；异步感知与缓存变更需要代次契约。
- **整版按工作流验收**：资源管理器文件 → Blink → Chat；截图/剪贴板图片 → Chat；编辑器内容 → 预设 → Diff → 确认交付。入口数量不替代端到端成功率。

### 2.2 明确“不是问题”的（审查澄清，避免误改）

- **不迁移 rig 记忆 trait**：现有 memory、水位、归档与摘要体系继续使用；本版修补手动摘要闭环，不另建记忆框架。
- **历史不落附件原文/base64 是刻意设计**：避免自动逐轮重放及持久化原始附件。音频先例只提供部分资源基础设施，不能据此认定文本/图片的重试和多轮语义已完整；当前会话需要有界重试快照。
- **截图 SESSION 不作为素材仓库**：overlay 关闭即结束；最近截图从剪贴板图片历史签发新引用，不延长截图 Session 生命周期。
- **OCR 交互结果保真**：LLM 默认瘦输出，截图 overlay 显式 full；两条后端返回分支共享投影，完整结果保留原结构。
- **已有镜像调度继续复用**：本地引擎/解释器下载沿用 mirrors 模块，本版补网络策略和更新降级，不重做下载源体系。
- **产品编辑器决策已存在**：product.md §2.9 已描述范围 × 预设及只预填 Chat。0.27.6 对齐该决策，不重复宣称产品文档尚未升级。

## 三、核心设计 / 决策

### 3.1 OpenAICompatible —— 显式 Chat，验证实际请求（已定，实机待验）

**定案**：build_openai_client 显式使用 openai::Route::Chat。锁定的 rig 0.43.0 中 OpenAI 方言默认 Responses，当前 factory 无覆盖，静态疑点成立；先捕获 wire 再修复并锁定，不把配置字段断言当作协议验收。

**理由**：本产品 OpenAICompatible 承诺面向 chat/completions 端点；聊天、工具调用、流式输出及标题/摘要等调用方应有一致协议。连接测试应区分 /models 可达与模型生成可用。

### 3.2 文件选中感知 —— Shell COM + 来源代次保护（已定，桌面/多标签页待实测）

**定案**：资源管理器通过 IShellWindows 定位冻结的目标视图，再取 SelectedItems；桌面优先验证 FindWindowSW(SWC_DESKTOP) → QueryActiveShellView → 视图接口路线。不能把找到 DefView HWND 当作完成 COM 视图桥接。不模拟 Ctrl+C。

**时序**：show 前冻结来源 HWND/PID、视图标识与 invoke generation；show 后在线程正确初始化的 COM worker 中异步采集。回写前核对 generation、来源、开关与敏感门控，失败/无选中清空本代状态。目标在唤起后不得改为 Blink 自己的前台窗口。

**边界**：worker 有界并发、单次完成时限和过期结果丢弃；超时不宣称能强行中止 COM。选中项只接受文件系统对象，目录可参与本地动作、不可自动当文本附件；虚拟项不伪造路径。网络路径感知不触发文件内容读取，附加时沿用网络路径授权规则。

**产品**：文件建议不盖过明确查询意图；复制路径展示数量，多目录 reveal 按父目录分组，限制窗口扇出。发往聊天在 0.27.9 一次接结构化附件，默认追加当前草稿、不自动发送，并可明确新建对话。

### 3.3 附件 —— 有界引用、单次注入、可恢复重试（修订已定）

**授权与输入**：使用带 kind 的封闭类型 audio/text_file/image，各自携带 resource_ref 与展示名；前端任意 path 不是授权凭据。资源仅由可信 picker、选中项确认或剪贴板历史读取链签发；owner/用途由后端推导并校验，canonical_path 不进入聊天历史/普通 IPC。附件作为有来源标识的用户数据，不提升为 system 指令。历史 JSON 只保留展示名、种类等非授权徽标，并兼容旧音频记录。

**生命周期**：草稿、在途请求、可重试请求分别管理。沿用 ResourceStore 的 TTL/配额，发送时验证并为有界在途任务保留 lease；切换会话可清草稿，但不得误撤销在途任务。当前会话缓存有界请求快照，重试不丢附件；过期/配额不足逐项反馈，预检成功前不截断旧历史。会话切换采用 draft revision 防 A→B→A 旧回写。

**后续轮次**：不自动把旧附件重放给模型。当前会话提供“再次附加”动作；引用失效、进程重启或文件发生变化时重新选择。徽标不表示模型仍能看到内容，不承诺重开后 AI 自动凭路径续读，也不绕过 read_text_file 的敏感授权。

**文本读取默认值**：每文件硬上限 256KiB，超过则明确拒绝；UTF-8（含 BOM）及无 NUL 的文本首版支持，其他编码明确提示转换，目录/PDF/Office 不静默按文本读。≤4000 估算 tokens 全文注入，超过截断为≤2000 的 UTF-8 安全前缀并附结构化范围/截断说明。超长单行可截前缀，不因字节切割产生坏 UTF-8。最多 8 个附件，文本合计默认≤8000 tokens，且必须满足当前模型整次请求预算；超额需用户调整，不静默丢项。

**续读**：截断显示本轮实际范围。新增窄用途 Capability read_attachment_text，以 resource_ref/cursor/limit 为参数，返回 start_byte/end_byte/next_cursor/eof/truncated；游标对应 UTF-8 边界与同一文件身份，每页默认≤2000、硬上限4000 tokens。只接受执行上下文绑定的会话/请求中已明确附加的 ref，不能由它获得任意路径读取权。工具池有工具模式下按已有策略暴露，pure_chat 不因此开启工具，可由用户选下一段再次附加。UI 与模型共用此原子读取入口和现有 probe/预算/分页纯逻辑，文件身份变化即失效；read_clipboard 不承诺分页。

**草稿流转**：take/ack revision 的载荷扩为正文与附件事务；验证成功后整体追加，失败保留来源和已有草稿，确认消费后再转移资源归属。不经过伪造的“请读此路径”文本。

### 3.4 Vision —— 显式能力、真实预算、错误保留草稿（修订已定）

**定案**：增加 ModelCapability::Vision，旧配置缺省关闭。目录 supports_vision 只对新建模型推荐预填，已有条目（包括显式关闭）不被目录刷新开启；用户值优先。前端提示与后端发送校验均检查有效能力，不做自动摘图重试。

**输入限制**：每图编码输入≤8MiB、所有图片合计≤16MiB；解码前后校验格式/像素及分配上限，默认≤24MP，超过要求用户缩小。处理方向，长边缩至≤2048 后按 provider 支持格式归一化；首版发送 PNG/JPEG，SVG 拒绝，GIF 明确拒绝并提示转静态图。限制必须在大分配前生效，解码任务串行/有界，归一化后重新校验编码总量。这些数值作为集中命名的首版默认上限，由实际 provider 约束与性能验证校准，不散落硬编码。

**预算与诊断**：本轮 pending images 在历史裁剪前计入按数量/尺寸/provider 保守估算的预算，不复用单一 256 token 布尔惩罚。HTTP 正文日志对图片/base64 脱敏，只留必要诊断元数据。模型拒绝时保留草稿，提供切换模型、移除图片或明确转 OCR 的动作。

### 3.5 代理 —— 显式网络策略与两层缓存失效（修订已定）

**定案**：infra net 工厂管理不可变配置快照、network generation 与按请求类别复用的 client；app/CLI 等入口启动读取并注入，不修改进程全局环境变量。HTTP 与 HTTPS 分别匹配协议；localhost、127.0.0.0/8、::1 等 loopback 显式直连，包括用户配置的本地 OpenAI/MCP endpoint。

**配置语义**：本版空配置明确直连并关闭默认系统代理；未配置某个协议的代理时该协议直连。保存前校验配置，无效配置保留旧快照并显示错误，不静默绕过代理。“跟随系统代理”作为独立模式不在本版隐式引入。

**热更新**：Provider fingerprint 与 Agent cache key 纳入 network generation，或同等显式失效两层缓存；registry.reload 本身不足以重建。新请求取新快照，在途流保持旧快照；MCP 按连接生命周期重连，不粗暴杀掉活跃调用。外部普通请求/下载/流式连接采用不同 timeout 与取消策略。

**承诺范围**：覆盖 Blink 本体及插件通过 core HTTP 代发的请求；插件自行联网不能靠 core client 工厂保证，按协议明确重启/独立代理支持边界，设置页不得笼统声称所有第三方流量自动受控。

### 3.6 更新检查 —— 保留 releases 主链，镜像只判版本（修订已定）

**定案**：主链继续 GitHub API releases 列表，保留多版本说明；主链失败后通过既有 github_proxy_candidates 拉 latest.json，返回 degraded 与“版本可检查、说明不可用”。镜像也遵守所选网络策略，配置代理时不静默旁路直连；直接探测可留在显式诊断。

**失败边界**：各层共享总时限/取消信号，校验版本与响应格式。镜像全失败显示检查失败，不能报“已是最新”；主站不可达但镜像可达才是降级成功场景，真正断网不承诺成功。下载/安装更新链仍沿用既有安全与确认约束。

### 3.7 提示词库 —— 稳定 ID、用户覆盖、变更通知（修订已定）

**定案**：blink_ai.db 的 prompt_library 存 id/name/content/override_content/scope(chat|editor)/builtin/sort_order/hidden/revision/created_at/updated_at。内置条目使用稳定命名 ID 与随版本提供的默认内容目录，override_content 为可空用户覆盖；自建条目使用 content。未覆盖的内置项随默认目录升级，已覆盖项保持用户值；种子幂等补元数据，不覆盖修改。恢复默认清除覆盖，复制生成独立自建项，隐藏只影响可选列表；内置不可删除由后端强制，默认整理始终可解析为兼容兜底。

**一致性**：Editor 的三内置预设映射这些稳定 ID，不保留另一套运行时正文。写入用 expected_revision 防覆盖，排序有稳定次序；builtin/scope 权限由后端校验。名称 1–80 字符、正文≤16KiB 且≤4000 估算 tokens；空值/超限明确报错。

**消费边界**：纯文本指令，不引入变量语言。Chat 插入用户输入，Editor 作为本次转换指令；不替代系统提示词或 Skill。变更事件让设置/Chat/Editor 刷新缓存，清聊天不清提示词资产。

### 3.8 /compact —— 自动触发与摘要读取分离（修订已定）

**定案**：复用既有水位与摘要存储；手动压缩覆盖最近两轮完整 user turn 之前的上下文，保留工具调用配对，已有摘要也参与有界合并。未满边界返回 no-op，不删除 DB 原文。

**生成与读取**：summary_enabled 约束自动触发；显式 /compact 可生成，并为该会话记录手动摘要启用状态。memory 读取水位及注入摘要按有效会话状态判断，不能仅绕过生成侧开关。自动关闭但从未手动压缩的旧会话不被隐式开启摘要。

**执行与提交**：无需先发消息创建缓存 Agent，按当前模型配置构造无工具摘要 agent，遵循全进程 AI 单活跃。冻结会话 revision/高水位，按摘要模型输入预算分段和合并；中途失败/取消/旧版本结果不推进水位，各分段结果暂存后统一有效提交。编辑/截断/删除与摘要提交协调。

**反馈**：任务包含 job_id/conversation_id，区分 running/succeeded/no-op/failed/cancelled，重复触发可识别，错误回显明确。80% 告警按钮与 /compact 共用手动语义；自动压缩仍保留原触发策略。

### 3.9 编辑器预设 —— 对齐产品的范围 × 预设（修订已定）

**定案**：按 product.md §2.9 实现整理/精简/中英互译及 scope=editor 自定义，默认整理保持原语义。请求冻结 preset ID/revision/正文，角色边界不变，快速模型、无记忆、无工具、显式触发与 Diff 确认继续遵守既有约束。

**预算与交互**：系统指令、自定义 prompt、选区和输出一起算预算；按钮/候选显示当前动作名。正文变化使候选不可替换。互译按主语言选择方向（中文→英文、英文→中文），混合或不明确时允许明确选择目标中文/英文，保留代码与专有名词。

**校验**：内置 prompt 的特定格式测试不扩大为用户输入禁令；自定义指令可以合理包含代码或 XML。

### 3.10 范围收敛与设计核验（已定）

生图、TTS、多类型 API、向量/RAG 不进入本版。实测未闭合的点保留为实施核验项：桌面/Explorer 多标签页 COM、各 provider 图像 wire、Tauri 原生拖放与 DOM 事件关系；先做最小验证再承诺入口完成。结果不支持原路线时记录替代设计与验收变化，禁止用未验收占位项宣称完整。

### 4.1 已有基础设施复用盘点

### 6.2 整版产品流程与性能

- [ ] 资源管理器选中文本文件 → Alt+Space → 带入当前/新聊天 → 提问 → 失败重试 → 再次附加追问，完整可用且授权明确。
- [ ] 截图 → 剪贴板历史 → Chat → 选择 Vision 模型 → 分析，图片失效/模型不支持时有恢复路径。
- [ ] Editor 选中内容 → 预设 → Diff → 确认替换，内容变化时旧候选不可替换；发往 Chat 仅预填。
- [ ] 与 0.25 同机同场景对比，唤起<50ms、首结果<20ms、常驻内存<300MB；焦点成功率目标>99.9%，记录样本数及失败，不把少量冒烟宣称为可靠性统计。
- [ ] 多次打开面板/粘贴图片/取消/切换会话后资源数与内存回落，感知 COM 与解码不进唤起/搜索热路径。
