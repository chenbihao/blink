## 二、背景与「不是问题」的澄清

要解决的四类缺口：提示词无资产入口；命令入口分散（/skill 硬编码、压缩埋在告警条）；内容流转不闭环（文件靠模型自读路径、图片进不了聊天、附件无失败重试）；地基缺口（OpenAICompatible 未显式路由、AI client 无统一代理、更新检查无降级）。

**补充项核验（2026-10-25）**：锁定依赖为 rig-core/rig-agent **0.43.0**（当日晚些时候已由 0.27.13 升级至 0.45.0 + rmcp 3.7，见 §5.13）。思考请求已有 OpenAI `reasoning_effort`、DeepSeek `thinking.type`、Anthropic 手动预算和 Ollama `think`，不应按“尚未接请求”重做；Gemini 当前返回空补丁，其他分支也缺模型级能力和完整 wire 验收。factory 仍用通用 `OpenAIConfig::new`，尚未选择厂商 dialect；0.27.1 的 Chat 路由前置已完成。两项迁入 §5.14/§5.15。rig **0.45.0 已于 2026-10-19 发布**，跨越 0.44 的类型化生成参数与 0.45 的记忆/MCP 破坏性变化，先以 §5.13 完成迁移（已完成），避免按 0.43 再造新版已提供的思考映射。

**刻意设计，勿改**：

- 保留现有 memory/水位/FTS5/摘要策略和 SQLite 数据归属；0.45 移除旧记忆 trait 后只迁 SDK 接缝，不将 Blink 历史改存为 rig session，不丢弃旧会话。
- **历史不落附件原文 / base64 是刻意设计**——避免自动逐轮重放与持久化原始附件；会话内有界重试快照是待补闭环，当前编辑/重试仅重发正文的问题见 §6.2 R4。
- 截图 SESSION 不作素材仓库——overlay 关闭即结束，最近截图从剪贴板历史签新 ref。
- OCR 双档保真——LLM 默认 text 瘦输出、overlay 显式 full，两分支共享投影。
- 编辑器「范围 × 预设、只预填 Chat」对齐 product.md §2.9 既有决策。

## 三、核心决策（定案结论）

**3.1 OpenAICompatible 显式 Chat 路由**：`build_openai_client` 显式 `openai::Route::Chat`（rig 0.43 的 OpenAI 方言默认 Responses）。方法论沉淀：**不把配置字段断言当协议验收**——用本地 TcpListener 捕获真实 wire（method/path/body）钉成回归测试（factory.rs::wire_tests）；/models 可达 ≠ 生成可用，两者分开呈现。

**3.2 文件选中感知**：IShellWindows 定位冻结视图取 SelectedItems，桌面走 `FindWindowSW(SWC_DESKTOP)`；不模拟 Ctrl+C，不把找到 DefView HWND 当完成 COM 桥接。show 前冻结来源 HWND/generation，show 后 STA worker 异步采集，回写前四重复核（代次/开关/来源仍属 explorer/敏感门控）。坑：**桌面回退必须校验 matched_hwnd**——Explorer 窗口无选中时不得落入桌面视图，否则桌面残留选中被错误归属（0.27.12 修复）；COM 调用不可中止，单次时限用「drop guard + 惰性看门狗」实现。

**3.3 附件——有界引用、单次注入、可恢复重试**：封闭类型 `audio/text_file/image`，前端任意 path **不是授权凭据**——资源仅由可信 picker / 选中确认 / 剪贴板历史链签发，owner 后端推导，`transfer_owner` 按 expected owner CAS。文本限额（集中命名常量）：单文件 256KiB 硬拒、≤4000 tokens 全文注入 / 超限截 ≤2000 UTF-8 安全前缀、最多 8 项、合计 ≤8000 tokens，逐项报错不静默丢。续读走窄用途 Capability `read_attachment_text`（ref/cursor/limit → UTF-8 边界分页），只接受请求级绑定的活跃 ref，策略三元组照抄 read_text_file 先例（Safe + sensitive + sensitive()）。下轮不重放：Persistent 靠预写 + 位置去重，Ephemeral 靠**围栏剥离**（`<<<blink-attachments-begin/end>>>`，0.27.12 补齐——临时会话没有去重机制，附件上下文会整块重放）。失败轮持久化（0.27.12）：messages 表 `status/error_text` 列，Error chunk 标记尾部 user 行、Done 清除，`load_all_messages`（模型上下文路径）**不读此列**。

**3.4 Vision——显式能力、真实预算**：`ModelCapability::Vision` 旧配置缺省关；目录 supports_vision 只对**新建**模型预填，用户值优先；前后端双校验，错误保留草稿不摘图重试。限额：单图 8MiB / 合计 16MiB（base64 展开计）/ 24MP / 长边 2048、PNG/JPEG 白名单（SVG/GIF 拒绝）、EXIF 方向归一化。坑一：**24MP 校验必须在解码（大分配）前**——先 `into_dimensions()` 读头部（0.27.12 修复，曾有验收项打勾不实）。坑二：**wire 用 base64 变体不用 raw**——rig 的 OpenAICompatible/Gemini 转换器对 `image_raw` 直接报错 "Raw files not supported"，`image_base64` 是三家通行路径（0.27.12 修复）。pending 图片按尺寸估算计入预算（非固定 256 布尔）；HTTP 日志对图片 base64 与 URI 凭据参数（Gemini `?key=`）脱敏。

**3.5 代理——显式网络策略**：infra net 工厂管不可变快照 + network generation + 按请求类别复用 client。**空配置 = 完全显式直连**：忽略 HTTP_PROXY/HTTPS_PROXY 环境变量、不读系统代理（存量用户需自行填地址）；loopback（localhost/127.0.0.0/8/`[::1]`——带方括号，坑见 0.27.12）恒直连。无效配置不覆盖旧快照不推进 generation；Provider fingerprint 追加 `|n{generation}` 使 Agent 两层缓存失效，在途流持旧 client 不打断；MCP 按连接生命周期重连。承诺边界：只覆盖本体 + 插件经 core HTTP 代发的请求，设置页如实声明。`build_client` 失败兜底用 no_proxy 直连重建（不能退回 `Client::default()`——它会读环境变量，违背显式直连）。

**3.6 更新检查降级**：主链 GitHub API releases → 失败经镜像 latest.json 只判版本返回 degraded（不拿单版 notes 冒充完整日志）；镜像全失败报检查失败不报「已是最新」；两层共用 15s 总预算，同走网络策略。

**3.7 提示词库**：blink_ai.db `prompt_library` 表，内置条目稳定 ID（`builtin.editor.tidy/refine/translate`）+ override_content 用户覆盖 + revision CAS；种子幂等（未覆盖内置随目录升级、覆盖不动、content 变化才推 revision）；内置删除后端双重拒绝、scope 不可变、builtin 列不可写。清空覆盖经 IPC 须用 double_option 反序列化（serde 默认把 JSON null 与缺省都解成 None，`Some(None)` 不可表达——0.27.12 修复的坑）。变更广播 `blink://prompt-library-changed`（payload 含 scope）；清聊天不清提示词资产。

**3.8 /compact 手动摘要**：手动边界保留最近两轮完整 user turn（ToolResult 投递不算 turn 起点）；冷构造无缓存前置；全局关闭时手动可生成，成功写会话 `manual_summary` 标记，memory 按「全局开 ∨ 手动标记」注入——旧会话不被隐式开启。提交 CAS 冻结高水位；任务全程持 `summary_in_flight` 单活跃（guard 经 disarm 移交 spawn 任务——0.27.12 修复，否则任务运行期门禁空转）。

**3.9 编辑器预设**：三内置映射库稳定 ID（不保留第二套运行时正文，迁移做逐字节一致验证）；请求冻结 preset 正文，在途不随库变化；互译自动方向按 CJK 占比 ≥1/2 判，可显式 zh/en；指令计入预算。

**3.10 composer 弹层协调**：`/` 命令面板、`@` 附件面板、模型/思考下拉、提示词面板经 `composer-popups.js` 统一互斥（openExclusive 打开前关其余）；composer 单调 `inputRevision`（输入/面板开闭/附件增删 +1），异步回写前核对防过期。键盘路由：Tab/Enter 采纳、Esc 只关面板不清输入、Shift+Enter 恒换行、IME 组合中不处理。坑（0.27.12）：**面板触发按钮须 `stopPropagation`**（否则冒泡到 document click-outside 开即关）；**adoptRow 首参在命令名与条目 kind 两个命名空间复用**——`/prompt` 命令曾撞条目 kind `prompt` 静默无操作，条目 kind 用独立名 `prompt_entry`。已知待决：模型/思考 flyout 无键盘路由、Tab 语义是否改为纯补全。

**3.11 消息重试锚定（0.27.12）**：`chat:retry` 事件携带消息锚点——assistant 锚点取其前最近 user、user 锚点取自身，经 handleEditMessage 截断该轮之后重发；此前无锚点恒重发最后一条。DOM `.chat-msg` 下标与 state.messages 对齐沿用 startEditMessage 定位，纯附件轮不产生 `.chat-msg` 的错位与编辑功能同边界（既有局限）。

**3.12 补充项边界（规划）**：保留四种协议级 `ProviderKind`，方言只表达兼容协议差异，不按厂商增加平行 Agent/Provider 实现。思考的“请求意图、模型支持、实际编码、输出展示”分别表达，`thinking_style` 的控件形态不能继续充当协议能力证明。未知网关保留通用行为与显式覆盖；两个出口共用解析与合并逻辑。

### 5.15 0.27.15 — 跨 Provider 深度思考模式适配（✅ 实现完成，真实厂商实发/GUI 待手动）

**目标**：完善已有参数通路，让控件准确表达模型的默认、开关、等级、始终开启、不支持或未知状态；支持范围由已验证模型元数据和用户显式覆盖决定，不把全部 OpenAI-compatible 模型当作支持 `reasoning_effort`。

**0.45 复用调整**：优先桥接 rig 的 `ReasoningSupport`/模型 facts 和类型化 `GenerationOptions::reasoning`，复用 wire 对常见协议的编码及不支持反馈；本地目录与用户覆盖仍是 Blink 配置入口，不另建第二份厂商映射大表。SDK 未覆盖的自建网关/vLLM 方言才用受控覆盖。raw additional_params 在新版编码顺序中位于 typed options 之后，因此只调用 `.reasoning(...)` 不足以保证本轮按钮优先；必须先归并/剔除与显式意图冲突的私参，保留无关嵌套字段，再验最终 wire。

| 协议/服务 | 当前实现 | 本次补齐 |
|---|---|---|
| OpenAI-compatible / 自建 vLLM | 非 DeepSeek 一律按 effort 分支，默认 omit，任意显式等级透传 | 按服务/模型声明能力与合法等级；未知保持默认并提供显式覆盖；vLLM 按部署的模板/协议实测，不能只由模型名推断 |
| DeepSeek | 仅二值 `thinking.type`，忽略本分支的 effort | 分开表达开关与强度；支持当前协议允许的组合，旧模型/转发端按实际能力降级 |
| Anthropic | 全部模型套手动 enabled/disabled，固定 budget=2048 | 区分 manual/adaptive/always-on/不支持；manual budget 校验最终 max_tokens，避免低输出上限导致非法请求 |
| Gemini GenerateContent | `thinking_request_patch` 返回 None，仍显示普通开关 | 接该协议的 thinkingConfig；区分预算型/等级型和不能关闭的模型，控件诚实呈现；不改接 Interactions API |
| Ollama | 所有模型只发 bool `think` | 支持模型声明的 bool/命名等级，区分不支持和未知；有可用 `/api/show` 元数据时解析，旧服务失败可降级 |

**统一语义**：

- 模型静态 custom parameters 先进入两个调用出口；本轮显式思考意图仅覆盖相关字段，保留无关嵌套参数。当前 Agent 路径漏用 custom parameters 的缺陷随本项修复。
- 发送时冻结实际 provider/model、能力、意图与编码结果；切换本轮思考不重建 Agent。静态协议/能力配置变化照常使缓存失效，不能与请求级开关混为一谈。
- 参数“未发送/跟随默认”不等于关闭；模型不支持关闭时显示实际限制。展示开关与请求控制分开，前端按本轮冻结状态防御处理意外 reasoning。
- 保存消息级思考元数据，历史/导出基于当轮状态；旧消息缺元数据时标未知，不用当前按钮状态倒推。补齐模型切换/连续设置的响应代次防护与键盘操作。
- 保留主窗临时对话、持久对话、编辑器/标题/摘要调用各自的默认策略，但共用能力解析与编码函数，不顺带改变这些入口的产品默认值。

**来源**：[Anthropic 手动预算与 adaptive 迁移](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)、[Gemini GenerateContent thinking](https://ai.google.dev/gemini-api/docs/generate-content/thinking)、[Ollama thinking](https://docs.ollama.com/capabilities/thinking)、[DeepSeek 思考与强度控制](https://api-docs.deepseek.com/guides/thinking_mode/)。模型清单随实现时官方协议复核，不把整家 Provider 简化成一个布尔值。
