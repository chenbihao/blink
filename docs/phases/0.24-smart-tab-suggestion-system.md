# Blink 0.24 — Smart Tab 与统一建议系统（从散落提示到可扩展的双槽位采纳）

> **范围**：建立后端统一 Suggestion 协议、Producer/Coordinator 与简单评分；收敛主窗口 Ghost、环境建议、AI 入口、结果导航和模式提示；最后用独立 Spike 验证 Needle 是否具备成为内置路由 Producer 的资格。
>
> **状态**：📋 规划中。
>
> **动机**：当前关键词补全、划词/剪贴板建议、“按 Tab 问 AI”与 Chord 提示虽部分共用 `Suggestion`/Ghost/statusbar，但产生、仲裁、采纳与展示责任仍分散。本阶段先让纯规则 Smart Tab 独立成立，再评估超轻量模型路由。
>
> **前置**：0.8 Suggestion/四域架构、0.16 感知交互、0.17 主窗口 AI 模式、0.21 Capability 唯一执行入口、0.22 本地模型运行时。
>
> **原则**：不影响 `Alt+Space → 窗口出现 → Focus → 立即输入` 主链路；Suggestion 只有呈现权，用户 Tab/Shift+Tab/点击采纳后才能穿过信任边界；前端保持纯静态 HTML/CSS/JS。

## 二、背景与动机

### 2.1 当前问题

`SearchResponse` 只暴露单个 `Option<Suggestion>`；Keyword/Context 进入 `SuggestionArbiter`，AI 却由 `SearchService` 在仲裁后特殊注入。前端把输入补全、Context 动作和 AI 模式入口都放进 `ghost.js`，再由 statusbar 按 `source` 二次解释。Chord 提示还会根据 query 是否为空在输入框 overlay 和 statusbar 之间迁移。

0.24 需使新增 Producer 只影响“建议什么”，不再修改键盘、DOM 布局或执行链路。

### 2.2 明确“不是问题的”

- Suggestion 域和“弱信号 pull 不 push”原则保留，Context 不重新抢占结果列表。
- Ghost Text 保留，但收窄为真正的输入补全视觉。
- Chord 保留稳定的固定功能语义，不用动态排名改变字母键含义。
- AI 主窗口临时对话与 `Alt+Q` 独立持久对话的 surface 差异保留。
- Tab/Shift+Tab 只在对应槽位有候选时接管；`Alt+Tab` 永远交还 Windows。

## 三、核心设计与决策

### 3.1 Suggestion 是领域，Smart Tab 是采纳面，Ghost 是补全投影（已定）

**定案**：后端以 Suggestion 域管理候选生产和仲裁；前端对用户呈现 Smart Tab。Ghost 只显示可自然接在用户文本后的 Completion，Suggestion Bar 显示动作建议及采纳键。

### 3.2 双槽位：Tab 主建议，Shift+Tab 次建议（已定）

**定案**：`SuggestionSet` 只暴露 `primary` 和 `secondary`，也可通过点击采纳，不展示第三条及更多候选。

**理由**：双槽位能表达“翻译为主、AI 为备选”，又不会变成第二份结果列表。

### 3.3 Query 与 Awareness 是并列评分输入（已定）

**定案**：简单评分既看划词/剪贴板，也对主窗口当前 Query 进行文本类型与语言判定。

- UI/翻译目标语言为中文，用户在主窗口直接输入一串通过自然语言门禁的英文：翻译为 Primary，AI 为 Secondary。
- Query 与目标语言同族且是自然语言：AI 为 Primary，不生成同语言翻译。
- 简短应用名/keyword、URL、路径、颜色、UUID、邮箱、命令参数、代码标识符和已明确命中的搜索/插件路由，不得被翻译建议抢占。
- 用户已输入明确翻译 keyword 时继续走确定路由，不叠加同义 Smart Tab。

### 3.4 规则分数与模型置信度分离（已定）

**定案**：规则排序值命名为 `rank_score`；`confidence` 保留给未来具备校准语义的模型输出。先做 eligibility，再按 `SuggestionPriority` 和 `rank_score` 排序。

| 候选 | 条件 | 初始 `rank_score` |
|---|---|---:|
| 关键词补全 | fuzzy 命中 | 归一到 0.70～0.98 |
| 打开 URL | Context 明确 URL | 0.95 |
| 路径动作 | Context 明确文件路径 | 0.93 |
| 翻译 Query/选区 | 非目标语言，来自 Query 或 Selection | 0.92 |
| 翻译剪贴板 | 剪贴板为非目标语言 | 0.82 |
| AI 处理 Query | Query 为目标语言自然文本 | 0.80 |
| AI 处理选区 | 选区为目标语言自然文本 | 0.72 |
| AI 处理外语 | 已有翻译主建议时作备选 | 0.62 |
| 通用 AI 兜底 | 其他合法自然语言 | 0.55 |

确定性规则高于模型，Selection 高于 Clipboard，同动作族去重，Secondary 需独立过最低分。

### 3.5 用户采纳才穿过信任边界（已定）

Producer/Coordinator 不执行 Capability。Tab、Shift+Tab 或点击产生显式 acceptance，并携带 suggestion id/slot/revision；过期 revision 拒绝采纳。翻译在 0.24 使用 `RouteQuery`，AI 使用 `EnterAiMode`；第一版不引入 `InvokeCapability` SuggestionAction。

### 3.6 Needle 是可选 Producer，不是新执行器（已定）

Needle Spike 只评估它是否能用少量闭合 tool schema 输出路由候选与置信度。即使通过，也只实现 `ModelIntentProducer`，不运行自动 tool loop，不直接执行 Blink Capability。

## 四、复用与范围边界

### 4.1 已有基础设施复用

| 基础 | 0.24 用途 |
|---|---|
| `SuggestionProducer` / `SuggestionArbiter` | 演进为多候选生产和双槽位仲裁 |
| `ContextTrigger` / `needs_translation` | Query 与 Awareness 的语言/结构化文本门禁 |
| `RankingHint` | 继续作 Suggestion → Routing 排序反馈，不注入执行参数 |
| `ConfigStore<T>` | Smart Tab/补全/Context/AI 建议显示策略 |
| `CapabilityRegistry` | 采纳动作最终执行的唯一原子入口 |
| search seq / Awareness revision | 拒绝过期搜索与建议 |
| `kbd.js` | Tab/Shift+Tab 键帽和文案投影 |
| 0.22 本地引擎运行时 | Needle 原生 runner 的进程/资产/健康/回收候选基础 |

### 4.2 不进 0.24

| 项 | 理由 |
|---|---|
| Needle 正式生产接入与自动下载 | Spike 通过后再定案，不污染规则版主线 |
| Needle LoRA 微调 | 官方契约中微调后不保留基座模型校准 confidence |
| 模型直接执行 Capability | 违反呈现权/执行权分离 |
| 超过两个可见建议 | 会变成第二份结果列表 |
| 历史自学习权重 | 第一版先固定、可解释、可测试 |
| 动态改变 Chord 键位 | 破坏肌肉记忆 |
| 前端框架/bundler | 违反前端工程铁则 |

## 五、子版本展开

### 5.1 0.24.0：基线与状态模型

- 冻结 Keyword、Context、AI Ghost、Chord overlay、statusbar 和三类 mode 现有行为。
- 定义 `MainWindowUiState` 的 Mode、Completion、Suggestions、Results、Transient 五个正交切片。

### 5.2 0.24.1：后端类型契约

- `SearchResponse.suggestion` 迁移为带 revision 的 `SuggestionSet`。
- 建立 `SuggestionKind`、`SuggestionAction`、`SuggestionPriority`、稳定 id 和 origin。

### 5.3 0.24.2：Producer/Coordinator 与评分

- Keyword、Context、AI 全部通过 Producer 注册，删除 `SearchService` 后置 AI 覆盖。
- Query 文本分类复用 `needs_translation` 类门禁，但 Routing 仍不读 Awareness。
- Coordinator 负责 eligibility、去重、分级、排序和 Primary/Secondary 选取。
- 以表驱动测试覆盖直接输入英文、目标语言输入、选区、剪贴板、明确路由和结构化文本。

### 5.4 0.24.3：采纳边界与可观测性

- 定义 Primary/Secondary 槽位与 Tab/ShiftTab/Click 手势。
- suggestion id + search seq + snapshot revision 拒绝旧候选。
- 日志记录 Producer、过滤 reason、排名和采纳，不记录 query/选区全文。

### 5.5 0.24.4：主窗口信息架构

```text
MainWindow
├── ModeHeader
├── QueryInput
│   └── CompletionGhost
├── SuggestionBar
│   ├── Primary   → Tab
│   └── Secondary → Shift+Tab
├── Results
├── ResultFooter
└── TransientFeedback
```

- CompletionGhost 只读 Completion。
- SuggestionBar 只显示下一步建议、来源和采纳键。
- ResultFooter 只显示结果导航、动作和分页。
- ModeHeader 表达 AI/命令/剪贴板等持续模式。
- TransientFeedback 承载 loading/success/error。
- Chord 只在按住 Alt 时投影独立 Cheat Sheet，不再在输入框与 statusbar 间迁移。

### 5.6 0.24.5：键盘、设置与打磨

- Tab/Shift+Tab 只在对应候选存在时采纳；IME 和独立模式优先。
- 点击和键盘共用 acceptance 路径。
- 设置页展示 Smart Tab、输入补全、环境建议、AI 兜底和第二建议；AI Provider 与翻译私有配置留在各自真源。
- 视觉可在实施中迭代，但不得重新混合五类 UI 语义。

### 5.7 0.24.6：Needle 资格 Spike

Needle 2 当前官方定位为 45M 参数结构化 tool-calling 模型，宣称单文件约 14MB、完整会话约 28MB RAM，支持 schema 约束输出、tool retrieval 与校准 confidence。官方主入口为 Python package，另提供 Windows 引擎产物和 Wasm Component。Spike 必须在 Blink Windows x64 真实路径复测，不接受宣传值作为结论。

**集成路线顺序**：Windows 原生 runner + stdio JSON；Wasm Component；Python 包只作正确性/性能对照，不获得生产资格。

**路由面**：最多声明 `translate`、`ask_ai`、`open_url`、`open_path`、`none` 五个闭合意图，只读取结构化 complete 结果。

**corpus**：可提交、无隐私的中英文集合，覆盖 Query 英文翻译、目标语言问 AI、URL/路径、短文本、结构化文本、混合语言、无关输入和对抗样本；评估 top-1/top-2。

| 指标 | 同步候选 | 异步增强 |
|---|---:|---:|
| Windows x64 warm p95 | ≤20ms | ≤80ms |
| 冷初始化 | ≤300ms | 可后台预热 |
| 增量 RAM | ≤64MB | ≤96MB |
| 下载/发布制品 | ≤25MB | ≤40MB |
| 路由 macro-F1 | ≥0.90 | ≥0.88 |
| 危险误路由 | 0 | 0 |
| 离线运行/遥测关闭/orphan=0 | 必须 | 必须 |

输出 `Adopt`、`Async-only` 或 `Reject/Observe` 三选一决策。

## 六、验收

### 6.1 后端

- [ ] `SearchResponse` 只有一个 SuggestionSet 真源，无独立 AI 覆盖分支。
- [ ] Keyword、Context、AI 全部通过 Producer + Coordinator。
- [ ] Primary/Secondary 去重、稳定排序且数量不超过 2。
- [ ] 目标语言为中文时，主窗口直接输入合法英文自然文本，Primary=翻译、Secondary=AI（两能力均可用）。
- [ ] 输入目标语言自然文本时 Primary=AI，不产生同语言翻译。
- [ ] `chrome`、URL、路径、代码标识符和已命中路由不被翻译抢占。
- [ ] 翻译插件/AI/Context binding 不可用时，对应候选被 eligibility 排除。
- [ ] 未采纳时不触发 Capability，过期 revision 不能采纳。
- [ ] 日志能说明未提示/排名原因，且不泄露原文。

### 6.2 前端

- [ ] Ghost 只显示 Completion，Context/AI/模型建议只进 SuggestionBar。
- [ ] ResultFooter 只显示结果导航/动作/分页，ModeHeader 是持续模式唯一呈现。
- [ ] Chord 提示不再在输入框和 Footer 之间迁移。
- [ ] Tab/Shift+Tab/点击共用 acceptance；无候选和 IME 组字时不误吞键。
- [ ] 同一建议不在两个视觉区重复出现。
- [ ] 新增 Producer 无需修改前端键盘/布局。
- [ ] 唤起、Focus、首结果和输入响应指标不退化。

### 6.3 Needle Spike

- [ ] Windows x64 得出原生 runner、Wasm 或明确不可行的集成结论，不以 Python 作生产通过。
- [ ] 锁定源版本、产物格式、SHA-256、许可和遥测关闭方式。
- [ ] 固定 corpus 输出 top-1/top-2、macro-F1、混淆矩阵、confidence 校准、warm/cold 延迟、RAM 和制品体积。
- [ ] 输出 `Adopt` / `Async-only` / `Reject/Observe` 决策与证据。
- [ ] 无论 Spike 结果如何，规则版 Smart Tab 可独立发布。
