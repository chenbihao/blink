# Blink 0.24 — Smart Tab 与统一建议系统（从散落提示到可扩展的双槽位采纳）

> **范围**：建立后端统一 Suggestion 协议、Producer/Coordinator 与简单评分；收敛主窗口 Ghost、环境建议、AI 入口、结果导航和模式提示。
>
> **状态**：📋 规划中。
>
> **动机**：当前关键词补全、划词/剪贴板建议、"按 Tab 问 AI"与 Chord 提示虽部分共用 `Suggestion`/Ghost/statusbar，但产生、仲裁、采纳与展示责任仍分散。本阶段让纯规则 Smart Tab 独立成立；超轻量模型路由（Needle）移出本版，改为 0.25 数据触发项（§5.7）。
>
> **前置**：0.8 Suggestion/四域架构、0.16 感知交互、0.17 主窗口 AI 模式、0.21 Capability 唯一执行入口、0.22 本地模型运行时。
>
> **原则**：不影响 `Alt+Space → 窗口出现 → Focus → 立即输入` 主链路；Suggestion 只有呈现权，用户 Tab/Shift+Tab/点击采纳后才能穿过信任边界，且 0.24 采纳动作零执行能力；前端保持纯静态 HTML/CSS/JS。
>
> **修订**：20260927 架构评审冻结全部契约（SuggestionAction 两变体、采纳协议、评分分层与去重、降频开关、Needle 移出），决策记录见 §三 各"已定"子节。

## 二、背景与动机

### 2.1 当前问题

`SearchResponse` 只暴露单个 `Option<Suggestion>`；Keyword/Context 进入 `SuggestionArbiter`，AI 却由 `SearchService` 在仲裁后特殊注入。前端把输入补全、Context 动作和 AI 模式入口都放进 `ghost.js`，再由 statusbar 按 `source` 二次解释；采纳分支散落在 ghost/statusbar/keyboard 三处。Chord 提示还会根据 query 是否为空在输入框 overlay 和 statusbar 之间迁移。

0.24 需使新增 Producer 只影响"建议什么"，不再修改键盘、DOM 布局或执行链路。

### 2.2 明确"不是问题的"

- Suggestion 域和"弱信号 pull 不 push"原则保留，Context 不重新抢占结果列表。
- Ghost Text 保留，但收窄为**输入的自然延伸**（补全 + 语音转写预览）。
- Chord 保留稳定的固定功能语义，不用动态排名改变字母键含义。
- AI 主窗口临时对话与 `Alt+Q` 独立持久对话的 surface 差异保留。
- Tab/Shift+Tab 只在对应槽位有候选时接管；`Alt+Tab` 永远交还 Windows。
- 内置 `open_url`/`open_path` 的结果列表召回是合理承载，0.24 维持现状（0.25 随 `InvokeCapability` 才考虑迁入建议栏，见 §3.5）。

## 三、核心设计与决策

### 3.1 Suggestion 是领域，Smart Tab 是采纳面，Ghost 是输入延伸投影（已定）

**定案**：后端以 Suggestion 域管理候选生产和仲裁；前端对用户呈现 Smart Tab。Ghost overlay 只渲染**输入的自然延伸**——Completion 影子文字与语音转写预览（组字中的"用户自己的话"，不穿信任边界）；SuggestionBar 显示动作建议及采纳键。

**理由**：语音预览与补全同属"输入正在形成"，本体上不是系统建议；保留现有 freeze/unfreeze 机制不动，避免 0.23 语音链路回归。

### 3.2 双槽位：Tab 主建议，Shift+Tab 次建议（已定）

**定案**：`SuggestionSet` 只暴露 `primary` 和 `secondary`，也可通过点击采纳，不展示第三条及更多候选。**键随槽走不随视觉区走**：Tab 恒采纳 primary、Shift+Tab 恒采纳 secondary；primary 为 Completion 时 Tab 作用于 ghost，SuggestionBar 只渲染非 Completion 槽位，同一建议不在两个视觉区重复出现。

**理由**：双槽位能表达"翻译为主、AI 为备选"，又不会变成第二份结果列表。

### 3.3 Query 与 Awareness 是并列评分输入（已定）

**定案**：简单评分既看划词/剪贴板，也对主窗口当前 Query 进行文本类型与语言判定。

- UI/翻译目标语言为中文，用户在主窗口直接输入一串通过自然语言门禁的英文：翻译为 Primary，AI 为 Secondary。
- Query 与目标语言同族且是自然语言：AI 为 Primary，不生成同语言翻译。
- 简短应用名/keyword、URL、路径、颜色、UUID、邮箱、命令参数、代码标识符和已明确命中的搜索/插件路由，不得被翻译建议抢占。
- 用户已输入明确翻译 keyword 时继续走确定路由，不叠加同义 Smart Tab。

### 3.4 规则分数、分层与去重（已定）

**定案**：规则排序值命名为 `rank_score`；`confidence` 保留给未来具备校准语义的模型输出。Coordinator 依次执行 eligibility → 分层 → 按 Kind 去重 → 排序 → 选槽。

| 候选 | 条件 | 初始 `rank_score` |
|---|---|---:|
| 关键词补全 | fuzzy 命中 | `0.70 + 0.28 × fuzzy`（0.70～0.98） |
| 打开 URL | Context 明确 URL | 0.95（**0.25 随 InvokeCapability 激活**） |
| 路径动作 | Context 明确文件路径 | 0.93（**0.25 随 InvokeCapability 激活**） |
| 翻译 Query/选区 | 非目标语言，来自 Query 或 Selection | 0.92 |
| 翻译剪贴板 | 剪贴板为非目标语言 | 0.82 |
| AI 处理 Query | Query 为目标语言自然文本 | 0.80 |
| AI 处理选区 | 选区为目标语言自然文本 | 0.72 |
| AI 处理外语 | 已有翻译主建议时作备选 | 0.62 |
| 通用 AI 兜底 | 其他合法自然语言 | 0.55 |

- **分层先于分数**：非空 query 时，query 派生候选（Completion / 翻译 Query）优先于 awareness 派生（选区/剪贴板）。这是 `SuggestionSource` 现有注释原则（"非空 query 时 keyword 意图更强，Context 让位"）的显式化——否则输 `fa`（fanyi 前缀低分）+ 剪贴板英文时，翻译剪贴板 0.82 会错误抢占 Primary。
- **按 Kind 去重**：每种 `SuggestionKind` 只留最高分候选，Primary/Secondary = 得分前两的 Kind。天然实现"翻译主、AI 次"，且"AI 处理外语 0.62"只在"AI-Query 0.80 不存在（query 非目标语言）"时参选，互斥自动成立。
- **Secondary 门槛**：`secondary_min_rank = 0.60`（`SuggestionConfig` 字段，精确挡掉 0.55 兜底——第二槽也该是有把握的建议）。
- 确定性规则高于模型，Selection 高于 Clipboard。

### 3.5 SuggestionAction 契约：两变体，0.24 采纳零执行（已定）

**定案**：

| 变体 | 语义 |
|---|---|
| `RouteQuery { query }` | 回写输入框 + 触发新一轮搜索（补全采纳与翻译采纳同用；翻译即 query 变为"翻译 xxx"走确定路由） |
| `EnterAiMode { prompt }` | 前端直进主窗口 AI 模式 |

`SuggestionKind = Completion | Translate | AskAi`（`OpenUrl`/`OpenPath` 作注释保留，0.25 激活）。0.24 采纳动作**零执行能力**——只是改 query 或进 AI 模式，最坏情况立即可见可撤销；`InvokeCapability` 变体留给 0.25，届时执行类采纳按 action 类型分流到同步校验，协议无需推倒。

**理由**：两个变体就是今天 `ghost.acceptCurrent` 两个分支的类型化，机械行为零变化；enum 是 additive 扩展点，不写死未来。open_url/open_path 因此留在结果列表：0.24 没有 InvokeCapability，建议栏采纳只能两步（Tab 改写 query → Enter），劣于现状一步 Enter。

### 3.6 采纳协议：前端乐观本地 + 单向遥测（已定）

**定案**：

```text
Tab / Shift+Tab / 点击
  → 前端查当前 SuggestionSet 对应槽位
  → set.revision === 前端当前 seq ？不等则本地拒绝（零 IPC、零延迟）
  → 按 action 本地执行：RouteQuery = 改 query + 重搜；EnterAiMode = 进 AI 模式
  → fire-and-forget invoke('report_suggestion_adoption', {id, slot, revision})
```

- `revision` 收敛为**单一标识** = 本次 search seq（后端原样回填），不引入多标识复合协议；suggestion `id` 是语义 slug（`translate-query`/`ai-selection` 等），前端不解释、仅回传供日志。
- 遥测 best-effort 记日志：producer/kind/slot/revision 匹配与否，**不记 query/选区原文**。
- **理由**：0.24 采纳无副作用，前端 seq 校验已覆盖时序风险，不需要服务端强校验——Tab 保持零延迟（主链路铁则）。0.25 执行类建议引入时，按 action 类型走同步 `accept_suggestion` 校验。

### 3.7 Coordinator 输入与 Producer 纯度（已定）

**定案**：`SuggestionProducer::produce(query, snapshot)` 签名不变；AI 兜底的"路由未命中"判定不进 Producer，由 Coordinator 结合 `route_summary` 做 eligibility：

```rust
struct CoordinateInput<'a> {
    query: &'a str,
    snapshot: &'a AwarenessSnapshot,
    route_summary: RouteSummary,          // 是否已有确定路由/接管/空 Mixed
    availability: SuggestionAvailability, // 翻译绑定 / AI Provider / binding 黑名单
    config: &SuggestionConfig,
}
fn coordinate(input) -> (SuggestionSet, Option<RankingHint>)  // hint 取 primary 的
```

**编排顺序即防环**：Route 先算、Coordinator 后算，`route_summary` 是编排层传值不是域依赖；`RankingHint` 依旧只影响下一轮路由。Producer 保持纯函数可独立单测；能力可用性（翻译插件绑定、AI Provider 配置、binding 黑名单）汇成 availability 表，排除时记 filter reason 日志。

### 3.8 建议降频：会话级抑制开关（已定）

**定案**：疲劳抑制归**建议域**——`SuggestionConfig.suppress_repeated`（设置页文案"建议降频"），**默认开启**；不放翻译插件设置。

- 计数键 = `(kind, origin, source_text 指纹)`，指纹为会话内哈希不落盘（与日志不记原文的隐私口径一致）；带指纹避免剪贴板换内容后误伤。
- 触发：同键连续 **3 次**未采纳 → 本会话抑制该候选；阈值硬编码，只留开/关一个配置。
- 清零：任一次建议被采纳，或主窗口隐藏（每次唤起是新会话）。
- 计数器由 SearchService 持有、主窗口隐藏钩子清零；计数逻辑纯函数化，表驱动测试。

**理由**：疲劳不是翻译专属（AskAi 同样常驻），插件也看不到 impression/adopt 信号——数据流决定归属建议域。默认开的依据：触发条件保守（连续 3 次无视同一建议）、误杀成本低（隐藏的是建议不是功能，显式 keyword 路由始终可用）。

### 3.9 Needle 移出 0.24，转为数据触发项（已定）

**定案**：原 0.24.6 Spike 整体移出。理由：① 验收指标 macro-F1 ≥0.90 必须与规则版在同一真实分布上比，现在手工造 corpus 是规则作者自己出题考自己（循环论证）；② 0.24.3 可观测性恰好是未来 Spike 的真实失败样本采集器；③ 工程解耦（0.24 少一个子版本，无需建 `spikes/`）。即使未来 Adopt，Needle 只实现 `ModelIntentProducer`，不运行自动 tool loop，不直接执行 Capability。触发条件与可选探针见 §5.7。

## 四、复用与范围边界

### 4.1 已有基础设施复用

| 基础 | 0.24 用途 |
|---|---|
| `SuggestionProducer` / `SuggestionArbiter` | Arbiter **更名演进为 Coordinator**，多候选生产与双槽位仲裁 |
| `ContextTrigger` / `needs_translation` | Query 与 Awareness 的语言/结构化文本门禁 |
| `RankingHint` | 继续作 Suggestion → Routing 排序反馈，不注入执行参数 |
| `ConfigStore<T>` | Smart Tab/补全/Context/AI 建议显示策略 + 降频开关 |
| `CapabilityRegistry` | 采纳动作最终执行的唯一原子入口（0.25 InvokeCapability 激活后接入） |
| search seq | revision 真源 + 拒绝过期搜索与建议 |
| `kbd.js` | Tab/Shift+Tab 键帽和文案投影（读 `autosuggest_tab_key` 配置） |
| 主窗口隐藏生命周期钩子 | 降频计数清零 |
| 0.22 本地引擎运行时 | （0.25 Needle 若触发）进程/资产/健康/回收候选基础 |

### 4.2 不进 0.24

| 项 | 理由 |
|---|---|
| Needle Spike | 移至 0.25 数据触发（§5.7），避免无基线的循环论证评估 |
| open_url/open_path 建议化 | 无 InvokeCapability 时两步采纳劣于现状一步 Enter；0.25 激活 |
| 模型直接执行 Capability | 违反呈现权/执行权分离 |
| 超过两个可见建议 | 会变成第二份结果列表 |
| 历史自学习权重（持久化） | 会话级降频已覆盖疲劳；持久学习先要 0.24.3 观测数据 |
| 动态改变 Chord 键位 | 破坏肌肉记忆 |
| 前端框架/bundler | 违反前端工程铁则 |

## 五、子版本展开

### 5.1 0.24.0：设计定案（纯文档）

交付物即本文档：§3.5 Action 契约、§3.6 采纳协议、§3.8 降频机制、§3.4 分层与去重全部"已定"，无代码无测试。已随 20260927 架构评审关闭。

### 5.2 0.24.1：后端类型契约

- `SearchResponse.suggestion` 迁移为带 revision 的 `SuggestionSet`（一次性切换，无兼容层）。
- 建立 `SuggestionKind`、`SuggestionAction`、语义 id、origin；`Suggestion` 增 `id/kind/action/rank_score`，`replacement` 语义并入 `RouteQuery.query`，`confidence` 保留给模型。
- `SuggestionArbiter` 更名 `SuggestionCoordinator`（contained rename，模块内 + SearchService 调用点）。

**✅ 已完成（实施注记，20260927）**：

- 类型契约如上落地；wire 形状有 serde 单测钉死（camelCase 字段、externally tagged action `{"routeQuery":{"query":…}}`/`{"enterAiMode":{"prompt":…}}`、空槽与 `ranking_hint` 不上 wire）。
- `SuggestionSource` 退役 wire 字段但保留为 producer 身份（`SuggestionProducer::source()` 返回值，仅日志/调试用），不再从 intent 层 re-export。
- **confidence 字段 0.24 不建**（§3.4"保留给模型"落在语义层）：0.24 规则侧无生产者，字段待 0.25 `ModelIntentProducer` 落地时随其一起加。
- `rank_score` 数值沿用旧 confidence（keyword=fuzzy 分 / context=门禁置信 / ai=0.5 与 1.0），排序行为零变化；§3.4 rank 表归一在 0.24.2。
- Context→`Kind::Translate` 映射依据：当前唯一 context 规则是 translate 插件的 `text_is_non_target_lang`；0.24.2 起按规则语义分类。id slug 已按 §3.4 对齐（`translate-selection`/`translate-clipboard`/`ai-query`/`ai-trigger`/`completion-keyword`）。
- `SuggestionSet.secondary` 恒 None（coordinator 仍是 top-1 过渡签名 `coordinate(query, snapshot)`）；双槽选取在 0.24.2。
- 前端最小适配保持可用：search.js 三处消费 `suggestion?.primary ?? null`；ghost.js/statusbar.js 按 `kind` 分支（completion/translate/askAi 取代 keyword/context/ai）；采纳走类型化 `action`（含无 action 防御回退）。行为与旧契约逐路径等价。
- 验证：`cargo test --bin blink` 3525 通过 0 失败；`cargo check --bin blink --no-default-features` 零警告（双构建铁则）。

### 5.3 0.24.2：Producer/Coordinator 与评分

- Keyword、Context、AI 全部通过 Producer 注册，删除 `SearchService` 后置 AI 覆盖（`maybe_ai_suggestion`/`make_ai_suggestion` 的仲裁职责并入 Coordinator eligibility）。
- Query 文本分类复用 `needs_translation` 类门禁，但 Routing 仍不读 Awareness。
- Coordinator 按 §3.4 执行 eligibility → 分层 → Kind 去重 → 排序 → 双槽。
- 表驱动测试覆盖：直接输入英文、目标语言输入、选区、剪贴板、明确路由、结构化文本，以及"低分补全 + 英文剪贴板 → 补全 Primary"的分层回归。

### 5.4 0.24.3：采纳边界、降频与可观测性

- §3.6 采纳协议落地：前端 seq 本地校验 + `report_suggestion_adoption` 遥测 command。
- §3.8 降频落地：会话计数器 + 隐藏清零 + 表驱动测试。
- 日志记录 Producer、过滤 reason、排名和采纳，不记录 query/选区全文；定义指标"每 kind 曝光→采纳转换率"（0.25 Needle 触发决策的数据源）。

### 5.5 0.24.4：主窗口信息架构

```text
MainWindow
├── ModeHeader
├── QueryInput
│   └── CompletionGhost（输入延伸：Completion + 语音转写预览）
├── SuggestionBar
│   ├── Primary   → Tab
│   └── Secondary → Shift+Tab
├── Results
├── ResultFooter（结果导航/动作/分页 + Chord 闲置一行提示）
└── TransientFeedback
```

- CompletionGhost 只渲染输入延伸；语音 freeze 态照常渲染预览，不受建议更新干扰。
- SuggestionBar 只显示下一步建议、来源和采纳键（非 Completion 槽位）。
- ResultFooter 只显示结果导航、动作和分页；空 query 闲置态的 Chord 一行提示归此处，**受现有 ChordConfig 提示可见性控制**。
- ModeHeader 表达 AI/命令/剪贴板等持续模式（统一三种模式现有各自为政的徽章/hint 容器）。
- TransientFeedback 承载 loading/success/error。
- Chord 完整键帽表只在按住 Alt 时投影独立 Cheat Sheet，不再在输入框与 statusbar 间迁移。
- **窗口高度粘性槽位**：建议首次出现时长高，query 非空期间保持；仅在空态↔非空态/ESC 转换时 resync（复用 ai-mode 的 grow-only + resync 模式）。

### 5.6 0.24.5：键盘、设置与打磨

- Tab 恒采纳 primary、Shift+Tab 恒采纳 secondary（现状 Shift+Tab 与 Tab 等价，属行为变更）；`autosuggest_tab_key` 的 Tab/ArrowRight 均保留为 primary 采纳键（ArrowRight 为遗留别名，不做强制迁移），键帽投影读配置。
- IME 组字和独立模式优先，无候选不吞键；点击和键盘共用 acceptance 路径。
- 设置页建议区展示：Smart Tab 总开关、输入补全、环境建议、AI 兜底、第二建议、**建议降频**；AI Provider 与翻译私有配置留在各自真源。
- 视觉可在实施中迭代，但不得重新混合五类 UI 语义。

### 5.7 Needle：0.25 触发条件（原 0.24.6 移出）

**触发条件**（满足其一即立项，届时再建 `spikes/`）：

- 观测数据显示规则路由误判超阈值（翻译抢占误报、该提示未提示占比超标）；
- 出现规则无法分类的混合语言/模糊意图样本聚集。

**可选去风险探针**（半天级，不进仓库）：Windows x64 手动跑 Needle 2 官方 runner，量 warm 延迟/RAM/制品体积，结论一行记入本节。注意评估时 Needle 3（121M）已发布，届时一并记录选型理由。

**集成约束**（触发后仍然有效）：Windows 原生 runner + stdio JSON 优先，Wasm Component 次之，Python 仅对照；路由面闭合为 `translate/ask_ai/open_url/open_path/none`；只挂 suggestion lane、**永不阻塞结果 lane**（表内"同步 ≤20ms"指建议链路自身 p95，结果链路 <20ms 预算不受影响）；确定性规则高于模型，危险误路由必须为 0；指标基线须来自 0.24 线上观测而非手工 corpus。

## 六、验收

### 6.1 后端

- [ ] `SearchResponse` 只有一个 SuggestionSet 真源，无独立 AI 覆盖分支（grep `maybe_ai_suggestion` 为 0）。
- [ ] Keyword、Context、AI 全部通过 Producer + Coordinator；Producer 签名保持 `(query, snapshot)`。
- [ ] Primary/Secondary 按 Kind 去重、分层、稳定排序且数量不超过 2。
- [ ] 目标语言为中文时，主窗口直接输入合法英文自然文本，Primary=翻译、Secondary=AI（两能力均可用）。
- [ ] 输入目标语言自然文本时 Primary=AI，不产生同语言翻译。
- [ ] `chrome`、URL、路径、代码标识符和已命中路由不被翻译抢占；低分补全 + 英文剪贴板时补全为 Primary（分层回归）。
- [ ] 翻译插件/AI/Context binding 不可用时，对应候选被 eligibility 排除并记 filter reason。
- [ ] 未采纳时不触发 Capability；revision 与前端 seq 不符时采纳被本地拒绝。
- [ ] 降频：同 (kind, origin, 指纹) 连续 3 次未采纳后抑制，采纳/窗口隐藏清零（表驱动测试）。
- [ ] 采纳遥测日志含 producer/kind/slot/revision 匹配与否，不含原文。

### 6.2 前端

- [ ] Ghost 只渲染输入延伸（Completion + 语音预览），Context/AI/模型建议只进 SuggestionBar。
- [ ] ResultFooter 只显示结果导航/动作/分页，ModeHeader 是持续模式唯一呈现。
- [ ] Chord 完整键帽只在 Alt-hold Cheat Sheet 出现，不再在输入框和 Footer 之间迁移；闲置一行提示受 ChordConfig 控制。
- [ ] Tab/Shift+Tab/点击共用 acceptance；**Shift+Tab 与 Tab 行为不再等价**；无候选和 IME 组字时不误吞键。
- [ ] 同一建议不在两个视觉区重复出现；primary 为 Completion 时 bar 不重复渲染该槽。
- [ ] 新增 Producer 无需修改前端键盘/布局。
- [ ] 连续输入过程中窗口高度不逐键变化；高度变化仅发生在空态↔建议态转换。
- [ ] 语音转写预览路径不回归（freeze 态渲染、降频/建议更新不干扰）。
- [ ] ArrowRight 配置用户主采纳不破坏，secondary 恒为 Shift+Tab。
- [ ] 唤起、Focus、首结果和输入响应指标不退化。
