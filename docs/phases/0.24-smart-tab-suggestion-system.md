## 二、核心决策（已定）

**Suggestion 域 / 双槽 / 键随槽走**：后端 Suggestion 域管生产与仲裁；`SuggestionSet` 只暴露 `primary`/`secondary`（可点击采纳，无第三条）。Tab 恒采纳 primary、Shift+Tab 恒采纳 secondary，键随槽不随视觉区；primary 为 Completion 时 Tab 作用于 ghost，SuggestionBar 只渲染非 Completion 槽，同一建议不在两视觉区重复。Ghost overlay 收窄为**输入的自然延伸**（Completion 影子 + 语音转写预览，freeze/unfreeze 机制不动）。

**评分：分层 → 按 Kind 去重 → 排序 → 选槽**（`rank_score` 为规则排序值；`confidence` 保留给具备校准语义的模型输出，0.24 不建字段）。数值表是调分行为契约：

| 候选 | 初始 `rank_score` |
|---|---:|
| 关键词补全（fuzzy 命中） | `0.70 + 0.28 × fuzzy` |
| 打开 URL / 路径 / 资源管理器定位 | 0.95 / 0.93 / 0.88（**0.24.8 激活**，原 0.25 候选提前） |
| 翻译 Query/选区 | 0.92 |
| 翻译剪贴板 | 0.82 |
| AI 处理 Query / 选区 / 外语备选 / 兜底 | 0.80 / 0.72 / 0.62 / 0.55 |

分层先于分数：非空 query 时 query 派生候选（origin=None）优先于 awareness 派生（origin=Some）——否则低分补全会被翻译剪贴板 0.82 错误抢占 Primary。按 Kind 去重后取前两 Kind 为双槽；`secondary_min_rank=0.60` 精确挡掉 0.55 兜底。query 文本分类双门禁（`is_natural_language_shaped` 拉丁必含空格 + `needs_translation` 全套护栏）落实"`chrome`/URL/路径/代码标识符不得被翻译抢占"；awareness 分类宽松（`classify_awareness_text`，无空格门禁）。三源 Producer（Keyword/Context/Ai）由 SearchService 持有的 Coordinator 仲裁（编排层，非域依赖——`route_summary` 编排层传值防环）；Producer 纯函数，可用性判定归 Coordinator eligibility（`FilterReason` 逐候选 debug 日志）。

**SuggestionAction 三变体（0.24.8 修订）**：`RouteQuery{query}`（改写输入框+重搜）与 `EnterAiMode{prompt}` 本地乐观执行；`InvokeCapability{capability_id, args}`（0.24.8 新增，打开类）采纳侧复用 `run_builtin_action` 同步 IPC——CapabilityRegistry 的 origin/runtime/policy 门禁与 result Enter 路径同源，失败走动作错误反馈。`Kind = Completion | Translate | AskAi | OpenUrl | OpenPath | RevealInExplorer`（后三者为 0.24.8 打开类）。采纳协议：前端 seq 本地校验（revision = search seq，不符零 IPC 本地拒绝）→ action 分派 → fire-and-forget 遥测（id 为语义 slug，不记原文）。执行类采纳不新建通道、不加旁路 invoke 路径（spec-backend §六）。

**降频（建议域，默认开）**：`suppress_repeated`；计数键 = `(kind, origin, source_text 指纹)`（会话哈希不落盘），同键连续 3 次未采纳抑制；任一次采纳或主窗口隐藏清零。SearchService 持有，`suggestion/fatigue.rs` 纯逻辑表驱动测试。

**展示策略五开关**（`SuggestionConfig`，默认全开，AppConfig 门面上 wire 热更新）：completion/context/ai/secondary_enabled + suppress_repeated；环境建议闸只拦 awareness 派生不连坐 query 派生，AI 闸独立于 Provider 可用性。

**键盘**：Tab（或 ArrowRight 遗留别名，读 `autosuggest_tab_key`）恒 primary、Shift+Tab 恒 secondary（行为变更：不再与 Tab 等价）；Alt 按下放行（Alt+Tab 归 Windows）、IME 组字/独立模式/无候选不吞键；键盘与点击共用 `suggestion-accept.js`（staleness → 类型化 action → 遥测）。

### 打开类建议化——纯建议化（0.24.8，已定）

**定案**：环境感知的打开动作（打开链接/打开路径/资源管理器定位）从 result lane 整体移交建议槽。BuiltinEngine 撤 context-only 召回（空 query `base_score=1.0` 首屏填充与非空 `0.3` 弱召回两路径都删），result 只保留 keyword 命中路径（"打开链接"/"url" 显式搜索，Enter 执行不变）；建议侧 `ContextProducer` 产 OpenUrl(0.95)/OpenPath(0.93)/RevealInExplorer(0.88)，awareness 派生（剪贴板，origin=Clipboard）与 query 派生（输入框粘 URL/路径，origin=None，分层优先、同 Kind 去重）双路。空 query + 剪贴板 URL 时 result 恒空、Enter no-op，打开只走 Tab/Shift+Tab——**行为变更**：原"唤起→Enter 一步打开"的肌肉记忆让位给"智能提示统一走 Tab 采纳"的单一心智。

**理由**：用户实测反馈"复制链接后，打开提示出现在 result 而非 Tab 建议"——原分界线（可执行 vs 不可执行）是技术/信任边界，与用户心智边界（"Blink 理解我的环境并建议下一步"）不重合。备选"双入口"（result 保留 + 建议槽镜像，零回归、以采纳遥测数据 0.25 再决定撤留）被否——选纯建议化换心智统一；若 Enter 肌肉记忆反馈强烈，双入口回补是 0.25 的低成本选项。

**连带决策**：① `reveal_in_explorer` 一并建议化——否则空 query + 路径剪贴板会剩一条孤儿 result，复刻同款不一致；路径场景双槽齐备（Tab 打开 / Shift+Tab 定位）。② query 派生纳入——纯建议化后输入 URL 在 result lane 无 keyword 可匹配，不补则该场景完全无打开入口。③ 禁用一致性：建议侧与 result 侧同源检查 `disabled_builtin_actions`（动作粒度，两种派生都拦）与 `disabled_context_bindings`（binding 粒度只拦 awareness 派生——query 派生是输入意图，不受环境 binding 约束），禁用态经共享 cell（`Arc<RwLock>`）注入 producer，设置页保存即热生效。④ 打开类 awareness 派生受 `context` 展示开关闸（五开关结构不变，不加新键）；降频对打开类照常生效（同键 3 次未采纳抑制，采纳/隐藏清零）。

## 三、Chord 提示呈现（0.24.4 改 → 0.24.7 回退）

0.24.4 将 chord 提示重构为「Alt-hold Cheat Sheet 底部浮动卡片 + 空 query 闲置常驻行」，用户实测后 0.24.7 回退。**最终形态（零迁移）**：空 query 不按 Alt 无任何 chord 提示；空 query + Alt → 输入框 `.ghost-chord` 影子（0.8.5 视觉规格，CSS `:has()` 与补全影子互斥，chord.js 渲染）；非空 query + Alt → statusbar `.hint-secondary` 副行（0.16.1 互斥分工）。cheat-sheet.js/css 与闲置常驻行已删除。

复盘（保留以防重蹈）：①「随 query 空/非空就近切换位置」是跟随视线的特性不是缺陷；② 4~6 个动作撑不起 cheat sheet 卡片心智——视觉重量与信息密度错配，与主窗口轻量 hint 风格割裂；③ 闲置常驻行与 Alt 影子重复且制造迁移跳动，Blink 键盘流用户的可发现性不靠常驻提示。**教训：视觉形态类重构（尤其替换已打磨多年的轻量形态）应先用户实测再冻结验收项。**

## 四、Needle Router Spike 结论（0.24.6，0.25 决策依据）

结论 **no-go（off-the-shelf 不可 Adopt）**，全部数据与实验脚本见 `xtask/spikes/needle-router/`（48 样本数据集 + 7 个可重跑脚本 + decision.md 十节档案）。

- **运行形态**：`--serve` 常驻 HTTP 可行（RAM 64.5MB、warm p50 114~126ms、60 连发 0 错），但官方 runner 无 stdio JSON、健康合同 4 项缺失；单发冷进程 432ms 差 3~4 倍；depth 4 复读退化不可用。
- **跨模型定论（任务语义错位）**：Needle3（121M，多语言不含中文）0.396、qwen3.5-0.8B（中文原生 + json_schema + 中文 few-shot）0.646 均不达标——LLM 按内容语义分类，语言同源性等形式特征判定本就是规则（`gating.rs` CJK/正则，≈1.0）的完美任务；产品语境（中文提问=ask_ai）prompt 层注入穷尽证伪，微调是唯一路径而**语料来源（0.24.3 观测不记原文）是 0.25 立项真正前置**。
- **最终架构产出：三层混合**——规则形式层（100%，含 CJK 判定）+ 判别式语义层（embedding 实测 natural_zh 0.83、p50 15ms 唯一进同步预算；零样本首选中文 embedding/NLI，数据充足后 laya 微调候选——laya base 零样本 0.417 不可直接用但概率接口完整）+ 生成式整体退出路由。"内置小引擎"正确形态是中文判别式小模型（bge-small-zh 24M 等）经 ONNX InProcess（PP-OCR 先例），**无需 0.8B**。不存在"<500M 且原生 tool-calling 的中文开源模型"生态位。
- **正式 Adopt 触发条件（0.25，不变）**：线上观测显示规则路由误判超阈值，或混合语言/模糊意图样本聚集。集成约束：路由面闭合 `translate/ask_ai/open_url/open_path/none`；只挂 suggestion lane 永不阻塞结果 lane；确定性规则高于模型、危险误路由必须为 0；指标基线须来自线上观测；接入走 `ModelIntentProducer` + infra 原语（不进 EngineManager），对外暴露走 capability 注册。
