# Blink 0.20 — 高频内容与视觉工作流（Clipboard, Capture & Color Workflow）

> **范围**：修复便签与上下文建议的可预测性，深化剪贴板独立模式，闭环当前剪贴板/历史图片/pin 图的统一编辑入口，优化截图交互性能与像素精调，并建立来源无关的颜色解析和图片配色核心。
>
> **状态**：📋 规划中。
>
> **动机**：0.19 已完成剪贴板独立模式、图片编辑会话解耦和多屏截图/DPI 基础，但高频日用链路仍存在异常预填、跨页内容不能批量流转、图片编辑入口不完整、截图交互帧偏重，以及配色结果缺少可直接使用的角色和输出格式等问题。0.20 聚焦“捕获 → 筛选 → 编辑 → 复用”，不夹带执行体系重构。
>
> **前置**：0.15（截图与取色配色）、0.16（剪贴板图片、内容编辑器与便签）、0.17（便签回收站与剪贴板来源）、0.19.7（图片编辑会话解耦）、0.19.15–0.19.16（剪贴板独立模式与多屏截图/DPI 收敛）。
>
> **原则**：不改变 Alt+Space 主链路预算；弱上下文不隐式写入用户内容；剪贴板多选状态不污染普通搜索；批量复制失败时不覆盖原剪贴板；大图片不走 Base64/JSON 热路径；截图坐标统一使用 bitmap 物理像素；颜色识别只接受确定性字面量；颜色算法来源无关；图片编辑只保留一个会话核心。
>
> **范围拆分说明**：原规划中的 Capability 唯一执行入口、Action 全量分流、统一功能目录与 AI/MCP 出口管理已独立为 [0.21](./0.21-capability-unification-feature-catalog.md)，避免产品工作流与高风险架构迁移互相阻塞。

## 二、背景与产品目标

### 2.1 用户问题

1. **不可预测**：空闲 Alt+S 可能带入旧选区；空便签进入回收站；结构化文本被误判为翻译对象。
2. **流转不完整**：剪贴板只能逐条复制；历史图片和早期 pin 图不能稳定进入现有编辑器。
3. **视觉交互偏重**：截图拖选虽有 rAF，但获准帧仍可能重绘完整多屏底图并发起坐标 IPC。
4. **颜色结果不够可用**：颜色字面量没有一等结果；图片提色缺少角色、对比度和可直接粘贴的输出。

### 2.2 最小操作路径

| 目标 | 旧路径 | 0.20 路径 | 改善 |
|---|---|---|---|
| 批量复用剪贴板文本 | 逐条打开、复制、拼接 | Alt+C → 键盘多选 → Ctrl+C | 少 N-1 次往返 |
| 编辑历史图片 | 回贴剪贴板后再启动编辑 | 历史图片右键“编辑” | 少一次剪贴板覆盖 |
| 编辑 pin 图 | 另存/复制后再编辑 | pin 右键“编辑” | 保留当前窗口图像版本 |
| 使用颜色值 | 手动辨认/转换 | 输入颜色 → 预览 → 复制目标格式 | 确定性即时反馈 |
| 从截图产出配色 | 逐色取样或切换方案 | 框选 → 角色色/推荐方案 → 整组复制 | 一次产生可用结果 |

### 2.3 明确不是问题的

- `display_pages` 控制剪贴板一次加载几页，普通 `page_size` 控制每页展示几项，两者不合并。
- 历史总数不足时末页不满是正确行为，不生成占位数据。
- 图片编辑核心已存在；本版只补来源解析、入口、限制、错误和生命周期。
- SelectionCache 继续作为 Awareness 数据源；只是 Alt+S 不再隐式消费它。
- 图片角色色与基准色 harmony 是两类结果，核心可组合但 UI 分层展示。
- 0.20 不建立独立颜色窗口，不暴露图片配色 Capability，不处理任意本地图片文件。

## 三、横切决策

### 3.1 Alt+S 语义：输入框文本预填，不读选区缓存（修订）

**定案**（0.20.0 实施后修订）：主窗口按 Alt+S 时，**输入框有文本则预填到便签**，输入框为空则创建空白便签。**不读取** SelectionCache、默认高亮结果或剪贴板。query、结果项、选区、剪贴板创建便签均通过明确的 Context Ghost、右键或结果操作触发。

**理由**：默认高亮和缓存选区都是弱信号，不应隐式预填。但用户在输入框**已经打了字**是强信号——Alt+S 把这些字带过去符合用户预期。输入框为空时创建空白便签，不隐式消费选区缓存。

### 3.2 批量复制只选择文本且原子提交（已定）

**定案**：0.20.2 的多选集合只接纳可复制文本项；图片不显示批量选择态。所有 LazyCopy 全部成功后才一次写入系统剪贴板；任一失败、取消或 epoch 失效均不修改原剪贴板。

### 3.3 图片编辑单会话且拒绝替换（已定）

**定案**：同一时刻只有一个图片编辑会话。已有会话时，新入口激活现有编辑器并提示“请先完成或关闭当前编辑”，不得静默替换未保存标注。

### 3.4 配色首屏强调可用结果（已定）

**定案**：首屏展示“来自图片”的角色色和最多 3 个推荐方案；完整 harmony 放入“更多方案”。输出支持颜色列表、CSS variables，并显示背景/前景对比度与推荐文字色。

### 3.5 配置迁移只向前、不支持降级（已定）

**定案**：`display_count` 只向 `display_pages` 单向迁移。升级保存后仅写新字段，不双写旧字段，也不保证旧版本读取新配置后的行为。

## 五、分子版本实施方案

### 5.1 0.20.0 — 便签与上下文可靠性

#### 目标与契约

- “关闭便签”是单个后端原子工作流，不再由前端先保存、再发独立回收命令。
- final content 经 Unicode whitespace trim 后为空则物理删除；非空则保存最终内容并移入回收站。
- 应用整体退出只隐藏/结束窗口，不改变便签 visible/trash 状态。
- Alt+S 创建空白便签；显式来源动作才能预填。
- 内置动作失败统一进入可见 toast/status 反馈，不静默吞错。

#### 实施步骤

1. 在 `StickyService` 增加 `close_note(id, final_content, expected_updated_at)`，同一事务内完成 revision 校验、最终保存和 delete/trash 决策。
2. 定义 `StickyCloseOutcome::{DeletedEmpty, Trashed}`；冲突、存储失败使用现有结构化工作流错误。
3. 前端拦截单便签关闭，提交 final content；只有成功后才真正关闭窗口。失败时保持窗口与内容并显示错误。
4. 保留独立“隐藏”动作；spare 窗口回收不得调用 close workflow。
5. 新建纯函数 `derive_sticky_title(content, locale)`：取第一条非空行、剥离常见 Markdown 前缀/行内标记、按 Unicode 字符安全截断到 48 字符；空内容回退本地化“便签”。
6. 内容保存、置顶切换、spare 借用/回收时同步 title 与 skip-taskbar；回收时重置 title，防止下一张便签继承。
7. 抽取共享 `sticky/palette.js`，顶部菜单和右键菜单只消费颜色 id 与 CSS token，不保存第二份 hex。
8. 修改 Alt+S：无论 query/结果/SelectionCache 状态均传空内容。为 query、结果文本、Selection 分别保留或新增显式“创建便签”动作。
9. 在 `needs_translation` 前加入分类型 `is_non_prose_structured_text`：颜色、UUID、hash、版本、IP/端口、邮箱、CSS 声明/变量、短 JSON、命令参数、纯代码标识符。每类为独立纯函数，禁止总括式“像代码”正则。
10. 抽取主窗口动作错误投影 helper：结构化错误 → 本地化消息 → toast/status；日志只记录 action id、error kind、长度/尺寸，不记录正文。

#### 验收

- [x] 空便签关闭后数据库与回收站均不存在；非空便签保存最终字符后进入回收站并可恢复。
- [x] revision conflict/数据库失败时窗口不关闭，最终内容仍留在编辑器中。
- [x] 应用退出、普通隐藏、用户关闭、管理器回收四条路径状态互不串线。
- [x] Alt+S 空输入框创建空白便签；非空输入框预填文本；SelectionCache 有值时不隐式读取。
- [x] 显式 query/result/selection 动作仍可创建带内容便签。
- [x] title 对中文、emoji、组合字符、Markdown、超长行安全；spare 复用不继承旧 title。
- [x] 结构化文本负向分类每类至少 5 个正例和 5 个自然语言反例；显式“翻译 …”不受抑制。
- [x] 无剪贴板图片时执行编辑动作有可见反馈；日志无便签、剪贴板、选区原文。

### 5.2 0.20.1 — 剪贴板页数配置与模式上限

#### 配置契约

```text
clipboard.display_pages: integer 1..=20, default 3
effective_limit = display_pages × current_page_size
```

- 新旧字段同时存在：`display_pages` 优先，忽略 `display_count` 并记录一次 warn。
- 只有旧字段：`ceil(display_count / page_size)` 后钳制到 `1..=20`；非法旧值回退 3 页。
- 迁移后的首次成功保存只写 `display_pages`，不双写，不支持降级。
- 后续修改 `page_size` 只改变 effective limit，不重新换算 `display_pages`。
- 旧 managed setting id `clipboard.display_count` 在一版内作为只写 alias 接受并换算，list 只返回 `clipboard.display_pages`；下一大版本可删除 alias。

#### 实施步骤

1. 为 ClipboardConfig 实现显式兼容反序列化/迁移 helper，输入同时包含 clipboard shard 与 search page size。
2. 更新 config command、setting service、managed settings、启动 wiring 和设置 UI。
3. ClipboardEngine 保存 `display_pages` 快照；每次搜索从 SearchService 获取当前 `page_size` 或调用方传入已计算 limit，禁止两边各算一套。
4. 为 clipboard mode 定义独立 `ResultLimitPolicy`；普通搜索仍走全局 `max_results`。
5. 前端 `results.js` 在 clipboard mode 使用 mode limit，不再被本地 `maxResults` 二次截断；退出模式恢复普通上限。
6. 设置热更新只影响下一轮搜索，不中途裁剪当前结果集合。

#### 验收

- [x] `display_count=30,page_size=9` 迁为 4 页；`display_count=18,page_size=9` 迁为 2 页。
- [x] 新旧字段并存时新字段胜出；非法/越界输入安全回退或钳制。
- [x] 保存后的配置中不存在 `display_count`；旧版降级不在支持范围。
- [x] 新安装默认 3 页；改变 page size 后 effective limit 随之变化，页数不变。
- [x] Alt+C 与关键词进入剪贴板模式使用相同上限，且不受普通 `max_results` 截断。
- [x] 普通搜索、AI 模式、命令模式的结果上限行为无变化。

### 5.3 0.20.2 — 剪贴板文本跨页多选与原子批量复制

#### 状态与键盘优先级

新建纯状态模块维护：

```text
selectedKeys: Set<stableTextHitId>
anchorKey: stableTextHitId | null
selectionEpoch: number
copyGeneration: number
```

键盘规则：

1. IME composition 优先，期间不接管多选快捷键。
2. `Ctrl+Space` 切换当前文本项；图片项无选择态。
3. 已经存在多选时，`Shift+Up/Down` 扩展连续范围并允许跨页；尚未开始多选时保留输入框文本选择。
4. query 为空时 `Ctrl+A` 全选当前返回的全部文本项；query 非空时保留输入框全选。
5. 存在多选时 `Ctrl+C` 批量复制；不存在多选时保留输入框原生复制。
6. `Esc` 顺序：结束 IME/关闭菜单 → 清空多选 → 退出 clipboard mode → 隐藏窗口。

#### 实施步骤

1. 从 `clipboard-mode.js` 抽出无 DOM 的 selection reducer/range helper，并单测跨页顺序、重排和删除。
2. 选择以稳定文本 history id 为真源；重渲染只重投影 CSS，不按 DOM index 保存状态。
3. 翻页或同 query 增量重排后保留仍存在的 key；已消失 key 清理并修正 anchor。
4. 批量复制按当前全局结果顺序生成 id 列表，以并发上限 4 拉取完整文本。
5. 所有请求成功且 generation/epoch 仍有效后，使用 `\n` 拼接并单次写剪贴板；任一失败则全部放弃。
6. 退出模式、query 变化或窗口隐藏递增 generation，旧请求不得写剪贴板、状态栏或 toast。
7. 状态栏显示“已选择 N 段文本”“正在加载 N 项”“已复制 N 段文本”或原子失败消息。

#### 验收

- [x] Ctrl+Space、Shift+方向键可跨页选择；图片从不进入 selectedKeys。
- [x] query 非空时 Ctrl+A 选择输入文本，query 为空时选择全部返回文本。
- [x] 翻页和同 query 重渲染后选择稳定；退出模式/隐藏窗口后完全清空。
- [x] 右键删除剪贴板历史记录后应该维持在剪贴板chord内而不是退出
- [x] 批量 LazyCopy 并发不超过 4，输出严格按结果全局顺序。
- [x] 任一加载失败、退出或 query 改变时不修改原系统剪贴板。
- [x] 普通搜索和输入框原生复制/选择行为不受影响。

### 5.4 0.20.3 — 确定性颜色字面量与共享 swatch

#### 支持范围

- `#RGB`、`#RGBA`、`#RRGGBB`、`#RRGGBBAA`，alpha 固定在末尾。
- `rgb()/rgba()` 常用整数与百分比。
- `hsl()/hsla()` 常用角度与百分比。
- 不支持 CSS 命名色、渐变、变量引用、长文本中的局部颜色。

#### 实施步骤

1. 新建 Rust `domain/color` 纯函数，输出统一 RGBA8 和 canonical HEX/RGB/HSL；统一使用 half-away-from-zero 或文档指定的固定舍入，Rust/JS fixture 必须一致。
2. 新增 sync-lane `ColorEngine`：仅当完整 trim query 可解析时返回 priority 结果，不 takeover。
3. 定义颜色结果 data contract，包含原始文本、RGBA、canonical 三格式和 alpha 信息。
4. 新建前端 `shared/color`：校验后端契约、对剪贴板完整文本做同范围降级识别、渲染棋盘底/swatch/浅色边界。
5. Enter 复制与输入同族的 canonical 格式；右键可复制 HEX/RGB/HSL。
6. Rust 与 JS 共同读取一份 JSON fixture；fixture 包含合法、边界、非法和舍入案例。

#### 验收

- [x] 颜色结果进入同步首批，普通英文、应用名、CSS 命名色不误触发。
- [x] Rust/JS 对所有 fixture 的 RGBA 与 canonical 输出完全一致。

### 5.5 0.20.4 — 图片编辑多来源闭环

#### 来源与资源限制

```text
EditorImageSource = CurrentClipboard | ClipboardHistory(image_id) | PinWindow(window_label)
compressed/input bytes <= 32 MiB
width,height <= 16_384
decoded RGBA bytes <= 256 MiB
single active editor session
```

#### 实施步骤

1. 在 app 层建立统一 `ImageEditorService::open(source)`；domain 只传受控 id/label，不传 Base64。
2. 当前剪贴板读取、历史 BLOB 查询、pin 引用解析后统一转换为 `PinImage::{Png,Bgra}`。
3. 校验 PNG 尺寸、解码预算、BGRA stride/长度；阻塞解析/编码进入 `spawn_blocking`。
4. editor session 已存在时返回结构化 `AlreadyActive`，窗口层激活旧 editor，前端显示提示。
5. pin registry 改为窗口 label 拥有稳定 `Arc<PinImage>`；协议 URL 只引用该窗口当前 image generation。
6. pin 刷新/重新标注时原子替换其引用；窗口销毁时释放。不得再依赖最近 8 项缓存维持可编辑性。
7. 历史图片右键“编辑”按 image id 读取原图，不先覆盖剪贴板；pin 右键只传自身 window label。
8. 编辑完成继续复用 copy/save/pin；取消只结束 editor session，不结束截图、长截图或 pin 生命周期。

#### 验收

- [ ] 当前剪贴板、任意历史图片、任意仍显示的 pin 图进入同一编辑器核心。
- [ ] 超过旧 8 项后早期仍显示 pin 可编辑；关闭 pin 后强引用释放。
- [ ] 第二入口不会替换活跃编辑内容，而是激活旧窗口并提示。
- [ ] PNG/BGRA 长度、尺寸、解码预算均有正反例测试；阻塞编码不裸跑在 async worker。
- [ ] 无图片、损坏、超限、查询失败、窗口创建失败均有结构化日志和可见反馈。

### 5.7 0.20.6 — 像素精调与取色冻结

#### 状态机

```text
Idle
SelectingNew
MovingSelection
ResizingSelection
ColorPickerFollowing
ColorPickerFrozen
Annotating
```

事件只由当前状态消费：标注对象键盘操作优先于选区；文本输入/IME 优先于截图快捷键；ColorPickerFrozen 中鼠标移动只移动内部准星，不解除冻结。

#### 实施步骤

1. 在 `ss-selection-geometry` 增加纯函数：选区 1 bitmap px 移动、边界钳制、resize 1:1 约束、准星步进。
2. 已有选区且未标注时，方向键移动整个选区 1 物理像素。
3. 新建/resize 时按 Shift 强制 1:1，松开恢复自由比例；方向键不提供 10px 加速。
4. 取色 following 状态下滚轮进入 frozen 并调整放大倍率；frozen 中方向键/鼠标只在冻结样本内移动准星。
5. Enter 确认当前像素；Esc 先退出 frozen/取色，再按截图总状态处理；再次移动真实鼠标不会自动跳回过期位置，只有显式退出 frozen 后恢复跟随。
6. 所有提示通过 `kbd.js` 和 i18n 按状态渲染。

#### 验收

- [ ] 选区和取色准星每次移动正好 1 bitmap 物理像素，混合 DPI 下颜色和坐标一致。
- [ ] Shift 只约束新建/resize，不改变方向键步长，不干扰图形工具既有等边逻辑。
- [ ] frozen 内滚轮、鼠标、方向键、Enter、Esc 行为与状态表一致。
- [ ] 工具切换、失焦、session reset 后无残留 frozen/precision 状态。

### 5.8 0.20.7 — 来源无关配色核心与可用输出

#### 算法契约

- 输入：基准 RGBA 或不超过 `96×96` 的 RGBA8 样本及来源元数据。
- 输出：确定性角色色、占比、对比度、推荐文字色、最多 3 个推荐方案及完整 harmony 列表。
- 透明度 `< 0.5` 的像素跳过；空样本返回结构化无结果。
- 使用 OKLab、确定性 k-means++ seed；`K=3..8`，最大 32 次迭代，中心位移小于固定 epsilon 时提前停止。
- K 选择、近色合并、点缀保留、边缘背景权重等常量集中在 `PALETTE_ALGORITHM_V1`，禁止散落 UI。
- 聚类中心映射到最近真实采样像素，保证代表色来自原图。
- Worker 协议携带 `version + epoch`；异常时只对同一有界样本同步降级。

具体阈值先由 golden fixture 反推并在实现前冻结；变更阈值必须更新 fixture 说明，不能只为单张图片调参。

#### 实施步骤

1. 建立 fixtures：固色、低饱和 UI、彩色 UI、照片、透明 PNG、渐变、小面积高饱和点缀、深浅主题截图。
2. 抽出无 DOM/Tauri/`ss-state` 依赖的颜色转换、DeltaE、对比度、文字色、harmony、聚类和角色分配纯模块。
3. 主线程先绘制 ≤96×96 分析 canvas，再读像素；禁止完整 4K `getImageData`。
4. Worker 负责聚类和方案生成；选区/档位/候选变化防抖 120ms，旧 epoch 丢弃。
5. 首屏渲染角色色与 3 个推荐方案；“更多方案”展开类似、互补、分裂互补、三角色、明暗、柔和、鲜明、深色等完整结果。
6. 显示 WCAG 对比度值和推荐黑/白文字色；色块保持左键设标注色、右键单色复制。
7. 支持勾选、复制所选/整组；输出格式包含 HEX/RGB/HSL、纯颜色列表、CSS variables。CSS 变量名按角色稳定生成，如 `--blink-color-background`。
8. 复制成功显示对应勾与数量；失败不改变选择并显示可见错误。

#### 验收

- [ ] 核心模块不 import `ss-state`、标注引擎、DOM 或 Tauri API。
- [ ] 4K 选区先缩放再读像素，主线程不执行完整选区聚类。
- [ ] 相同输入重复运行结果和顺序完全一致；自动色数在 3–8，代表色可在样本中找到。
- [ ] fixtures 的角色、色数范围、点缀保留和背景判断满足冻结预期。
- [ ] 选区变化 120ms 后启动最新分析，旧 epoch 不覆盖新结果；Worker 异常降级可用。
- [ ] 首屏最多 3 个推荐方案，完整方案折叠；对比度和推荐文字色计算有 WCAG 公式单测。
- [ ] 列表、CSS variables、HEX/RGB/HSL 输出顺序稳定且互相等价。
