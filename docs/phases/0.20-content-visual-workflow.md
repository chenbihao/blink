# Blink 0.20 — 高频内容与视觉工作流（Clipboard, Capture & Color Workflow）

> **范围**：修复便签与上下文建议的可预测性，深化剪贴板独立模式，闭环当前剪贴板/历史图片/pin 图的统一编辑入口，优化截图交互性能与像素精调，建立来源无关的颜色解析和图片配色核心，并补齐便签管理/任务栏辨识与剪贴板键盘操作。
>
> **状态**：🚧 0.20.0–0.20.7 已完成（含配色能力化修订：Rust 单一真源、`analyze_image_palette` Capability、真实像素智能搭配、复制 UI 收敛）；0.20.8 日用交互补齐待实施。
>
> **动机**：0.19 已完成剪贴板独立模式、图片编辑会话解耦和多屏截图/DPI 基础，但高频日用链路仍存在异常预填、跨页内容不能批量流转、图片编辑入口不完整、截图交互帧偏重，以及配色结果缺少可直接使用的角色和输出格式等问题。0.20 聚焦“捕获 → 筛选 → 编辑 → 复用”；0.20.7 修订只建立图片配色这一项闭合 Capability，不夹带 Action 全量迁移或功能目录重构；0.20.8 补齐排查中发现的便签入口/任务栏标题回归和剪贴板模式键盘短路径。
>
> **前置**：0.15（截图与取色配色）、0.16（剪贴板图片、内容编辑器与便签）、0.17（便签回收站与剪贴板来源）、0.19.7（图片编辑会话解耦）、0.19.15–0.19.16（剪贴板独立模式与多屏截图/DPI 收敛）。
>
> **原则**：不改变 Alt+Space 主链路预算；弱上下文不隐式写入用户内容；剪贴板多选状态不污染普通搜索；批量复制失败时不覆盖原剪贴板；大图片不走 Base64/JSON 热路径；截图坐标统一使用 bitmap 物理像素；颜色识别只接受确定性字面量；颜色算法来源无关且只有一个 Rust 真源；图片编辑只保留一个会话核心。
>
> **范围拆分说明**：Action 全量分流、统一功能目录、调用来源类型墙与 AI/MCP 出口管理仍独立进入 [0.21](./0.21-capability-unification-feature-catalog.md)。0.20.7 只新增 `analyze_image_palette` 这一项纯分析 Capability，并复用现有 Registry、ImageStash 与图片会话，不提前实现 0.21 的目录和授权体系。

## 二、背景与产品目标

### 2.1 用户问题

1. **不可预测**：空闲 Alt+S 可能带入旧选区；空便签进入回收站；结构化文本被误判为翻译对象。
2. **流转不完整**：剪贴板只能逐条复制；历史图片和早期 pin 图不能稳定进入现有编辑器。
3. **视觉交互偏重**：截图拖选虽有 rAF，但获准帧仍可能重绘完整多屏底图并发起坐标 IPC。
4. **颜色结果不够可用**：颜色字面量没有一等结果；图片提色缺少角色、对比度和可直接粘贴的输出。
5. **日用入口不完整**：便签右键缺管理入口；非置顶便签虽已有首行标题代码，却因次级窗口 ACL 未授予 `set-title` 而在任务栏仍都显示“便签”；剪贴板模式的编辑/删除只能走右键菜单。

### 2.2 最小操作路径

| 目标 | 旧路径 | 0.20 路径 | 改善 |
|---|---|---|---|
| 批量复用剪贴板文本 | 逐条打开、复制、拼接 | Alt+C → 键盘多选 → Ctrl+C | 少 N-1 次往返 |
| 编辑历史图片 | 回贴剪贴板后再启动编辑 | 历史图片右键“编辑” | 少一次剪贴板覆盖 |
| 编辑 pin 图 | 另存/复制后再编辑 | pin 右键“编辑” | 保留当前窗口图像版本 |
| 使用颜色值 | 手动辨认/转换 | 输入颜色 → 预览 → 复制目标格式 | 确定性即时反馈 |
| 从截图产出配色 | 逐色取样或切换方案 | 框选 → 角色色/推荐方案 → 整组复制 | 一次产生可用结果 |
| 管理当前便签 | 顶部“更多” → 便签管理 | 右键 → 便签管理 | 入口与当前操作位置一致 |
| 区分多个非置顶便签 | 逐个点开同名“便签”任务 | 任务栏直接显示内容首条非空行 | 无需逐窗试错 |
| 编辑/删除剪贴板项 | 右键 → 编辑/删除 | 光标定位 → Ctrl+E / Ctrl+D；空查询可用 Delete | 保持双手在键盘上 |

### 2.3 明确不是问题的

- `display_pages` 控制剪贴板一次加载几页，普通 `page_size` 控制每页展示几项，两者不合并。
- 历史总数不足时末页不满是正确行为，不生成占位数据。
- 图片编辑核心已存在；本版只补来源解析、入口、限制、错误和生命周期。
- SelectionCache 继续作为 Awareness 数据源；只是 Alt+S 不再隐式消费它。
- 图片角色色与基准色数学配色是两类结果：前三组和“原图智能搭配”只返回原图真实颜色；显式基准色方案允许生成新颜色，UI 必须分层标识。
- 0.20 不建立独立颜色窗口或本地文件选择入口；0.20.7 仅通过既有截图/图片编辑会话与 `image_ref | png` 建立来源无关配色 Capability。
- 便签首行标题派生算法不是缺失项：Rust/JS 实现和 spare 重置均已存在；0.20.8 修复的是 `sticky-*` capability 未授权 `core:window:allow-set-title` 导致的运行时拒绝，并补验证防止文档再次与实际行为失配。

## 三、横切决策

### 3.1 Alt+S 语义：输入框文本预填，不读选区缓存（修订）

**定案**（0.20.0 实施后修订）：主窗口按 Alt+S 时，**输入框有文本则预填到便签**，输入框为空则创建空白便签。**不读取** SelectionCache、默认高亮结果或剪贴板。query、结果项、选区、剪贴板创建便签均通过明确的 Context Ghost、右键或结果操作触发。

**理由**：默认高亮和缓存选区都是弱信号，不应隐式预填。但用户在输入框**已经打了字**是强信号——Alt+S 把这些字带过去符合用户预期。输入框为空时创建空白便签，不隐式消费选区缓存。

### 3.2 批量复制只选择文本且原子提交（已定）

**定案**：0.20.2 的多选集合只接纳可复制文本项；图片不显示批量选择态。所有 LazyCopy 全部成功后才一次写入系统剪贴板；任一失败、取消或 epoch 失效均不修改原剪贴板。

### 3.3 图片编辑单会话且拒绝替换（已定）

**定案**：同一时刻只有一个图片编辑会话。已有会话时，新入口激活现有编辑器并提示“请先完成或关闭当前编辑”，不得静默替换未保存标注。

### 3.4 配色首屏强调可用结果，格式与批量模板分层（修订）

**定案**：首屏展示四组只含原图真实像素的结果：图片主题色、视觉焦点色、均衡/界面关键色、原图智能搭配；显式基准色生成的数学方案放入“更多方案”并标明“非原图提取色”。智能搭配按背景、表面、正文、主强调、可选次强调分配角色，以正文对比度 `>= 4.5:1`、非文本强调对比度 `>= 3:1` 为硬门槛；无法满足时不伪造颜色，降级为均衡配色或不显示。

HEX/RGB/HSL 是全面板共享的颜色表示格式；“每行一个”和 CSS variables 是批量复制模板，不再与颜色格式混在第二个 select 中。当前颜色、单色复制、复制整组与复制多选统一消费共享格式；批量模板收进“复制整组/所选”的菜单。

### 3.5 配色分析是 Capability，选区与吸管仍是 Interaction（修订）

**定案**：`analyze_image_palette` 接收一份已经确定的图片资源并返回结构化配色，是稳定 id、有限参数和明确结果的一次调用，归入 Capability。区域拖选、吸管 following/frozen、方向键精调和面板生命周期继续属于 Screenshot/ImageEditor Interaction，Capability 不操纵 DOM、不伪造用户手势，也不把“等待用户选区”报告为分析完成。

本地截图面板不得把 4K RGBA/PNG 用 Base64 或 JSON 回传：普通截图复用 Screenshot SESSION 的 BGRA 并只传 bitmap `x/y/w/h`；剪贴板/历史/pin 编辑复用 Image Editor SESSION 的原始 PNG 并只传选区。长截图不支持配色提取，完成时不为配色上传或暂存拼接大图；普通取色和标注颜色仍可用。AI/MCP/CLI 消费方走既有 `image_ref | png` 契约。会话适配层与 Capability 都调用同一个 Rust 配色核心，不保留 JS/Rust 双算法。

### 3.6 配置迁移只向前、不支持降级（已定）

**定案**：`display_count` 只向 `display_pages` 单向迁移。升级保存后仅写新字段，不双写旧字段，也不保证旧版本读取新配置后的行为。

### 3.7 剪贴板快捷删除只作用于 active 单项（已定）

**定案**：`Ctrl+E` 编辑结果光标所在的文本项；`Ctrl+D` 删除结果光标所在的单条文本或图片历史。裸 `Delete` 仅在剪贴板查询为空时等价于 `Ctrl+D`，查询非空时保留输入框前删字符语义。IME composition 期间全部放行。

0.20.2 的多选集合继续只服务文本批量复制；0.20.8 不把快捷删除解释为无确认的批量删除。编辑从 active 项的既有 `edit_text_item` action 分派，删除复用文本/图片单条删除命令，成功后保持 clipboard mode 并刷新当前页。

## 五、分子版本实施方案

### 5.1 0.20.0 — 便签与上下文可靠性

#### 目标与契约

- “关闭便签”是单个后端原子工作流，不再由前端先保存、再发独立回收命令。
- final content 经 Unicode whitespace trim 后为空则物理删除；非空则保存最终内容并移入回收站。
- 应用整体退出只隐藏/结束窗口，不改变便签 visible/trash 状态。
- Alt+S 创建空白便签；显式来源动作才能预填。
- 内置动作失败统一进入可见 toast/status 反馈，不静默吞错。

#### 实施步骤

1. 在 `StickyService` 增加 `close_note(id, final_content, expected_updated_at)`，同一事务内完成 revision 校验、最终保存和 delete/trash 决策。
2. 定义 `StickyCloseOutcome::{DeletedEmpty, Trashed}`；冲突、存储失败使用现有结构化工作流错误。
3. 前端拦截单便签关闭，提交 final content；只有成功后才真正关闭窗口。失败时保持窗口与内容并显示错误。
4. 保留独立“隐藏”动作；spare 窗口回收不得调用 close workflow。
5. 新建纯函数 `derive_sticky_title(content, locale)`：取第一条非空行、剥离常见 Markdown 前缀/行内标记、按 Unicode 字符安全截断到 48 字符；空内容回退本地化“便签”。
6. 内容保存、置顶切换、spare 借用/回收时同步 title 与 skip-taskbar；回收时重置 title，防止下一张便签继承。
7. 抽取共享 `sticky/palette.js`，顶部菜单和右键菜单只消费颜色 id 与 CSS token，不保存第二份 hex。
8. 修改 Alt+S：无论 query/结果/SelectionCache 状态均传空内容。为 query、结果文本、Selection 分别保留或新增显式“创建便签”动作。
9. 在 `needs_translation` 前加入分类型 `is_non_prose_structured_text`：颜色、UUID、hash、版本、IP/端口、邮箱、CSS 声明/变量、短 JSON、命令参数、纯代码标识符。每类为独立纯函数，禁止总括式“像代码”正则。
10. 抽取主窗口动作错误投影 helper：结构化错误 → 本地化消息 → toast/status；日志只记录 action id、error kind、长度/尺寸，不记录正文。

#### 验收

- [x] 空便签关闭后数据库与回收站均不存在；非空便签保存最终字符后进入回收站并可恢复。
- [x] revision conflict/数据库失败时窗口不关闭，最终内容仍留在编辑器中。
- [x] 应用退出、普通隐藏、用户关闭、管理器回收四条路径状态互不串线。
- [x] Alt+S 空输入框创建空白便签；非空输入框预填文本；SelectionCache 有值时不隐式读取。
- [x] 显式 query/result/selection 动作仍可创建带内容便签。
- [x] title 对中文、emoji、组合字符、Markdown、超长行安全；spare 复用不继承旧 title。
- [x] 结构化文本负向分类每类至少 5 个正例和 5 个自然语言反例；显式“翻译 …”不受抑制。
- [x] 无剪贴板图片时执行编辑动作有可见反馈；日志无便签、剪贴板、选区原文。

### 5.2 0.20.1 — 剪贴板页数配置与模式上限

#### 配置契约


### 5.8 0.20.7 — 来源无关配色核心与可用输出

#### 现状与修订目标

0.20.7 首版已在前端建立 OKLab 聚类、三组原图提取方案、数学配色、对比度与复制 UI，但算法与图片资源仍停留在 WebView：完整选区由前端 `getImageData()` 扫描，Worker 只消费前端直方图；单色格式与批量复制格式各有一份状态；透明度棋盘 Canvas 又被滑条圆角裁切。修订目标是把闭合分析收敛为 Rust 单一真源和 `analyze_image_palette` Capability，同时保持选区/吸管 Interaction 的即时反馈与现有图片会话生命周期。

#### 结果协议与算法契约

- 输入分两类：本地 Interaction 使用后端会话来源 + bitmap 选区；Capability 公共契约使用 `image_ref | png`，二选一。`png` 只作为有界兼容/测试输入，大图片和所有 UI 热路径必须使用会话来源或 `image_ref`，不得用 Base64/JSON 搬运完整图片。所有图片和解码后像素继续受既有大小、尺寸、超时与取消预算约束。
- 输出为结构化主题摘要、样本信息、角色色、四组原图方案和显式基准色数学方案；颜色项至少携带稳定 hex/rgb、占比、角色、对比度与推荐文字色，方案携带稳定 id/label/description/source_kind/confidence。
- 四组原图方案固定回答不同问题：面积主导的“图片主题色”、保护小面积高色度点缀的“视觉焦点色”、背景/层级/点缀并重的“均衡配色/界面关键色”、满足角色与可读性约束的“原图智能搭配”。四组均只返回真实输入像素，按 OKLab 距离稳定去重。
- 智能搭配先从角色色、显著色和均衡色的底层候选池选背景/表面/正文/主强调/可选次强调，而不是从已渲染 DOM 二次取色。正文对比度 `>= 4.5:1`、强调对比度 `>= 3:1` 为硬约束；再按亮度阶梯、色相协调、候选可靠度、色度预算和两两距离评分。没有合格组合时返回结构化低置信/无结果，不通过数学变换伪造“原图色”。
- 数学方案与图片提取彻底分层：显式 anchor 才可生成新颜色；从 HSL 迁为 OKLCH 明度/色度/色相变换并做 sRGB gamut mapping，输出明确标记 `source_kind=generated`。
- 透明度 `< 0.5` 的像素跳过；空样本返回结构化无结果。使用确定性 seed，`K=3..8`、最大 32 次迭代、固定收敛 epsilon；聚类中心映射到最近真实像素。
- 阈值、色度预算、近色合并、点缀保留和组合评分权重集中在版本化算法常量中。阈值变更必须更新跨 Rust/JS 共用 golden fixture 说明，禁止为单张图片特调。

`CapabilityResult` 使用 `Items`：每个方案是一项自解释 `data`，AI/CLI/MCP 只读取纯净数据；本地 UI 投影不把复制按钮、DOM 类名或中文展示布局塞回能力结果。图片内容属于敏感上游资源，Capability 只分析调用方已获准读取的 `image_ref | png`，不自行截屏或打开选择器。

#### 图片来源与零回传链路

1. **普通截图**：前端只传经 `ss-selection-geometry.js` 计算的 bitmap `x/y/w/h + epoch`；app 适配层从 Screenshot SESSION `crop()` 取得 BGRA，`spawn_blocking` 调配色核心。不得把 Canvas RGBA、PNG、Base64 或 JSON 字节数组从 WebView 回传。
2. **剪贴板/历史/pin 编辑**：前端只传编辑会话选区；后端从 Image Editor SESSION 取得原始 PNG，解码/裁剪后分析。一次会话内允许按资源预算缓存解码像素，关闭会话即释放。
3. **长截图**：不支持配色提取。进入长截图模式后禁用该入口，完成、预览、复制和保存链路均不为配色编码、上传或暂存拼接大图；普通取色和标注颜色不受影响。

### 5.9 0.20.8 — 便签入口、任务栏辨识与剪贴板键盘短路径

#### 排查结论

1. **便签右键入口**：顶部“更多”菜单已经通过共享 API `showStickyManager()` 打开管理窗口；便签自绘右键菜单只有编辑、颜色、隐藏、删除，缺的是同一入口的菜单投影，不需要新增 Rust command 或窗口。
2. **任务栏标题**：`derive_sticky_title`、前端等价派生、保存后 `setTitle()` 和 spare 回收重置均已实现。实际阻断点是 `capabilities/secondary-windows.json` 覆盖了 `sticky-*`，却没有授予 `core:window:allow-set-title`；因此 JS 调用被 Tauri ACL 拒绝，窗口保留 builder 的固定标题“便签”。这是 0.20.0 验收与运行时权限不一致的回归补齐。
3. **剪贴板快捷键**：文本结果已经声明 `edit_text_item` secondary action；文本与图片已有 `delete_clipboard_item` / `delete_clipboard_image` 命令，列表也已有模式内重载与位置恢复。缺口只在 `clipboard-mode.js` 的键盘门禁和对 active 项的动作选择。

#### 实施步骤

1. 在便签自绘右键菜单中增加“便签管理”，文案走 i18n，点击后先关闭菜单，再调用与顶部入口相同的 `showStickyManager()`；失败走现有结构化错误归一化与可见反馈，不复制管理窗口逻辑。
2. 为覆盖 `sticky-*` 的次级窗口 capability 增加最小权限 `core:window:allow-set-title`。不扩大到窗口创建、任意 WebView 或其他无关权限；保留前端标题同步的失败日志。
3. 补一条 capability/配置静态验证，确保便签窗口具备 `set-title` 权限；手测新建窗口、既有窗口、spare 借用/回收和语言 fallback，避免只验证纯派生函数。
4. 在 clipboard mode 的 IME 门禁之后增加快捷键分派：`Ctrl+E` 从 active 项 actions 中查找 `runId=edit_text_item` 并复用 `activateItem`；图片项或无 active 项不误开文本编辑器。
5. `Ctrl+D` 只对 `source=clipboard` 的 active 项按文本/图片类型复用既有单删命令；颜色降级结果等非历史项不得删除。裸 `Delete` 仅在 query 为空时进入同一路径，query 非空时不得 `preventDefault()`。删除成功调用模式内 reload，保留当前页并由既有 reconcile 清理已不存在的多选 key；失败保留结果、模式和选择并显示错误。
6. 为快捷键判定/目标解析抽出无 DOM helper，覆盖 Ctrl/Meta、大小写、IME、非空 query、文本/图片、无 active、已有多选等组合；键盘 handler 不读取完整 LazyCopy 文本来判断是否可编辑。

#### 验收

- [ ] 单便签任意位置右键可见“便签管理”，与顶部入口打开同一个复用的管理窗口；连续点击、窗口已显示和打开失败均不产生第二套状态。
- [ ] 非置顶便签在任务栏显示内容第一条非空行；空内容回退“便签/Sticky”，Markdown、中文、emoji 与超长行沿用 48 Unicode 字符契约；多个非置顶便签可直接区分。
- [ ] 置顶切换后 `skip-taskbar` 与标题状态不串线；新建、重开、内容保存、spare 借用/回收均不会继承另一张便签标题；控制台无 ACL denied。
- [ ] clipboard mode 中 `Ctrl+E` 只编辑 active 文本项并复用既有 LazyCopy 编辑 action；图片项、空列表和 IME 组字不误触发。
- [ ] `Ctrl+D` 可删除 active 文本或图片历史；空查询下 `Delete` 等价，非空查询下 `Delete` 只编辑搜索词；删除成功后仍停留在 clipboard mode，当前页/光标夹紧正确。
- [ ] 已有文本多选时快捷删除仍只删除 active 单项，缺失项从 selection reconcile；失败时不退出模式、不清空其余选择且有可见错误反馈。
- [ ] 快捷键 helper 单测覆盖门禁和目标分派；`cargo check --bin blink`、前端 JS tests 与 `git diff --check` 通过。

### 6.3 子 agent 交付格式

每个子版本单独委派时，交付必须包含：

1. 本子版本涉及的状态/配置/IPC 契约清单。
