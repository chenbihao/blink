# Blink 0.22 — 本地模型运行时与 PP-OCRv6（从专用维护到多引擎生命周期）

> **范围**：建立受限的本地模型运行时，统一进程、Provider、模型资产、状态与设置管理；以 ONNX PP-OCRv6 和常驻 GGUF FunASR 落地 OCR/STT；完成运行时设置、首启引导、截图与窗口能力、语音可靠性、常见 WAV 规范化及 `transcribe_audio`。
>
> **状态**：✅ 已完成（0.22.0～0.22.17 全部落地；当前版本 0.22.17）。
>
> **动机**：把散落在 FunASR/STT 中的安装、进程、模型、日志和清理职责收敛为可复用的本地引擎管理面，并删除 OCR 的 Python/uv/PaddlePaddle 重栈。
>
> **前置**：0.10 本地 STT、0.11/0.17 OCR、0.18 截图与输入、0.21 Capability 体系。
>
> **原则**：不影响 `Alt+Space → Focus → 输入` 主链路；分层、日志、错误、事件与前端约束以 `spec-architecture.md`、`spec-backend.md`、`spec-frontend.md` 为准；未知进程绝不按端口自动终止。

## 二、背景与动机

### 2.1 最终解决的问题

0.22 将本地模型的安装、资产、进程、健康、模型选择和诊断从单一 STT 功能中抽离，形成 OCR/STT 共用管理面；随后以实测结果保留有价值的执行路线，清除未采用的 Python 与 ASR ONNX 负担，并补齐设置、首启、截图、语音和文件转写体验。

### 2.2 明确“不是问题”的设计

- 模型按需下载，不进入安装包；安装包只携带锁、许可和必要 worker。
- WinRT OCR 永久保留为零安装 fallback；PP-OCRv6 是可选高质量后端。
- 管理命令不是 Capability；原子执行能力与运行时管理面保持分离。
- FunASR 可按用户策略常驻，OCR 默认按需加载并经 idle TTL 回收。
- 设置窗口关闭继续使用 hide；主热键继续走 hook，次级全局键使用 `RegisterHotKey`。
- 前端继续使用纯静态 HTML/CSS/JS，无 bundler、npm 或构建步骤。

## 三、核心设计与决策

### 3.1 分层与注册边界（已定）

`domain/local_engine` 定义框架无关协议，`infra/local_engine` 提供进程、部署、Provider 和 worker 原语，`app/local_engine` 持有唯一 `EngineManager` 并投影 IPC/事件。引擎、implementation、模型、可执行文件和下载源均来自编译期 allowlist，前端及 AI 不能注入路径、URL、argv 或环境变量。通用四域与 Capability 边界见 `spec-architecture.md`。

### 3.2 状态、部署与进程安全（已定）

环境、进程、服务、模型、desired state 和 operation 分开表达；`service_epoch + revision` 拒绝旧实例投影。安装在 staging/candidate 完成校验后原子切换 active pointer，失败保留旧部署。Windows 进程以 Job Object、instance token、PID 创建时间、可执行路径和 health identity 联合验证；未知进程只报错或换端口，绝不自动终止。

### 3.3 最终执行拓扑（已定）

最终保留：

- OCR：`oar-ocr + ONNX Runtime`，in-process lazy Session、单 Session 有界队列、idle TTL。
- STT：稳定 `funasr` engine id 下的 SenseVoice、Paraformer-zh、Fun-ASR-Nano 三个 GGUF 模型；一次只运行当前选择模型对应的锁定 worker。
- WinRT OCR：零安装 fallback。

ASR ParaformerOnline ONNX 的 first partial 和中文 CER 未达注册门，FSMN-VAD 未形成生产价值，二者均在 0.22.10 退役。恢复真流式前必须重新满足延迟、CER、生命周期和无 orphan 门槛；不得把“流式 VAD + 离线 ASR”描述为真流式。证据保留在 `xtask/spikes/onnx-spike/` 与 `xtask/spikes/fsmn-vad/`。

### 3.4 OCR 路由与执行（已定）

`auto` 在 PP-OCRv6 已安装时优先本地引擎，否则使用 WinRT；显式 PP-OCRv6 未安装时允许带提示降级，已安装但启动/识别失败必须返回结构化错误。ORT 与模型联合 staging、自检后提交；Session 在专用 blocking executor 上串行执行，queued 可取消，active native call 的迟到结果丢弃。PP-OCRv6 CPU spike 约 4 秒、峰值约 1136MiB，不得称为轻量默认后端。

### 3.5 FunASR、VAD 与文本提交（已定）

模型选择、已安装状态和实际 active 模型分别表达；运行中切模执行 stop → commit selection → start，失败保持可解释状态。EnergyVad 使用有界底噪、on/off 滞回和 attack debounce；伪流式句尾通过 pending → commit/rollback 事务提交，空结果、错误、超时和旧 generation 不得覆盖最后非空文本或跳过可重试音频。

短词是否形成 VAD 段受 `min_sentence_ms` 影响；VAD 是麦克风端点质量指标，不是文件 `transcribe_audio` 的成功条件。模型识别质量按模型与场景记录，不与 WAV 解码正确性混为一项。

### 3.6 WAV 规范化与 `transcribe_audio`（已定）

正式 decoder 支持 RIFF/WAVE 常见 PCM16/24/32、float32 及相应 `WAVE_FORMAT_EXTENSIBLE`，解析真实容器元数据并统一为 16kHz mono f32；压缩 WAV、MP3/AAC/FLAC、视频和 URL 不在本版。麦克风与文件复用 downmix 和有状态重采样原语，跨 chunk 保持连续相位。

`transcribe_audio` 只消费 app 层签发的短期 `audio_ref`，校验 regular file、引用代际、文件身份、大小、时长和解码预算；执行时冻结 STT 配置、engine/model/instance identity 与 generation，同一请求只调用一个 executor，不隐式下载模型。设置页、CLI、AI/MCP 复用同一 Capability。GGUF 仅标点输出统一收敛为空文本并返回 `no_speech=true`。

### 3.7 交互与桌面能力（已定）

次级 chord 动作用 `RegisterHotKey` 提升为独立全局键，OS 试注册与内部 binding 检查共同发现冲突；LL-hook 类软件占用无法被系统注册完整探测，UI 只承诺尽力而为。设置页关闭保持 hide，编辑器三态确认向后兼容既有两按钮调用，四步向导只编排既有配置与下载能力。

截图使用会话级 DWM cloak 事务排除 Blink 窗口，并以短期 `window_ref` 二次核验目标身份；成功、失败、取消和超时均恢复窗口状态与前台焦点。`manage_window` 只开放 activate/minimize/maximize/restore，窗口状态副作用继续走授权、确认和审计。

## 四、复用与范围边界

### 4.1 复用的既有基础

| 基础 | 0.22 中的用途 |
|---|---|
| `ConfigStore<T>` 与配置事件 | 引擎偏好、OCR 路由、STT 模型和向导状态 |
| Capability/Interaction 与 policy | OCR、截图、窗口管理、文件转写的统一执行与授权 |
| `ManagedProcess` / Provider / deployment | worker 生命周期、事务安装、active/rollback |
| `model_storage` | GGUF 与 ONNX 模型资产管理 |
| 截图 session/epoch 与窗口身份 | OCR、净化截图、迟到结果和 TOCTOU 防护 |
| 设置页模块、CSS token、共享对话框 | 运行时卡片、下载进度和交互收尾 |

### 4.2 不进 0.22

| 项 | 理由 |
|---|---|
| 第三方任意本地引擎注册、通用模型商店 | 缺少独立签名、授权和供应链设计 |
| 完整 GPU 调度、多 ASR 同时常驻 | 需要 RAM/VRAM 仲裁 |
| Linux/macOS 本地引擎 | 本版仅面向 Windows |
| AI/MCP 安装、启动或清理引擎 | 尚无外部管理授权模型 |
| PP-Structure、表格、公式、OCR-VL | 输出协议超出截图文字识别 |
| 压缩 WAV、MP3/AAC/FLAC、视频音轨 | 需要独立 codec、供应链和资源预算 |
| 窗口 close/move/resize/持久置顶 | 涉及数据丢失、混合 DPI 和遗留状态 |

## 五、子版本完成摘要

### 5.1 运行时基础（0.22.0～0.22.6）

完成 PP-OCRv6 资格验证、通用进程与 Provider、事务 deployment、领域协议、唯一 Manager、OCR 路由、设置页和恢复/可观测性硬化。

### 5.2 执行路线收敛（0.22.7～0.22.10）

GGUF worker 接管 FunASR，OCR 原位切换 ONNX；STT ONNX/FSMN-VAD 经实测未达门槛后退役，PythonVenv、uv、PaddleOCR Python server 与相关资源删除，仅保留升级用户可安全读取/清理的 legacy 数据形状。

### 5.3 交互与桌面体验（0.22.11～0.22.14）

完成设置页关闭、编辑器三态确认、次级 chord 全局键、首启向导、下载进度、OCR 划选与降级提示、混合 DPI 修正、AI 净化截图、`window_ref` 和受限窗口管理。

### 5.4 语音与文件转写（0.22.15～0.22.16）

完成 EnergyVad 自适应、伪流式文本事务和 G1 文本防回退；建立常见 WAV 唯一规范化链路、`audio_ref` 安全模型、`transcribe_audio`、设置页与 CLI 入口，以及合成/本地 corpus 分层验收。

### 5.5 交互与性能收尾（0.22.17）

- 截图 `blink_visibility` 未传参时按调用来源缺省：AI/MCP/CLI → `auto` 净化截图；本地手动入口 → `include` 不隐藏 Blink（修 0.22.14 手动触发时设置页等被一并隐藏的回归）。选区截图不再全量 cloak，只隐藏主窗 + 右键菜单，并以显式事务锁与 AI 净化截图互斥。
- 本地引擎部署制品漂移门禁：self-test 通过但磁盘部署 artifact 与当前构建期望不符时强制重装（兜底 0.22.16 源码回退后残留 runtime 推理慢 ~10 倍却无报错的事故）。
- 体验与性能：聊天 thinking 块流式增量渲染（保留滚动位置/展开态、贴底跟随）；pin 图滚轮缩放窗口提交合流 + `blink-pin` 协议 PNG 编码缓存；截图 raw 拉取加硬超时与重试、会话原子启动防半会话；剪贴板模式 ESC 直接隐藏窗口。

- [x] 私有 corpus 未进 Git/发布资源，实跑退出后无 orphan worker

### 6.2 0.22.16 分层 corpus 结论

- [x] 11/11 WAV 完成格式解析、16kHz mono 规范化和真实 worker 推理。
- [x] 3/3 静音或非语音样本收敛为空文本；模型原始仅标点输出已在生产后处理统一为空。
- [x] 8 个语音样本形成可复现质量基线：3 个严格文本命中，3 个语义可辨但有错漏字，2 个明显失败。该结果描述当前 SenseVoice Q8 能力，不作为 WAV decoder 或 Capability 接线失败。
- [x] VAD 段数单独记录：5 个样本与 manifest 不符；短词受最短句参数影响，长停顿允许的分段差异不阻塞文件转写。
- [x] 代表性指标已记录：短样本 decode 约 11ms、queue 约 2ms、inference 约 867ms、total 约 896ms、峰值约 265MiB；18.19s 样本 decode 约 111ms、queue 约 2ms、inference 约 8.70s、total 约 9.00s，worker 峰值约 321MiB。

测试文件名、场景标签、期望和转写文本可用于本地质量报告；原始录音及可恢复声纹仍必须保持 ignored、不得上传或进入发布资源。应用运行日志继续不记录用户音频与转写全文。

### 6.3 已知边界

- PP-OCRv6 CPU 性能和内存成本较高，且 in-process ORT 不具备 native crash isolation。
- SenseVoice Q8 在极短词、远场、背景噪声和长停顿场景存在可复现错漏；后续模型比较不得反向修改期望文本制造通过。
- EnergyVad 的最短句与阈值需按麦克风场景继续评估，不能用文件转写 corpus 的段数代替实时端点验收。
- `RegisterHotKey` 无法探测所有 LL-hook 占用；截图/窗口管理的混合桌面行为仍需在新增系统环境中持续回归。
