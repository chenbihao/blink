## 二、背景与根因边界

### 2.1 当前状态为什么会分叉

当前同一输入事实由四组状态共同表达：

| 状态 | 当前真源 | 问题 |
|---|---|---|
| Alt 是否按下 | `ALT_LOGICALLY_HELD` | 依赖 down/up 累积和 200ms 合成 keyup 猜测 |
| Chord 是否独占 | `CHORD_MODE` | 由前端异步 IPC 开关，可能晚到或泄露 |
| 可吞键集合 | `CHORD_KEYS` | Hook 热路径读取 `RwLock<HashSet<_>>` |
| Chord 是否显示 | 前端 `altLast/chord-visible` | 每 50ms IPC 轮询，shown/hidden 再补偿 |
| 主窗口是否可见 | Window `STATE` | `on_focused(true)` 能把已隐藏窗口重新标成 Visible |

现有链路形成闭环：Hook 更新 Alt → 前端轮询 → 前端推导 Chord → IPC 写回 Hook → Hook 触发动作 → 窗口 show/hide → 生命周期清理前端。冷启动、覆盖安装、WebView listener 尚未注册、IPC in-flight、Focus 事件晚到或系统注入键事件都会让某一份状态滞后。

### 2.2 已确认的高风险点

1. `ll_proc` 在 Alt keyup 回调内调用 `GetAsyncKeyState` 判断另一侧 Alt。Windows 明确规定低级 Hook 回调发生在异步键状态更新之前，因此该读数不能表示“当前事件应用后的状态”。
2. `EXPECT_SYNTH_KEYUP_AT` 假定 `SetForegroundWindow` 会在 200ms 内产生可识别的 injected Alt keyup；该事件是否产生、顺序和虚拟键形态均不应成为业务状态机契约。
3. Hook 安装时用 `GetAsyncKeyState` 初始化长期 Alt 状态，程序重启可能重新导入已经异常的 Windows session 状态，符合“程序重启无效、电脑重启恢复”的现象。
4. `on_focused(true)` 无条件写 Visible，启动阶段晚到的 Focused 事件可以制造“窗口实际隐藏、逻辑却可见”的 phantom visible。
5. 前端 `shown` listener、`chord.refresh()`、首个 Alt poll 和 `set_chord_mode` 是多条独立异步链，首次唤起存在天然竞态。
6. 覆盖安装后的异常还可能叠加旧 Blink 进程/旧 Hook 未退出或完整性级别变化；0.18.7 需要记录进程与 Hook 生命周期，但不得擅自杀进程或注入按键。

### 2.3 明确不是本次要重做的内容

| 不重做项 | 原因 |
|---|---|
| `ChordRegistry`、`ChordAction` 和动作实现 | 动作注册与执行边界没有问题，重构只替换输入状态层 |
| Chord 默认键位和用户 bindings | 保持用户行为兼容，不借架构重构改产品语义 |
| `requires_input` 的文本解析顺序 | contextual chord 仍需前端提供 active item/query/awareness 文本 |
| 语音 STT 管线 | 只改 Hold/HoldRelease 事件来源，不改录音、识别和注入实现 |
| 跨平台完整实现 | 保留 `infra/platform/hotkey/mod.rs + windows.rs` 边界，不为尚不存在的平台过度抽象 |
| 安装器自动终止旧进程 | 先通过日志确认是否存在残留；自动结束进程属于另一个有破坏性的任务 |

## 三、目标架构与不可违反的语义

### 3.1 单线程输入引擎与生命周期（已定）

Windows Hook 线程同时承载：

- `WH_KEYBOARD_LL`：全局即时观察、动作边沿、Chord keydown 拦截、注入事件 fallback。
- message-only window + Raw Input：本地键盘真实 make/break、左右修饰键 level 校正。
- Hold deadline timer。
- 配置、窗口状态、Recorder、Voice 和视图上下文控制消息。
- 纯 `InputStateMachine` reducer。

所有输入按同一线程顺序进入 reducer。LL Hook 必须同步得到 `Pass/Swallow`；业务副作用通过 channel 发给 `HotkeyService`，不能在 Hook 内执行。这里的“无锁”指 Hook 正常回调不得取得可能阻塞/竞争的 Mutex/RwLock；原子操作和非阻塞 channel send 允许。

`InputController` 生命周期固定为：

1. `start()` 创建控制队列和 ready channel，启动命名线程。
2. Hook 线程注册窗口类、创建 message-only HWND、注册 Raw Input、安装 Hook。
3. 全部成功后才通过 ready channel 返回 `Result<(InputController, EffectReceiver), InputStartError>`；失败必须带上下文返回，不能只在后台线程 panic。
4. 控制方把不可变控制消息放入队列，再 `PostMessage(WM_APP_*)` 唤醒 message loop；队列锁只由控制方和 WindowProc 使用，LL Hook callback 不访问该锁。
5. `stop()` 发退出控制消息并等待确认；Hook 线程依次 Unhook、注销 Raw Input、销毁窗口并退出。
6. 进程内只允许一个 Controller；重复启动返回结构化错误。跨进程残留只诊断，不在本 phase 自造杀进程或命名互斥修复。

Raw Input 注册使用 `RIDEV_INPUTSINK | RIDEV_DEVNOTIFY`，禁止 `RIDEV_NOLEGACY`，避免改变系统和其他应用的正常键盘输入。

### 3.2 输入源、乱序校正与多设备（已定）

```rust
enum InputSource {
    Local,
    Injected,
}
```

- Hook 是动作边沿与同步 `Pass/Swallow` 的唯一权威来源。Tap/Hold/Chord/VoiceCancel 只能由 Hook/timer 路径产生。
- Raw Input 只校正本地**修饰键** level；非修饰键仅可用于阶段 B trace 诊断，不进入动作 reducer，也不产生业务 effect。
- 非注入 Hook down 可立即建立 Local 候选，随后 Raw Input 确认/校正。同一 transition 的 Raw 确认不能再次产生 effect。
- adapter 为 Hook 与 Raw 事件附同一 Win32 时间域的 `time_ms`（Hook 用 `KBDLLHOOKSTRUCT.time`，Raw message 用 `GetMessageTime`）及归一化 key/transition。每个 modifier 保存最近已接受的 Local Hook 时间和 transition；比最近 Hook transition 更旧的 Raw 事件丢弃，防止延迟 Raw down 把已处理的 Hook up 写回 Down。`u32` 时间回绕比较抽成纯函数并单测。
- reducer 只在逻辑 edge 变化时发布 UI 状态：重复 down、同态 Raw 确认和 autorepeat 均不得重复触发动作。
- gesture 一旦由 Local 建立，中途的 injected Alt keyup 不得结束它；没有 Raw Input、由 injected down 建立的远程 gesture，则接受完整 injected down/up。
- 对 injected-owned gesture，若焦点切换产生无法区分的 injected Alt up，按真实到达事件结束 gesture；不得重新引入时间窗猜测。远程验收要求“不残留、不误触发”，不承诺跨焦点持续保持远程 Alt hold；需要时用户重新按下 Alt。
- 同一 gesture 不混用 Local 和 Injected 事件配对。
- Hook 安装时 modifier 为 Unknown，不用 `GetAsyncKeyState` 导入长期镜像；若 Alt 在 Hook 安装前已按下，非注入主键事件上的 `LLKHF_ALTDOWN` 建立 `InferredDown` 临时 level：既可满足本次主热键 gesture，也可在窗口显示后维持 Alt UI/Chord Session，直到真实 Alt up、Raw 校正或设备/session reset 结束。它不是跨真实 keyup 保留的长期镜像。注入主键的 ALTDOWN 只归 injected source。
- Raw modifier 按 `hDevice` 保存每设备 pressed set，聚合状态为所有设备 OR；收到 `GIDC_REMOVAL` 时清除对应设备，防止拔掉按住 Alt 的键盘后永久残留。
- Local modifier down 可由 Hook 先建立 provisional Down；local up 不得在 Raw 聚合仍显示 Down 时制造短暂假 Up，等待同时间域 Raw up/设备移除确认。若该 modifier 从未出现 Raw 设备状态，则 Hook up 作为 fallback 生效。过期 Raw down 仍由时间规则丢弃。

阶段 B 必须验证 Hook/Raw 的实际到达顺序、时间字段可比较性、generic/left/right Alt 形态和设备移除行为；任一假设不成立时停在 B 更新本节，不能由实现 agent 静默改策略。

### 3.3 单一 reducer、独立 ID 与公开状态协议（已定）

不同生命周期禁止共用一个 generation：

```rust
struct InputState {
    modifiers: ModifierState,
    gesture: GestureState,
    chord: ChordSession,
    window: MainWindowState,
    view: MainViewContext,
    voice: VoicePhase,
    recorder: RecorderMode,
    next_gesture_id: u64,
    next_chord_session_id: u64,
    next_ui_revision: u64,
    config_revision: u64,
}

struct MainWindowState {
    visible: bool,
    revision: u64,       // Window 模块拥有，每次成功 visibility transition 递增
}

struct MainViewContext {
    view_epoch: u64,     // 后端 register command 分配
    revision: u64,       // 当前 view_epoch 内前端递增
    ready: bool,
    query_empty: bool,
    ai_mode: bool,
}

#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase")]
struct InputUiState {
    revision: u64,       // 公开状态发生变化时递增，事件/快照只比较此字段
    alt_down: bool,
    window_visible: bool,
    exclusive_chord_active: bool,
}
```

- `gesture_id` 只标识一次主键 down→up；HoldDeadline、HoldStarted、HoldReleased 携带它。
- `chord_session_id` 独立标识一次“窗口可见期间 Alt down→退出 exclusive”的 Chord Session；窗口可能由托盘/单实例打开后再按 Alt，因此 Chord Session 禁止复用或依赖主热键 gesture id。
- `window.revision` 只处理 show/hide 乱序，不参与 HoldDeadline 判断。
- `ui_revision` 是前端事件/快照唯一比较字段；公开字段未变化时不递增、不重复 emit。
- `config_revision` 标识配置快照，不参与 UI revision 比较。
- 新 view 注册时后端分配新 `view_epoch`；旧 epoch 的 context update 一律丢弃。同一 epoch 内只接受更大的 context revision。

事件/effect 边界：

```rust
enum InputEvent {
    HookKey(HookKeyEvent),
    RawModifier(RawModifierEvent),
    RawDeviceRemoved { device_id: usize },
    HoldDeadline { gesture_id: u64 },
    WindowChanged { visible: bool, revision: u64, reason: WindowTransitionReason },
    WindowFocusObserved(bool),
    ViewContextChanged(MainViewContext),
    VoicePhaseChanged { gesture_id: Option<u64>, phase: VoicePhase },
    RecorderModeChanged(RecorderMode),
    ConfigChanged(InputConfigSnapshot),
}

enum InputEffect {
    Tap { gesture_id: u64, triggered_at: Instant },
    HoldStarted { gesture_id: u64 },
    HoldReleased { gesture_id: u64 },
    VoiceCancel { gesture_id: Option<u64> },
    ChordTriggered { chord_session_id: u64, key: String },
    UiStateChanged(InputUiState),
}
```

类型可按 Rust 所需调整，但上述 ID 所有权、序列化字段和比较语义不得改变。

### 3.4 配置快照与热更新（已定）

Hook 线程只持有 app 层派生好的不可变原始值，不读取 DB、不依赖 `ChordRegistry`/domain 类型：

```rust
struct InputConfigSnapshot {
    revision: u64,
    hotkey: NormalizedHotkey,
    tap_threshold: Duration,
    chord_enabled: bool,
    exclusive_tap_keys: HashSet<String>,
    voice_hold_enabled: bool,
}
```

- app 层从 `HotkeyConfig`、`ChordConfig.bindings`、disabled chord actions 和 `ChordRegistry` 派生 snapshot；`exclusive_tap_keys` 只含 enabled、tap semantic、空 query 可 native 触发的键。
- 前端不再向后端传 tap keys。
- 启动时在 HotkeyService wiring 完成后发送完整 snapshot。
- `tap_threshold`、`hotkey`、`chord_toggles`、`chord_bindings`、`disabled_chord_actions` 任一更新成功后，必须调用同一个 `refresh_input_config(app)` helper 重建并推送完整 snapshot；禁止各 command 局部 patch Hook 状态。
- 主热键在 Armed 时冻结该 gesture 的 `NormalizedHotkey + tap_threshold`，配置更新从下一次 gesture 生效。
- chord_enabled/keys/voice_hold_enabled 更新立即影响尚未触发的 Chord/Hold：禁用 Chord 立即结束 exclusive session；已产生的 effect 不回滚，新的 keydown 使用新 snapshot。
- `state.rs` 不得 `use crate::domain`、Tauri 或 Win32；跨层类型在 app 层投影成上述 primitive snapshot，借本次重构清除 hotkey infra 反向读取 domain config 的遗留。

### 3.5 窗口状态与物理键解耦（已定）

- `WindowHidden` 结束 Chord Session，但绝不伪造 `AltReleased`。
- `on_focused(true)` 只记录诊断，不写 Visible。
- 所有主窗口 visibility 写入统一收敛到一个 helper（命名可调整），输入为 `Visible/Hidden + WindowTransitionReason`；必须覆盖 Startup、Invoke、Toggle、Escape、Watchdog、Screenshot、SingleInstance 和 AI-active Refocus。
- Visible 只能在 `show()` 成功后建立；Hidden 只能在 `hide()`/cloak 成功或明确 Startup 初始化后建立。`set_focus` 失败不回滚“已经显示”，但要带 reason 记录诊断。
- `hide_for_screenshot` 禁止直接写第二套状态，必须走同一 transition helper。
- 每次成功 transition 递增 window revision 并通知 InputController；旧 revision 丢弃。
- Alt 按住期间唤起主窗口时，`show()` 成功后必须由窗口调用侧同步提交 `WindowChanged(Visible)`，等待输入线程确认该 revision 已应用并据当前 Alt/view/config 建立 native exclusive Chord Session；确认后才能 emit `SHOWN`、发布 `exclusive_chord_active=true` 或结束本次 invoke。等待发生在 effect/window 调用侧，严禁放入 LL Hook callback；该确认耗时计入 `<50ms` 唤起预算。
- 上述确认使用有界等待并返回明确结果。超时/Controller 已停止时，窗口可以保持已显示，但不得对外宣告 Chord active；记录包含 window revision、gesture/chord session id（若有）、等待耗时和失败原因的 anomaly，并触发一次状态快照重同步。不得用前端乐观状态伪装成功，也不得为补偿而伪造 Alt up/down。
- 因而对外不变量是：只要前端已经观察到本次 `exclusive_chord_active=true`/Chord 提示，Hook 就已经具备同步吞掉配置命中 chord keydown 的能力。主窗口物理可见到确认完成之间的极短窗口不定义为“已进入 Chord 模式”。
- AI active 时 Tap 维持现有“refocus + SHOWN、不 hide”语义，作为 `AiActiveRefocus` reason，不伪造新的 visibility transition。
- 看门狗只依据 Window 模块权威 visible state；Focus 是观察量，不是状态写入口。

### 3.6 Chord UI、独占与 contextual 路径（已定）

- 后端状态机拥有 Alt 和 native exclusive Chord Session。
- 前端只上报 `ready/query_empty/ai_mode` 离散视图上下文；不把 query 文本持续同步到输入状态机。
- native exclusive 条件为：window visible、Alt down、view ready、query empty、非 AI mode、chord enabled、存在 exclusive tap key。
- 空 query native exclusive 由 Hook 吞键并向后端触发。
- 非空 query 的 `requires_input` contextual chord 保留前端 keydown 路径，因为它需要 active item/query/awareness payload。
- AI mode 禁止 native exclusive，保留前端 Alt+Q “提升临时对话”路径。
- `InputUiState` 只发布物理/窗口/exclusive 真相；前端结合本地 chord config/action availability 投影 `chord-visible`，不得反向修改物理状态。
- 前端 contextual chord、Alt+1～9 和 Alt+Space preventDefault 使用 `inputState.isAltDown() || e.altKey`：后端快照抵抗 WebView synthetic keyup，事件自带 `altKey` 覆盖状态事件尚未到达的即时边沿。不得再只用 `e.altKey`。
- Chord key autorepeat 只触发一次，直到匹配 keyup 才能再次触发。
- 延续既有铁则：默认按键放行；exclusive chord 只吞配置命中的非修饰键 keydown，Alt 本身和 keyup 不吞。

### 3.7 Recorder 与 Voice 模式（已定）

快捷键录制不是旁路，必须纳入输入线程：

- `RecorderMode::Recording { recorder_id }` 由 `record_hotkey_blocking` 通过 InputController 开启，Hook 线程拥有录制期间 pressed modifiers 和完成 sender；Hook callback 不再调用带 Mutex 的全局 recorder 状态。
- Recording 时 Raw/Hook 仍更新 modifier truth并把归一化事件交给 recorder，但禁止 Tap/Hold/Chord/VoiceCancel effect。
- 录制完成、取消或 10s 超时后退出 Recording，清空 gesture/chord、递增 gesture id，使录制主键后续 keyup 不会触发正常快捷键；物理 modifier level 不清零，等待真实 up/Raw 校正。
- 保留录制期间 Alt+Space 特殊吞键语义，但只在 Recording mode 内生效。

Voice 业务不重写，但状态 wiring 必须收敛：

- `VoicePhase = Idle | Starting { gesture_id } | Recording { gesture_id }`；替代独立 `VOICE_RECORDING` atomic。
- Hold timer fire 后状态机用 gesture 自身的 Holding 状态吞 Space autorepeat，不依赖异步 VoiceService 已经启动。
- Voice worker 调用 generation-aware 的 hotkey wiring（具体命名可调整，例如 `start_recording_for_hotkey(gesture_id)` / `stop_recording_for_hotkey(gesture_id)` / `cancel_recording_for_hotkey(gesture_id)`），使 VoiceService 能把同一 gesture id 回报给 Controller；Chat 按钮入口继续走无 gesture id 的独立方法。
- `app/voice.rs` 所有 start 成功、早退、error、stop、cancel、Drop guard 路径都通过 InputController 回报 VoicePhase；Starting 早退必须回 Idle，成功才进 Recording，stop/cancel 无论成功失败最终回 Idle。允许修改该文件的 wiring 与方法签名，禁止改 STT/音频/识别业务。
- ESC 仅在 Starting/Recording 时产生 VoiceCancel。
- Chat 窗口按钮驱动的录音不需要吞 Alt+Space，但仍可报告独立的非 hotkey voice 状态；不得用它污染当前 hotkey gesture id。

### 3.8 Effect 分发、顺序与背压（已定）

- Hook→effect channel 必须非阻塞；接收循环不得查 DB，不得直接等待模型加载或 Chord action。
- Tap/window effect 在接收循环立即按既有策略执行，保持 `<50ms` 主链路。
- Voice effects进入独立串行 worker，按 gesture id 保持 Start→Release/Cancel 顺序；沿用当前“start 完成后再处理 release”的业务语义，但不得阻塞 Tap/window receiver。
- Chord effects进入独立串行 worker；worker 使用 app 层内存配置/Registry，不能每次回查 DB。慢 Chord action 不阻塞 Tap 和 Voice。
- `InputEffect` 是 reducer 已提交的决定，接收后不得因为用户随后松 Alt、窗口随后隐藏或配置随后变化而回查并丢弃已经接受的 Tap/Chord；否则快速 keyup 会让动作随机消失。channel 不做业务重试，worker 只处理 Voice gesture 的幂等与排序，配置变化只影响后续输入事件。
- Voice Start/Release/Cancel 因本身是同一长生命周期，可按 gesture id 处理过期/排序；这条例外不得扩展到已经提交的 Tap/Chord。
- channel 关闭、worker panic/退出必须写带上下文日志；不得静默丢 Tap/HoldRelease。

### 3.9 首次状态同步与 View 生命周期（已定）

前端初始化顺序：

1. 注册 `INPUT_STATE_CHANGED` listener。
2. 调用 `register_main_input_view({ queryEmpty, aiMode })`；后端分配非 0 `view_epoch`，用这两个初始字段建立 `ready=true/revision=0` 的 context，原子返回 `{ viewEpoch, state: InputUiState }`。
3. 用 `state.revision` 比较 listener 已收到的事件与注册返回快照，只接受更新的一份。
4. 后续 `update_main_input_context` 携带 `viewEpoch + revision + queryEmpty + aiMode`；字段未变化不发送。

`ready` 只表示当前 WebView 实例完成 input-state 初始化，不因普通 hide/show 重置；WebView reload/recreate 通过新的 register 获得新 epoch。Hidden 自身关闭 exclusive，保留最后 query context；lifecycle 清空 query 或切换 AI mode 后必须立即上报 context。这样无需 `PENDING_SHOWN` 特例，也不会依赖首个 `blink://shown` 是否早于 listener。

### 3.10 阶段 B 必须回答的验证问题

进入阶段 C 前，日志报告必须逐项给出结论：

1. 本机 Hook 与 Raw Input 对同一 modifier down/up 的实际顺序和时间字段是否可比较。
2. `SetForegroundWindow` 前后是否产生 injected Alt up，其 vk/scanCode/flags/time/extraInfo 形态。
3. 快速真实 keyup 先到、无 injected keyup、左右 Alt、AltGr、双键盘和设备移除是否符合 reducer 假设。
4. 覆盖安装期间是否同时存在多个 Blink PID、Hook install/uninstall 是否成对、进程 session/integrity 是否改变。
5. 至少一种远程/SendInput 场景是否能完整结束且不残留；若焦点 injected up 结束远程 hold，按 §3.2 的已定降级语义记录，不新增猜测。

任一项无法解释时，阶段 B 状态保持 🚧，由用户决定修订设计或另立安装/单实例问题；实现 agent 不自行进入 C。

## 四、复用与范围边界

### 4.1 复用现有基础设施

| 基础设施 | 复用方式 |
|---|---|
| `HotkeyService` channel 消费模型 | 改为消费 `InputEffect`，继续在 Tauri runtime 执行业务副作用 |
| `HotkeyConfig` / tap threshold | 构造不可变 `InputConfigSnapshot`，通过控制消息更新 Hook 线程 |
| `ChordRegistry` / bindings | 继续作为动作和有效键位真源，不复制动作业务逻辑 |
| `EventNames` 双端常量 | 新增 `INPUT_STATE_CHANGED`，禁止字面量散落 |
| Window `invoke/hide/watchdog` | 保留窗口行为，只收窄状态写入口并向输入控制器发事件 |
| 剪贴板 listener 的 message-only window 实践 | 参考 Win32 窗口类注册与消息循环写法，不复用其业务状态 |

### 4.2 不进 0.18.7

| 项 | 理由 |
|---|---|
| 新快捷键录制 UI | 与状态流转无关 |
| 修改 tap threshold 默认值 | 会改变产品手感，无法用于掩盖状态错误 |
| 自动焦点循环或按键注入 | 会制造更多不可观测状态和系统副作用 |
| 为 Raw Input 引入后台高频轮询 | Raw Input 本身是事件驱动，不应再造 polling |
| 全仓库注释清理 | 只清理本次触达的输入、窗口、前端键盘文件 |
| 立即修改全局 architecture spec | 先在 phase 验证；完成并稳定后再由用户确认是否提升为跨版本铁则 |

## 六、验收

### 6.1 纯逻辑自动化

- [ ] Alt down → Space tap → WindowShown → injected Alt up → real Alt up。
- [ ] 没有 injected keyup 时，真实 keyup 正常退出 Chord。
- [ ] 真实 keyup 早于 injected keyup 时不残留。
- [ ] 左右 Alt 同时按下并分别抬起。
- [ ] 通用 `VK_MENU` 与左右 Alt 归一化。
- [ ] AltGr 不误判成 Ctrl+Alt 快捷键。
- [ ] Hook 安装前 Alt 已按下，`LLKHF_ALTDOWN` 可建立本次 gesture。
- [ ] startup Unknown 不凭空触发快捷键。
- [ ] Space/chord autorepeat 不重复触发。
- [ ] stale HoldDeadline 不影响新 gesture。
- [ ] Hidden while Alt down 不伪造释放。
- [ ] Focused(true) 不改变 Hidden。
- [ ] query empty/non-empty 正确切换 exclusive session。
- [ ] Alt-held invoke 严格保持 `show success → Visible revision applied → exclusive session established → SHOWN/UI active`；ack 前不得发布 exclusive，旧 revision 的 ack 不得完成新 transition。
- [ ] Visible ack 超时/Controller stopped 时不伪造 Chord active、不修改物理 Alt，并请求状态快照重同步；后续有效 transition 可恢复。
- [ ] 本地 source 忽略 injected focus keyup。
- [ ] injected source 完整 down/up。
- [ ] 配置热更新不在 gesture 中途产生额外动作。
- [ ] gesture/window/UI/config 四类 revision 互不串用，旧 UI/window revision 被丢弃。
- [ ] Hook up 后延迟 Raw down 不把 modifier 回写为 Down；`u32` time wrap 比较正确。
- [ ] 两个 Raw keyboard device 的 modifier 聚合正确；移除按住 Alt 的设备后自愈。
- [ ] RightAlt standalone、Ctrl+Space、Ctrl+Alt+Key 配置匹配正确。
- [ ] Recorder 成功、取消、超时都不泄露正常 Tap/Hold/Chord，后续 keyup 不误触发。
- [ ] Voice effect 按 gesture id 串行，慢 start 不阻塞 Tap/window receiver。
- [ ] `InputUiState` event/snapshot 乱序与旧 view epoch 由前端纯测试覆盖。

### 6.2 Windows/前端手工验收

- [ ] 覆盖安装后立即连续触发 Alt+Space 30～50 次。
- [ ] 覆盖安装后连续使用至少 10 分钟，前后行为一致。
- [ ] 退出程序再启动且不重启电脑，行为一致。
- [ ] 电脑重启后作为对照，行为一致。

- [ ] Alt+Space 连续 toggle，无 phantom visible。
- [ ] Alt+A/C/Q/E/S 正常；非空 query contextual chord 正常。

- [ ] AltGr、左右 Alt、双 Alt、Space autorepeat 正常。

- [ ] 自定义 RightAlt standalone、Ctrl+Space 至少各完成 tap/hold 冒烟。

- `src/infra/platform/window/windows.rs` — 收窄 visible 写入口、移除 Focus 反写、发送 generation 事件。
- `src/infra/platform/window/mod.rs` — 暴露收敛后的窗口接口。
- `src/domain/event_names.rs` / `frontend/js/shared/event-names.js` — `INPUT_STATE_CHANGED` 双端常量。
- `frontend/js/main-window/keyboard.js` — 删除 Alt polling/Chord Mode 控制；Alt+1～9/contextual chord 改用后端 Alt 快照辅助，保留 payload 解析。
