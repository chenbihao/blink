## 二、背景与边界

0.23 把 Blink 从“把识别结果一次性写到输入框”推进为可持续工作的文本处理链：来源文本可精确编辑，语音可连续追加，AI 修改必须先展示候选并由用户确认。实现以单会话、明确版本号和单写入点约束异步任务，避免旧结果覆盖新内容。

本阶段不解决：

- 富文本格式的无损往返；Markdown 仅支持安全子集预览。
- 多文档、多窗口并行编辑。
- 无确认的 AI 自动改写。
- 远程桌面下依赖系统排除捕获能力的“无条件可见”长截图。

## 三、核心决策与最终约束

### 3.1 单个预热编辑器与 EditorSession

- 全局复用一个预热编辑器窗口，激活相同来源；来源不同且已有活动会话时返回 EditorBusy。
- 会话身份由 session_ref + generation + content_revision 共同限定。所有异步回传在落地前复核身份与版本。
- 用户编辑、语音提交、AI 确认都走统一事务入口，统一更新 revision 与撤销栈。
- 窗口隐藏不等于会话结束；复用 WebView 必须在进入前同步复位，在退出时立即失活并取消旧任务。

### 3.2 Source、Markdown 与写回

- Source 是唯一文本真源；Markdown 只是安全渲染视图，不反向承载隐式格式状态。
- SourceDescriptor 描述来源，CommitTarget 描述写回目标；读取能力不自动获得写权限。
- 文件保存通过 UTF-8 原子写能力完成，并受 mutation gate 约束。
- 自动 Markdown 预览上限 32 KB；可编辑 Markdown 上限 128 KB；Source 上限 200 万字符；Diff 上限 200 KB；AI 输入上限 24k tokens。

### 3.3 连续听写与 AI 整理

| 场景 | 语音结果 |
|---|---|
| G2 输入框 | Preview 仅展示；Draft 定稿即注入前台应用，会话终态只补交剩余（0.23.13 渐进上屏） |
| Editor | Preview 作为临时装饰；Draft 持续提交到正文 |
| G1 / G3 | 保持 Legacy 流程 |

- 任一时刻只有一个活动语音会话和一个活动 AI 请求。
- AI 启动时冻结 revision、选区与内容 hash，只生成候选；确认时再次校验，成功后作为单个事务写入。
- AI 候选与 Diff 不修改 Source；用户继续编辑后，过期候选不能提交。

### 3.4 Preview/Draft 双层识别

- 单 worker 串行调度识别任务，保留“一个运行中的任务、一个待执行 Draft、最新 Preview”。
- AudioRange 使用半开区间和绝对采样位置；owned_range 与 model_input_range 分离，禁止靠文本相似度拼接。
- Preview 允许被更新或丢弃，**不是可靠正文**；可靠提交只来自 Draft/Final。Draft 只能按不重叠音频范围提交。
- committed_watermark 与 reserved_watermark 分别表示已提交和已占用边界；积压硬上限为最大窗口的 2 倍。
- RequestAudioGate 在任务执行前再次验证范围与代次；G2 最终识别失败时不注入未定稿残余，已定稿内容仍补交不丢。

| 参数 | 默认值 | 可配置范围 |
|---|---:|---:|
| Preview 窗口 | 3000 ms | 2000～4000 ms |
| Preview 刷新 | 700 ms | 500～1000 ms |
| Draft 最短片段 | 5 s | 3～10 s |
| 强停顿 | 700 ms | 500～1500 ms |

VAD 采用 800 ms / 300 ms 双阈值、8 / 12 / 12 秒窗口、轻量语音计数、渐进停顿和 1.2 秒谷底切分；底噪上升护栏为稳定性判定（修复高底噪麦克风下的自举死锁），时间触发短语冻结兜底停顿检测失灵；silence_threshold 已退役为兼容字段（默认 0.001，UI 无滑杆）。FSMN 不进入本阶段生产链路。

### 3.5 短语级收口

- 0.23.10 引入 Phrase Anchor、Phrase Ledger 与 ShortPhraseEnd，Preview 可按短语稳定展示。
- 尾段只有真正提交成功后才清除；失败时保留可恢复状态。
- worker 预热、请求限速、单调任务 ID 与单调音频范围共同阻止旧识别覆盖新短语。

### 3.6 主链路稳定性收口（0.23.11）

- 热键状态每 2 秒自愈；异常须连续两次确认。程序注入不推进物理按键时间游标，重装 hook 前重建物理快照。
- 截图原始 IPC 透传选项，RGBA 数据先校验、失败再回退；图钉失败对用户可见，并支持按窗口 label 定向刷新。
- OCR 支持静默选区、空白拖动恢复选区移动、空白双击复制；截图和图钉共用文字选区算法。
- 图钉增加 OCR/翻译文字层；原文使用 font_h，译文使用稳定墨迹坐标，并加入面板避让。OCR/翻译叠层颜色保真：原文字色按词单元对齐（camelCase/snake_case 不拆），译文模式对代码特征行启用分段着色。
- 截图复用窗口显式 session 生命周期：同步复位完成后才揭示新截图；退出先递增 OCR/翻译 revision，再取消任务与清理。

关键教训（后续维护必读）：preventDefault() 不会阻止同一页面上的其他键盘监听器，正常模块接管后必须注销应急 ESC。Tauri 隐藏窗口不会销毁 WebView，所有截图临时层都必须按“复用会话”而不是按“页面卸载”清理。

## 八、0.23.12：统一资源 ref 层（✅ 已完成）

**背景一句话**：此前 ImageStash（内存字节/TTL/非消费读取）与 AudioResourceRegistry（磁盘路径/一次性 resolve，且“先 remove 再校验”会烧掉错误 scope 的一次性 ref）两套资源引用平行运作。0.23.12 合并为统一、短期、最小授权的资源句柄协议 `ResourceStore`：内存字节/本地文件/未来远程对象 → 身份、授权、生命周期、配额 → opaque ResourceRef → OCR/pin/STT/文本读取等 Capability 消费。ResourceStore 是 Capability 之间的**数据平面**，不是新的执行平面，不改变 0.21 Capability 唯一原子执行语义。原 0.23.12/13/14 三段规划实际一次交付，源码注释锚点统一为 0.23.12。

### 8.1 核心决策（已定案）

1. **backing 双模**：`Memory(Bytes)` 与 `LocalFile(FrozenLocalFile)`；`RemoteObjectKey` 只留类型边界不实现（远程牵动 SSRF/下载炸弹/凭据，本阶段不背）。配额与 TTL 按 backing 分口径独立计数（内存 16 项/64 MiB/TTL 15 分钟；本地文件 32 项/256 MB/TTL 5 分钟），读取不续期。
2. **ResourceUse 封闭枚举**：use 集由签发方决定，AI 只能消费不能自选；变体只收有真实消费方的。ReusePolicy（Reusable/OneShot/MaxReads(n)）是 grant 属性，不由媒体类型隐含。每新增消费型 Capability 需扩枚举并评审签发方白名单——**这是有意的收敛摩擦，不是债，不得当债优化掉**。
3. **`issue_from_ref` 只许衰减（attenuation-only）**：派生 grant 的 use 必须是源 grant 子集、读取授权 ≤ 源剩余、有效期取 min，越界返回 `permission_escalation`；“同时保留分析与回放”由签发方一次授予，不靠通用 clone 增权。
4. **token 换 CSPRNG**（≥128 位，`rref_` + 32 hex）：ref 会被 AI/MCP 持有，本质是 bearer capability，弱随机不可接受。
5. **resolve 顺序：校验全过才消费**：查找 → 各项校验 → 同一临界区内提交使用次数；错误 use 不消耗 one-shot，并发 one-shot 单赢家。
6. **撤销语义收敛**：`revoke_group` 取代裸 generation（后者是 dead 机制），`revoke_by_owner` 为会话级补充；真实调用方为设置页音频 picker（一次选择 = 一个调试会话）、media.rs RAII revoke、chat 附件按会话 owner 回收。
7. **Blob 投影统一入 store**：消除 `image/*` 特殊分支；MCP `call_tool` 返回与审计**单次投影**共用（此前 bearer token 进审计记录），审计只记脱敏元数据；非图片 Blob 返回稳定 reason，不签发假可用 ref。
8. **CapabilityResult 不加 Resource 变体**：无生产者需要显式签发变体，等真实场景出现再加。
9. **读取接口只落地 `read_all_bounded(max_bytes)`**：`read_range`/`open_stream` 留签名不实现；`read_text_file` 不动（本地绝对路径与短期授权句柄解决不同问题）；`bind_local_resource`（权限放大器）推迟到有真实需求再立项。
10. **CLI/MCP 降级口径**：无 ResourceStore 的运行时在 invoke 边界返回结构化 Unsupported，不静默吞；`blink transcribe` 是真实消费方，与 TauriDomainEnv 构造同一 store 走全链路。
11. **引擎生命周期不在 Capability 内管理**：`transcribe_audio` 维持「不启动、不安装、不切换」；ensure 责任在可信入口（CLI 显式 start；chat 附件与设置页 picker 共用后台预热）。不新增引擎生命周期 capability——暴露给 AI 牵动 danger 分级与确认策略，本阶段不背。

### 9.3 case_17 专项定案（后续维护关键知识）

**根因**：伪文本候选经 `natural_pause` 放行后，还会累计静默到 `long_pause` 再被放行、终态尾段 drain 还会把它送进模型——三个出口必须同时收口；能量占比判据（强帧占比）无区分度（伪文本 32.1% 与合法噪声 21.9%、真句最弱档 38.5% 区间重叠），已废弃。

**有效判据是形态证据——连续强有声段**：强有声 = 10ms 帧 RMS ≥ VAD 自适应 `on` 阈值。真语音是连续发声段，环境声形态上是稀疏脉冲。门槛 `CREDIBLE_VOICED_RUN_MIN_MS = 100`，落在三处：`natural_pause` 分支、`long_pause` 分支、终态尾段送模范围门。VAD 行为未改动，拒绝发生在采纳层与送模层。

两条实现约束（有实测依据，**不得简化**）：

- **不在 finalize 用“当下阈值”重新测量范围**——VAD `on` 随底噪自适应，尾段静音会让底噪漂移，同一段音频不同时刻结论矛盾（case_04 实测：流式累计 290ms、finalize 重测仅 90ms，重测导致正文全丢）。一律复用流式累计的 `uncommitted_strong_run_max`。
- **送模范围门只作用于 PreviewDraft**——Legacy（G1/G3）没有候选观察路径，累计值恒为 0，一并套用会拒掉全部终态文本。

**修复后结果**：全量 corpus 17 例回归通过，仅 5 例文本变化且减少的全部是静音/环境声尾段幻觉（case_17 采纳边界 4→3 = manifest 期望、Final 30→28 字）；总推理耗时 −8.7%；整条 vs 伪流式对照 case_17 达 100%。

## 十、0.23.15：截图实线选区拖动流畅度与残影消除（✅ 已完成）

> **范围**：只动截图 overlay 的实线选区路径（新建拖选、选区移动、八向缩放）及其共用的实时预览调度、主画布输入与生命周期清理。截图输出/crop/pin/OCR/翻译数据路径、智能预选虚线框动画均不改。

**根因一句话**：`interaction-canvas` 是与虚拟桌面物理像素同尺寸的透明层，实线拖选每帧 `clearRect` 全层 + 4 次全屏 `fillRect` + `strokeRect`，开销随截图总像素面积线性增长，4K / 多屏 / 高刷新率下突破帧预算（双 4K 占 60Hz 预算的 160–173%），表现为实线右下角落后鼠标与旧帧残影。

### 10.1 核心决策（定案）

1. **实线拖选的实时预览改用专用 DOM 层（四遮罩 + 唯一边框），拖动期间 `interaction-canvas` 零绘制**。理由：DOM 层每帧成本是 5 个盒子的 style 写入 + 合成，与截图总像素面积无关；canvas 方案成本与整屏像素成正比。用 DOM 承接“逐帧变化的几何”，canvas 承接“一次提交的成品”，职责按变化频率切分。
2. **实时层几何直接消费 CSS 像素**（`norm(...)` 或 `ss.selCss`），不做位图换算；四条遮罩锚定式只写“变化的那一个维度”，每帧无强制同步布局。
3. **边框线宽沿用 `border-width = 2 × uiScaleAtCss(x, y, meta)` 的跨屏视觉补偿语义**；不引入 `devicePixelRatio` 作为坐标换算真源（权威比例是 canvas 实测 `renderScale`，spec-frontend §5.6）。
4. **单一实时预览调度器**：唯一入口 `updateLiveSelection(rect)`，事件侧只写最新矩形、单飞 rAF 只消费最新矩形。删除 `scheduleDrawSelection`/`scheduleDrawFinalSelection` 两个名字——它们本来就是同一队列的两个入口，名称分离会诱导后来者再按“两套预览”加逻辑。
5. **激活即“清空一次 + 同步落地首帧”**：清空 canvas 与 DOM 覆盖必须同帧完成（否则闪白）；首次更新才清空，单击不动必须保持原选区可见。
6. **提交原子性由 `drawFinalSelection()`/`drawDimmed()` 内部保证**：画 canvas 前先隐藏实时层，“提交 + 隐藏”落在同一 task 同一帧，覆盖所有退出路径。
7. **主画布拖选迁移 Pointer Events 并真正启用 pointer capture**（原代码在 `mousedown` 分支写 `setPointerCapture`，`MouseEvent` 没有 `pointerId`，capture 形同虚设）；`getCoalescedEvents` 只取最后一个采样点；必须删除 mouse 拖选监听避免双处理。
8. **拖动期间不画八个手柄**（实时层只含 5 个元素，手柄松手后一次性画回）——有意取舍：实时层只负责“选区在哪里”，不负责“选区可操作”；若需要再增量立项，不回退 canvas 逐帧重绘。
9. **几何计算纯函数化**：`computeDragRect`（ss-utils）与 `computeInteractionRect`（ss-interaction）由 pointermove 与 release 路径共用，保证松手时用 release 最新坐标同步计算最终矩形，三条路径不漂移。

实施期发现与教训（保留）：

- `applySquareResize` 在 `ss-interaction.js` 被调用但从未导入——**Shift + 八向缩放路径实际不可用（ReferenceError）且长期潜伏**。教训：Shift 约束是两条独立实现，只有一条有覆盖测试时，另一条的错误会潜伏；收敛到同一可测函数是根治手段。
- 初版 CSS 给右遮罩同时声明 `right: 0` 与 `width: 0`，绝对定位下 `right` 被忽略——**右遮罩永不显示，且单测测不出**（单测只能断言 JS 写了什么值，写不进浏览器算出来的布局）。教训：补了 `testdata/screenshot/live-selection-layout-check.html`，注入产品 HTML/CSS 用 `getBoundingClientRect`/`getComputedStyle` 断言布局，正是它抓出该缺陷。

### 10.2 明确“不是问题”的（防误改）

> **前置**：0.23.14（PreviewSpan 范围契约、settle 语义、corpus 17 例基线）。
>
> **原则**：不改 VAD 切段判据本身（natural/long/strong pause 阈值语义）；反回退一律按 span 音频范围裁决、禁止字符串裁剪（0.23.14 决策延续）；单 worker 串行是硬约束，不引入第二模型实例；默认行为零变化（新配置默认关闭/等于现状）。

### 11.2 回退根因清单（调研定案，后续维护关键知识）

按对用户体感的影响排序，全部在代码中坐实：

1. **尾部整串替换允许变短**：`set_preview_if_changed`（pseudo_streaming/mod.rs）对同一段音频重复识别，模型返回更短/不同文本时直接替换（引擎自统计 `preview_retreat_chars` 只记数不阻断）。同锚、范围只增不减时的"变短替换"可以安全拦截——这是 0.23.16.3 的靶子。0.23.14 已明确不做字符串裁剪式视觉单调（决策保留），本版拦截条件是**范围裁决**（新范围 ⊆ 旧范围且文本更短），与该决策不冲突。
2. **Draft 在途停摆**：Draft finalize 期间（单 worker 串行，数百 ms～秒级）时间冻结兜底与尾部刷新被 `pending.is_none() && !finalize_in_flight` 跳过；若 Draft 耗时较长（deferred 链/慢机），尾部窗口前滚使前缀只能靠事后时间冻结恢复，且冻结本身也被停摆阻塞——恢复延迟叠加。0.23.16.4 解除互斥（登记/入队继续，推理按 worker gate 自然排队，gate 后 stale 复核保证排队任务不浪费模型时间）。
3. **短语入账/settle 清退的瞬时空洞**：短语冻结或 Draft 提交时，与范围重叠的尾部整条清退（`settle_tail_for_phrase` / `settle_preview_after_commit`），未被覆盖的后缀文本短暂消失，待下一次尾部重识别后回场——组合投影上的可见回退。诊断泳道（.1/.2）负责把它显式化；单 worker 下完全消除需要后缀立即重识别（推理量翻倍），不在本版硬做。
4. **G2 显示层 confirmed 窗口收缩**：注入 ack 到达后浮窗 confirmed 层清空（文字已进目标应用）——设计语义（0.23.14.4 双水位），不是缺陷，但与 1/3 叠加时加重"怪怪的"观感。

### 11.3 核心决策（定案）

**D1 单 worker 保持，"P/D 并发"在调度层实现（已定）**
定案：不引入并发推理。证据：引擎 `worker_gate` + `NdjsonWorkerClient` events 锁两层串行（客户端锁覆盖"写请求→读到匹配响应"全程）；worker 是原生 exe 单推理上下文（引擎注释记录：并发 hello 与推理线程竞争可触发访问违例）；第二 worker 实例 = 第二份模型内存，击穿常驻 <300MB 硬目标。落地方式：Draft 在途时 P 的时间冻结登记、刷新入队继续推进（0.23.16.4），推理请求在 worker gate 排队、gate 后 stale 复核淘汰过期任务——体感即"P/D 并行"。

**D2 反回退以 span 范围裁决（已定）**
定案：`set_preview_if_changed` 拒绝"新范围 ⊆ 旧尾部范围且新文本字符数更少"的替换，保留旧文本并计数 `preview_blocked_retreat_chars`（诊断）；范围扩展（end 增长）时正常替换。settle/锚点回退/清退路径不受影响（它们的范围语义是"音频已易主"，不是同锚改写）。禁止字符串裁剪（0.23.14 决策延续）。

**D3 Draft 目标窗口 = 双滑杆（中心 + 宽容半径），默认关闭（已定）**
定案：`draft_target_s`（目标中心，默认 0=关闭）+ `draft_target_tolerance_s`（单侧宽容，默认 3）。窗口 = [target−tol, target+tol]。开启后 `candidate_readiness` 增加目标窗口门：
- 下界 `floor = max(draft_min_s, target−tol)`：owned 低于 floor 时，natural/strong/draft_min 分支全部等待（wait_reason=`below_draft_target`），用户复语则候选作废继续积累——对应"不到优选区间就等下一个候选"；
- 逃逸阀：长静音（long_pause_ms）与强制切（hard_window/uncommitted_cap）不受目标门影响——用户明显说完或音频超限必须立即定稿，不能为凑窗口悬停；
- 上界 ceiling 之上无需新逻辑：等不到合格停顿的连续语音由既有 hard window 强制切兜底（切点回退谷底）。sanitize 保证 `target + tol ≤ max_uncommitted_s`（否则收敛 target 并 warn），想用 20/30s 目标需同步调大 VAD 窗口滑杆（设置页已有）；
- 默认关闭 = 现状"首个合格候选即切"，0.23.13"G2 定稿即注入"的默认产品行为不变。开启后默认 10s/2s（优选 [8s, 12s]）——宽容定 2 而非 3：stock `max_uncommitted_s = 12` 时 10+2 恰好可达上界，sanitize 不再收敛目标值；用户要 [7s, 13s] 只需把宽容调到 3 并同步调大 VAD 未提交上限滑杆。

**D4 P 固定冻结节奏可配置（已定）**
定案：`phrase_freeze_interval_ms`（默认 0=沿用现状"绑定预览窗滚动"的 1.2s 兜底）。设 800–3000ms 时，时间冻结的前缀门槛改用该值且**不再要求前缀滚出预览窗**（固定节奏主动追认），切点仍走合格谷枚举 + 谷内稳健位置。识别量会随节奏加快上升（单 worker 下挤占尾部刷新），默认关闭。

**D5 retention 不配置化（收窄原 Handoff C，已定）**
定案：G2 retention=0（定稿即注入）/ Editor retention=1 是 0.23.13 的产品语义，不是实现参数；无真实需求前不加配置面，防止用户改出"定稿不上屏"的非预期状态。原 Handoff C 中该项裁剪。

**D6 组合投影真源在引擎侧（已定）**
定案：调试页组合泳道的数据来自引擎 `rebuild_preview_text` 边沿记录（composite observer：组合文本实际变化时记录 spans 清单 + 归因 + 变化类型），不是前端把行式记录二次拼接——后者无法复现 latest-slot 合并、settle 清退与反回退拦截。生产引擎不挂 observer，零分配成本。

**D7 G2 浮窗双层投影（已定）**
定案：`SttEvent::Preview` 已携带 spans 清单，voice.rs 目前拍平成单字符串。本版把"除末段外的冻结短语"与"活动尾部"两级灰度透传浮窗（`previewFrozen` + `previewTail` 两字段），直接呈现"稳定递增"的视觉语义。Legacy（G1/G3）不受影响。

**D8 settle 清退按范围精化（实施期定案）**
定案：`settle_preview_after_commit` 的尾部清退从"committed 推进即清空"精化为"尾部范围覆盖已提交音频（start < committed）才清空"——Draft 在途期间刷新产生的实时后缀（start ≥ committed）在定稿瞬间不再消失又回场。与跨界整条删除、剩余交回尾部重识别的既有语义一致（范围裁决，不做字符串裁剪）。

### 11.8 遗留观察

- 反回退门拦截计数（`preview_blocked_retreat_chars`）已进 `SttStreamStats`，corpus 汇总行暂未打印该列——需要量化拦截频率时在 corpus_runner 汇总里补一行即可。
- settle 清退精化（D8）消除了"后缀消失又回场"，但短语冻结瞬间其后缀仍走"清退→重识别"路径（单 worker 语义，见 §11.2-3）；固定节奏（默认关闭）会放大该路径的频率，开启后若体感闪烁明显，后续可评估"短语入账时同步保留未覆盖后缀的尾部快照"。
- 组合泳道当前只在 WAV 回放（设置页）可见；生产 G2 会话的实时组合时间线（需要的话）可在后续版本把 composite observer 挂到生产引擎并按需开关。
- `draft_target_s` 对识别准确率的实际收益未验证——需要用 §11.6 的 corpus 回放 + 目标窗口开启做 A/B 扫参（0.23.14 遗留的 `long_pause_ms` 联合扫参可一并做），结论供产品决策是否切默认。
