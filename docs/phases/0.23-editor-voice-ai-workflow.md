# Blink 0.23 — 通用文本编辑工作台（Source/MD、连续听写与可确认 AI）

> **范围**：编辑器、连续听写、AI 整理、统一资源 ref 层、VAD 双层识别、截图实线选区与图钉文字层的主链路收口；0.23.17～0.23.19 为实机使用反馈打磨批次。
>
> **状态**：✅ 已完成（0.23.0～0.23.19 全部落地；遗留观察见 §六）。
>
> **动机**：把 Blink 从"识别结果一次性写进输入框"推进为可持续工作的文本处理链——来源文本可精确编辑、语音可连续追加、AI 修改必须先展示候选再由用户确认。
>
> **前置**：0.10 语音输入（G1/G2/G3 与伪流式 VAD）、0.21 Capability 唯一原子执行（资源 ref 层与语音链路都建立在它的执行语义之上）。
>
> **原则**：UTF-8 文本是真源；单个预热编辑器与单活 Voice/AI；AI 只生成候选，确认后提交；不得损伤 Alt+Space 主链路；前端无 bundler。

## 二、背景与边界

### 2.1 为什么做 0.23

Blink 已有的搜索/唤起能力无法承载"拿到文本之后要继续加工"的真实场景。0.23 补齐三件事：来源文本可精确编辑并安全写回、语音可连续追加到正文、AI 修改必须先展示候选再由用户确认；实现上以单会话 + 明确版本号 + 单写入点约束异步任务，避免旧结果覆盖新内容。随后两个版本节点（0.23.12 资源 ref 层、0.23.14/16 语音端点与双层识别）都是在实机暴露的真实缺陷上补的范围。

### 2.2 不解决的

- 富文本格式的无损往返；Markdown 仅支持安全子集预览。
- 多文档、多窗口并行编辑。
- 无确认的 AI 自动改写。
- 远程桌面下依赖系统排除捕获能力的"无条件可见"长截图。

### 2.3 明确"不是问题"的（防误改）

| 项 | 说明 |
|---|---|
| Preview 文本允许短暂回退/回缩 | 设计语义：Preview 不是可靠正文，回退一律按音频范围裁决（D2/D8），**不得**用字符串裁剪制造视觉单调 |
| confirmed 窗口在注入 ack 后清空 | 0.23.14.4 双水位语义（文字已进目标应用），不是缺陷 |
| `_drawSelectionRaf` 单飞、智能预选虚线框 130ms 过渡、`drawFinalSelection` 一次画全遮罩+边框+8 手柄 | 均为刻意设计，0.23.15 只收敛实时预览队列，不碰它们 |
| `ss.selCss` 存 CSS 像素、`bitmap = CSS × renderScale` | 契约不变（权威比例是 canvas 实测 `renderScale`，不是 `devicePixelRatio`） |
| 资源 store 是"数据平面" | 不改变 0.21 Capability 唯一原子执行语义；开新消费方要扩 `ResourceUse` 枚举是**有意收敛摩擦，不是债** |
| Preview 环境声尾段短暂幻觉、连续强有声段判据不是语音检测器 | 已登记为遗留（§六），贸然加门会延迟正常渐进上屏 |
| swatch 颜色只写 `--swatch-overlay`（上层 linear-gradient），不写 `background-color` | 0.23.19 层叠语义：background-color 垫在 background-image 之下，会被不透明棋盘格完全盖住（"只有棋盘格没有颜色"） |

## 三、核心决策与最终约束

### 3.1 单个预热编辑器与 EditorSession

- 全局复用一个预热编辑器窗口，激活相同来源；来源不同且已有活动会话时返回 `EditorBusy`。
- 会话身份 = `session_ref` + `generation` + `content_revision` 共同限定，所有异步回传落地前复核身份与版本。
- 用户编辑、语音提交、AI 确认走统一事务入口，统一更新 revision 与撤销栈；窗口隐藏不等于会话结束（复用 WebView 必须进入前同步复位、退出时立即失活并取消旧任务）。

### 3.2 Source、Markdown 与写回

- Source 是唯一文本真源；Markdown 只是安全渲染视图，不反向承载隐式格式状态。
- `SourceDescriptor` 描述来源、`CommitTarget` 描述写回目标；读取能力不自动获得写权限。
- 文件保存走 UTF-8 原子写能力并受 mutation gate 约束。
- 上限：自动 Markdown 预览 32 KB；可编辑 Markdown 128 KB；Source 200 万字符；Diff 200 KB；AI 输入 24k tokens。

### 3.3 连续听写与 AI 整理

| 场景 | 语音结果 |
|---|---|
| G2 输入框 | Preview 仅展示；Draft 定稿即注入前台应用，会话终态只补交剩余（0.23.13 渐进上屏；保留窗口 0.23.16.7 起可配置） |
| Editor | Preview 作为临时装饰；Draft 按保留窗口（默认 1 句）持续提交到正文 |
| G1 / G3 | 保持 Legacy 流程 |

- 任一时刻只有一个活动语音会话和一个活动 AI 请求（G1/G2/G3/Editor 共同排他）。
- AI 启动时冻结 revision、选区与内容 hash，只生成候选；确认时再次校验，成功后作为单个事务写入；用户继续编辑后过期候选不能提交。
- AI 候选与 Diff 不修改 Source。

### 3.4 Preview/Draft 双层识别

- 单 worker 串行调度：一个运行中任务 + 一个待执行 Draft + 最新 Preview（更早的 Preview 值可被替换或丢弃）。
- `AudioRange` 是半开区间 + 绝对采样坐标；`owned_range` 与 `model_input_range` 分离；**禁止靠文本相似度拼接**。
- Preview **不是可靠正文**，可靠提交只来自 Draft/Final；Draft 只能按不重叠音频范围提交；`committed_watermark` / `reserved_watermark` 分离，积压硬上限 = 最大窗口 × 2（超限即 `stt_overloaded` 终止会话）。
- `RequestAudioGate` 在任务执行前再次验证范围与代次；G2 最终识别失败时不注入未定稿残余，已定稿内容仍补交不丢。
- 短语级收口（0.23.10）：Phrase Anchor + Phrase Ledger + `ShortPhraseEnd`，尾段只有真正提交成功后才清除，失败保留可恢复状态；worker 预热、请求限速、单调任务 ID 与单调音频范围共同阻止旧识别覆盖新短语。

| 参数 | 默认值 | 可配置范围 | 备注 |
|---|---:|---:|---|
| Preview 窗口 | 3000 ms | 2000～4000 ms | 尾部每次送模携带的音频上限 |
| Preview 刷新 | 700 ms | 500～1000 ms | 实际节奏随上轮推理耗时自适应（上限 5 s） |
| Draft 最短片段 | 5 s | 3～10 s | 目标窗口开启后 floor 取它与 (target−tol) 的较大值 |
| 强停顿 | 700 ms | 500～1500 ms | — |
| 长静音定稿 | 1100 ms | 800～2000 ms | **不得低于强停顿**（最小间隔 50 ms，前后端三处同步） |
| 短语固定冻结节奏 | 0（关） | 0 或 800～3000 ms | 0 = 绑定预览窗滚动兜底 |
| 定稿目标窗口 中心/宽容 | 10 s / 2 s | 0（关）或 4～30 s / 1～10 s | 0.23.16.7 起默认开启；sanitize 保证 target+tol ≤ 未提交上限 |
| 渐进上屏保留窗口 | G2 0 / Editor 1（句） | 0～5 | 0.23.16.7 起可配置，会话开始时冻结 |

VAD 采用 800 ms / 300 ms 双阈值、8 / 12 / 12 秒窗口、轻量语音计数、渐进停顿与谷内稳健切点（谷内偏移 30–150 ms）；底噪上升护栏作为稳定性判定（修复高底噪麦克风自举死锁）；时间触发短语冻结兜底停顿检测失灵；`silence_threshold` 已退役为兼容字段。FSMN/Silero 等神经 VAD 不在生产链路。

### 3.5 主链路稳定性收口（0.23.11）

- 热键状态每 2 秒自愈，异常须连续两次确认；程序注入不推进物理按键时间游标，重装 hook 前重建物理快照。
- 截图原始 IPC 透传选项（RGBA 先校验、失败回退）；图钉失败对用户可见并支持按窗口 label 定向刷新；OCR 支持静默选区、空白拖动恢复选区移动、空白双击复制，与图钉共用文字选区算法。
- 图钉文字层：原文用 `font_h`，译文用稳定墨迹坐标并做面板避让；颜色保真按词单元对齐（camelCase / snake_case 不拆），译文模式对代码特征行分段着色。
- 截图复用窗口显式 session 生命周期：同步复位完成后才揭示新截图；退出先递增 OCR/翻译 revision，再取消任务与清理。

**关键教训（后续维护必读）**：

- `preventDefault()` **不会**阻止同一页面上的其他键盘监听器——正常模块接管后必须注销应急 ESC。
- Tauri 隐藏窗口**不会**销毁 WebView——所有截图临时层必须按"复用会话"而不是"按页面卸载"清理。

### 3.6 统一资源 ref 层（0.23.12）

原 ImageStash（内存字节/TTL）与 AudioResourceRegistry（磁盘路径/一次性 resolve）合并为统一、短期、最小授权的句柄协议 `ResourceStore`：内存字节/本地文件/未来远程对象 → 身份、授权、生命周期、配额 → opaque `ResourceRef` → OCR/pin/STT/文本读取等 Capability 消费。原 0.23.12/13/14 三段规划一次交付，源码锚点统一为 0.23.12。

1. **backing 双模**：`Memory(Bytes)` / `LocalFile(FrozenLocalFile)`；`RemoteObjectKey` 只留类型边界不实现（远程牵动 SSRF / 下载炸弹 / 凭据）。配额与 TTL 按 backing 独立计数（内存 16 项 / 64 MiB / 15 分钟；本地文件 32 项 / 256 MB / 5 分钟），读取不续期。
2. **`ResourceUse` 封闭枚举**：use 集由签发方决定，AI 只能消费不能自选；变体只收有真实消费方的。`ReusePolicy`（Reusable / OneShot / MaxReads(n)）是 grant 属性，不由媒体类型隐含。
3. **`issue_from_ref` 只许衰减**：派生 grant 的 use ⊆ 源、授权 ≤ 源剩余、有效期取 min，越界返回 `permission_escalation`；"同时保留分析与回放"由签发方一次授予。
4. **token 用 CSPRNG**（≥128 位，`rref_` + 32 hex）：ref 会被 AI/MCP 持有，本质是 bearer capability。
5. **resolve 顺序：校验全过才消费**：在临界区内提交使用次数；错误 use 不消耗 one-shot，并发 one-shot 单赢家。
6. **撤销语义**：`revoke_group` 取代裸 generation（dead 机制），`revoke_by_owner` 作会话级补充；调用方为设置页音频 picker、media.rs RAII revoke、chat 附件按会话 owner 回收。
7. **Blob 投影统一入 store**（消除 `image/*` 特殊分支）；MCP `call_tool` 返回与审计**单次投影共用**，审计只记脱敏元数据，非图片 Blob 返回稳定 reason 而不签发假可用 ref。`CapabilityResult` **不加** Resource 变体。
8. **读取接口只落地 `read_all_bounded(max_bytes)`**；`read_range`/`open_stream` 留签名不实现；`bind_local_resource`（权限放大器）推迟。无 ResourceStore 的运行时（CLI/MCP 降级）在 invoke 边界返回结构化 Unsupported；引擎生命周期**不在** Capability 内管理（`transcribe_audio` 维持"不启动、不安装、不切换"，ensure 责任在可信入口）。
9. **对话附件：模型输入与用户可见正文分离**：附件上下文只注入本轮模型输入，气泡/标题/持久化历史全用可见正文；`messages.attachments` 只落文件名 JSON，**ref 绝不落库**；ref 由模型作为 `transcribe_audio` 的 tool 参数消费（需用户在 AI 能力设置开启，`ai_default: Off`）；Reusable grant，发送成功后按本次 ref 精确离框，生命周期归会话切换/新对话按 owner 回收。chat 附件 TTL 定案 30 分钟；空 use 集 grant 直接拒绝。

### 3.7 语音端点与 G2 交接收尾（0.23.14）

诊断结论：EnergyVad 能识别主要静音，主要矛盾不在微调 `silence_threshold`，而在"候选升级为可靠 Draft"的门槛、Preview 范围语义、任务调度与 G2 交接。批次结论：

- **长静音独立终结**：`long_pause_ms`（默认 1100 ms）+ 可信有声下限 300 ms；`ShortPhraseEnd` 冻结短语同时登记 `short_phrase` 候选，静默累计后按长静音规则升级，复语作废。
- **PreviewSpan 完整范围账本**：`{range, text}` 取代 `(end_sample, text)`；事务式 phrase anchor（单槽 + 回退）；settle 按范围清退——**跨界 span 整条删除、剩余交回尾部重识别，禁止字符串裁剪**。
- **gate 后 stale 复核**：Preview/Phrase 任务拿到 worker gate 后、调模型前复核代际；边界接受 bump 代际使 Draft 优先。
- **G2 注入确认闭环**：账本拆 `queued` / `acked` 双水位，**只有注入 ack 后才从浮窗退场**；终态剩余按 queued 前缀裁剪并冲刷 worker 内 deferred；新增 `blink://voice-g2-delivery`。
- **切点优先低能量谷底**；"多次 hypothesis 稳定公共前缀晋升（LCP）"经 Review 明确**不进**。
- **Review 修复**：复合 Preview 范围契约（`SttEvent::Preview.spans` 是范围单一真源，消费方 Draft 到达即本地 settle）；G2 终态 barrier 三条路径**无条件排入**（`g2_deferred` 只作诊断，依据它跳过会在前台漂移时丢字）；账本 peek/commit 两段式 + 失败回滚保留重试权；跨目标终态超时恢复不静默丢文（G2 走终态 gate + 账本恢复，G1/G3 走 `final_delivery` 闸门恰好交付一次）。

**case_17 环境声尾段误切判据（后续维护关键知识）**：能量占比判据无区分度（伪文本 32.1% / 合法噪声 21.9% / 真句最弱档 38.5% 区间重叠，已废弃）。有效判据是**形态证据——连续强有声段**：强有声 = 10 ms 帧 RMS ≥ VAD 自适应 `on` 阈值；真语音是连续发声段，环境声是稀疏脉冲；门槛 `CREDIBLE_VOICED_RUN_MIN_MS = 100`，同时作用于 `natural_pause` 分支、`long_pause` 分支与终态尾段送模范围门（三个出口必须同时收口，否则"换个分支再采纳一次"）。两条实现约束**不得简化**：

- **不在 finalize 用"当下阈值"重测范围**——`on` 随底噪自适应，尾段静音会让底噪漂移，同一段音频不同时刻结论矛盾（实测流式累计 290 ms vs 重测 90 ms，重测导致正文全丢）；一律复用流式累计的 `uncommitted_strong_run_max`。
- **送模范围门只作用于 PreviewDraft**——Legacy（G1/G3）无候选观察路径，累计值恒为 0，套用会拒掉全部终态文本。

### 3.8 截图实线选区拖动（0.23.15）

根因：`interaction-canvas` 与虚拟桌面物理像素同尺寸，实线拖选每帧全层 `clearRect` + 4 次全屏 `fillRect` + `strokeRect`，开销随截图总像素面积线性增长（双 4K 占 60 Hz 预算的 160–173%），表现为选区落后鼠标与残影。决策：

1. 实时预览改用**专用 DOM 层（四遮罩 + 唯一边框）**，拖动期间 `interaction-canvas` 零绘制——按"变化频率"切分职责：DOM 承接逐帧几何，canvas 承接一次提交的成品。
2. 实时层几何直接消费 **CSS 像素**（`norm(...)` 或 `ss.selCss`），不做位图换算；四条遮罩锚定式只写"变化的那一个维度"，每帧无强制同步布局。
3. 边框线宽沿用 `2 × uiScaleAtCss(x, y, meta)` 的跨屏视觉补偿语义。
4. **单一实时预览调度器**：唯一入口 `updateLiveSelection(rect)`，事件侧只写最新矩形、单飞 rAF 只消费最新矩形；删除 `scheduleDrawSelection` / `scheduleDrawFinalSelection` 两个同队列入口。
5. 激活即"清空一次 + 同帧落地首帧"，单击不动保持原选区可见；提交原子性由 `drawFinalSelection()` / `drawDimmed()` 内部保证（画 canvas 前先隐藏实时层，同一 task 同一帧）。
6. 主画布拖选迁移 Pointer Events 并**真正启用 pointer capture**（原 `mousedown` 分支里的 `setPointerCapture` 因 `MouseEvent` 无 `pointerId` 形同虚设）；`getCoalescedEvents` 只取最后一点；必须删除 mouse 拖选监听避免双处理。
7. 拖动期间不画八个手柄（实时层只含 5 个元素，松手后一次性画回）——有意取舍：实时层只负责"选区在哪里"，不负责"选区可操作"。
8. 几何纯函数化：`computeDragRect` / `computeInteractionRect` 由 pointermove 与 release 路径共用，保证松手用 release 最新坐标计算最终矩形。

**实施期教训（保留）**：

- `applySquareResize` 在 `ss-interaction.js` 被调用但从未导入——**Shift + 八向缩放路径实际不可用且长期潜伏**。Shift 约束是两条独立实现、只有一条有测试时，另一条的错误会潜伏；收敛到同一可测函数是根治手段。
- CSS 给右遮罩同时声明 `right: 0` 与 `width: 0`，绝对定位下 `right` 被忽略——**右遮罩永不显示且单测测不出**（单测只能断言 JS 写了什么，写不进浏览器算出的布局）。为此补了 `testdata/screenshot/live-selection-layout-check.html`（注入产品 HTML/CSS 用 `getBoundingClientRect` / `getComputedStyle` 断言布局），正是它抓出该缺陷。

### 3.10 AI 整理替换语义（0.23.17）

`planRangeReplacement` 纯函数（headless 可测）承载两条引擎级约束，替换规划与应用执行分离：

1. **MD 源文不存在能解析回真实空段落节点的字节序列**——AI 整理稿中的空行必须跳过，段间 `\n\n` 由相邻段落序列化时自然恢复；否则延迟物化的整篇复核必败（回滚 + 只读）。
2. **多行替换必须扩为父 textblock 的块级替换**（blockFrom/blockTo 取段前/段后）——在段内行内 range 上 `replaceWith` 段落数组会被 slice fitter 闭合出幽灵空段落。blockSafe 只保证单块，范围外的同段文字回填进首/末新段，保证实际替换的恰好是冻结文本。

交互配套：应用成功即消费冻结范围（`onApplied` 回调让听写 chips 立即隐藏——已替换的旧 handle 二次整理必失败）；应用不可用的原因内联可见（stale / MD 跨块范围仅支持复制，不再只靠 hover tooltip 零反馈）。

### 3.11 截图/pin 视觉与交互收口（0.23.18）

- **选区 1px 接缝**：实时选区四遮罩与边框改为**一份整数格点矩形推导所有边**——禁止 `round(y)` / `round(h)` / `round(y+h)` 独立取整：混合 DPI 下指针 CSS 坐标（物理像素 ÷ renderScale）是小数，独立取整约半数位置差 1px，遮罩拼接处出现整屏宽 1px 空缝或叠色；与 `drawFinalSelection`「一份取整矩形推导四块 fillRect」同一纪律。left/top 钳 0 对齐 canvas fillRect 的视口自然裁剪。
- **pin 右键与菜单扩窗**：拖动收尾忽略右键的窗口 200ms → 80ms（原值吃掉"拖完立刻右键"的正常节奏）；右键落在已打开菜单上重定位菜单。小 pin 菜单显示不全改为**临时扩窗**（`expandRectForMenu` 默认右/下生长，超工作区时左/上平移回屏内并补偿图片 CSS 偏移，图片视觉位置不动）；新增 `pin_work_area` command + Win32 `MonitorFromWindow` / `GetMonitorInfoW` rcWork 做避让；DPI reconcile 期间扩窗状态先还原再翻转（扩窗平移量是按旧 DPR 算的物理值）。
- **DPI 视觉补偿补齐**：OCR sel-loading / sizeHint / precisionHint 按锚点所在屏 `uiScaleAtCss` 补偿（translate 百分比基于未缩放盒宽，元素中心仍精确落在定位点，无需改定位逻辑）；预选框**几何对齐不缩放、边框线宽按 uiScale 补偿**（`BORDER_CSS_WIDTH × uiScale`，与实时选区边框同一契约，spec-frontend §5.6）。

### 3.12 修复合集（0.23.19，含 Review 修补）

实机使用暴露的杂项批次，五组有决策价值的结论：

| 决策 | 结论 |
|---|---|

## 六、验收与遗留观察

**验收结论**：全量 Rust 测试由 0.23.11 的 3419 项增至 **0.23.16.7 的 3515 passed / 0 failed / 8 ignored**；`cargo check --all-targets` 零 error/warning；前端 **102 个测试文件全绿**（含截图 185 项、渲染策略基准、真实浏览器布局校验 56 项）；`cargo xtask lint`、`git diff --check` 通过。真实 Nano corpus 17 例回放、G2 同构回放与整条 vs 伪流式文本对照均实际执行；0.23.15 性能基准：每帧主线程成本从随截图像素面积线性增长（4K 6.45–6.64 ms、双 4K 26.7–28.9 ms）降为恒定 0.03–0.05 ms。0.23.17～0.23.19 增量验收：全量 Rust 测试 **3522 passed / 0 failed / 8 ignored**；前端全量 `node --test` **720 项全绿**（截图域 219 项；新增 markdown-engine 替换规划、实时选区接缝、pin 扩窗避让、sel-loading 缩放、编辑器 ESC 行为测试等用例）。

**仍需持续观察**：

- 人工验收类：对话附件闭环端到端 GUI 手测；G2 真实场景听写与 `long_pause_ms` / 目标窗口联合扫参（含 D9 目标窗口默认开启后的准确率收益 A/B）；0.23.15 真机矩阵（4K / 120·144 Hz / 多 DPI / 跨屏 / 拖出边缘 / ESC 中断）；图钉文字层在不同 DPI、缩放与复杂背景下的视觉验证。
- 已知边界（非回归）：环境声尾段的 Preview 可变层可能短暂幻觉（终态已不可能提交）；短语冻结/Draft 提交的瞬间，与其范围重叠的尾部整条清退，未覆盖后缀要等下一次尾部重识别才回场（单 worker 下立即重识别会翻倍推理量，未做）；连续强有声段判据不是语音检测器，对稳态高电平环境声（恒定转速风扇）不拒绝，届时需频谱证据；远场轻声尾段重识别是既有行为，根治需终态尾段的远场噪声门控；RustDesk / ToDesk 下长截图受 WDA_EXCLUDEFROMCAPTURE 限制。
- 云端引擎（在线 STT）只实现旧 `SttEngine`：录音期间无 Preview、无 Draft，松键后一次性 finalize 全文并注入（无丢字、无重复上屏，但渐进上屏退化为一次性上屏，高级区双层参数对云端无效）。要复用双层协议需先把伪流式的送模通道抽象成可插拔，且每次刷新都是一次 HTTP 调用（费用/RPM/延迟），更适合"本地 VAD 分段 + 只在合格候选处调云端"的折中；词汇级实时预览需供应商提供流式 ASR。
