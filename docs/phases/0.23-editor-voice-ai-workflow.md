## 二、背景与边界

0.23 把 Blink 从“把识别结果一次性写到输入框”推进为可持续工作的文本处理链：来源文本可精确编辑，语音可连续追加，AI 修改必须先展示候选并由用户确认。实现以单会话、明确版本号和单写入点约束异步任务，避免旧结果覆盖新内容。

本阶段不解决：

- 富文本格式的无损往返；Markdown 仅支持安全子集预览。
- 多文档、多窗口并行编辑。
- 无确认的 AI 自动改写。
- 远程桌面下依赖系统排除捕获能力的“无条件可见”长截图。

## 三、核心决策与最终约束

### 3.1 单个预热编辑器与 EditorSession

- 全局复用一个预热编辑器窗口，激活相同来源；来源不同且已有活动会话时返回 EditorBusy。
- 会话身份由 session_ref + generation + content_revision 共同限定。所有异步回传在落地前复核身份与版本。
- 用户编辑、语音提交、AI 确认都走统一事务入口，统一更新 revision 与撤销栈。
- 窗口隐藏不等于会话结束；复用 WebView 必须在进入前同步复位，在退出时立即失活并取消旧任务。

### 3.2 Source、Markdown 与写回

- Source 是唯一文本真源；Markdown 只是安全渲染视图，不反向承载隐式格式状态。
- SourceDescriptor 描述来源，CommitTarget 描述写回目标；读取能力不自动获得写权限。
- 文件保存通过 UTF-8 原子写能力完成，并受 mutation gate 约束。
- 自动 Markdown 预览上限 32 KB；可编辑 Markdown 上限 128 KB；Source 上限 200 万字符；Diff 上限 200 KB；AI 输入上限 24k tokens。

### 3.3 连续听写与 AI 整理

| 场景 | 语音结果 |
|---|---|
| G2 输入框 | Preview 仅展示；Draft 定稿即注入前台应用，会话终态只补交剩余（0.23.13 渐进上屏） |
| Editor | Preview 作为临时装饰；Draft 持续提交到正文 |
| G1 / G3 | 保持 Legacy 流程 |

- 任一时刻只有一个活动语音会话和一个活动 AI 请求。
- AI 启动时冻结 revision、选区与内容 hash，只生成候选；确认时再次校验，成功后作为单个事务写入。
- AI 候选与 Diff 不修改 Source；用户继续编辑后，过期候选不能提交。

### 3.4 Preview/Draft 双层识别

- 单 worker 串行调度识别任务，保留“一个运行中的任务、一个待执行 Draft、最新 Preview”。
- AudioRange 使用半开区间和绝对采样位置；owned_range 与 model_input_range 分离，禁止靠文本相似度拼接。
- Preview 允许被更新或丢弃；Draft 只能按不重叠音频范围提交。最终尾段与 Draft 优先级高于 Preview。
- committed_watermark 与 reserved_watermark 分别表示已提交和已占用边界；积压硬上限为最大窗口的 2 倍。
- RequestAudioGate 在任务执行前再次验证范围与代次；G2 最终识别失败时不注入未定稿残余，已定稿内容仍补交不丢（0.23.13）。

| 参数 | 默认值 | 可配置范围 |
|---|---:|---:|
| Preview 窗口 | 3000 ms | 2000～4000 ms |
| Preview 刷新 | 700 ms | 500～1000 ms |
| Draft 最短片段 | 5 s | 3～10 s |
| 强停顿 | 700 ms | 500～1500 ms |

VAD 最终采用 800 ms / 300 ms 双阈值、8 / 12 / 12 秒窗口、轻量语音计数、渐进停顿和 1.2 秒谷底切分；0.23.13 底噪上升护栏改为稳定性判定（修复高底噪麦克风下的自举死锁），并新增时间触发短语冻结兜底（停顿检测失灵时预览仍按短语增量累积）；silence_threshold 退役为兼容字段（默认 0.001，UI 已移除滑杆）。FSMN 不进入本阶段生产链路。

### 3.5 短语级收口

- 0.23.10 引入 Phrase Anchor、Phrase Ledger 与 ShortPhraseEnd，Preview 可按短语稳定展示。
- 尾段只有真正提交成功后才清除；失败时保留可恢复状态。
- worker 预热、请求限速、单调任务 ID 与单调音频范围共同阻止旧识别覆盖新短语。

### 3.6 0.23.11 主链路稳定性收口

- 热键状态每 2 秒自愈；异常须连续两次确认。程序注入不推进物理按键时间游标，重装 hook 前重建物理快照。
- 截图原始 IPC 透传选项，RGBA 数据先校验、失败再回退；图钉失败对用户可见，并支持按窗口 label 定向刷新。
- OCR 支持静默选区、空白拖动恢复选区移动、空白双击复制；截图和图钉共用文字选区算法。
- 图钉增加 OCR/翻译文字层；原文使用 font_h，译文使用稳定墨迹坐标，并加入面板避让。
- 截图复用窗口新增显式 session 生命周期：初始与退出状态用 screenshot-session-inactive 隐藏旧图层；同步复位完成后才揭示新截图；退出先递增 OCR/翻译 revision，再取消任务与清理 loading snapshot；翻译面板轮询同时校验任务版本、会话版本和 DOM 连接状态。
- OCR/翻译叠层颜色保真：原文字色按词单元对齐（正则分词，camelCase/snake_case 不拆）；译文模式对代码特征行（结构簇判定）启用分段着色并合并碎片段，多语法色代码行译文不再集体回退黑白灰。配套 corpus 颜色采样评测（testdata/ocr/corpus + PaddleOCR 真实推理探针）。

关键教训：preventDefault() 不会阻止同一页面上的其他键盘监听器；正常模块接管后必须注销应急 ESC。Tauri 隐藏窗口也不会销毁 WebView，所有截图临时层都必须按“复用会话”而不是按“页面卸载”清理。

## 八、0.23.12：统一资源 ref 层（✅ 已完成）

> 文档原按 0.23.12/0.23.13/0.23.14 三段规划（协议与音频腿 / 图片腿与投影 / review 收紧），实际合并为 0.23.12 一次交付，拆分作为风险控制手段完成使命，源码注释锚点已统一为 0.23.12。原 0.23.99 转正。

### 8.1 背景与定位

此前两套资源引用平行运作：ImageStash（内存字节、15 分钟 TTL、非消费读取、64 位 xorshift token，喂 OCR/pin/图片 Capability，投影层只把 `image/*` Blob 移入 stash）与 AudioResourceRegistry（磁盘路径 + FileIdentity、5 分钟 TTL、scope 字符串、一次性 resolve，喂转写与 VAD 调试），且后者 `resolve` 先 remove 再校验，错误 scope 会烧掉一次性 ref。0.23.12 把「合并两套 Registry」收口为统一、短期、最小授权的资源句柄协议：ResourceStore 是 Capability 之间的**数据平面**（跨调用传递大资源的临时句柄），不是新的执行平面，不改变 0.21 Capability 唯一原子执行语义。定位：内存字节/本地文件/未来远程对象 → ResourceStore（身份、授权、生命周期、配额）→ opaque ResourceRef → OCR/pin/STT/文本读取等 Capability 消费。

### 8.2 核心决策（已定案）

1. **backing 双模**：`Memory(Bytes)` 与 `LocalFile(FrozenLocalFile)` 落地；`RemoteObjectKey` 只留类型边界不实现（远程牵动 SSRF/下载炸弹/凭据，本阶段不背）。配额与 TTL 均按 backing 分口径、独立计数：`resident_memory_bytes`（16 项/64 MiB/单项 32 MiB，TTL 15 分钟）与 `referenced_local_bytes`（32 项/256 MB/单项 128 MB，TTL 5 分钟），读取不续期；投影层 `expires_in_seconds: 900` 改由 grant 元数据派生，与内存腿 15 分钟绑定。
2. **ResourceUse 封闭枚举**：scope 上升为所有 ref 的通用属性；use 集由签发方（UI/Interaction/内部 Capability）决定，AI 只能消费不能自选；变体只收有真实消费方的（DecodeImage/OcrImage/PinImage/TranscribeAudio/PreviewAudio），无消费方不占位。ReusePolicy（Reusable/OneShot/MaxReads(n)）是 grant 属性，不由媒体类型隐含。每新增消费型 Capability 需扩枚举并评审签发方白名单——这是有意的收敛摩擦，不是债，不得当债优化掉。
3. **`issue_from_ref` 只许衰减（attenuation-only，review 收紧定案）**：派生 grant 的 use 必须是源 grant 子集、总读取授权 ≤ 源剩余授权（OneShot 不得派生 Reusable/MaxReads(n>1)）、有效期 = min(请求 TTL，源剩余有效期)，越界返回 `permission_escalation`。VAD 调试所需的双 use 由可信 picker 在签发阶段一次授予，派生即纯衰减；对只允许 `TranscribeAudio` 的 ref（普通 picker / chat 附件）派生在 store 层被拒——"同时保留分析与回放"由签发方决定，不靠通用 clone 增权。
4. **token 换 CSPRNG**：≥128 位 OS 安全随机（getrandom，`rref_` + 32 hex），替换两套 xorshift/时间戳方案。ref 会被 AI/MCP 持有，本质是 bearer capability，弱随机不可接受。
5. **resolve 顺序：校验全过才消费**：查找 → TTL/revoke_group/use/identity 校验 → 取得 lease → 同一临界区内提交使用次数；错误 use 不消耗 one-shot，并发 one-shot 单赢家。校验与消费必须同锁原子完成——修复了旧 registry "先 remove 再校验"烧掉一次性 ref 的缺陷。
6. **撤销语义收敛**：`revoke_group` 取代裸 generation（generation 在生产代码零调用，本就是 dead 机制），`revoke_by_owner` 为会话级补充原语；撤销采用移除语义（被撤 ref 返回 `invalid_resource_ref`，`GroupRevoked` 错误不可达即删除）。真实调用方：设置页音频 picker 每次成功 pick 分配新撤销组并撤销上一组未消费 ref（"一次选择 = 一个调试会话"，`AudioPickSession`）、media.rs 请求结束 RAII revoke、chat 附件按会话切换/新对话以 owner 回收。
7. **Blob 投影统一入 store**：`to_rig_tool_result_with_store` 消除 `image/*` 特殊分支，仅图片 Blob 签发 `image_ref`（wire 参数名保留，LLM 语义友好；其余为 `resource_ref`）；无 store 时结构化降级（`blob_unavailable`）不静默吞摘要。review 收紧两条：MCP `call_tool` 返回与审计**单次投影**共用（此前双投影产生两个 ref、两份缓存，且 bearer token 进审计记录），审计摘要只记 MIME/尺寸等脱敏元数据、不含 `rref_`；非图片 Blob 不签发假可用 ref，返回稳定 reason `unsupported_media_type`。
8. **CapabilityResult 不加 Resource 变体**：Blob 仍是一次调用的直接二进制返回。当前无生产者需要显式签发变体（截图/剪贴板走 Blob 投影、转写返回文本、VAD 调试走 command）；等真实场景出现再加，届时投影层已统一、增量小。
9. **读取接口只落地 `read_all_bounded(max_bytes)`**：文本分页由 `read_text_file` 承担，音频转写整读够用；`read_range`/`open_stream` 留签名不实现。`read_text_file` 不动（本地绝对路径与短期授权句柄解决不同问题）；`read_text_resource`/`bind_local_resource`（后者是权限放大器）推迟到有真实需求再立项。
10. **CLI/MCP 降级口径**：无 ResourceStore 的运行时在 invoke 边界返回结构化 Unsupported（spec-architecture §A3.2 既有规定），投影层不静默吞成摘要；CLI `blink transcribe` 是真实消费方，与 TauriDomainEnv 构造同一 store 走全链路，不得降级。
11. **引擎生命周期不在 Capability 内管理**：`transcribe_audio` 维持「不启动、不安装、不切换」；引擎未运行返回结构化 `SttBackendUnavailable`、未配置 `SttNotConfigured`、云端文件转写维持 `Unsupported`（H04 未实现）。ensure 责任在**可信入口**：CLI invoke 前显式 start；chat 附件签发与设置页 picker 共用 `spawn_stt_engine_prewarm` 后台预热（失败不阻塞附件，转写时结构化报错）。不新增引擎生命周期 capability——现有引擎管理在 Tauri command 层（设置页专用），暴露给 AI 牵动 danger 分级与确认策略，本阶段不背。
12. **对话附件：模型输入与用户可见正文分离**：发送负载 = `{text（可见正文）, attachments（结构化元数据）}`；附件上下文只注入本轮模型输入，预写落库/标题截断/LLM 命名全用可见正文——`audio_ref` 技术块不进气泡、标题与持久化历史；`messages.attachments` 列只落文件名 JSON，**ref 绝不落库**；附件渲染为独立卡片气泡，不参与消息编辑/重试流，发送、历史加载、编辑重渲染、导出四处一致。附件 ref 由模型作为 `transcribe_audio` 的 tool 参数消费——需用户先在 AI 能力设置开启该 cap（`ai_default: Off`，0.21.5 allowlist），确认流程照旧；Reusable grant，转写失败重试不烧 ref。发送成功后附件按本次发送的 ref 精确离框（后端不撤销——本轮 agent 仍要消费，生命周期归会话切换/新对话按 owner 回收）；composer 会话 id 由 `initComposer({getConversationId})` 注入，picker 返回时会话已变则立即撤销刚签发的 ref 并丢弃。

**实现期补充定案**：空 use 集 grant 在签发层直接拒绝（无人能 open 的 ref 不签发）；chat 附件 grant TTL 定案 30 分钟（`CHAT_ATTACHMENT_TTL`，Reusable + 会话撤销场景放宽 LocalFile 默认 5 分钟）。

## 九、0.23.14：VAD 与 Preview/Draft 稳定性收口（📋 规划中）

> 原资源层 0.23.14 规划已随 0.23.12 合并交付而失效；本节重新使用 0.23.14 版本槽，主题仅为语音端点、双层识别与 G2 交接稳定性。
>
> 本节来自 2026-09-17 的只读排查与真实 corpus 回放；截至记录时未修改生产代码。

### 9.1 诊断结论与证据

结论：EnergyVad 能识别主要静音，当前主要矛盾不在继续微调 `silence_threshold`，而在“VAD 候选升级为可靠 Draft”的门槛、Preview 短语账本的范围语义、识别任务调度，以及 G2 注入/浮窗交接。

- 一条 16.81 秒停顿梯度录音的调试日志仅产生 3 次 Draft，提交范围约为 5.31s、5.00s、5.69s；最终尾段约 0.81s。`boundaries=3 / decisions=5 / commits=3`，说明实际行为受 5 秒 Draft 门槛主导，而非每个明显长停顿都及时提交。
- 同一日志有 28 次 worker 完成，累计推理约 9457ms，平均 337.7ms、最大 769.5ms；其中一次已过期 Preview 仍完整运行 487.7ms 后才因代际变化被丢弃。
- Preview 字符数序列出现 `8→8→10→20→16→0`、`3→6→5→5→0`、`3→3→10→9→19→14→20→0`，证明尾部预览存在真实替换/回缩；Draft 提交后的清零是协议行为，但 G2 注入未确认时清零会形成可见空档。
- 生产默认配置（`silence_threshold=0.001`）真实回放：短词样本整段/伪流式一致（100%，2 次调用）；长停顿续说约 85%（7 次调用）；停顿梯度约 98%，但 16.81 秒音频需 27 次调用；多短停顿加久停顿样本预期 2 段，生产 PreviewDraft 实际只接受 1 个 Draft 边界。纯静音样本最终为空且无边界，说明 NoSpeech 基线基本正常。
- VAD 单元测试 41 项、pseudo_streaming 单元测试 89 项通过；现有测试覆盖音频范围、水位、代际和终态接管，但未覆盖短句后长静音、短语识别空/失败后的锚点恢复、过期排队任务是否在推理前取消、G2 注入确认前的浮窗保留。

### 9.2 已定位根因

1. **长静音不是独立 Draft 终结条件**：普通候选不足 `draft_min_s=5` 时，还要求 owned audio ≥2s、有效语音 ≥1.2s、静音达到 strong pause；因此约 0.8～2 秒短句后即使静音数秒，也可能只停在 Preview，直到复语或会话结束。
2. **Preview 尾部本来就是整串替换值**：滚动窗口每轮重新识别，`set_preview_if_changed` 不承诺文本单调；字符数与内容均可回退。
3. **时间冻结先推进锚点、后等待识别**：滚动窗前缀达到 1.2 秒即可能在无声学边界处切片，`phrase_anchor` 在短语识别成功前已推进；错误或空文本会让该前缀从 Preview 视图丢失。
4. **Preview 账本范围不足**：`preview_phrases` 只保存 `(end_sample, text)`，组合 Preview 却只携带最近尾部/短语的 range；边界回退或 Draft 部分覆盖时无法按音频范围精确清退、保留和去重。
5. **逻辑协调器未形成真实执行优先队列**：Preview/短语/Draft 最终仍以异步任务竞争单 worker gate；排队任务拿到 gate 后没有先复核代际，导致过期 Preview 消耗模型并推迟 Draft。
6. **G2 “已冲刷”早于“已注入”**：G2 retention=0，Draft 投递注入 worker 后立即从浮窗 confirmed 窗口退场；注入可能尚未完成、失败或因前台变化延迟，用户会看到 Preview/Draft 短暂消失或漂移。
7. **测试参数真源不完全一致**：部分 corpus 段数统计仍使用 `EnergyVad::new()` 的旧 0.005 默认值，而生产配置默认已是 0.001，可能造成验收假阳性或口径不一致。
