## 二、背景与动机

### 2.1 已解决的问题与当前矛盾

0.23 已把编辑器从裸 `origin/format/save_policy` 与两套分支逻辑，收敛为有身份、代际、revision 和明确保存目标的临时编辑会话；连续听写与 AI 整理也已进入同一套生命周期和竞态防线。

0.23.7 改善了长句边界，但当前伪流式链路仍把 VAD 边界近似等同于正式切片。短片段有利于快速出字，却缺少足够上下文；简单延长切片又会损害预览响应。0.23.9 因此把“快反馈”和“较可靠草稿”拆成两个逻辑层。

### 2.2 明确“不是问题的”

- Source 与 MD 使用不同 Engine 是合理分工；统一的是 Adapter 和文本真源，不是底层 DOM。
- 编辑器仍是临时 Interaction，不扩展为笔记库、标签页或多文档工作区。
- G2 的实心字与虚字目前都位于 Blink 悬浮层，并非外部应用中的系统选区或输入法组合文本；外部应用只在结束时收到一次最终注入。
- 编辑器与 G2 已共享 `StreamingSttPort` 的 confirmed/preview 来源，但提交策略不同：编辑器 confirmed 进入正文，G2 confirmed 留在悬浮层缓冲。
- 双层识别是一个 worker 内的两条逻辑 lane，不是两个模型进程；单模型内存与全进程单 VoiceSession 约束不变。

## 三、核心设计 / 决策

### 3.1 单窗口、单活动 EditorSession（已定）

继续复用预热 `content-editor` 窗口。后端持有不可猜测的 `session_ref`、generation、来源、保存目标、来源 revision 和异步 operation id；前端持有工作文本、selection、undo/redo、Engine 状态与单调 `content_revision`。所有异步回流按会话身份和请求身份过滤，旧代结果不得修改新会话。

打开同一持久来源时激活现有窗口；不同来源返回结构化 `EditorBusy` 并激活当前任务，不排队、不覆盖、不自动合并。

### 3.2 Source/MD 是同一 UTF-8 文本的双视图（已定）

Source 精确保真，MD 只对已验证 Markdown 子集提供 Tiptap 所见编辑。未发生 MD 编辑时切回 Source 必须保留原文；风险结构拒绝进入可编辑 MD。当前冻结门限为：32KB 以上不自动进入 MD、128KB 以上拒绝进入可编辑 MD、Source 硬上限 2,000,000 字符、Diff 输入上限 200KB、AI 整理输入估算不超过 24,000 token。

Editor Adapter 只暴露快照、opaque range handle、单事务替换、追加、定位、undo/redo、focus 和生命周期订阅；后端不解析 DOM/ProseMirror position，也不按字符 offset 修改正文。

### 3.3 来源、保存目标与副作用分离（已定）

`SourceDescriptor` 只描述来源，`CommitTarget` 只描述主保存去向。主保存支持剪贴板结果、便签原位更新、有效调用方回写和用户确认的文件；“另存为副本”、复制、创建便签、发送到 AI 对话不改变主目标。

文件写入收敛到唯一文本写入 Capability，使用 UTF-8、同目录临时文件、原子替换和 identity 冲突检查。保存、关闭和结束会话由同会话 mutation gate 串行化；同 revision 只有同一 mutation 的精确重放才幂等。

### 3.4 连续听写与目标投影（已定）

连续听写是单 VoiceSession 的 Editor 模式。语音引擎产生的可靠段按 `epoch + segment_seq` 排序，编辑器使用有界 snapshot 补缺；preview 只进装饰层，不进入正文、dirty、undo、保存或 AI 输入。

现有目标投影保持：

| 目标 | 稳定文本 | 临时预览 | 会话结束 |
|---|---|---|---|
| G2 | Blink 悬浮层实心字 | Blink 悬浮层虚字 | 拼接完整结果并向外部应用注入一次 |
| Editor | 追加到正文 | 编辑器装饰层虚字 | 冲刷尾段并结束听写状态 |

### 3.5 AI 整理只产候选（已定）

“整理选中内容”和“整理本次听写”复用全进程 AI 单活跃协调器，使用无记忆、无工具的 completion。请求冻结 `content_revision + range_handle + selected_text_hash`；正文变化即令候选 stale。模型完整终稿到达后才生成稳定 Diff，用户确认后由当前 Engine 单事务替换，一次 undo 可恢复。

### 3.6 长语音 VAD 收敛结论（已完成）

0.23.7 将原三轮工作合并为一个完成里程碑，生产结论为：

- 默认窗口保持 `min_sentence=800ms`、`min_silence=300ms`、soft/hard/max-uncommitted=`8s/12s/12s`，高级设置可配置并在前后端安全归一化。
- 轻声句长按 `RMS >= off` 的非静默帧累计，解决滞回区轻声不计入有效句长的问题。
- 8s 后软切由“首个低能量帧立即切”改为 300→150ms 的渐进连续静默。
- 12s hard/cap 触发时，可在最近 1.2s 内回退到合格低能量谷底；没有安全候选时仍按原上限兜底。
- 回退尾音会重新进入下一段 VAD 状态；绝对音频区间、pending/deferred/terminal 接管和 compact 均保持单调、无重复、无丢段。
- 降低 800ms 门槛或引入 4s 短句累计的候选出现噪声误切或过切，未进入生产。FSMN-VAD 因缺少可运行 GGUF 资产未作质量结论，也未接入生产。

自动化证据覆盖 11 条标注样本、6 条匿名长录音、真实 Nano 回放、VAD/引擎不变量与全量回归。人工复听清单、G1/G2/编辑器真机体感和无语音 terminal 幻觉作为后续质量观察项保留，不再阻塞该里程碑关闭。

### 3.7 双层识别 —— Preview + Draft（0.23.9 已定方案）

**定案**：VAD 只产生候选边界；统一识别协调器在同一个 worker 上调度 Preview 与 Draft 两条逻辑 lane。Preview 负责低延迟反馈，Draft 负责带更多上下文的稳定草稿，最终提交由目标投影决定。

**理由**：响应速度与上下文长度不再由同一个切片同时承担；G2 和编辑器复用同一音频时间轴与识别结果，又不需要在首版进行字符串相似度合并。

```text
连续音频 / VAD 候选
        │
        ├─ Preview lane：短语定稿增量拼接 + 尾部上下文（默认 3s 上限，2～4s 可调），约 700ms 刷新，latest-wins
        │
        └─ Draft lane：优先聚合为 5～12s 非重叠片段，可靠排队
                    │
                    ├─ G2：实心草稿 + 虚字预览，结束后一次注入
                    └─ Editor：草稿追加正文 + 尾部虚字预览
```

Preview 的“输入窗口”和“刷新周期”是两个独立参数。首版默认 `preview_window_ms=3000`、`preview_refresh_ms=700`，设置页允许分别在 2000～4000ms / 500～1000ms 范围内调整；会话开头至少积累 1.2s 有效输入才发首个 Preview。0.23.10 起尾部输入区间锚定 `phrase_anchor`（最近被复语作废候选的 quiet_start 与 committed 的较大者）：`[max(phrase_anchor, captured_audio_end - preview_window), captured_audio_end)`，短语内窗口从头增长，仅单个短语超过 `preview_window` 才回退滚动，不足最小有效音频时跳过。候选停顿被复语作废时，对 `[phrase_anchor, quiet_start)` 做一次“短语定稿”（≥500ms 有声门控），冻结文本进入短语账本，与尾部拼接成对外仍是单个可替换的 Preview 字符串；真实切割的 Draft 整段重识别替换后，按 committed 清退被覆盖短语。窗口适当长于刷新周期，目的是让每次 Preview 都携带短语级上下文，而不是把新增的 500～700ms 孤立音频送入模型；它仍只是可变反馈，不承担最终准确度。

Draft 初始边界策略固定为：普通自然候选只有在未提交音频达到 `draft_min_s` 后才可接受（默认 5s，设置范围 3～10s）；达到 `strong_pause_ms` 的强停顿可提前冲刷（默认 700ms，设置范围 500～1500ms），但仍要求未提交区间至少 2s 且其中有效有声累计至少 1.2s，避免重新制造 800ms 左右的正式短片段；会话结束无条件检查并冲刷有效尾段；达到现有 `hard_window_s` 或 `max_uncommitted_s` 时必须定稿，并优先回退到最近 1.2s 内的安全低能量候选。默认组合仍形成“5～12s Draft”，用户调参后单次上限以 `max_uncommitted_s` 为最终保险。

VAD 事件不再直接创建 Draft。协调器保存一个有界 `BoundaryCandidate`（绝对切点、quiet start、原因、有效有声量）；300ms 普通停顿先形成候选，后续原始能量帧把同一候选升级为 700ms strong pause。VAD 自身即使重置句子状态，候选及其静默证据仍由协调器持有，直到被接受、被更新或被后续语音作废。

### 3.8 音频时间轴代替文本合并（0.23.9 已定）

识别会话维护非重叠 `DraftSpan` 与一个可替换的 active preview。领域协议使用半开绝对样本区间 `AudioRange { start_sample: u64, end_sample: u64 }`，采样率在 session 开始时冻结；不得把 `usize`、buffer 局部 offset 或模糊的毫秒值作为跨层身份。调度占有的 `owned_range` 与实际送模的 `model_input_range` 分开：前者负责时间轴无缝覆盖，后者允许 audio gate 裁去首尾静音。每个结果至少携带 session generation、request/span id、音频绝对区间和自身 revision：

- Preview 可以重叠，只保留最新请求；迟到结果丢弃，永不直接提交。
- Draft 只覆盖 `[draft_committed_audio_end, boundary)`，可靠排队并按音频区间追加。
- Draft 到达后，覆盖相同音频范围的 Preview 整体失效。
- Draft 失败时不推进 committed audio end，后续请求重新覆盖该段。
- VAD 裁剪后为空或短到无有效语音的请求不得进入模型。

首版不通过 LCS、文本后缀或语义相似度拼接重叠识别结果。`span_id/audio_range/revision` 从首版保留，为后续整句重识别和已提交 Draft 替换建立身份基础。这里的 revision 只表示同一 span 的修订版本；引擎状态 revision、Editor `content_revision`、事件 `seq` 和 session generation 继续各自命名，禁止共用一个裸 `revision` 猜语义。

`StreamingSttPort` 的可靠交付物改为类型化 Draft 事件，而不是让消费方从累计 `confirmed` 字符串推导增量。Editor snapshot 同步保存 `seq + DraftSpan`；G2 的累计实心文本只是 Draft ledger 的视图投影。Preview 事件携带 `request_id + audio_range + text`，发出新 request id 后，旧请求即使先返回也视为 stale。旧 G1/G3 投影如仍需要累计文本，由 app 层从 span ledger 生成兼容 payload，不把字符串反推逻辑留在领域层。

### 3.9 单 worker 优先级与结束语义（0.23.9 已定）

调度优先级固定为 `会话结束尾段 / Draft > Preview`。优先级是单 worker 上的非抢占优先级：已经进入 worker 的请求不能被中断，但它结束后的下一请求必须按该顺序选择。调度器最多持有一个 running request、一个可合并的 pending Draft 和一个 latest pending Preview；新 Preview 覆盖旧 pending Preview，Draft 建立后删除尚未开始的重叠 Preview。

G2 结束时进入 closing，冻结 `recording_audio_end`，取消 pending Preview 并使在途 Preview 结果失效。在途 Draft 可在整体 12s 结束预算内完成；尚未开始的 Draft 不再逐个执行，而由有界 terminal drain 接管当时的 `[draft_committed_audio_end, recording_audio_end)`。每个 final-tail 请求不超过配置的 `max_uncommitted_s`；派生 backlog hard limit 等于其两倍，保证 terminal drain 最多两段。如果在途 Draft 失败，committed end 不推进，因此 terminal drain 自动重新覆盖失败区间。全部 final-tail 成功后按 Draft ledger 拼接并向原应用注入一次。

Preview 不再作为 terminal 识别失败的提交兜底。final-tail 失败时，G2 不向外部应用注入不完整文本，悬浮层显示明确错误并保留已成功 Draft 供用户查看，用户可重新发起听写；Editor 保留已追加 Draft、丢弃 Preview 并报告尾段失败。纯静音或经统一 audio gate 判定为无有效语音的尾段视为“无需新增文本”的成功结束，而不是失败。

### 3.10 Preview 与 Draft 的重叠转换（0.23.9 已定）

Draft commit 时按音频区间处理当前 Preview：

- Preview 完全位于 Draft 范围内：清除；
- Preview 完全位于 Draft 之后：保留；
- Preview 与 Draft 部分重叠：整体清除，禁止裁剪识别字符串；若 Draft 之后已经积累足够有效尾音频，绕过常规 cooldown 立即排一个新 Preview。

Draft commit、rollback、pending Preview 替换和 terminal takeover 都必须推进相应 request/span generation，使迟到结果只能释放自己的资源，不能清除新请求的 owner 或覆盖新文本。

### 3.11 有界积压与失败重基（0.23.9 已定）

协调器同时维护 `draft_committed_audio_end` 与 `draft_reserved_audio_end`：前者只随成功 Draft 推进；后者覆盖 running/pending Draft 已预留的末端，防止正常排队时创建重叠请求。若 running Draft 失败，pending Draft 必须以新的 request/span identity 重基为 `[draft_committed_audio_end, pending.end)`，不得沿用失败前的起点。

Draft pending 采用“单槽合并边界”而非逐候选排队：worker 忙时，新接受边界只扩展同一个 pending Draft 的 end，且最多扩展到距其 start `max_uncommitted_s`；更后的音频留在未预留尾部，等槽位释放后再形成下一段，因此请求对象数量有界。running 失败后的重基同样按候选/`max_uncommitted_s` cap 拆分，不能产生超长重试请求。当 `captured_audio_end - draft_committed_audio_end` 达到派生的 `2 × max_uncommitted_s` backlog hard limit（默认 24s）时，协调器停止接收新音频、取消 Preview，并以 `stt_overloaded` 明确终止会话，禁止静默丢音频或继续无界持有 PCM。Editor 保留已提交 Draft；G2 不自动注入不完整结果。backlog hard limit 是内部安全派生值，不单独暴露设置，用户不能把它关闭。

PCM compact 只回收小于“所有 running/pending/active preview 最小 start”的前缀；请求持有绝对区间而不是借用可移动 buffer。队列槽数、retained PCM 时长与 overload 次数进入无正文诊断快照。

### 3.12 暂停、结束与目标启用范围（0.23.9 已定）

Editor pause 是捕获边界而非时间轴中的静音：暂停后不接收新 PCM，取消 Preview，并把暂停前有效尾段作为 Draft flush；在途可靠 Draft 仍可提交。resume 从新的声学段继续，暂停期间墙钟时间不写入音频坐标，避免把暂停前后的语音无边界拼成同一 Draft。

0.23.9 通过领域层 `RecognitionProfile` 启用策略：G2 与 Editor 使用 `PreviewDraft`；G1/G3 首版使用由同一协调器表达的 `Legacy` profile，保持其现有刷新、提交和界面契约。profile 只描述识别调度参数，不携带 `VoiceTarget` 或 Tauri 类型。完成 G2/Editor 验证后，再单独决定是否让 G1/G3 切换到双层参数。

### 3.13 统一请求卫生与静音消费（0.23.9 已定）

Preview、Draft、final-tail 共用纯领域 `RequestAudioGate`，输入 owned range、PCM 与本次冻结的 VAD 阈值，输出：

- `Valid { model_input_range, voiced_samples }`：允许送模；
- `TooShort`：普通 Preview/Draft 暂不请求，继续积累；显式结束/暂停边界仍允许有效短语进入 final-tail；
- `NoSpeech`：不调用模型，以无文本 disposition 消费整个 owned range 并推进音频水位。

audio gate 只使用能量、有效帧数和长度，不读取或记录转写正文。对 `NoSpeech` 推进的是音频覆盖水位，不产生 `DraftSpan`，从而避免纯静音既反复重试又撑大 backlog。裁剪后 WAV 为空必须在 transport 调用前返回；case_09/10/11 等预期无语音样本不得产生流中 Draft 或 terminal 幻觉。

### 3.14 配置归属、设置页与旧字段迁移（0.23.9 已定）

Preview/Draft 是识别协调策略，不属于 VAD 本身。`LocalEngineConfig` 新增独立 `recognition` 子配置（类型名可用 `RecognitionConfig`），旧配置缺字段时由 serde default 安全补齐，不要求数据库破坏性迁移：

| 新字段 | 默认 | 设置范围 | 设置页含义 |
|---|---:|---:|---|
| `preview_window_ms` | 3000ms | 2000～4000ms | 尾部虚字识别的上下文上限；短语内从头增长，单个短语超过该长度才回退滚动 |
| `preview_refresh_ms` | 700ms | 500～1000ms | 虚字尝试刷新间隔；不是送模音频长度 |
| `draft_min_s` | 5s | 3～10s | 普通 VAD 候选可形成实心 Draft 前的最低累计上下文 |
| `strong_pause_ms` | 700ms | 500～1500ms | 允许不足 `draft_min_s` 的有效短语提前 Draft 的强停顿门槛 |

约束统一由后端 sanitize，前端只做同规则即时回显：`preview_refresh_ms < preview_window_ms`、`draft_min_s <= max_uncommitted_s`；`strong_pause_ms` 小于现有 `min_silence_ms` 时，有效强停顿门槛自然取两者较大值。1.2s 首次 Preview 有效输入、2s strong-pause owned range、1.2s strong-pause voiced、派生 backlog hard limit 都是安全不变量，不暴露为普通配置，避免设置页变成十余个互相牵制的旋钮。

设置页在现有 VAD 卡片之后新增独立“Preview 与 Draft（高级）”卡片，只在本地伪流式配置下显示上述四项及“恢复默认”。现有 VAD 六项全部继续生效，但 UI 语义按双层模型修订：

| 现有字段 | 0.23.9 后职责 | 处理 |
|---|---|---|
| `silence_threshold` | VAD、候选静默与 RequestAudioGate 的共同能量基准 | 保留原设置 |
| `min_silence_ms` | 产生普通停顿候选的门槛，不再表示立即定稿 | 保留值，改帮助文案 |
| `min_sentence_ms` | 过滤咳嗽/瞬时噪声能否形成候选，不等于 Draft 最短上下文 | 保留值，标签改为“候选最短语音”并改帮助文案 |
| `soft_window_s` | 持续语音后开始寻找低能量候选，不再直接提交文本 | 保留值，改帮助文案 |
| `hard_window_s` | VAD 持续有声时的强制 Draft 边界 | 保留原设置 |
| `max_uncommitted_s` | 不依赖 VAD speaking 的单段/未提交兜底上限；总 backlog 另由其两倍硬限保护 | 保留值，改帮助文案 |

因此没有当前可见 VAD 配置变成静默无效项；变化的是 `min_silence_ms`、`min_sentence_ms`、`soft_window_s`、`max_uncommitted_s` 的解释必须同步更新。历史结构里已经标为 deprecated 且不在设置页展示的 `hotwords/use_itn/streaming_model/local_model_id/model_dir/streaming` 继续按既有迁移策略处理，不属于 0.23.9 新增失效。

**核心语义**：预览从"3s 滚动窗口整段替换"改为**短语定稿增量拼接**——候选停顿被复语作废时对 `[phrase_anchor, quiet_start)` 做一次短语识别（`PHRASE_MIN_VOICED_MS=500` 有声门控）冻结进短语账本，多短语增量拼接，对外仍是单个可替换 Preview 字符串（前端契约零改动）；尾部窗口锚定 `phrase_anchor`（短语内从头增长，仅单个短语超过 `preview_window` 才回退滚动）；真实切割 Draft 整段重识别替换（质量权威），提交后按 committed 清退被覆盖短语。锚点不变量 = 不低于 committed，由 `commit_or_rollback`/`consume_no_speech`/终态提交三路径统一的 `settle_preview_after_commit` 保证。

**顺带修复（0.23.10）**：入队刷新限频——尾部预览 in-flight 期间排队快照落后 ≥500ms 新音频才 replace（修复 request id 以块率烧号，实测 spawn id 1→394）；清空信封保留 request id（修复清空信封 id 倒退被消费方 request-id 墙丢弃，句尾旧虚字残留）。

**0.23.10.2（真机验证暴露缺陷的修复）**：

- **短句停顿被 VAD 静默吞掉**（首字 4～5s 的主因）：句长不足 `min_sentence_ms` 的停顿原实现无任何事件，短首句既进不了短语账本也凑不满首预览 1.2s 门槛。新增 `VadEvent::ShortPhraseEnd`（`is_boundary()=false`，不进切分/未提交上限语义，Legacy 路径忽略），引擎收到即对 `[phrase_anchor, quiet_start)` 立即短语定稿并推进锚点——不再等复语作废。
- **接受边界即清尾部导致预览回缩闪烁**（实测 21→9→0 字符回缩）：尾部清空从"边界接受"迁移到"真实提交/NoSpeech 消费推进 committed"（`settle_preview_after_commit` 以 `preview_settled_committed` 水位做边沿检测）；Draft 在途期间虚字保持显示，回滚无需恢复。
- **worker 首推理懒加载**（冷启 ~650ms vs 热态 ~300ms）：会话开始 fire-and-forget 预热（`SttEngine::warm_up`，voice.rs 在 `begin_session` 后调用；VAD 调试回放同样预热），把开销移到用户尚未说话的窗口；预热结果与引擎状态完全解耦。
- 短语定稿事件信封携带真实 `audioRange`（修复调试时间线显示 0.00s–0.00s 退化区间）。

**验证**：pseudo_streaming 105 单测（含短语累积/入队限频/清空 id 单调/短句即时定稿/尾部存活到提交）；真实 Nano 回放时间线证据：短语单调增长、range 从锚点增长、Draft 后短语清退、信封 requestId 全程单调；全量 Rust 3414 / 前端 551 通过；fmt 与编译警告清零；TEMP-PROBE 排查探针已按收尾计划全部清除。

### 5.8 0.23.99：统一资源 ref 层（📋 规划占位，不进当前实施）

**动机**：现有两套资源引用平行运作——ImageStash（`domain/capability/image_stash.rs`，内存字节、15 分钟 TTL、16 项/64 MiB、无 scope，喂 OCR/pin/图片类 Capability）与 AudioResourceRegistry（`src/app/audio_resource/`，磁盘路径句柄 + identity + scope 隔离，喂转写）。若要支持"从硬盘把图片、音频等文件读取为内存 ref，统一供各 Capability 使用"，需要先收敛这两套的模型差异。

**实施前必须定的设计决策（待定）**：

1. backing 模型：全内存化 vs "内存字节 + 路径句柄"双模。全内存受常驻 <300MB SLO 与长录音体积（16kHz 约 2MB/分钟）挤压；现有 64 MiB/15 分钟策略按图片制定，不适配音频。
2. 信任模型：audio_ref 的 scope 隔离（如 `stt_transcribe`）是否上升为 ref 的通用属性；ImageStash 当前无 scope。
3. CLI/MCP 最小运行时降级：`image_stash()` 返回 None 的投影降级路径需随抽象重新设计。

**边界**：不改 0.21 Capability 唯一原子执行语义；开工前必读 0.21 phase 与 spec-architecture。预估设计 + 实现 + OCR/pin/转写/CLI 回归为 2～4 天量级。

**触发条件与便宜替代**：出现真实功能需求时再启动。若只是"本地图片文件喂 OCR/pin"，可用 `pick_image_file` 命令 + `stash.put(文件字节)` 的约 50 行适配独立交付，不必等统一；VAD 调试播放音频走 audio_ref resolve 读字节即可，同样不依赖本项。
