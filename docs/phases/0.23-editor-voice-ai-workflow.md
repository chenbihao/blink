# Blink 0.23 — 编辑器语音与 AI 工作流（连续听写、语音浮窗与可确认改写）

> **范围**：把内容编辑器扩展为持续听写工作台；将现有 G2 `voice-overlay` 升级为可展开、可缩成 Mini 圆球、可拖动和可操作的通用语音浮窗；AI 初版只转换编辑器选区，并通过 Diff 确认后替换。
>
> **状态**：📋 规划中，主方向已定，交互细节继续讨论。
>
> **动机**：现有编辑器适合承接长文本，现有 STT 已具备伪流式 VAD、多目标交付和录音代际保护，AI Provider 也已成熟。0.23 将三者连接成“口述 → 校对 → 选区优化 → 确认替换 → 保存”的可靠内容生产链路。
>
> **前置**：0.10 语音输入、0.12 AI Provider、0.16/0.18 通用内容编辑器与 Tiptap IR、0.21 Capability/Interaction 边界、0.22 STT 本地模型运行时。
>
> **原则**：不影响 `Alt+Space → 窗口出现 → Focus → 立即输入` 主链路；录音会话不依赖编辑器窗口是否前台或最小化；浮窗始终明确展示麦克风状态；AI 不得静默覆盖原文；纯文本与 Markdown 共用统一编辑语义；前端保持无 bundler。

## 二、背景与动机

### 2.1 为什么由编辑器承接长语音

当前 G1 主窗口语音面向短查询，G2 面向外部应用光标注入，G3 面向 Chat composer。长时间口述需要稳定的可见文本面、局部修订、格式控制、未保存保护和最终落点；这些职责已经由内容编辑器承担，不应在主窗口或语音 overlay 内另建完整编辑器。

内容编辑器同时支持 `textarea` 纯文本与 Tiptap Markdown IR，但全文读取、选区提取、锚点插入、范围替换、revision 和撤销仍依赖具体编辑实现。STT 与 AI 接入前需要建立统一的 Editor Adapter，避免两条功能分别操作 DOM。

### 2.2 为什么升级现有 G2 overlay

现有 `voice-overlay` 已具备透明、置顶、不抢焦点、跳过任务栏、动态高度和 confirmed/preview 展示。新建另一套悬浮球会复制窗口生命周期、声波、状态和错误 UI。

0.23 因此复用并升级这一个 Surface：G2 只是语音目标之一，窗口产品名统一为“语音浮窗”。浮窗负责展示与控制，文字交付仍由 VoiceSession 根据 target 决定。

### 2.3 明确“不是问题的”

- G1/G2/G3 与 `Alt+Space` hold-to-talk 保留；编辑器连续听写是显式新增的 Editor target，不改变既有目标语义。
- 现有伪流式 VAD、录音 epoch、终稿幂等、本地/云端 STT 选择继续复用，不另造识别引擎。
- 编辑器仍是 Interaction，不因接入 AI 而变成持久对话窗口。
- 浮窗不是文本真源，也不是编辑器的缩小副本；它只投影 VoiceSession 状态并发出控制意图。
- Chat 的持久记忆、Agent tool loop 和 MCP 工具不进入编辑器 AI 初版。
- `clipboard_new` / `sticky_update` 保存语义不因听写或 AI 改变。

## 三、核心设计与决策

### 3.1 一个 VoiceSession，多个目标与一个通用浮窗（已定）

**定案**：VoiceService 仍是录音和 STT 会话唯一所有者；`VoiceTarget` 新增 `EditorWindow`。`voice-overlay` 从 G2 专属提示窗升级为通用语音浮窗，根据 session metadata 投影不同交互。

浮窗状态至少包含：

| 字段 | 语义 |
|---|---|
| `session_id` | 当前语音会话身份 |
| `epoch` | 拒绝旧 partial/final/end 的单调代际 |
| `target` | `foreground` / `editor`，后续可扩展 `chat` |
| `interaction_mode` | `hold` / `continuous` |
| `phase` | `listening` / `transcribing` / `paused` / `stopping` / `error` |
| `confirmed` / `preview` | 已稳定文本与临时预览 |

Editor 目标由编辑器 IPC 显式启动，不通过“哪个窗口可见”推断。G2 仍由热键路径显式选择 Foreground target。

### 3.2 编辑器窗口状态不控制录音生命周期（已定）

**定案**：编辑器连续听写开始后，浮窗持续存在；编辑器前台、失焦或最小化都不终止录音。用户只能通过编辑器控件、浮窗菜单或明确的关闭流程暂停、结束或取消 VoiceSession。

**理由**：录音不应因最小化、参考其他资料或切换应用而意外中断。持续可见的置顶浮窗负责提醒用户麦克风仍在工作。

编辑器关闭与最小化不同。录音中关闭窗口时的具体选择仍需在 0.23.0 定案，候选为：结束并保存、继续后台听写、取消听写并关闭。

### 3.3 语音浮窗双形态（已定）

**展开模式**沿用现有宽浮窗，显示声波、confirmed、preview、阶段和简短操作提示。**Mini 模式**缩为圆球，只显示声波与状态颜色。

- 双击在展开/Mini 间切换。
- 两种模式都可拖动，并限制在当前显示器工作区内。
- 始终置顶、跳过任务栏，普通交互不抢外部应用焦点。
- 编辑器连续听写首次显示默认展开，用户可缩成 Mini；选择只在当前会话内保持。
- G2 每次新会话默认定位到光标附近；Editor 连续会话使用用户拖动后的位置。
- Mini 模式不受 confirmed/preview 的自动高度调整影响。
- 首版不绑定单击动作，避免双击先触发暂停等副作用；暂停/结束走右键或展开态按钮。

### 3.4 浮窗右键菜单语义（方向已定）

右键菜单根据 session phase 和 target 投影可用项：

- 暂停听写 / 继续听写（continuous）
- 结束并保留文字
- 取消当前未确认片段
- 取消本次听写
- 打开编辑器（Editor target）
- 语音设置

“关闭语音识别”不作为一级文案，以免和设置页全局 STT 开关混淆。真正关闭全局功能仍进入设置页操作。

待定：取消整次编辑器听写时，是否自动删除本次已经插入的 confirmed 文本；当前倾向要求二次确认，并允许“仅停止、保留已写入文字”。

### 3.5 confirmed、preview 与可恢复交付分离（已定）

**定案**：confirmed/final 才能进入编辑器文档；preview 只在语音浮窗或编辑器非文档装饰层显示，不参与保存、脏检查、AI 输入和撤销历史。

后端为 Editor VoiceSession 维护有序 confirmed segment 与递增 `segment_seq`。编辑器记录最后消费的 seq；窗口被最小化、WebView 被节流或前端事件丢失后，可按 session id 拉取快照并补齐，不允许仅依赖瞬时 emit。

迟到事件需要同时通过 editor session generation、voice session id、epoch 和 segment seq 校验，避免窗口复用后把旧听写写入新 payload。

### 3.6 固定听写锚点（方向已定）

开始听写时捕获文档插入锚点，每个 confirmed segment 在该听写块末尾追加并推进锚点。用户可以编辑文档其他位置，不让语音内容跟随浏览或选区操作跳动。

待原型确认：是否提供“从当前光标继续听写”动作；当锚点所在内容被删除时，是迁移到最近合法位置，还是暂停并要求用户重新指定。

### 3.7 AI 初版只转换显式选区（已定）

**定案**：0.23 初版没有选区时禁用“AI 优化”；不处理全文，也不自动处理整次听写。请求只携带被冻结的选区内容、格式、转换模式、范围锚点和 content revision。

**理由**：选区范围明确、发送内容可见、成本可控，也显著降低误覆盖和 Markdown 全文结构损坏风险。全文/本次听写及“听写结束后自动整理”后移，不进入 0.23 验收。

### 3.8 AI 是无记忆、无工具的文本转换（已定）

编辑器 AI 复用 AI Provider、模型解析、流式输出、取消和错误协议，但使用独立的 Editor Transform 编排：

- 不写入持久 Chat memory。
- 不加载 Capability、Skill 或 MCP tool pool。
- 输入是选区文本、格式和一个明确转换指令。
- 输出是候选文本，不直接操作 DOM。
- Markdown 选区需要声明保持原有结构与代码块边界。

### 3.9 优化模式使用可扩展预设框架（方向已定）

工具栏使用分裂按钮：主按钮执行默认或上次使用的模式，下拉菜单选择其他模式。数据模型允许多个内置/用户预设，但初版一次只执行一个模式，不串行叠加多种转换。

候选模式包括润色表达、清理口语、精简内容、调整语气、整理结构、扩写内容和自定义指令。具体默认集合、命名、Prompt 与用户自定义方式留待后续专项讨论，不在本轮提前定案。

### 3.10 Diff 完成后确认替换（已定）

AI 流式生成时只展示候选结果；终稿完成后生成正式 Diff。未经用户确认，不得修改编辑器正文。

确认面至少提供：

- 替换选区
- 复制结果
- 放弃

短内容采用统一 Diff：删除内容、增加内容分别用清晰但非仅依赖颜色的样式表达。长内容是否增加左右对照视图在 0.23.0 原型中决定。中文 Diff 使用字符级计算并合并连续片段，不能依赖空格分词。

请求开始时冻结原选区、锚点和 revision。AI 返回时若文档或目标范围已变化，禁止直接替换，只允许复制结果或基于当前选区重新生成。成功替换必须成为一次编辑器事务，单次撤销即可恢复原文。

## 四、复用与范围边界

### 4.1 已有基础设施复用

| 基础 | 0.23 用途 |
|---|---|
| `VoiceService` / `VoiceTarget` | 新增 Editor target，继续作为采集、STT 与交付会话唯一所有者 |
| `voice-overlay` | 升级为通用语音浮窗，不另建 Mini WebView |
| `voice-wave.css` | 展开与 Mini 共用声波动画 |
| `StreamingSttPort` / 伪流式 VAD | 连续切句、confirmed/preview/final |
| recording epoch | 拒绝迟到 partial/final/end |
| 内容编辑器 `sessionGen` | 与 voice/AI 标识组合，隔离窗口复用竞态 |
| Tiptap IR / `textarea` | 经 Editor Adapter 投影插入、选区、替换和撤销 |
| AI Provider registry / 模型选择 | 无记忆文本转换与流式响应 |
| 编辑器脏检查和三态关闭 | STT/AI 变更统一进入未保存保护 |
| 便签自绘右键菜单 | 浮窗菜单的交互和边缘定位参考 |
| 窗口 topmost / clamp 基础 | 置顶、跨屏拖动和工作区约束 |

### 4.2 不进 0.23

| 项 | 理由 |
|---|---|
| 新建第二套 voice-mini WebView | 与现有 overlay 重复，统一升级一个语音 Surface |
| 全局永久后台监听 | 隐私、资源和误录风险高于编辑会话内连续听写 |
| AI 全文转换 | 初版先把选区范围、Diff 与冲突保护做可靠 |
| AI 自动处理整次听写 | 需在选区转换稳定后再讨论触发与覆盖语义 |
| 多模式串行 AI 流水线 | 结果和费用难预测，初版一次一个明确转换 |
| 编辑器内完整多轮 Chat | 与独立 Chat surface 职责重叠 |
| AI tool/MCP 自动调用 | 文本转换不需要外部副作用，避免扩大信任边界 |
| 新前端框架或 bundler | 违反前端工程铁则 |

## 五、子版本展开

### 5.1 0.23.0：体验与协议定案

- 完成语音浮窗展开/Mini、拖动和右键菜单原型。
- 完成编辑器听写入口、录音状态和 AI Diff 确认面的原型。
- 冻结 VoiceSession metadata、Editor segment snapshot 和 AI transform 请求/结果协议。
- 定案编辑器关闭时的录音选择、听写锚点失效策略、整次取消语义和长文本 Diff 形态。
- 定义本地/云端 STT 与 AI 外发时的可见提示和日志脱敏边界。

### 5.2 0.23.1：通用语音浮窗

- 将 `voice-overlay` 从 G2 专属投影改为读取 target、interaction mode、phase 和 session 标识。
- 支持展开/Mini 双形态、双击切换、拖动、跨屏工作区约束和会话内位置保持。
- 增加自绘右键菜单及暂停、继续、结束、取消、打开编辑器、设置动作。
- 收敛动态高度与 Mini 固定尺寸的互斥，保留 G2 光标附近定位和 `NOACTIVATE`。
- 将窗口显示/隐藏从 G2 分支中抽离为 VoiceSession Surface 策略。

### 5.3 0.23.2：编辑器连续听写

- 建立 textarea/Tiptap 共用 Editor Adapter：全文、选区、锚点插入、范围替换、revision、事务和 focus/selection 恢复。
- 新增 Editor VoiceTarget 与显式 start/pause/resume/stop/cancel commands。
- VAD 切段后持续交付 ordered confirmed segments，静音不结束 session。
- 后端维护 session snapshot；编辑器按 seq 消费并在恢复时补齐。
- preview 只进非文档展示层，不污染正文与撤销栈。
- 保存、取消、关闭和窗口复用时按最终定案可靠收口会话。

### 5.4 0.23.3：选区 AI 与 Diff

- 新增无记忆、无工具的 Editor Transform 应用编排。
- 仅当存在合法选区时启用 AI 操作，冻结选区、锚点和 content revision。
- 建立可扩展 `EditorTransformPreset` 结构与分裂按钮；首版一次执行一种模式。
- 流式展示候选文本，终稿生成中文友好的统一 Diff。
- 支持确认替换、复制和放弃；revision 冲突时禁止替换。
- 替换使用单次 textarea/Tiptap 事务，保证一次撤销恢复原文。

### 5.5 0.23.4：可靠性与体验打磨

- 覆盖麦克风失败、STT 未就绪、空识别、AI 超时、中止、窗口复用和迟到事件。
- 补齐设置入口、i18n、键盘可达性、右键菜单屏幕边缘定位与多屏 DPI。
- 验证长时间录音的内存、音频任务、segment buffer 上限与回收。
- 验证 G2 原有 hold-to-talk、焦点恢复和外部文本注入不退化。

## 六、验收

### 6.1 0.23.0

- [ ] 原型明确展示展开/Mini、录音阶段、右键操作、编辑器入口与 AI Diff。
- [ ] 编辑器关闭、锚点失效、整次取消和长 Diff 均有最终决策。
- [ ] STT/AI 外发范围和隐私提示可被用户理解。

### 6.2 0.23.1

- [ ] G2 与 Editor 共用同一个 `voice-overlay` Surface，不存在第二套 Mini WebView。
- [ ] 展开/Mini 双击切换和拖动不抢外部应用输入焦点。
- [ ] Mini 不被文本 auto-resize 撑开；展开模式仍能随文本合理增长。
- [ ] G2 新会话靠近光标，Editor 会话不覆盖用户拖动位置。
- [ ] 右键操作只作用于匹配的 active session，旧菜单动作不能终止新会话。

### 6.3 0.23.2

- [ ] 编辑器最小化、失焦和切换应用期间连续听写不中断。
- [ ] 纯文本和 Markdown 均能在固定锚点按 seq 插入多段 confirmed 文本。
- [ ] WebView 恢复后可补齐缺失片段，无重复、丢段或乱序。
- [ ] preview 不参与保存、脏检查、AI 输入和撤销历史。
- [ ] 旧 editor generation、session id、epoch 或 segment seq 的事件不能写入当前文档。
- [ ] 既有 G1/G2/G3 行为和主窗口快捷键性能不退化。

### 6.4 0.23.3

- [ ] 没有选区时 AI 优化不可执行；有选区时只发送该范围。
- [ ] Editor Transform 默认无持久记忆、无 Capability/Skill/MCP tools。
- [ ] AI 结果未经确认不修改正文。
- [ ] Diff 清楚表达中文连续增删，不只依赖红绿颜色。
- [ ] 请求期间正文或目标范围变化时拒绝静默替换。
- [ ] 替换后一次撤销可恢复原选区内容。
- [ ] Markdown 选区转换不破坏基本标题、列表、引用和代码块边界。

### 6.5 0.23.4

- [ ] 连续听写或 AI 失败不影响既有正文保存。
- [ ] 录音期间始终存在明确可见状态，结束后麦克风、浮窗和后台任务完成回收。
- [ ] 长时间会话的 segment buffer 有界且恢复协议可验证。
- [ ] 日志包含 session/epoch/seq/revision/耗时，不记录转录或编辑器正文全文。
- [ ] G2 外部注入、overlay 定位和焦点恢复通过回归。
