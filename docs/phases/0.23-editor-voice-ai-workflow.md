# Blink 0.23 — 通用文本编辑工作台（Source/MD、连续听写与可确认 AI）

> **范围**：把现有内容编辑器收敛为单窗口、单活动会话的临时文本工作台；统一 Source 原文与 Markdown 所见编辑、来源与保存目标，再接入连续听写、“整理选中内容 / 整理本次听写”和确认 Diff。
>
> **状态**：✅ 已完成——0.23.0～0.23.5 全部落地；可靠性、异常、可访问性、性能与发布回归见 §5.6 / §6.6。
>
> **动机**：当前编辑器仍由 `origin`、`format`、`save_policy` 和两套 DOM 编辑逻辑驱动。直接叠加语音、AI 与文件保存会继续放大分支和竞态；0.23 先建立一个简单、可信的编辑会话，再完成“捕获 → 整理 → 交付”闭环。
>
> **前置**：0.10 语音输入、0.12 AI Provider、0.16/0.18 内容编辑器与 Tiptap、0.21 Capability/Interaction 边界、0.22 STT 本地模型运行时。
>
> **原则**：UTF-8 文本是持久化真源；0.23 只保留一个预热编辑器窗口和一个活动 EditorSession；VoiceSession 与 AI 请求均服从现有全进程单活跃约束；AI 未经确认不改正文；所有保存目标真实可见；不影响主窗口 P0 链路；前端运行时仍无 npm/bundler，Tiptap 由 xtask 预打包。

## 二、背景与动机

### 2.1 当前问题

- 后端只有一个会被后续请求覆盖的 `PendingEditorPayload`，前端也用模块级变量保存正文、来源和保存策略。
- Plain 使用 textarea，Markdown 使用 Tiptap，两套实现没有统一的 selection、revision、事务和清理契约。
- 保存逻辑由裸字符串分支直接执行；来源、保存目标和窗口生命周期混在一起。
- VoiceService 只认识 G1/G2/G3；编辑器连续听写需要稳定目标、confirmed/preview 分离和顺序保护。
- 现有 AI 全进程单活跃，编辑器整理不能另建并发体系。

### 2.2 明确“不是问题的”

- Plain 与 Markdown 都以文本保存，不建立两套内容产品，也不把 ProseMirror JSON 变成真源。
- Source 与 MD 使用不同 Engine 是合理分工；统一的是 Adapter 和产品语言，不是底层 DOM。
- 编辑器是临时 Interaction，不建立笔记库、文档数据库、标签页或工作区。
- 0.23 只允许一个活动 EditorSession。再次打开同一来源时激活现有窗口；打开不同来源时返回 `EditorBusy` 并激活当前任务，绝不覆盖正文。
- 全进程仍只有一个 VoiceSession 和一个运行中的 AI 请求。
- Chat 的记忆、Agent tool loop 与 MCP 不进入编辑器整理。

## 三、核心设计 / 决策

### 3.1 单窗口、单活动 EditorSession（已定）

继续复用现有预热 `content-editor` 窗口，不建设动态 N+1、多窗口池或多任务管理器。窗口无活动会话时保持预热；绑定会话后是普通任务窗口，失焦不隐藏；结束会话后完整 reset 并回到预热态。

`EditorSessionRef` 是后端生成的不可猜测引用。所有 IPC 至少校验 `session_ref + generation`，命令还必须校验调用窗口就是绑定的 `content-editor`。涉及保存或正文替换时再校验相应 revision/request id。

新请求规则固定：

- 无活动会话：绑定并显示。
- 与当前持久来源相同：激活已有窗口。
- 来源不同：返回结构化 `EditorBusy`，激活已有窗口并提示先完成当前任务。
- 用户结束当前任务后可重新发起原操作；0.23 不排队、不覆盖、不自动合并。

### 3.2 状态所有权与正交状态（已定）

后端拥有 session 身份、来源、保存目标、来源 revision、便签租约、窗口绑定和异步操作 id；前端拥有当前工作文本、selection、undo/redo、Engine 状态与单调 `content_revision`。保存时前端提交完整 UTF-8 文本和 revision，后端校验后执行目标副作用。

状态不压成一个大 `phase`，而是四个正交切片：

| 切片 | 状态 |
|---|---|
| `lifecycle` | `binding / active / closing / idle` |
| `save` | `idle / running / conflict / failed` |
| `voice` | `idle / recording / paused / finalizing` |
| `transform` | `idle / running / candidate / stale / failed` |

异步结果必须携带 operation/request id；旧 generation、旧 operation 或旧 request 只能清理自身，不能修改新会话。

### 3.3 Source/MD 是同一文本的双视图（已定）

内部使用 `source / ir`，界面固定显示“原文 / MD”。Source 精确保真；MD 使用 Tiptap/ProseMirror 所见编辑。来源以 `MarkdownViewPolicy` 声明入口：

| 策略 | 行为 |
|---|---|
| `disabled` | 只显示原文 |
| `available` | 默认原文，可手动进入 MD |
| `preferred` | 通过风险门后默认 MD |

空白和便签为 `preferred`；剪贴板、选区和普通能力结果为 `available`；明确的代码/配置等结构化来源可为 `disabled`。风险门优先于来源偏好，弱内容检测只提示，不自动改变视图。

Tiptap 以仓库锁定版本和 0.23.0 corpus 结果为准，不承诺任意 Markdown 字节级无损：

- 未发生 MD 编辑时，切回 Source 必须逐字符保留原文。
- 首次 MD 编辑前保存会话级原文检查点。
- 发生 MD 编辑后只对已验证子集承诺语义正确；未知或可能丢失的结构拒绝进入可编辑 MD。
- 切换视图会取消运行中的整理请求并丢弃候选，不做跨 textarea/ProseMirror 的复杂 anchor 迁移；正文不受影响。
- Source 不受 MD/Diff/AI 阈值限制，但 0.23.0 必须给出整个编辑器可支持的文档大小 envelope，不能宣称无限文本。

首批验证子集：标题、段落、粗体、斜体、删除线、链接、有序/无序/任务列表、引用、行内代码、围栏代码块和分隔线。表格、脚注、数学、任意 HTML 与自定义语法未逐项通过前保持 Source。

### 3.4 Editor Adapter 只暴露当前 Engine 能可靠完成的语义（已定）

SourceEngine 与 MarkdownIrEngine 共同提供：文本快照、当前 selection 文本、当前 Engine 内的 opaque range handle、单事务替换、追加文末、undo/redo、focus、scroll-to-range、change/selection 订阅和 dispose。

不跨 IPC 暴露 DOM Range、ProseMirror position 或通用字符 offset；后端不按 offset 修改正文。整理请求冻结 `range_handle + selected_text_hash + content_revision`，当前 Engine 负责最终校验和替换。

### 3.5 来源与保存目标分离（已定）

`SourceDescriptor` 只描述来源；`CommitTarget` 只描述主保存去向。首版来源为 `empty / clipboard_item / sticky / selection / capability_result`，目标为 `clipboard_result / update_sticky / return_to_caller / confirmed_file`。

默认映射：剪贴板、空白、选区和不可回写能力结果 → `clipboard_result`；便签 → `update_sticky`；具有可靠 endpoint 的 Blink 调用方 → `return_to_caller`。

主保存区始终显示真实去向。“保存”和 `Ctrl+S` 保存但不关闭：

- `clipboard_result`：第一次保存创建一个会话结果历史项并写系统剪贴板；后续保存更新同一结果项，不堆积历史。内部剪贴板写入必须抑制监听器重复采集。
- `update_sticky`：带 revision 原位更新同一便签。
- `return_to_caller`：只向仍有效的 endpoint/generation 回写；失效后引导改存剪贴板或文件。
- `confirmed_file`：仅由用户完成“保存到…”后建立，后续保存校验文件 identity/mtime/hash 后原位写入。

“保存到…”成功后切换主目标；“另存为副本…”、复制、创建便签和发送到 AI 对话不改变主目标。文件写入复用唯一 Capability，采用 UTF-8、临时文件加原子替换；取消和失败均不改变正文、dirty 或主目标。

clean 关闭直接结束；dirty 关闭显示“保存并关闭 / 放弃修改 / 继续编辑”。用户主动退出 Blink 且存在 dirty 编辑会话时只显示一次汇总确认；系统关机或强制退出不阻塞。0.23 不建立磁盘恢复草稿。

### 3.6 连续听写是单 VoiceSession 的 Editor 模式（已定）

长按说话保持原有 G1/G2/G3 行为。编辑器连续听写由按钮显式开始，冻结当前 `session_ref + generation`，confirmed segment 按 `epoch + segment_seq` 追加到最新文末；首段按需补一个段落分隔。preview 只进装饰层，不进入正文、dirty、undo、保存或 AI 输入。

VoiceService 保存有界 confirmed snapshot。前端记录 `last_seq`：重复 seq 忽略，发现缺号、窗口恢复或重新聚焦时拉取 snapshot 补齐。录音失焦、最小化不中断；STT 失败或关闭目标时保留 confirmed、丢弃 preview。

结束后记录本次追加范围并显示两个显式动作：“定位到本次听写”“整理本次听写”。它们只是用户主动入口，不自动上传或改写，也不增加整次录音管理器。

### 3.7 AI 整理服从全局单活跃并只产候选（已定）

首版只有“整理选中内容”和“整理本次听写”，两者最终都提交明确的非空范围。整理只修正明显误识别、标点、分段和无意义口水词，不总结、扩写、翻译或改变立场。

- 复用全进程 AI 请求协调器；主窗口、Chat 与 Editor 同时最多一个运行中请求。
- 使用无记忆、无 Capability/Skill/MCP tool 的 `AIProvider::complete`；模型复用主窗口当前选中的 AI 模型，未配置时隐藏整理动作，不新增一套模型选择器。请求固定 `temperature=0.1`、关闭 thinking，`max_tokens` 按输入估算加小幅余量且不超过模型上限。
- system instruction 与用户文本分消息传递，不把用户正文拼进可闭合的 XML/Markdown 指令模板。
- 超过安全阈值时不截断发送；模型输出被截断或为空时不生成可应用候选。
- 终稿完整到达后一次性生成稳定 Diff，不显示跳动的增量 Diff。
- 请求冻结完整 `content_revision`。请求后正文任何变化都会把候选标为 stale，只允许复制或按最新内容重新整理；首版不做范围外编辑仍可应用的复杂映射。
- 当前视图切换、窗口关闭或新请求都会取消旧请求并丢弃候选。
- 通过 revision、range handle 和文本 hash 校验后，用 Adapter 单事务替换，一次 undo 恢复。

Diff 对中文使用字符/词组级比较；删除为浅红底加删除线，新增为浅绿底并辅以 `−/+` 等非颜色标识。无法安全保持 Markdown 块边界时只允许复制结果。

### 3.8 能力布局与隐私（已定）

界面只保留：顶部任务/来源/“原文·MD”，正文，底部当前保存目标与保存按钮，常驻连续录音按钮，以及按上下文出现的整理动作。“更多”中放保存到、另存副本、复制、创建便签和发送到 AI 对话；不可用动作隐藏。

“发送到 AI 对话”有选区时预填选区，无选区时预填全文，不自动发送、不关闭编辑器、不改变保存目标。云端 STT/AI 继续服从既有强告知门；日志只记录 session、generation、revision、epoch、seq、长度和耗时，不记录正文、转录或 AI 输入。

### 3.9 最小 IPC 契约（已定）

沿用现有命名入口并收窄为以下最小集合，避免每个子功能另造窗口控制协议：

| IPC | 用途 |
|---|---|
| `open_content_editor(request)` | 创建、激活同源会话或返回 `EditorBusy` |
| `get_content_editor_session(session_ref)` | 前端绑定时拉取只读 snapshot |
| `commit_content_editor(request)` | 按当前 CommitTarget 保存，返回新 baseline/revision |
| `end_content_editor(request)` | 保存后结束或明确放弃，并释放租约、reset 窗口 |
| `start/pause/resume/stop_editor_voice` | 控制 Editor continuous VoiceSession |
| `get_editor_voice_snapshot(epoch, after_seq)` | 缺号、恢复或重新聚焦时补 confirmed segment |
| `start/cancel_editor_transform` | 发起或取消全局单活跃整理请求 |

正文替换、selection、undo/redo 和 Diff 应用只在前端 Adapter 内发生，不增加“任意修改编辑器正文”的 Tauri command。事件统一进入 `EventNames`，至少包括 voice segment/status 和 transform completed/failed；所有事件带匹配的 session/generation 及 epoch/request id。

结构化错误至少包括：`EditorBusy`、`StaleSession`、`StaleRevision`、`SourceConflict`、`TargetUnavailable`、`VoiceBusy`、`AiAlreadyActive`、`Cancelled`、`Unsupported`、`Io`。前端按 kind 显示和决定是否可重试，不解析中文错误字符串。

### 3.10 0.23.0 定案记录（已定，证据见 testdata 报告）

以下结论由 0.23.0 的原型、语料与性能 spike 产出，进入 0.23.1 前为冻结态；改动需重跑对应 runner。

**finish_reason 投影（已定）**：rig-core 0.42 的 `CompletionResponse` 自带规范化 `FinishReason`（`Stop/Length/ToolCalls/ContentFilter/Other`），`truncated_output()` 覆盖 `Length|ContentFilter`；四种 ProviderKind 的非流式 completion 均有 wire 值映射（OpenAI `choices[].finish_reason`、Anthropic `stop_reason`、Gemini `finishReason`、Ollama `done_reason`→Stop/Length，其余归 `Other`）。落地方式：0.23.4 给自有 `CompletionResponse` 增加 `finish_reason: Option<FinishReasonKind>` 投影（类型墙，不泄漏 rig 类型）；`truncated_output()==true` 或文本为空 → 不生成可应用候选；`None/Other` 不宣称截断保护，记非敏感诊断。

**全局 AI 并发（已定）**：复用既有 `ChatService::RequestTracker` 单活跃协调器（主窗口与 Chat 已共用）；0.23.4 把 Editor transform 请求注册进同一 tracker，`ActiveChatStatus.target_window` 增加 `"editor"` 取值；`AiAlreadyActive` 携带当前活跃窗口标识。

**调用窗口校验（已定）**：全部 editor command 校验 `session_ref + generation`；`session_ref` 为后端生成的不可猜测 opaque 引用；`commit/end` 及任何触正文的 command 还须校验调用窗口 label == `content-editor` 与相应 `revision/request id`。

**剪贴板结果项（已定）**：`clipboard_result` 第一次保存创建一条会话结果历史项，后续保存更新同一项（以结果项 id 为键），不堆积历史；应用层内部剪贴板写入必须带 source 标记以抑制监听器重复采集。

**range handle（已定）**：由当前 Engine 签发的 opaque 字符串（形如 `engine-kind:anchor`），仅当前 Engine 可解析与校验；后端永不解析 handle、不按 offset 改正文；整理请求冻结 `range_handle + selected_text_hash + content_revision`，替换前由 Engine 复核三者。

**EOF 换行约定（已定）**：Tiptap `serialize()` 不输出文末换行；0.23.1 的 MD→文本保存路径在序列化后统一补一个末尾换行。round-trip"逐字节一致"按补换行后比较；纯视图切换的逐字符保真由会话级原文检查点保证，与序列化无关（原型已验证）。

**Markdown 风险门规则（已定，语料证据见 `testdata/editor/markdown/roundtrip-report.md`）**：拒绝进入可编辑 MD 的结构 = GFM 表格（整块内容丢失）、脚注（被改写为链接）、`$$` 数学块（命令被转义污染）、HTML 块/内联/注释（标签转义为字面文本）、行内代码含反引号（Tiptap 3.29.2 序列化器缺陷，二次解析不稳定）。未识别自定义语法（`:::`、`==`）字面保留，安全。规范化重写（`*`→`-`、`__`→`**`、Setext→ATX、宽松列表收敛、autolink、实体解码、`~~~`→```` ``` ````、嵌套缩进 2/3 空格）不阻断，首次 MD 编辑保存时提示"已按编辑器规范重写"。

**阈值与 envelope（已定，测量见 `testdata/editor/markdown/perf-report.md`）**：

| 门 | 冻结值 | 依据 |
|---|---|---|
| 可编辑 MD 尺寸门 | ≤32KB 正常进；32–128KB 可进但不自动、提示卡顿；>128KB 拒绝（保持 Source） | 混合文档 parse 超线性：32KB p95≈41ms、128KB≈0.5s、512KB≈7.5s |
| Diff 输入门 | ≤200KB（≈2 万 token）；D>4000 熔断 | 5% 编辑率 200KB p95≈35ms；500KB/5% 已现熔断 |
| AI 整理输入门 | `estimate_text_tokens(input) ≤ 24,000`；`max_tokens = clamp(input_est+2048, 1024, context−input_est−margin)` | tiered fallback 最小窗 32K 推导（perf 报告 §三） |
| Source envelope | 2,000,000 字符硬上限，超限拒绝载入 | 字符串操作 p95=0.2ms@2MB；textarea 体验由 0.23.5 真窗复测 |

风险门（内容结构）优先于尺寸门，尺寸门优先于 `MarkdownViewPolicy` 来源偏好；Source 不受任何增强门限制，始终可编辑保存。

## 四、复用与范围边界

### 4.1 复用盘点

| 现有基础 | 0.23 用途 |
|---|---|
| 静态预热 `content-editor` | 保留单窗口，增加 session bind/reset |
| `EditableContentPayload` / pending pull | 迁移为结构化 session snapshot，完成后删除单槽 |
| Tiptap 3 + `@tiptap/markdown` | 共享 MarkdownIrEngine、corpus 与风险门 |
| textarea | SourceEngine |
| Sticky revision | `update_sticky` 冲突防线和编辑租约 |
| CapabilityRegistry / SurfacePort | 打开编辑器和原子输出动作唯一入口 |
| VoiceService / voice-overlay | Editor target、连续听写和通用浮窗 |
| AI Provider / 全局请求协调 | 无记忆整理和跨窗口单活跃 |
| 自绘确认卡片 | 保存冲突与 Diff 面板 |

### 4.2 不进 0.23

| 项 | 理由 |
|---|---|
| 多 EditorSession、动态 N+1 编辑器窗口池 | 不是连续听写与整理闭环的必要条件，显著增加窗口和竞态复杂度 |
| 文档数据库、笔记库、标签页、工作区、崩溃恢复中心 | 编辑器仍是临时任务 Interaction |
| 任意 Markdown 字节级无损 IR | Source 是保真出口 |
