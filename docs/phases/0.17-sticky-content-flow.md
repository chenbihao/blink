# Blink 0.17 — 内容流转与桌面便签（Content Flow & Persistent Sticky Notes）

> **范围**：让主窗口文本、文本型 item、剪贴板和编辑器内容进入通用编辑工作台或直接生成桌面便签；实现便签内容、位置、尺寸、颜色和显隐状态持久化，提供便签管理界面以及崩溃/重启恢复。
>
> **状态**：📋 规划中。
>
> **动机**：0.16 建立通用内容编辑器与共享 Markdown renderer 后，Blink 可以把“刚刚出现的内容”直接转为可编辑、可常驻桌面的便签。差异化不在复刻 Windows 便签，而在省去新建、复制、切应用、粘贴的中间步骤。
>
> **前置**：依赖 0.16.1 item actions 数组、0.16.2 共享 Markdown renderer、0.16.3 通用内容编辑器；复用 0.15 多窗口/pin 相关基础设施，但文本便签与图片 pin 是不同实体。
>
> **原则**：便签本身就是明确持久化的用户数据；关闭只隐藏、删除才移除；内容与窗口状态都可恢复；共享内容核心但不强行共享窗口外壳；不引入笔记库、Todo、文件夹、标签或同步；便签恢复不得阻塞主窗口 P0 唤起链路。

---

## 一、背景与动机

### 1.1 为什么 0.17 做桌面便签

单独做一个 Windows 便签替代品，操作路径和产品边界都缺乏优势。0.16 通用编辑器落地后，Blink 已经握有其它便签应用没有的入口：主窗口 query、搜索 item、剪贴板、选中文本以及后续 AI 文本结果。

0.17 要建立的是内容流转闭环：

```text
主窗口 query / 文本型 item / 剪贴板 / Awareness 选区
  → chord-E 或“编辑”action → 通用编辑器
  → chord-S 或“钉为便签”action → 持久化桌面便签
  → 便签“深度编辑” → 通用编辑器
  → 便签管理 → 显示 / 隐藏 / 编辑 / 删除
```

用户明确创建或钉住便签后，Blink 必须记住内容和桌面状态。应用正常退出、Windows 重启或 Blink 异常崩溃后，已显示的便签应恢复，隐藏的便签应继续留在管理界面中。

### 1.2 明确不是问题的

| 项 | 澄清 |
|---|---|
| 是否需要通用笔记模型 | 当前不需要；0.17 只建立 `StickyNote` 实体，不提前设计 Notes/Todo |
| 是否复用 0.15 图片 pin 数据 | 不直接复用实体；图片 pin 与文本便签生命周期、编辑和持久化语义不同，只复用窗口/平台基础设施 |
| 是否共用编辑器与便签整套样式 | 不共用外壳；共用 Markdown renderer、编辑基础组件和主题 token |
| 关闭按钮是否删除内容 | 不是；关闭等于隐藏并持久化 `visible=false`，永久删除必须在明确确认后执行 |
| 应用退出是否等于隐藏全部 | 不是；退出不修改用户设定的 visible 状态，下一次启动据此恢复 |
| 是否要完全复刻 Windows 便签 | 不需要；借鉴成熟的颜色、列表管理和直接编辑形态，但入口与内容流转保持 Blink 特性 |

## 二、核心设计 / 决策

### 2.1 `StickyNote` 是独立持久化实体（已定）

**定案**：0.17 不建立 `ContentDocument`/笔记库抽象，便签直接以 `StickyNote` 持久化。建议字段：

```text
StickyNote
- id
- content
- format: plain | markdown
- color
- visible
- x / y / width / height
- always_on_top
- created_at / updated_at
```

便签数据写入 `blink_history.db` 的独立表，与启动历史、剪贴板历史分表管理；“清除历史”不得删除便签，只有便签删除和卸载全量清理可以移除。这样不增加第五个数据库，也不会把用户内容当 cache。

**理由**：当前明确不做笔记，先抽象通用文档会引入尚无消费者的类型和迁移负担。未来若笔记立项，再评估将 `StickyNote.content` 迁为通用内容实体，而不是现在预埋。

### 2.2 内容和窗口状态都必须自动保存（已定）

**定案**：内容输入短防抖自动写库；颜色、显隐、置顶、位置和尺寸在变化后防抖写库；失焦、隐藏和窗口关闭前强制 flush。SQLite 使用事务更新，启动时只读取最后一次完整提交。

**理由**：便签的核心承诺是“放在那里就不会丢”。只在用户点保存或应用退出时写入，无法覆盖崩溃和系统强制结束。

恢复策略：

- 正常启动后异步读取所有便签；
- `visible=true` 的便签恢复窗口，`visible=false` 只进入管理界面；
- 恢复在主窗口服务 ready 后走旁路，不阻塞 Alt+Space；
- 显示器减少、分辨率或缩放变化时，将越界窗口钳制到最近可见工作区；
- 单条便签恢复失败只记录并跳过，不阻断其它便签和主窗口。

### 2.3 关闭、隐藏、退出、删除四种语义分离（已定）

**定案**：

| 操作 | 内容是否保留 | visible | 下次启动 |
|---|---:|---:|---|
| 便签关闭按钮 | 保留 | false | 不自动显示，可从管理界面恢复 |
| 管理界面“隐藏” | 保留 | false | 不自动显示 |
| 应用退出/系统重启 | 保留 | 不改变 | 原本显示的继续恢复 |
| 管理界面“删除” | 永久删除 | — | 不恢复，必须确认 |

窗口 close event 需要区分“用户关闭便签”和“应用整体退出”。整体退出只 flush，不批量把 visible 改成 false。

### 2.4 颜色采用有限成熟色板（已定）

**定案**：首版提供有限语义色板，例如黄、粉、紫、蓝、绿、灰；默认黄色。颜色改变立即应用并持久化，前景色和控件对比度由 token 配对，不能让用户输入任意色值。

**理由**：Windows 便签的有限色板已经验证了选择效率；任意取色会扩大可读性、暗色主题和状态图标对比度问题。未来有真实需求再扩展自定义颜色。

颜色属于单条便签，不随全局主题覆盖；全局深浅主题只影响控件、阴影和 Markdown 代码块等辅助层。

### 2.5 便签可直接编辑，也可进入工作台（已定）

**定案**：便签窗口支持直接编辑并自动保存，同时提供“在编辑器中打开”动作。便签只保留最小控件：拖动、颜色、更多菜单、关闭；Markdown 预览、复杂选择和未来格式化能力留在通用编辑器。

编辑器以 `origin=sticky`、`origin_ref=sticky_id` 打开；保存回写同一便签，不复制出新实体。编辑器“钉住”则从当前内容创建新便签，除非当前 session 已绑定某个 sticky id。

### 2.6 chord 分为空闲入口与上下文动作（已定）

**定案**：不移除现有 chord 总门禁，而是增加 action availability：

```text
Idle       query 为空且无用户结果时可用
Contextual 当前 query 或 active item 能提供所需内容时可用
```

- `Alt+E`：编辑当前内容；无上下文时打开空白编辑器。
- `Alt+S`：将当前内容创建为便签（Sticky）；无上下文时创建空白便签。
- 便签管理不占新 chord，通过主窗口内置 action“便签管理”和托盘入口打开。

上下文解析顺序：

1. 当前 active item 明确声明的 edit/pin action；
2. 非空 query；
3. 空闲态下仍有效的 Awareness 选中文本；
4. 无内容时为空白编辑器/空白便签。

状态栏必须显示动作目标摘要，避免 query 与 active item 同时存在时目标不透明。只有明确提供文本 payload 的 item 才能出现 edit/pin，不能把任意文件名或展示 label 当正文。

### 2.7 便签管理是唯一集中管理入口（已定）

**定案**：提供独立便签管理窗口，至少展示内容摘要、颜色、显隐状态和更新时间，并支持：

- 创建空白便签；
- 显示/聚焦已显示便签；
- 恢复隐藏便签；
- 隐藏便签；
- 在通用编辑器中打开；
- 修改颜色；
- 删除（确认后永久移除）。

管理界面不是笔记库：不做文件夹、标签、全文知识管理、Todo 聚合或同步。

## 三、里程碑

### 3.1 0.17 版本里程碑

| 版本 | 内容 | 优先级 | 依赖 |
|---|---|---|---|
| **0.17.0** | `StickyNote` 数据模型、CRUD、自动保存与恢复服务 | P0 | 0.16 基础完成 |
| **0.17.1** | 桌面便签窗口 V1：直接编辑、颜色、关闭隐藏、位置尺寸持久化 | P0 | 0.17.0 |
| **0.17.2** | 内容流转：chord-E/chord-S、query/item/选区→编辑器/便签、便签↔编辑器 | P0 | 0.16.1-0.16.3、0.17.1 |
| **0.17.3** | 便签管理界面：显示/隐藏/聚焦/编辑/改色/删除 | P0 | 0.17.1 |
| **0.17.4** | 崩溃恢复、多显示器与生命周期可靠性收尾 | P1 | 0.17.1-0.17.3 |

**依赖关系**：数据持久化先于窗口；内容流转与管理界面可在便签窗口完成后并行；最后统一验证崩溃、重启、多显示器和 P0 主链路。

### 3.2 已有基础设施复用盘点

| 基础设施 | 复用方式 |
|---|---|
| 0.16 `EditableContent` | sticky 作为新的 origin/save policy 接入通用编辑器 |
| 0.16 shared Markdown renderer | 便签阅读态与编辑器预览共用渲染核心 |
| 0.16 `AppEntry.actions` | 文本型 item 声明 edit/pin actions，前端无需按 source 分支 |
| 0.15 pin/overlay 窗口经验 | 复用置顶、拖动、显示器钳制和窗口生命周期做法 |
| SQLite data 层 | 在 `blink_history.db` 新增独立 sticky 表和 repository |
| ChordRegistry / statusbar | 增加 E/S action 与 contextual availability，保持提示和触发同源 |

### 3.3 不进 0.17 的项

| 项 | 理由 |
|---|---|
| 笔记库 / Note 实体 | 当前明确不考虑；便签用独立实体闭环 |
| Todo / Markdown 任务聚合 | 不提前进入任务管理产品边界 |
| 文件夹、标签、双链、全文知识库 | 属笔记产品，不是便签管理 |
| WebDAV/云同步 | 多设备与冲突解决是独立 phase；0.17 只保证本机持久化 |
| 多人协作/分享 | 超出本地桌面工具范围 |
| 任意自定义颜色/背景图 | 首版有限色板优先保证可读性 |
| 富文本/WYSIWYG | 继续使用纯文本 + Markdown，不引入新编辑器依赖 |
| 代码格式化、Diff、AI 加工 | 属通用编辑工作台后续扩展，不阻塞便签闭环 |
| QuickLook 式文件预览 | 与内容流转正交且体积/边界风险高，继续留作远期候选 |

## 四、子版本展开

### 4.1 0.17.0 Sticky 数据与恢复服务

- 在 `blink_history.db` 新增 sticky 表与迁移；
- repository 提供 create/get/list/update_content/update_appearance/update_geometry/set_visible/delete；
- 内容与窗口状态更新使用事务和短防抖；
- 事件/command 只传 sticky id 与必要字段，不在日志记录正文；
- 启动恢复服务异步加载，单条失败隔离；
- 清历史、清剪贴板不得误删 sticky 表。

### 4.2 0.17.1 桌面便签窗口 V1

- 动态窗口 label 使用稳定 sticky id；
- 直接编辑，输入自动保存；
- 支持拖动、缩放、置顶和有限色板；
- 移动/缩放/改色后持久化；
- 关闭按钮隐藏而非删除；
- 更多菜单提供“在编辑器中打开”“隐藏”“删除”；
- 视觉参考成熟便签形态，但使用 Blink token、图标包和中文不斜体铁则。

### 4.3 0.17.2 内容流转与 chord

- Chord action 增加 idle/contextual availability；
- `Alt+E` 打开通用编辑器；
- `Alt+S` 从当前 payload 创建并显示便签；
- 主窗口 query 可编辑/钉住；
- 只有具有文本 payload/actions 的 item 可编辑/钉住；
- Awareness 选区只在用户显式按 E/S 后进入编辑器或持久化便签；
- sticky→editor 保存回同一实体；editor→sticky 创建或聚焦绑定实体；
- statusbar 显示目标摘要，Chord 提示与触发资格同源。

### 4.4 0.17.3 便签管理界面

- 独立管理窗口，通过主窗口 builtin action 和托盘菜单进入；
- 列表按最近更新时间排序，显示颜色、摘要、可见状态；
- 已显示便签可聚焦，隐藏便签可恢复；
- 支持隐藏、编辑、改色和删除；
- 删除二次确认，关闭管理窗口不影响桌面便签；
- 空状态提供“新建便签”，不出现笔记/文件夹等超范围入口。

### 4.5 0.17.4 可靠性收尾

- 正常退出、任务管理器结束、模拟崩溃、Windows 重启后验证恢复；
- 区分用户关闭便签与应用整体退出；
- 显示器拔插、分辨率/DPI 改变后保证窗口至少部分可见；
- 大量便签恢复做并发/节流，不能抢占主窗口焦点；
- 对损坏记录、重复窗口 label、创建失败做隔离和日志；
- 确认恢复流程不进入主窗口热键和首结果热路径。
