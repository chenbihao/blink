## 二、背景与动机

单 bin crate 增量验证约 36.8s，拆分使热点域能独立编译测试；其余子版本各自解决一个体验断层：快捷键占用无恢复入口、复用窗口配置陈旧、长译文溢出、应用搜索来源不一致、更新只能外链手动下载、翻译失败日志全在 debug 级排障无门、预选框内部被暗罩盖住、CM 命名混乱与插件密钥明文落库、AI 代码块暗色穿帮、MD 视图丢内容、更新日志只见最新一条、脚本解释器探测体系零消费者。

**架构澄清（"不是问题的"）**：builtins 与多个域相互依赖，留在同一 domain crate 是本版的有意取舍；"常用系统入口"是维护的功能目录，基础应用扫描仍来自开始菜单；配置开启与全局快捷键注册成功分别展示，不能用 checkbox 推断系统注册状态。

## 三、核心决策与维护要点

### 3.1 粗拆 domain，协议错误先独立

拆分顺序为 infra → capability-error/config/local-engine → stt → domain。Capability 协议主体和 builtins 消费多个域服务，随 domain 整体迁入，避免强拆循环依赖。bin 的 `src/{infra,domain}/mod.rs` 保留 re-export shim，旧 `crate::infra::*` / `crate::domain::*` 引用无需改写。

**跨 crate 测试隔离教训**：依赖 crate 不以 `cfg(test)` 编译，原有缓存和引擎目录隔离因此失效——`blink_infra::runtime_mode` 默认隔离缓存与数据目录，生产入口显式 `activate_production()`。STT 配置迁移只接收 provider 的 id/kind/base_url 投影，避免 config crate 依赖完整 AI 配置类型。

### 3.2 后端确认值驱动回填，字段 CAS 保护写入

两窗口先订阅 `CONFIG_CHANGED` 再首读，事件和 focus 共用单飞刷新入口；通知是失效信号，只有最新有效读取才能提交共享状态和 DOM。保存、录制及输入草稿暂停回填，结束后补读。共享分片从最新值合并目标字段、保留未知字段、拒绝损坏配置回写；过期修改返回 `config_conflict`，全量迁移/重置走数据库事务。自启动 release 下依次查询→注册→核验→保存→广播，失败补偿恢复系统原状态（补偿失败明确报 `autostart_restore_failed`）；debug 仅保存偏好。系统注册与数据库没有共同事务。

### 3.3 系统入口按稳定身份合并，启动目标必须明确

常用与发现目录共用稳定 entry_id、独立 history key、别名/拼音匹配和带类型的启动目标；同目标但语义不同的入口保持独立。自动发现读取本机 Windows 设置 XML 的可靠子集（该目录不是稳定公开协议）；DeepLink 经白名单校验，PageID 仅是父级定位不能据此猜子设置 URI；缺目标/未知条件/歧义项跳过。`open_system_entry` 只接受 entry_id，执行时核验当前来源状态；主窗口和 `search_apps` 共用目录分别投影为 RunAction 和 Invoke；AI/MCP 默认授权关闭。

### 3.4 一键更新选官方 updater 插件，签名与镜像链路自建衔接（0.25.10，已定）

**定案**：集成 `tauri-plugin-updater` 2.12（2.13 起要求 tauri ^2.12，与 2.11.5 冲突故锁版本）；`bundle.createUpdaterArtifacts` 开启，build 自动产 minisign `.sig`。公钥嵌 `tauri.conf.json`；私钥真源为 CI secret 与本地 `~/.tauri/blink-updater.key`（均不入 Git）——**私钥丢失则存量用户无法验签升级，必须长期备份**。更新源 `releases/latest/download/latest.json` 由 `cargo xtask release` 生成，**draft 不计入 latest，publish 后才对用户生效**；安装包 URL 固定主站直链，代理场景由 `github_proxy_candidates` 候选链 + 全局代理覆盖（签名只校验文件字节，走代理不放宽供应链约束）。前端不直调插件 API；`install_update` 后台任务执行、进度走 `UPDATE_INSTALL_PROGRESS` 事件（≥200ms 节流），互斥单飞防重复——**检查期所有 `?` 早退路径必须由调用方复位标志**，否则卡死无法重试。debug 构建直接拒绝安装。

### 3.5 浅色主题专项：token 化优先，原色只做亮度缩放（0.25.11，已定）

1. **`--yellow` 升级为正式主题 token**（dark `#e5c07b` / light `#976014`）——主窗错误项此前恒用 Mocha 黄 fallback，浅色底 1.53:1 几乎隐形。
2. **未定义颜色引用一律收敛到语义 token，不留颜色常量 fallback**（约 20 处）；dark 渲染不变（fallback 恰是当前生效值）。两处有意偏离"dark 不变"：popup 折叠头 hover 与滚动条 hover 改为获得真实 hover 增量。
3. **Latte 状态色只向黑色方向缩放、保留色相**，不搞"文字专用第二套状态色"（token 翻倍、组件无所适从）。
4. **截图 overlay 与钉图窗口保持暗色自持 palette**，作为 spec-frontend"色彩绝不 hardcode"的明示豁免——固定深色保证任意底材可读。
5. **新增 theme-debug.html 主题调试页**：聚合全部语义 token 与组件样本并实时算 WCAG 对比度；**验证主题只开这一页**，替代逐窗口截图老验法。设置页「调试」Tab 入口（single-flight 建窗 + close=hide 复用，不预热不常驻）。

### 3.6 程序化写入主窗口输入框后必须显式滚动跟随（0.25.12，已定）

> 通用铁则已迁 [spec-frontend §5.8](../specs/spec-frontend.md)（Chromium 硬约束：裸 `value=` 重置 `scrollLeft`、程序化 `setSelectionRange` 不触发滚动跟随）。

**定案**：`#query` 所有程序化整串写入路径（voice 终稿、confirmed-only 回填、baseQuery 恢复、右键粘贴）统一补"设光标到末尾 + `ghost.scrollWithMargin()`"，复用 0.10.6 既有函数，不动 partial 的 rAF 跟随链路。**录音中避让语音指示器**：`body.voice-active` 下给 `#query`/`#ghost-overlay` 同步加 padding-right 避让带（宽度按指示器 `offsetWidth + 8px` 实测写 `--voice-avoid-w`），input 滚动区计入右 padding，`maxScroll` 自然落在指示器左侧、滚动逻辑零改动；灰字 preview 另加 `clip-path: inset()` 把裁切沿收到避让带内沿（单行空间不足时预览让位）。避让用 padding 而非 width 收窄：与"overlay 镜像 #query 的 padding"既有约定同属性同步。

### 3.7 翻译插件错误必带根因、降级必须用户显式开启（0.25.13，已定）

**定案**：

1. **错误必带根因**：插件记录非 200 响应体（300 字符）并解析供应商错误 JSON，最终错误形如「翻译失败（ali: InvalidAccessKeyId.NotFound: …）」；主引擎未配置也记明「未配置 API 密钥」。
2. **插件 stderr 分级约定**：行内含 `[error]`/`[warn]`/`[info]` 方括号标记时 core 按标记级别转发，无标记保持 debug（约定正文见 protocol.rs）；SLO 失败埋点与「插件返回错误信息」提级 warn。
3. **密钥空格检测不自动改写输入**：manifest `no_space: true` 声明，设置页红字提示 + 「移除空格」按钮（点击才清除）；插件侧读取凭据统一 `cred()` trim 兜底存量。自动 trim 曾实现后按用户要求撤回——密钥是否含空格由用户确认。
4. **降级默认关闭（行为变更）**：manifest `allow_fallback`（默认 false）门控 `try_next_fallback`，主引擎失败直接报错不静默换引擎；「降级顺序」用 `visible_when` 条件显隐（schema 通用机制）。
5. **引擎元数据走 desc 通道**：`RawToolResult.desc`（实际引擎，降级时带「已降级」前缀）注入 `CapabilityResult.desc`——**不进 data**，AI 出口拿完整 data，塞进 data 的元数据会污染模型可见的译文。
6. **批量翻译全失败必须报错**：`translate_lines` 返回 `{lines, engine, failed, error}`，全失败返回 Err，不再拿原文冒充译文；部分失败 Ok + failed 计数。

### 3.8 预选挖洞遮罩独立四块 DOM、就绪前拖选只缓存起点（0.25.14，已定）

遮罩本有三套实现（预选态整屏 canvas 暗罩 / 拖动态 DOM 挖洞 / 确定态 canvas 挖洞）；「等遮罩下来才能拖」的根因是 pointer handler 开头的 `!ss.screenshot → return` 丢弃按下事件。

**定案**：

1. **预选挖洞用独立四块遮罩 DOM，挂 ss-preselection-hint 生命周期**：三个预选来源本就全部汇过 show/hide/reset 三函数，遮罩驱动内嵌其中、调用方零改动。几何写入复用 `writeGeometry` 的整数格点纪律（混合 DPI 下独立取整产生 1px 亮缝，0.23.15 已踩过）。**消隐不调 drawDimmed**——hide 的调用路径都会跟进 canvas 提交，`drawDimmed`/`drawFinalSelection` 开头强制隐藏本遮罩（与 `hideLiveSelection` 同构），双暗与漏恢复由此封死。
2. **开关 `preselection_cutout` 默认开**（serde `default_true` 零迁移），前端消费 `!== false` 语义；开关同时是特殊 DPI/驱动环境的降级逃生门。
3. **就绪前拖选只缓存起点**：pointerdown 在 `!ss.screenshot` 时记 `{startX, startY, pointerId}` 并 capture（不丢弃），ready 前 move 以当前指针位置直接刷新拖选预览（live-selection 不依赖底图，黑罩期即有蓝框反馈），ready 后首个仍按住的 move 衔接为正常 isDragging；ready 前松手视为放弃。可拖时刻从「截图 ready」提前到「P5 暗罩可见」。
4. **懒加载屏局部重绘**：每块屏就绪后按显示器矩形 `redrawBaseRegion` 只刷主 canvas 底图区，替代全屏 drawDimmed；以 `ss._dimmedReady` 为前提——P5 纯黑期不擦（否则黑罩上出无暗罩亮斑）。
5. **桌面回退预选与窗口挖洞共用同一开关**；canvas-backed 来源（图片编辑）不激活挖洞。

**实机修订（0.25.14-fix，保留的教训）**：

- 窗口列表异步加载完成前，「列表未就绪」会被误判为「鼠标在桌面」——用 `windowsLoaded` 门控（失败也置位，预选降级桌面回退不僵死）。
- **`canvas.width` 同值赋值也会清空画布（HTML 规范）**——同值必须跳过；BitBlt 抓帧与 DWM 合成真桌面存在色彩档差（夜灯/HDR 下偏暗），属采集管线特性，本版不处理。
- 唤起后鼠标不动则补预选无位置——`show_screenshot_overlay` 注入 show 时刻真实光标（取不到注入 `null` 哨兵），列表就绪即补选。
- 挖洞遮罩的 0.13s 几何 transition 只适用于预选这类低频离散跳变（首次激活禁 transition + 强制 reflow 锁首帧，hide 延迟到边框淡出确认）；拖动逐帧写入仍守「几何禁止过渡」铁则，两者不冲突。

**不做（推迟）**：确定态遮罩 DOM 化与 `#interaction-canvas` 整体退役（0.23.15 刚完成拖动路径迁移）；唤起前段微优化等 0.19.14 打桩日志实测数据。

### 3.9 CM 命名 v2：keyring target modifier 显式指定完整 target（0.25.15，已定）

**定案**：

1. **命名 `blink:{module}:{subject}:{purpose}`**（如 `blink:ai:{uuid}:key` / `blink:stt:cloud:key`），应用前缀置首。用 `keyring_core::Entry::new_with_modifiers` 的 `target` modifier 显式指定完整 target（windows-native store 此时忽略 service/user 拼接）；不用自建 store 的 prefix/divider 配置（仍受 `{user}{div}{service}` 段序约束）。
2. **`SecretRef{module,subject,purpose}` 显式命名空间**取代裸 `(provider_id, purpose)` 签名，模块归属（Ai/Stt/Plugin）在类型层钉死；`from_legacy_pid` 承接历史 pid（`stt:cloud`→Stt，其余→Ai，含 0.14.6–0.17.11 的 slug id）。
3. **迁移读写必须与写入路径对称**：v1 条目 CredentialBlob 是 UTF-16LE，复用 v0 的 UTF-8 raw 读取器会把密钥读成 `s\0k\0…` 乱码静默写入新命名——v1 读写删必须走无 modifier 的 keyring Entry（与 v1 写入同路径），v0 迁移继续用 raw。**教训：跨代迁移先确认 blob 编码，不能复用上一代的读取器。**
4. **单测 store 自写**：keyring 自带 mock 拒绝一切 modifier，按 `CredentialApi`/`CredentialStoreApi` 自写按 target name 键存的内存实现；单测绝不碰真实 CM。
5. **枚举不依赖 CredEnumerateW 通配语法（0.25.16-fix 修订）**：该 API 的通配是不文档化子集——`*blink*` 直接 ERROR_NOT_FOUND 被当空列表（首版因此静默空跑、密钥全部"未配置"），`blink*`/`*.blink` 却可用。修订为 filter=NULL 全量枚举 + Rust 端 `contains("blink")` 过滤（`enumerate_blink_secrets_anywhere`），迁移去 marker 改每启动自愈扫描（无残留即 no-op，顺带覆盖双版本并行/备份恢复）。**教训：Win32 通配符语法能不用就不用；ERROR_NOT_FOUND ≠ 过滤器非法。**

### 3.10 插件密钥字段：声明式标记 + 宿主统一拦截（0.25.16，已定）

**定案**：manifest `"secret": true`（0.7 起就写在翻译插件里，本版激活解析）→ 宿主在唯一写入咽喉 `update_config` 自动转存 CM（`blink:plugin:{plugin_id}:{field_key}`），SQLite settings 只留空串占位；插件进程注入前由 `resolved_settings` 从 CM 还原明文（插件二进制与协议零改动）；存量明文启动期一次性搬迁（幂等由构造保证）。`get_settings` 保持脱敏版供前端/AI 路径。理由：写入路径自 0.17.8 起收敛在单一分支，拦截点唯一可靠；密钥只在「前端输入→invoke→写 CM」与「CM 读出→子进程 stdin」两个既有窗口存在明文，与 AI 密钥链路安全模型一致。

**已知取舍**：CM 写失败仅 warn 仍脱敏（宁丢配置不落明文，用户重存即可）；降级到 0.25.15 及之前版本时插件密钥表现为「未配置」（本体仍在 CM 不丢失）。**热路径取舍**：`resolved_settings` 每次查询逐字段读 CM（≈1-2ms，debounce + 网络瓶颈掩盖）不做缓存——失效面复杂度不值，实测有感知再优化。

### 3.11 编辑器 MD：内容保全优先于字节保真（0.25.18，已定）

用户实测三轮驱动的同一根问题：MD 视图编辑后 `takeSourcePatch` 整篇复核失败，旧响应是「回滚用户输入 + 永久只读」，从格式误判一路升级为真实丢内容。三层根治：

1. **口径层**：`jsonEqual` 忽略 undefined 值 key、`normalizeNodeJson` 统一空 `content` key 口径——@tiptap/markdown 解析产物与 `toJSON()` 快照键数不等导致「任何含代码块文档载入即锁只读」类问题由此封死；单节点序列化不剃尾随空白（parser 逐字保留，剃除使「abc 」物化成「abc」，复核必败）。
2. **规划器层**：`planSourcePatch` 从按编辑形态分 6 个特例分支重构为**区间统一重建**——以内容块为锚点定替换区间 `[前一内容块 contentEnd, 后一内容块 contentStart)`，区间内空段落按唯一公式重发文本（块间 E 空段 ↔ `2(E+1)` 换行、文档首/尾 ↔ `2E`、尾部保留 EOF 换行奇偶性），空段增删与块插删改全落同一公式。
3. **安全模型层**：探测证实存在序列化器级不可往返形态（纯空白文本段、代码块内容含围栏字符、空引用段），信息在序列化层即被破坏，规划器无法拯救，回滚是错误响应。定案**内容保全优先于字节保真**：tier1 最小块级 patch（默认，逐字节无损）→ tier2 序列化兜底（复核失败时 canonical 前进到整篇序列化结果，内容完整、格式可能规范化，保持可编辑，`editor.md.normalized` 提示）→ 仅序列化器抛错才回滚 + 只读（最后防线）。**未编辑区间逐字节保留从绝对不变量降级为默认路径不变量**，规范化必须可见；`readOnly` 退化为载入对齐失败/序列化异常的罕见终点。

**为何自研（生态调研定案）**：现成方案（Tiptap 官方 `@tiptap/markdown` 与社区包）只提供 parse/serialize 双向转换，按 CommonMark 规范化重写全文；字节保真只有「源码为唯一真相」（Vditor-SV/ByteMD）或「保留原文 + 位置映射增量写回」（Marklive/Baram）两条路且均无开源库——blink 正是后者。已知真不可表达形态（走 tier2 兜底而非锁死）：纯空白文本段、同标记列表间空段落（CommonMark lazy continuation）。

**ACL 放行教训**已迁 [spec-architecture §A7.4](../specs/spec-architecture.md)（0.25.18 放行 `core:window:allow-show` 后，页面残留的废弃 `win.show()` 从「被 ACL 拒绝恰好无害」变为每次启动弹窗，两处残留已清理）。另：MD 长文档滚动（`.ProseMirror` 从 `min-height:100%` 改内部滚动，与便签同模式）；只读徽章绝对定位悬浮不推移工具行。

### 3.12 脚本解释器：托管制品而非系统资源（0.25.20，已定）

**定案**：0.6 的「探测系统 python/node + 设置页手动配路径」体系自建成起零消费者（builtin 插件全为 Rust exe；FunASR/OCR 的 Python 栈已在 0.22 原生化删除），替换为**托管分发**：解释器是 Blink 下载的版本化制品——`asset-lock.json` `include_str!` 编译期锁 Python 3.12.10 embeddable / Node 22.11.0 win-x64 的 URL/SHA-256/size/exe 路径；安装事务 single-flight → staging 下载（华为云镜像逐个降级，换源不放宽供应链）→ zip 级 SHA-256 → zip slip 防护解压（绝对路径/盘符/`..` 段 fail-closed）→ self-test → 原子 promote，残留由启动清扫回收（sweep 跳过并发活跃安装的 staging）。**未安装不回退系统 PATH**——版本不可控破坏托管语义，缺失走 0.6 四层兜底转「请在 设置 → 引擎 → 脚本运行时 安装」错误项。不进 EngineManager 引擎注册表（无模型契约与服务生命周期，只是插件系统共享运行时制品）。安装入口三层全部显式（设置页手动 / 启用插件确认后深链 / 兜底错误项指路），无静默下载。

**边界与取舍**：Python embeddable 无 pip，脚本插件边界定为「标准库 + 插件目录自带文件」，不做 npm/venv 依赖管理（0.22 已清过 uv 重栈，不回头）；下载循环与 `local_engine/providers/onnx.rs` 的 `download_and_verify` 受控重复，第三处使用时统一收敛。`RuntimeType` 四变体与 manifest 格式不变，0.6 脚本插件向前兼容。

**跨链路教训（迟到占位丢弃）**：Tauri invoke 返回与事件推送到达顺序不保证——通用铁则已迁 [spec-frontend §5.1](../specs/spec-frontend.md)。本版场景：插件查询足够快时结果事件先于 sync 占位批到达，占位成为同 seq 无人清理的增量（结果与转圈同屏；builtin 网络插件耗时大必先回 invoke，踩不到此窗口）；修复为前端 merge 对「已有同 source 真结果的 seq」追加占位前丢弃。

### 3.13 剪贴板治理：真实粘贴与可信定位（0.25.21–0.25.25，已定）

用户实测暴露三类问题：UIA 无法可靠识别 Typora/Java IDE 输入框，逐字符注入使换行变为按键并与 IME 竞争，整页编辑器矩形被误当光标行导致贴顶。最终策略：

1. **诊断（0.25.21）**：show 前捕获焦点观测，保留进程内快照与 `debug_uia_focus`；不记控件 Name/Value。Document 正确常量为 50030，CRLF Unicode 注入合并一次回车。
2. **上屏（0.25.22）**：显式文本上屏一律剪贴板 + Ctrl+V，终端按窗口类名改用 Shift+Insert；不以 UIA 控件类型为门控，不搜索控件或强制 SetFocus。复制/隐藏前固定原窗口 HWND/PID/线程，等待物理修饰键释放后恢复并复核，发键前再校验；目标失效、恢复失败或修饰键超时仅保留复制。请求互斥至后台粘贴结束，发送错误透传，成功日志只表明发键。语音 G2 strict 注入保持独立：Ctrl+V keydown 会打断 hold-to-talk。watchdog 保留 GA_ROOT 自识别修复。
3. **筛选（0.25.23）**：全部/文本/图片 chips 与 Tab/Shift+Tab 共用切换；kind 下推查询并跳过另一张表。IME 组字及 Alt+Tab 放行。切换清选择并使旧响应失效；图片筛选不显示颜色字面量。文件/音频待采集支持。
4. **批量上屏（0.25.24）**：有选择时 Enter 将文本按点击顺序以换行拼接后一次粘贴；Ctrl+C 仍批量复制，Alt+数字/双击仍单条激活。取数共用原子路径，缺项整体报错，旧会话静默放弃。
5. **定位（0.25.25 最终修订）**：唤起先落鼠标所在屏幕附近；后台仅用可信光标行/紧凑输入框校准，整页、过高及离屏矩形不覆盖鼠标落点。位置钳制到 owner DWM 与工作区交集；无定位信息仍可粘贴。校准受窗口 revision 和 250ms 时限保护，慢返回不移动正在操作的窗口。Typora 无定位、Zcode 非输入区、Obsidian 滚动后容器顶部三类场景均由鼠标兜底；不持续追随鼠标移动。

**教训**：UIA 的「可识别输入框」不能代表应用能否处理显式粘贴；控件包围矩形不能代表光标位置。历史白名单与 SetFocus 尝试已退出粘贴链路，定位和粘贴许可分别处理。

### 3.15 长图 pin 双击消失与拖动 DPI 换算（0.25.26，已定）

**双击消失——现象与根因**：长截图 pin 双击（进入缩小态）后窗口"消失"。mini 落位原为图片左上角锚定（`imageScreenX/Y` 不变，pin-geometry.test §14 左上角不变式）；而 0.24.10 起超高长图走 JS 拖动、顶边可合法推出屏幕外（否则长图下方内容不可达），左上角锚定的小窗（≤200 CSS px）整体落在工作区外。普通 pin 原生拖动受 DefWindowProc 顶边钳制、顶边恒在屏内，故仅长图复现。窗口并未销毁——再次双击会在原锚点还原（大窗盖屏可见）。

**双击消失——定案**：`enterMiniMode` 落位前经 `clampMiniAnchor` 查询 `pin_work_area`，把 mini 窗口矩形钳制进所在屏工作区（`pin-geometry.js::clampWinOriginToWorkArea` 纯函数：逐轴四向 clamp，窗口边长超工作区时该轴居中，工作区非正退化为不钳制）；钳制发生即同步改写 `imageScreenX/Y`（= 钳制后原点 + padPhys）——否则 onMoved → dragEndWatchdog → reconcileFromBackend 安全网按 `winX + pad` 反推旧锚点把窗口拉回屏外。锚点被挪动时跳过 CSS 缩放动画直接落位（动画发生在大窗内旧屏外位置本就不可见）；reduced-motion 分支并入统一 `settleMini`（顺带修复该分支漏消费 `pendingReconcileDpr`）。工作区查询失败退化为原左上角锚定。await 后校验 `miniAnimGen`（动画/会话重置使旧钳制作废），`miniState='entering'` 期间挡住 dblclick/滚轮/reconcile 重入。exitMiniMode 不需钳制——还原大窗的锚点已同步为可见位置。

**拖动 DPI——现象与根因**：超高长图 pin 在高 DPI 屏拖动速度不对（150% 屏只有光标的 1/1.5）、跨不同 DPI 屏拖动跳变；普通 pin 原生拖动正常。0.24.10 的长图 JS 拖动把 `e.screenX/Y` 增量当物理像素累加（注释声称"与 0.19.13 旧实现同语义"，git 考古确认旧实现同样无换算，复活时原样继承了错误假设），而 WebView2 里 `MouseEvent.screenX/Y` 是 CSS 像素——main-window/contextmenu.js 已有同一实测结论（高 DPI 屏当物理像素用偏 1/3，右键菜单坐标因此改走后端 GetCursorPos）。原生拖动由系统按物理像素 1:1 移动、松手后 reconcileFromBackend 从 Win32 真源回读，故不受影响；拖动结束的回读也保证了旧 bug 只坏跟手感、不损坏最终状态。

**拖动 DPI——定案**：新增 `pin-geometry.js::applyJsDragMove`（reducer 风格原地推进会话状态）——按当前屏 DPR 把 CSS 增量换算为物理位移；跨 DPI 屏时 WebView 坐标空间随所在屏整体重标，DPR 翻转瞬间先把已积累位移按旧尺度落账（`startImage += (lastScreen − startScreen) × 旧 dpr`）重定基准再继续，分段换算避免用新尺度重算全程的假跳变，翻转事件跨界微差由拖动结束 reconcile 收敛。DPR 取 `window.devicePixelRatio`（拖动期实时渲染尺度；初始化不信任它是因为加载期未稳定，两决策不矛盾），异常回退 `monitorDpr`。已知有界误差：长图大窗跨屏时指针所在屏 ≠ 窗口主导屏的逐事件尺度小偏差，不为此引入每事件查询指针屏。顺带把 onScaleChanged 的 reconcile 在拖动期间（jsDrag/nativeDragActive）跳过：跨 DPI 边界时窗口关联屏翻转恰在此刻触发 scale 变化，中途回读回设与拖动移动流打架（resize 重建合成表面）；pointerup/watchdog 的既有 reconcile 已覆盖拖动结束收敛——与滚轮拦截 nativeDragActive、watchdog 查左键态同一套防御思路。

**否决项**：① 双击消失按可见交集中心锚定（`zoomAroundCenter`）——需额外对齐窗口实际可见区域，收益仅观感，左上角钳制已保证可见且状态同步更简单（该函数本就无调用方，注释已改为锚点数学参考）；② 拖动 DPI 每事件后端查询光标所在屏 DPR——把拖动热路径从"零 IPC 移动 + rAF 合流提交"退化为每事件 IPC，换来的只有跨屏理论精度几个物理像素，且拖动结束 reconcile 已兜底。

## 四、复用与范围边界

复用既有输入线程控制队列、录制握手、配置库与通知、搜索引擎/fuzzy/历史、Capability 协议、图标协议及 Canvas 渲染。窗口查询只读已发布快照，CLI 一次性查询显式预热。

本版保留 domain 内部循环依赖，不继续细拆 search/ai/config 或下沉 app 服务；未引入全局前端状态框架、通用扫描框架、Windows 搜索私有数据库、桌面/PATH/注册表应用扫描或逐项系统 Capability。外部快捷键占用程序名称无法从注册失败结果取得，反馈只说明占用与可操作的恢复方式。

**全链路回写审计与兜底（0.25.27 定案）**：逐一核对全部写入点——单条复制/上屏/多选组合 `User`（顶置/入库去重 ✓，组合入库为最终定案见 §五）、历史图回贴/编辑器回写 `HistoryRepost`/`EditorResult`（skip ✓）、截图三处 `Screenshot`（有意入库 ✓）、`write_clipboard` Capability `blink:ai`（AI 交付内容入库，有意 ✓）、图片编辑输出 `image_editor_copy` `User`（编辑产生新内容入库≈另存，sha256 防繁殖，✓）；**修正两处**：`pin_save_clipboard`/`pin_save_as` 由 `User` 改 `HistoryRepost`——pin 的图多来自历史（同图删旧留新即可），User 会把原条目来源标签覆盖成 Blink 丢失来源信息。**兜底机制**（标记的单点脆弱：一次写入双事件错位消费唯一标记 / 监听线程繁忙致事件晚于 TTL 500ms）：① 文本写入外壳成功后记录**内容指纹**（fx_hash，2s 窗口），监听器标记 miss 时按内容比对，命中沿用该写入的标签与 skip 语义——免疫双事件与 TTL 过期（外部恰好同内容误命中的后果仅是等价于删旧留新，可接受；图片不做指纹，sha256 天然防繁殖）；② 标记与指纹都 miss 且前台进程为 blink 自身时，来源统一标 `blink:app`，消灭历史里的 `blink.exe` 野标签。**遗留**：STT 注入 `inject_text_clipboard` 的备份只读文本，原剪贴板为图片时不恢复（语音注入吃掉图片剪贴板）——恢复需备份/回写 DIB，改动较重待后续立项。批量删除 `delete_clipboard_items_batch` 单事务（缺失 id 幂等跳过），成功后 `removeKeys` 只清本次 key + `reloadList` 维持页号；删除是幂等 DB 副作用不用 generation 拒绝（§3.13 多选语义延伸） |

### 6.1 自动验证与拆分实测

各子版本完成时定向测试全通过，明细见 git log；涉及真实 CM 的路径按 [spec-backend §二](../specs/spec-backend.md) 留集成级（§6.3 实机验收）。

拆分后按包增量验证实测：stt 5.9s、infra 11.8s、domain 13.8s、app 17.6s（原单 crate 基线 43.6s，0.24 优化后 36.8s）——需用 `cargo test -p <目标 crate>` 才有收益，全量命令见 [AGENTS.md](../../AGENTS.md)。

0.25.8 只读回放：XML 保留 108 条候选、合并常用目录后 59 项；100 次纯内存匹配 P95 ≈2.34ms（采样不含窗口/IPC/历史读取，不能证明端到端性能达标）。

**0.25.25 全量复测（20261012，开发机热缓存）**：3675 个 Rust 单测通过、11 个原有 ignore；1 个 doctest 执行通过、2 个原有 ignore；116 个前端测试文件全部通过。模型管理组原先跳过的 71 项全部执行，并新增跨 crate 路径隔离回归；新 runner 自测覆盖并行上限、失败透传、超时和 Cargo 环境清理。

**0.25.26 长图 pin 修复验证（20261012）**：前端 118 个测试文件全部通过（pin-geometry 45 用例，新增 pin-mini-clamp / pin-drag-dpi 结构契约各 6 条）；pin.html 内联模块提取后 `node --check` 语法通过。纯前端改动，无 Rust 侧变更。

**0.25.27 剪贴板多选菜单治理验证（20261012）**：`cargo test -p blink-infra clipboard` 40 项通过（新增 `delete_items_batch_removes_all_and_ignores_missing`）；前端 118 个测试文件全部通过——clipboard-mode 竞态脚本新增 7 用例（批量删除成功/失败/迟到会话隔离、合并编辑参数与 epoch 失效放弃、合并便签拼接）、clipboard-shortcuts 新增 Alt+S 解析 5 用例、clipboard-selection 新增 `removeKeys` 3 用例；`cargo check --bin blink` 通过（编辑器新建路径后端零改动；此前 target 缓存陈旧误报 5 个存量符号错误，`cargo clean -p blink-infra` 后消失）。
