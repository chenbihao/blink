## 二、核心决策（含实施修订记录）

### 3.1 拆分顺序 —— 实施时修订为 infra 先行（已定，修订自规划稿）
**定案**：infra → 三小 crate（capability-error/config/local-engine）→ stt → domain 主体。
**修订原因**：调研发现 capability 协议主体与域服务深度缠绕（`event.rs` 的 CapabilityEnv 端口引用全部服务类型；`policy.rs` 引用 sticky/resource/editor 词汇），不是第一批能拆的；而 infra 是真正的底层（被一切依赖）。stt 的实际依赖需求（CapabilityError + stt_config + infra audio）决定了"协议主体随 0.25.4 主体走、只单独拆 error 词汇"。

### 3.2 builtins 随 domain 主体入 crate，不单独归位各域（已定，修订自"两段式"）
**定案**：builtins（~11.5K 行）随 0.25.4 整体进 `blink-domain`。
**理由**：builtins 消费全部域类型，domain 主体成 crate 后它们天然合法；按域再细分归位的收益递减（见 §4.2）。

### 3.3 剩余 domain 整体粗拆，不按子域细拆（已定）
12/16 子域在同一个强连通分量（capability builtins 消费所有域、各域又依赖 capability 协议），crate 内部互相引用合法——粗拆即拿到编译记账收益。

### 3.4 `#[cfg(test)]` 开关对依赖 crate 失效 —— 运行时模式开关（已定，0.25.1 教训）
**踩坑**：infra 的 DB 读缓存（`CONFIG_CACHE`）与引擎数据目录靠 `#[cfg(test)]` 在测试编译期关闭/隔离——**依赖 crate 永远以非 test 配置编译**，bin 测试进程里跑的是生产分支：全局缓存把多个测试的 in-memory pool 串台（11 个配置/mcp 测试 flaky），引擎路径指向真实 `%APPDATA%`。
**定案**：`blink_infra::runtime_mode`（AtomicBool，默认隔离模式：无缓存+临时目录），`main()` 顶部显式 `activate_production()`。生产行为不变，一切测试进程天然隔离。
**通用教训**：**凡 crate 化搬移，必查 `#[cfg(test)]` / `#[cfg(not(test))]` 双轨**——它们只在"本 crate 自己的测试"里生效，跨 crate 全部失效（同款问题本次共修 8 处：Endpoint::new、with_selection/with_clipboard、layout 两函数、stt 诊断回放 5 处、schema::empty 等）。

### 3.5 stt_config 的 apply_migration 参数收窄（已定）
SttConfig 迁移只消费 AIConfig providers 的 (id, kind, base_url) 投影（`SttMigrationProvider`），bin 侧 `ai_config::stt_migration_providers()` 构造——config crate 不依赖 ai_config 全型（ai_config 与 ai::memory/skill 类型缠绕，整体抽太肥）。

### 3.6 0.25.5 — Chord 与全局快捷键设置优化（已实现）

主窗口唤起仍由 hook 识别短按/长按，功能项全局键仍用 `RegisterHotKey`。复用录制握手、键帽组件、`chord_bindings` 保存队列、输入线程控制队列和 `GLOBAL_HOTKEY_STATUS` 事件。

- 「触发键位」改为「Chord 触发键位」，「跟随触发键」改为「跟随 Chord 键位」；提示说明主窗口按住 Alt 的入口及输入/模式门禁，Chord 保留 Alt+字母。
- 自定义全局键允许单独 F1–F11，保留 Ctrl/Alt/Win + 字母/数字/F1–F11/空格。录制、IPC 写入及注册层校验一致；F12 为系统保留，单独字母/数字/空格不开放。
- 内部冲突显示功能名称；外部占用说明「其他程序或系统占用」，提示释放同组快捷键后重试或换键，不推测占用程序名称。
- `retry_global_hotkey` 投递到输入窗口归属线程，只注册目标条目，不注销其他成功绑定；返回本次结果，占用未变化也结束等待。重复点击合并，过期响应不覆盖新配置。
- 欢迎页开关表示配置已开启，注册状态独立显示；Chord 键与 Custom 全局键分别展示，保留已有自定义全局键，并提供设置入口、读取实际主窗口热键。
- 录制期间忽略功能项 `WM_HOTKEY`，防止录制已注册按键时执行功能；应用、Tauri 版本与 lockfile 更新为 0.25.5；修复拆包遗留的 STT 配置前端测试源码路径。

本版不增加透传/吞键 switch，不迁移主窗口注册机制，不探测外部占用程序名称。

### 3.7 0.25.6 — 欢迎页与设置页配置同步

**问题原因（实现前）**：欢迎页勾选自启动已走同一个 `set_config` 保存通道；`auto_start` 分支缺少配置广播，设置页通用模块缺少订阅，获得焦点后虽重新读取配置却只更新 `currentConfig`，没有回填表单。设置窗口会预热复用，首次初始化的 checkbox 因此保持旧值。欢迎页也只在初始化时读取这些配置，存在反向同步缺口。

**定案**：复用配置库、`CONFIG_CHANGED` 事件、已有设置应用服务和表单回填函数；事件通知负责提示重新读取，后端已确认配置负责显示。先覆盖两窗口共有的自启动、Chord 开关/键位/全局绑定、动作禁用状态及主窗口热键，不重新初始化整页，不引入持续轮询。

#### 3.7.1 通知与读取闭环

- 成功完成持久化及必要系统副作用后，通过共用 helper 广播 `CONFIG_CHANGED`，payload 使用现有 `{key}` 契约，key 统一为配置分片名。消除相关分支的无 payload 广播；消费者兼容旧空 payload 和旧逻辑 key，将其映射为本窗口负责范围的失效通知。
- 两窗口均先注册监听，再执行首次读取；初始化、相关事件、重新获得焦点统一进入同一刷新入口。事件缺失时由首次读取/焦点刷新补偿；不依赖隐藏窗口是否收到每次通知。
- 同一窗口的连续事件与焦点刷新合并；读取期间再收到变更，标记失效并在本轮后补读。发事件失败记录带 key 的日志，配置保存成功不因通知失败被误报为保存失败。

| 分片 | 设置页回填范围 | 欢迎页回填范围 |
|---|---|---|
| `app.appearance` | 自启动及相关通用控件；保护正在编辑的字段 | 自启动开关 |
| `app.chord` | Chord 开关、动作键位/全局绑定、快捷键速查 | Chord 开关、实际键位与全局绑定 |
| `app.hotkey` | 主热键、相关滑块/速查 | 实际主窗口热键 |
| `app.disable` | Chord 动作启用状态 | 全局键未注册时的功能禁用状态说明 |

全局键实际生效与否继续由 `GLOBAL_HOTKEY_STATUS` 提供，配置开启与注册成功保持分别展示。

#### 3.7.2 回填与异步竞态

- 将一次性事件绑定与可重复表单回填分开。设置页复用并导出 `applyGeneralConfig`、热键回填等必要函数；刷新只更新相关控件，不重复执行 `initGeneralTab` 等初始化，不重建无关 Tab，不触发新的保存。
- 刷新读取与状态提交分开：当前 `loadConfig()` 在读取完成时立即调用 `setCurrentConfig()`，必须把提交移到刷新 generation 校验之后；否则仅拦截 DOM 回填仍会让旧响应污染共享状态。
- 初始化读取、事件、焦点和本地修改推进失效代次；返回后仅最新有效读取可提交。相关保存尚未完成时暂缓回填该字段，保存结束再补读；新事件不能使旧请求重新生效。
- 区分最后确认值、当前编辑值和保存中状态。自启动保存时禁用该开关并显示等待，两窗口均捕获本次目标值，不在 await 后重新读取 checkbox 值；成功后重取确认，失败显示可行动错误并重取实际配置，旧失败不得回滚较新的成功。文本、滑块、录制中的键位保留本地编辑，冲突显式反馈。

#### 3.7.3 后端写入保护

**依据（实现前）**：`update_auto_start` 等单字段更新会读取完整 AppConfig 再 `save_config()`，后者重写多个分片；欢迎页与设置页各自的前端保存队列不能防止跨窗口覆盖。`setting_service` 已有更新锁与 expected-old-value 检查，可复用，但当前旧路径并未统一进入它。

- 将运行期 AppConfig 单项修改收敛为只更新所属分片/目标字段；所有可能重写 `app.appearance`、`app.chord`、`app.hotkey`、`app.disable` 的入口共用同一更新保护，包含设置命令、受控设置/Capability 与绑定适配路径。不得只给 `auto_start` 添加独立锁而留下旧的整份快照保存。
- 同分片 read-modify-write 串行保护；两个窗口编辑同一字段/绑定时，复用现有 expected-old-value 校验思路，以前端最后确认值作为修改前提，过期请求返回可识别冲突并重取，不静默覆盖。同分片不同字段从最新值合并，保留未改动字段。
- 全量保存仅用于明确的迁移/重置等操作，并纳入一致性保护；不要把不同页面的陈旧快照用于运行期全量回写。更新锁只用于配置写入，不进入 hook、搜索或窗口唤起热路径。

#### 3.7.4 自启动的系统状态与失败恢复

- release 下串行处理自启动变更：读取已确认偏好与系统原状态 → 应用并核验系统自启动 → 仅持久化自启动字段 → 广播。系统操作失败时不提交成功偏好，尝试恢复系统原状态并返回错误；持久化失败时也补偿恢复系统原状态。
- 补偿失败不能标成已恢复：返回可区分的失败信息、记录系统与持久化状态不一致，界面明确提示需要重试/修复。数据库与系统注册没有共同事务，不宣称绝对原子；保留启动时按持久化偏好对齐系统状态，并记录恢复失败。
- debug 继续只保存偏好、跳过系统自启动注册，并在两处提示此语义；启动时现有 debug 注册项清理行为保持。

**落地**：共享 `config-sync.js` 合并首读、事件与 focus；读取与 `currentConfig`/DOM 提交分离，保存、录制和输入草稿持有刷新暂停，结束后权威补读。通用/热键回填独立于初始化，Chord 数据读取与渲染分离，保留展开状态；新配置不触发无关 Tab 的语言刷新。自启动两处均禁用等待并捕获目标值，debug 显示只保存偏好的提示，错误不会被补读重建的列表抹掉。

后端 `ConfigStore::update` 从最新分片合并字段，通过 SQLite expected-value 条件更新重试，保留未知字段、拒绝损坏配置回写；配置写入与缓存同序，旧 miss 不回填过期缓存。直接 setter、受控设置、绑定适配与读取时的引导版本迁移均接入；`set_config_section` 禁止直接覆盖共享分片，避免绕过校验/副作用。绑定与 Chord 开关、自启动/功能启用状态支持 expected 前提，过期请求返回 `config_conflict`。主热键与 Chord 跨分片冲突检查串行。明确的全量迁移/重置一次数据库事务提交。

`app/autostart.rs` 串行执行系统查询、应用与核验、偏好保存及失败补偿；阻塞系统接口在 `spawn_blocking` 执行，重置同样进入补偿流程。成功再广播 `{key}`；补偿失败返回 `autostart_restore_failed`，启动时对齐失败记录日志。应用版本已升为 **0.25.6**。

**范围边界**：本版不迁移所有设置 Tab 的生命周期，不新增全局前端状态框架，不改热键透传/吞键或输入状态机；写入保护必须覆盖上述共享分片的既有写路径，不能以范围有限为由保留覆盖风险。

### 3.8 0.25.7 — 截图译文字号与溢出适配

**问题**：默认字号按 OCR 框高估算，观感偏大；逐行缩小后再取组内字号中位数，会将部分长行重新放大并添加省略号。

**定案**：复用 OCR 的 `font_h`（缺省回退 `rect.h`）作为参考，前端统一乘 **0.82** 和现有用户缩放系数作为起始字号上限（首轮 0.85，20261003 按用户反馈调为 0.82）。Canvas 对实际绘制文本测宽高只继续缩小，不为追求框高而反向放大。参考字号分组取中位数后，每行仍须满足自身上限与宽高约束，长句允许独立变小。

- 原 OCR `rect` 继续用于背景覆盖与划词，后端检测框/字号字段保持现有契约；校准系数在前端只有一个常量，原文/译文与后台 Pin 合成共用。
- 排版模块以原框内边距、Canvas 推进宽度与可见字形边界约束单行文字；实际字形高度与基线用于框内垂直居中。缺少有效字形指标时回退字体大小估算。
- 普通文本保留 8px 下限，原文参考尺寸更小时不强行撑大；只有下限仍放不下才按完整字素截断并添加省略号。完整译文数据与面板内容不变。
- 本版不新增原图像素字形高度估算，不引入依赖，不扩宽文字框或自动换行；复用现有 Canvas 渲染与字号滑杆。

**落地**：排版抽到 `overlay-text-layout.js`，原文/译文与后台快照渲染共用，参考字号按 0.1px 精度二分适配；上限已可容纳时直接采用，避免短句反复测量。应用/Tauri/lockfile 版本同步至 **0.25.7**，开发监听已自动构建并重启该版本。

### 3.9 0.25.8 — 应用搜索来源与系统入口增强（已实现）

**背景**：开始菜单引擎扫描用户/公共 `Start Menu\Programs` 的 `.lnk`，可合并 AppsFolder 中的 UWP/MSIX 应用；另一份 `SystemShortcutEngine` 硬编码 10 项系统入口且始终启用。现有「应用搜索」总开关只影响前者。系统入口缺少常见别名，「环境变量」还把程序和参数整串传给路径打开函数。`search_apps` Capability 只查开始菜单引擎，与主窗口覆盖范围不同。

**澄清**：「常用系统入口」是维护的功能列表，包含控制面板及常用系统设置；它不是开始菜单目录或默认搜索路径。基础来源始终随应用搜索启用，关闭全部增强项仍能搜索开始菜单应用。当前设置描述中的「桌面快捷方式」未被这条应用扫描链路覆盖，本版将文案改为实际范围，不顺带新增桌面/PATH/注册表应用扫描。

#### 3.9.1 设置结构与开关语义

保留「应用搜索」卡片，顶部开关作为该卡片全部来源的总开关，描述改为「搜索已安装应用和 Windows 系统入口」。卡片内分「基础搜索」与「增强搜索」；增强只是分组，无额外分组总开关。

| 分组 | 来源 / 控件 | 默认 | 行为 |
|---|---|---|---|
| 基础搜索 | 用户、公共开始菜单快捷方式 | 随总开关启用 | 无独立来源开关；沿用扫描深度，说明仅影响开始菜单递归扫描 |
| 增强搜索 | 包含 UWP/MSIX 应用 | 开 | 沿用 `include_uwp`，控制 AppsFolder 枚举及结果 |
| 增强搜索 | 包含常用系统入口 | 开 | 控制维护的常用入口列表，如控制面板、环境变量、设备管理器 |
| 增强搜索 | 发现更多系统设置项 | 关 | 从本机 Windows 设置目录解析可用入口，后台建索引 |

- 三个增强选项相互独立。常用入口开 / 自动发现关是默认体验；常用入口关 / 自动发现开只使用自动来源，它仍可能发现同名入口。开关关闭来源，不表示屏蔽某个系统功能。
- 总开关关闭时，所有上述来源退出召回，不发起新的扫描/发现任务；子选项保留并在 UI 中禁用，重新开启按保存偏好恢复。文件、计算器、插件及 Blink 自身设置入口不受影响。此语义明确改变旧版「系统入口始终开启」行为。
- 自动发现项下显示「正在建立索引」「已发现 N 个额外入口」「当前系统暂不支持」或可重试失败提示。N 按当前启用来源合并后的额外可搜索项统计；已就绪但零项与不支持/失败分别显示。

#### 3.9.2 配置与运行时更新

复用 `StartMenuConfig` 与 `engine:start_menu` 存储键，保留 `enabled`、`scan_depth`、`include_uwp`，新增 `include_system_shortcuts`（缺省 true）、`discover_system_settings`（缺省 false）。旧配置逐字段补默认；定向更新保留未知字段，损坏配置报错而非用默认值覆盖。

- `SearchService` 统一把配置更新分发给开始菜单与系统入口引擎。常用入口开关立即改变召回；只修改系统入口选项不触发无关的开始菜单全量扫描。
- 开始菜单预扫和后台刷新检查 `enabled`，构建私有快照后通过 generation 校验发布；总开关/UWP/深度变更使旧结果失效。补齐全量扫描后的增量缓存，修正变更文件保留逻辑及删除计数下溢。
- 设置保存复用 `set_config`、配置通知与 0.25.6 刷新调度，使用字段级 CAS；后端串行持久化与运行时更新，前端保存中禁用控件、冻结旧读取，失败后补读确认值。
- 统一通知键为 `engine:start_menu`，消费者兼容既有 `start_menu_config` 逻辑键；隐藏设置窗口再次聚焦时补读，不靠一次初始化值。
- 窗口查询只读已发布索引，冷启动不等待扫描；一次性 CLI 查询显式 `prewarm`，保持首次 CLI 搜索可用。

#### 3.9.3 A：常用系统入口与启动模型

常用目录由现有 10 项扩充到 **37 项定义**，按系统版本、程序存在性及 Wi-Fi/蓝牙硬件过滤；本机只读回放中 37 项可用，实际启动仍待实机抽样。

| 类别 | 首批覆盖 |
|---|---|
| 现有入口 | 回收站、控制面板、此电脑、网络、程序和功能、系统属性、设备管理器、任务管理器、服务 |
| 环境与管理 | 账户环境变量、系统环境变量、高级系统设置、网络连接、磁盘管理、计算机管理、事件查看器 |
| 常用设置 | 显示、声音、蓝牙、鼠标、打印机、电源、存储、代理、VPN、Wi-Fi、默认应用、启动应用、日期和时间、语言、剪贴板、Windows Update、恢复 |

- 条目包含稳定 `entry_id`、独立 `history_key`、中英文标题、别名/关键词及预计算拼音、图标引用、可用性和带类型的启动目标。别名显式匹配并取最高分，不继续把不同语义全部塞进拼音字段；完整查询「编辑系统环境变量」和「卸载程序」应命中对应入口。
- 账户环境变量使用 `rundll32.exe` + `sysdm.cpl,EditEnvironmentVariables`；系统环境变量与高级系统设置使用 `SystemPropertiesAdvanced.exe`。共用启动目标的不同功能可以保留不同标题/身份。
- 启动目标区分 Shell 路径、受支持的设置 URI、程序及参数；优先复用官方 `ms-settings:` 与稳定 Shell/CPL/MSC 入口，依系统版本/硬件检查可用性。图标保持 `blink-icon` 懒加载，不能进入搜索输入热路径。
- 扩展现有 `SystemShortcutEngine` 为有配置的系统入口引擎，共用一份领域目录服务；静态定义可拆到独立 catalog 模块。复用现有 fuzzy、归一化与历史排序，系统项仍标记 `source: system`；不为全部设置项增加固定置顶分。

**执行链路**：新增有限参数的 `open_system_entry` Capability，入参只接受 `entry_id`，通过共享目录解析受信任启动目标；内部 `SearchAction::SystemEntry` 向主窗口投影为既有 RunAction，向 `search_apps` 投影为 `ItemAction::Invoke`。平台实际启动位于 `blink-infra::platform`，程序与参数分别传递；既有 `.lnk`/UWP 继续使用 `open_path`。

目录服务通过既有 SearchService 服务依赖提供查找，搜索只出候选，用户选择才执行；执行时核验身份、当前来源状态及目标可用性。Capability 出口单独声明桌面运行时与来源策略；新增能力的 AI/MCP 默认授权关闭，目录可搜索不代表自动获得执行授权。现有 `.lnk`/UWP 打开路径继续使用 `open_path`。

**历史兼容**：扫描生成的 `.lnk` 路径和现有 10 项旧 history key 保留，身份/图标键/启动目标不再混用。旧「环境变量」历史归账户环境变量，新系统环境变量单独记账；新发现项使用稳定设置身份键。RunAction 切换必须补齐应用层系统入口启动历史记录，沿用搜索历史开关并在成功受理启动后记录，避免新增链路丢失历史加权；CLI/AI 的普通 Capability 调用不隐式写搜索历史。

#### 3.9.4 自动发现：后台索引与可靠子集

本机只读排查定位到 `%WINDIR%\ImmersiveControlPanel\Settings\AllSystemSettings_*.xml`，其中存在「编辑账户的环境变量」「编辑系统环境变量」对应的本地化描述、关键词和 DeepLink。该目录是 Windows 实现数据，不视为跨版本稳定的公开协议；本版提供可降级的解析适配器，不承诺完整复刻开始菜单搜索。

- infra 使用 `quick-xml` 有界解析（最多 16 文件、每文件 8MiB），资源走 `SHLoadIndirectString`，现代 Settings 资源补充显式 PRI 路径；domain 负责目录身份、预计算匹配、缓存与排序，不直接调用 Win32。
- 支持受维护的 Shell/CPL/MSC/程序目标、控制面板 canonical name 白名单及约 33 个现代设置页面映射。缺少目标、未知 HostID/条件/feature、歧义页面或资源解析失败的条目跳过；DTD、任意命令/协议/参数不导入。
- 只读取系统目录候选，解析后的程序/协议/参数经过受支持规则校验，不将任意 XML 命令字符串交给 shell；解析资源不会执行设置动作。现代条目的页面定位不等同于可直接启动 URI，不能仅靠 PageID 猜测。
- 多份 XML 按设置身份合并，再通过显式身份或同目标且同语义的标题/别名合并到常用目录；常用项优先，发现关键词参与匹配。同 URI 的不同设置身份、共用程序的环境变量与高级设置保持独立。
- 默认关闭时不读取目录、不解析资源、不启动发现任务。开启后单次后台扫描，状态为 disabled/building/ready/unsupported/failed；缓存为空时搜索也不等待发现完成，基础应用与常用项先正常返回。
- 索引构建采用 single-flight 和 generation，配置关闭/语言或目录版本变化使旧任务失效；不可中断的阻塞工作结束后丢弃旧结果，不能恢复已关闭来源。提交只短时替换内存快照，不把扫描锁带入输入热路径。
- 使用内存快照与目录元数据指纹，开启时每 5 分钟后台检查；文件变化、语言变化或手动重试触发重建，扫描前后指纹不一致则丢弃重试。不新增 watcher/数据库表。常用目录跟随 Blink 语言，自动项使用本机可解析的系统语言资源。
- 缺目录/当前版本不支持是可预期降级；损坏/读取失败分别统计并提供状态。关键日志记录 generation、候选/有效/额外/跳过数量、耗时及失败上下文，避免逐条刷屏，不记录用户搜索内容。

**落地**：主窗口和 `search_apps` 使用同一份应用/系统来源配置与目录。别名复用 fuzzy 打分核心，借用候选直接合并最高分，仅对最终入口排序，避免复制/排序全部别名。图标引用独立于身份与 history key，仍走 `blink-icon` 懒加载；设置状态读取带代次保护，只在构建中轮询。应用/Tauri/lockfile 版本同步至 **0.25.8**。

**后续修复（20261003）**：用户实机日志发现「重新发现」同步 IPC 在 WebView 主线程调用 `tokio::spawn`，因无 Tokio runtime 崩溃；命令改为 async，并用返回 `Send Future` 的契约测试防止改回同步调度。启动时的语言初始化也放入异步运行时，覆盖英文语言且自动发现已开启的重启路径。基础/增强分组与新增选项说明统一复用 `field-hint-icon` 悬浮提示，移除独立说明段落。

**范围边界**：复用开始菜单缓存、搜索引擎与 Capability 协议、配置保存/同步、图标协议和搜索历史；未新增通用扫描框架、设置操作执行器或逐项系统 Capability，未接入 Windows 搜索私有数据库及桌面/注册表/PATH 扫描，未修改环境变量、提权或改动热键/焦点链路。
