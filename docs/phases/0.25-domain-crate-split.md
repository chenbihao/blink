## 二、背景与动机

单 bin crate 增量验证约 36.8s，拆分使热点域能独立编译测试；其余子版本解决快捷键占用缺恢复入口、复用窗口配置陈旧、长译文溢出、主窗口与 `search_apps` 来源不一致、更新只能外链下载等问题。0.25.13 起因是用户侧阿里翻译 404 排障无日志可看（根因：密钥粘贴混入空格 + 失败日志全在 debug 级）；0.25.14 起因是预选框内部也被暗罩盖住、唤起后到截图就绪前拖选无响应。

**架构澄清（"不是问题的"）**：builtins 与多个域相互依赖，留在同一 domain crate 是本版的有意取舍；"常用系统入口"是维护的功能目录，基础应用扫描仍来自开始菜单；配置开启与全局快捷键注册成功分别展示，不能用 checkbox 推断系统注册状态。

## 三、核心决策与维护要点

### 3.1 粗拆 domain，协议错误先独立

拆分顺序为 infra → capability-error/config/local-engine → stt → domain。Capability 协议主体和 builtins 消费多个域服务，随 domain 整体迁入，避免强拆循环依赖。bin 的 `src/{infra,domain}/mod.rs` 保留 re-export shim，旧 `crate::infra::*` / `crate::domain::*` 引用无需改写。

**跨 crate 测试隔离教训**：依赖 crate 不以 `cfg(test)` 编译，原有缓存和引擎目录隔离因此失效——`blink_infra::runtime_mode` 默认隔离缓存与数据目录，生产入口显式 `activate_production()`。STT 配置迁移只接收 provider 的 id/kind/base_url 投影，避免 config crate 依赖完整 AI 配置类型。

### 3.2 后端确认值驱动回填，字段 CAS 保护写入

两窗口先订阅 `CONFIG_CHANGED` 再首读，事件和 focus 共用单飞刷新入口；通知是失效信号，只有最新有效读取才能提交共享状态和 DOM。保存、录制及输入草稿暂停回填，结束后补读。共享分片从最新值合并目标字段、保留未知字段、拒绝损坏配置回写；过期修改返回 `config_conflict`，全量迁移/重置走数据库事务。自启动 release 下依次查询→注册→核验→保存→广播，失败补偿恢复系统原状态（补偿失败明确报 `autostart_restore_failed`）；debug 仅保存偏好。系统注册与数据库没有共同事务。

### 3.3 系统入口按稳定身份合并，启动目标必须明确

常用与发现目录共用稳定 entry_id、独立 history key、别名/拼音匹配和带类型的启动目标；同目标但语义不同的入口保持独立。自动发现读取本机 Windows 设置 XML 的可靠子集（该目录不是稳定公开协议）；DeepLink 经白名单校验，PageID 仅是父级定位不能据此猜子设置 URI；缺目标/未知条件/歧义项跳过。`open_system_entry` 只接受 entry_id，执行时核验当前来源状态；主窗口和 `search_apps` 共用目录分别投影为 RunAction 和 Invoke；AI/MCP 默认授权关闭。

### 3.4 一键更新选官方 updater 插件，签名与镜像链路自建衔接（0.25.10，已定）

**定案**：集成 `tauri-plugin-updater` 2.12（2.13 起要求 tauri ^2.12，与 2.11.5 冲突故锁版本）；`bundle.createUpdaterArtifacts` 开启，build 自动产 minisign `.sig`。公钥嵌 `tauri.conf.json`；私钥真源为 CI secret 与本地 `~/.tauri/blink-updater.key`（均不入 Git）——**私钥丢失则存量用户无法验签升级，必须长期备份**。更新源 `releases/latest/download/latest.json` 由 `cargo xtask release` 生成，**draft 不计入 latest，publish 后才对用户生效**；安装包 URL 固定主站直链，代理场景由 `github_proxy_candidates` 候选链 + 全局代理覆盖（签名只校验文件字节，走代理不放宽供应链约束）。前端不直调插件 API；`install_update` 后台任务执行、进度走 `UPDATE_INSTALL_PROGRESS` 事件（≥200ms 节流），互斥单飞防重复——**检查期所有 `?` 早退路径必须由调用方复位标志**，否则卡死无法重试。debug 构建直接拒绝安装。

### 3.5 浅色主题专项：token 化优先，原色只做亮度缩放（0.25.11，已定）

1. **`--yellow` 升级为正式主题 token**（dark `#e5c07b` / light `#976014`）——主窗错误项此前恒用 Mocha 黄 fallback，浅色底 1.53:1 几乎隐形。
2. **未定义颜色引用一律收敛到语义 token，不留颜色常量 fallback**（约 20 处）；dark 渲染不变（fallback 恰是当前生效值）。两处有意偏离"dark 不变"：popup 折叠头 hover 与滚动条 hover 改为获得真实 hover 增量。
3. **Latte 状态色只向黑色方向缩放、保留色相**，不搞"文字专用第二套状态色"（token 翻倍、组件无所适从）。
4. **截图 overlay 与钉图窗口保持暗色自持 palette**，作为 spec-frontend"色彩绝不 hardcode"的明示豁免——固定深色保证任意底材可读。
5. **新增 theme-debug.html 主题调试页**：聚合全部语义 token 与组件样本并实时算 WCAG 对比度；**验证主题只开这一页**，替代逐窗口截图老验法。设置页「调试」Tab 入口（single-flight 建窗 + close=hide 复用，不预热不常驻）。

### 3.6 程序化写入主窗口输入框后必须显式滚动跟随（0.25.12，已定）

**Chromium 硬约束（实测锚定）**：裸 `value=` 赋值把 `scrollLeft` 重置为 0，程序化 `setSelectionRange` 即使有焦点也不触发滚动到光标——录音中 partial 的显式 `scrollLeft = maxScroll` 一直有效，终稿/回填路径恰好缺这一步。

**定案**：`#query` 所有程序化整串写入路径（voice 终稿、confirmed-only 回填、baseQuery 恢复、右键粘贴）统一补"设光标到末尾 + `ghost.scrollWithMargin()`"，复用 0.10.6 既有函数，不动 partial 的 rAF 跟随链路。**录音中避让语音指示器**：`body.voice-active` 下给 `#query`/`#ghost-overlay` 同步加 padding-right 避让带（宽度按指示器 `offsetWidth + 8px` 实测写 `--voice-avoid-w`），input 滚动区计入右 padding，`maxScroll` 自然落在指示器左侧、滚动逻辑零改动；灰字 preview 另加 `clip-path: inset()` 把裁切沿收到避让带内沿（单行空间不足时预览让位）。避让用 padding 而非 width 收窄：与"overlay 镜像 #query 的 padding"既有约定同属性同步。

### 3.7 翻译插件错误必带根因、降级必须用户显式开启（0.25.13，已定）

**定案**：

1. **错误必带根因**：插件记录非 200 响应体（300 字符）并解析供应商错误 JSON，最终错误形如「翻译失败（ali: InvalidAccessKeyId.NotFound: …）」；主引擎未配置也记明「未配置 API 密钥」。
2. **插件 stderr 分级约定**：行内含 `[error]`/`[warn]`/`[info]` 方括号标记时 core 按标记级别转发，无标记保持 debug（约定正文见 protocol.rs）；SLO 失败埋点与「插件返回错误信息」提级 warn。
3. **密钥空格检测不自动改写输入**：manifest `no_space: true` 声明，设置页红字提示 + 「移除空格」按钮（点击才清除）；插件侧读取凭据统一 `cred()` trim 兜底存量。自动 trim 曾实现后按用户要求撤回——密钥是否含空格由用户确认。
4. **降级默认关闭（行为变更）**：manifest `allow_fallback`（默认 false）门控 `try_next_fallback`，主引擎失败直接报错不静默换引擎；「降级顺序」用 `visible_when` 条件显隐（schema 通用机制）。
5. **引擎元数据走 desc 通道**：`RawToolResult.desc`（实际引擎，降级时带「已降级」前缀）注入 `CapabilityResult.desc`——**不进 data**，AI 出口拿完整 data，塞进 data 的元数据会污染模型可见的译文。
6. **批量翻译全失败必须报错**：`translate_lines` 返回 `{lines, engine, failed, error}`，全失败返回 Err，不再拿原文冒充译文；部分失败 Ok + failed 计数。

### 3.8 预选挖洞遮罩独立四块 DOM、就绪前拖选只缓存起点（0.25.14，已定）

遮罩本有三套实现（预选态整屏 canvas 暗罩 / 拖动态 DOM 挖洞 / 确定态 canvas 挖洞）；「等遮罩下来才能拖」的机制是 pointer handler 开头的 `!ss.screenshot → return` 丢弃按下事件。

**定案**：

1. **预选挖洞用独立四块遮罩 DOM，挂 ss-preselection-hint 生命周期**：三个预选来源本就全部汇过 show/hide/reset 三函数，遮罩驱动内嵌其中、调用方零改动。几何写入复用 `writeGeometry` 的整数格点纪律（混合 DPI 下独立取整产生 1px 亮缝，0.23.15 已踩过）。**消隐不调 drawDimmed**——hide 的调用路径都会跟进 canvas 提交，`drawDimmed`/`drawFinalSelection` 开头强制隐藏本遮罩（与 `hideLiveSelection` 同构），双暗与漏恢复由此封死。
2. **开关 `preselection_cutout` 默认开**（serde `default_true` 零迁移），前端消费 `!== false` 语义；开关同时是特殊 DPI/驱动环境的降级逃生门。
3. **就绪前拖选只缓存起点**：pointerdown 在 `!ss.screenshot` 时记 `{startX, startY, pointerId}` 并 capture（不丢弃），ready 前 move 以当前指针位置直接刷新拖选预览（live-selection 不依赖底图，黑罩期即有蓝框反馈），ready 后首个仍按住的 move 衔接为正常 isDragging；ready 前松手视为放弃。可拖时刻从「截图 ready」提前到「P5 暗罩可见」。
4. **懒加载屏局部重绘**：每块屏就绪后按显示器矩形 `redrawBaseRegion` 只刷主 canvas 底图区，替代全屏 drawDimmed；以 `ss._dimmedReady` 为前提——P5 纯黑期不擦（否则黑罩上出无暗罩亮斑）。
5. **桌面回退预选与窗口挖洞共用同一开关**；canvas-backed 来源（图片编辑）不激活挖洞。

**不做（推迟）**：确定态遮罩 DOM 化与 `#interaction-canvas` 整体退役（0.23.15 刚完成拖动路径迁移，本版只做预选增量）；唤起前段微优化等 0.19.14 打桩日志实测数据说话。

### 3.9 CM 命名 v2：keyring target modifier 显式指定完整 target（0.25.15，已定）

**定案**：

1. **命名 `blink:{module}:{subject}:{purpose}`**（如 `blink:ai:{uuid}:key` / `blink:stt:cloud:key`），应用前缀置首。用 `keyring_core::Entry::new_with_modifiers` 的 `target` modifier 显式指定完整 target（windows-native store 此时忽略 service/user 拼接）；不用自建 store 的 prefix/divider 配置（仍受 `{user}{div}{service}` 段序约束）。
2. **`SecretRef{module,subject,purpose}` 显式命名空间**取代裸 `(provider_id, purpose)` 签名，模块归属（Ai/Stt/Plugin）在类型层钉死；`from_legacy_pid` 承接历史 pid（`stt:cloud`→Stt，其余→Ai，含 0.14.6–0.17.11 的 slug id）。
3. **迁移读写必须与写入路径对称**：v1 条目 CredentialBlob 是 UTF-16LE，复用 v0 的 UTF-8 raw 读取器会把密钥读成 `s\0k\0…` 乱码静默写入新命名——v1 读写删必须走无 modifier 的 keyring Entry（与 v1 写入同路径），v0 迁移继续用 raw。**教训：跨代迁移先确认 blob 编码，不能复用上一代的读取器。**
4. **单测 store 自写**：keyring 自带 mock 拒绝一切 modifier，按 `CredentialApi`/`CredentialStoreApi` 自写按 target name 键存的内存实现；单测绝不碰真实 CM。
5. **枚举不依赖 CredEnumerateW 通配语法（0.25.16-fix 修订）**：该 API 的通配是不文档化子集——`*blink*` 直接 ERROR_NOT_FOUND 被当空列表（首版因此静默空跑、密钥全部"未配置"），`blink*`/`*.blink` 却可用。修订为 filter=NULL 全量枚举 + Rust 端 `contains("blink")` 过滤（`enumerate_blink_secrets_anywhere`），迁移去 marker 改每启动自愈扫描（无残留即 no-op，顺带覆盖双版本并行/备份恢复）。**教训：Win32 通配符语法能不用就不用；ERROR_NOT_FOUND ≠ 过滤器非法。**

### 3.10 插件密钥字段：声明式标记 + 宿主统一拦截（0.25.16，已定）

**定案**：manifest `"secret": true`（0.7 起就写在翻译插件里，本版激活解析）→ 宿主在唯一写入咽喉 `update_config` 自动转存 CM（`blink:plugin:{plugin_id}:{field_key}`），SQLite settings 只留空串占位；插件进程注入前由 `resolved_settings` 从 CM 还原明文（插件二进制与协议零改动）；存量明文启动期一次性搬迁（幂等由构造保证）。`get_settings` 保持脱敏版供前端/AI 路径。理由：写入路径自 0.17.8 起收敛在单一分支，拦截点唯一可靠；密钥只在「前端输入→invoke→写 CM」与「CM 读出→子进程 stdin」两个既有窗口存在明文，与 AI 密钥链路安全模型一致。

**已知取舍**：CM 写失败仅 warn 仍脱敏（宁丢配置不落明文，用户重存即可）；降级到 0.25.15 及之前版本时插件密钥表现为「未配置」（本体仍在 CM 不丢失）。

## 四、复用与范围边界

复用既有输入线程控制队列、录制握手、配置库与通知、搜索引擎/fuzzy/历史、Capability 协议、图标协议及 Canvas 渲染。窗口查询只读已发布快照，CLI 一次性查询显式预热。

本版保留 domain 内部循环依赖，不继续细拆 search/ai/config 或下沉 app 服务；未引入全局前端状态框架、通用扫描框架、Windows 搜索私有数据库、桌面/PATH/注册表应用扫描或逐项系统 Capability。外部快捷键占用程序名称无法从注册失败结果取得，反馈只说明占用与可操作的恢复方式。

## 五、分版本实现总结

### 5.1 0.25.1–0.25.4：crate 拆分

拆出 `blink-infra`、`blink-domain-capability`、`blink-domain-config`、`blink-domain-local-engine`、`blink-domain-stt`、`blink-domain`；bin 保留 app/main/cli 与兼容 shim。跨 crate inventory 注册保持完整；domain 不直接引用 Tauri/Win32，由架构守卫核验。

### 5.2 0.25.5：快捷键设置

Chord 保留 Alt+字母，自定义全局键开放单独 F1–F11，拒绝 F12、裸输入键及未知修饰键；录制、IPC 与注册白名单一致。重试只在输入窗口归属线程注册目标绑定，不注销其他成功项；重复点击合并，过期结果丢弃。欢迎页分别显示 Chord 与 Custom。

### 5.3 0.25.6：配置同步与失败恢复

分片通知同步兼容旧空 payload 和逻辑 key，隐藏窗口再次聚焦补读。配置首读失败结束初始化等待，持续显示错误和重试入口；重试单飞，欢迎页导航与退出独立于配置成功，不用默认配置解锁写入。

### 5.4 0.25.7：截图译文排版

共用 `overlay-text-layout.js`：参考字号取 OCR 字号与框高较小值 × 0.82 × 用户缩放；组内参考字号统一后每行仍受自身上限和 Canvas 宽高约束，长句独立缩小；字形边界垂直居中，普通文本 8px 下限，放不下按完整字素省略。

### 5.5 0.25.8：应用搜索与发现生命周期

总开关统一控制基础与增强来源；UWP 和常用系统入口默认开，自动发现默认关（默认关闭不读目录；最多解析 16 个文件、每个 8MiB）。后台单飞构建经 generation 与目录指纹核验提交，开启时每 5 分钟检查。同步 IPC 曾因无 Tokio runtime 崩溃，已改 async 并补契约测试。

### 5.6 0.25.9：rig 0.43 升级

只做 API 迁移不引入新架构（不接 `rig-run` 状态机，ChatService/AgentProvider 结构不变，rig 隔离墙仍收敛在三处触点）。要点：MCP 集成迁 `rig-rmcp`（`McpTool::from_mcp_server` 逐个转 `DynamicTool`）；模型句柄去泛型（`DynModel<Completion>` 擦除，`RigProvider` 由泛型变具体类型）；`Usage` 计数 Option 化（`from_rig_usage` 全仓唯一映射点，None 归零、`is_reported()` 哨兵语义保持，前端 JSON 契约不变）；`http_log.rs` 内核换 `rig_reqwest::ReqwestClient`；流式事件换 `StreamAssistantItem` 轨道（tool call 从专用变体取，不再从 delta 拼装）；思考块 Sealed 签发方——本地拼接的部分回复用 `Issuer::from("blink")` 签发，崩溃恢复后该段思考不回传模型；system 以 `Message::System` 置于 chat_history 首（CompletionRequest 无 preamble 字段）。

### 5.7 0.25.10：应用内一键更新

后端注册 updater 插件与 `install_update` 命令（含 `global_proxy_url` 共用）；前端关于页「一键更新」按钮与进度条（total 未知退化为不确定态）。发布链路：`cargo xtask release` 新增生成 `latest.json` 步骤（读 tauri.conf 版本 + NSIS `.sig` + repository），CI 注入私钥 secret 并上传；事件常量两端同步。

### 5.8 0.25.11：浅色主题可读性专项

**token 层**：新增 `--yellow`（dark/light 两档），light 调整 green/warning/accent/text-dim 等 7 值全部达 AA（正文 ≥4.5:1）；dark 除新增 `--yellow` 零改动。**引用清理**：约 20 处未定义颜色引用收敛到语义 token。**主题调试页**：`theme-debug.html` + 对比度单测，主题下拉与 settings.html 同步维护。**应用内入口**：设置页调试 Tab 按钮 → single-flight 窗口（close=hide 复用，不预热）；调试台视图层整体放开 `overflow` 并配 token 化滚动条。**主题目录扩充**：新增 Catppuccin 四官方风味（变量块追加在 `themes/nvchad.css` 文末），Latte 沿用本版 AA 调整值并覆盖 `--warning`/`--yellow`；分组重排为 Blink → Nord → Catppuccin → Genshin → Custom → NvChad Light → NvChad Dark（总量 95 项，设置页与调试台两处目录同步）。

### 5.9 0.25.12：主窗口超长文本滚动跟随

`search.js::fillQuery`、`lifecycle.js` VOICE_RECORDING_END 两分支、`contextmenu.js` 右键粘贴共三处写入点统一补"设光标到末尾 + scrollWithMargin"；partial 的 rAF 跟随链路本就正确未动。避让带：`body.voice-active` 下 `#query`/`#ghost-overlay` 同步加 padding-right，`lifecycle.js` 在录音开始/状态提示时实测写 `--voice-avoid-w`（CSS fallback 84px）；灰字 preview 加 `clip-path` 裁到带内沿；松键后一并收回。

### 5.10 0.25.13：翻译插件诊断与降级治理

插件侧：非 200 记响应体 + 解析供应商错误 JSON 进 `last_error_detail` 并附到终局错误；stderr 按约定加方括号标记；`try_next_fallback` 受 `allow_fallback` 门控；凭据读取统一 `cred()` trim。core 侧：`stderr_line_level` 按标记转发，SLO 失败与插件报错提级 warn；`RawToolResult.desc` 双向向后兼容，`apply_result_desc` 注入；`translate_text_impl` 带出引擎，`translate_lines` 返回 `TranslateLinesResult`。设置页：9 凭据字段 `no_space` 红字提示 + 移除按钮（顺带修复 `.plugin-save-msg` 缺失导致保存失败提示静默的旧缺陷）；`visible_when` 条件显隐。OCR 面板：徽标按 tab 切换（原文 OCR 引擎 / 译文「翻译：{供应商}」），失败显示原因，【重新翻译】按钮三路径同步。

### 5.11 0.25.14：截图预选挖洞与唤起衔接

`#preselection-mask` 四块遮罩 DOM 由 `ss-preselection-hint.js` 驱动（show 时 `syncCutoutMask` 同帧清整屏暗罩+写几何，hide 延迟到边框淡出确认）；`drawDimmed`/`drawFinalSelection` 开头 `hideCutoutMask` 封死双暗；遮罩色 rgba(0,0,0,0.45) 与三态同源。A1 就绪前拖选（见 §3.8）；A2 懒加载局部重绘 `redrawBaseRegion`（前提 `_dimmedReady`）。配置链：`preselection_cutout` 走 ScreenshotConfig 分片，`!== false` 语义读取。

**时序修订（0.25.14-fix，三轮实机反馈）**：① 窗口列表异步加载完成前桌面回退会把「列表未就绪」误判为「鼠标在桌面」→ `windowsLoaded` 门控（失败也置位，预选降级为桌面回退不僵死）；② `canvas.width` 同值赋值也清空画布（HTML 规范）→ 同值跳过，P5 保留至 rAF 同帧原子替换；BitBlt 抓帧与 DWM 合成真桌面存在色彩档差（夜灯/HDR 下偏暗），属采集管线特性本版不处理；③ 唤起后鼠标不动则补预选无位置 → `show_screenshot_overlay` 注入 show 时刻真实光标（取不到注入 `null` 哨兵），列表就绪即补选；④ 挖洞遮罩补 0.13s 几何 transition 与边框一致（与 `#live-mask-*`「几何禁止过渡」铁则不冲突——那条针对拖动逐帧写入，预选是低频离散跳变），首次激活禁 transition + 强制 reflow 锁首帧，hide 延迟到淡出确认使跨层级切换连续形变。

### 5.12 0.25.15：CM 密钥命名 v2 迁移

`SecretRef` 命名体系与 target modifier Entry 构造见 §3.9。迁移链：全量枚举 + Rust 过滤 → `parse_keyring_v1_target` 识别 v1 形状（纯函数单测）→ `from_legacy_pid` 恢复模块 → keyring Entry 读明文 → 写 v2 → 同 Entry 删老条目（写成功才删，单向流动）；无 marker 每启动自愈。`main.rs` 在 v0 迁移之后、AIConfig 读取之前接线；v0 迁移写侧经新 store 落地即 v2。调用方（ai/management、stt/mod、factory、agent_provider、diagnostic）全部改 SecretRef 构造器；存储页 secret_count 换全量枚举（修复 0.17.11 起漏计）；nsis 卸载注释更新三代命名。首版 `*blink*` 通配翻车事故与修复见 §3.9-5，修复后经真实机器验证（4 条 v1 同秒收编、v1 删除）。

### 5.13 0.25.16：插件密钥字段接入 CM

`SettingField.secret`（serde default）+ 解析单测；`engine.rs` 四方法：`secret_field_keys` / `sanitize_config_secrets`（写入咽喉，CM 写失败仍脱敏）/ `resolved_settings`（仅喂子进程路径）/ `migrate_secret_fields_to_cm`（启动期搬迁）；`update_config` 持久化前过 sanitize。命令层 `get_plugin_secret_hint`（掩码，仅 manifest 声明字段放行防探测）/ `clear_plugin_secret`（幂等）；`cleanup_all_data` 密钥清理纳入插件字段。前端 secret 字段 password 渲染恒空值、`collectSettings` 跳空（空 = 未修改契约）、保存后清空回填掩码、清除按钮走专门 invoke。**热路径取舍**：`resolved_settings` 每次查询逐字段读 CM（≈1-2ms，debounce + 网络瓶颈掩盖），不做缓存——失效面复杂度不值，实测有感知再优化。

## 六、验收结果与遗留

### 6.1 自动验证与拆分实测

各子版本完成时定向测试全通过（bin / blink-domain / blink-infra / blink-domain-stt / 前端逐文件 `node --test` / 翻译插件），明细与逐项计数见 git log；涉及真实 CM 的路径按 spec-backend §二留集成级（§6.3 实机验收）。

拆分时按包增量验证实测：stt 5.9s、domain 13.8s、infra 11.8s、app 17.6s（原单 crate 基线 43.6s，0.24 优化后 36.8s）。需使用 `cargo test -p <目标 crate>` 才获得按层验证收益；全量命令见 [AGENTS.md](../../AGENTS.md)。

0.25.8 review 修复后的本机只读回放：XML 保留 108 条候选，合并常用目录后共 59 项（额外入口 22 项）；100 次 Debug 纯内存匹配 P95 约 2.34ms。采样不含窗口、IPC、历史读取，不能证明端到端性能达标。

20261008 review 修复（均无行为变更）：`windows.rs` 的 `cursor_pos_virtual` 注释归位（原误插在 `launcher_position` doc 中间）、`index.js` predrag 缓存移除未消费的 endX/endY、translate manifest `visible_when` 缩进。

### 6.2 测试限制

- 受限工作区测试曾跳过模型管理 71 项（沙箱拒绝真实 AppData 访问）；末轮工作区复测的既有 Taskmgr 图标提取用例间歇失败（根因未定位，本版未改图标提取），不能把末轮全量测试记为通过。
- 原生自动化未取得可操作的开发版 Blink 窗口，设置卡片仅 mock IPC 静态双主题预览。
- **workspace 全量 `cargo test` 的 doctest 链接失败（存量）**：blink-infra 的 `StringTruncateExt` doctest 在全量并行构建下以 rust-lld 链接失败（CRT 符号缺失）；单包 `--doc` 稳定通过，stash 基线全量同样失败——属 rust-lld + workspace 并行 doctest 的环境问题，非代码回归。规避：按包跑；后续可考虑 doctest 加 `no_run` 或回退 link.exe 复查。
