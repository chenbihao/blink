## 二、背景与动机

单 bin crate 的增量验证仍需约 36.8s，拆分使热点域能独立编译测试。后续功能解决了快捷键占用缺少恢复入口、预热复用窗口显示旧配置、长译文被重新放大以及主窗口与 `search_apps` 来源不一致的问题。0.25.10 起因是设置页「检查更新」发现新版本后只能外链到 release 页手动下载安装，应用内无法一键完成。

**架构澄清**：builtins 与多个域相互依赖，留在同一 domain crate 是本版的有意取舍；“常用系统入口”是维护的功能目录，基础应用扫描仍来自开始菜单。配置开启与全局快捷键注册成功分别展示，不能用 checkbox 推断系统注册状态。

## 三、核心决策与维护要点

### 3.1 粗拆 domain，协议错误先独立

拆分顺序为 infra → capability-error/config/local-engine → stt → domain。Capability 协议主体和 builtins 消费多个域服务，随 domain 整体迁入，避免强拆循环依赖。bin 的 `src/{infra,domain}/mod.rs` 保留 re-export shim，旧 `crate::infra::*` / `crate::domain::*` 引用无需改写。

**跨 crate 测试隔离教训**：依赖 crate 不以 `cfg(test)` 编译，原有缓存和引擎目录隔离因此失效。`blink_infra::runtime_mode` 默认隔离缓存与数据目录，生产入口显式 `activate_production()`；拆分同时修正相关测试分支。STT 配置迁移只接收 provider 的 id/kind/base_url 投影，避免 config crate 依赖完整 AI 配置类型。

### 3.2 后端确认值驱动回填，字段 CAS 保护写入

两窗口先订阅 `CONFIG_CHANGED` 再首读，事件和 focus 共用单飞刷新入口；通知是失效信号，只有最新有效读取才能提交共享状态和 DOM。保存、录制及输入草稿暂停回填，结束后补读；初始化与重复回填分离，避免重复监听。

共享分片从最新值合并目标字段，保留未知字段，拒绝损坏配置回写；写入锁、缓存更新与 expected-value 校验覆盖直接 setter、受控设置及绑定适配路径。过期修改返回 `config_conflict`，全量迁移/重置走数据库事务。Chord 开关和动作禁用列表串行保存，下一笔 CAS 使用上一笔已确认基线，旧失败不能回滚较新意图。

自启动在 release 下依次查询原状态、应用并核验系统注册、保存偏好、广播；失败补偿恢复系统原状态，补偿失败明确返回 `autostart_restore_failed`。系统注册与数据库没有共同事务。debug 仅保存偏好并提示此语义。

### 3.3 系统入口按稳定身份合并，启动目标必须明确

常用与发现目录共用稳定 entry_id、独立 history key、别名/拼音匹配和带类型的启动目标；同目标但语义不同的入口保持独立，既有 `.lnk` 路径及旧 history key 保留。账户环境变量使用 `rundll32.exe` 的指定参数，系统环境变量与高级系统设置使用 `SystemPropertiesAdvanced.exe`。

自动发现读取本机 Windows 设置 XML，提供可降级的可靠子集；该目录不是稳定公开协议。明确 DeepLink 经白名单校验；PageID 仅是父级定位，不能据此猜子设置 URI。“磁盘和卷”以已知设置身份映射到 `ms-settings:disksandvolumes`；缺目标、未知条件/HostID/feature、歧义或资源失败项跳过。多份 XML 的同身份标题和关键词在 domain 合并去重，现代与旧格式使用同一 SettingID。

`open_system_entry` 只接受 entry_id，执行时核验当前来源状态与可用性；主窗口和 `search_apps` 共用目录，分别投影为 RunAction 和 Invoke。AI/MCP 默认授权关闭，搜索可见不自动获得执行权限。图标继续懒加载，成功受理主窗口启动后按既有开关记历史。

### 3.4 一键更新选官方 updater 插件，签名与镜像链路自建衔接（0.25.10，已定）

**定案**：集成官方 `tauri-plugin-updater` 2.12（2.13 起要求 tauri ^2.12，与当前 tauri 2.11.5 冲突故锁 2.12.0）；`bundle.createUpdaterArtifacts` 开启，tauri build 自动对 NSIS/MSI 产物产出 minisign `.sig`。公钥嵌入 `tauri.conf.json`；私钥真源为 CI secret `TAURI_SIGNING_PRIVATE_KEY` 与本地 `~/.tauri/blink-updater.key`（空密码），两者不入 Git（`.gitignore` 已挡 `*.key`）——私钥丢失则存量用户无法验签升级，必须长期备份。

**更新源**：静态清单 `releases/latest/download/latest.json` 由 `cargo xtask release`（release profile）生成——读 tauri.conf 版本 + NSIS `.sig` 内容 + 根 Cargo.toml `repository`，CI 随安装包上传。该地址是 release 资产直链，无 api.github.com 匿名限流；**draft 状态不计入 latest，发布 publish 后才对用户生效**。latest.json 内的安装包 URL 固定主站直链（插件不支持资产 URL 镜像改写），代理场景由全局代理覆盖。

**国内网络衔接**：复用 mirrors 代理候选体系——新增 `infra::utils::mirrors::github_proxy_candidates`（latest.json 属 `releases/latest/download/` 重定向形态，既有 `download_candidates` 不识别）；`install_update` 运行时经 `updater_builder()` 覆盖 endpoints 为「主站 → 加速代理」候选链并注入 `_global_proxy`（`.proxy()`）。签名只校验文件字节，与下载源无关，走代理不放宽供应链约束。

**应用侧包装**：前端不直调插件 API，无 updater capability 需求；`install_update` command 内同步完成检查（返回 `no_update` / `started`），下载安装在后台任务执行，进度走 `UPDATE_INSTALL_PROGRESS` 事件（`downloading`/`installing`/`failed`，≥200ms 节流）；互斥标志单飞防重复触发，**检查期所有 `?` 早退路径统一由调用方复位标志**（直接 `?` 会卡死标志导致无法重试）。进度回调参数为 `usize`（内部统一 u64）。debug 构建直接拒绝（未走安装器，覆盖安装不成立）。检查展示仍用既有 `check_update`（保留 release notes 渲染），安装时插件内部再查一次，代价可忽略。

## 四、复用与范围边界

复用既有输入线程控制队列、录制握手、配置库与通知、搜索引擎/fuzzy/历史、Capability 协议、图标协议及 Canvas 渲染。窗口查询只读已发布快照，CLI 一次性查询显式预热。

本版保留 domain 内部循环依赖，不继续细拆 search/ai/config 或下沉 app 服务；未引入全局前端状态框架、通用扫描框架、Windows 搜索私有数据库、桌面/PATH/注册表应用扫描或逐项系统 Capability。外部快捷键占用程序名称无法从注册失败结果取得，反馈只说明占用与可操作的恢复方式。

## 五、分版本实现总结

### 5.1 0.25.1–0.25.4：crate 拆分

拆出 `blink-infra`、`blink-domain-capability`、`blink-domain-config`、`blink-domain-local-engine`、`blink-domain-stt`、`blink-domain`；bin 保留 app/main/cli 与兼容 shim。跨 crate inventory 注册保持完整，面向 bin CLI 的 skill help 测试移至 app；domain 不直接引用 Tauri/Win32，由架构守卫核验。

### 5.2 0.25.5：快捷键设置

Chord 保留 Alt+字母，自定义全局键开放单独 F1–F11，拒绝 F12、裸输入键及未知修饰键；录制、IPC 与注册白名单一致。重试只在输入窗口归属线程注册目标绑定，不注销其他成功项；重复点击合并，过期结果丢弃，录制期间忽略功能项 `WM_HOTKEY`。欢迎页分别显示 Chord 与 Custom，保留已有自定义全局键。

### 5.3 0.25.6：配置同步与失败恢复

自启动、Chord、动作禁用及主热键通过分片通知同步，兼容旧空 payload 和逻辑 key，隐藏窗口再次聚焦补读。配置首读失败结束初始化等待，持续显示错误和重试入口；重试初始化保持单飞，欢迎页导航与退出独立于配置成功，不用默认配置解锁写入。

### 5.4 0.25.7：截图译文排版

共用 `overlay-text-layout.js`：参考字号取 OCR 字号与框高较小值，再乘 0.82 和用户缩放；组内参考字号统一后，每行仍受自身上限和 Canvas 宽高约束，长句独立缩小。字形边界用于垂直居中，普通文本保留 8px 下限，更小原文不强行放大；下限仍放不下才按完整字素省略。原文/译文与后台快照共用排版，OCR 框及完整文本保持原契约。

### 5.5 0.25.8：应用搜索与发现生命周期

应用搜索总开关统一控制基础与增强来源；基础开始菜单无独立开关，UWP 和常用系统入口默认开，自动发现默认关，三个增强选项相互独立。总开关关闭停止召回与新扫描，子选项保留；系统增强变更不触发无关开始菜单重扫。配置使用 `engine:start_menu`，兼容旧逻辑 key。

37 项常用定义按系统版本、程序和硬件可用性过滤。自动发现最多解析 16 个文件、每个 8MiB，资源通过 Windows 资源接口解析；默认关闭不读目录。后台单飞构建通过 generation 与目录指纹核验提交，语言/目录变化或手动重试重建，开启时每 5 分钟检查；额外项数量按当前来源合并后统计。同步 IPC 曾因无 Tokio runtime 调度发现任务崩溃，已改为 async，并补异步契约测试和启动语言初始化修复。

### 5.6 0.25.9：rig 0.43 升级

rig 0.43（20260930）延续 0.42 的拆分方向，把运行时继续拆成独立 crate：agent run protocol 拆出 sans-IO 的 `rig-run`，MCP tool 集成从 rig-agent 拆出 `rig-rmcp`（rig-agent 0.43 不再有 `rmcp` feature），默认 HTTP transport 拆出 `rig-reqwest`（rig-core 不再自带 reqwest/tokio）；`Usage` 计数 Option 化（各 provider 语义统一）。0.42 时代"rmcp feature 已转移到 rig-agent"的依赖注释过期；拆分属于上游结构性方向，版本差距越大升级成本越高，故立专项跟进。

**迁移口径**：

- **只做 API 迁移，不引入新架构**：不接 `rig-run` 状态机，ChatService / AgentProvider / AgentCacheKey 结构不变；rig 隔离墙不变——全项目 rig 触点仍收敛在 `domain::ai`、`infra::utils::http_log`、`ToolSchema::to_rig_tool` 三处。
- **MCP 集成迁移到 `rig-rmcp` crate**：`AgentBuilder::rmcp_tools` 路径移除，改为 `rig_rmcp::McpTool::from_mcp_server(tool, sink).into()` 逐个转 `DynamicTool` 注册（默认携带 rig-rmcp 的 300s 单次调用超时）；rmcp 2.x 依赖与传输 feature 集不变。
- **模型句柄去泛型**：rig 0.43 以 `Model<W>`（wire+transport 对）+ `DynModel<Completion>`（擦除句柄）取代非 object-safe 的 `CompletionModel` trait。`RigProvider` 由泛型 `RigProvider<M>` 变为具体类型持 `DynModel<Completion>`；四种 provider client（`OpenAI/Anthropic/Gemini/Ollama`）不再携带 HTTP 泛型参数，factory 统一 `.completion(id).into()` 擦除。
- **Usage Option 归一**：rig 计数变 `Option<u64>`（None = 未报告）。`message::Usage::from_rig_usage` 是全仓唯一映射点，`None` 归零、`reported` 改用 `is_reported()`（任一计数 Some 即已报告），"未报告 ≠ 真实零"哨兵语义保持，`ChatStreamChunk::Done` 对前端的 JSON 契约不变。
- **LoggingHttpClient 迁至 rig-reqwest**：`http_log.rs` 继续自实现 `HttpClientExt`，内核由裸 `reqwest::Client` 换为 `rig_reqwest::ReqwestClient`（进程共享连接池，`send_multipart` 委托其 trait 实现）；非 2xx 错误改用 `InvalidStatusCodeWithDetails{status, body, headers}` 三元组。
- **流式事件模型换轨**：`MultiTurnStreamItem` 改为 `StreamAssistantItem(Item<StreamEvent>)` + 专用 `ToolCall`/`ToolExecutionCommitted`/`CompletionCall`/`ModelTurnRetried` 变体。文本/思考增量从 `StreamEvent::Text/Reasoning` 取；tool call 从专用变体取（不再从 delta 拼装）；整块定型的 Reasoning part（`End` 事件）转一条完整 Thinking；`agent.stream_prompt()` 改为 `agent.prompt(Message::user(..)) → AgentRunner → .stream()`（同步构造 lazy 流，原"建连超时"阶段并入首个 item 的 idle timeout）。
- **Reasoning 签发方（Sealed）语义**：0.43 起思考块由来源 provider 签名（重放时只有签发方打开）。本地拼接的实况部分回复用 `Issuer::from("blink")` 签发——崩溃恢复后该部分思考不回传模型（provider 不打开），文本仍完整落库并回显 UI；rig 自身产出的思考块经 SQLite JSON 序列化后 issuer 原样保留、重放正常。
- **CompletionRequest 无 preamble 字段**：system 以 `Message::System` 置于 `chat_history` 首；`Message::tool_result` 显式接 `CallId + ToolName`（空名在 try_from 处拒绝）。

### 5.7 0.25.10：应用内一键更新

后端注册 updater 插件并新增 `install_update` 命令（含 `global_proxy_url` 从 check_update 提取共用）；前端关于页新增「一键更新」按钮与下载进度条（`UPDATE_INSTALL_PROGRESS` 单事件承载阶段与字节进度，total 未知退化为不确定态动画 + 已下载字节数），zh/en 文案齐备；错误文案入口 `friendlyUpdateError` 增加「更新失败」动作前缀与签名失败识别。发布链路上 `cargo xtask release` 新增第 N 步生成 `latest.json`（仅 release profile），xtask 自动从 `~/.tauri/blink-updater.key` 注入签名私钥（环境变量优先），CI 注入 secret 并上传 `latest.json`。事件常量两端同步（`EventNames::UPDATE_INSTALL_PROGRESS` ↔ `event-names.js`）。`gen/schemas/` 为 tauri-build 自动再生成（updater 插件 ACL schema 入树，随本版提交）。
