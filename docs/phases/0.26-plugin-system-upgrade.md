## 二、背景与动机

原天气插件每次按名称取首个城市，地点身份不稳定；查询、配置、供应商与展示逻辑耦合，缺少一致的预算、取消和缓存。此次以确定地点和统一天气服务为中心补齐三家来源，并把公共配置与进程链路的缺口收敛到宿主。

**维护澄清**：插件已有宿主配置注入、HTTP 代理及 Capability 注册，不需要自行读取数据库、直连网络或新增执行入口；确认地点也不需要引入完整城市/GIS 数据库。

## 三、核心设计与维护要点

### 3.1 地点与天气分责

LocationResolver 和 WeatherProvider 通过 ResolvedLocation 连接，Query/ToolCall 共用 WeatherService。地点保留原始坐标、坐标系及来源身份，供应商只派生请求坐标；和风 Location ID、Open-Meteo ID 与 adcode 不互换。

请求位置优先级为显式 city/location → default_location → 兼容 default_city；city/location 互斥。显式 unit 优先于设置；确认坐标跳过地名搜索。严格匹配且唯一时才直接查询，模糊或多候选返回 needs_location，不按首项或人口自动确认。候选不会隐式改写默认地点。

彩云大陆请求使用 GCJ-02，其他地区使用 WGS84。区域证据来自解析器国家码、可信和风国家与省级行政区，或用户显式声明；显式声明优先，未知仍要求确认。旧和风保存值可恢复明确的区域证据，不用地名、时区或粗矩形猜测国界；坐标转换不回写原值。

### 3.2 配置与凭据

继续使用既有插件配置存储，结构化 default_location 与普通字段按补丁保存。普通控件、触发词和密钥清除共用写入队列；地点草稿单独提交。冲突保留草稿并提供主动重载，不让陈旧保存覆盖其他操作。

天气/翻译凭据组默认收起，显示字段完整度、申请链接及移除空格提示。和风 API Key、彩云 App Secret 使用系统凭据管理器；彩云 App Key 是普通可见配置，开发期旧 CM 值不自动迁移。通用配置与密钥提交契约见 [spec-backend §7.6](../specs/spec-backend.md#76-插件配置与密钥提交强制)。

### 3.3 供应商与结果契约

- **Open-Meteo**：current + daily，完整 WMO 映射；96/99 为雷暴伴冰雹，逐日描述表示当天最严重现象。
- **和风天气**：账号专属 Host + API Key；Host 接受裸域名或 HTTPS 根地址。GeoAPI 与天气 v1 分开解析，实况/逐日并行、纬度在前、当地时间输出；路径不附加多余斜杠，逐日描述区分白天与夜间。
- **彩云天气**：v2.6 综合接口、metric:v2 与最多 7 天逐日；App Secret 生成 HMAC-SHA256/URL-safe Base64 签名，签名和 URL 使用同一份编码。App Key 在路径，签名请求拒绝重定向；实际天数与权限以账号返回为准。

统一 WeatherSnapshot 保留 location、provider、current/daily、有效时间、原始天气代码、warnings 和 attributions。逐日数组按日期关联，不按下标硬拼；缺失值不补为 0 或晴天，日期按来源时区解释。

get_weather 保持单元素 raw 数组及既有工具 ID，新增 status/summary/结构化地点与来源时间：ok 为完整天气，partial 为部分可用，needs_location 仅含候选。search_locations 只返回候选，不写配置。复制动作使用完整摘要，来源声明通过受限 HTTPS 链接打开；国内地址按国家/省/市/区县排列，时间格式化并保留来源时区。

### 3.4 缓存、取消与显式降级

地点缓存 128 条/6 小时/1 MiB，天气缓存 64 条/5 分钟/4 MiB；TTL、LRU、容量和权重共同限界。只缓存非空有效候选与完整天气；partial、错误及降级结果不缓存，不后台刷新或用过期天气兜底。

缓存键包含来源、位置/坐标系/区域、请求能力/时区和配置代次/摘要；统一数值可跨单位复用，结果保留原获取时间。换密钥、Host 或其他配置使旧代次失效，迟到请求不能回填新缓存。

最多 4 个 producer，每个最多 8 个等待者；只合并已有 transport 期限能够覆盖的新调用。等待者独立取消，最后一个退出才停止续发。已发出的宿主 HTTP 仍可能执行至原超时，取消不保证停止上游计费。

自动降级默认关闭，开启后按用户顺序尝试已配置来源，共用原预算和取消状态；已有 partial 直接返回，不混合或替换来源。通用执行契约见 [spec-backend §4.4](../specs/spec-backend.md#44-插件执行契约强制)。

## 五、子版本实现总结

### 5.1 0.26.0 — 公共底座（✅）

### 5.2 0.26.1 — 地点闭环（✅）

新增 search_locations 与卡片内地点编辑器，支持限定搜索、候选确认、手工坐标和明确清除。默认地点持久化，参数覆盖规则统一；配置补丁、CAS 与密钥失败恢复保护结构化设置和跨窗口操作。

### 5.3 0.26.2 — 和风天气（✅）

接入 Host/Key、GeoAPI 和天气 v1 实况/逐日，统一并行聚合、单位、日期、错误与来源声明。解析来源可显式选择，切换天气来源保持已保存地点。

### 5.4 0.26.3 — 彩云天气（✅）

接入 v2.6 签名、区域坐标派生和综合 DTO；签名与实际发送参数同源，缺失数据/权限不足明确反馈。无和风账号也能使用 Open-Meteo 候选或手工地点查询彩云。

### 5.5 0.26.4 — 缓存与稳定性（✅）

新增有界缓存、预算兼容的请求合并与独立等待者取消，配置代次隔离旧结果。收敛 service/pipeline 职责，修复和风并行请求与单侧失败 partial，并保护禁用或改配置后的主搜索迟到回写。

### 5.6 0.26.5 — 配置与公共交互（✅）

统一天气/翻译凭据分组、自动保存、移除空格提示及页面状态保留，彩云 App Key 改为普通字段。加入显式顺序降级，修正和风路径/Host、旧地点区域证据、中文来源名及时间/国内地址格式；剪贴板悬浮显示完整正文，错误项支持全文预览与右键复制。中英文指南新增独立“插件使用”章，申请链接旁统一使用“每月免费额度”简短文案。


### 5.7 0.26.6 — IP 网卡与多出口（🚧 已实现，待体验）

以原 get_ip/JSONL/宿主 HTTP 为入口，拆分网卡快照、配置、检测来源、状态机与展示。Windows 通过 GetAdaptersAddresses 枚举物理网卡地址，不再把通往 Google DNS 的单个源地址当作局域网 IP。“增强网络信息”默认关闭；开启后才采集网关、隧道/其他虚拟网卡地址与系统代理状态，查询与工具展示共同遵守该开关。旧 show_virtual 不自动开启增强功能。

国内来源 IPIP → 公云 3322 → 花生壳，国际 IPv4 默认来源 ifconfig.co → ipify（优先提供归属地，保留已有自定义顺序）；各组顺序可拖动、降级可关闭，成功即停止，同址合并并保留各组来源。所有接口使用 HTTPS；归属地仅使用检测回包已有字段，不与出口检测绑定额外定位服务。IPv6 查询默认关闭；开启后独立检测一组 IPv6 出口，默认 test-ipv6.com → ipify；不再区分国内/国际，移除 IPW/IPIP IPv6 检测链及两套旧排序项，统一使用 ipv6_order。旧区域 IPv6 顺序不再参与检测，新默认优先 test-ipv6.com；IPv4 自定义顺序保持原样。test-ipv6.com 使用 HTTPS IPv6-only 查询入口，严格解析固定 JSONP 包装并核对 type/ip，不执行脚本，错误地址族不能当成功；请求间隔限制为 60 秒。IPv4 国内/国际与单组 IPv6 分别续发与缓存；外部地址严格校验为对应类型的公网地址，私网、共享地址、保留地址、地址族不符及格式异常不能当成功。

结果复用 60 秒，普通结果不显示获取日期，缓存显示“缓存于 HH:mm”（跨日补日期）；完整 RFC 3339 获取时间保留在工具数据中，显示遵循 [spec-frontend §3.5](../specs/spec-frontend.md#35-用户可见日期与时间强制)。ip refresh 主动刷新仍遵守来源最小间隔，公云/ifconfig.co/test-ipv6.com 为 60 秒。来源配置或网卡/代理快照变化后不复用旧结果，纯显示选项变化只重新展示，增强开关切换重新采集快照；失败与过期结果不伪装成功。最多三组并发、组内按序续发，共用宿主剩余预算，取消清理 pending 并丢弃迟到响应；时间不足保留本机和已成功组，明确缺失组。ip local 只查本机，兼容旧 geo_provider=none 的离线选择。

IPv4 结果优先，随后为各一个有效非临时和临时本机 IPv6、IPv6 出口，最后为增强详情；查询与工具顺序一致。Windows 同时检查 DAD 状态与地址寿命，ValidLifetime=0 的地址丢弃；默认分别从有效且 PreferredLifetime>0 的物理地址中选取一个非临时和一个临时 IPv6，优先公网范围与低 metric，其余有效地址仅在增强信息中显示，增强模式中额外地址标为“其他”，仍有效但已弃用的地址在标题明确标记。快照只存寿命状态，避免倒计时导致缓存持续失效；开启 IPv6 保留可复用的 IPv4 缓存，关闭后不发起 IPv6 请求。

**范围边界**：本机 IPv6 展示不等于公网可达验证；IPv6 检测失败不回填 IPv4，不据此断言本机未配置 IPv6；ifconfig.co 为双栈接口，本版未将其作为强制 IPv6 来源；检测站位置不保证直连/代理属性，TUN 可在跳过 HTTP 代理后继续接管。多级 NAT 只留后续诊断方向，本版不自动探测路由器。
