## 二、背景与动机
  
原天气插件地点身份不稳定，供应商、配置与展示耦合，预算/取消/缓存缺乏统一契约。本版以确定地点和统一天气服务接入三家来源，并补齐宿主配置、进程与公共交互。

**维护澄清**：宿主已有配置注入、HTTP 代理和 Capability 注册；插件无需自行读库、直连网络或新增执行入口，地点确认也无需引入完整城市/GIS 库。

## 三、核心设计与维护要点

### 3.1 地点与天气分责

LocationResolver 与 WeatherProvider 通过 ResolvedLocation 连接，Query/ToolCall 共用 WeatherService。显式 city/location → default_location → 兼容 default_city；city/location 互斥，显式单位优先。严格匹配且唯一才自动查询，其余返回 needs_location；候选和 search_locations 均不隐式修改默认地点。

地点保存原坐标、坐标系和来源身份，供应商只派生请求坐标；和风 Location ID、Open-Meteo ID、adcode 不互换。彩云大陆使用 GCJ-02、其他地区 WGS84；区域依解析器证据或用户显式声明，未知需确认，不用地名、时区或粗矩形猜国界，转换不回写原值。

### 3.2 供应商与结果

- **Open-Meteo**：current + daily，完整 WMO 映射；96/99 为雷暴伴冰雹，逐日描述表示当天最严重现象。
- **和风**：账号专属 Host + API Key，Host 接受裸域名或 HTTPS 根地址；GeoAPI 与天气 v1 分开解析，实况/逐日并行、纬度在前，路径不额外加斜杠，逐日区分昼夜。
- **彩云**：v2.6 综合接口、metric:v2、最多 7 天逐日；App Secret 生成 HMAC-SHA256/URL-safe Base64 签名，签名与 URL 编码同源，签名请求拒绝重定向。实际天数以账号权限为准。

统一模型保留地点、来源、有效时间、原始天气代码、warnings 与 attributions；逐日按日期关联，缺失不补为 0/晴天。get_weather 保持单元素 raw 数组和工具 ID，status 区分 ok/partial/needs_location；复制完整摘要，来源链接限 HTTPS，天气时间保留来源时区。

### 3.3 配置、缓存与取消

结构化地点按补丁保存，地点草稿独立提交；普通字段、触发词和密钥清除共用写队列，冲突保留草稿并提供主动重载。跨窗口刷新可在编辑期间延后，焦点离开后补刷新。和风 Key、彩云 Secret 进入 CM；彩云 App Key 为普通字段，开发期旧 CM 值不自动迁移。提交契约见 [后端 spec §7.6](../specs/spec-backend.md#76-插件配置与密钥提交强制)。

地点与天气缓存分别有 TTL/LRU/容量/权重上限；只缓存有效候选与完整天气，partial、错误、降级结果不缓存。键包含来源、坐标/区域/时区及配置代次，旧代次不能回填新缓存。最多 4 个 producer、每个 8 个等待者，仅合并 transport 期限覆盖新调用的请求，等待者独立取消。

自动降级默认关闭，开启后按用户顺序尝试已配置来源，共用原预算；partial 直接返回，不混合来源。排队时间计入预算；取消阻止续发，已发宿主 HTTP 可能执行至原超时，不保证停止上游计费。通用契约见 [后端 spec §4.4](../specs/spec-backend.md#44-插件执行契约强制)。

### 3.4 IP 地址与出口

本机地址来自 GetAdaptersAddresses，出口来自站点实际观察；临时/非临时 IPv6 可同时有效，字符串长短不代表优先级。默认只采集物理地址；增强开关默认关闭，开启才采集网关、隧道/虚拟网卡及代理详情。DAD 与寿命过滤无效地址，优先有效且 preferred 的物理地址；临时 IPv6 按 SuffixOrigin 识别，TRANSIENT 是集群标记。

IPv4 国内默认 IPIP → 公云 3322 → 花生壳，国际默认 ifconfig.co → ipify；IPv6 为单组 test-ipv6.com → ipify IPv6，默认关闭。各组独立、组内按序，允许排序和关闭降级；旧区域 IPv6 排序不再生效。只接受对应地址族的公网回包，test-ipv6 的 JSONP 只解析固定包装，不执行脚本。

结果复用 60 秒，网卡/代理快照或检测配置变化即失效，纯显示选项不清缓存；开启 IPv6 保留 IPv4 缓存。ip local 离线查询不清掉已成功的出口缓存；ip refresh 仍遵守来源间隔（公云/ifconfig.co/test-ipv6.com 为 60 秒），间隔内优先显示有效缓存，无缓存则明确本次未请求及剩余等待时间。首次失败/取消也不绕过来源节流，过期或迟到结果不伪装成功。

查询与工具顺序一致：本机 IPv4 → IPv4 出口 → 本机非临时/临时 IPv6 → IPv6 出口 → 增强详情。IPv6 失败不回填 IPv4，也不能据此断言没有 IPv6 出网能力；单组只代表所用站点的观测，其他目标的源地址/代理分流可能不同，TUN 仍可接管流量。

### 3.5 主窗口统一列表导航

偏好迁入 app.search.wheel_mode（step/page，默认 step），通用设置为唯一入口；新字段优先，否则承接有效旧值。初始化以双分片 CAS 事务落库并移除旧字段，幂等且保留未知字段；读取失败或损坏配置报错，不覆盖原记录，不在搜索热路径迁移。

list-navigation.js 统一滚轮单位/余量/反向/上下文复位；方向键逐条，PgUp/PgDn 整屏，Alt+数字映射当前视口。热切偏好保留视口/高亮/多选/已加载数据，末页向下不倒退；状态栏按真实视口投影，流式未完显示已加载量 `+`。通用交互约束见 [前端 spec](../specs/spec-frontend.md)。

## 四、复用与范围边界

复用 PluginConfig/CM/配置广播、CapabilityRegistry、JSONL/宿主 HTTP、projection/Copy/open_url，以及通用控件、i18n、token 和 Lucide。新增能力仍归既有执行与展示链路。

本版不含自动定位、地图/GIS、多城市收藏、分钟降雨/AQI/预警、AI 改默认地点、持久化天气缓存、后台轮询、插件市场/沙箱、局域网扫描、代理/路由修改或 NAT 层级推断。0.27.4 全局网络改造承接本版 HTTP、配置与错误契约。

0.26.22 复用既有长截图追踪/重定位、防错拼、回放、坐标换算和公共图片编辑/输出链路；其决策、范围边界与实施顺序统一见 §5.23。

### 5.9 0.26.8 — 悬浮预览与列表展示

列表去掉 60 字截断：仅本批返回项读取有界正文前缀与真实字数（候选仍匹配原摘要），前端按列宽省略、全文按需读取。文字/错误/图片条目统一左侧三分之一触发预览（停留 350ms、离开 150ms 缓冲、经过其他行不关闭），浮窗跟随结果行两侧对齐并做视口避让；通用 hover 约束见 [前端 spec §5.3](../specs/spec-frontend.md#53-悬浮层留消失延迟强制)。

预览文本支持拖选与 Ctrl+C/Ctrl+A，点击预览才取键盘焦点，Esc 关闭归还搜索框；右键复用所属条目 itemMenu，文本选区只覆盖复制，菜单会话与预览生命周期绑定（打开持有快照，取消/执行/失败均释放，旧菜单通知不释放新预览）。图片预览读取限并发 2，与正文回流共同校验 revision/锚点/连接，迟到图片不覆盖新条目。副行悬浮提示仅在标题被截断时幂等追加。

### 5.10 0.26.9 — 剪贴板文件条目

采集→路径历史→写回→删除/清理闭环 + 本地 PNG 预览/入库。要点：监听器**单次 OpenClipboard 快照**按「有效文本 → 开启的 DIB → 开启的 HDROP」选一类入库，多格式不混入另一轮复制；DROPFILES 编解码纯函数收敛在 `platform/clipboard/dropfiles.rs`（UTF-16 双 NUL / 路径形态判定 / 1MiB 序列化上限）；路径历史新表 `clipboard_files`（去重哈希核对防碰撞 + 条数/载荷双上限淘汰）；写回按复制语义不继承剪切标记；三个复制/入库 Capability 绑定条目引用查库，不接受 UI 任意路径。预览走 `blink-clipimg /file-preview/<条目id>`：仅单路径 + `fs_guard` 受限路径防御（UNC/网络盘/云占位/重解析点，探测不触发下载）+ 独立文件 I/O 通道（并发 2、无排队、1s 等待超时不取消底层任务）+ PNG magic 白名单；多文件只展示 DB 路径列表，失败原因分类展示。

### 5.11 0.26.10 — 剪贴板条目右键智能操作

### 5.12 0.26.11 — 剪贴板文件独立筛选与多格式原图预览

### 5.15 0.26.14 — 托管 Everything 运行时（内置文件搜索引擎）

用户未安装 Everything 时，设置页一键按需下载受管 Everything 1.4 stable 便携版作为 blink 专属实例；FileEngine 的 HTTP 查询路径零改动，改动面为 data_source 优先级链与实例生命周期。

**路线决策**：① 只做托管运行时不自研索引（MFT/USN 需 SYSTEM 服务 + 管理员 + 约两万行长尾工程；Everything MIT 许可允许分发，关于页附 MIT + PCRE BSD-3 声明）；② 按需下载不捆绑（沿 asset-lock 模式锁 URL+sha256+size+MZ 头校验，装 `%APPDATA%\blink\runtimes\` 与 PATH 隔离；不锁 1.5 beta——IPC 协议迁移中）；③ 提权显式同意（默认不提权，Everything 未提权退化慢扫仍可用；UAC 仅设置页显式按钮触发）；④ 查询走 HTTP 不引 everything-ipc（reqwest 零新增依赖、localhost 毫秒级；everything-sdk 为 GPL 永久排除）。

**实机踩坑（关键维护知识）**：① `-hide` 不是 Everything 1.4.1 合法开关（弹错误模态框后 exit 1），后台静默启动用 `-startup`；② 专属 ini **必须带 `[Everything]` 段头**，否则全部键被标准 INI 解析忽略（HTTP 不启动）；③ 监督循环**state 锁内零长等待**——首版在锁内 `child.wait()` 挂整个进程生命周期，`stop()` 抢不到锁静默死锁；重构为就绪等待与监督均无锁轮询 + run_id 轮次令牌，`stop()` 经 CancellationToken 即时打断；④ 实例**启动即拉起**而非纯懒启动——纯懒启动在 app 重启/dev 热重载后表现为「装好的引擎消失了」，用户拿托管端口去探测用户实例而扑空；⑤ 用户/托管端口语义拆开分立配置（托管默认 52819、占用向上扫 20），避免混用误配。

**归属与状态**：启动先恢复遗留命名实例（同持有句柄核对 exe 路径后请求正常退出，超时仅终止已验证句柄）再判是否复用外部 Everything，防止同端口把旧托管实例认成外部来源；运行中用户实例状态与 auto 链统一排除托管实例实际端口——HTTP 有响应不能取代归属判断。`file_search` 保存改补丁合并（防 local_*/managed_* 字段被整结构覆盖重置）；auto 链如实区分「不可用」与「应答但 0 匹配」（索引未建完）。子进程加 kill-on-close Job Object；专属 INI 只覆盖 Blink 管理的连接/后台键，保留卷信息防每次启动覆盖索引配置。设置页用户/托管两区块收敛单一 `get_file_search_status` 聚合状态面（一次 invoke + 单一重新探测 + 3s 只读轮询）。

### 5.18 0.26.17 — IP 插件流控与参数提示协议

**流控止血**：ip manifest 补 `debounce_ms: 500` + `concurrency: 1→4`。根因：后端 per-plugin 防抖缺省 0 = 每键真实触发（前端仅 40ms 合并）；concurrency=1 下首个数秒出口检测占死唯一信号量槽位，逐键查询被宿主以 Busy 立即拒绝。防抖落地后打字中间态不再 Busy，最终失败仍如实显示错误行（不静默吞错）。

**args.hints 协议（通用能力）**：manifest 顶层 `args.hints: [{value, aliases, desc}]`（desc 双语；未列字段 serde 忽略，旧宿主兼容），本版仅 IP 声明（天气自由参数不适用枚举）。宿主两路消费：**列表引导项**（keyword 命中且 arg 为空或前缀时合成可执行条目，参数合法性提示前置到宿主，不再依赖插件报错兜底）+ **Ghost 前缀补全**（豁免「精确+尾空格不出 hint」规则，Tab 采纳回写 `{keyword} {value} ` 走既有 completion 通道）。**Router 是唯一真源**：hints 经 `args_hints` 表与 keyword 规则 join 成 `ArgHintRule`，两路同源；引导项回写注册原文 keyword（拼音/别名命中也回规范形式）；main.rs 对全部插件注册（含禁用——禁用过滤由规则移除承载，跳过注册会让「启动时禁用后来启用」的插件拿不到 hints）。语义要点：`resolve_surface(Auto, Exact)` = Priority 混排——裸 `ip `/`ip` 的引导项来自 Mixed 路径，带参 `ip r` 才是 Takeover，两路共用 `arg_guide_entries`；新增 `ActionKind::Route`（前端回写输入框 + 光标置尾 + 显式滚到末尾派发新搜索，spec-frontend §5.8）；引导项分数 0.3（低于真实结果与占位、高于错误行）。

**踩坑（0.26.20 修复）**：引导项与占位同 source 且非占位——前端「迟到占位丢弃」原扫全量 allItems，把同批引导项当「真实结果已到」误丢占位（裸 `ip ` 无转圈，Mixed 批顺序 guides → placeholder 所致；Takeover 占位在前不受影响）；判定改为只看**本批之前**已入列的真实结果（spec-backend §4.4 / spec-frontend §5.1）。

### 5.22 0.26.21 — 浏览器搜索引擎导入与超链列表滚动（已实施）

**数据源（本机 Chrome 实测）**：Chromium 系（chrome/edge/brave）每 profile 的 `Web Data` SQLite 库 `keywords` 表承载全部站点搜索引擎，本机 28 条样本覆盖三类形态——默认引擎（prepopulate_id≠0）、starter pack 内部搜索（`@书签`/`@历史` 等 chrome:// 协议项）、OpenSearch 自动发现的站点搜索（导入主体价值）。占位符为 TemplateURL 语法 `{searchTerms}`，与 blink `{query}` 单占位符模型同构。0.26.12 明确推迟的「导入导出」本版补导入半边。

**导入=只读扫描+既有保存链路合并（已定）**：新增只读 command `scan_browser_search_engines(browser, profile)` 返回候选与状态；确认导入由前端把勾选条目并进 `config.entries` 走既有 `saveConfig("weblinks")`——keyword 冲突校验/CAS/热更新/广播单写路径零分叉，失败回滚语义与逐条编辑一致。否决「后端 import command 直接写分片」：第二写路径必复制校验与回滚逻辑，且绕过前端编辑态。

**扫描路径**：复用 0.26.13 的 `browser_user_data_dir` 与 `parse_local_state_profiles`（均已是 pub，零提取）→ 复制 `Web Data` 至临时目录再只读打开（Chrome 运行中持有句柄，Windows 直开原文件不可靠；Web Data 为 journal 模式非 WAL，单文件复制即安全，本机实测通过）→ SELECT 仅取需要的列（short_name/keyword/url/prepopulate_id/starter_pack_id/created_by_policy）→ 纯函数转换。SQLite 只读打开落 app 层 command（domain 不引 sqlx，不为一次性读扩 infra 公共 API）；转换/过滤/判重纯函数落 domain 新模块，fixture 用本机真实样本。

**TemplateURL→`{query}` 映射（逐条实测）**：`{searchTerms}`→`{query}`；`{inputEncoding}`→`utf-8`（百度/搜狗在用）；`{xxx?}` 可选 token 删除（torrents 站 `page={startPage?}`）；`{google:baseURL}`→`https://www.google.com/`；HTML 实体反转义（`&amp;`→`&`）。过滤：非 http(s) 跳过（chrome:// starter pack）；替换后仍残留 `{`/`}` 的标记「模板不支持」不可导入（Google 默认引擎的 `{google:RLZ}` 等高级 token——种子表已含 Google，无损失）。`home_url` 留空由既有 origin 推导补齐；`favicon_url` 不消费（沿 0.26.12 决策）。判重以 keyword（大小写不敏感）对既有表+批内；URL 相同 keyword 不同（Chrome 允许并存，实测本机 Gumroad×2）按 keyword 判即可。

**UI（复用 0.26.12 modal 模式）**：超链工具栏「从浏览器导入」→ 弹窗选浏览器（仅列检测到 `Web Data` 者；多 profile 时选 profile，切换浏览器即时重扫——重建选项时保留选中值）→ 预览清单每条勾选框+状态（可导入/跳过-原因/keyword 冲突），keyword 预览内可编辑（Chrome keyword 多为域名风格如 `linux.do`，或需改短词）；列表上方三态主复选框「全选」+「反选」按钮（只作用于可导入行）→ 确认合并保存，冲突复用既有逐条标红。复选框走全局 `.checkbox` 组件、关键词输入走 `input-small` 主题样式（用户反馈：原生控件样式不合主题）。

**列表滚动**：筛选与 A–Z 拼音排序已有（0.26.15），`.weblinks-list` 补 max-height（约 40vh）+ overflow-y:auto（与 `weblinks-editor-body` 同风格）与工具栏条数计数；不做排序切换（筛选已够用，避免过度工程）。

**实现要点**：命令对 `list_browser_search_sources`（仅列检测到 `Web Data` 的浏览器×profile，profile 枚举/复制/查询均 `spawn_blocking` 隔离）+ `scan_browser_search_engines`（临时副本 + Drop 守卫清理 + usage_count 降序最常用在前）；前端 `importSeq` 会话守卫丢弃迟到扫描响应（切浏览器/重扫/关弹窗），`enqueueSave` 从 persistConfig 提取为共享串行保存队列；导入保存的 keyword 冲突详情显示在导入弹窗内（主列表错误区被遮罩挡住），失败 `load()` 回滚乐观状态、预览行保留供改词重试。

**用户反馈修复（0.26.21 实测）**：删除条目后列表不刷新——**0.26.12 起存量 bug**（删除处理只改数据走保存链路，普通状态下渲染仅经编辑弹窗 closeEditor 间接触发；残留行重复点击成为空操作保存，日志特征为反复 `entries=N` 同值），删除处理补 `render()`；其余反馈（预览控件套主题组件、全选/反选、切换浏览器不重扫）见上。

### 5.23 0.26.22 — 长截图连续采集重构与技术债清理（R1 实施中）

**目标**：以微信长截图的连续滚动手感为体验参照，让用户正常滚动时无需主动停下来等待识别，已确认长图持续增长；滚完立即完成能够可靠收尾。微信仅作为体验参照，不假设其内部算法。R0/R1 已开工；以下目标尚未整体验收，不能视为已实现或性能承诺。

**审查基线（2026-10-22，R0 开工前）**：当时链路是「滚轮转发 → 防抖 → 灰度探针等稳定 → 完整抓帧 → 匹配/重定位 → 确认提交 → 预览」。手动路径的 45ms 防抖、35ms 初始等待及 90/180ms 稳定门槛，形成约 170/260ms 的等待起点，尚未计抓屏/IPC/算法成本；稳定探针可等到 900ms 超时，新滚轮还会重启等待或使完整帧过期。等待期间不保留完整中间帧，停下时与上一确认帧的重叠可能已不足。上述时间来自源码推导，尚无本轮真机性能基线。

**已有保护应保留**：0.24.10 已落地鲁棒相邻匹配、信息量感知的 unchanged 判断与歧义守门，不重复立项；绝对坐标、关键帧/内容分区重定位、历史像素复核、低置信拒绝和双向去重仍是正确性基础。纯像素完全无重叠或完全周期内容不可凭猜测补齐。既有 10 个长截图测试文件在本轮 review 中通过，但合成回放与等待阈值测试不等同于连续输入的实机验收。

#### 5.23.1 方案取舍与目标边界

| 方案 | 本版安排 | 理由 |
|---|---|---|
| A：缩短等待、修收尾、匹配离开 UI 线程 | 正确性修复作为前置；单纯调阈值不作为最终交付 | 无法解决等待期间中间帧缺失与重叠不足 |
| B：连续采集、有界缓冲、连续追踪、可靠提交 | **本版规划主线** | 同时改善响应与定位成功率；与既有防错拼规则兼容 |
| C：应用专用捕获/滚动位置先验 | 后续候选，不作为本版验收依赖 | 覆盖面与维护成本需要单独验证 |

拟将 [0.15 §3.2](./0.15-screenshot-redesign.md) 的「前端等待稳定后抓帧」替换为连续采集模型；在本版实施验收前，0.15 仍描述当前实现。正常路径不再以全画面静止为前提，稳定性改为质量与收尾信号；只有可靠定位和像素证据才能推进确认结果。

1. **采集与输入解耦**：进入采集后持续观察画面，运动时提高采样频率、静止时降频；滚轮只提供意图/方向参考。先以约 30fps 为采集实验起点，最终频率由实测成本决定。不能因新滚轮到来而一律丢掉仍可定位的中间帧。
2. **缓冲保连续性**：缓冲有字节/帧数上限，保留连接已确认内容所需的中间帧；禁止简单「只留最新帧」破坏重叠。积压时自动滚动减速；手动快滚超出可恢复范围则提示并保留已确认内容，不静默漏段。
3. **追踪与提交分离**：连续观测更新候选位置；高置信路径及时提交，有歧义时跨帧验证。预览区分当前位置与已确认范围，预测不能冒充已捕获内容；正式图像只有一个串行提交者，避免多条状态流。
4. **计算与平台分层**：匹配/大像素处理离开 UI 线程。目标由 app 会话服务编排、domain 承载框架无关的追踪/提交规则、infra 提供采集与输入平台接口；保持 Interaction 语义，不新建平行 Capability 执行入口。可先把现有 JS 算法移入原生模块 Worker 验证模型（无 bundler），再按回放对拍收敛 Rust 实现；不能长期维护两套生产算法真源。
5. **结束有明确截止点**：停止接受新控制输入/停止自动注入，收尾采集并处理至截止帧，然后冻结结果进入编辑/输出。截止点需覆盖已发生滚动的末段；收尾等待有界，无法确认则明确提示未确认尾部，不能静默丢弃或猜测提交。取消仍可立即失效并清理。
6. **输入与 UI 生命周期统一**：穿透开启/恢复绑定 session 代际，旧后台任务不得修改新会话。验证采集区域持续穿透、工具栏与预览独立交互的可行性；同时覆盖排除捕获引起的 WebView 呈现停摆、焦点和 DPI，不把现有「先摆 UI 再设排除」当作持续呈现已解决。
7. **资源按实际使用治理**：帧缓冲、图像分块、缩略预览、编辑与编码统一预算；采集期不长期复制整张原图作预览。双向高度按投影后 `bottom - top` 计算，限额通过后再原子提交坐标/片段/关键帧。预算由实测分配与峰值校准，不能把原图查看路径改回仅凭估算拒绝大图（参见 0.26.11 教训）。

**待实验选型**：Windows Graphics Capture 帧事件作为连续采集候选，现有 GDI 作为基线/兼容候选；比较捕获成本、裁剪/复制、排除捕获、窗口遮挡、多屏 DPI、远程桌面与资源释放后再定案，不将更换 API 等同于体验已改善。算法先保持既有鲁棒验证；相位相关只考虑快路径/候选召回，遵守 [scroll-stitch Spike](../../xtask/spikes/scroll-stitch/decision.md) 的小重叠/周期混叠结论，不整体替换成一维相位相关。

**不进本版**：横向长截图、任意快速跳转且没有重叠时自动补图、全应用专用适配、强制引入 UIA/特征模型或大视觉依赖、绕过系统捕获限制。不会以放松歧义/置信门槛换取表面成功率。
