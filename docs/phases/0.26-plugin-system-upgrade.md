## 二、背景与动机

原天气插件地点身份不稳定，供应商、配置与展示耦合，预算/取消/缓存缺乏统一契约。本版以确定地点和统一天气服务接入三家来源，并补齐宿主配置、进程与公共交互。

**维护澄清**：宿主已有配置注入、HTTP 代理和 Capability 注册；插件无需自行读库、直连网络或新增执行入口，地点确认也无需引入完整城市/GIS 库。

## 三、核心设计与维护要点

### 3.1 地点与天气分责

LocationResolver 与 WeatherProvider 通过 ResolvedLocation 连接，Query/ToolCall 共用 WeatherService。显式 city/location → default_location → 兼容 default_city；city/location 互斥，显式单位优先。严格匹配且唯一才自动查询，其余返回 needs_location；候选和 search_locations 均不隐式修改默认地点。

地点保存原坐标、坐标系和来源身份，供应商只派生请求坐标；和风 Location ID、Open-Meteo ID、adcode 不互换。彩云大陆使用 GCJ-02、其他地区 WGS84；区域依解析器证据或用户显式声明，未知需确认，不用地名、时区或粗矩形猜国界，转换不回写原值。

### 3.2 供应商与结果

- **Open-Meteo**：current + daily，完整 WMO 映射；96/99 为雷暴伴冰雹，逐日描述表示当天最严重现象。
- **和风**：账号专属 Host + API Key，Host 接受裸域名或 HTTPS 根地址；GeoAPI 与天气 v1 分开解析，实况/逐日并行、纬度在前，路径不额外加斜杠，逐日区分昼夜。
- **彩云**：v2.6 综合接口、metric:v2、最多 7 天逐日；App Secret 生成 HMAC-SHA256/URL-safe Base64 签名，签名与 URL 编码同源，签名请求拒绝重定向。实际天数以账号权限为准。

统一模型保留地点、来源、有效时间、原始天气代码、warnings 与 attributions；逐日按日期关联，缺失不补为 0/晴天。get_weather 保持单元素 raw 数组和工具 ID，status 区分 ok/partial/needs_location；复制完整摘要，来源链接限 HTTPS，天气时间保留来源时区。

### 3.3 配置、缓存与取消

结构化地点按补丁保存，地点草稿独立提交；普通字段、触发词和密钥清除共用写队列，冲突保留草稿并提供主动重载。跨窗口刷新可在编辑期间延后，焦点离开后补刷新。和风 Key、彩云 Secret 进入 CM；彩云 App Key 为普通字段，开发期旧 CM 值不自动迁移。提交契约见 [后端 spec §7.6](../specs/spec-backend.md#76-插件配置与密钥提交强制)。

地点与天气缓存分别有 TTL/LRU/容量/权重上限；只缓存有效候选与完整天气，partial、错误、降级结果不缓存。键包含来源、坐标/区域/时区及配置代次，旧代次不能回填新缓存。最多 4 个 producer、每个 8 个等待者，仅合并 transport 期限覆盖新调用的请求，等待者独立取消。

自动降级默认关闭，开启后按用户顺序尝试已配置来源，共用原预算；partial 直接返回，不混合来源。排队时间计入预算；取消阻止续发，已发宿主 HTTP 可能执行至原超时，不保证停止上游计费。通用契约见 [后端 spec §4.4](../specs/spec-backend.md#44-插件执行契约强制)。

### 3.4 IP 地址与出口

本机地址来自 GetAdaptersAddresses，出口来自站点实际观察；临时/非临时 IPv6 可同时有效，字符串长短不代表优先级。默认只采集物理地址；增强开关默认关闭，开启才采集网关、隧道/虚拟网卡及代理详情。DAD 与寿命过滤无效地址，优先有效且 preferred 的物理地址；临时 IPv6 按 SuffixOrigin 识别，TRANSIENT 是集群标记。

IPv4 国内默认 IPIP → 公云 3322 → 花生壳，国际默认 ifconfig.co → ipify；IPv6 为单组 test-ipv6.com → ipify IPv6，默认关闭。各组独立、组内按序，允许排序和关闭降级；旧区域 IPv6 排序不再生效。只接受对应地址族的公网回包，test-ipv6 的 JSONP 只解析固定包装，不执行脚本。

结果复用 60 秒，网卡/代理快照或检测配置变化即失效，纯显示选项不清缓存；开启 IPv6 保留 IPv4 缓存。ip local 离线查询不清掉已成功的出口缓存；ip refresh 仍遵守来源间隔（公云/ifconfig.co/test-ipv6.com 为 60 秒），间隔内优先显示有效缓存，无缓存则明确本次未请求及剩余等待时间。首次失败/取消也不绕过来源节流，过期或迟到结果不伪装成功。

查询与工具顺序一致：本机 IPv4 → IPv4 出口 → 本机非临时/临时 IPv6 → IPv6 出口 → 增强详情。IPv6 失败不回填 IPv4，也不能据此断言没有 IPv6 出网能力；单组只代表所用站点的观测，其他目标的源地址/代理分流可能不同，TUN 仍可接管流量。

### 3.5 主窗口统一列表导航

偏好迁入 app.search.wheel_mode（step/page，默认 step），通用设置为唯一入口；新字段优先，否则承接有效旧值。初始化以双分片 CAS 事务落库并移除旧字段，幂等且保留未知字段；读取失败或损坏配置报错，不覆盖原记录，不在搜索热路径迁移。

list-navigation.js 统一滚轮单位/余量/反向/上下文复位；方向键逐条，PgUp/PgDn 整屏，Alt+数字映射当前视口。热切偏好保留视口/高亮/多选/已加载数据，末页向下不倒退；状态栏按真实视口投影，流式未完显示已加载量 `+`。通用交互约束见 [前端 spec](../specs/spec-frontend.md)。

## 四、复用与范围边界

复用 PluginConfig/CM/配置广播、CapabilityRegistry、JSONL/宿主 HTTP、projection/Copy/open_url，以及通用控件、i18n、token 和 Lucide。新增能力仍归既有执行与展示链路。

本版不含自动定位、地图/GIS、多城市收藏、分钟降雨/AQI/预警、AI 改默认地点、持久化天气缓存、后台轮询、插件市场/沙箱、局域网扫描、代理/路由修改或 NAT 层级推断。0.27.4 全局网络改造承接本版 HTTP、配置与错误契约。

### 5.10 0.26.9 — 剪贴板文件条目

> §5.9/§5.10 的 1024px 缩放策略与仅 PNG 预览范围已由 0.26.11 多格式原图直出取代，见 §5.12；列表缩略图继续保持轻量。

采集→路径历史→写回→删除/清理闭环，以及本地 PNG 预览/入库。纯函数编解码与边界收敛在 `platform/clipboard/dropfiles.rs`（DROPFILES 头 + UTF-16 双 NUL、路径形态/设备命名空间判定、排序去重键、1MiB 序列化上限，跨平台可单测）；路径历史存 history 库新表 `clipboard_files`（原始顺序 JSON + 去重哈希 + 条数/载荷双上限淘汰，哈希命中后核对列表防碰撞覆盖）。

监听器改为**单次 OpenClipboard 快照**：同一会话按「有效文本 → 开启的 DIB → 开启的 HDROP」选一类入库，空白文本可继续下一类，多格式不混入另一轮复制。写回（`write_file_list` 平台原语 + HistoryRepost 标记 + 路径组合指纹兜底）按复制语义不继承剪切标记；`copy_clipboard_files` / `copy_clipboard_file_paths` / `save_clipboard_file_as_image` 三个 Capability 均绑定条目引用查库，不接受 UI 任意路径，多选合并路径逐段计量 1MiB。配置 `capture_files`/`max_file_items` 独立于图片开关，沿用补丁/CAS/热更新与 retention_days。

All 页签混排文件条目（file-text 图标，搜索按各路径 LIKE 预筛 + fuzzy），Text/Image 页签排除；副行「时间 · N 个文件 · 悬浮查看」。预览走 `blink-clipimg /file-preview/<条目id>`：恰好单路径 + `fs_guard` 受限路径防御（UNC/网络盘/云占位 RECALL 属性/重解析点远程目标，探测不触发下载）+ 独立文件 I/O 通道（并发 2、无排队、1 秒等待，超时不取消底层任务）+ 共享图片解码额度（try_acquire 繁忙即返）；magic 白名单为 PNG（image crate 仅启用 png feature），32MiB 原文件/64MiB 解码/1024px Triangle。多文件只展示 DB 路径列表；失败原因经 `get_clipboard_file_preview_status` 分类展示。入库共用读取/解码服务，转 PNG + 256 缩略图 + sha 去重，保留原文件条目、不改系统剪贴板。

### 5.11 0.26.10 — 剪贴板条目右键智能操作

右键是用户对指定历史条目的显式询问：`ContextProducer::item_open_candidates`（纯字符串派生，不查 DB/fs）按条目**完整原文**（文本）或 **DB 原始单路径**（文件，目录适用）派生三个打开类 Kind——完整 trim 后是单个 URL → OpenUrl；单个绝对路径/恰好单文件 → OpenPath + RevealInExplorer；多文件、图片、普通文本不产。origin 标记 `SuggestionOrigin::ClipboardItem` 仅供遥测，不进 Coordinator（豁免双槽/binding/fatigue/展示开关）；`disabled_builtin_actions` 仍拦。

只读 IPC `get_clipboard_item_actions`（`clipboard/item_actions.rs` 领域服务）：查库 + LocalSurface origin/runtime/policy 展示前过滤（与 `run_builtin_action` 执行门禁同构，点击时 Registry 仍重检）；DB 故障返回结构化错误不拿当前剪贴板兜底；全文只在后端派生。菜单会话：右键先显示基础菜单 + 不可点击「正在识别操作」，结果回流校验 menuId/条目身份/锚点连接后按**内容代次**（generation）原地更新同一 Popup 并重算尺寸——popup 点击回传代次，旧内容上的点击与更新竞争时后端拒绝（`ACTIVE_MENU_GENERATION`），不按新数组位置执行另一操作；空组移除 loading，失败显示失败态，基础复制/编辑/删除始终可用。点击执行 `run_builtin_action`（不读新剪贴板、不改 query、失败不回退），采纳遥测 `report_clipboard_item_action` 只记 Kind/动作 id/结果。图标/文案复用 SuggestionBar 的 globe/folder-open/folder-search 与 `suggestionbar.*_with`。

### 5.12 0.26.11 — 剪贴板文件独立筛选与多格式原图预览

补齐「全部 / 文本 / 图片 / 文件」四类筛选，Tab/Shift+Tab 正反循环。分类以已采集条目身份为准：路径文本仍属文本，文件/目录/多文件组合及文件条目中的 PNG 属文件；「存为图片条目」保留原文件、另建图片历史。0.26.9 的「文件仅 All 展示」限制由此解除。

复用 `ClipKind`、三表查询与 keyset 游标，文件筛选在空查询和 fuzzy 搜索中均只取文件表，按时间/id 倒序分页；不读取磁盘内容。切换保留搜索词、清空选择并回首批，使旧响应与追加游标失效；重新进入默认全部。颜色字面量快捷结果限全部/文本。沿用 0.26.10 的右键打开与定位、既有预览/复制/删除入口与主题 chips，不增加新采集格式或持久化筛选偏好。

悬浮图片与文件预览改为原始字节直出，去除后端 1024px 缩放及重新编码，避免重复采样损失与 debug 缩放延迟。文件及 DIB 采集后的 PNG 图片历史均在阻塞线程中只检查头部/动画结构，不在 Rust 展开像素，也不按估算的 RGBA 内存拒绝大图。保留 32MiB 原始数据上限、元数据解析器辅助分配限制、既有并发/路径防护；实际像素解码交给 WebView，前端等比适配面板。转存单张像素/解码上限与编辑器现有 RGBA 预算对齐为 256MiB，并单任务执行；该值不是进程峰值估算。预览 URL 升为 `?v=native`，隔离旧缩小图及旧预算拒绝响应；404 明确 no-store，文件预览仍每次读取当前内容。

文件预览扩展 PNG/JPEG/GIF/WebP，按内容 magic 识别，协议以原始字节和真实 MIME 返回；WebView 负责像素解码及 GIF/动态 WebP 动画播放。GIF 扫描帧边界/颜色表/数据块、跳过 LZW 解码，WebP 读取动画元数据；保留最多 200 帧，取消累计 RGBA 估算门槛。静态 PNG/JPEG/WebP 可转存为 PNG 图片历史并生成 256px 缩略图，转存时完整解码并应用 EXIF 方向。GIF 菜单不提供入库；后端按真实内容拒绝 GIF（包括伪装扩展名）及动态 WebP 静态化。预览失败后的状态查询共用实际校验，区分动画帧数限制与解码失败；头部通过而 WebView 拒绝像素数据时显示解码失败。

前期本机 debug 同一张 1312×1199、约 1.88MiB PNG：旧解码/缩放/编码分段合计 1.02–1.11 秒，移除缩放后的文件/图片历史读取与完整解码校验 89–114ms（各 5 次、内存库，输出逐字节一致；不含协议传输与 WebView 显示）。随后实图复现发现 GIF 合成缓冲触发 Rust 64MiB 分配限制，2459×12448 JPEG 的 RGBA 约 116.8MiB 超过旧像素上限，因此文件预览改为元数据校验并独立设置 128MiB 像素预算。本轮不引入文件预览短缓存。

后续 5437×8467 PNG 实图反馈：文件仅 4,571,027 字节（4.36MiB），却被 175.6MiB RGBA 估算触发上述 128MiB 门槛；该门槛未基于 WebView 实测，误挡正常图片。最终取消预览的估算像素内存拒绝，同时去除图片历史遗留的完整解码/64MiB 限制，共用头部校验工具。修改后实际文件后端原始字节一致，浏览器独立验证页能解码并显示原图（读取及解码单次约 288–375ms，非 WebView 内存峰值测量）。本轮不引入文件预览短缓存。

元数据方案对上述实际文件做只读回放：3317×3205 GIF 与 2459×12448 JPEG 均返回正确 MIME、原始字节逐字节一致，后端单次耗时分别约 3ms/4ms（本机 debug，不含协议与 WebView 显示；未写入用户数据库或修改原文件）。

文件图片与 DIB 采集后保存的 PNG 统一使用 `clipboard-image-viewer`：默认完整适配，滚轮围绕鼠标位置缩放（比例以自然像素尺寸计，最大 4 倍），放大后左键拖动并钳制可见范围，双击复位，切换条目重置。同一个 img 保持动画，不重新读取或重编码；pointer capture 保证越界拖动，松开/取消/关闭释放并恢复 150ms 缓冲。文件图片显示后才请求 `get_clipboard_file_entry(includeMetadata=true)`，由受限路径防护及独立有界 I/O 通道探测单文件 metadata.len，按 KB/MB/GB 显示磁盘大小；不进搜索、不逐个扫描多文件、不延迟首图，迟到元数据按 revision/锚点身份拒绝。

图片预览总高度由固定 260px 改为主窗口高度的 75%（以 260px 为最低目标，再按窗口上下各 8px 边距钳制），为图片视口预留扣除内边距/底栏后的空间；小图不放大，长图可使用更高视口，文本仍保持 260px 上限。位置沿用上下翻转及窗口内钳制，不扩展原生窗口。

单文件 PNG/JPEG/静态 WebP 的列表与预览菜单新增「存为图片条目并钉图／编辑」。UI 适配命令 `save_clipboard_file_image` 经 Registry 调用同一个 `save_clipboard_file_as_image` Capability，返回实际入库的 `image_id`，前端据此接续既有钉图/历史图片编辑入口，不查找最新条目、不覆盖系统剪贴板、保留原文件条目。转存失败不接续；后续失败保留图片并明确提示，已有编辑器沿用激活现有会话行为。完成后仅在原选择 epoch/revision 仍有效时关闭剪贴板主窗，避免迟到完成隐藏新选择。GIF/动态 WebP 保持只预览。

修复同一张 5437×8467 PNG 在接续钉图前被旧 64MiB 转存门槛拒绝：普通非交错、无 EXIF 的 PNG 改为逐行校验完整像素流及尾部，中心取样到最长边 1024px 的有界中间图，再生成 256px 缩略图，入库原 PNG 不重新编码。交错/动画/EXIF PNG 回落既有完整解码路径，保留方向归一；JPEG/静态 WebP 仍完整解码转 PNG。输入/输出 32MiB 上限不变，转存单任务额度随实际 blocking 任务结束释放，超限日志含尺寸/字节预算。真实文件只读回放（内存 SQLite，无用户库写入）：该 PNG 转存约 700ms，原字节一致，缩略图 164×256，独立进程峰值工作集约 43.6MiB；2459×12448 JPEG 转存约 19.1 秒、输出 PNG 3,999,122 字节，峰值约 116.3MiB。本机 debug 单次结果，不含原生钉图/编辑窗口与 WebView；JPEG 重编码仍有明显耗时。

修复失败提示被预览遮住：`#app` 的 backdrop-filter 建立独立层叠上下文，内部 toast 即使 z-index 很高也可能被 body 下的预览覆盖。将 `#transient-feedback` 移到 body，与预览同层，固定在窗口底部并使用既有 toast token；不改变窗口尺寸。浏览器旧/新层级对照及深浅主题验证提示在前景，原生 Win11 Popup 链路仍保留手动验收。

文件预览原因码 `not_image` 作为正常路径展示处理，不再对普通文件附加「不是支持的图片文件」；保留丢失、受限来源、解码失败及其他具体原因提示。分类继续使用后端真实内容校验结果，不按扩展名猜测；迟到响应沿用 revision/锚点校验。

右键智能组首屏合并预算 32ms：快速完成只弹出最终菜单，慢识别到期显示 loading 和基础操作，结果仍按会话/代次更新；取消时清理首屏定时器，迟到结果不能重开。后端同会话已显示菜单只更新内容及尺寸，沿当前物理原点按目标屏 DPI/工作区钳制，不再按新鼠标位置重新定位或执行 show/uncloak；Popup 用 fragment 原子替换菜单 DOM，减少两次弹窗和内容闪动。

### 5.13 0.26.12 — 快捷超链与自定义搜索引擎

本体新增一路 **sync 引擎 WebEngine**（非插件进程）：用户自管「超链/搜索引擎」表，`gh` 无前缀直达站点、`bing rust` 前缀搜索，执行走既有 `SearchAction::Open { path: url }` → 前端 `launchApp` → ShellExecute 链路，不新增执行入口。对标 Raycast Quicklinks / Flow Web Search / Lertaro WebSearch 的通用形态（keyword + `{query}` URL 模板）。

- **数据与配置（已定）**：`WebLinkEntry { id, name, keyword, url_template, enabled }`，是否搜索型由模板含 `{query}` 推导；新分片 `app.weblinks`（`impl ConfigKey`，ConfigStore 的 revision/CAS/`blink://config-changed` 广播直接复用）；`seeded` 标志区分「从未生成默认表」与「用户清空」（仿 0.21.10 `exposure_seeded`）。种子表：Bing/Baidu/GitHub/Bilibili/知乎/Wikipedia 默认启用，Google 收录但默认禁用（默认网络环境可达性不稳定，收录可自行启用而非缺席）。
- **Route 扩展（已定，本版唯一机制改动）**：`match_engine_keyword` 现只返回 `(engine_id, ExecArg)`，多 keyword 引擎无法区分命中词；`Route::EngineTakeover` 增加 `keyword: Option<String>` 字段（route() 内单点构造，存量 match 均带 `..`），`exec_engine_takeover` 经 `QueryContext.takeover_keyword` 下传。剪贴板引擎不受影响（None）。否决替代：engine 收原始 query 自行剥离——破坏 ClipboardEngine 的 arg 契约。
- **路由注册与冲突校验（已定）**：启动及 weblinks 配置变化时 `add_engine_rule("weblinks", keywords)`（重复注入即覆盖，热更新天然成立；用户清空/全部禁用时注入空 keywords 表，等效不再命中）；keyword 冲突校验（保存时拒绝 + 加载时 warn 跳过）覆盖既有 engine 触发词、全部插件 triggers（含用户自定义触发词）、保留前缀 `ai`、表内重复——engine keyword 优先级高于 plugin keyword，不校验会静默盖掉插件。`add_engine_rule` 现有源码注释假设「engine keyword 表运行时不变」，本版打破该假设，实施时同步更新注释。
- **行为（已定）**：Takeover 路径——无参出单条占位项（「Google 搜索…」），带参出单条「Google 搜索 \<arg\>」，`{query}` 按 UTF-8 percent-encoding 替换；Mixed 路径——**仅直达型（无 `{query}`）**按 name/keyword/拼音首字母双路召回，搜索引擎型不混排、只在 keyword 触发时出现（2026-10-18 已定）。
- **呈现与执行**：`SearchAction::Open { path: url }` 既有链路（engine.rs 注释明确 Open 覆盖 URL）；source 低权（`bake_source_boost`，"weblinks" 落 rank 4 最低档），图标 Lucide external-link 按 `source` 渲染（与剪贴板 file-text 同机制，在 results.js 图标链首短路——URL 走 blink-icon 协议只会得到空图）；设置页「超链」tab（engines 组），列表式增删改/开关/冲突提示，i18n zh/en。

**实施落点**：`KeywordOwner` 占用查询与 `Route::EngineTakeover.keyword` 在 intent 域（search 依赖 intent 为既有方向）；`QueryContext.takeover_keyword` 只在 EngineTakeover 分派时为 Some，Mixed 恒 None。分片损坏时以空表启动且不覆盖存储值（weblinks 是用户自建数据，`get_checked` 拒绝默认值回写）；启动 seed 用 `seeded` 标志防「用户清空后回生」。设置页保存失败保持表单打开、输入值保留，冲突逐条展示并给 keyword 输入红边。

**不进本版**：SuggestUrl 网络联想（进不了热路径）、favicon 抓取、多占位符/自定义编码变体、POST 型搜索、导入导出。

本体 sync 引擎 BookmarkEngine：后台读 Chromium 系书签文件建内存索引，默认 `bm` keyword 独占搜索，回车 `open_url`。对标 Lertaro BrowserData / Raycast Browser Bookmarks / Flow Browser Bookmarks。

### 5.15 0.26.14 — 托管 Everything 运行时（内置文件搜索引擎，📋 规划中）

用户未安装 Everything 时，设置页一键按需下载受管的 Everything 1.4 stable 便携版，作为 blink 专属文件搜索引擎实例运行；FileEngine 的 HTTP 查询路径零改动（复用现有客户端与请求格式），改动面为 data_source 优先级链与实例探测生命周期——现有 `start()` 启动即探测固定端口、Unavailable 后定期重试，需适配懒启动、动态端口与用户/托管实例的优先级重估。

**路线决策（2026-10-19 已定）**：
- **只做托管运行时**（自研 MFT/USN 索引不做）：Lertaro 式引擎需 SYSTEM 服务 + 管理员 + 约 2 万行长尾工程（快照格式/USN 追赶/恢复/盘拔插），且 MFT/USN 三种读法均为管理员专属、Rust 侧无成熟 live-volume 库；Everything 许可为 MIT（License.txt 原文核实，允许 distribute/sublicense），关于页附 MIT + PCRE BSD-3 声明即合规。竞品格局：商业工具（WizFile/UltraSearch/Listary）全线无集成接口，开源新秀（dowse 35★/ultrasearch 30★）成熟度差 5-10 年，Everything 是唯一「成熟+便携+全套接口+许可允许」四项全占。
- **按需下载，不捆绑安装包**：沿 0.25.20 脚本解释器的 asset-lock 模式——锁 URL+sha256+size+exe_relpath+version_check，下载事务+进度回调+失败清理，安装到 `%APPDATA%\blink\runtimes\everything\` 与 PATH 隔离。锁 **1.4 stable**（1.4.1.1032 便携 zip 约 1.8MB；不锁 1.5 beta——其 IPC 协议迁移中且非必要）。
- **提权显式同意**：默认不提权运行（Everything 未提权时自身退化为启动慢扫，仍可用）；设置页提供「安装 Everything 服务以启用实时 NTFS 索引」显式按钮，一次 UAC；拒绝则保持慢扫。
- **查询通道用 HTTP，不引入 everything-ipc**：reqwest+serde 零新增依赖、curl 可调试、localhost 开销毫秒级；`everything-ipc`（19★ 单人项目）`-instance` 支持未在 Rust 侧文档化、需 HWND 消息循环、耦合 1.5 beta 协议，留作 profiling 证实瓶颈后的备选；`everything-sdk` crate 为 GPL-3.0，永久排除。

**核心设计**：
- **实例隔离**：`Everything.exe -instance blink` + 生成专属 ini（http_server 开、绑定 127.0.0.1、动态区间专属端口、关闭 ETP/桌面集成）；探测到用户已装并开启 HTTP 的 Everything 时**复用而不另起实例**。
- **生命周期治理**：按需懒启动（首次文件搜索或设置页测试）；崩溃重启带退避上限；blink 退出时终止托管实例（按 instance 名 + PID 双重校验防误杀）；单实例守卫。
- **data_source 优先级链**：`auto` = 用户 Everything HTTP → 托管实例 → 既有 walkdir 浅层兜底；显式选项可固定单一来源；托管实例开关/端口为 FileSearchConfig 扩展字段。
- **风险兜底与披露**：杀软误报/隔离给原因码与重下入口；微软驱动拦截类事件提示降级慢扫；设置页如实披露内存预期（约 35MB/25 万文件、100MB/100 万文件——独立进程，不计入 blink 自身 300MB 预算）。
- **设置页**：文件搜索设置区新增「内置搜索引擎」区块——下载/进度/状态/版本/服务安装（UAC）/卸载清理。

**不进本版**：everything-ipc/命名管道通道、Everything 1.5、自研索引引擎（非管理员 jwalk+notify+SQLite 组合留作远期后路）、内容搜索、es.exe。
