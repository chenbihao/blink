## 二、背景与动机

### 2.1 当前问题

- `builtin.weather` 只有 Open-Meteo；名称搜索 `count=1` 后取首项，每次默认城市查询都重新解析，不能让用户确认同名地点。
- 天气 `main.rs` 混合协议、参数、阶段、供应商 DTO 与展示；Query / ToolCall 有重复，工具单位目前先读取 settings，显式参数可能被遮蔽；逐日温度固定摄氏度。
- manifest 总超时 5 秒，内部 HTTP 每段 15 秒；忽略 cancel、HTTP ID 用毫秒时间戳、无天气缓存；`concurrency=1` 只是声明，宿主尚未执行该信号量。
- 通用设置前端只收集 schema 字段，后端替换完整 settings；新增地点对象会在其他字段保存时丢失，插件配置尚未接入并发版本检查。
- 工具错误被拍平为 message，丢失 code；宿主 HTTP 日志输出 URL，彩云路径凭据可能泄漏；插件 Capability 打印完整 args 也不适合精确位置。
- 天气代码描述过粗、缺少来源与天气有效时间；逐日现象不能解释成全天持续。广州“冰暴”等反馈必须按地点、时间、原始代码、插件映射与 AI 转述核查，不能未经复现归因供应商。

### 2.2 明确“不是问题”的

- 插件已有配置消费能力：每次 Query / ToolCall 由宿主传 settings；宿主还原密钥后只发给子进程。无需插件直接访问 SQLite 或任意读取其他模块配置。
- 宿主 HTTP 协议已有 headers；天气插件自身的消息副本需要补齐，不另建直连 HTTP 客户端。
- 插件 tool 已经注册到 CapabilityRegistry；设置页桥接调用同一 Capability，不恢复 Action 双轨或复制天气逻辑。
- `get_weather` 当前 city 可省略且已有默认城市兜底；保留能力 ID 和省略语义。`setting_bindings` 修改 schema，不是运行时取得配置的必需机制。
- 搜索精确触发与带参触发的 min_arg_length 检查不同；先验证“天气”及尾空格，不凭 manifest 数值推断默认查询不可达。
- 需要候选确认不等于需要完整城市/GIS 数据库；默认地点是用户配置，搜索和天气缓存才是可重建数据。

## 三、核心设计 / 决策

### 3.1 位置获取、地点解析与天气查询分责（已定）

**定案**：天气插件内分别建模 LocationResolver 与 WeatherProvider，以统一 ResolvedLocation 连接；固定供应商枚举分发，首期不建立动态 Provider 框架或新 workspace crate。Query 与 ToolCall 保留协议入口，内部共用 WeatherService。

**理由**：确认一次地点后可跨供应商使用，避免切换天气来源又选到另一个同名城市。环境定位未来属于 infra/platform → app 显式注入边界，不由插件自行读取 Awareness。

### 3.2 地点模型与坐标适配（已定）

ResolvedLocation 包含 name/display_name、country_code、可缺失的 administrative_areas、具名 latitude/longitude、coordinate_system、可缺失 timezone、kind、source/source_id、resolved_at。行政区层级不强制全球统一成省市区；kind 区分城市中心、区县中心和手工坐标。来源 ID 使用命名空间，和风 Location ID、Open-Meteo ID 与 adcode 不互换。

保存解析器原始坐标和坐标系；供应商适配器派生所需请求坐标，不反复覆盖原值。彩云 v2.x 大陆 GCJ-02、其他地区 WGS84 的规则独立适配，区域信息不足时拒绝猜测并提示明确坐标系。QWeather 坐标精度与顺序遵循当前接口，实际请求坐标/返回网格信息仅作为有界诊断，不静默改写用户地点。

外部传入坐标必须有限、纬度在 [-90, 90]、经度在 [-180, 180]，显式坐标系仅允许已支持枚举；不从数值大小推断顺序。调用方提交的名称/来源是待验证元信息，不冒充解析器确认结果。无可靠地名显示“指定坐标”；城市中心不称为用户当前位置。

### 3.3 默认地点与解析选择（已定）

请求优先级：显式 city 或 location → settings.default_location → 旧 default_city 兼容解析 → location_not_configured。city/location 同传返回 invalid_arguments；显式 unit → settings.temperature_unit → 摄氏度。空白旧 city 可视为省略，非法类型不当作省略。

已确认 default_location/明确坐标跳过城市搜索。名称解析默认优先已配置的和风 GeoAPI，否则 Open-Meteo；面板展示实际来源，允许用户显式换源。鉴权失败、网络失败与无结果分开，不静默换源掩盖配置问题。

Open-Meteo 返回多个候选；统一按名称/可信别名、明确国家与行政区限定、地点类型筛选。名称明确匹配且无合理歧义时可直接查；前缀/模糊匹配、多候选不得仅凭首项、人口或 provider rank 自动确认。限制无法映射时明确说明，不能静默丢弃过滤。首期不建泛化地址 NLP。

主搜索保留“天气 广州”，支持确定语法“天气 辽宁/朝阳”“天气 北京/朝阳”；存在歧义展示完整候选并提示补充限定，首期不增加主窗口多步骤地点选择会话。候选选中不隐式修改默认地点。

### 3.4 地点设置交互（已定）

天气卡片展示已保存地点的完整名称与类型、天气来源、温度单位及各家凭据；更换地点在当前设置窗口展开面板，输入名称，可选国家/上级行政区，防抖搜索、有界候选、选择确认。高级入口分别填写经纬度/坐标系，不要求普通用户输入供应商地点 ID。

搜索草稿与已保存值分离，关闭/失败不改默认地点；保存成功才提交 UI 状态，清除有明确动作。输入、筛选、解析来源变化立即递增 revision，使旧请求失效；关闭/重载面板丢弃旧结果。支持上下/Enter/Esc、IME composition，按前端 spec 使用 token、Lucide 与统一 invoke 桥，不新建窗口或引入 bundler。

禁用插件时配置仍可编辑，网络候选搜索遵循启用检查，提示启用后再搜索，不静默启用。手工地点可直接配置，执行天气仍遵循启用与出口授权。

### 3.5 配置持久化、密钥与兼容（已定）

继续使用 config.db 的 `plugin:builtin.weather`，settings 增加 settings_version、default_location、default_provider；保留 temperature_unit 与过渡 default_city。默认 provider 为 open_meteo，不改变存量用户来源；default_location 是结构化对象，缺省 null。新字段由后端/插件解析层补默认值，不依赖首装 manifest 初始化覆盖存量记录。

和风为 qweather_api_host + qweather_api_key；彩云为 caiyun_app_key + caiyun_app_secret，Token 模式有实际需求再追加。0.26.5 起凭据在 UI 分组，App Key 按用户决定改为普通可见设置、不迁移开发期 CM 存量；其余 secret 字段声明 secret:true、复用 CM 命名、掩码及清除，不进入 AI 参数。Host 接受域名或 HTTPS 根地址，执行时规范化为校验后的 HTTPS 服务地址，不允许 AI 临时提交 URL；对带鉴权请求限制非预期重定向，避免凭据发送到其他目的地。

前端新增天气专用编辑模块并提供小型挂载/收集接口，0.26.5 起普通 schema 控件自动按字段补丁保存、地点草稿单独提交，写入与触发词/清密钥共用队列；保留未改的非密钥设置，不把对象 JSON 当字符串渲染。未提交、显式 null、空密钥未修改、明确清密钥分别处理。增加 plugin 配置 revision/expected 的原子检查，CAS 冲突返回 config_conflict，0.26.5 起保留当前草稿并提供用户主动重新加载入口；冲突检查与提交同序，冲突不得已改密钥。

CM/SQLite 不能假设跨存储原子事务：实现时明确变更顺序及失败恢复，单项 CM 写失败不继续显示保存成功，配置落库失败不得遗留“新密钥配旧元信息”的无提示状态；错误反馈可重试，单测使用 mock store。更新/清除密钥与 Host 变化推进配置代次，供请求快照和缓存失效使用。

旧配置不在只读查询时自动改写：default_city 可继续查并提示确认；用户确认后以 default_location 为准，清除同时清旧兼容值，避免复活。跨窗口广播后重读配置；旧 revision 不覆盖新选择。

### 3.6 对外 Capability 与 schema（已定）

| tool | 全局 ID | 参数与语义 |
|---|---|---|
| get_weather | builtin_weather_get_weather（保留） | city 或 location 可选且互斥，city 可带 country_code/admin，unit 可选；`{}` 查询默认地点，来源/凭据由插件读取配置 |
| search_locations | builtin_weather_search_locations（新增） | query 必填，可选 country_code/admin/有界 limit；返回候选及完整位置，不写配置 |

AI/CLI/MCP 经现有 policy、启用状态和授权过滤复用同一实现，不新增每个出口的独立天气接口。候选包含完整坐标，后续可直接传 location，不依赖短命缓存 ID；没有候选可返回正常空列表。

移除天气 manifest 的 city/unit setting_bindings 及静态单位 default，schema 明确“省略时执行阶段读取用户设置”。避免模型从 schema 回填旧城市名或默认摄氏值，覆盖结构化地点/最新单位；不把默认地点对象或密钥注入工具 schema。

设置页增加受限 search_weather_locations IPC，只允许固定工具，经 CapabilityRegistry 标记 Local 来源并检查授权/运行时；不暴露任意 tool dispatcher。默认地点保存仍经既有宿主配置入口；首期不新增 AI 写默认地点能力。

### 3.7 统一天气与结果契约（已定）

内部 WeatherSnapshot 保存 location、provider、fetched_at、可缺失 current、按当地日期组织的 daily、availability、warnings、attributions。温度与风速内部使用统一数值单位，出口转换；保留 condition_code/原始描述/天气有效时间。逐日分字段数组按日期关联，空值不补 0/晴；服务返回时区优先，不用电脑本地日期解释海外天气。

get_weather 的 raw data 继续为单元素数组，正常项兼容 city/temp/condition/wind_speed/daily，并增加 status、summary、结构化 location/current 与来源时间。status=ok 为完整天气，partial 为部分可用，needs_location 为候选确认且不携带天气；AI/CLI/MCP 必须读 status，不将候选视为查询成功。search_locations 使用单元素结果包保存 resolver、candidates 和数量，candidates 可为空；两工具 projection 分开配置。

实况成功预报失败返回实况并说明；只有预报明确标“仅预报”，temp 可缺失；不足 7 天说明实际天数；必要数据均失败返回错误。天气摘要由统一 presentation 生成，来源/缺失/有效时间进入 data，不能只放 AI 不读取的 desc。Copy 继续可用，复制天气摘要而非只复制城市；作为用户可见变化随指南同步。

错误统一至少区分 invalid_arguments、location_not_configured、location_not_found、provider_not_configured、authentication_failed、rate_limited、quota_exceeded、network_failed、timeout、invalid_response、busy。宿主 PluginError 保留插件 code/message 并映射既有 CapabilityError；地点歧义走正常 data，无须为了候选扩大全局错误 payload。未知工具名拒绝，不按天气执行。

### 3.8 供应商与天气解释（已定，真实账号待验）

- **Open-Meteo**：确定坐标后获取 current + daily，现有功能作为迁移回归基线；完整天气代码映射、单位和时区统一。
- **和风**：API Host + API Key，使用当前 GeoAPI、`/weather/v1/current/{latitude}/{longitude}` 与 `/weather/v1/daily/{latitude}/{longitude}`；实况/逐日并行，共用预算。旧 v7 城市响应不与新接口 DTO 混用。
- **彩云**：优先稳定 v2.6 综合 weather 接口，按权限请求当前与逐日；App Key 在路径，App Secret 生成 HMAC-SHA256/URL-safe Base64 签名，nonce/时间戳每请求更新；同一参数编码结果用于签名与 URL，单测对官方样例。7 天、免费权限与步长限制先用真实账号核验，不承诺未验证能力。

Open-Meteo 96/99 是雷暴伴冰雹，不能转述为冻雨或全年天气；逐日 weather_code 是当天最严重现象，不代表全天。保留原始 code、current/daily 类型和时间，复现反馈先核对地点和响应再判断模型问题，不按南方城市硬过滤，也不把所有 current 都称为站点实测。

来源声明随数据展示。主窗口提供可打开声明的来源标签，链接按 HTTPS/来源白名单校验，经既有 open_url 能力打开；不把设置页的声明当作结果归因替代。协议与 UI 实现以当前 result/payload 投影能力确定最小改造，不提前扩成通用富卡片系统。

### 3.9 deadline、取消与有界并发（已定）

每请求冻结 provider/settings_revision/配置、地点和单位；HTTP ID 使用递增序号。query_id 管查询状态与截止时间，http_id 关联 query_id/阶段；单线程消息循环管理状态，不保留无用途 Arc<Mutex>。

宿主以 manifest 上限与 InvokeContext 剩余时间取更小预算，经向后兼容可选字段传插件；排队、进程准备、写 stdin 与等待结果计入总 deadline，插件 HTTP 使用剩余预算。先核验两段请求实际延迟再设总值，不保留宿主 5 秒/内部每段 15 秒冲突，不靠无限重试延长。

取消/调用方 drop 清理 pending 并尽力发送 cancel；插件丢弃迟到响应、停止续发。设置搜索、主窗口与 AI 请求有独立归属，不能以“最新请求”全局取消其他调用。已由宿主发出的 HTTP 首期仍受请求超时约束，不宣称取消一定能阻止上游计费；主动 abort 全链路可另评估。

显式实现有界查询与 HTTP 并发、有限等待者，超额 busy，不将 manifest 声明当成已限流。相同有效请求 single-flight；一个等待者取消不取消其他等待者，全部失效才停止后续阶段。断线/重启清理仅作用于原进程代次。

### 3.10 缓存、日志与网络边界（已定）

有界进程内地点缓存按解析器/查询/限定/语言/配置代次；天气缓存按供应商/坐标与坐标系/请求能力/语言/配置代次。可缓存统一内部数值，单位在出口转换；默认地点为持久用户配置，不随缓存过期。失败不长期缓存；TTL/容量集中为内部参数，按实际配额与延迟校准。首期不做过期数据自动兜底或后台定时刷新。

换密钥/清密钥/改 Host 失效相关缓存与在途结果写入权限；新配置查询不能被旧缓存掩盖鉴权错误。旧查询可按旧快照完成，但不能覆盖新代次缓存/界面。

宿主继续现有 HTTP 代理路径，核验 Gzip feature 与压缩响应；日志去除 URL 路径/查询及网络库错误中的凭据，插件 args 不打印精确位置。保留 provider、stage、耗时、状态码、天气 code 与关联 ID，协议 stdout 只发 JSONL，诊断走既有 stderr 分级桥。

0.27.4 负责未来全局网络快照、client 复用、代理语义与更新降级；0.26 只补本次必需压缩/脱敏/deadline，不依赖未来 net 工厂、不改变直连/代理产品承诺。0.27 实施时承接这些测试与协议，避免覆盖回退。
