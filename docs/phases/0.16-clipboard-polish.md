# Blink 0.16 — 剪贴板增强与内容基础（Clipboard Enhancement & Content Foundation）

> **范围**：修复剪贴板与设置页存量问题，打通 item actions 数组，抽取共享 Markdown 渲染，建立通用文本编辑器并首先接入剪贴板，补齐剪贴板图片与图片 pin，以及卸载清理能力。
>
> **状态**：📋 规划中。
>
> **动机**：剪贴板历史（Alt+C）已经是高频 chord surface，但当前只有文本复制，没有可靠的编辑、图片和多动作链路；与此同时，0.17 的桌面便签需要复用编辑器与 Markdown 渲染，0.16 应先把内容基础设施做成通用能力。
>
> **前置**：0.16.5（剪贴板图片→pin）依赖 0.15 pin 能力；item actions 数组借力 0.14 已落地的 `ItemResult.actions: Vec<ItemAction>` 协议。
>
> **原则**：编辑器从第一天就是通用内容编辑器，但 0.16 只接剪贴板入口；不提前实现便签、笔记或 Todo；前端无 bundler、共享渲染、用户内容可恢复、P0 主窗口链路不退化。

---

## 一、背景与动机

### 1.1 为什么 0.16 做这件事

剪贴板历史已有文本采集、搜索和回贴，但存在六类缺口：

1. item 右键菜单按 `source` 硬编码，剪贴板项显示“打开”但实际执行复制；
2. capability 协议已经支持多 actions，桥接到 `AppEntry` 时却只保留首个；
3. 剪贴板文本无法在独立窗口编辑后回贴；
4. 对话窗口已有 Markdown 渲染，但没有可供编辑器和 0.17 便签复用的共享模块；
5. 采集端只读 `CF_UNICODETEXT`，图片复制会被跳过；
6. 存储清理、Provider 开关、表单样式和卸载残留等存量问题仍未收口。

0.16 的目标因此不只是“补一个剪贴板编辑页面”，而是先建立一套不绑定剪贴板的数据契约与渲染基础，再用剪贴板完成第一条闭环。

### 1.2 明确不是问题的

| 项 | 澄清 |
|---|---|
| 剪贴板复制执行逻辑 | `SearchAction::Copy` / `ItemAction::Copy` 已正确，错误主要在前端 label 与 actions 压扁 |
| capability 多 action 协议 | `ItemResult.actions` 已存在，不另造协议；0.16 只接通最后一段投影 |
| 图片写入系统剪贴板 | 截图链路已有 BGRA/PNG 写入能力，0.16.4 主要补采集、存储、搜索和展示 |
| Markdown 渲染 | 对话窗口已有实现，0.16.2 做抽取与统一，不重新引入一套 renderer |
| 便签持久化 | 属 0.17；0.16 编辑器不建立通用笔记库，也不让剪贴板编辑器承担便签存储 |

## 二、核心设计 / 决策

### 2.1 item actions 全量投影（已定）

**定案**：`AppEntry.action: Action` 升级为 `AppEntry.actions: Vec<Action>`；回车执行 `actions[0]`，右键展开全部动作。

**理由**：capability 层已经完成 `ActionDef → ItemAction` 的数组投影，当前断点只是 `items_to_entries()` 使用 `actions.first()` 压扁。修通后，剪贴板、插件、AI 结果以及未来“编辑/钉住”动作都不再依赖前端按 source 写分支。

投影链保持：

```text
manifest ActionDef
  → ItemResult.actions: Vec<ItemAction>
  → items_to_entries 解析 pointer 并映射全部动作
  → AppEntry.actions: Vec<Action>
  → 回车执行首个 / 右键展开全部
```

文件管理类附加菜单（打开所在文件夹、复制路径等）仍按 `lnkPath` 存在性由前端追加，不混入 capability actions。

### 2.2 Markdown 只共享渲染核心（已定）

**定案**：从对话窗口抽取 `frontend/js/shared/markdown.js`，统一 Markdown 解析、净化与渲染；对话窗口、内容编辑器和 0.17 便签使用同一入口。

**理由**：共享内容核心不等于共享窗口外壳。对话消息、编辑工作台和桌面便签的布局职责不同，但 Markdown 语义、安全净化和主题 token 必须同源。

### 2.3 通用内容编辑器，0.16 仅接剪贴板（已定）

**定案**：编辑器窗口不命名为 `ClipboardEditor`，入口接受通用 payload，例如：

```text
EditableContent
- body
- format: plain | markdown
- title
- origin
- origin_ref
- save_policy
```

0.16 只实现 `origin=clipboard` 的打开与保存策略：剪贴板项右键“编辑”→独立编辑器→纯文本/Markdown 编辑与预览→保存为一条新剪贴板记录并写回系统剪贴板。原历史项不原地覆盖，保留可恢复路径。

0.17 可在不修改编辑器内核的前提下接入主窗口 query、文本型 item、便签和 chord-E。

### 2.4 编辑器高级加工后置（已定）

**定案**：0.16 编辑器只做纯文本、Markdown 编辑/预览、复制与保存回贴；不做代码高亮、格式化、Diff 或 AI 加工。

**理由**：先验证通用内容窗口和保存契约；高级加工会扩大依赖、交互和安全净化范围，不应阻塞基础闭环。

### 2.5 剪贴板图片留在 0.16（已定）

**定案**：图片采集、存储、缩略图、回贴和图片→pin 保留在 0.16，按独立子版本拆分。

**理由**：图片是剪贴板增强的完整性要求；拆成 0.16.4/0.16.5 后不会阻塞文本编辑器基础，也能保持独立验收。

### 2.6 卸载清理复用 STT 范式（已定）

**定案**：设置页清理入口与 NSIS 卸载钩子共享后端清理函数，复用“探测→展示→确认→清理→刷新”范式；新增 `blink/*` Credential Manager 批量枚举与删除。

**理由**：项目已有成熟的 STT 空间清理骨架，继续复用能保证错误聚合、幂等、删前停止占用进程和确认默认拒绝等行为一致。

### 2.7 表单样式统一（已定）

**定案**：新增 `components/radio.css`，将裸 radio/checkbox 收编到组件样式，并修复 Debug 日志开关引用不存在 CSS 类的问题。

## 四、子版本展开

### 4.1 0.16.0 小修合集

| 项 | 改动点 |
|---|---|
| 剪贴板菜单 label | actions 重构前先止血显示“复制”，0.16.1 后由后端 hint 派生 |
| 存储清理 VACUUM | 清理命令完成 DELETE 后实际收缩数据库文件 |
| 对话模型名 ellipsis | 强制单行省略，避免 header 撑高 |
| Provider 启用/禁用 | `ProviderEntry` 增加 enabled，注册与选择器统一过滤 |
| 主窗口全选门控 | 无文本/无选区时不显示“全选” |
| radio/checkbox | 新增 radio 组件并收编裸控件 |

### 4.2 0.16.1 item actions 数组全链路

1. `AppEntry.action` 改为 `actions: Vec<Action>`；`SearchItem.action` 保持单值，在 `into_app_entry` 包成 vec。
2. `items_to_entries()` 遍历并映射全部 `ItemAction`，保留空 actions + 标量数据隐式 copy fallback。
3. 前端 results dataset 存取 actions 数组；回车执行首个；右键动态展开全部。
4. statusbar/hints 统一读取 `actions[0]`；文件管理附加项继续按 `lnkPath` 拼接。

### 4.3 0.16.2 共享 Markdown 渲染

抽取共享模块，至少覆盖：Markdown→安全 DOM/HTML、代码块与链接的既有策略、主题适配和渲染入口。对话窗口迁回共享入口，确保抽取不是复制。

### 4.4 0.16.3 通用文本编辑器 V1

新建独立编辑器窗口与通用 `EditableContent` 打开契约。首个接入点是剪贴板文本 item 的“编辑”action。

核心行为：

- 纯文本/Markdown 模式切换；
- 编辑与预览使用共享 renderer；
- 保存时创建新剪贴板历史记录并写回系统剪贴板；
- 原剪贴板记录保持不变；
- Esc/关闭窗口不写回，未保存内容离开前提示；
- 编辑器窗口的创建和聚焦不得阻塞主窗口 P0 唤起链路。

### 4.5 0.16.4 剪贴板图片历史

- 采集 `CF_DIB`，解码后存储 BLOB；
- schema 增加内容 kind 与图片数据，迁移不丢旧文本；
- 图片哈希去重；
- 列表展示缩略图并支持写回系统剪贴板；
- 补齐 `source_app` 采集；
- 搜索引擎对图片 item 给出稳定标题与 actions。

### 4.6 0.16.5 剪贴板图片→pin

剪贴板图片 item 增加 pin action，复用 0.15 图片 pin 能力。这里的 pin 是图片悬浮能力，不等同于 0.17 文本便签实体。

### 4.7 0.16.6 卸载清理能力

- 新增数据占用探测与按 scope 清理命令；
- 新增 `enumerate_blink_secrets()` / `delete_all_blink_secrets()`；
- 设置页提供明确列出删除内容的一键清理入口；
- NSIS 卸载时提供默认不勾选的“同时删除用户数据与模型”；
- 删除前停止占用资源，NotFound 视为成功，错误聚合返回。
