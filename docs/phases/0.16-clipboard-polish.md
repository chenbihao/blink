# Blink 0.16 - 剪贴板增强、内容流转与桌面便签（Clipboard Enhancement, Content Flow & Sticky Notes）

> **范围**：修复剪贴板与设置页存量问题，打通 item actions 数组，抽取共享 Markdown 渲染，建立通用文本编辑器并首先接入剪贴板，补齐剪贴板图片与图片 pin，以及卸载清理能力；在此基础上实现内容流转闭环（chord-E/chord-S、query/item/选区→编辑器/便签）与可持久化桌面便签（数据模型、窗口、管理界面与崩溃恢复）。
>
> **状态**：✅ 已完成（0.16.0-0.16.11 全部完成）。
>
> **动机**：剪贴板历史（Alt+C）已经是高频 chord surface，但当前只有文本复制，没有可靠的编辑、图片和多动作链路；通用内容编辑器与共享 Markdown renderer 落地后，Blink 可以把"刚刚出现的内容"直接转为可编辑、可常驻桌面的便签。差异化不在复刻 Windows 便签，而在省去新建、复制、切应用、粘贴的中间步骤。原计划包含的主窗口感知交互清爽化与 chord requires_input 架构已在 0.15.10 顺手完成，不再列入本 phase。
>
> **前置**：0.16.5（剪贴板图片->pin）依赖 0.15 pin 能力；item actions 数组借力 0.14 已落地的 `ItemResult.actions: Vec<ItemAction>` 协议；chord requires_input 基础设施已由 0.15.10 落地，为 0.16.9 chord-E/chord-S 的 contextual 解析提供基础；0.16.7-0.16.11 的便签与内容流转复用 0.16.1-0.16.3 落地的 actions 数组、共享 Markdown renderer 和通用内容编辑器。
>
> **原则**：编辑器从第一天就是通用内容编辑器，但 0.16.0-0.16.3 只接剪贴板入口；便签本身就是明确持久化的用户数据，关闭只隐藏、删除才移除；内容与窗口状态都可恢复；共享内容核心但不强行共享窗口外壳；不引入笔记库、Todo、文件夹、标签或同步；便签恢复不得阻塞主窗口 P0 唤起链路；前端无 bundler、共享渲染、用户内容可恢复、P0 主窗口链路不退化。

## 二、背景与动机

### 2.1 为什么 0.16 做这件事

以下问题推动了本 phase：

**剪贴板与内容基础设施（0.16.1-0.16.6）**：剪贴板历史已有文本采集、搜索和回贴，但存在六类缺口：

1. item 右键菜单按 `source` 硬编码，剪贴板项显示“打开”但实际执行复制；
2. capability 协议已经支持多 actions，桥接到 `AppEntry` 时却只保留首个；
3. 剪贴板文本无法在独立窗口编辑后回贴；
4. 对话窗口已有 Markdown 渲染，但没有可供编辑器和便签复用的共享模块；
5. 采集端只读 `CF_UNICODETEXT`，图片复制会被跳过；
6. 存储清理、Provider 开关、表单样式和卸载残留等存量问题仍未收口。

0.16 的目标是建立一套不绑定剪贴板的数据契约与渲染基础，用剪贴板完成第一条闭环。原计划包含的主窗口感知交互清爽化与 chord requires_input 架构已在 0.15.10 顺手完成，不再列入本 phase。

### 2.2 为什么在 0.16 做桌面便签

单独做一个 Windows 便签替代品，操作路径和产品边界都缺乏优势。0.16.0-0.16.3 建立通用编辑器与共享 Markdown renderer 后，Blink 已经握有其它便签应用没有的入口：主窗口 query、搜索 item、剪贴板、选中文本以及后续 AI 文本结果。

0.16.7-0.16.11 要建立的是内容流转闭环：

```text
主窗口 query / 文本型 item / 剪贴板 / Awareness 选区
  → chord-E 或“编辑”action → 通用编辑器
  → chord-S 或“钉为便签”action → 持久化桌面便签
  → 便签“深度编辑” → 通用编辑器
  → 便签管理 → 显示 / 隐藏 / 编辑 / 删除
```

用户明确创建或钉住便签后，Blink 必须记住内容和桌面状态。应用正常退出、Windows 重启或 Blink 异常崩溃后，已显示的便签应恢复，隐藏的便签应继续留在管理界面中。

### 2.3 明确不是问题的

| 项 | 澄清 |
|---|---|
| 剪贴板复制执行逻辑 | `SearchAction::Copy` / `ItemAction::Copy` 已正确，错误主要在前端 label 与 actions 压扁 |
| capability 多 action 协议 | `ItemResult.actions` 已存在，不另造协议；0.16.1 只接通最后一段投影 |
| 图片写入系统剪贴板 | 截图链路已有 BGRA/PNG 写入能力，0.16.4 主要补采集、存储、搜索和展示 |
| Markdown 渲染 | 对话窗口已有实现，0.16.2 做抽取与统一，不重新引入一套 renderer |
| 便签持久化 | 属 0.16.7-0.16.11；0.16.0-0.16.3 编辑器不建立通用笔记库，也不让剪贴板编辑器承担便签存储 |
| 是否需要通用笔记模型 | 当前不需要；0.16.7-0.16.11 只建立 `StickyNote` 实体，不提前设计 Notes/Todo |
| 是否复用 0.15 图片 pin 数据 | 不直接复用实体；图片 pin 与文本便签生命周期、编辑和持久化语义不同，只复用窗口/平台基础设施 |
| 是否共用编辑器与便签整套样式 | 不共用外壳；共用 Markdown renderer、编辑基础组件和主题 token |
| 关闭按钮是否删除内容 | 不是；关闭等于隐藏并持久化 `visible=false`，永久删除必须在明确确认后执行 |
| 应用退出是否等于隐藏全部 | 不是；退出不修改用户设定的 visible 状态，下一次启动据此恢复 |
| 是否要完全复刻 Windows 便签 | 不需要；借鉴成熟的颜色、列表管理和直接编辑形态，但入口与内容流转保持 Blink 特性 |

## 三、核心设计 / 决策

### 3.1 item actions 全量投影（已定）

**定案**：`AppEntry.action: Action` 升级为 `AppEntry.actions: Vec<Action>`；回车执行 `actions[0]`，右键展开全部动作。

**理由**：capability 层已经完成 `ActionDef -> ItemAction` 的数组投影，当前断点只是 `items_to_entries()` 使用 `actions.first()` 压扁。修通后，剪贴板、插件、AI 结果以及未来“编辑/钉住”动作都不再依赖前端按 source 写分支。

投影链保持：

```text
manifest ActionDef
  -> ItemResult.actions: Vec<ItemAction>
  -> items_to_entries 解析 pointer 并映射全部动作
  -> AppEntry.actions: Vec<Action>
  -> 回车执行首个 / 右键展开全部
```

文件管理类附加菜单（打开所在文件夹、复制路径等）仍按 `lnkPath` 存在性由前端追加，不混入 capability actions。

### 3.2 Markdown 只共享渲染核心（已定）

**定案**：从对话窗口抽取 `frontend/js/shared/markdown.js`，统一 Markdown 解析、净化与渲染；对话窗口、内容编辑器和便签窗口使用同一入口。

**理由**：共享内容核心不等于共享窗口外壳。对话消息、编辑工作台和桌面便签的布局职责不同，但 Markdown 语义、安全净化和主题 token 必须同源。

### 3.3 通用内容编辑器，0.16 仅接剪贴板（已定）

**定案**：编辑器窗口不命名为 `ClipboardEditor`，入口接受通用 payload，例如：

```text
EditableContent
- body
- format: plain | markdown
- title
- origin
- origin_ref
- save_policy
```

0.16.0-0.16.3 只实现 `origin=clipboard` 的打开与保存策略：剪贴板项右键“编辑”->独立编辑器->纯文本/Markdown 编辑与预览->保存为一条新剪贴板记录并写回系统剪贴板。原历史项不原地覆盖，保留可恢复路径。

0.16.7-0.16.11 可在不修改编辑器内核的前提下接入主窗口 query、文本型 item、便签和 chord-E。

### 3.4 编辑器高级加工后置（已定）

**定案**：0.16.0-0.16.3 编辑器只做纯文本、Markdown 编辑/预览、复制与保存回贴；不做代码高亮、格式化、Diff 或 AI 加工。

**理由**：先验证通用内容窗口和保存契约；高级加工会扩大依赖、交互和安全净化范围，不应阻塞基础闭环。

### 3.5 剪贴板图片留在 0.16（已定）

**定案**：图片采集、存储、缩略图、回贴和图片->pin 保留在 0.16，按独立子版本拆分。

**理由**：图片是剪贴板增强的完整性要求；拆成 0.16.4/0.16.5 后不会阻塞文本编辑器基础，也能保持独立验收。

### 3.6 卸载清理复用 STT 范式（已定）

**定案**：设置页清理入口与 NSIS 卸载钩子共享后端清理函数，复用“探测->展示->确认->清理->刷新”范式；新增 `blink/*` Credential Manager 批量枚举与删除。

**理由**：项目已有成熟的 STT 空间清理骨架，继续复用能保证错误聚合、幂等、删前停止占用进程和确认默认拒绝等行为一致。

### 3.7 表单样式统一（已定）

**定案**：新增 `components/radio.css`，将裸 radio/checkbox 收编到组件样式，并修复 Debug 日志开关引用不存在 CSS 类的问题。

### 3.8 `StickyNote` 是独立持久化实体（已定）

**定案**：0.16.7-0.16.11 不建立 `ContentDocument`/笔记库抽象，便签直接以 `StickyNote` 持久化。建议字段：

```text
StickyNote
- id
- content
- format: plain | markdown
- color
- visible
- x / y / width / height
- always_on_top
- created_at / updated_at
```

便签数据写入 `blink_history.db` 的独立表，与启动历史、剪贴板历史分表管理；“清除历史”不得删除便签，只有便签删除和卸载全量清理可以移除。这样不增加第五个数据库，也不会把用户内容当 cache。

**理由**：当前明确不做笔记，先抽象通用文档会引入尚无消费者的类型和迁移负担。未来若笔记立项，再评估将 `StickyNote.content` 迁为通用内容实体，而不是现在预埋。

### 3.9 内容和窗口状态都必须自动保存（已定）

**定案**：内容输入短防抖自动写库；颜色、显隐、置顶、位置和尺寸在变化后防抖写库；失焦、隐藏和窗口关闭前强制 flush。SQLite 使用事务更新，启动时只读取最后一次完整提交。

**理由**：便签的核心承诺是“放在那里就不会丢”。只在用户点保存或应用退出时写入，无法覆盖崩溃和系统强制结束。

恢复策略：

- 正常启动后异步读取所有便签；
- `visible=true` 的便签恢复窗口，`visible=false` 只进入管理界面；
- 恢复在主窗口服务 ready 后走旁路，不阻塞 Alt+Space；
- 显示器减少、分辨率或缩放变化时，将越界窗口钳制到最近可见工作区；
- 单条便签恢复失败只记录并跳过，不阻断其它便签和主窗口。

### 3.10 关闭、隐藏、退出、删除四种语义分离（已定）

**定案**：

| 操作 | 内容是否保留 | visible | 下次启动 |
|---|---:|---:|---|
| 便签关闭按钮 | 保留 | false | 不自动显示，可从管理界面恢复 |
| 管理界面“隐藏” | 保留 | false | 不自动显示 |
| 应用退出/系统重启 | 保留 | 不改变 | 原本显示的继续恢复 |
| 管理界面“删除” | 永久删除 | — | 不恢复，必须确认 |

窗口 close event 需要区分“用户关闭便签”和“应用整体退出”。整体退出只 flush，不批量把 visible 改成 false。

### 3.11 颜色采用有限成熟色板（已定）

**定案**：首版提供有限语义色板，例如黄、粉、紫、蓝、绿、灰；默认黄色。颜色改变立即应用并持久化，前景色和控件对比度由 token 配对，不能让用户输入任意色值。

**理由**：Windows 便签的有限色板已经验证了选择效率；任意取色会扩大可读性、暗色主题和状态图标对比度问题。未来有真实需求再扩展自定义颜色。

颜色属于单条便签，不随全局主题覆盖；全局深浅主题只影响控件、阴影和 Markdown 代码块等辅助层。

### 3.12 便签可直接编辑，也可进入工作台（已定）

**定案**：便签窗口支持直接编辑并自动保存，同时提供“在编辑器中打开”动作。便签只保留最小控件：拖动、颜色、更多菜单、关闭；Markdown 预览、复杂选择和未来格式化能力留在通用编辑器。

编辑器以 `origin=sticky`、`origin_ref=sticky_id` 打开；保存回写同一便签，不复制出新实体。编辑器“钉住”则从当前内容创建新便签，除非当前 session 已绑定某个 sticky id。

### 3.13 chord 分为空闲入口与上下文动作（已定）

**定案**：不移除现有 chord 总门禁，而是增加 action availability：

```text
Idle       query 为空且无用户结果时可用
Contextual 当前 query 或 active item 能提供所需内容时可用
```

- `Alt+E`：编辑当前内容；无上下文时打开空白编辑器。
- `Alt+S`：将当前内容创建为便签（Sticky）；无上下文时创建空白便签。
- 便签管理不占新 chord，通过主窗口内置 action“便签管理”和托盘入口打开。

**与 0.15.10 的关系**：`requires_input` 基础设施已在 0.15.10 落地（`ChordAction` trait 声明 + `getTapKeys` 动态过滤 + 入参管道 + hook 吞键收窄 + ChatAction 接通）。0.16.9 在此基础上扩展 contextual 解析——0.15.10 只做空/非空 query 二分（非空 query 时 `requires_input=true` 的 chord 可触发，入参为输入框文本），0.16.9 增加多源解析（active item payload > query > awareness > 空白）。

上下文解析顺序：

1. 当前 active item 明确声明的 edit/pin action；
2. 非空 query；
3. 空闲态下仍有效的 Awareness 选中文本；
4. 无内容时为空白编辑器/空白便签。

状态栏必须显示动作目标摘要，避免 query 与 active item 同时存在时目标不透明。只有明确提供文本 payload 的 item 才能出现 edit/pin，不能把任意文件名或展示 label 当正文。

**空文本提示隐藏（0.16.11）**：E/S 是 Contextual 上下文动作，空文本时主用途依赖 awareness 选区兜底，提示价值低、徒增噪声。`ChordAction` trait 新增 `hint_hidden_when_empty()` 方法（默认 `false`），E/S 覆盖为 `true`——空文本时 overlay 不显示 E/S 提示，但 Alt+E/S 触发全保留（空白编辑器/空白便签/awareness 选区场景）。Q（AI 对话）空文本时是"打开空对话窗口"的明确入口，性质不同，不隐藏。该字段仅影响 `list()` 输出（overlay 提示可见性），`list_all()`（设置页）不含此字段，设置页始终展示全部可开关项。

### 3.14 便签管理是唯一集中管理入口（已定）

**定案**：提供独立便签管理窗口，至少展示内容摘要、颜色、显隐状态和更新时间，并支持：

- 创建空白便签；
- 显示/聚焦已显示便签；
- 恢复隐藏便签；
- 隐藏便签；
- 在通用编辑器中打开；
- 修改颜色；
- 删除（确认后永久移除）。

管理界面不是笔记库：不做文件夹、标签、全文知识管理、Todo 聚合或同步。

### 5.4 0.16.3 通用文本编辑器 V1

**架构归属（定案）**：编辑逻辑在前端，后端只做窗口创建 + 剪贴板读写桥接。`src/app/commands/content_editor.rs` 单文件 IPC 入口，不建 domain/content_editor 模块--编辑器是应用层窗口编排，无独立业务域逻辑。

**EditableContent 打开契约（IPC）**：

`open_content_editor(payload)` 命令，payload 为 JSON（camelCase，前端约定）：

| 字段 | 类型 | 0.16 取值 |
|---|---|---|
| body | string | 剪贴板文本内容 |
| format | “plain” \| “markdown” | “plain”（0.16 不自动判定 md） |
| title | string? | “编辑剪贴板内容” |
| origin | string | “clipboard” |
| originRef | string? | 原剪贴板记录 id（用于继承 hit_count，见保存链路） |
| savePolicy | “clipboard_new” | 0.16 唯一策略 |

**保存回贴链路（savePolicy=clipboard_new）**：

1. 前端调 `save_content_editor(payload)` 命令，传编辑后的 body。
2. 后端：新建一条 `ClipboardItem`（新 id、新 created_at），`hit_count` 从 `originRef` 继承（原项 hit_count），写入 `clipboard_history` 表（`save_item`，INSERT OR REPLACE）。
3. 后端调 `write_text_to_clipboard(body)` 写回系统剪贴板。
4. **原项不删除、不覆盖**--满足”保留可恢复路径”。
5. 返回新记录 id，前端关闭编辑器窗口。

**窗口生命周期与看门狗**：

6. 编辑器窗口是 Blink 进程内 Tauri 窗口。看门狗 `is_self_foreground`（window/windows.rs:410）按 PID 判定，前台切到编辑器时 `fg_pid == self_pid`，**主窗不会被误隐藏**。
7. 主窗被唤起（Alt+Space）时编辑器不自动跟随隐藏--两者可并存；编辑器由用户主动关闭。
8. 编辑器窗口创建/聚焦不得走搜索热路径，不阻塞主窗 P0 唤起（< 50ms）。

**核心行为**：

- 纯文本/Markdown 模式切换；Markdown 预览用共享 renderer（0.16.2）。
- Esc/关闭窗口不写回；有未保存改动时 `beforeunload` 提示。

### 5.5 0.16.4 剪贴板图片历史（✅ 已完成）

**存储定案**：图片独立建表，放 `blink_cache.db`（cache 库，已有 BLOB 经验），不进 `blink_history.db` 的 `clipboard_history` 表。

理由：单张截图 CF_DIB ~14MB / PNG 1-3MB，若塞进 `clipboard_history`（max_items=10000）历史库可达 20GB；且 SQLite 单 pool 写锁会阻塞文本历史和搜索历史。

| 表 | 库 | 存什么 | 上限 |
|---|---|---|---|
| `clipboard_history`（现状） | history | 文本 + 元数据 | max_items=10000 |
| `clipboard_images`（新建） | cache | PNG BLOB + 缩略图 BLOB + 哈希 + 元数据 | max_image_items=200（独立配置） |

**schema（clipboard_images 表）**：

```sql
CREATE TABLE IF NOT EXISTS clipboard_images (
    id TEXT PRIMARY KEY,
    png_blob BLOB NOT NULL,          -- 完整 PNG，写回系统剪贴板用
    thumb_blob BLOB NOT NULL,        -- 缩略图 PNG（max 边 256px），列表展示用
    width INTEGER NOT NULL,
    height INTEGER NOT NULL,
    sha256 TEXT NOT NULL,            -- 内容去重用
    created_at INTEGER NOT NULL,
    source_app TEXT
);
```

**采集链路**：

1. `windows.rs` `on_clipboard_change()` 当前只读 `CF_UNICODETEXT`（:117），读不到文本就跳过。改为：文本读取失败时尝试 `CF_DIB`，解码为 BGRA -> 编码 PNG。
2. `source_app` 采集：复用 `foreground_title()`（windows.rs:103 已有），存窗口标题。
3. 缩略图：采集时生成（PNG，max 边 256px），不延后到展示时--避免列表滚动时重复解码。

**去重语义（定案）**：

4. **保留 10s 短窗口防连发**（`DEDUP_WINDOW_MS`，windows.rs:29）--这是内存态抖动过滤，挡 Ctrl+C 连发，轻量，不移除。
5. **新增内容去重"删旧留新"**（文本 + 图片统一）：入库前按内容哈希查现有记录，命中则 DELETE 旧记录 + INSERT 新记录（新 created_at）。文本用 fx_hash，图片用 sha256。
6. 移除原 `clipboard.rs:5` 注释"相同内容 10 秒内不重复记录"的误导性描述，改为"10s 防连发 + 跨时段内容去重删旧留新"。

**搜索引擎（clipboard_engine.rs）**：

7. 图片 item 稳定标题：`图片 {W}x{H} ({source_app或"未知"})`，desc 为复制时间。
8. 图片 item actions：`[Copy]`（写回系统剪贴板），0.16.5 追加 `[Pin]`。
9. 文本和图片在剪贴板列表（Alt+C）混合展示，按 created_at 排序；图片显示缩略图，文本显示 preview。

1. 新建 `src-tauri/nsis/uninstall-cleanup.nsh`，定义 `NSIS_HOOK_PREUNINSTALL` 宏：
   - `MessageBox MB_YESNO|MB_DEFBUTTON2`（默认选否）询问"是否同时删除用户数据与模型"；

2. `tauri.conf.json` `bundle.windows.nsis.installerHooks` 指向该 .nsh。
3. MSI 包（WiX）不在 0.16.6 范围--设置页一键清理入口兜底。

**设置页清理入口**：

4. 复用范式：`diagnostic.rs::clear_cache_db`（探测->DELETE->VACUUM->刷新）+ `stt/maintenance.rs`（探测->展示->确认->清理）。子 agent 开工前读这两个函数。
