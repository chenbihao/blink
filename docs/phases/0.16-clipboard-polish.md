# Blink 0.16 — 剪贴板增强、内容流转与桌面便签（Clipboard Enhancement, Content Flow & Sticky Notes）

> **范围**：修复剪贴板与设置页存量问题，打通 item actions 数组，抽取共享 Markdown 渲染，建立通用文本编辑器并首先接入剪贴板，补齐剪贴板图片与图片 pin，以及卸载清理能力；在此基础上实现内容流转闭环（chord-E/chord-S、query/item/选区→编辑器/便签）与可持久化桌面便签（数据模型、窗口、管理界面与崩溃恢复）。
>
> **状态**：✅ 已完成。
>
> **动机**：剪贴板历史已是高频 chord surface，但缺少可靠的编辑、图片和多动作链路；通用编辑器与共享 Markdown renderer 落地后，Blink 可将"刚刚出现的内容"直接转为可编辑、可常驻桌面的便签，省去新建、复制、切应用、粘贴的中间步骤。
>
> **前置**：0.15 pin 能力（0.16.5 图片→pin）；0.14 `ItemResult.actions` 协议（0.16.1 actions 投影）；0.15.10 chord `requires_input` 基础设施（0.16.9 contextual 解析）。
>
> **原则**：编辑器从第一天就是通用内容编辑器，但 0.16.0-0.16.3 只接剪贴板入口；便签是明确持久化的用户数据，关闭只隐藏、删除才移除；内容与窗口状态都可恢复；共享内容核心但不强行共享窗口外壳；不引入笔记库、Todo、文件夹、标签或同步；便签恢复不得阻塞主窗口 P0 唤起链路。

## 二、实现总结

0.16 完成了两条主线：

- **剪贴板与内容基础设施**：打通 `AppEntry.actions` 数组投影（capability→entries→前端），抽取共享 Markdown 渲染模块，建立通用内容编辑器并接入剪贴板编辑→回贴闭环，补齐图片采集/存储/缩略图/回贴/图片→pin，修复卸载清理的目录错配 bug 并补 Credential Manager 批量清理。
- **桌面便签与内容流转**：建立 `StickyNote` 持久化实体与恢复服务，实现便签窗口（直接编辑、有限色板、关闭隐藏、位置尺寸持久化），打通 chord-E/chord-S 内容流转（query/item/选区→编辑器/便签），提供便签管理界面，完成崩溃恢复与多显示器可靠性收尾。

## 三、核心决策

### 3.1 item actions 全量投影

`AppEntry.action` 升级为 `AppEntry.actions: Vec<Action>`，回车执行首个、右键展开全部。capability 层已完成 `ActionDef -> ItemAction` 数组投影，0.16.1 只修通 `items_to_entries()` 中 `actions.first()` 的压扁断点。修通后剪贴板、插件、AI 结果及未来"编辑/钉住"动作不再依赖前端按 source 写分支。文件管理类附加菜单（打开文件夹、复制路径等）仍由前端按 `lnkPath` 追加，不混入 capability actions。

### 3.2 Markdown 只共享渲染核心

从对话窗口抽取 `frontend/js/shared/markdown.js`，统一 Markdown 解析、净化与渲染。共享内容核心不等于共享窗口外壳——对话消息、编辑工作台和桌面便签布局职责不同，但 Markdown 语义、安全净化和主题 token 必须同源。

### 3.3 通用内容编辑器

编辑器窗口不命名为 `ClipboardEditor`，入口接受通用 payload（`EditableContent`：body / format / title / origin / origin_ref / save_policy）。0.16.0-0.16.3 只实现 `origin=clipboard` 的打开与保存策略：剪贴板项右键"编辑"→独立编辑器→编辑与预览→保存为一条新剪贴板记录并写回系统剪贴板，原历史项不原地覆盖。0.16.7-0.16.11 在不修改编辑器内核的前提下接入便签、query 和 chord-E。

编辑逻辑在前端，后端只做窗口创建 + 剪贴板读写桥接（`src/app/commands/content_editor.rs` 单文件 IPC 入口），不建 domain 模块——编辑器是应用层窗口编排，无独立业务域逻辑。

0.16.0-0.16.3 编辑器只做纯文本、Markdown 编辑/预览、复制与保存回贴；不做代码高亮、格式化、Diff 或 AI 加工。

### 3.4 剪贴板图片独立建表

图片放 `blink_cache.db`（cache 库），不进 `blink_history.db` 的 `clipboard_history` 表。原因：单张截图 CF_DIB ~14MB / PNG 1-3MB，塞进 max_items=10000 的历史库可达 20GB，且 SQLite 单 pool 写锁会阻塞文本历史和搜索历史。

采集链路：文本读取失败时尝试 `CF_DIB`→解码 BGRA→编码 PNG；采集时同步生成缩略图（max 边 256px），避免列表滚动时重复解码。去重保留 10s 短窗口防连发（内存态抖动过滤），新增跨时段内容去重"删旧留新"（文本 fx_hash、图片 sha256）。

### 3.5 卸载清理复用 STT 范式

设置页清理入口与 NSIS 卸载钩子共享后端清理函数，复用"探测→展示→确认→清理→刷新"范式。修正了 Tauri 默认 NSIS 模板 `deleteAppData` 执行 `$APPDATA\com.blink.launcher` 但实际数据在 `$APPDATA\blink` 的目录错配 bug。新增 `blink/*` Credential Manager 批量枚举与删除（`CredEnumerateW` + `CredDeleteW`）。

### 3.6 `StickyNote` 是独立持久化实体

不建立 `ContentDocument`/笔记库抽象，便签直接以 `StickyNote` 持久化（id / content / format / color / visible / x / y / width / height / always_on_top / created_at / updated_at）。数据写入 `blink_history.db` 的独立 `sticky_notes` 表，与启动历史、剪贴板历史分表管理；"清除历史"不得删除便签，只有便签删除和卸载全量清理可以移除。

**理由**：当前明确不做笔记，先抽象通用文档会引入尚无消费者的类型和迁移负担。未来若笔记立项，再评估将 `StickyNote.content` 迁为通用内容实体，而不是现在预埋。

### 3.7 内容和窗口状态都必须自动保存

内容输入短防抖自动写库；颜色、显隐、置顶、位置和尺寸在变化后防抖写库；失焦、隐藏和窗口关闭前强制 flush。便签的核心承诺是"放在那里就不会丢"——只在用户点保存或应用退出时写入，无法覆盖崩溃和系统强制结束。

恢复策略：启动后异步读取所有便签（不阻塞 Alt+Space）；`visible=true` 恢复窗口，`visible=false` 只进入管理界面；显示器变化时钳制到最近可见工作区；单条恢复失败只记录并跳过，不阻断其它便签和主窗口。

### 3.8 关闭、隐藏、退出、删除四种语义分离

| 操作 | 内容是否保留 | visible | 下次启动 |
|---|---:|---:|---|
| 便签关闭按钮 | 保留 | false | 不自动显示，可从管理界面恢复 |
| 管理界面"隐藏" | 保留 | false | 不自动显示 |
| 应用退出/系统重启 | 保留 | 不改变 | 原本显示的继续恢复 |
| 管理界面"删除" | 永久删除 | — | 不恢复，必须确认 |

窗口 close event 需区分"用户关闭便签"和"应用整体退出"——0.16.11 用 `IS_APP_EXITING: AtomicBool` 标志实现：退出时不 `prevent_close`、不修改 `visible`，退出前 `flush_all_sticky_windows()` 确保防抖中的未保存内容落库。

### 3.9 颜色采用有限成熟色板

首版提供有限语义色板（黄、粉、紫、蓝、绿、灰），默认黄色。颜色属于单条便签，不随全局主题覆盖；全局深浅主题只影响控件、阴影和 Markdown 代码块等辅助层。不引入任意取色——可读性、暗色主题和状态图标对比度问题由 token 配对保证。

### 3.10 便签可直接编辑，也可进入工作台

便签窗口支持直接编辑并自动保存，同时提供"在编辑器中打开"动作。便签只保留最小控件：拖动、颜色、更多菜单、关闭；Markdown 预览、复杂选择和未来格式化能力留在通用编辑器。编辑器以 `origin=sticky`、`origin_ref=sticky_id` 打开；保存回写同一便签，不复制出新实体。

### 3.11 chord 分为空闲入口与上下文动作

不移除现有 chord 总门禁，而是增加 action availability：Idle（query 为空且无用户结果时可用）和 Contextual（当前 query 或 active item 能提供所需内容时可用）。

- `Alt+E`：编辑当前内容；无上下文时打开空白编辑器。
- `Alt+S`：将当前内容创建为便签；无上下文时创建空白便签。

`requires_input` 基础设施已在 0.15.10 落地（trait 声明 + `getTapKeys` 动态过滤 + 入参管道 + hook 吞键收窄 + ChatAction 接通）。0.16.9 在此基础上扩展 contextual 解析——入参来源从 0.15.10 的"仅输入框文本"扩展为多源（active item 文本 payload > 非空 query > Awareness 选区 > 空白）。只有明确提供文本 payload 的 item 才能出现 edit/pin，不能把任意文件名或展示 label 当正文。

**空文本提示隐藏**：E/S 是 Contextual 上下文动作，空文本时主用途依赖 awareness 选区兜底，提示价值低。`ChordAction` trait 新增 `hint_hidden_when_empty()` 方法，E/S 覆盖为 `true`——空文本时 overlay 不显示 E/S 提示，但 Alt+E/S 触发全保留。Q（AI 对话）空文本时是明确入口，不隐藏。该字段仅影响 overlay 提示可见性，设置页始终展示全部。

### 3.12 便签管理是唯一集中管理入口

提供独立便签管理窗口，支持创建空白便签、显示/聚焦/恢复/隐藏/编辑/改色/删除。管理界面不是笔记库：不做文件夹、标签、全文知识管理、Todo 聚合或同步。

## 四、不进 0.16 的项

| 项 | 理由 |
|---|---|
| 笔记库 / Note 实体 / Todo / 文件夹、标签、双链、全文知识库 | 当前明确不做，不提前设计通用笔记模型 |
| WebDAV/云同步 | 多设备与冲突解决是独立 phase |
| 多人协作/分享 | 超出本地桌面工具范围 |
| 任意自定义颜色/背景图 | 首版有限色板优先保证可读性 |
| 富文本/WYSIWYG | 继续使用纯文本 + Markdown，不引入新编辑器依赖 |
| 代码高亮、格式化、Diff、AI 加工 | 编辑器高级能力，待基础闭环验证后评估 |
| QuickLook 式文件预览 | 与内容流转正交且边界风险高，远期候选 |
| 剪贴板文件列表（CF_HDROP） | 独立数据类型，后置 |
| SearchItem 升级为 actions 数组 | 查询引擎只产单动作；仅 `AppEntry` 需要统一数组契约 |
