# Blink 0.15 — 截图标注体验重做（Alt+A Screenshot Redesign）

> **范围**：重做 Alt+A 截图标注体验，补齐长截图采集与选区阶段的窗口吸附、像素检查能力。
>
> **状态**：🚧 进行中。0.15.0~0.15.6、0.15.8~0.15.9、0.15.11~0.15.14 已完成并精简；当前只保留 0.15.7 的完整实施信息。
>
> **动机**：截图是 Blink 的高频 chord surface。标注工具已经完成系统性重做，剩余工作集中在长截图的可验证可靠性，以及选区增强的最终验收与收尾。
>
> **前置**：0.11 标注能力；0.14.7 截图模块拆分与 OCR 基础设施迁移。
>
> **原则**：无 bundler；长截图未确认的帧不得污染已确认结果；定位不确定时拒绝猜测；截图像素与回放数据默认不持久化、不进入日志。

---

## 一、背景与边界

### 1.1 本阶段解决什么

0.15 已完成工具栏、per-tool 配置、文字与数字标号、高斯模糊、聚光灯、局部放大、色盘、配色提取和 pin 反馈等标注体验重做。当前剩余两条线：

- **0.15.7 长截图**：滚动驱动、稳定检测、帧定位、双向拼接、预览、编辑与输出；继续提高快速滚动、重复纹理和丢失恢复场景的鲁棒性。
- **0.15.8 选区增强**：顶层窗口吸附、像素放大镜取色、坐标与尺寸提示；仓库已有一版未验收原型，但预热生命周期、单击/拖动判定、rAF 节流和混合 DPI 坐标契约仍需按 R0~R4 收敛。

### 1.2 明确不是问题的

| 项 | 结论 |
|---|---|
| pin 左上角缩放锚点 | 是保证缩放丝滑的刻意设计，不修改缩放数学 |
| 手动与自动滚动并存 | 手动模式兼容性更高，自动模式更省操作，两者互为降级路径 |
| 定位丢失后暂停 | 是数据正确性保护；无法验证的帧不能靠滚动方向猜坐标 |
| 灰度关键帧召回 | 只负责找候选，候选仍须经高分辨率参考确认 |
| `cmd.mode` 存在命令中 | 是 undo/redo 正确重放的必要条件，不应退回全局模式状态 |

## 二、核心设计与决策

### 2.1 已完成标注能力摘要

0.15.0~0.15.6 及后续反馈轮次已收敛为以下最终事实，实施过程与逐条反馈留在 git 历史：

| 能力 | 最终实现结论 |
|---|---|
| 工具栏 | 高频工具分组为 split-button；撤销/重做/重置始终可见；工具组支持滚轮轮换 |
| 工具配置 | `TOOL_CAPS` 描述能力；笔画、画笔、文字、效果各自持有独立配置；模式写入 command |
| 文字与标号 | 字号、字体、粗体、斜体、阴影独立；数字标号从可见命令栈推导序号 |
| 效果工具 | 高斯模糊、单次/多次聚光灯、局部放大已落地；preview 与 final render 均覆盖 |
| 马赛克 | 一个工具承载两种模式：框选为整片像素化，画笔为轨迹涂抹 |
| 取色与配色 | SV 色盘、HEX/RGB/HSL、截图取色、median cut 主色与 harmony 配色已落地 |
| pin | 保留左上角缩放锚点；缩放提示固定定位，不随图片缩放漂移 |
| 交互收尾 | 数值滑块上滚增大；列表类滚轮按自然顺序切换；文字/水印配置使用可关闭 sub-panel |

关键维护约束见 `spec-frontend.md`；本 phase 不再保留已完成部分的代码草案和验收流水账。

### 2.2 长截图——闭环采集（已定）

**定案**：前端持有唯一闭环，每轮严格执行：

```text
滚动一次 → 灰度探针等待稳定 → 抓取完整帧 → 定位与拼接确认 → 才允许下一轮滚动
```

自动滚动不存在独立固定 tick 生产者。手动滚动与自动滚动共用稳定检测和全帧确认；上一轮未确认时不得推进下一轮。

**理由**：固定节拍会在页面动画、惯性滚动或前端繁忙时跨过可匹配重叠区，使“滚动过快”演变成不可恢复的连续错误。

### 2.3 长截图——有坐标帧与分层重定位（已定）

每个确认帧携带长图坐标 `top`。正常路径先匹配上一确认帧；局部失败后依次使用：

1. 当前位置附近关键帧；
2. 滚动方向对应的全局关键帧；
3. 后续阶段增加的已拼接内容分区召回；
4. 原分辨率参考精确确认。

小型灰度指纹只做候选召回。远距离候选、相似内容候选和大跨度跳转必须经过更严格确认；无法消除歧义时进入 `lost`，保留已确认内容并暂停自动滚动。

### 2.4 长截图——统一会话与生命周期（已定，架构阶段已完成）

`ScrollCaptureSession` 是长截图状态、代际、定时器和在途任务的唯一所有者。普通 overlay、输出模块和长截图协调器不再各自维护清理字段；退出、重置、失焦和取消共享同一生命周期入口。

采集框与缩略预览独立为呈现模块；普通截图与长截图复用 PNG 编码和 pin/save/copy 输出分发。`ss.scroll*` 访问器暂作兼容门面，后续内部模块逐步迁移到显式 `session.*`。

### 2.5 选区增强——顶层窗口枚举（已定）

overlay 打开时一次性调用 Rust `EnumWindows`，过滤不可见、cloaked、tool window 等目标，以 `DWMWA_EXTENDED_FRAME_BOUNDS` 获取去除阴影后的真实边界；前端缓存矩形并在 mousemove 时纯 JS hit-test。

不用 `WindowFromPoint` 轮询：它容易命中按钮等子窗口，顶层窗口粒度不稳定。吸附提示只画虚线框，不改变区域亮度。

**能力边界**：0.15.8 只识别桌面上的**顶层应用窗口**。窗口内部按钮、输入框、网页卡片等 UIA 控件，以及仅凭截图像素推断的任意视觉区域，均不进入本版。前者需单独评估 UI Automation 兼容性，后者会引入图像分割或视觉模型，不应混入轻量窗口吸附。

### 2.6 选区增强——像素检查器（已定）

选区尚未确定时显示跟随鼠标的 9×16 像素网格、物理坐标和中心色值。mousemove 只记录位置，实际 `getImageData` 与绘制由 rAF 节流；Shift 切换 HEX/RGB/HSL，C 复制当前色值。

这里的 pixel inspector 是选区阶段工具，与标注工具 magnifier（局部放大）是两个独立能力。

### 2.7 不进 0.15 的项

| 项 | 理由 |
|---|---|
| CAP 闭环（AI 看见屏幕） | 属于后续 AI 感知能力，不与截图体验收尾耦合 |
| OCR/翻译能力增强 | 已有链路保持不变，不扩大当前 phase 范围 |
| 无验证锚点时推测缺失内容 | 会生成看似连续但实际错误的长图，违反正确性原则 |
| 窗口内部 UIA 控件吸附 | Electron、浏览器、自绘控件兼容性差异大，另立增强项评估 |
| 任意视觉元素识别 | 需要图像分割或视觉模型，会显著扩大体积、性能和隐私边界 |

## 四、0.15.7 长截图

### 4.1 用户流程与状态机

```text
idle
  → 框选区域并点击“长截图”
capturing
  → 手动或自动滚动，闭环采集与定位
  → 点击“编辑”
editing
  → 对合成长图标注
  → pin / 保存 / 复制
idle
```

采集阶段使用专属工具栏和右侧缩略预览。当前可靠路径为纵向；横向入口不作为当前验收目标。编辑阶段使用合成长图作为独立底图，不再从屏幕选区重新抓取。

### 4.2 R1：闭环采集（已完成）

- Rust 将采集带降采样为至多 96×64 灰度探针，避免稳定等待反复跨 IPC 传完整 RGBA。
- 前端按短间隔采样，连续稳定后才抓完整帧；超时交由全帧匹配确认。
- 手动 wheel 合并输入；自动模式每轮只注入一次滚轮。
- 自动滚动依据已确认位移调整下一轮 wheel delta，并限制幅度。
- `unchanged` 连续出现才判断到底；`no-match` 暂停自动模式并保留结果。
- ESC、编辑、输出、取消和 overlay 重载通过代际令牌使旧任务失效。

### 4.3 R2：双向拼接与重定位（已完成）

- 同时估算上、下方向位移，滚轮方向只作为候选优先级，不直接决定拼接方向。
- 记录当前视口在长图坐标中的绝对 `top`；只保存新暴露的顶部或底部行。
- 回滚到已有区域只更新定位，不重复追加内容。
- 局部匹配失败后先搜附近关键帧，再扩大到方向相关的全局关键帧。
- 灰度候选必须使用不可变纵向参考进行精确确认。
- 多个远距离候选分数接近时拒绝定位，避免重复纹理导致错误跳转。

**能力边界**：重定位只能恢复仍与已捕获内容存在视觉重叠的帧。一次滚入完全未采集区域且没有任何锚点时，不推测中间缺失内容。

### 4.4 R3：行为保持型架构收敛（已完成）

- `ScrollCaptureSession` 集中状态、代际、timer、wheel 队列和在途 capture。
- `resetScrollCaptureSession` 成为 overlay 重载的同步失效入口；异步退出复用同一状态清理。
- 预览与采集框移入 `ss-scroll-preview.js`，不参与匹配决策。
- 长截图复用 `ss-output.js` 的 PNG 编码与输出分发。
- 移除 `ss-output.js` 动态反向 import `ss-scroll.js` 的依赖。
- 保留 `ss.scroll*` 访问器兼容现有调用，真实数据只存在 session。

### 4.5 R4：帧序列记录与离线回放（下一步）

**目标**：让真实场景中的偶发错位可重复、可自动回归，避免靠反复手测调阈值。

**设计**：

- 仅在显式开发开关开启时记录：采集帧、时间、滚动方向、探针结果、定位决策和已确认 `top`。
- 用目录级 manifest 描述一段会话；算法测试从 fixture 读取帧，逐帧调用纯匹配/定位函数。
- 原始截图可能含敏感信息：默认关闭，只保存在用户指定的本地目录，不进入 tracing；fixture 入库前必须裁剪或脱敏。
- 首批场景覆盖：连续向下、向下后回顶、快速滚动丢失后恢复、重复纹理、局部动画、完全无重叠、滚到底。

**验收**：

- 同一 fixture 重放结果确定，输出每帧 accepted/rejected、top、追加区间和原因。
- 已确认区域不因后续拒绝帧发生变化。
- “回到顶部”最终定位回已知顶部，不追加到底部。
- 重复纹理 fixture 不出现未经确认的大跨度跳转。

### 4.6 R5：诊断模型与置信度可视化

**目标**：把笼统的“滚动过快”拆成可诊断原因，并隔离错误决策对后续预览的影响。

统一匹配决策至少包含：候选来源、预计方向、最佳与次佳分数、重叠率、候选 `top`、与上次位置距离、接受/拒绝原因。拒绝原因区分：

- `unchanged`：画面未变化；
- `no-overlap`：没有可验证重叠；
- `ambiguous`：多个候选过于接近；
- `low-confidence`：最佳候选本身不可信；
- `motion-timeout`：页面未稳定；
- `inactive`：会话已经失效。

开发模式在预览旁显示当前 top、候选来源和置信度；正式 UI 只显示对用户有行动意义的提示。预览定位只能消费已确认决策，拒绝帧不得推进 locator。

### 4.7 R6：自动滚动闭环体验优化

- 以实际确认位移而非 wheel delta 作为速度反馈。
- 连续低置信、稳定超时或位移过大时逐级减速；恢复稳定后缓慢提速。
- 识别惯性滚动和局部动画，页面仍运动时不抓完整帧。
- 丢失后停止注入新滚轮；定位恢复后才允许继续。
- wheel 穿透、稳定等待和全帧 capture 保持单生产者串行，不能形成第二条隐式滚动链。

### 4.8 R7：已拼接内容分区召回与迟滞确认

在关键帧召回仍失败时，可对已拼接内容做**有界的粗到细分区搜索**：

1. 按滚动方向优先搜索长图对应半区，而不是无条件扫描整图；
2. 低分辨率分区指纹召回少量候选；
3. 从已确认帧重建候选附近原分辨率视口；
4. 精确验证后才接受坐标；
5. 大跨度跳转要求连续两帧或更强唯一性确认。

增加位置连续性和迟滞：新候选只比当前轨迹略好时不切换；只有显著更可信，或当前轨迹已经失效，才允许跳到远端候选。该机制用于避免列表、表格和重复卡片间来回跳定位。

### 4.9 R8：剩余架构拆分

在回放测试覆盖后，再把 `ss-scroll.js` 拆为：

- 采集驱动：wheel 转发、稳定等待、完整帧抓取；
- 追踪协调器：候选召回、精确验证、接受/拒绝决策；
- 自动滚动控制器：速度反馈、暂停、恢复和到底判断；
- 会话与呈现：继续保持独立。

内部调用逐步从 `ss.scroll*` 迁到 `session.*`，兼容门面只供尚未迁移的外围模块使用。拆分必须以回放结果完全一致为验收条件。

### 4.10 风险与降级

| 风险 | 处理 |
|---|---|
| 快速滚动跨过全部重叠区 | 暂停并要求回滚到可定位区域，不补造缺失内容 |
| 重复纹理产生多个候选 | 标记 ambiguous，拒绝大跨度定位 |
| 动态广告/视频影响稳定检测 | 探针容忍小面积变化；必要时后续增加静态区域投票 |
| 自动滚轮对自绘窗口无效 | 保留手动滚动模式和明确提示 |
| 超长图内存与 Canvas 上限 | 后续按实测决定 tile 化输出，不在当前阶段提前引入 |

## 五、0.15.8 选区体验增强（已完成）

### 5.1 做了什么

选区阶段增加两项能力：顶层窗口吸附和像素检查器。

- **窗口吸附**：overlay 打开时一次性 `EnumWindows` 枚举顶层桌面窗口，过滤不可见/cloaked/tool/noactivate/自进程/桌面目标，用 `DWMWA_EXTENDED_FRAME_BOUNDS` 取真实边界。鼠标悬停时显示蓝色虚线预选框（无背景填充），未明显移动即松开采用窗口矩形；按下后移动 ≥3 CSS px 转为自由框选。吸附后保存 HWND 供长截图优先使用。
- **像素检查器**：选区未确定时显示 9×16 像素网格 + 物理坐标 + 中心色值。mousemove 只记录 pending 坐标，`getImageData`/绘制/DOM 定位全部 rAF 节流。边缘采样用有界读取 + 网格偏移保证中心格对应鼠标像素。Shift 切换 HEX/RGB/HSL（忽略 repeat），C 复制色值。
- **坐标契约**：新建 `ss-selection-geometry.js` 纯函数模块统一物理屏幕 ↔ bitmap ↔ CSS 换算，选区提示、输出裁剪、窗口矩形转换均引用同一组 helper。

**能力边界**：只识别顶层应用窗口，不识别窗口内部 UIA 控件或任意视觉区域。

### 5.2 关键约定

- 吸附提示只画虚线框，不改变区域亮度。
- 窗口列表按 generation 防过期回流；`__blinkReloadScreenshot` 重新加载。
- EnumWindows 按 Z-order 从前景到背景返回，前端正序遍历取第一个命中。
- 手动选区预览为实线边框，智能预选为虚线边框，视觉上区分。
