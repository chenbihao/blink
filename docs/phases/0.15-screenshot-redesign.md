## 一、背景与动机

### 1.1 为什么 0.15 做这件事

截图（Alt+A）是 Blink 四个 chord surface 之一，是"独占屏幕"的高频能力。0.8.7 + 0.11 已搭起完整标注能力（选区/画笔/形状/马赛克/文字/水印/OCR/图上翻译/钉图），但交互层有三个显性痛点：

1. **菜单栏过长**——在 27 寸屏占近 1/3 垂直空间，11 组按钮平铺。
2. **配置维度单一**——全工具共用一个 `width`（2/4/8 三档），文字字号、画笔粗细、高亮宽度、橡皮半径全部由这一个标量派生（文字=`width*6`、高亮=`width*4`、橡皮=`width*3`），无法独立调参。
3. **工具缺失 + 取色简陋**——缺高斯模糊/聚光灯/放大镜/数字标号；取色只有原生 `<input type="color">`，无色盘/HEX/RGB 切换/取色器/配色提取。

### 1.2 审查澄清（深读代码后的重要修正）

| 项 | 澄清 |
|---|---|
| ~~pin 缩放锚点是 bug~~ | **推翻**。深读 `pin.html:9-20` 注释，"左上角固定"是深思热虚的设计（60fps 丝滑、Snipaste 同款），不是 bug。用户反馈的"缩放百分比指示器定位"问题是 **zoom label 样式**（指示器贴窗口右下角，应贴图右下角），与缩放数学无关 |

## 二、核心设计 / 决策

### 2.1 范围与菜单结构（已定）

**范围**：0.15 全做（大 phase）。

**菜单结构 —— 5 核心高频一级 + 其余下拉 + 后置独立**：

```
核心高频一级（左→右，按使用频率）:
│ 选取 │ 形状▾ │ 画笔▾ │ 马赛克▾ │ 文字▾ │ 橡皮 │
              默认矩形 默认画笔 默认马赛克 默认文字
              └ 椭圆   └ 箭头   └ 涂抹   └ 水印
              └ 聚光灯 └ 高亮▾  └ 模糊   └ 数字标号
              └ 局部放大  (multiply/translucent 下拉切换)
                └ 倍率子菜单(1.3×/1.5×/2.0×)

共享配置组:
│ 颜色▾ │ 笔画▾（粗细+样式）│ 画笔粗▾ │

操作组（0.15.9 改为三键一组，始终可见）:
│ 撤销 │ 重做 │ 重置 │

输出组:
│ OCR │ 翻译 │ 保存 │ 钉图 │ 长截图 │ 复制 │ 取消 │
```

**关键决策**：
- **5 核心**（形状/画笔/马赛克/文字/橡皮）为独立一级 split-button，默认工具是该组高频项（画笔组默认**画笔**而非箭头，画笔优先级更高）
- **高亮/箭头/涂抹/水印/数字标号**等低频变体作为各自组的下拉子项
- **聚光灯/放大镜**归入形状组下拉子项（0.15.9 从后置独立改为形状组内）；放大镜带倍率子菜单（1.3×/1.5×/2.0×，默认 1.3×）
- **取色**后置独立（低频但有用）
- **箭头降级**：原属笔画组一级，现降为画笔组下拉子项（画笔优先级更高，作组默认）
- **操作组三键一组**（0.15.9）：撤销/重做/重置始终可见（原 hover 展开 redo 已废弃）；重置按钮清空全部标注

### 2.2 per-tool 配置模型（核心决策）★

**定案**：粗细按工具性质分两类——笔画类（strokeWidth 5 档 + strokeStyle）vs 画笔类（brushSize 数值）；文字独立字体编排；效果类各自独立强度。颜色全局共享。
**理由**：粗细不是单一维度。现状单标量 `currentWidth`（`annotation-engine.js:34`）导致调画笔粗细连带影响文字字号（`width*6`）、高亮宽度（`width*4`）等，违反直觉。

把单一 `currentWidth` 标量重构为**按工具语义分类的配置模型**。关键认知：粗细不是单一维度，按工具性质分两类——**笔画**（细而精确）vs **画笔**（粗而面积大）。

| 配置层 | 字段 | 归属工具 | 调节方式 |
|---|---|---|---|
| **共享·颜色** | `color` | 所有工具 | 当前色 + 6 色预设；当前色点击展开完整色盘（见 §2.8） |
| **笔画类** | `strokeWidth`（5 档）/ `strokeStyle`（实线/虚线） | 形状（rect/ellipse）、箭头、画笔（pencil） | 5 档快选 + 悬浮滚轮 |
| **画笔类** | `brushSize`（数值） | 涂抹（mosaic）、橡皮、高亮 | 预设档 + 滚轮 + 实时预览光标 |
| **文字/数字标号** | `fontSize`（5~72）/ `fontFamily` / `bold` / `italic` / `shadow` | 文字、数字标号 | 字号档 + 滚轮；字体下拉；粗/斜/阴影切换 |
| **效果类** | `blockSize`（pixelate）/ `intensity`（blur） | 块状马赛克、高斯模糊 | 独立强度滑块 + 滚轮 |

**文字斜体特别说明**：截图标注的 italic 是**用户创作内容的样式**，不是 Blink 产品 UI 的字体。`spec-frontend` 的"中文 UI 不斜体"铁则约束的是软件界面字体辨识度，不约束用户在标注画布上的创作表达。两者正交。

### 2.3 滚轮优先交互铁则（横切，已定）★

**定案**：所有数值维度支持悬浮滚轮调节 + 实时预览。建议沉淀为前端交互规范。
**理由**：交互顺手的程度是 pixpin 式打磨的核心。

**凡是能滚轮调的维度都应支持滚轮**——粗细、大小、字号、强度等，用户鼠标悬浮在控件上时滚轮可直接调，不强制点开菜单。此铁则适用于 0.15 全部工具，并建议沉淀为前端交互规范。

### 2.4 数字标号（已定）

text 工具变体，点击按顺序自增放置数字（1/2/3...）。复用文字配置（字号/字体/粗斜阴影/颜色）。

**counter 与 undo 栈关系（已定）**：counter 不单独维护，而是**实时从 undo 栈推算**——counter = 当前 undo 栈可见前缀（`commands.slice(0, undoIndex+1)`）中 number 工具命令的最大序号 + 1。这样 undo/redo 自动正确：撤销 3 → 推算出 counter=3（下次放还是 3）；redo 3 → counter=4。无需手动同步 counter 与栈。

### 2.5 高斯模糊（已定）

模糊组新增第三种 `blur`，沿用 `pixelate` 的框选逻辑（p1/p2 两点），渲染用 canvas `filter: blur(Npx)`，N 由独立 `intensity` 控制。

### 2.6 聚光灯与局部放大（已定，0.15.9 修订）

两个工具，归形状组下拉子项（0.15.9 从后置独立按钮改为形状组 dropdown 内项目）。**命名注意**：这里叫"局部放大(magnifier)"是**标注工具**（在选区内画一个放大区域），与 §2.15 选区阶段的"像素放大镜取色器(pixel inspector)"是**完全不同的两个东西**——后者是选区未定时跟随鼠标的 9×16 取色网格，不是标注工具。文档统一区分：magnifier = 标注局部放大工具；pixel inspector = 选区取色器。

- **聚光灯（spotlight）**：框选某处，其余地方压暗提示焦点。渲染 = 全屏半透明黑色遮罩 + 镂空选中区。
- **局部放大（magnifier）**：圈选某范围放大显示。渲染 = 局部区域 scale 变换 + 边框。数据源用 `cropSourceCanvas`（`reset()` 已缓存），不要用 1× 的 `cropImageData`。**0.15.9**：倍率可调（1.3×/1.5×/2.0×，默认 1.3×），形状组 dropdown 内有倍率子菜单行（选中放大镜时显示）。

两者默认框选（圈定区域语义清晰），不强求模式切换。

### 2.7 框选/画笔模式切换（已定）★

**核心洞察**：现状 `pixelate`（框选）和 `mosaic`（画笔）是两个独立工具，但本质是同一种效果的两种使用方式。统一为带模式切换的单工具。

**定案**：模糊/马赛克/橡皮/高亮 等效果类工具统一支持框选/画笔模式切换，二级菜单首位是模式切换器，**默认画笔**。

**关键技术约束（深读发现）**：模式必须**存在 command 里**（`cmd.mode = 'box' | 'brush'`），不能是全局 `currentMode`。理由：undo/redo 要重放用户画那一刻的模式；若用全局态，用户切换模式后 redo 会用新模式重放旧命令，导致错乱。这复用了 `overlayLayer.mode` 的先例（mode 在数据对象上而非全局）。

框选复用 `pixelate` 的 p1/p2 两点逻辑；画笔复用 `mosaic` 的点序列逻辑。

### 2.8 取色器与色盘 UI（已定）★

**色盘设计**（参考 pixpin，布局：预设上 + 横条下）：

```
┌────────────────────────┐
│ 预设 ▢▢▢▢▢▢▢▢          │  ← 预设阵列在最上（高频快选）
├────────────────────────┤
│ ┌────────┐  取色器 ▢   │  ← SV 正方形色盘（左白下黑，右上当前色）
│ │        │             │     + 右侧取色按钮（吸图取单色）
│ │ SV色盘 │             │
│ │        │             │
│ └────────┘             │
│ 色相  ████▍███████     │  ← 色相条（横，在色盘下方）
│ 透明 ░░░░▍░░░░░░░     │  ← 透明度条（横，在色盘下方）
├────────────────────────┤
│ [HEX▾] #FFFFFF  [确认] │  ← 色彩类型下拉 + 数值 + 确认/取消
└────────────────────────┘
```

- **预设阵列**：放最上方（高频快选，收纳旧 8 色 + 常用色）
- **SV 色盘**：正方形，左白下黑，右上是当前色（标准 HSV picker 布局）
- **色相条/透明度条**：横排放在色盘下方（不竖排右侧）
- **取色按钮**：吸管图标，点击进入"从截图取单色"模式。**像素源分阶段**：标注模式（cropImageData 已存在）复用 `sampleAverageColor()`；选区未定阶段（cropImageData 为 null）直接从 main canvas `getImageData`（main canvas 已设 `crossOrigin` 不污染）。两种阶段都要支持取色。
- **色彩类型联动**：HEX / RGB / HSL 三种切换，数值与色盘双向联动
- **滚轮支持**：色相条/透明度条支持悬浮滚轮调节（§2.3 滚轮优先铁则）

### 2.9 配色提取（已定，含色彩理论）★

**定案**：基础档（median cut 主色调）必做；进阶档（harmony 配色方案）放最后视情况做。
**理由**：预研验证算法亚毫秒级可行，但"顺眼配色"需色彩理论，难度有不确定性，降级策略保留。

**两档能力**：

| 档 | 内容 | 难度 | 算法 |
|---|---|---|---|
| **基础档** | 单色取色（点取 #xxxxxx）+ median cut 提取主色调（N 个代表色展示供复制） | ⭐ 低 | 纯 JS 亚毫秒级，预研已验证 |
| **进阶档** | 基于主色生成 harmony 配色方案（互补色/三元色/类比色等），可选每组配色数量 | ⭐⭐⭐ 中高 | 色彩理论 hue harmony rules |

**预研结论**（已用 Node 验证算法可行性）：
- 像素采样需降采样（全图像素太多），取 N×N 网格采样
- median cut / 直方图 Top N / HSL 聚类均为亚毫秒级，纯 JS 可行
- 真正"顺眼配色"需 hue harmony rules（互补 180°/三元 120°/类比 30° 等），算法本身不难，难点在"美学定义"

**降级策略**：进阶档放 0.15 最后，视情况决定是否做那么细致。若 harmony 实现复杂度超预期，可只交付基础档。

### 2.10 pin 百分比指示器样式修复（已定，重新定性）

**定案**：是 zoom label 样式定位问题，非缩放 bug。缩放数学不动（左上角固定缩放设计保留，那是 60fps 丝滑的保证）。
**理由**：深读 `pin.html:9-20` 注释，"左上角固定"是深思热虚的设计（Snipaste 同款），不是 bug——避免后人误改刻意设计的丝滑缩放逻辑。用户反馈的"缩放百分比定位"问题，是 zoom label（`#zoom-level`）样式贴窗口右下角而非图右下角。

`pin.html` 的 `#zoom-level`（缩放百分比指示器）现在贴**窗口**右下角，应贴**图**右下角。纯 CSS/JS 定位调整。

### 2.11 长截图（scroll capture，已定纳入 0.15）★

**性质**：采集层能力，非标注增强。0.15 唯一的后端线，也是最复杂、最不确定的一块。

**入口（已定）**：先框选矩形（确定宽度 W + 起点）→ 工具栏出现 → 点【长截图】按钮。与现有 pin/copy/ocr 一致，不另设状态机。框选矩形宽度 = 采集带宽度（用户可控截多宽）。

**三阶段状态机 + 专属工具栏**：

```
[阶段1: 拼接中]  点长截图按钮后进入
  专属工具栏显示:
    │ 方向▾(纵向/横向) │ 自动滚动 │ 编辑 │ | pin │ 保存 │ 复制 │ 取消 │
  + 右侧实时预览缩略图(拼接进度可见)
  + 选区变为"采集带"(宽度=W,高度随滚动动态增长)

  滚动模式(两种并存,用户选):
    - 手动滚动(默认): 用户自己滚,软件监听截帧拼接
    - 自动滚动(点按钮): SendInput 驱动滚动 + 截帧

  点[编辑] → 合成完整长图 → 进阶段2

[阶段2: 长图编辑]  合成长图后进入
  切回完整截图工具栏(标注引擎),对长图做标注
  - 复用现有 annot.reset(pw, ph, cropData) ← cropData 来自拼好的长图
  - 标注引擎对尺寸无硬上限,理论可吃长图
  - 编辑完 → 输出(接阶段3)或回到阶段1继续滚

[阶段3: 输出]  pin/保存/复制 接现有链路
```

**专属工具栏控件（已定）**：
- **方向切换**（纵向/横向）：纵向 = 垂直滚动（默认）；横向 = 水平滚动（表格/时间轴场景，较少见）
- **自动滚动按钮**：点击后软件 SendInput 驱动滚动 + 截帧（与手动滚动是两种并存模式）
- **编辑按钮**：点后才合成图片进入标注编辑（拼接中不合成，省性能）
- **输出操作**（pin/保存/复制/取消）：保留，与普通截图一致

**为什么双滚动模式并存**：手动滚动可靠性高（用户主动，软件被动拼接，避开窗口兼容性）；自动滚动省事（一键到底）但有兼容性风险（自绘滚动条/虚拟列表/Electron 可能驱动失败）。pixpin 两种都提供，让用户按场景选。

**长图编辑的架构可行性**（已核实，需小改）：`annot.reset(pw, ph, cropData)` 只关心 ImageData，对尺寸无上限约束——这部分通的。但 `enterAnnotationMode`（index.js:225）内部用 rect.x/y 去 main canvas 抓 cropData，长图的 cropData 是自己合成的，**不能直接调它，需新增 `enterAnnotationWithCropData` 入口**（抽取"进入标注"后半段，跳过屏幕抓像素）。属小改，非阻塞。

**难点**：
- 拼接去重（相邻帧重叠区模板匹配，纯色/重复纹理可能失败需降级）
- 自动滚动的 SendInput 兼容性（部分窗口驱动失败需降级提示）
- 实时预览性能（长图缩略图追加渲染）
- 超长图（5000px+）标注 canvas + getImageData 性能待实测

### 2.12 复用盘点

### 2.14 智能窗口吸附选区（已定）★

**功能**：截图选区阶段，鼠标 hover 在窗口上时，**虚线框**自动高亮推荐选区（该窗口的真实边界），单击即选中。

**核心实现（ShareX 同款，非 WindowFromPoint 轮询）**：
- overlay 打开时**一次性 `EnumWindows`** 枚举所有可见顶层窗口（过滤 cloaked/toolwindow），用 `DWMWA_EXTENDED_FRAME_BOUNDS` 取真实边界（去掉不可见阴影边距，`GetWindowRect` 会大 7-8px），缓存矩形列表
- mousemove 时纯 JS hit-test（`pointInRect`，ss-utils.js 已有），命中则画虚线框
- 单击（mousedown 不拖动）吸附为选区

**为什么不用 `WindowFromPoint`**：它会返回按钮级别的子窗口（对话框里的按钮），需 `GetAncestor` 向上走，脆弱。EnumWindows-once + hit-test 在枚举时就决定粒度（顶层），绕开陷阱。

**视觉约束**：只用**虚线框**提示，不动亮度/不加蒙版——避免干扰用户精确框选（用户反馈明确要求）。

**Blink 已有基础设施**：全屏透明 overlay canvas、多显示器 DPI（DisplayGeometry）、Tauri command 模式。要补：Rust `EnumWindows` 枚举器 ~150 行 + 1 个 `screenshot_window_list` command + 前端 hover 虚线框渲染。

### 2.17 高亮归类 —— 画笔类，合并为单工具下拉切变体（已定）★

**定案**：highlight-multiply/translucent 归画笔类，用 brushSize；**UI 合并为一个"高亮"按钮 + 下拉切变体**（multiply 同色不加深 / translucent 多笔加深）。
**理由**：高亮本质是粗的半透明画笔（面积覆盖），语义接近涂抹/橡皮。两个变体渲染逻辑不同（multiply 按 color 分组渲染避免同色加深，translucent 逐笔 alpha），但用户视角是"高亮的一种"，合并为单工具 + 下拉切换更符合心智模型（pixpin 同款），减少一级按钮占用。
**实现影响**：command 里仍用 `type: 'highlight-multiply'|'highlight-translucent'` 区分（渲染层需要），但 UI 层"高亮"工具的 `data-tool` 切换实际写入的是当前选中变体。下拉开 + icon-mirror 复用 split-button 机制。

### 4.8 0.15.7 长截图（采集层，后端线）

**目标**：支持滚动截取长页面（参考 pixpin 交互）。

**性质**：0.15 唯一的后端线，与前端标注正交，也是全 phase最复杂、最不确定的一块。

**完整交互流程（已定，三阶段 + 专属工具栏）**：
```
1. Alt+A 进入截图
2. 鼠标拖出矩形选区（确定宽度 W + 起点 Y0）
3. 工具栏出现，选区已定（与 pin/copy/ocr 一致）
4. 点【长截图】按钮
   ↓ 进入 [阶段1: 拼接中]
5. 隐藏默认工具栏，显示长截图专属工具栏:
     │ 方向▾(纵向/横向) │ 自动滚动 │ 编辑 │ | pin │ 保存 │ 复制 │ 取消 │
   选区变为"采集带"(宽度=W,高度随滚动动态增长)
   右侧出现实时预览缩略图
6. 滚动(手动或自动) → 逐帧截取 → 重叠区模板匹配拼接 → 预览追加
7. 点【编辑】 → 合成完整长图
   ↓ 进入 [阶段2: 长图编辑]
8. 切回完整截图工具栏,对长图标注(复用 annot.reset)
9. 编辑完 → pin/保存/复制
   ↓ [阶段3: 输出] 接现有链路
```

**交互决策（已定）**：
- **入口**：先框选 → 点按钮（与现有 pin/copy/ocr 一致，不另设状态机）
- **宽度来源**：框选矩形宽度 = 采集带宽度（用户可控截多宽）
- **双滚动模式并存**：手动滚动（默认，用户主动滚软件被动拼）+ 自动滚动（点按钮 SendInput 驱动）
- **专属工具栏**：拼接中隐藏默认工具栏，显示长截图专用（方向/自动滚动/编辑/输出）
- **编辑回环**：点编辑才合成长图进标注；拼接中不合成省性能

**实现要点（可分派）**：

*前端三阶段状态机*：
- `ss` 状态加 `scrollCapturePhase: 'idle' | 'capturing' | 'editing'` + `scrollFrames: ImageData[]` + `scrollDirection: 'vertical'|'horizontal'` + `autoScroll: boolean`
- 阶段切换：idle→capturing（点长截图按钮）；capturing→editing（点编辑，合成长图调 `enterAnnotationMode` 喂合成 cropData）；editing→output（标注完输出）
- 工具栏切换：capturing 阶段隐藏默认 toolbar，显示 `#scroll-toolbar`（专属 DOM）；editing 阶段切回默认 toolbar

*专属工具栏 DOM*（chord-screenshot.html 新增 `#scroll-toolbar`）：
- 方向下拉（纵向/横向，默认纵向）
- 自动滚动按钮（toggle，激活后 SendInput 驱动）
- 编辑按钮（触发合成 + 进 editing）
- 输出组（pin/保存/复制/取消，复用现有绑定）

*滚动检测（两模式）*：
- 手动模式：监听全局 wheel 事件（前台窗口滚动时触发）→ 截帧
- 自动模式：Rust 端 SendInput 模拟滚轮（间隔如 80ms）+ 每次截帧 → 驱动失败降级提示
  - **驱动窗口 = 进入长截图时记录的前台窗口**（`GetForegroundWindow` 锁定 HWND）；滚轮事件通过 `PostMessageW(hwnd, WM_VSCROLL/WM_MOUSEWHEEL)` 发给该 HWND 而非系统级 SendInput，避免焦点漂移导致滚错窗口
  - **焦点稳定性**：长截图期间用户不应切窗口（切了会破坏采集目标）；自动滚动用 PostMessage 给锁定 HWND 可不抢前台焦点，比 SendInput 稳定
- 兜底：轮询采集带像素 diff（哈希变化 → 已滚）

*拼接算法*：
- 取上一帧底部 N 行（如 20 行）作模板，在新帧顶部区域垂直滑动匹配（SAD 绝对差之和）
- 找到最小 SAD 位置 = 重叠量，裁掉重叠部分后拼接
- 横向模式同理，只是方向改为水平
- 退化：纯色/重复纹理匹配失败 → 降级"直接拼接无去重"（可能错位但不中断）

*长图编辑（架构已核实，需新增入口）*：
- 合成长图：`scrollFrames` 垂直拼接成一张大 ImageData（宽=W，高=总高）
- **不能直接调 `enterAnnotationMode(rect)`**——它内部用 `rect.x/y` 去 main canvas `getImageData`（index.js:250）抓像素，而长图的 cropData 是自己合成的、不对应屏幕任何位置，传 rect 会抓错
- **需新增入口** `enterAnnotationWithCropData(cropData, pw, ph)`：跳过从屏幕抓 cropData 的步骤，直接用传入的合成 ImageData 调 `annot.reset(pw, ph, cropData)` + 设置标注 canvas 尺寸 + 显示标注层。这是 `enterAnnotationMode` 的一个变体（抽取共享的"进入标注"后半段）
- 标注引擎对尺寸无硬上限，理论可吃长图；**超长图（5000px+）canvas + getImageData 性能需实测**

*实时预览*：
- 采集带右侧 fixed 定位缩略图 canvas（宽 ~120px CSS），高度按比例
- 每拼一帧追加渲染到底部

*输出*：
- 复用 `compositeSelection` 思路：编辑后的长图（或未编辑的合成图）→ PNG → `screenshotCopy`/`screenshotSave`/`screenshotPin`

**风险**：0.15 最不确定的一块。① 拼接算法对纯色/重复纹理可能失败（降级直接拼接）② 自动滚动 SendInput 兼容性（部分窗口驱动失败）③ 滚动检测跨窗口类型行为不一 ④ 超长图标注性能。实施时若可靠性不达标，可降级为"实验功能"或推迟。

**独立性**：可与前端标注并行，不依赖 0.15.0-0.15.6 的标注框架（但入口按钮挂在工具栏，需 0.15.0 的 toolbar 结构；编辑回环依赖标注引擎本身）。

### 4.9 0.15.8 选区体验增强（智能窗口吸附 + 像素放大镜取色）

**目标**：截图选区阶段两个体验增强（§2.14 + §2.15）。

**实现方案（可分派）—— 前端为主，窗口吸附需补少量 Rust**：

**A. 智能窗口吸附（§2.14）**：
- Rust：新建 `src/infra/platform/window/list.rs`（或扩展 `windows.rs`），`enumerate_pickable_windows(ignore: &[isize]) -> Vec<WindowRect>`：
  - `EnumWindows` 遍历顶层窗口
  - 每窗口：`IsWindowVisible` + `DwmGetWindowAttribute(DWMWA_CLOAK)` 过滤 cloaked + 过滤 `WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE` + 类名黑名单（CEF-OSC-WIDGET/Progman）
  - 取边界：`DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`（优先，去阴影边距），fallback `GetWindowRect`
  - `ignore` 排除 overlay 自身 + 主窗 HWND
- Tauri command：`screenshot_window_list()` in `src/app/commands/search/media.rs`，overlay 挂载时调一次（`spawn_blocking` 避免 5-15ms 枚举阻塞首帧），返回物理像素矩形列表
- 前端（新 `ss-hover.js` 或扩展 ss-interaction.js）：mousemove handler（index.js:400）未拖动时 `windows.find(w => pointInRect(...))` hit-test，命中画**虚线框**（不动亮度）；mousedown 无拖动则吸附为选区
- 自排除：overlay + 主窗 HWND 传入 ignore

**B. 像素放大镜取色（§2.15）**：
- 前端：新增 `#pixel-magnifier` DOM（chord-screenshot.html），CSS 复用 stroke-cursor 的 `position:fixed; pointer-events:none`
- 放大镜渲染：mousemove 存坐标 → rAF 回调里 `ss.ctx.getImageData(pxX, pxY, 9, 16)` → 填充 9×16 网格 div（或小 canvas）+ 中心格高亮 + 坐标/色值行
- 色值格式：默认 HEX，Shift 切 RGB/HSL；C 复制（keydown 加分支，index.js:524，复用 guard 模式）
- 性能：建议 main ctx 加 `{ willReadFrequently: true }`（ss-state.js:75）
- **选区信息增强**（顺手）：`#size-hint` 格式从 `123 × 456` 改 `(x, y) 123 × 456 px`（ss-draw.js:50-54 + ss-interaction.js:109-113 两处）

**依赖**：无（选区阶段独立于标注）。可与标注子版本并行。

**难度**：窗口吸附 ⭐⭐（中，Rust EnumWindows + DWM 边界）；像素放大镜 ⭐（低，复用 stroke-cursor 模式）。

## 七、实现参考（分派给子 agent 的关键设计）

### 7.1 TOOL_CAPS 工具能力表设计

消除当前 brush-family 列表重复 5 次的问题。建议放 `ss-state.js` 导出：

```js
// 每个工具的能力描述，所有 switch/if 改读此表
export const TOOL_CAPS = {
  select:    { points: null,    widthCat: null,    widthMul: 0, hasCursor: false, minDrag: 0, supportMode: false },
  rect:      { points: 'box',   widthCat: 'stroke',widthMul: 1, hasCursor: false, minDrag: 3, supportMode: false },
  ellipse:   { points: 'box',   widthCat: 'stroke',widthMul: 1, hasCursor: false, minDrag: 3, supportMode: false },
  arrow:     { points: 'box',   widthCat: 'stroke',widthMul: 1, hasCursor: false, minDrag: 3, supportMode: false },
  pencil:    { points: 'stream',widthCat: 'stroke',widthMul: 1, hasCursor: true,  minDrag: 0, supportMode: false },
  'highlight-multiply':    { points:'stream', widthCat:'brush', widthMul:1, hasCursor:true, minDrag:0, supportMode:true },
  'highlight-translucent': { points:'stream', widthCat:'brush', widthMul:1, hasCursor:true, minDrag:0, supportMode:true },
  mosaic:    { points: 'stream',widthCat: 'brush', widthMul:1, hasCursor: true,  minDrag: 0, supportMode: true },
  pixelate:  { points: 'box',   widthCat: 'effect',widthMul:1, hasCursor: false, minDrag: 3, supportMode: true },
  blur:      { points: 'box',   widthCat: 'effect',widthMul:1, hasCursor: false, minDrag: 3, supportMode: true },  // 新增
  eraser:    { points: 'stream',widthCat: 'brush', widthMul:1, hasCursor: true,  minDrag: 0, supportMode: true },
  text:      { points: 'box',   widthCat: 'text',  widthMul:0, hasCursor: false, minDrag: 0, supportMode: false },
  number:    { points: 'box',   widthCat: 'text',  widthMul:0, hasCursor: false, minDrag: 0, supportMode: false },  // 新增数字标号
  spotlight: { points: 'box',   widthCat: null,    widthMul:0, hasCursor: false, minDrag: 3, supportMode: false }, // 新增
  magnifier: { points: 'box',   widthCat: null,    widthMul:0, hasCursor: false, minDrag: 3, supportMode: false }, // 新增
};
```

- `points`: `'box'`（start+end 两点）/`'stream'`（完整点序列）/`null`（非绘制工具）
- `widthCat`: 决定读 config 哪一层（stroke/brush/text/effect/null）
- `widthMul`: 旧的魔法乘数（高亮×4 等迁入 config 层后此字段可废弃，过渡期保留）
- `supportMode`: 是否支持框选/画笔模式切换

**高亮 UI 合并说明**：表里 highlight-multiply / highlight-translucent 是两个 command type（渲染层需要区分），但 **UI 层合并为一个"高亮"工具 + 下拉切变体**（§2.17）。selectTool('highlight-multiply') 和 selectTool('highlight-translucent') 是同一个 UI 按钮的两种状态，下拉开切换实际写入的 type。

**UI 分组 vs widthCat 是两个独立维度**：UI"画笔组"（§2.1）是按工具使用场景聚合（画笔/箭头/高亮放一起），widthCat 是按粗细语义分类。画笔组里 pencil/arrow 用 stroke（细而精确），高亮用 brush（粗而面积大）——这是合理的，组内工具各自走自己的 widthCat，二级菜单按 widthCat 显示对应粗细控件。命名"画笔组"是 UI 习惯叫法，不强制等于 brushSize。

### 7.4 模式切换的命令分派

`endDraw`（annotation-engine.js:173-212）构建 command 时：

```js
const caps = TOOL_CAPS[currentTool];
const useStream = caps.supportMode
  ? (toolMode[currentTool] === 'brush')  // 支持模式的工具按当前模式
  : (caps.points === 'stream');          // 不支持模式的按固定 points 类型
const cmdPoints = useStream ? points : [{x:drawStartX,y:drawStartY}, lastPoint];
const cmd = {
  type: currentTool,
  points: cmdPoints,
  color: currentColor,
  width: getWidthForTool(currentTool),
  fill: currentFill,
  mode: caps.supportMode ? toolMode[currentTool] : undefined,  // 关键：写入 command
};
```

`executeCommand` 按 `cmd.mode` 分派 box/brush 渲染路径。
