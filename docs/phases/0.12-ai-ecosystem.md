# Blink 0.12 — AI 能力架构搭建

> **目标**：从主窗口单轮 AI 补全，演进到独立对话窗口、多轮 Agent、工具循环与持久化对话。
>
> **产品边界**：Blink 不做 AI 运行时。本地推理由外部 ollama / lmstudio 提供，Blink 只负责 Provider 对接、Agent 编排和能力调用。
>
> **当前状态（2026-07-26）**：✅ **0.12.0-0.12.7 全部完成**。测试基线 **875 passed**。
>
> **范围**：0.12 打通对话主链路 + 体验打磨 + 分组管理。MCP 双向 / Skill / 记忆 FTS5 召回 / CLI 化后续在 0.13 落地；当时预留的 RAG / 记忆向量召回现已撤销版本规划，归入 roadmap 远期观察。

## 二、0.12.0 基础设施

### 2.1 DB 四层拆分

`DbPools { config, history, ai, cache }`，四库独立连接池和写锁，互不阻塞。

| 数据库 | 表 | 语义 |
|---|---|---|
| `blink_config.db` | `config` | 用户配置 KV |
| `blink_history.db` | `history` / `clipboard_history` | 用户行为历史 |
| `blink_ai.db` | `ai_tool_audit` / `conversations` / `messages` / `conversation_groups` | AI 对话、审计与分组 |
| `blink_cache.db` | `performance_metrics` / `icon_cache` | 可删除缓存 |

旧 `blink.db` → 四库迁移（SQL `ATTACH` + `INSERT INTO ... SELECT`），完成后删除旧库。

### 2.2 Tool 适配层

`CapabilityTool` / `ActionTool` 实现 `rig::tool::ToolDyn`，把现有 Capability/Action 接入 rig Agent tool loop。

- `ai_eligible() == false` 的 Action 不进 Agent tool 池。
- Dangerous tool 在 `ToolDyn::call` 内 emit 确认事件后**挂起 await 用户确认**（`PendingConfirms` + oneshot + 60s 超时）。
- 错误经 `capability_error_to_string` / `exec_error_to_string` 中文化后返回 `ToolError::ToolCallError`。

### 2.3 Provider 模型统一

`ModelEntry.capabilities` 支持 Chat / Embedding / STT。`AIProviderRegistry` 热更新（`reload` 增量重建 provider 池，密钥版本号 `secret_epoch` 强制重建）。

## 三、对话窗口与机制（0.12.1-0.12.3）

### 3.1 AgentProvider

`ChatAgent` 枚举承载 4 种 `ProviderKind` 的具体 `Agent<M>`（rig `CompletionModel` 非 object-safe，用枚举替代 `dyn`）。

`stream_prompt` → 泛型 `run_stream<M>` 消费 `MultiTurnStreamItem` 转为 `ChatStreamChunk` emit 前端：`Text / Thinking / ToolCall / ToolResult / Done / MaxTurnsReached / Error`。

**空响应检测**（0.12.6 修复）：rig 在 SSE 解析失败时 yield 空 `FinalResponse`，转为 `Error` chunk 而非 `Done`，避免前端卡死。

### 3.2 ChatService

- 单 active request（`RequestTracker`：`install` / `abort` / `clear_if` compare-and-clear）。
- `start_gate` 串行化启动，防止并发 IPC 绕过 active 检查。
- `ensure_provider(preamble)` 懒构造 AgentProvider，cache key = `(provider_id, model_id, fingerprint, preamble_hash)`。

### 3.3 SQLite ConversationMemory

`SqliteConversationMemory` impl rig `ConversationMemory` trait。`messages.content` 存序列化 rig `Message` JSON。滑动窗口 20 条，持久化层保留完整历史。重启恢复对话列表和消息。

### 3.4 数据表

```sql
CREATE TABLE conversations (
  id TEXT PRIMARY KEY, title TEXT,
  created_at INTEGER NOT NULL, last_active_at INTEGER NOT NULL,
  group_id TEXT  -- 0.12.6 新增
);
CREATE TABLE messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  conversation_id TEXT NOT NULL, role TEXT NOT NULL,
  content TEXT NOT NULL,  -- 序列化的 rig Message
  created_at INTEGER NOT NULL
);
CREATE TABLE conversation_groups (  -- 0.12.6
  id TEXT PRIMARY KEY, name TEXT NOT NULL,
  system_prompt TEXT, parent_id TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  expanded INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL
);
```

## 五、对话分组（0.12.6）

参考元宝网页端——侧边栏多层分组层级，每分组可配独立系统提示词。

- **多层嵌套**：`parent_id` 支持任意深度，递归渲染 + 缩进。
- **分组操作**：新建 / 重命名 / 删除（组内对话移至默认，子分组 re-parent）/ 系统提示词编辑。
- **折叠状态**：DB 持久化（`expanded` 列），默认组用本地状态。
- **拖拽排序**：HTML5 Drag & Drop（对话跨分组移动 + 分组 sort_order 交换）。
- **分组系统提示词**：`chat_prompt` 时查询分组 `system_prompt`，追加到基础 `chat_system_prompt()` 之后。preamble hash 变化触发 Agent 重建。

**后端**：`conversation_groups` 表 + `conversations.group_id` 列迁移；分组 CRUD 8 个函数；`get_effective_system_prompt` LEFT JOIN 查询。

**前端**：`sidebar.js` `buildTree` 递归构建 → `renderGroupNode` / `renderConversationItem`；`ipc.js` 新增 8 个分组 IPC；`main.js` `handleSend` 传 `currentGroupId`。

## 六、对话窗口布局体系化（0.12.7）

从逐版本叠加的视觉元素演进为 IM 级布局体系，参考现代 IM 应用但适配 AI 对话场景（工具调用、思考过程、Token 用量）。

| 项目 | 说明 |
|---|---|
| **面包屑标题** | header 标题区改为 `文件夹A / 子文件夹 / 对话标题`。仅对话标题可编辑（点击→内联输入）。直属分组有系统提示词时显示 accent 圆点指示器。 |
| **悬浮操作行 z-index** | `.chat-msg-actions` 加 `z-index: 10`，修复被下方消息气泡盖住的问题 |
| **Signal 信号消息** | IM 式居中系统通知（`renderSignal(text, type)`），替代 error 消息。类型：info / warning / error / success。场景：停止生成、已达工具上限、LLM 报错、危险操作已执行等。 |
| **时间分隔符** | 相邻消息 `created_at` 间隔 >5min 时自动插入居中时间标签（`renderTimeSeparator`）。后端 `ChatMessageSnapshot` 增加 `created_at` 字段。 |
| **系统提示词横幅** | 当前对话直属分组有 `system_prompt` 时显示，可折叠/关闭，不随消息滚动。 |
| **工具卡片增强** | 头部行（工具图标 + 名称 + 状态 + 耗时）+ 参数预览 + JSON 格式化结果区。`ChatStreamChunk::ToolCall` 增加 `arguments` 字段。 |
| **消息间距优化** | 轮次间距分级：用户消息大间距（新轮次）/ 助手+工具小间距（同轮）/ Signal+时间分隔符中间距。用 `margin-top` 按元素类型分级，取消统一 `gap`。 |
