## 一、进入 Phase 的条件

候选方向依次判断：

1. 是否有真实场景和可验证收益；
2. 是否让现有能力形成闭环、减少搬运和心智切换；
3. 是否复用统一能力底座，而非新增平行系统；
4. 是否默认本地、按需启用，并符合既有产品性能与资源约束。

只有用户价值、最小操作路径、技术边界和验收范围均明确后，候选才迁入 `phases/{version}-*.md`。下列分类表示方向归属，不代表类内实施顺序。

## 四、其他候选（按类型）

### 4.1 优化项

#### 长截图困难页面与自动滚动增强（低优先级）

按用户实测与优先级调整，从 [0.26.22 R3](phases/0.26-plugin-system-upgrade.md) 移出的增强方向：复杂固定导航/悬浮层与持续动画的进一步适配、低细节/重复内容及快速滚动后的恢复增强、自动滚动更细致的速度控制。当前已有的固定层处理、歧义拒绝、历史像素复核、丢失恢复和低置信降速/暂停继续保留；漏尾、错拼、取消/焦点回退仍按可靠性问题及时修复。

有可复现的失败回放或高频体验问题后再立项；先明确目标页面、成功/拒绝边界与性能成本，再决定是否扩展算法或平台适配。普通页面实测暂未发现问题，不为这些增强扩大本轮改动范围。

2026-10-22 用户确认采集已流畅并结束本轮优化。末段采集并行、Pin 按片段交接/可见区域加载及整图编码链路改造暂不实施；只有钉图等待再次成为高频问题，并经原型证明整体收益、像素正确性与资源成本后再重评，不预占版本号。

#### Windows 多窗口 IME：上游修复跟踪与隔离回退

**隔离起因（2026-10-24）**：同一 Blink 进程内切换原生窗口，后聚焦窗口的中文组词/候选框可能漂到屏幕左上角，或无法唤起；英文输入正常，微软拼音和微信拼音均可触发，已测的外部应用返回对照通常正常。直接 Tao/Wry 双窗口 textarea 也曾复现，但故障最终属于哪一层尚未确定。升级至 Tauri 2.12.5 / Wry 0.57.1 / Tao 0.37.2，以及单独使用 WebView2 156 均未解决。

**当前规避**：见 [0.27 §五的 0.27.11 实现要点](phases/0.27-ai-interaction-enhancement.md#五子版本实现要点)。编辑器使用独立 WebView2 数据目录后，系统运行时 142.0.3595.69 下“主窗口/AI 对话/便签 ↔ 编辑器”三组经用户实测正常；“主窗口 ↔ AI 对话”“主窗口 ↔ 便签”仍异常，所以追加主窗口独立目录。最终主窗口、编辑器、其余窗口形成三组浏览器环境，已核验实际进程与目录；用户随后确认“主窗口跟其他已经没问题了”。完整验收边界以 phase 为准，未承诺其余共享窗口任意组合均已修复。

**优化动机**：不同数据目录引入独立浏览器/GPU/辅助进程、缓存及预热成本。整组内存不等于净增量，需同机同场景 A/B 测启动、常驻内存和交互负载；避免把隔离扩展成每个窗口各一组。业务数据库与会话不随浏览器缓存目录迁移。

**上游跟踪入口**：[Wry #1908](https://github.com/tauri-apps/wry/issues/1908)、[Tauri #16391](https://github.com/tauri-apps/tauri/issues/16391)。这两个报告是重新评估的入口；issue 关闭或版本号更新本身不等于本场景已修复。

**调整回共享环境的条件**：相关修复实际进入 Blink 所用依赖或 WebView2 运行时后，建立隔离/共享两版对照；微软拼音与微信拼音都验证主窗口 ↔ AI 对话/便签/编辑器、AI 对话/便签 ↔ 编辑器，并补测其他相关共享窗口组合和外部应用返回。覆盖反复往返、冷启动/预热/复用、Alt+Space 首次输入、隐藏再唤起和已有持久状态；记录资源收益与失败样本。全部通过再撤回独立数据目录和仅为此引入的主窗显式创建；后台 Alt 松开不抢焦点的独立保护保留。旧缓存目录的清理另行确认，不能连带删除用户业务数据。

### 4.2 功能增强

#### 剪贴板历史音频类型

剪贴板监听当前只采集文本/图片/HDROP 首文件名三种格式，音频（CF_WAVE/CF_RIFF）完全无处理。补齐需评估：格式枚举与转码（WAV/MP3）、blob 存储体积（对照 clipboard_images 200 条上限策略）、预览与播放 UI、以及"发送到聊天窗口"作为音频附件的联动。

#### 简易录音机与可选 STT 转录

2026-10-22 用户提出的功能候选：提供简易麦克风录音机，支持开始、暂停/继续、停止、回放与保存，方便留下语音备忘或短音频。未配置 STT 时，录音功能仍可独立使用；配置了可用 STT 时，可对录音发起转录，并复制、保存或送入现有编辑器处理转录文本。

立项前评估现有音频采集与 STT 能力的复用范围，明确长于语音输入场景的时长/体积预算、临时素材与成品归属、取消清理及转录进度/失败重试。原始录音与转录结果分离保存，转录失败不能丢失录音；与剪贴板音频历史的流转可在素材契约明确后联动。

#### 极轻量文件快速预览

不做完整 QuickLook（解码器、体积和维护成本偏离核心定位）。收敛方向：仅文本与图片两类的极轻量预览——图片复用 pin 窗口体系（blink-pin:// 自定义协议 + spare 预热），文本参考 sticky/voice-overlay 的轻量无框窗形态。前置：文件选中感知（0.27.3）落地后验证真实预览诉求。

#### 主动建议深化

弱意图信号只产 Ghost/Suggestion，由用户采纳；不抢首屏、不直接执行副作用、可一键关闭。只有建议能稳定减少至少一步操作且误报足够低时才立项。

#### 词汇学习：记忆曲线与四六级等词包（仅记录）

2026-10-25 用户明确：背单词作为后期功能，初步方向为依据记忆曲线安排复习，以及四级、六级等可选背词包。当前只记录方向，不选定复习算法、不建设词包课程/学习计划/复习 UI，也不将学习数据纳入首版 WebDAV 配置同步。

前置为 [0.28](phases/0.28-plugin-platform-and-tools.md) 的词典查询与插件数据包/独立存储契约稳定。后续立项时分别明确词包成员与词典释义来源、许可和版本，学习进度与可替换词库的身份关系，以及记录备份、恢复、删除和跨设备同步；不因现在有插件持久化能力就提前创建完整学习系统。

### 4.3 AI 相关

#### Agent 能力增强

路径级授权、`write_text_file`、受控 `read_url` 与长任务能力应集中设计，不能零散扩大权限。

- 文件能力需定义规范化路径、symlink/reparse point、目录递归、授权失效和“用户指定/模型发现”边界；
- 写文件需明确原子写入、默认不覆盖、覆盖确认、编码、大小限制和失败恢复；
- URL 读取需明确响应上限、超时、重定向、正文抽取、内容类型及 SSRF 边界；
- Capability 保留 canonical data，AI 出口自行适配上下文，不在通用结果层做隐式全局截断。

#### per-conversation MCP 工具限定

`/mcp` 查看已由 0.27.7 实现；"限定当前对话只用某个 MCP 来源"是另一件事：工具池现为全局 disabled_tools 过滤 + epoch 触发 Agent 重建（chat_service 组装时 collect_tools 无 conversation 维度参数）。对话级白名单需要 InvokeContext/agent 组装链路带 conversation 级 tool 过滤并重新定义缓存键语义，单独设计后再立项。

#### 外部 agent 作为 subagent

只将外部 agent 包装成受控粗粒度 tool，不把其作为 Blink 执行后端。立项前需明确工作目录和可写范围、失败降级、分钟级任务的进度/中止、授权粒度及非编码高频场景。

#### AI 生成 Skill

只有真实工具证明纯文本解析准确率不足时，才评估让 LLM 补全语义；生成物必须可预览、编辑和确认，不能静默成为执行指导。

#### 多类型 API 扩展（生图/TTS 等）

生图与 TTS 不随语言大模型 provider 混做：rig image_generation 仅覆盖 OpenAI 系/Gemini/Venice（硅基流动需 additional_params 方言），DeepSeek/Anthropic 无生图端点，收益配不上集成面（0.27 规划时移出）。立项条件是先支持"按类型独立配置 API 端点"（生图/STT/TTS 各自的 provider/base_url/key 配置面），再评估接入；届时生成结果走 ResourceStore image_ref → pin_image/写剪贴板消费链路。

#### 结构化输出抽取（rig extractor / prompt_typed）

rig-agent ExtractorBuilder 提供 schema 约束输出 + 可配置重试（含"模型拒调 submit 工具时宽容解析最终文本"的 native 模式 prompt_typed）。受 rig 隔离墙约束只能落在 domain::ai 新模块（泛型方法不能进 object-safe 的 AIProvider trait），依赖 `rig_core::schemars` re-export 零新增。当前无必需场景（标题生成现状鲁棒、编辑器整理是自由文本）；首个真结构化输出需求（意图兜底、批量操作确认）出现时立项。

## 五、远期观察：向量、RAG 与长期记忆

现有 token-aware 窗口 + FTS5 记忆召回是正式方案。当前没有数据证明语义召回是主要瓶颈；向量化会引入模型、索引、重建、后台任务、失败恢复、隐私告知和设置 UI，不作为局部增强提前建设。

未来重评必须同时满足：

1. 真实高频用例证明 FTS5 或普通文件搜索明显不足；
2. 有可量化的离线评测集与收益门槛；
3. 实现满足 Rust、Windows、安装体积和常驻内存约束；
4. 来源、更新、删除、引用和隐私告知生命周期完整；
5. 后台索引不影响主链路，关闭后可彻底删除数据。

若未来实现，必须保持无 embedding 时完整可用、后台旁路化、模型身份锁定、本地优先、可降级/可删除，并通过 Capability 进入既有 tool loop。

事实记忆应先验证显式写入、读取、纠正和删除的产品模型，不因“想做记忆”顺带引入向量基础设施。
