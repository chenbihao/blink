# Blink 0.20 — AI 调用能力扩展（向量版：zvec / 记忆向量召回 / RAG）

> **范围**：① 向量基础设施（zvec + embedding 模型管理）+ ② 记忆向量召回（对话历史语义检索，混合 BM25 + cosine）+ ③ RAG 知识库（文档检索）。
>
> **主题**：0.13 让 AI 能调外部世界（MCP client）、能暴露能力给生态（MCP server + CLI 化）、能被 Skill 流程指导、能记住更远的对话（FTS5 召回），且**零嵌入模型依赖**。0.20 在此基础上**升级到向量语义**——引入 zvec 向量库 + embedding 模型管理，从 FTS5 关键词召回升级为混合检索（BM25 + cosine）；落地 RAG 知识库。
>
> **产品边界决策**：**Blink 不做 AI 运行时**。本地嵌入靠外部（ollama `nomic-embed-text` / lmstudio），Blink 只作 Provider 对接 + 能力编排。
>
> **前置**：0.13 完成（MCP client + MCP server + CLI 化 + Skill + 记忆 FTS5 召回 + token-aware 窗口）+ 0.14 完成（能力协议重构——Capability 协议统一、Action/Capability 边界钉死、投影引擎收敛）。0.20 的 RAG `search_knowledge_base` Capability 直接走 0.14 重构后的干净协议。
>
> **原则**：zvec 作为统一向量库（BM25 + 向量，一个库两种检索）；嵌入模型走 0.12 Provider 统一管理；0.13 的 FTS5 召回保留作为降级方案（嵌入模型不可用时自动降级）。

## 二、0.20.0 向量基础设施（zvec + embedding 模型管理）

### 2.1 定位

为记忆向量召回（0.20.1）和 RAG 知识库（0.20.2）提供统一的向量存储与检索基座。引入 zvec（阿里轻量进程内向量数据库）作为统一向量库，一个库支持 BM25 全文检索 + 向量语义检索。

### 2.2 前置依赖（0.12 / 0.13 已铺好）

| 产出 | 0.20.0 复用方式 |
|---|---|
| **Provider 模型统一管理**（0.12 §2.7） | embedding 模型从 `ModelEntry.capabilities` 含 `Embedding` 的模型中选 |
| **ollama 接入**（0.12 §2.3） | 本地 embedding 走 ollama `nomic-embed-text`（rig 现成） |
| **DB 四层拆分**（0.12 §2.2） | 向量数据存 AI 库 `blink_ai.db` |
| **0.13.2 FTS5 召回** | FTS5 表保留作为关键词检索后端 + 降级方案 |

### 2.3 zvec 接入

**zvec** 是阿里的进程内向量数据库，crates.io 上有 Rust 绑定：

```
zvec = "0.1.0"             # Rust bindings to zvec, an in-process vector database by Alibaba
zvec-core = "0.1.0"        # Rust-native vector database engine
zvec-rust = "0.6.0"        # Safe Rust bindings for the zvec vector database
```

**能力**：HNSW + IVF + DiskANN/Vamana + **BM25 FTS** + scalar filtering + FP16/INT8 量化

**亮点**：zvec 内置 BM25 全文检索——一个库同时做向量语义检索和关键词全文检索。0.20.1 记忆召回和 0.20.2 RAG 可以用混合检索（BM25 + cosine），不需要 FTS5 和向量库两套系统。

**技术选择**：

| 层 | 技术选择 | 理由 |
|---|---|---|
| **embedding 生产** | 走 rig `EmbeddingsModel`（ollama `nomic-embed-text` / 云端 API） | 复用 0.12 Provider 抽象 + ollama 接入，零摩擦 |
| **向量存储 / 检索** | zvec（HNSW 索引 + BM25 FTS + scalar filtering） | 进程内，轻量；一个库两种检索；中文友好 |

### 2.4 embedding 模型管理

**embedding Provider 复用 0.12 的统一配置**：用户在 AI 供应商页标记 `nomic-embed-text` 为 Embedding 能力后，向量基础设施直接从此配置取 provider + model。本地 ollama 零成本产 embedding；云端按 token 计费时用户可切云端 embedding Provider。

**嵌入模型可用性检测**：
- 启动时检测是否有 `ModelEntry.capabilities` 含 `Embedding` 的模型
- 有 → 向量召回可用（0.20.1 记忆向量召回 + 0.20.2 RAG）
- 无 → 自动降级到 0.13.2 FTS5 召回（记忆）/ RAG 不可用（RAG 强依赖 embedding）

### 2.5 embedding 一致性约束（切模型必重建）

**向量库必须锁 embedding model_id**：向量存 `(model_id, vector)`，切 embedding Provider（维度不同 / 语义空间不同）触发**重建索引 UI 提示**，不隐式失效数据。

### 2.6 向量存储 schema（AI 库）

```sql
-- zvec 管理向量索引，SQLite 表存储元数据
-- zvec 的向量数据文件存 %APPDATA%\blink\vector\

-- 向量元数据表（与 0.13.2 memory_fts 通过 content_hash 关联）
CREATE TABLE vector_index (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source_type TEXT NOT NULL,         -- 'memory' / 'knowledge_base'
  source_id TEXT NOT NULL,           -- memory_fts rowid / embeddings source_path
  content_hash TEXT NOT NULL,        -- 与 FTS5 表关联的 content hash
  embedding_model_id TEXT NOT NULL,  -- 锁 embedding 模型
  zvec_doc_id TEXT NOT NULL,         -- zvec 文档 ID
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_vector_source ON vector_index(source_type, source_id);
CREATE INDEX idx_vector_model ON vector_index(embedding_model_id);
```

### 2.7 设置页

设置页「AI」tab 新增向量配置区：
- 当前 embedding 模型显示（从 Provider 统一配置取）
- 嵌入模型可用性状态（✅ 有可用模型 / ❌ 无可用模型，记忆降级到 FTS5）
- 切换 embedding Provider 提示重建索引
- 向量库状态（文档数 / 向量数 / 索引大小）

### 2.8 0.20.0 验收

```
 zvec 依赖引入（Cargo.toml）+ 基础接入（创建 collection / 插入文档 / 检索）
 embedding 模型从 Provider 统一配置取（capabilities[Embedding]）
 启动时检测嵌入模型可用性，无则记忆降级到 FTS5、RAG 不可用
 向量元数据表 vector_index 建表 + migration
 切 embedding Provider 提示重建索引，不隐式失效
 向量库状态在设置页可见（文档数 / 向量数 / 索引大小）
 单测：zvec 插入 + 检索 round-trip + BM25 检索
```

## 三、0.20.1 记忆向量召回（对话历史语义检索）

### 3.1 定位

0.13.2 的 FTS5 召回已覆盖"关键词相关时召回旧消息"。0.20.1 升级为**混合检索**——BM25 关键词 + cosine 语义，取并集排序。当用户问"上次那个性能问题的解决方案"时，即使旧消息里没出现"性能"关键词，语义相近的消息也能被召回。

### 3.2 前置依赖

| 产出 | 0.20.1 复用方式 |
|---|---|
| **0.13.2 FTS5 召回** | FtsDemotionHook + memory_fts 表 + load() 改造保留 |
| **0.20.0 向量基础设施** | zvec 向量存储/检索 + embedding 模型管理 |

### 3.3 混合检索（BM25 + cosine）

```
新消息进来 → 滑动窗口截断 → FtsDemotionHook 归档到 memory_fts（0.13.2 不变）
                                              ↓
                                    同时 embedding → zvec 向量库（0.20.1 新增）

load() 时：
  1. 加载窗口内 20 条消息
  2. 从最后一条 User 消息提取 query
  3. FTS5 BM25 检索 memory_fts → Top-K1（关键词召回）
  4. query embedding → zvec cosine 检索 → Top-K2（语义召回）
  5. 合并去重（content_hash）→ 加权排序 → 最终 Top-K（默认 3）
  6. 召回的旧消息以 <memory> 标签注入消息列表头部
```

**混合排序权重**（可配置）：
- BM25 分数归一化 → weight_b25（默认 0.4）
- cosine 相似度 → weight_cosine（默认 0.6）
- 最终分数 = `weight_bm25 * bm25_score + weight_cosine * cosine_score`

### 3.4 与 FTS5 的关系（升级路径）

| 场景 | 检索方式 | 来源 |
|---|---|---|
| 有 embedding 模型 | 混合检索（BM25 + cosine） | FTS5 + zvec |
| 无 embedding 模型（降级） | 仅 BM25 检索 | FTS5（0.13.2 不变） |
| embedding 模型不可用（临时） | 自动降级到仅 BM25 | FTS5（0.13.2 不变） |

**0.13.2 → 0.20.1 升级不破坏**：FTS5 表和数据完全保留，只是 `load()` 的检索逻辑从"仅 FTS5"升级为"FTS5 + zvec 混合"。`FtsDemotionHook` 的 `on_demote` 同时写 FTS5 和 zvec（dual-write）。

### 3.5 向量存储 schema（AI 库）

```sql
-- 记忆向量表（与 memory_fts 通过 content_hash 关联）
CREATE TABLE memories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  conversation_id TEXT NOT NULL,         -- 来源对话
  message_content TEXT NOT NULL,        -- 原始消息内容
  content_hash TEXT NOT NULL,           -- 与 memory_fts 关联
  embedding BLOB,                        -- 向量（zvec 管理索引，此 BLOB 为备份）
  embedding_model_id TEXT,               -- 锁 embedding 模型（null = 未 embedding）
  zvec_doc_id TEXT,                      -- zvec 文档 ID（null = 未入向量库）
  created_at INTEGER NOT NULL,
  FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE
);
CREATE INDEX idx_memories_conv ON memories(conversation_id);
CREATE INDEX idx_memories_hash ON memories(content_hash);
```

### 3.6 设置页

「AI」tab 记忆策略配置升级：
- 记忆模式：滑动窗口 / 滑动窗口 + FTS5 召回 / 滑动窗口 + 混合召回（BM25 + 向量）
- 召回数量 K（默认 3）
- BM25 权重（默认 0.4）/ cosine 权重（默认 0.6）
- cosine 相似度阈值（默认 0.7）
- 无 embedding 模型时自动降级到 FTS5（标注降级状态）

### 3.7 0.20.1 验收

```
 滑动窗口截断的旧消息同时归档到 FTS5 + zvec 向量库（dual-write）
 load() 升级为混合检索：FTS5 BM25 + zvec cosine → 合并去重 → Top-K 召回
 混合排序权重可配置（BM25 0.4 / cosine 0.6）
 无 embedding 模型时自动降级到仅 FTS5（0.13.2 行为不变）
 召回的消息标注「来自历史对话（X 天前）」
 删除对话时级联清理 memories 表 + memory_fts 对应行
 设置页可配置记忆模式 + 混合检索参数
 主窗口不受影响（无 memory）
```

## 四、0.20.2 RAG 知识库（文档检索作为内部 tool）

### 4.1 定位

VectorRouter 在 0.9 移出后在这里找到归宿——对本地文档库 / 笔记做语义检索，作为 AI 回答的上下文。用户加文档 → 后台异步 embedding → 写入 zvec 向量库 → AI 调 `search_knowledge_base` 检索。

### 4.2 前置依赖

| 产出 | 0.20.2 复用方式 |
|---|---|
| **0.20.0 向量基础设施** | zvec 向量存储/检索 + embedding 模型管理 |
| **ollama 接入**（0.12 §2.3） | 本地 embedding 走 ollama `nomic-embed-text` |
| **Tool 适配层**（0.12 §2.4） | RAG 作为 `search_knowledge_base` Capability，经 Tool 适配层包装进 tool 池 |
| **对话窗口 tool loop**（0.12.2） | AI 自主调 RAG tool，结果走 tool loop 回流 |

### 4.3 文档处理流水线

- **支持的格式**：`.txt` / `.md` / `.pdf`（文本提取） / `.docx`（文本提取）
- **分块策略**：按段落分块，每块 ~500 token，相邻块重叠 50 token
- **异步处理**：用户加文档后后台异步 embedding（走 ollama），进度可见，不阻塞 UI
- **增量更新**：文件修改时间变化时重新 embedding 该文件，删除文件时清理对应向量
- **BM25 + 向量混合**：文档同时写入 zvec 的 BM25 索引和向量索引

### 4.4 混合检索

```
AI 调 search_knowledge_base(query)
  ↓
1. query embedding → zvec cosine 检索 → Top-K2（语义召回）
2. query → zvec BM25 检索 → Top-K1（关键词召回）
3. 合并去重 → 加权排序 → 最终 Top-K（默认 5）
4. 返回 CapabilityResult::Items（title=文件名, subtitle=路径, payload=chunk_text）
```

### 4.5 RAG 作为内部 Capability

**建模决策**：RAG 检索建模为一个 Capability `search_knowledge_base`，进对话窗口 tool 池。AI 判断需要本地知识时自主调用，结果走 tool loop 回流。

这样 RAG **不需要单独的调用路径**，完全复用 0.12 铺好的链路：
- 用户加文档 → 后台异步 embedding（走 ollama）→ 写入 zvec
- AI 调 `search_knowledge_base(query)` → 混合检索 → `CapabilityResult::Items`
- 结果投影走 0.12.0 统一 `to_rig_tool_result()`
- rig Agent 自主消费 RAG 上下文做总结

### 4.6 向量存储 schema（AI 库）

```sql
-- 知识库向量表
CREATE TABLE knowledge_chunks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source_path TEXT NOT NULL,            -- 源文件路径
  chunk_index INTEGER NOT NULL,         -- 分块序号
  chunk_text TEXT NOT NULL,            -- 分块文本
  content_hash TEXT NOT NULL,          -- 内容 hash（增量更新判断）
  embedding BLOB,                       -- 向量（zvec 管理索引，此 BLOB 为备份）
  embedding_model_id TEXT NOT NULL,    -- 锁 embedding 模型
  zvec_doc_id TEXT NOT NULL,           -- zvec 文档 ID
  file_modified_at INTEGER NOT NULL,   -- 源文件修改时间（增量更新判断）
  created_at INTEGER NOT NULL,
  UNIQUE(source_path, chunk_index)
);
CREATE INDEX idx_kb_source ON knowledge_chunks(source_path);
CREATE INDEX idx_kb_model ON knowledge_chunks(embedding_model_id);
```

### 4.7 设置页

设置页新增「知识库」tab：
- 文档/目录列表（路径 / 状态已索引·索引中·失败 / 向量数 / 最后索引时间）
- 添加文件 / 添加目录按钮
- 删除按钮（删文档 + 清理对应向量）
- 当前 embedding 模型显示 + 切换模型提示重建
- 索引进度条（异步 embedding 时）
- 混合检索参数（BM25 权重 / cosine 权重 / 召回数量 K）

### 4.8 0.20.2 验收

```
 设置页「知识库」tab，可添加本地文档（单文件 / 目录）
 后台异步 embedding（走 ollama nomic-embed-text 或云端），进度可见，不阻塞 UI
 文档分块（.txt/.md/.pdf/.docx），增量更新（文件改动重新索引）
 向量存储走 zvec + knowledge_chunks 元数据表，锁 embedding_model_id
 混合检索（BM25 + cosine），Top-K（默认 5）
 search_knowledge_base Capability 进对话窗口 tool 池，经 Tool 适配层包装
 对话窗口问"我笔记里有没有提到 XXX" → AI 自主调 search_knowledge_base
 切 embedding Provider 提示重建索引，不隐式失效
 无 embedding 模型时 RAG 不可用（设置页标注"需要 embedding 模型"）
```
