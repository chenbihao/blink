## 二、已落地的核心设计(0.9.0~0.9.3 精简归档)

### 2.1 统一 Tool 架构

- **一切皆 tool**:builtin(同进程) + 插件(IPC) + MCP/skill(0.11 预留)
- **统一描述层**:向 MCP/OpenAI function calling/rig `ToolDefinition` 对齐,执行路由按 `exec` 字段分流
- **落地**:`ActionSchema` + `to_rig_tool()` 唯一 rig 类型触点

### 2.2 Provider 多档抽象

- **三档配置**:路由模型(快/便宜) → 轻量模型(日常) → 主模型(最强)
- **rig 按模式分层**:主窗口只用 `CompletionModel` + `ToolDefinition`;Agent 窗口(0.10)开放 `AgentBuilder` + memory + tool loop
- **Provider 全 buildin**:LLM 流式转发过 IPC 与「AI 反馈铁则」冲突
- **密钥安全**:Windows Credential Manager + `SecretString` zeroize on drop

### 2.3 主窗口文本闭环

```
用户打字
  ├─ 命中规则? ──→ 确定性快速通道,直接执行(不过 AI)
  └─ 未命中 → 四筛子过滤 → 调路由模型
       ├─ 高置信 + 安全动作 ──→ 直接执行
       ├─ 需多轮 ──→ Ghost "展开对话"(0.10)
       └─ 不确定 ──→ 回退常规搜索
```

**两条路径铁则**:确定性路径(< 1s)不过 AI;AI 永远是回退决策者。

### 2.4 四筛子决策树

| 筛子 | 默认阈值 |
|---|---|
| 最短长度 | ≥ 4 字符(≥ 2 CJK) |
| 含空格 | 必含至少 1 个 |
| 非纯数字/纯符号 | 排除 |
| 非 URL / 文件路径 | Awareness 已判定时不走 AI |

**四铁则**:默认关 / 命中规则不走 AI / 用户可全局关 / 必埋遥测

### 2.5 SLO 分档

- **骨架层**(我们控):硬超时 2500ms / ESC 零延迟取消 / loading 150ms 反闪烁 / Provider 切换零重启
- **观测层**(供应商决定):P50/P95 是用户配的供应商实际表现,设置页调试 tab 展示

### 2.6 插件 Tool-Call(0.9.3)

- manifest 声明 `tools` → 启动时自动注册进 `ActionRegistry`
- `ActionRegistry` 改 `RwLock`,支持动态注册
- Tool 分组聚合:12 内置动作 → 3 个 AI tool,减少 prompt token

### 2.7 类型收窄铁则

主窗口拿到的类型编译期没有 `AgentBuilder` 能力——`AIProvider` trait 只有 `kind / model_id / complete` 三个方法。

## 三、0.9.4 供应商配置 UI 升级（✅ 2026-07-09）

供应商配置从手填升级为「选预设 → 自动发现模型 → 连通测试」一条龙：

- **预设目录** `AI_PRESET_CATALOG`：按 main / cn / gw / local / custom 五类组织，选中自动填充 kind + base_url + display_name。
- **模型自动发现** `fetchAvailableModelsFor`：OpenAI 兼容协议 `GET /v1/models` 拉取；Anthropic / Gemini 官方无 list API，硬编码常用列表兜底；失败回退手动输入。
- **模型表格**：provider 卡片 accordion 展开，列 `[启用] | model id | display_name | 删除`；`ModelEntry.enabled`（serde `default_true`）向后兼容老配置。
- **连通测试** `test_ai_provider` command：用 rig 发最小请求验 Key+URL，前端 ✅/❌ 展示（测试 Key 走内存，不经 Credential Manager）。

边界：不动 `ProviderKind` 枚举 / `AIConfig` 整体结构 / 模型参数 UI（留 0.10 Agent 窗口）。

## 五、0.9.5 前端架构重整 + AI 调用体验优化（✅ 2026-07-11）

> 两 commit 合并：`4919d9e`（前端 token 化 + 原子重构，纯结构）+ `e961770`（AI 配置/调用体验优化，含 Rust 改动）。测试 453 → 461。

**前端架构重整**：
- **CSS 七层**：`vendor/(open-props) → tokens/(语义映射) → themes/ → base/ → components/(14 跨窗口) → views/(窗口级) → entries/(每 HTML 单 link)`。加载顺序铁则 `reset→tokens→themes→base→components→views`。
- **Open Props = 数值源非命名源**：组件只见 `var(--space-md)` 不见 OP 原始 `--size-3`；去 OP 化成本为零（改 `tokens/` 映射）。
- **JS 拆分**：`settings.js` 4169→2133 行（`index + shared/{state,ipc,ui} + tabs/ 10 模块`，IPC 签名不变后端零改动）；`i18n.js` → `zh/en/index` 三件套，429 leaf key 对齐。
- **主题/抛光**：82 套全保留 + 新增 `neutral`（OP 色阶试点）；双层阴影 / accent 收敛 / 毛玻璃（配置化开关）。

**关键决策**：不引 Tailwind/DaisyUI（要加构建或撞冷启动 SLO）；选 OP（纯 CSS 变量、零 JS 零构建）。

**已知遗留**（非 0.9.5 引入，留专项清理）：
- `js/settings/shared/ui.js` 4 导出中 3 个零调用（`createModal`/`showToast`/`markUnsaved`）。
- `views/settings-ai.css` 旧敏感应用 modal 死代码。
- components 与 views 同名冗余（`.modal-search`/`.btn`/`.extension-card` 双份）。
