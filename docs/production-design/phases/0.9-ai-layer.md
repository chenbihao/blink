# Blink 0.9 — 智能层（AI Provider / Chat / Semantic Router）

> **范围**：AI 能力抽象 + 云端/本地 Provider + AI Chat View + Embedding 语义路由
>
> **主题**：让 blink 从"感知 + 快速操作"进化到"理解意图 + 智能推理"。
>
> **前置**：0.8 感知与操作层全部完成（Context 感知、Chord 模式底层、Autosuggestion）。
>
> **原则**：本体只提供最小抽象接口，具体实现全部走插件。本地模型按需下载，不强制捆绑，安装包保持小巧。

---

## 一、最小 AI Provider Trait（0.9.0）

> **核心原则**：AI 逻辑不放本体，全部做成可插拔插件。本体只提供最小 Provider 抽象。

### 1.1 Trait 设计

**本体只定义接口**，具体实现由插件提供，避免膨胀 core。

```rust
// 定义在 core 层,供插件系统消费
pub trait AIProvider: Send + Sync {
    fn id(&self) -> &str;
    fn is_available(&self) -> bool;

    // 只保留最基础的两个方法
    async fn chat(&self, messages: &[ChatMessage]) -> Result<String>;
    async fn chat_stream(&self, messages: &[ChatMessage]) -> Result<Stream>;

    // 可选:embedding(0.9.3 VectorRouter 依赖)
    async fn embed(&self, texts: &[String]) -> Result<Vec<Vec<f32>>> {
        Err(Error::NotSupported)
    }
}

pub struct ChatMessage {
    pub role: Role,  // System / User / Assistant / Tool
    pub content: String,
    pub tool_calls: Option<Vec<ToolCall>>,  // 预留 function calling
}
```

### 1.2 不做的事

- ❌ 不内置 embedding 推理（走 Provider 抽象，插件提供）
- ❌ 不内置本地 LLM
- ❌ 不做复杂的 Provider 管理（多 Provider 竞价/降级/负载均衡等）
- ❌ 不自动下载模型（用户手动触发才下）

### 1.3 Provider 注册与管理

**Provider 通过插件贡献**：

- 插件 manifest 声明 `provides: ["ai_provider"]`
- 插件初始化时通过 JSONL 协议向后端注册 Provider 实例
- 后端维护 `Arc<RwLock<Vec<Arc<dyn AIProvider>>>>` 全局注册表
- 前端选择使用哪个 Provider（默认第一个 available 的）

**关联文件**：
- 新增 `src/domain/ai/mod.rs`（Trait + 注册表）
- 新增 `src/domain/ai/message.rs`（ChatMessage / Role / ToolCall）
- 改造 `src/domain/plugin/protocol.rs`（新增 `register_ai_provider` 消息）

## 二、云端 AI 插件（OpenAI 兼容，0.9.1）

**作为独立插件实现**（`plugins/builtin/ai-cloud` 或第三方发行）：

- 一套代码支持 OpenAI / 通义千问 / 豆包 / DeepSeek / 任何兼容 OpenAI Chat Completion API 的接口
- API Key 加密存储（Windows Credential Manager 或 DPAPI）
- 流式响应 + 打字机效果（走 JSONL 增量协议）

### 2.1 用户体验

1. 设置页 → AI Tab → 「添加 AI 提供商」
2. 选择类型（OpenAI / Compatible） + 输入 API Key + Base URL + 模型名 + 测试连接
3. 自动注册 AI Provider，`ai xxx` 触发可用

### 2.2 密钥安全

- **不进 SQLite**（避免误提交/误备份泄漏）
- Windows：调用 [Windows Credential Manager](https://learn.microsoft.com/en-us/windows/win32/api/wincred/) 存
- 内存中 zeroize on drop
- 设置页显示时用 `••••••` mask，编辑时清空重填

### 2.3 关联文件

- 新增 `plugins/builtin/ai-cloud/` (Python 或 Rust binary)
- 新增 `src/infra/platform/secret/windows.rs`（Credential Manager 封装）

## 三、AI Chat View 对话界面（0.9.2）

> `ai xxx` 触发进入独立对话视图，支持多轮上下文 + 流式渲染 + 引用 Context。

### 3.1 触发方式

- Keyword: `ai <question>` → Takeover 进入 Chat View
- Chord: `Alt + Enter` 长按（预留，视用户反馈决定是否加）
- 从任意搜索结果右键 → "让 AI 解释" → 带上下文进 Chat View

### 3.2 UI 范式

- 独立于主搜索窗口的新 view（复用同一 WebviewWindow，切换 template）
- 类 ChatGPT 布局：消息流 + 输入框
- 支持 Markdown 渲染 + 代码高亮 + 复制按钮
- ESC 返回搜索模式

### 3.3 Context 注入

Chat 消息可自动带上（用户可关）：
- 当前剪贴板（`clipboard_text`）
- 最近选区（`selected_text`）
- 前台应用（`foreground_app.name`）
- 用户显式引用："@选区" / "@剪贴板"

### 3.4 关联文件

- 新增 `frontend/chat.html` + `frontend/js/chat.js` + `frontend/chat.css`
- 新增 `src/domain/ai/chat_session.rs`（会话状态 + 历史管理）
- 新增 `src/app/commands/ai.rs`（`ai_send_message` / `ai_stream_reply` 等）

## 四、VectorRouter 语义匹配（0.9.3）

> 原 MVP P3 规划，纳入 0.9 阶段实现。

**可选项**，用户启用 AI 后才生效。

### 4.1 原理

- 使用云端 embedding（OpenAI text-embedding-3-small）或本地 embedding（用户下载了模型）
- 内置 50+ 常用意图模板（"翻译" / "查天气" / "打开设置" / "计算" ...）
- 用户历史行为自动学习（点击某结果 → 该意图向量微调）
- 置信度阈值可调（默认 0.75，低于阈值不采纳 VectorRouter 结果）

### 4.2 向量存储

- ❌ 不引入 zvec / qdrant / lancedb 等复杂向量数据库
- 初期内存暴力 cosine 够用（1000 条向量以内，SIMD 优化可选）
- 持久化：SQLite BLOB 列存 f32 数组

### 4.3 本地模型按需下载（预留口子）

**设计原则**：

- 默认不捆绑任何模型（安装包保持小巧）
- 用户主动点击「下载模型」才开始下载
- 下载进度在设置页显示，可暂停、可取消
- 支持自定义本地模型路径（用户自己放模型文件）

**初期只支持**：

- `all-MiniLM-L6-v2`（~20MB，用于 embedding 语义匹配）
- 更复杂的本地 LLM 后续再说

### 4.4 与 RuleRouter 的关系

- RuleRouter 优先（keyword/regex/context 命中直接走）
- 未命中 → VectorRouter 补位（相似度 top-3）
- VectorRouter 命中一律 `Surface::Priority`（不 Takeover，语义匹配是弱信号）

### 4.5 关联文件

- 新增 `src/domain/intent/vector.rs`（VectorRouter 实现）
- 新增 `src/domain/ai/embed.rs`（embedding 抽象）
- 改造 `src/domain/intent/mod.rs`（RuleRouter 未命中时回退到 VectorRouter）

## 六、决策备忘

- **AI 拆到 0.9 独立版本**：与 0.8 感知/交互层解耦。0.8 是纯 Rust/Win32/前端工程；0.9 涉及外部 API、密钥管理、流式响应 UI、模型下载体验、成本控制、隐私边界——决策密度不同，不适合塞同一版本。
- **本体不实现具体 Provider**：全部走插件。避免 core 绑死某厂商 API。
- **VectorRouter 用暴力 cosine 起步**：1000 条向量内 CPU 单次 <10ms，够用。真需要扩到 10万+ 再上向量库。
- **Function Calling / Agent Loop 预留但不做**：0.9 只做 Chat + Embedding 两条最基本能力，Agent 类扩展留 1.0+。
- **本地 LLM 不做**：安装包保持 <100MB 是硬约束。想要本地推理的用户可以自行接 ollama/lm-studio 到 OpenAI 兼容端点。
