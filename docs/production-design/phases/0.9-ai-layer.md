# Blink 0.9 — Agent 地基(统一 Tool 架构 + Provider + 主窗口文本闭环)

> **范围**:能力描述统一 schema + `Action` trait tool-call 兼容 + Provider 多档抽象 + 主窗口「打字 → 路由 → 执行」纯文本闭环
>
> **前置**:0.8 全部完成(四域架构 + 0.8.6 三个统一入口)。产品定位与护城河见 [product-platform.md §6](../product-platform.md#6-护城河定位--统一-tool-架构)。
>
> **原则**:本体只提供最小抽象,**Provider 全 buildin(rig-core 直编)**;**确定性与 AI 路径分离**;**AI 调用期间必有感知反馈**;**主窗口模式** AI 只产 Suggestion / tool-call 候选,`AgentBuilder` 不用于主窗口;**Agent 窗口模式**(0.10)允许 rig 更多能力,详见 §2.3。

## 一、统一 Tool 架构

### 1.1 一切皆 tool

| tool 来源 | 执行方式 | 0.9 |
|---|---|---|
| **builtin** | 同进程(Rust) | ✅ 已有,走 `Action` trait |
| **插件** | 子进程 + JSONL IPC | ✅ 已有 |
| **MCP server** | 远程,MCP 协议 | 🔜 0.11 |
| **skill** | 声明式能力(CLI 包装等) | 🔜 0.11 |

**统一描述层,保留执行分层**——builtin 同进程的性能优势不为了「统一」牺牲成 IPC。schema 统一的是「能力声明」,执行路由按 `exec` 字段分流。

### 1.2 统一能力描述 schema

向 **MCP tool schema / OpenAI function calling / rig `ToolDefinition`** 对齐:

```jsonc
{
  "name": "translate",
  "description": "翻译文本到目标语言",
  "parameters": {                    // JSON Schema,tool-call 参数契约
    "type": "object",
    "properties": {
      "text":        { "type": "string" },
      "target_lang": { "type": "string" }
    },
    "required": ["text"]
  },
  "surface": "priority",             // 呈现权(沿用现有 inline/priority/takeover)
  "exec":    "plugin"                // 执行分派:builtin | plugin | (0.11) mcp
}
```

0.9.0 落地在 `src/domain/execution/schema.rs::ActionSchema`(rust 中间层)+ `to_rig_tool()`(唯一 rig 类型触点)。

### 1.3 不做的事(0.9 边界)

- ❌ 不统一执行层(builtin 同进程 vs 插件 IPC,分层保留)
- ❌ 不做运行期 skill 探索(留 0.11,做成配置期而非运行期)
- ❌ 不做 MCP(留 0.11,schema 已预留 `exec: mcp` 位置)
- ❌ 不引入向量数据库(0.11 RAG 才需要)

## 二、Provider 多档抽象

### 2.1 能力供应商

| 能力 | 方法 | 0.9 | 0.10 |
|---|---|---|---|
| LLM 对话(流式) | `chat` / `chat_stream` | ✅ | — |
| 语音转文字 | `transcribe` | 接口预留 | ✅ |
| Embedding | `embed` | 接口预留 | —(留 RAG) |

一个 Provider 可只供一两项(本地 whisper 只供 STT),也可全供(OpenAI)。

### 2.2 三档配置

设置页 → AI Tab,配置:

1. **供应商**(OpenAI / DeepSeek / Anthropic / 本地 ollama / ...)→ 每个供应商配多个**模型**
2. **角色指派**:从已配模型里独立指派三档

| 档 | 用途 | 特征 |
|---|---|---|
| **路由模型** | 意图分类 + 参数抽取 | 快、便宜、可本地、高频调 |
| **轻量模型** | 日常单轮任务 | 中等 |
| **主模型** | 多步推理 / Agent loop | 最强、最贵 |

**档位降级**:某档空缺 → 自动降级到下一档并 tracing warn(注册见 §2.4,代码见 §6.2)。

**不照搬 Obsidian YOLO 全自动执行**——危险动作(§3.4)哪怕模型高置信也必须用户确认。

### 2.3 Provider 落地形态

**结论**:Provider 全部 buildin,由 `rig-core` 提供实现。原「Provider 走插件 JSONL」方案作废——LLM 流式转发过 IPC 会增几十毫秒首 token 延迟,与 AI 反馈铁则(§3.3)冲突。

**rig 用法按交互模式分层**:

| 交互模式 | 用户授权 | rig 能力开放范围 | 危险动作 |
|---|---|---|---|
| **主窗口打字模式**(0.9) | 未显式授权 tool loop——用户在"搜索" | ✅ `providers::*` + `CompletionModel` + `ToolDefinition`;❌ `AgentBuilder` / `Prompt` 自动 dispatch | 一律 Tab 确认 |
| **Agent 窗口模式**(0.10) | 已显式授权 | ✅ 允许 `AgentBuilder` + `Prompt` + `memory` + tool loop | 依然一律 Tab 确认 |

**主窗口代码范例**:

```rust
// ✅ 只用 CompletionModel + ToolDefinition,ToolCall 自己路由
use rig_core::providers::anthropic;
use rig_core::client::CompletionClient;

let client = anthropic::Client::from_env()?;
let model  = client.completion_model(anthropic::CLAUDE_3_5_HAIKU);
let resp   = model.completion_request(prompt).tools(tool_defs).send().await?;
// resp.tool_calls → SuggestionArbiter → Ghost Text "回车执行" → 用户确认才穿透
```

### 2.4 Provider 注册

- **buildin 注册**:启动时按配置构造 `Vec<Arc<dyn AIProvider>>`,由 `AppContext` 持有
- **多档指派**:`AIConfig`(第七分片)记录三档模型 id,运行时按档选 Provider
- **动态切档**:配置变化触发 Provider 重建(reqwest Client 懒构造,冷成本 ~1-5ms,不上热键路径)

### 2.5 密钥安全概览

- **不进 SQLite**(避免误提交/误备份泄漏)
- Windows Credential Manager / DPAPI 存储
- 内存 zeroize on drop;设置页 `••••••` mask,编辑时清空重填

**详细 UX 决策 + review 清单见 §5**。

### 2.6 AIProvider trait 类型收窄(编译期强制)

「rig 用法按模式分层」不能靠代码 review 自觉——**主窗口拿到的类型必须在编译期就没有 `AgentBuilder` 能力**,否则任何开发者一个 `.into_agent()` 就穿透边界。

**0.9.1 完整草案**:

```rust
// src/domain/ai/provider.rs
use async_trait::async_trait;

pub struct CompletionRequest {
    pub messages: Vec<ChatMessage>,
    pub tools: Vec<crate::domain::execution::ActionSchema>,
    pub max_tokens: Option<u32>,
    pub temperature: Option<f32>,
    pub timeout_ms: Option<u32>,
}

pub struct CompletionResponse {
    pub text: Option<String>,
    pub tool_calls: Vec<ToolCall>,
    pub usage: Usage,
    pub first_token_ms: u32,  // §3.3 SLO
    pub total_ms: u32,        // §3.3 SLO
}

pub struct ToolCall {
    pub id: String,
    pub name: String,
    pub arguments: serde_json::Value,  // 直接注入 ActionContext::from_arguments()
}

#[async_trait]
pub trait AIProvider: Send + Sync {
    fn kind(&self) -> ProviderKind;
    fn model_id(&self) -> &str;

    async fn complete(&self, req: CompletionRequest) -> Result<CompletionResponse, AIError>;

    // 注意:没有 agent_session() / prompt() / memory() —— 这些留 Agent 窗口(0.10)独立类型
}

// src/domain/agent_window/session.rs(0.10 落地,主窗口路径不 import)
pub struct AgentSession { /* 内部持有 rig::agent::Agent */ }
// AgentSession 只在 domain/agent_window/ 下被引用,主窗口模块无 use path
```

**模块可见性钉死**:

- `AIProvider` trait / `CompletionRequest` / `ToolDefinition` 类型 → `pub`
- `AgentSession` / `rig::agent::Agent` 相关 → `pub(in crate::domain::agent_window)`
- 主窗口路径**只 use `AIProvider`,拿不到 `AgentSession`**

**编译期负面测试**:0.9.1 落地时加 `tests/type_narrowing.rs`,用 trybuild `#[compile_fail]` 守护——若某天有人破了 `pub(in ...::agent_window)` 边界,此测立即拦。

## 三、主窗口文本闭环(0.9.2 验收核心)

### 3.1 闭环流程

```
用户打字
  ├─ 命中 builtin/插件/keyword/regex? ──→ 确定性快速通道,直接执行(不过 AI)
  └─ 未命中
       ├─ 前置过滤未通过(query 太短/纯数字/URL 路径)──→ 常规 fuzzy 搜索结果
       └─ 通过 → 调【路由模型】判断
            ├─ 高置信 + 安全动作 ──→ 直接执行(Suggestion + Tab,或直接)
            ├─ 需多轮 ──→ 产 Suggestion「回车展开对话」(0.10 才真展开 Agent 窗口)
            └─ 不确定 ──→ 回退常规搜索结果
```

### 3.2 两条路径铁则

- **确定性路径**(< 1s):命中规则 → 直接执行,**不过 AI**,保护 P0
- **模糊意图路径**:未命中才走 AI 路由

AI 永远是**回退决策者**,不是默认路径。

### 3.3 AI 反馈铁则 + SLO 附录

> **AI 调用期间必须有感知反馈**——路由模型思考时,主窗口要有明确 loading 态,结果回流要有过渡动画。

CLAUDE.md §2「首个结果 < 20ms」是**确定性路径**的铁则,AI 路径必须显式分档。

**关键区分**:SLO 指标有两类,不要混:

- **骨架层**(我们控制)—— 抗延迟能力,与供应商无关,**必须打死**
- **观测层**(供应商决定)—— 用户看得到,我们不作硬承诺(供应商随时切换)

| 指标 | 类别 | 目标 | 触发降级 |
|---|---|---|---|
| 首个视觉反馈(loading 开始渲染) | 骨架 | < 100ms | — |
| loading 显示延迟(避免闪烁) | 骨架 | 150ms 之内不显 | 150ms 后未回才显 |
| **硬超时(单次路由调用)** | 骨架 | 2500ms 精确 abort | 静默回退常规 fuzzy,不弹错 |
| 用户中断响应(ESC / 换 query) | 骨架 | < 100ms 取消 in-flight | — |
| 意图返回 P50 | 观测 | 参考值 < 800ms | — |
| 意图返回 P95 | 观测 | 参考值 < 2000ms | 超过硬超时 → 兜底走 fallback |

**观测层不硬承诺**:P50/P95 是"当前用户配的供应商在他网络下的实际表现",设置页调试 tab 显示,让用户自行判断要不要换供应商;我们不替用户做选择。

**埋点约定**:tracing target `blink::ai::slo`,字段 `first_token_ms` / `intent_total_ms` / `fallback_to_search` / `timeout` / `tier`。0.9.0 已定义(`perf.rs::ai_slo` mod),0.9.2 上数据。

### 3.4 信任边界(白名单——独立于交互模式)

轻量路由「能直接执行」的动作必须白名单化。**独立于主窗口 / Agent 窗口两种模式**:

| 类别 | 例子 | 主窗口 | Agent 窗口 |
|---|---|---|---|
| **可逆 / 安全** | 打开文件、搜索、翻译、查天气 | 高置信可直接执行 | AgentBuilder 自主循环 |
| **危险 / 不可逆** | 删除、发送、移动、执行命令、写文件 | **必须 Tab / 确认** | **必须 Tab / 确认**——pre-exec hook 弹确认 |

**落地**:`Action::danger_class() -> DangerClass` 元数据。0.9.0 已完成 12 内置动作 + 3 Chord 全显式分类(6 Safe + 6 Dangerous)。

Agent 窗口(0.10)tool 注册按 danger_class 分流:
- `Safe` → 直接进 `AgentBuilder` tools 池
- `Dangerous` → 不进 tools 池,或走 pre-exec hook 封装 tool

### 3.5 主窗口 → Agent 窗口过渡(0.10 落地)

- 主窗口打字未命中 + 路由判"需多轮" → Ghost "Alt+1 展开对话"
- Alt+1 展开 → 复用 WebviewWindow 切换到 `view: chat` 模板
- Agent 窗口内自主循环调 tool / MCP / skill,消息历史交给 rig `Prompt` / memory 管
- ESC 返回主窗口搜索模式,会话可选保留

### 3.6 未命中过滤规则

**为什么必须先定原则**:进 AI 的判定是**产品体验分水岭**——过严 → AI 白装,过松 → 每次拼错就打云端(成本 + 隐私 + 延迟三重坑)。

**四条铁则**(0.9.0 定型,不动):

1. **默认关**——用户没显式配 Provider 且没打开 AI Tab 开关,一律不走 AI
2. **命中规则不走 AI**——`RuleRouter` / builtin / 插件 keyword / 计算器命中任一 → 零 AI 调用
3. **用户可全局关**——设置页 AI Tab 一个开关(默认 off,即使配了 Provider 也要 opt-in)
4. **必埋遥测**——每次「进 AI」都在本地 SQLite `perf` 表记录:query 长度 / 语言 / 是否命中规则 / 路由耗时 / 是否 fallback。设置页调试 tab 可见,不上报。

**四条候选筛子**(0.9.2 spike 定阈值):

| 筛子 | 默认建议 |
|---|---|
| 最短长度 | ≥ 4 字符 |
| 含空格 | 必含至少 1 个 |
| 非纯数字/纯符号 | 排除 `\d+` / `[!-/:-@\[-`\{-~]+` |
| 非 URL / 文件路径 | Awareness 已判定时不走 AI |

**决策树伪代码**:

```
if !ai_enabled_in_config() { return fallback_search }
if rule_router.hit() || builtin.hit() || plugin_keyword.hit() { return }
if awareness.is_url() || awareness.is_file_path() { return fallback_search }
if query.len() < min_len_config { return fallback_search }
if !query.contains(' ') && !looks_like_phrase(query) { return fallback_search }
if query.chars().all(char::is_numeric) { return fallback_search }
emit_slo_metric("ai_routing_started");
// 通过 → 调 AI 路由
```

### 4.4 Phase 1 spike 验收门槛(动手前定死)

**关键定位修正**:spike **不是**跑供应商延迟榜单——供应商由用户自己配、随时切,我们无权替用户做选择。**Phase 1 只验我们自己的抗延迟骨架能不能撑住任何供应商**。

供应商实际的 P50/P95 数字是用户视角的观测指标(设置页调试 tab 显示,0.9.2 落),不是我们的验收门槛。

**验收门槛(全部走通才进 Phase 2)**:

| # | 项 | 目标 | 状态 |
|---|---|---|---|
| 1 | **硬超时可信** | 请求发出后 2500ms 精确 abort,不因 SSE 半开而挂 | ✅ mock 5s + 300ms timeout,300±80ms abort |
| 2 | **中断可信** | 用户 ESC / 换 query 时,in-flight LLM 调用零延迟取消 | ✅ tokio select drop + AbortHandle 双验证,<150ms 取消 |
| 3 | **loading 反闪烁** | 150ms 内返回不显 loading;≥150ms 才 fade-in | ✅ 80ms/300ms 两档赛跑参考实现验证 |
| 4 | **首 token 埋点通路** | SSE 首 packet 到达时 `first_token_ms` 已发射,不等 total | ⏳ 并入 Phase 4 rig Client 落地 |
| 5 | **rig Client 冷构造 ≤5ms** | 首次调用不上热键路径的假设成立 | ⏳ 并入 Phase 4 |
| 6 | **SecretString 生命周期** | 读 Key → 传给 rig → 用完立即 drop,不残留栈上 | ⏳ 并入 Phase 2 密钥层 |
| 7 | **Provider 切换零重启** | 用户改配置 → 下一次调用生效,无需 relaunch | ⏳ 并入 Phase 5 三档指派 |

**Spike 已产出**(2026-07-08):

- `src/domain/ai/spike/mock_server.rs`(60 行 tokio TCP,可配置延迟)

- **前 3 条不依赖 rig-core** —— 抗延迟骨架与 LLM SDK 解耦,是纯 tokio + reqwest 能力

**§3.3 SLO 数字的定位**:

- **确定性反馈部分**(loading 显示 150ms、首视觉反馈 100ms、硬超时 2500ms)—— **我们的骨架保证**,spike 已落实

## 五、密钥安全 UX 决策(0.9.1 Phase 0)

**目标**:API Key **零污染**——SQLite / tracing / 日志 / 崩溃 dump / 备份 / 剪贴板任何一处泄漏一次都是安全事故。

### 5.1 存储位置(唯一真源)

| 层 | 存哪里 | 理由 |
|---|---|---|
| **持久层** | Windows Credential Manager(`CredWriteW`, `CRED_TYPE_GENERIC`)| DPAPI 加密,用户账户级隔离,免自维护密钥派生 |
| **内存中** | `SecretString` newtype 包 `String` + `impl Drop { self.0.zeroize() }` | 防内存 dump / core dump 泄漏 |
| **SQLite** | 存 `secret_ref: String`(如 `"blink/openai/key1"` 一个 CM 别名)+ 元数据;**绝不**存 raw Key | SQLite 会自动备份,Key 落盘一次不可逆 |
| **tracing/log** | ⛔ 绝不出现——Debug trait 特殊 impl 输出 `"<redacted>"` | tracing append-only |
| **前端渲染** | 输入后立即 `••••••••{last4}` mask | 不允许"点击显示明文" |

### 5.2 首次配置 UX 流程

```
用户点"添加供应商" → 弹配置卡片
  ├─ 供应商选 (OpenAI / DeepSeek / Anthropic / ...)
  ├─ 显示名 (用户自命名, 如 "我的 OpenAI 备用号")
  ├─ Base URL (可选, default 由供应商 preset)
  ├─ API Key 输入框
  │    ├─ 输入时: 明文可见(方便粘贴校对)
  │    ├─ 失去焦点: 立即 mask 为 ••••••••{last4}
  │    └─ 提交前: 前端拿到明文 → invoke `save_ai_secret` → 后端立即写 CM → 内存清零
  ├─ 保存: 显示"验证连接?" (可选打一次最便宜的 completion)
  └─ 保存后卡片: 供应商 + 显示名 + 掩码, 无编辑按钮 —— 要改 Key 必须"重新配置"走"清空重填"
```

**关键铁则**:

- **编辑 Key = 清空重填**——不允许"保留旧 Key + 只改 Base URL"
- **`save_ai_secret` invoke 参数用 `String`,command 层立即转 `SecretString`**——tauri IPC 是本进程内 SPSC 不落盘
- **删除 Provider = 立即 `CredDeleteW`**——不是"标记删除"

### 5.3 总开关与首次配置的耦合(0.9.1 UX 决策)

**问题**:§3.6 铁则 1 说"用户没显式配 Provider 且没打开 AI Tab 开关一律不走 AI",但用户**配完 Provider 后总开关自动开还是保持关**?这决定"配置一次"和"启用一次"是不是同一件事。

**决策**:**严格 opt-in——配完 Provider 后总开关保持关闭,弹一次 toast「已保存供应商配置,启用 AI 意图辅助?[启用] [稍后]」**。

理由:
- Blink 主链路 P0 是「打字即出结果 < 20ms」,AI 是**回退能力**不是默认能力。配 Provider ≠ 想立即接管路由
- 用户可能只是"先配着,试跑几个 completion 看看",不该配完就自动 opt-in 到主链路
- 一次配置多个 Provider 很正常——如果每次配完就翻转总开关,状态不可预测
- toast 一次性引导比"配完自动开"更清晰,且用户点[稍后]后总开关仍能在 AI Tab 顶部随时打开

**编辑既有 Provider 时**:总开关状态保持不变,不弹 toast。
**删除唯一一个 Provider 时**:自动把总开关置回 false + tracing warn(下次进 AI Tab 提示"无可用供应商")。

### 5.4 迁移旧配置

若历史用户在 SQLite `config` 表误存过 Key 相关字段:

- 启动时扫 `SELECT key FROM config WHERE key LIKE '%api_key%' OR '%secret%' OR '%token%'`
- 命中则 tracing::warn + 一次性 `UPDATE` 清空 value + 通知用户重新配置
- **不自动搬到 CM**——不知道是不是有效 Key

### 5.5 Review 清单(每次改 AI 代码前查)

- [ ] `tracing::debug!` / `info!` 里没有直接引用 `SecretString` 内容(必须 `%secret.masked()` 或 `?REDACTED`)
- [ ] `Debug for AIProvider` impl 输出不含 Key
- [ ] serde 序列化 `Provider` 类型时 `#[serde(skip)]` 标注 secret 字段
- [ ] panic backtrace / anyhow chain 里不 include Key(`RUST_BACKTRACE=1` 手跑一次 grep 无命中)
- [ ] SQLite migration 里没有 `INSERT INTO config VALUES ('...api_key...', ...)`
- [ ] 崩溃 dump / logs 目录 grep Key 前缀(如 `sk-`)无命中

### 6.2 三档降级策略

```rust
impl AIConfig {
    pub fn resolve_tier(&self, tier: Tier) -> Option<(&ProviderEntry, &ModelEntry)> {
        let chain = match tier {
            Tier::Router => vec![&self.tier_router, &self.tier_light, &self.tier_main],
            Tier::Light  => vec![&self.tier_light, &self.tier_main],
            Tier::Main   => vec![&self.tier_main],
        };
        for (i, assignment) in chain.iter().enumerate() {
            if let Some(a) = assignment {
                if let Some(entry) = self.find_provider_model(a) {
                    if i > 0 {
                        tracing::warn!(
                            target: crate::infra::utils::perf::ai_slo::TARGET,
                            requested = ?tier, degraded_to = i,
                            "AI 档位降级"
                        );
                    }
                    return Some(entry);
                }
            }
        }
        None // 全空 → 主窗口按"未配置"回退常规搜索
    }
}
```

### 6.4 降级 UX(§6.2 `resolve_tier` 的用户可见部分)

**问题**:`resolve_tier` 空档降级只 `tracing::warn`,用户看不到——**配了主档没配路由档 → 路由自动跑主档 → 悄悄烧贵模型**。设置页必须显式化。

**三处 UX 埋点**:

1. **三档下拉旁的即时提示**:某档为空时,下拉框右侧显示灰字 `→ 未指派,将使用「主档 XXX」`(轻量档同理向主档降级;主档为空则显示 `→ 未配置,AI 意图辅助将不生效`)
2. **AI Tab 顶部 banner**:任一档降级时页面顶部黄条 `⚠️ 路由档未指派,当前正使用主档,可能产生较高成本` + [立即指派] 跳转到三档区域
3. **首次实际触发降级 toast**:后端 `resolve_tier` 首次命中降级 → 通过 event `blink://ai/tier-degraded { requested, actual }` 通知前端 → 主窗口右下角一次性 toast(该 session 只弹一次,避免刷屏),点击跳转 AI Tab
4. **删除 Provider 前的连带检查**:若被删的 Provider 是任一档的引用 → 弹确认框 `此供应商是「路由档」的引用,删除后该档将回退到「主档」。确认?` 而不是静默失败

**兜底行为**:三档全空 + AI 总开关 = on → 后端 `resolve_tier` 返回 None → SearchService 走常规 fuzzy(不崩不弹错) + tracing warn 一次。**永远不因 AI 配置错误破坏主链路**。

## 七、技术选型量化

**结论**:**rig-core(按交互模式分层用)+ rmcp(0.11 起用)+ 自建外层胶水**。完整对比与拒绝理由见 memory `rust-ai-lib-selection-0-9.md`。

### 7.1 rig 能力开放清单

| rig 组件 | 主窗口(0.9) | Agent 窗口(0.10) | 说明 |
|---|---|---|---|
| `providers::*` / `Client` | ✅ | ✅ | Provider Client,底层能力 |
| `CompletionModel` / `completion_request` | ✅ | ✅ | 单次 LLM 调用 |
| `ToolDefinition` | ✅ | ✅ | tool schema 类型 |
| `ToolCall`(响应) | ✅ 自路由 | ✅ AgentBuilder 自动或自路由 | 主窗口显式路由 |
| `AgentBuilder` | ❌ | ✅ | 主窗口用户未授权 tool loop |
| `Prompt` / `TypedPrompt` | ❌ | ✅ | 消息历史管理 |
| `rig::agent::memory` | ❌ | ✅ | 短期记忆(长期留 0.11 RAG) |
| Structured output | ❌ | ✅ | 结构化返回 |
| `EmbeddingsModel` | 保留可选 | ✅ | 消息检索 |
| `TranscriptionModel` | 0.9 不用 | ✅(0.10) | 语音 STT |
| rig vector store | ❌ | ❌ | 0.11 RAG 自写 + `sqlite-vec` |

**独立铁则**:无论哪种模式,`Action::danger_class() == Dangerous` 一律走人机确认。

### 7.2 成本账单

| 维度 | 增量 |
|---|---|
| Release 二进制 | +2 ~ 3 MB(LTO fat + strip 后) |
| 冷编译时长 | +90 秒(实测 0.9.0 命中) |
| 增量编译 | ~0 |

| 破坏性升级预算 | 每季度半天(rig 一年 26 minor) |

### 7.3 未来阶段库映射

| 阶段 | 需求 | 选型 |
|---|---|---|
| **0.10** Agent 窗口 | tool loop + memory + structured output | rig `AgentBuilder` + `Prompt` |

## 九、决策备忘

**生效中**(不删):
