# Blink 0.9 — Agent 地基(统一 Tool 架构 + Provider + 主窗口文本闭环)

> **范围**:能力描述统一 schema + `Action` trait tool-call 兼容 + Provider 多档抽象 + 主窗口「打字 → 路由 → 执行」纯文本闭环
>
> **前置**:0.8 全部完成(四域架构 + 0.8.6 三个统一入口)。产品定位与护城河见 [product-platform.md §6](../product-platform.md#6-护城河定位--统一-tool-架构)。
>
> **原则**:本体只提供最小抽象,**Provider 全 buildin(rig-core 直编)**;**确定性与 AI 路径分离**;**AI 调用期间必有感知反馈**;**主窗口模式** AI 只产 Suggestion / tool-call 候选,`AgentBuilder` 不用于主窗口;**Agent 窗口模式**(0.10)允许 rig 更多能力。

## 二、已落地的核心设计(0.9.0~0.9.3 精简归档)

### 2.1 统一 Tool 架构

- **一切皆 tool**:builtin(同进程) + 插件(IPC) + MCP/skill(0.11 预留)
- **统一描述层**:向 MCP/OpenAI function calling/rig `ToolDefinition` 对齐,执行路由按 `exec` 字段分流
- **落地**:`ActionSchema` + `to_rig_tool()` 唯一 rig 类型触点

### 2.2 Provider 多档抽象

- **三档配置**:路由模型(快/便宜) → 轻量模型(日常) → 主模型(最强)
- **rig 按模式分层**:主窗口只用 `CompletionModel` + `ToolDefinition`;Agent 窗口(0.10)开放 `AgentBuilder` + memory + tool loop
- **Provider 全 buildin**:LLM 流式转发过 IPC 与「AI 反馈铁则」冲突
- **密钥安全**:Windows Credential Manager + `SecretString` zeroize on drop

### 2.3 主窗口文本闭环

```
用户打字
  ├─ 命中规则? ──→ 确定性快速通道,直接执行(不过 AI)
  └─ 未命中 → 四筛子过滤 → 调路由模型
       ├─ 高置信 + 安全动作 ──→ 直接执行
       ├─ 需多轮 ──→ Ghost "展开对话"(0.10)
       └─ 不确定 ──→ 回退常规搜索
```

**两条路径铁则**:确定性路径(< 1s)不过 AI;AI 永远是回退决策者。

### 2.4 四筛子决策树

| 筛子 | 默认阈值 |
|---|---|
| 最短长度 | ≥ 4 字符(≥ 2 CJK) |
| 含空格 | 必含至少 1 个 |
| 非纯数字/纯符号 | 排除 |
| 非 URL / 文件路径 | Awareness 已判定时不走 AI |

**四铁则**:默认关 / 命中规则不走 AI / 用户可全局关 / 必埋遥测

### 2.5 SLO 分档

- **骨架层**(我们控):硬超时 2500ms / ESC 零延迟取消 / loading 150ms 反闪烁 / Provider 切换零重启
- **观测层**(供应商决定):P50/P95 是用户配的供应商实际表现,设置页调试 tab 展示

### 2.6 插件 Tool-Call(0.9.3)

- manifest 声明 `tools` → 启动时自动注册进 `ActionRegistry`
- `ActionRegistry` 改 `RwLock`,支持动态注册
- Tool 分组聚合:12 内置动作 → 3 个 AI tool,减少 prompt token

### 2.7 类型收窄铁则

主窗口拿到的类型编译期没有 `AgentBuilder` 能力——`AIProvider` trait 只有 `kind / model_id / complete` 三个方法。

## 三、0.9.4 供应商配置 UI 升级(待做)

> **目标**:让配 AI 供应商像选 App 一样直观——网格 Picker + 模型自动发现 + 连通性测试。

### 3.1 供应商 Picker 网格化

**现状**:modal 内 preset 是纯 `<select>` 下拉,9 个 option,无视觉区分。
**目标**:可点击的卡片网格,按分类展示,每张卡片有品牌色 + monogram。

预设分类:

| 分类 | 预设 |
|---|---|
| main(国际主流) | OpenAI, Anthropic, Gemini |
| cn(国内) | DeepSeek, 硅基流动, Moonshot, 智谱, 百炼 |
| gw(网关) | OpenRouter, Groq |
| local(本地) | Ollama, LM Studio |
| custom | 自定义(手填 kind + base_url) |

每个 tile 结构:monogram(如 "OA")+ tint 背景色 + 预设名 + "已添加" 标签。选中后自动填充 kind + base_url + display_name(复用现有 `applyAIPresetToModal` 逻辑)。

**改动文件**:`settings.html`(preset 行从 `<select>` 改网格容器)、`settings.js`(新增 `AI_PRESET_CATALOG`)、`settings-modal.css`(新增 `.ai-preset-tile` 样式)。

### 3.2 模型自动发现

**现状**:textarea 手填 model id,每行一个。
**目标**:选择供应商后自动拉取可用模型列表,用户勾选。

实现策略:
- `openai_compatible` 协议:`GET {base_url}/models`(尝试 `/v1/models` 和 `/models` 两个路径)
- `anthropic_messages` / `gemini_generate_content`:硬编码常用模型列表兜底(官方不暴露 list API)
- 加载中显示 spinner,失败时 fallback 到手动输入

modal 内 textarea 替换为:
1. **批量选择区**:checkbox 列表 + 搜索过滤 + 全选
2. **手动输入区**:折叠式输入框,用于 API 拉不到的模型

**改动文件**:`settings.js`(新增 `fetchAvailableModels()` 函数 + modal 渲染逻辑)。

### 3.3 模型表格升级

**现状**:provider 卡片只显示 model id 文本。
**目标**:provider 可展开/折叠(accordion),展开后显示模型表格。

表格列:`[启用开关] | model id | display_name | 删除`

**数据结构变更**: `ModelEntry` 新增 `enabled` 字段:

```rust
// src/app/ai_config.rs
pub struct ModelEntry {
    pub id: String,
    pub display_name: String,
    #[serde(default = "default_true")]
    pub enabled: bool,          // ← 新增
    // ... 其余字段不变
}
```

向后兼容:老配置缺字段 → serde default `true`,零迁移成本。

**改动文件**:`ai_config.rs`(`ModelEntry` 加 `enabled`)、`settings.js`(`renderAIProviders` 改 accordion + 模型表格)、`settings-modal.css`(新增 `.ai-models-table` 样式)。

### 3.4 连通性测试

**现状**:无。配完才知道 Key 对不对。
**目标**:modal 内 "测试连接" 按钮,点一下验证 Key + URL。

**后端**: `src/app/commands.rs` 新增 `test_ai_provider` command:
- 接收 `(kind: ProviderKind, base_url: Option<String>, api_key: String)`
- 用 rig 发一个最小请求(`GET /models` 或空 completion)
- 返回 `Result<String, String>`(成功返回模型数量/首条模型名,失败返回错误信息)
- 注意:测试用的 api_key 直接传入内存,不走 CM 读写(用户可能还没保存)

**前端**:modal 内 API Key 行右侧加 "测试" 按钮,点击调 `invoke("test_ai_provider")`,显示 ✅ 通 / ❌ 不通 + 错误信息。

**改动文件**:`commands.rs`(新增 command)、`settings.js`(测试按钮 + 结果展示)。
