# Blink 0.8 — 感知与操作层

> **范围**：意图路由优化 + Autosuggestion 补全 + 翻译插件 Context 感知路由 + 四域架构重构 + Chord 模式底层能力 + **架构固化**
>
> **主题**：让 blink 更懂用户在做什么，让操作路径更短、更快。**AI 相关能力（Provider / Chat / Embedding）全部移至 0.9**。
>
> **状态**：0.8.0 ~ 0.8.8 全部完成。0.8 归档。测试基线 **309 通过**。

---

## 一、意图路由优化 + 内置动作抽象升级（0.8.0，已完成）

**成果**：
- **UIA 划词感知**：`WH_MOUSE_LL` 监听划词瞬间抓取，覆盖 Win32/WPF/Office/VS Code/Chrome/Typora；Scintilla/Java 已知不支持。
- **`BuiltinAction` 参数化 + Context 感知**：`RunAction { id, arg }` 替代魔法串；剪贴板 URL/文件路径触发对应动作。
- **拼音全拼匹配**：`shezhi` 也能命中"打开设置"。

**关键教训**：UIA 抓取必须在焦点未失时（`show()` 之前）；Chrome 用 `FindAll` 而非 `FindFirst`。

---

## 二、Autosuggestion / Ghost Text 输入补全（0.8.1，已完成）

**成果**：
- **路由三态**：`Exact` / `Prefix`（强信号）/ `Initials`（弱信号不独占）——首拼不强制 Takeover。
- **Ghost text = 发现工具**：部分拼音走独立 fuzzy 通道显示灰色行内补全，Tab 后才进 Takeover。
- **`empty_arg_hint`**：manifest 声明后空 arg 命中直接展示静态占位，跳过 IPC。

**关键教训**：`match_keyword` 三候选独立展开；Tab 后 keyword + arg 整段替换。

---

## 三、翻译插件 Context 感知路由（0.8.2，已完成）

**成果**：
- **`needs_translation` 判定层**：内建 4 类护栏（URL/文件路径/短文本/Empty）。
- **`RuleRouter` 消费 Context**：`context_rules` 表 + `merge_hits`。

**关键教训**：push 模式默认激进——弱意图信号该 pull 不该 push（→ 0.8.3 转 Ghost）。

---

## 四、Suggestion 抽象 + Ghost 采纳 + 智能感知面板（0.8.3，已完成）

**成果**：
- **`Suggestion` 统一契约**：`Suggestion { display, replacement, source, confidence, origin, ranking_hint }`，0.9 加 `SuggestionSource::Ai` 只加生产者。
- **Context 从 push 转 Ghost**：空 query 时 `route()` 不再产 Context candidate，统一走 Ghost + Tab 采纳。
- **awareness 域重构**：`AwarenessSnapshot { texts: Vec<AwarenessText { source, text }> }`，数据侧带 origin 一等标签。

**关键教训**：每加一路信号就多一个字段是设计味道；route() 与 best_suggestion 命中判定必须同源。

---

## 五、四域架构重构（0.8.4，已完成）

**背景**：0.8.3 收尾发现「输入 `fy` 未打参数，应用竟自动用剪贴板发起翻译」——领域边界破洞。0.8.4 把四域划分做进架构。

**成果**：
- **四域单向流**：Awareness → Suggestion → Routing → Execution
- **`route()` 断 Awareness**：签名无 snapshot 参数，编译级保证
- **`ExecArg` 类型墙**：构造 `UserExplicit` 必须显式——防回归
- **`RankingHint` Surface Booster**：只影响排序不影响 arg

**跨版本备忘**：
- `ExecArg` 是后端内部墙，非端到端信任链
- AI 永远产 Suggestion，永远不产 `Route.arg`（**主窗口模式的铁则；Agent 窗口模式 0.10 起授权粒度扩为"整个会话"，`AgentBuilder` 内的 tool loop 例外——详见 [0.9-ai-layer.md §4.3 rig 用法分层](../phases/0.9-ai-layer.md#43-provider-落地形态2026-07-定型) + [§5.4 危险动作白名单独立于模式](../phases/0.9-ai-layer.md#54-信任边界可直接执行的白名单独立于交互模式)**）
- Execution 域物理模块收敛留 0.8.6

## 六、Chord 模式底层能力（0.8.5，已完成）

**核心理念**：「主窗可见 + Alt hold 状态驱动」——提示可用快捷动作。

**成果**：
- **`ChordAction` trait + `ChordRegistry`**：注册表模式，新 Chord 低成本加入
- **Ghost overlay 提示层**：`.ghost-chord` 与 `.ghost-suggest` 平级，`:has()` 让位
- **Alt+Q 划词翻译**：独立悬浮球 `chord-ball`（`WS_EX_NOACTIVATE`），confirm flow
- **Alt+C 剪贴板历史**：独立 `ClipboardEngine` + `Route::EngineTakeover` 独占返回
- **剪贴板监听器补 0.7 漏**：单向依赖架构

**Chord 定位**：快捷键 + 独占屏幕能力的复合入口，只有真正需要独占屏幕的动作才用 Chord。

**关联文件**：`src/domain/chord/`、`src/domain/intent/mod.rs`（`Route::EngineTakeover`）、`src/domain/search/clipboard_engine.rs`、`frontend/chord-ball.html`

## 八、0.8.7 Alt+A 区域截图（已完成）

**能力**：Chord 三剑客补齐——Alt+A → 全屏截取 → 拖选矩形 → 写入剪贴板。

**关键决策**：
- SESSION 单点截屏（避免竞态）
- DWM Cloak 隐藏主窗（绕过 Win11 fade 动画）
- BGRA 全链路（省两次全屏 swap）
- PNG 速度优先（`Compression::Fast + FilterType::NoFilter`，600ms → ~150ms）

**性能**（2560×1440）：总感知延迟 **~320ms**（dev build）

**关联文件**：`src/infra/platform/screenshot/`、`frontend/chord-screenshot.html`
