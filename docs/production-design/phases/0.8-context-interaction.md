# Blink 0.8 — 感知与操作层

> **范围**：意图路由优化 + Autosuggestion 补全 + 翻译插件 Context 感知路由 + 四域架构重构 + Chord 模式底层能力
>
> **主题**：让 blink 更懂用户在做什么，让操作路径更短、更快。**AI 相关能力（Provider / Chat / Embedding）全部移至 0.9**。
>
> **原则**：本体保持轻量，纯感知/交互层无外部依赖。
>
> **状态**：0.8.0 ~ 0.8.5 已完成；Alt+A 截图划入 0.8.6。

---

## 一、意图路由优化 + 内置动作抽象升级（0.8.0，已完成 · 归档）

**成果**：
- **UIA 划词感知**：`AwarenessSnapshot` 数据通道打通，`WH_MOUSE_LL` 监听划词瞬间抓取（焦点未失前）。覆盖 Win32/WPF/Office/VS Code/Chrome/Typora；Scintilla/Java 已知不支持——用户复制文本走 clipboard fallback。
- **`BuiltinAction` 参数化 + Context 感知**：新加 `RunAction { id, arg: Option<Value> }` 变体替代 `__BLINK_ACTION_XXX__` 魔法串；剪贴板 URL → 打开链接 / 剪贴板文件路径 → 打开路径 / 资源管理器定位。
- **参数校验 Context 门禁**：Action 声明需 Clipboard 参数但 snapshot 无值 → 不召回（挡"打开链接 + 空 clipboard"僵尸候选）。
- **拼音全拼匹配**：`shezhi` / `dakaishezhi` 也能命中"打开设置"。

**关键教训**：
- **黄金时机原则**：UIA 抓取必须在焦点未失时（`show()` 之前）。原实现在 `show()` 后再抓 → Electron 全军覆没；改 `WH_MOUSE_LL` 划词瞬间抓取后 Typora/Chrome 反转成功。
- **UIA 用 `FindAll` 而非 `FindFirst`**：Chrome 地址栏 Edit + 网页 Document 都是 TextPattern，FindFirst 会误命中无选区的地址栏。

**关联文件**：`src/domain/search/builtin_engine.rs`、`src/domain/context/{probe.rs,trigger.rs}`、`src/infra/platform/selection/`。

## 二、Autosuggestion / Ghost Text 输入补全（0.8.1，已完成 · 归档）

**成果**：
- **路由三态**：`MatchType` 拆 `Exact` / `Prefix`（强信号，独占）/ `Initials`（弱信号，不独占）——首拼 `fy` 不再强制 Takeover 截断本地引擎。
- **Ghost text = 发现工具，非召回工具**：部分拼音 `fan hello` 严格不 route 命中，走独立 fuzzy 通道显示灰色行内 `→ fanyi hello`；用户 Tab 后才进 Takeover。
- **候选展开对齐 route**：`compute_hint` 对每个 keyword 展开 `[原文小写, pinyin_full]` 打分，中文原文（`翻` → `翻译`）也能触发 ghost。
- **`empty_arg_hint` 机制**：manifest 声明后空 arg 命中直接展示静态占位 item，跳过插件查询（翻译 `fanyi` 空 arg 从 500ms 防抖 IPC 变为瞬时）。

**关键教训**：
- **`match_keyword` 三候选独立展开**：意图侧走 `[原文小写, pinyin_full, pinyin_initials]`，前两者归 Exact/Prefix 强信号，首拼独占 Initials 弱信号——修 0.8.0 遗留 bug（`fanyi hello` 命中"翻译"从未成立）。
- **Tab 后 keyword + arg 整段替换**：`replacement` 是最终形态，无参 Tab 补尾空格（`fy` → `fanyi `），直接进 Takeover 等参数。

**关联文件**：`src/domain/intent/{mod.rs,suggest.rs}`、`src/domain/search/service.rs`（`SearchResponse.completion_hint`，0.8.3 已并入 `suggestion`）、`frontend/js/{ghost.js,search.js,keyboard.js}`。

## 三、翻译插件 Context 感知路由（0.8.2，已完成 · 归档）

**成果**：
- **判定层 `needs_translation`**：内建 4 类护栏（URL / 文件路径 / 短文本 < 3 字符 / Empty 分类）与 0.8.0 「打开链接」互斥——复制 URL 不会被误翻译。
- **manifest 扩容**：`PluginTrigger::Context { when, surface }`；`PluginSettingResolver` trait 反转依赖让 RuleRouter 通过 trait 读插件 `target_lang`，避免 `intent → plugin::engine` 循环。
- **`RuleRouter` 消费 Context**：加 `context_rules` 表 + `merge_hits`（keyword+context 同 plugin：surface max、arg kw 优先）。

**关键教训**：
- **函数命名贴意图**：原名 `is_non_target_lang` 只答"字符集不同"；改名 `needs_translation` 让 URL 护栏成为自然的语义组成。
- **manifest enum 与 domain enum 分离 + `From` 集中映射**：Step 5 加 `TextIsNonTargetLang` 变体时改动集中一处。
- **push 模式默认激进**：Context 命中直接 Priority 抢首屏，验收发现"复制英文只是想粘贴不是想翻译"——**弱意图信号该 pull 不该 push**（→ 0.8.3 转 Ghost 修正）。

**关联文件**：`src/domain/context/{probe.rs,trigger.rs}`、`src/domain/plugin/{mod.rs,manifest.rs,engine.rs}`、`src/domain/intent/mod.rs`、`plugins/builtin/translate/manifest.json`。

## 四、感知交互统一 —— Suggestion 抽象 + Ghost 采纳 + 智能感知面板（0.8.3，已完成 · 归档）

**成果**：
- **`Suggestion` 统一契约**：新增 `domain/intent/suggestion.rs`——`Suggestion { display, replacement, source, confidence, origin, ranking_hint }`。`SearchResponse.suggestion` 单字段替代 0.8.1 `completion_hint`。0.9 加 `SuggestionSource::Ai` 只加生产者不改契约。
- **Context 从 push 转 Ghost**：空 query 时 `route()` 不再产 Context candidate（不抢首屏），统一走 `best_suggestion` 出 Ghost + Tab 采纳。
- **共享判定入口 `match_context_hits`**：`route()` 与 `best_suggestion` 唯一命中判定入口，含黑名单过滤 + 插件启用态过滤。
- **智能感知面板**：设置页"上下文"tab 改名"上下文智能感知"，逐条 binding 开关；`disabled_context_bindings` 黑名单 key 格式 `{target_id}::{trigger_key}`。
- **awareness 域重构**（收尾）：`ContextSnapshot` 平级字段升级为 `AwarenessSnapshot { texts: Vec<AwarenessText { source, text }> }`——数据侧带 origin 一等标签，intent 层删除 `infer_origin` 等 3 处推断 helper。
- **本地化 Ghost 文本**：`build_context_suggestion_text` display 走 `manifest.name.resolve(lang)`；replacement 反查 Router 内 keyword 表按当前 UI 语言字符集偏好选择（保 Tab 采纳后命中 Takeover）。

**关键教训**：
- **每加一路信号就多一个字段是设计味道**：0.8.1 `completion_hint` + 0.8.2 若加 `context_suggestion` + 0.9 若加 `ai_suggestion` → 前端 `pickGhost()` 会写成硬编码优先级链。抽 `Suggestion { source, confidence }` 让多路信号在后端竞争完再暴露单字段是正解。
- **route() 与 best_suggestion 命中判定必须同源**：分别实现会撕裂（candidate 与 Ghost 不一致），抽 `match_context_hits` 共享入口。
- **Ghost.replacement 必须能命中 route()**：若用 `id 末段`（`translate`）而不是本地化 keyword（`翻译`），zh 用户 Tab 后 dead 状态。加闭环单测 `suggestion_ghost_replacement_hits_takeover_via_route` 防回归。
- **manifest 声明 ≠ 用户启用**：0.8.2 让"翻译 manifest 声明 context trigger 就自动纳入路由"——用户没关闭入口。0.8.3 集中到"智能感知"面板。

**关联文件**：`src/domain/intent/{mod.rs,suggestion.rs,suggest.rs}`、`src/domain/search/service.rs`、`src/domain/plugin/mod.rs`、`src/app/{config.rs,commands.rs}`、`frontend/js/{ghost.js,search.js,statusbar.js}`、`frontend/settings.{html,js,css}`。

## 五、四域架构重构（0.8.4，已完成 · 归档）

**背景**：0.8.3 收尾报「输入 `fy` 未打参数，应用竟自动用剪贴板发起翻译」的 bug。复盘发现是**领域边界破洞**多种表现——四域无清晰边界，铁则活在文档不在代码。0.8.4 把四域划分做进架构，让越界的代码写不出来。

**成果**：
- **四域单向流**：Awareness（纯数据带 origin）→ Suggestion（唯一读 Awareness，产 Ghost）→ Routing（只看 query + history + ranking_hint）→ Execution（只接受 `ExecArg::UserExplicit`）。
- **`route()` 断 Awareness**：签名 `route(query, history, ranking_hint)`，无 snapshot 参数。Context 命中只走 Suggestion 域产 Ghost + Tab 采纳。
- **`ExecArg` 类型墙**：`Hit.arg` / `Route::Takeover.arg` / `Candidate.arg` 全换 `ExecArg`。构造 `UserExplicit` 必须显式——把 snapshot 抽来的值塞进执行参数的代码编译不过。**真实价值是防回归**（0.8.3 收尾已修行为，0.8.4 用类型系统钉住）。
- **`RankingHint` Surface Booster**：Suggestion 产 Ghost 时附带 `RankingHint { boost_plugin_id }`，SearchService 下一轮 route 把它作排序梯标——只影响 surface 排序，不影响 arg / 候选集。
- **Suggestion 覆盖非空 query**：`best_suggestion` 非空 query 无 Keyword 命中时 fallback ContextGhost——兜住「chrome + 剪贴板 URL → 打开链接 Ghost」。
- **`PluginQueryContext.clipboard_text` deprecated**：插件要环境信息须走 Suggestion + 参数。

**跨版本决策备忘**：
- **`ExecArg` 是后端内部墙，非端到端信任链**：`run_builtin_action` 命令入口对前端 arg 无条件包装成 `UserExplicit`（自我认证，非不可伪造）。**0.9 接 AI Provider 勿误以为能防"AI 构造的恶意 invoke"**——它只防后端域越界。
- **AI 永远产 Suggestion，永远不产 `Route.arg`**：类型系统守死"AI 有幻觉不能直接执行"的产品原则。AI 是 Suggestion 域一个 producer。
- **RankingHint 跨轮反馈在 0.9 异步化下失效**（已知限制）：依赖 best_suggestion 同步先于 route 完成。0.9 AI 接入后 best_suggestion 变异步，需改「route 内预留 boost 槽 + 异步 hint 到达触发增量重排」。
- **Execution 域 0.8.4 不做物理收敛**：执行逻辑仍散在 `commands.rs::run_builtin_action` + `plugin/engine.rs`，唯一物理抓手是 `ExecArg` 类型墙。物理模块收敛（`domain/execution/`）留 0.9。

**关键教训**：
- **设计新 API 前先 grep 调用点**：原拟 `best_suggestion` 返回 `(Suggestion, Option<RankingHint>)` tuple 会炸 40+ 处测试调用。改 `Suggestion` 内嵌 `ranking_hint` 字段。
- **诚实区分「编译保证」「注释审计」「运行时断言」三种验证强度**：`route()` 签名不含 snapshot 参数**本身就是**证明，写运行时对比测试是冗余；`ExecArg` 构造点审计靠类型墙 + doc 注释，不是运行时遍历。

**关联文件**：`src/domain/intent/{mod.rs,suggestion.rs}`、`src/domain/search/service.rs`、`src/domain/plugin/protocol.rs`。**测试**：265 例（0.8.3 基线 247 → +18，`exec_arg_tests` 5 例 + `ranking_hint_boosts_surface_without_touching_arg` + 非空 fallback ContextGhost 翻转）。

## 六、Chord 模式底层能力（0.8.5，已完成 · 归档）

> **核心理念**：从「按 Alt 唤起→输入搜索」的被动模式，扩展为「主窗可见 + 未开始输入时按住 Alt → 提示可用快捷动作」。
>
> **范围**：底层能力（Chord 注册机制 + 触发链 + 配置面板 + 第一批动作），而非"堆一堆具体动作"。第一批动作作为验证载体，真正沉淀的是**新 Chord 能低成本加入**的注册机制。
>
> **状态**：Alt+Q 划词 + Alt+C 剪贴板 + 配置面板已完成；**Alt+A 截图划入 0.8.6**（§八）。

### 6.1 成果

- **交互模型「主窗可见 + Alt hold 状态驱动」**：hook 层与 toggle 逻辑零改动，前端 `keyboard.js::chordEligible` 门禁 = `chord_enabled + query 空 + 结果空`。
- **`ChordAction` trait + `ChordRegistry`**：注册表模式（每个动作声明 id / key / label / surface / execute），前端 `list_chord_actions` 拉列表渲染，`trigger_chord(key)` 分派执行。
- **Alt 物理态轮询**：WebView2 不转发 Alt keydown 到 JS，改后端 `is_alt_down()` command + 前端 100ms 轮询驱动 `alt-active` class。
- **Ghost overlay 提示层**（§6.4）：`.ghost-chord` 与 `.ghost-suggest` 平级，CSS `:has(.ghost-suggest:empty)` 让位——**Ghost 补全强信号优先，Chord 弱待命列表隐藏**；不占布局。走 `renderCombo` 键帽 + `+` 连接符 + `│` 分组（对齐 [product-principles §14.7](../product-principles.md#147-键盘提示样式统一强制规则)）。
- **Alt+Q 智能划词**：独立悬浮球 `chord-ball` webview（`WS_EX_NOACTIVATE` 不抢焦点），用户去原应用选文本 → 点球 → emit `blink://chord-translate` → 主窗还原 + 填「翻译 {text}」。UIA 覆盖 Chrome/Edge/Office/VS Code/Typora/Windows Terminal；Scintilla/Java 已知限制。
- **Alt+C 剪贴板历史**（§6.4 重构）：改走 fill-query → 独立 `ClipboardEngine` (sync lane, `takeover_only`) → `Route::EngineTakeover` 独占返回 top-9 → Alt+1~9 选中激活复制 + `record_clipboard_hit` 回写。
- **剪贴板监听器补 0.7 漏**：`infra/platform/clipboard/` 单向依赖架构（只依赖 data 层，不碰 AppHandle/domain/commands/前端），仿 selection 模块范式。
- **Chord 配置面板**（§6.6）：设置页新增 "Chord 交互" tab——总开关 / 提示条可见性 / 逐条动作 disable / 剪贴板监听 toggle；`ChordAction::label` 走 `LocalizableText` zh/en 双语；`ClipboardService` 尊重 `cfg.enabled`。

### 6.2 关键实施决策（偏离规划稿）

1. **主窗 mini mode 放弃** → 独立悬浮窗：原规划 CSS scale 与主窗看门狗失焦 hide + `set_focus` 抢前台根本矛盾。改 `chord-ball` 独立 webview + `WS_EX_NOACTIVATE`（不抢焦点，看门狗按 PID 判定天然豁免）。48×48 + `data-tauri-drag-region` 可拖。
2. **Alt+Q confirm flow**（非规划稿的"小球附着结果"）：悬浮球出现 → 用户选文本 → 点球 confirm → 主窗还原显示翻译结果（主窗空间大读翻译更舒服，免去球内嵌翻译 UI）。
3. **Scintilla/Java 划词 fallback 不可行**：Scintilla `SCI_GETSELTEXT` 跨进程消息不 Marshalled（LPARAM 指针不跨进程拷贝）；Java Access Bridge 可行但工程量大。作为已知限制。

### 6.3 Chord 定位澄清（2026-07-05）

**Chord ≠ 独立动作体系，而是"快捷键 + 独占屏幕能力"的复合入口**：
- 快捷键部分：Alt+字母 = 已存在动作的直达方式
- 独占屏幕部分：**只有真正需要独占屏幕的动作才用**（截图 / 悬浮球指示）

按此定位复审三个动作：

| Chord | 独占屏幕必需？ | 定位判定 |
|---|---|---|
| **Alt+A 截图** | ✅ 全屏覆盖 + 拖选，屏幕都要吃掉 | Chord ✓（0.8.6 落地） |
| **Alt+Q 划词** | ✅ 悬浮球不抢焦点让用户去原应用选文本 | Chord ✓ |
| **Alt+C 剪贴板** | ❌ 完全不需要独占 | Chord ✗ → 改走 results mix（§6.4） |

**三套并行动作抽象**（四域架构里都是 Execution 域入口，长期共用 Action trait 但使用场景稳定前不抽）：

| 系统 | 触发 | 结果去向 | disable 存储 |
|---|---|---|---|
| **BuiltinAction**（0.8.0） | keyword/context → results | mix 进 results，回车 `run_builtin_action` | `disabled_builtin_actions` |
| **Plugin**（0.3+） | keyword/context → results | mix 进 results，回车走 IPC | 插件 enabled |
| **ChordAction**（0.8.5） | Alt+字母 → 独占屏幕/emit | 直接执行副作用 | `disabled_chord_actions` |

### 6.4 Alt+C 重构关键设计（Engine + EngineTakeover + takeover_only）

**载体选择：独立 `ClipboardEngine` (sync lane) 而非 BuiltinAction 或 builtin plugin**：
- BuiltinAction 是"一 action ↔ 一 SearchItem"心智，塞"展开 top-N"撑坏语义
- BuiltinEngine 无 pool 注入，改造要动 EngineConfigs 构造链
- 做成 builtin plugin 要绕 subprocess JSONL IPC——本体自家 SQLite 表没必要
- 与 CalcEngine（keyword-triggered、一次展开若干条 Copy）心智同类

**独占返回：新增 `Route::EngineTakeover { engine_id, arg }` 变体**（类型墙原则，跟 0.8.4 `ExecArg` 精神一致）：
- `Route::Takeover.plugin_id` → SearchService `spawn_takeover` 走 JSONL IPC
- `Route::EngineTakeover.engine_id` → SearchService 直接调对应 sync engine
- 分派通过 enum 而非字符串前缀约定，避免各处解析散裂
- `RuleRouter` 加独立 `engine_rules` 表，`route()` 中先检查 engine 命中再检查 plugin——本体自家数据信号天然强，优先级恒高于插件

**`SearchEngine::takeover_only()` trait 方法**（默认 false，ClipboardEngine 返回 true）：
- **踩坑**：把 `detect_trigger` 从 engine 挪到 intent 后以为搞定，忘了 `SearchService::search` 的 `Route::Mixed` 分支硬编码"遍历所有 sync_engines"——用户输入任意内容都会调 ClipboardEngine.search(任意) → 无 keyword 检测直接 fuzzy 搜整个剪贴板历史污染结果
- **修复**：trait 方法声明"我只在 keyword 命中时活"是**引擎的自我声明**，orchestrator 不该记账；Mixed 分支遍历时 `continue` 跳过
- **收益**：未来新加同类 engine（如"待办事项"入口）零改动

**触发门禁 `chordEligible()` 单一真源**（三重与门：`chord.isEnabled()` + query 空 + 结果空）：
- **踩坑**：上一版只在 `onChordTrigger` 加 query 非空守卫，忘了菜单显示走独立 CSS `body.alt-active` → 分裂（能触发但不显示 / 反之）
- **修复**：抽 `chordEligible()` 同时驱动触发闸口 + `body.chord-visible` class；`alt-active` 与 `chord-visible` 分开（前者供 Alt+1~9 数字角标，后者供 chord 菜单显示）

## 八、0.8.6 规划：Alt+A 区域截图

**目标**：完成 Chord 三剑客最后一员，`ChordAction { key: 'a', surface: Screenshot }` 从 stub 升级为真实动作。

**核心能力**：
- 全屏透明覆盖窗（新 webview `chord-screenshot.html`，仿 `chord-ball` 独立生命周期）
- 鼠标拖选矩形区域（overlay 上 canvas 画 marquee，实时预览裁剪区）
- 截图写入剪贴板 + 自动记录到剪贴板历史（对齐 0.8.5 §6.4 剪贴板监听闭环）
- ESC 取消 / Enter 或松开鼠标确认

**已知复杂点**：
- **多显示器 + HiDPI**：Windows `EnumDisplayMonitors` + per-monitor DPI 缩放；覆盖窗必须覆盖所有虚拟屏幕（`SM_XVIRTUALSCREEN` / `SM_CXVIRTUALSCREEN`）
- **截图 API 选择**：BitBlt / PrintWindow / DXGI Desktop Duplication——BitBlt 兼容性最好但对 hardware-accelerated 窗口（Chrome/Firefox 部分模式）截黑屏，DXGI Duplication 稳但需 D3D11 上下文
- **透明覆盖窗焦点抢占**：`WS_EX_NOACTIVATE` + `WS_EX_TOPMOST` + `WS_EX_LAYERED`，仿 chord-ball 但要接键盘/鼠标事件（chord-ball 不接）——需要仔细处理"接输入但不真的抢焦点"的边界

**关联文件（规划）**：
- 新 `src/infra/platform/screenshot/`（GDI 截图 + 保存到内存 PNG）
- 新 `frontend/chord-screenshot.html` + 对应 `screenshot-ball.js`
- 扩 `src/domain/chord/mod.rs::ScreenshotAction`（execute 里 hide 主窗 + 显示 screenshot webview + 等待 confirm/cancel）
- 扩 `src/app/commands.rs`：`show_screenshot_overlay` / `capture_region` / `hide_screenshot_overlay`

**收益**：
- Chord 交互三剑客补齐（截图 / 划词 / 剪贴板）
- 与 0.8.5 剪贴板监听器闭环：截图 → 复制 → 剪贴板历史里能召回
- 悬浮球 webview 范式的第二个消费者，验证独立 webview 基础设施可扩展

**非目标**（0.9 或按需再做）：
- 标注（箭头 / 文字 / 马赛克）
- 存文件 / 上传云端
- 延时截图 / 滚动截图 / 窗口截图（点选具体窗口）

## 九、验收速览（0.8.1 ~ 0.8.5）

各版本子验收清单见对应章节末。0.8.0 ~ 0.8.5 已通过验收（276 单测）；0.8.6 待做。

```bash
cargo test --bin blink   # 全 pass（每子版本递增测试）
cargo run

# 0.8.1 Autosuggestion
→ 输入 "fy hello" → 翻译 Priority + 本地引擎结果保留 + ghost text 显示
→ 按 Tab → 补全为 "翻译 hello" 并触发 Takeover

# 0.8.2 翻译 Context 路由（架构层）
→ 选中一段英文 → 按 Alt → 翻译插件 Priority 置顶
→ 复制英文 → 按 Alt（不输入） → 翻译插件 Priority + 其他 Context 动作并存
→ 复制 URL → 按 Alt → 「打开链接」top，翻译**不出现**（URL 护栏）

# 0.8.3 Context 交互修正（Ghost + Tab 采纳）
→ 选中英文 → 按 Alt → 输入框显示 ghost "Tab 翻译 ..."，首屏不抢
→ 按 Tab → query 变 "翻译 ..." → 走 keyword Takeover
→ 设置页 → 智能感知 → 关掉某条 trigger → 该 Ghost 不再出现

# 0.8.4 四域架构（类型墙 + 域边界）
→ 复制 URL + 输入 "fy" → **不再自动用剪贴板作参数**（ExecArg 类型墙防回归）
→ 复制 URL + 输入 "chrome" → chrome 与「打开链接」都是 Routing 域 candidate，按 score 共存；翻译类弱信号走 Suggestion Ghost
→ `route()` 签名不含 snapshot 参数（编译级保证）

# 0.8.5 Chord 交互
→ 主窗 shown 空 query 空结果 → 按住 Alt → Ghost overlay 影子层显示单行键帽提示（Alt+A/Q/C）
→ 有 Ghost 补全时提示自动让位（`:has()` 保 Ghost 补全强信号优先）
→ 有输入或有结果时按 Alt → 提示不显示、Alt+字母 不触发（chordEligible 门禁）
→ Alt+Q → 独立悬浮球（不抢焦点）→ 用户去原应用选文本 → 点球 → 主窗还原 + 填「翻译 {text}」
→ Alt+C → 主窗 show + 自动填「剪贴板 」→ ClipboardEngine 独占返回 top-9 → Alt+1~9 选中激活复制 + 回写 hit
→ 输入「剪贴板 hello」→ fuzzy 搜历史（EngineTakeover 分派，不与 start_menu 混排）
→ 设置页 → Chord 交互 tab → 关闭"启用 Chord" → 主窗立即（无需重启）Alt 无反应；只关"显示提示条" → 提示不显示但 Alt+C 仍触发
→ 语言切 English → 主窗按 Alt 提示变 `Alt+A Screenshot │ Alt+Q Smart selection │ Alt+C Clipboard history`；ClipboardEngine subtitle 变 "3 min ago · 12 chars"
```
