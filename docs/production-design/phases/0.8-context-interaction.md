# Blink 0.8 — 感知与操作层

> **范围**：意图路由优化 + Autosuggestion 补全 + 翻译插件 Context 感知路由 + 四域架构重构 + Chord 模式底层能力
>
> **主题**：让 blink 更懂用户在做什么，让操作路径更短、更快。**AI 相关能力（Provider / Chat / Embedding）全部移至 0.9**。
>
> **原则**：本体保持轻量，纯感知/交互层无外部依赖。
>
> **状态**：0.8.0 ~ 0.8.4 已完成；0.8.5（Chord）规划中。

## 一、意图路由优化 + 内置动作抽象升级（0.8.0，已完成 · 归档）

### 1.1 选中文本感知（UIA 划词）

**成果**：`ContextSnapshot.selected_text` 通道打通 —— 用户划选文本瞬间被抓取并缓存，`invoke` 时回填 snapshot。

#### 覆盖面（实测定案）

| 应用类型 | 实例 | 结果 |
|---|---|---|
| 原生 Win32/WPF | 记事本 / Office / VS Code | ✅ |
| Electron | Typora / Chrome 网页 | ✅（划词触发 Chromium 懒启用 a11y） |
| Scintilla | Notepad++ / Notepad3 / Geany | ❌ 控件不暴露 UIA |
| Java Swing | RustRover (IntelliJ) | ❌ 控件不暴露 UIA |

Scintilla / Java 兜底：用户主动 Ctrl+C → 走既有 `clipboard.rs`。分层扩展 L2 `SCI_GETSELTEXT` / L3 Java Access Bridge **按需再做**。

#### 关键工程教训（供后续版本参考）

- **黄金时机原则**：抓取时机必须在**焦点未失**时。最初 `invoke` 在 show 后再抓 → Electron 全军覆没（Chromium 失焦退化选区）。改为 `WH_MOUSE_LL` 监听划词瞬间抓取后，Typora/Chrome 反转成功。0.8.3 Chord 抓 Context 也要遵守此原则。
- **Ctrl+C 兜底决定不做**：Windows 没有"不碰剪贴板的复制 API"，`Ctrl+C` 必然污染剪贴板历史（备份恢复救不了历史工具已记录的那条）。不可接受。
- **UIA 用 `FindAll` 而非 `FindFirst`**：Chrome 地址栏 Edit + 网页 Document 同为 TextPattern 元素，FindFirst 易命中无选区的地址栏。候选上限 64 护性能。
- **COM 用 MTA 不与图标提取（STA）冲突**：`selection::CACHE` 独立于 SearchService，避免 infra→domain 反向依赖。

#### 后续消化（已闭环）

- §1.1 原"⏸ 选区/剪贴板是外文 → 翻译插件动作置顶" → **§三（0.8.2）补齐架构层**，**§四（0.8.3）转 Ghost + Tab 采纳**（push 模式假阳性高，复制英文≠想翻译）。
- §1.3 "剪贴板 URL / 文件路径 → 内置动作置顶"的**内置动作侧**本节已完成；插件侧（翻译 Priority）由 0.8.2 补齐。

#### 隐私

选区文本只进内存 snapshot，不持久化；成功 `debug` 级只记长度，内容仅 `trace` 级记前 100 字符。

### 1.2 Context 感知路由（无 AI）

**问题**：复制了代码后还得手动输入「翻译」。

**方案**：简单规则引擎，根据 Context 状态调整插件优先级；纯规则，不涉及 AI 推理。

| Context 状态 | 路由调整 | 状态 |
|---|---|---|
| 剪贴板是 `http://` | 「打开链接」「下载」动作置顶 | ✅ 0.8.0 |
| 剪贴板是文件路径 | 「打开目录」「在资源管理器定位」置顶 | ✅ 0.8.0 |
| 前台是浏览器 + URL 是 GitHub | 「打开仓库」「搜 Issue」插件置顶 | ⏸ 待具体插件 |
| 前台是 VS Code + 剪贴板是代码 | 「解释代码」「格式化」插件置顶 | ⏸ 0.9 AI 层 |
| 选中/剪贴板是非目标语言 | 翻译插件置顶 | ✅ 0.8.2（架构）/ 0.8.3（Ghost） |

### 1.3 内置动作抽象升级（Context 路由的载体）

**成果**：`BuiltinAction` 从"无参操作 + 魔法串分派"升级为"参数化 Action + Context 感知 + 一等公民"。

**数据模型要点**（供 0.8.3 Chord 复用）：
- `BuiltinAction` 加 `context: &[ContextTrigger]`（空 = 不参与 Context 路由）和 `param_source: ParamSource`（`None` / `Clipboard` / `Selection`）字段
- `ContextTrigger` 覆盖 `ClipboardIsUrl` / `ClipboardIsFilePath` / `SelectionNonEmpty`，预留 `ClipboardIsCode` / `ForegroundIs` 等 0.8.0 无消费者
- `BuiltinActionKind` 分无参（`OpenSettings` / `LockWorkstation` 等 9 项）和参数化（`OpenUrl` / `OpenPath` / `RevealInExplorer`）
- 详见 `src/domain/search/builtin_engine.rs` 与 `src/domain/context/probe.rs`

**匹配规则**（0.8.2 翻译路由沿用同套约定）：
- **同一 Action 至多产出一个 `SearchItem`**：keyword 与 Context 双路命中时取 `max(keyword_score, ctx_score)`。
- **空 query 场景**：只召回 Context 命中动作，`base_score = 1.0` 保证排首屏首位。这是 0.8.0 最大产品行为改动 —— 空 query 从"不召回"改成"Context 感知主战场"。
- **参数校验（Context 门禁）**：Action 声明 `param_source: Clipboard`，但 `snapshot.clipboard_text` 为 None → **不召回**。避免"打开链接"配空参数的僵尸候选。
- **`SearchItem.id` 去重**：`builtin:{action_id}`，参数不进 id。

**分派链废魔法串**：`SearchAction` 加 `RunAction { id, arg: Option<Value> }` 变体，前端命中 `RunAction` → `invoke("run_builtin_action", { id, arg })` → 后端 `match id`。`__BLINK_ACTION_XXX__` 魔法串全部废除（含右键菜单）。

**跨版本决策备忘**：

- **`context::probe` 放 `domain/context/` 不放 `infra/platform/context/`**：纯字符串判定无平台调用；`RuleRouter`（`domain/intent/`）与 `BuiltinEngine`（`domain/search/`）共用，别写两份。0.8.2 `needs_translation` 已加在同一模块。
- **参数来自 Context，不做本地 NER**：`param_source` 只从 Clipboard / Selection 取。本地 BERT NER 不划算，长句参数走 **0.9 AI function calling**。
- **`RunAction.arg` 用 `Option<serde_json::Value>` 而非 `String`**：前后端契约一次到位。0.8.0 传字符串就是 `Value::String(...)`，0.8.4 后端内部换 `ExecArg` 但对外契约层仍 `Option<Value>`（见 §5.1）。
- **Disable 状态用 `AppConfig.disabled_builtin_actions: Vec<String>` 内存快照**：不走 SQLite 热路径。0.8.3 Context binding disable 复用同套机制。
- **不升格独立 `domain/action/` 模块**：0.8.0 只扩字段，改动局限在 `search::builtin_engine`。
- **`BuiltinAction` 命名沿用**：避免跟前端契约 `Action` / `ActionKind` 起冲突。

## 二、Autosuggestion / Ghost Text 输入补全（0.8.1，已完成 · 归档）

> **动机**：原 `match_keyword` 把「汉字精确」和「首拼命中」都归入 `Prefix` → `Auto` 一律升 Takeover。首拼是**弱信号**（`fy` 可能是"翻译"也可能是同名应用），强制 Takeover 截断本地引擎结果。插件生态扩大后，任何首拼冲突都会误炸普通查询。
>
> **策略**：首拼降级为**普通匹配 + 分值加成**（不独占），配合 ghost text 教学"更规范的 keyword"，用户 Tab 显式进 Takeover。**"独占"从此只有两个入口**：完整键入 keyword，或 Ghost Text + Tab。

### 2.1 成果

- **路由三态**：`MatchType` 拆 `Exact` / `Prefix`（强信号）/ `Initials`（弱信号）三态；`resolve_surface(Auto)` 对 Initials 无参→Priority、带参→Inline，独占入口收窄。
- **Ghost text = 发现工具，非召回工具**：部分拼音（`fan hello`）route 严格不命中，但走独立 fuzzy 通道显示 ghost `→ fanyi hello`。用户 Tab 后才进 Takeover。
- **候选展开对齐 route**：`compute_hint` 对每个 keyword 展开 `[原文小写, pinyin_full]` 两个 target 打分，精确等值用 `f64::INFINITY` 顶格分统一决策；中文原文（如 `翻` → `翻译`）也能触发 ghost。
- **`empty_arg_hint`（新机制）**：manifest 声明后，空 arg 命中该插件直接展示静态占位 item，**不发起插件查询**。翻译插件 `fanyi` / `翻译` / Tab 补全后从"500ms 防抖 + Python 进程 IPC"变为瞬时。i18n 走 `LocalizableText`。语义与 `min_arg_length` 正交：前者是"给静态占位不查询"，后者是"降级到 Generic 搜索"。

### 2.2 路由行为对照（终态）

| Query 类型 | 例子 | 结果 |
|---|---|---|
| 汉字 Exact / Prefix | `翻译` / `翻译 hello` | Priority / Takeover |
| Latin Exact / Prefix | `translate` / `translate hello` | Priority / Takeover |
| Pinyin_full Exact / Prefix | `fanyi` / `fanyi hello` | Priority / Takeover |
| **首拼 Exact** | `fy` | Priority + ghost `→ fanyi` |
| **首拼 Prefix + arg** | `fy hello` | **Inline** + ghost `→ fanyi hello` |
| 部分拼音（fuzzy） | `fan` / `翻` | 不召回 + ghost `→ fanyi` / `→ 翻译` |
| 已完整 + 无尾空格 | `fanyi` / `翻译` | 走 Priority + Tab-only hint（`display=""`） |
| 已完整 + 尾空格/参数 | `fanyi ` / `fanyi hello` | 走 Takeover，无 ghost |

### 2.3 决策备忘（跨版本参考）

- **Ghost 独立于召回**：部分拼音不进 route（保严格），只做提示。避免召回污染。
- **首拼 Exact 保留 Priority 而非 Inline**：无参场景 Priority 已不独占，配合 ghost 教学最完整。
- **Tab 后 keyword + arg 整段替换**（不做"只补 keyword 部分"）：`replacement` 是最终形态。无参 Tab 补尾空格（`fy` → Tab → `fanyi `，直接进 Takeover 等参数）。
- **后端算 ghost**：`RuleRouter::suggest_completion` 顺路算，与 route 共用 keyword 表；避免前端搬 fuzzy/pinyin 两份逻辑。IPC 契约走 `SearchResponse { entries, completionHint }`（camelCase）。0.8.3 后 `completionHint` 已被统一进 `SearchResponse.suggestion`（见 §四）。
- **多候选切换（→ 循环）v2 再做**：一期只返最高分那个，避免键位争议。分数相同时按 keyword 注册顺序取第一个（`>` 严格比较）。
- **`match_keyword` 三候选展开**：意图侧独立走 `[原文小写, pinyin_full, pinyin_initials]`，前两者归 Exact/Prefix 强信号，首拼独占 Initials 弱信号。修复 0.8.0 遗留 bug（`fanyi hello` 命中"翻译"从未成立）。`normalize_candidates` 保留供应用搜索侧继续使用。
- **`empty_arg_hint` 走 manifest 而非插件端**：省一次 IPC + 支持 i18n + Tab 补全时也命中；`SearchService` 持 language 快照跟随 AppConfig 热更新。翻译 `main.py` 的空 arg 分支保留为兜底（返空 items）。

### 2.4 参数模型约定（未落地，1.0 前重审）

现状 `arg: String` 单串、插件自切分，无 shell-quoting / schema。0.8.1 不动（无卡点，ghost 一期不需参数结构感知）；真正需要是 0.9 AI Function Calling 场景，届时一起设计（备选 `Vec<String>` + shell-quoting，或 `Value + manifest schema` 类型安全方案）。0.8.4 后端内部 `arg` 已类型化为 `ExecArg`（见 §五），但插件侧切分模型未动。

### 2.5 关联文件

- 后端：`src/domain/intent/mod.rs`（三态 + `match_keyword`）、`src/domain/intent/suggest.rs`（`compute_hint`）、`src/domain/search/service.rs`（`SearchResponse` + `empty_arg_hint` 分支 + language 快照）、`src/domain/plugin/manifest.rs`（`empty_arg_hint` 字段）、`src/domain/plugin/engine.rs`（`get_empty_arg_hint`）、`src/app/config.rs`（`autosuggest_enabled` / `autosuggest_min_score`）
- 前端：`frontend/js/ghost.js` / `search.js` / `keyboard.js` / `kbd.js` / `statusbar.js` / `autosuggest-config.js` / `css/style.css` + `css/kbd.css` / `settings.html`
- 插件：`plugins/builtin/translate/manifest.json`（`empty_arg_hint`）+ `main.py`（空 arg 分支简化）

## 三、翻译插件 Context 感知路由（0.8.2，已完成 · 归档）

> **归档摘要**。0.8.2 完成的是**架构层**——`RuleRouter` 从"只处理 keyword/regex"扩到"能消费 `ContextSnapshot`"，翻译插件补齐 Context 触发闭环。**交互层 push 抢首屏的问题 → 0.8.3 §四 转 Ghost 模式修正**。完整方案讨论见 git 历史。

### 3.1 成果

- **判定层**：`domain/context/probe.rs` 加 `TextLang` + `detect_lang` + `needs_translation`。**关键：`needs_translation` 内建 4 类护栏**（URL / 文件路径 / 短文本 < 3 字符 / Empty 分类），与 0.8.0「打开链接」内置动作**互斥**，避免复制 URL 被翻译。25+ 例单测。
- **共用 enum 上移**：`ContextTrigger` / `ParamSource` 从 `builtin_engine.rs` 抽到 `domain/context/trigger.rs`，内置动作与插件共享。
- **manifest 扩容**：`PluginTrigger::Context { when, surface }` + `ManifestContextWhen`（snake_case 反序列化）+ 容错反序列化（单条 trigger 解析失败仅 warn 跳过，不整个 manifest 挂）。schema_version 保持 1（0.x 未发布无兼容压力）。
- **`PluginSettingResolver` trait**：反转依赖，`RuleRouter` 通过 trait 读插件 `target_lang`；`PluginEngine` 实现。避免 `intent → plugin::engine` 正向循环。
- **`RuleRouter` 消费 Context**：加 `context_rules` 表 + `match_context_rules` + `merge_hits`（keyword+context 同 plugin：surface max、arg kw 优先）。`Auto`/`Priority`/`Inline` 声明中 `Inline` warn+降级（0.8.2 收窄）。
- **翻译 manifest** 声明 `{ type: context, when: text_is_non_target_lang, surface: priority }`。

### 3.2 关键工程教训（供后续版本参考）

- **单测过 ≠ 集成过**：Step 5 单测全过后集成才发现 `SearchService::search` 空 query 短路了 `router.route()`——插件 Context 触发在空 query 场景永远不生效。前端 `search.js` 里也有同型 bug（`!queryEl.value.trim() → return` 丢空 query 增量结果）。→ [[empty-query-must-run-router]]
- **函数命名要贴意图**：原名 `is_non_target_lang` 只答"字符集不同"，实际需要"值得翻译吗"（含 URL 护栏语义）。改名 `needs_translation` 让护栏成为自然的语义组成。
- **manifest 侧 enum 与 domain 侧 enum 分离 + `From` 集中映射**：`ManifestContextWhen`（4 变体，snake_case JSON）→ `ContextTrigger`（域内 enum，带 `TextSource`）。映射放 `impl From`，Step 5 加 `TextIsNonTargetLang` 变体时改动集中一处。
- **依赖反转 trait**：`RuleRouter` 需要读插件 setting 但不能引用 `PluginEngine`（会形成循环）。定义 `PluginSettingResolver` trait 让 `PluginEngine` 实现，`RuleRouter` 只知 `Arc<dyn PluginSettingResolver>` + 后置注入。
- **push 模式默认激进**：0.8.2 让 Context 命中直接 Priority 抢首屏，验收发现"复制英文只是想粘贴不是想翻译"——**弱意图信号该 pull 不该 push**。→ [[context-as-ghost-suggestion]]，0.8.3 §四 修正。

### 3.3 关联文件

- `src/domain/context/trigger.rs`（新）· `src/domain/context/probe.rs`（+lang/translation）· `src/domain/plugin/mod.rs`（+trait）· `src/domain/plugin/manifest.rs`（+Context 变体 + 容错解析）· `src/domain/plugin/engine.rs`（+trait impl）· `src/domain/intent/mod.rs`（+context_rules + merge_hits）· `src/domain/search/service.rs`（去空 query 短路）· `src/domain/search/builtin_engine.rs`（enum 上移引用）· `plugins/builtin/translate/manifest.json`（+context trigger）· `frontend/js/search.js`（去空 query 增量拦截）
- **测试**：`context::probe` 25+ 例（含护栏 + Kana/CJK 特例 + 多行 URL）；`context::trigger` 15 例；`intent` 加 21 例（Context 命中 / URL 护栏 / target=auto / arg 截断 / kw+ctx 合并等）。总 221 例（0.8.1 基线 166 → +55）。

## 四、感知交互统一 —— Suggestion 抽象 + Ghost 采纳 + 智能感知面板（0.8.3，已完成 · 归档）

> **归档摘要**。0.8.3 完成**四件事**：**Suggestion 契约统一**（给 0.9 AI 意图铺路）、**Context 从 push 转 Ghost**（弱意图信号该 pull 不该 push）、**智能感知面板**（用户可关闭 binding）、**awareness 域重构**（数据侧带 origin,intent 层零推断,§4.5）。完整讨论/决策/伪代码见 git 历史。

### 4.1 成果

- **`Suggestion` 统一契约**：新增 `domain/intent/suggestion.rs`——`Suggestion { display, replacement, source, confidence, prefix_len, origin }`。`SearchResponse.suggestion` 单字段替代 0.8.1 `completion_hint`。前端契约保持一个字段,0.9 加 `SuggestionSource::Ai` 只加生产者不改契约。
- **`best_suggestion` 主入口**：`RuleRouter::best_suggestion` 统一分派——空 query 走 Context 分支（多命中按 `context_confidence` 取 top-1）、非空 query 走 Keyword 分支（走 `compute_hint_scored` 拿 fuzzy 分）。空/非空互斥保 0.8.3 阶段两源不竞争,竞争路径为 0.9 预留。
- **Context 从 push 转 Ghost**：空 query 时 `route()` 不再产 Context candidate（不抢首屏）,统一走 `best_suggestion` 出 Ghost + Tab 采纳。非空 query 保留 `merge_hits_keyword_only`（keyword+context 同 plugin 加分,不 solo context 抢位）。
- **共享判定入口**：`match_context_hits` 是 `route()` 与 `best_suggestion` 唯一命中判定入口,内含黑名单过滤 + 插件启用态过滤,避免 candidate 与 Ghost 撕裂。
- **`disabled_context_bindings` 黑名单**：`AppConfig` 加 `Vec<String>`,key 格式 `{target_id}::{trigger_key}` 双冒号分隔（避开 target_id 内部点/冒号）。心智同构 `disabled_builtin_actions`。
- **智能感知面板**：设置页 "上下文" tab 改名 "上下文智能感知",顶部收纳 "输入补全"（从通用挪来,存储 key 不变）,中部新增 "Context 触发规则" 逐条开关,底部保留原 "采集与敏感应用"。
- **本地化 Ghost 文本**：`build_context_suggestion_text` display 走 `manifest.name.resolve(lang)`（`翻译`/`Translate`）,replacement 反查 Router 内 keyword 表按当前 UI 语言字符集偏好（zh 优先 CJK / en 优先 ASCII）保 Tab 采纳后能命中 Takeover。
- **origin 提示**：`Suggestion.origin` 携带来源（Selection / Clipboard）,前端 statusbar 追加 "· 来自划词 / · 来自剪贴板" 弱视觉提示。

### 4.2 关键工程教训

- **每加一路信号就多一个字段是设计味道**：0.8.1 `completion_hint`、0.8.2 若加 `context_suggestion`、0.9 若加 `ai_suggestion`——前端 `pickGhost()` 会写成硬编码优先级链。抽 `Suggestion { source, confidence }` 让多路信号在后端竞争完再暴露单字段是正解,晚做代价指数级。→ [[suggestion-abstraction-for-0-9]]
- **push 模式默认激进**：Context 是弱意图信号（"复制英文≠想翻译"）,直接 Priority 抢首屏体验差。0.8.1 Ghost Text 的 Tab 采纳心智可以复用,不重造。→ [[context-as-ghost-suggestion]]
- **manifest 声明 ≠ 用户启用**：0.8.2 曾让"翻译 manifest 声明 context trigger 就纳入路由"——用户没有关闭入口。0.8.3 加黑名单集中到"智能感知"面板,用户学一次通全套。→ [[context-trigger-user-configurable]]
- **route() 与 best_suggestion 命中判定必须同源**：两路都跑 context 命中,若判定分别实现会撕裂（candidate 与 Ghost 结果不一致）。抽 `match_context_hits` 共享入口,黑名单/启用态过滤都在一处。同理 `context_confidence` 与 `infer_origin` 的 selection 判定共用 `snapshot_has_meaningful_selection`。
- **Ghost.replacement 必须能命中 route()**：`replacement` 是 Tab 后重跑 route 的输入文本。若用 `id 末段`（`translate`）而不是本地化 keyword（`翻译`）,zh 用户 Tab 后无法命中 keyword 表 → 死态。反查 Router 内 keyword 表 + 按当前 UI 字符集偏好是正解。加了闭环单测 `suggestion_ghost_replacement_hits_takeover_via_route` 防回归。
- **origin 推断有味道**：0.8.3 落地时 `Suggestion.origin` 靠 `infer_origin(when, snapshot)` 事后推断——功能上正确,但暴露了 selection/clipboard 分层不干净的问题（详见 §4.5 awareness 重构）。

### 4.4 决策备忘（跨版本参考）

### 4.5 awareness 重构（0.8.3 收尾 · 已完成）

**动机**：`Suggestion.origin` 0.8.3 一版靠 `infer_origin(when, snapshot)` 事后推断——功能正确,但暴露架构味道：

- **数据丢标签**：`ContextSnapshot { selected_text, clipboard_text }` 是平级字段,消费方靠字段名认 origin,不靠类型
- **三处重复推断**：`infer_origin` / `context_confidence.src_w` / `TextSource::extract` 取值顺序各自实现"selection 非空吗",靠 `snapshot_has_meaningful_selection` helper 绑到一起
- **抽象空转**：`TextSource` enum 只有一个 `SelectionThenClipboard` 变体,却当策略层用

**成果**：

- **新数据结构**：`AwarenessSnapshot { texts: Vec<AwarenessText { source, text }>, foreground_app }` —— 每条文本自带 `AwarenessSource (Selection / Clipboard)` 一等标签
- **内聚判定入口**：`AwarenessSnapshot::find_text(source)` 是 trim 语义唯一入口,取代 `snapshot_has_meaningful_selection` / `TextSource::extract` 的松散判定
- **`TextSource::extract` 返回 `Option<AwarenessView>`** 而非 `Option<&str>` —— 调用方拿 `(source, text)` 一起,不必事后推断
- **`Hit.origin` 从数据侧带来**：`match_context_hits` 从 `AwarenessView.source` 或 trigger 语义直取,`best_suggestion` 直接映射到 `Suggestion.origin`
- **`context_confidence` 签名简化**：`(&when, &snapshot)` → `(&when, Option<AwarenessSource>)` —— 不再需要 snapshot 参数,origin 权重由 Hit 带来的数据决定
- **`SuggestionOrigin` 零 cost 转换**：`impl From<AwarenessSource> for SuggestionOrigin` —— 一对一映射,无分支推断
- **过渡 alias**：`pub type ContextSnapshot = AwarenessSnapshot` 保留一版,消费方零改动过渡

**删除的三个函数**：`infer_origin` / `snapshot_has_meaningful_selection` / `context_confidence` 的旧 snapshot 推断分支。

**命名**：物理路径仍为 `infra/platform/context/`（避免 git 历史与 import 全改）；逻辑域改称 awareness 与 0.9 AI 的「意图判定」层次对齐。0.9 或 1.0 前可做物理目录改名。

### 4.6 决策备忘（awareness 重构）

- **`Vec<AwarenessText>` 而非 `HashMap`**：未来 Chord 场景下同一 source 可能多条（历史剪贴板）,遍历/过滤/去重容易表达；source 量少 Vec 查找 O(n) 不是问题
- **`foreground_app` 单独放**：它是元数据不是文本,进 `AwarenessText.text` 语义扭曲；消费方(敏感应用过滤、plugin protocol)也确实按元数据用
- **`AwarenessSnapshot::upsert_text` 代替字段直写**：`update_selected_text` 改为 upsert 语义（找到同 source 替换 / 否则 append / None 删除）,与 `collect()` 的分支 append 路径一致
- **0.9 Chord 扩展位**：`AwarenessSource` 加 `ChordSelection` / `ChordClipboard` 变体；`SuggestionOrigin` 的 `From` 映射策略决定是否拆更细变体
- **`PluginQueryContext` 外部契约不变**：JSONL 锁死,`from_snapshot` 内部改用 `find_text(Clipboard)` 抽 clipboard_text
- **`TextSource` enum 保留但简化**：`extract` 内部委托 `AwarenessSnapshot::find_text`,不再自己做 trim 判定；0.9 Chord 加 `SelectionOnly` / `ClipboardOnly` 变体

## 五、四域架构重构（0.8.4，已完成 · 归档）

> **归档摘要**。0.8.3 收尾时报「输入 `fy` 未打参数,应用竟自动用剪贴板内容发起翻译」的 bug。修完复盘发现这不是孤立 bug,是**领域边界破洞**的多种表现：内置动作 `ParamSource::extract` 无脑抽参、`route()` 偷读 Awareness、`best_suggestion` 只覆盖空 query、插件 protocol 直读 Awareness。**核心病灶**：Awareness / Suggestion / Routing / Execution 四域无清晰边界,0.8.3 归档的三条铁则活在文档不在代码。0.8.4 把四域划分做进架构——让越界的代码写不出来（类型墙 / 签名收敛 / 域接口单向）,给 0.9 AI 意图判定器铺信任边界。原规划 Chord 顺延 0.8.5。完整方案讨论（含四域图、铁则表、伪代码、迁移路径）见 git 历史。

### 5.1 成果

- **四域单向流**：Awareness（纯数据,带 origin）→ Suggestion（唯一读 Awareness,产 Ghost）→ Routing（只看 query + history + ranking_hint）→ Execution（只接受 `ExecArg::UserExplicit`）。数据只能沿箭头流,每段中间有信任边界（Tab / 点击 / 回车 / 类型约束）。
- **`route()` 断 Awareness**：签名 `route(query, history, ranking_hint: Option<&RankingHint>)`,无 snapshot 参数。`match_context_hits` 移出 route,只在 `best_suggestion` 消费——Context 命中走 Suggestion 域产 Ghost + Tab 采纳,不进 Routing。
- **`ExecArg` 类型墙**：`Hit.arg` / `Route::Takeover.arg` / `Candidate.arg` 全换 `ExecArg`。构造 `UserExplicit` 必须显式,把 snapshot 抽来的值塞进执行参数的代码编译不过。对外 `SearchAction::RunAction.arg` 序列化仍 `Option<Value>`（`ExecArg::to_run_action_arg` 转换），前端契约零变化。**真实价值是防回归**（0.8.3 收尾已修行为）,非修现存 bug。
- **`RankingHint` Surface Booster**：Suggestion 产 Ghost 时附带 `RankingHint { boost_plugin_id }`,SearchService 下一轮 route 把它作排序梯标传入——只影响同 plugin 候选的 surface 排序,不影响 arg、不影响候选集。保住「打"翻译" + 剪贴板英文 → 翻译排序靠前」的便利,不破边界。
- **Suggestion 覆盖非空 query**：`best_suggestion` 非空 query 无 Keyword 命中时 fallback ContextGhost——兜住「chrome + 剪贴板 URL → 打开链接 Ghost」。**翻转 0.8.3「空/非空互斥」决策**（测试 `suggestion_non_empty_query_does_not_produce_context` → `_fallback_context`）。
- **内置动作不延后抽参**：`BuiltinEngine::search` 阶段抽参 → 整链路透传同一 arg 到执行（§5.1 决策）。理由：内置动作参数强相关（复制 URL ≈ 想打开）,延后会引入预览/执行时间差竞态（看到的 A、打开的 B）,且 Context 门禁已挡住「僵尸候选」,孪生 bug 前提不成立。
- **`PluginQueryContext.clipboard_text` deprecated**：`#[deprecated]` 标记 + 注释「历史兼容至 1.0 前移除」。插件要环境信息须走 Suggestion + 参数。

### 5.2 关键工程教训（含与方案稿的偏离）

- **方案稿的返回签名要顺测试调用改**：原拟 `best_suggestion` 返回 `(Suggestion, Option<RankingHint>)` tuple——会炸 40+ 处测试调用（`.expect` / `.is_none` / `.is_some`）。改为 `Suggestion` 内嵌 `ranking_hint: Option<RankingHint>` 字段（`#[serde(skip_serializing)]`）,前端契约零变化。**设计新 API 前先 grep 调用点**。
- **类型墙落地后展示文本要分离**：`Hit.arg` 统一为「执行参数」语义后,context hit 的**展示文本**（待翻译内容片段）不能再进 `Hit.arg`（context hit `arg = None`）。`build_context_suggestion_text` 加 snapshot 参数从 Awareness 直取（Suggestion 域读 Awareness 合法）。执行参数与展示文本是两路。
- **「编译级保证」别写成运行时测试**：方案稿拟的三条边界回归测试,落地时只有 `ranking_hint_boosts_surface_without_touching_arg` 是运行时 `#[test]`；`route()` 签名不含 snapshot 参数本身就是证明（写「传两 snapshot 比对结果」的运行时测试在签名删掉后无法编译、是冗余）；`ExecArg` 构造点审计靠类型墙 + 构造处 doc 注释,不是运行时遍历。**诚实区分「编译保证」「注释审计」「运行时断言」三种验证强度**。
- **route 签名留 history 但不消费**：`route(query, history, _ranking_hint)` 中 history 现状 unused（频率加权在 search 层 apply）,签名含 history 为 0.9 VectorRouter / AIRouter 预留稳定接口——换内部实现不动签名。

### 5.3 关联文件

- `src/domain/intent/mod.rs`（`ExecArg` + `RankingHint` + `route` 签名简化 + `best_suggestion` 非空 fallback + `match_context_hits` 移出 route + `merge_hits_keyword_only` 改 RankingHint boost）
- `src/domain/intent/suggestion.rs`（`Suggestion.ranking_hint` 内嵌字段,`#[serde(skip_serializing)]`）
- `src/domain/plugin/protocol.rs`（`PluginQueryContext.clipboard_text` `#[deprecated]`）
- `src/domain/search/service.rs`（`last_ranking_hint` 跨轮缓存 + hint 透传 route）
- **测试**：`exec_arg_tests`（5 例）+ `ranking_hint_boosts_surface_without_touching_arg` + 非空 fallback ContextGhost 翻转。总 265 例（0.8.3 基线 247 → +18）。

### 5.4 决策备忘（跨版本参考）

- **`ExecArg` 是后端内部墙,非端到端信任链**：`run_builtin_action` 命令入口对前端 arg 无条件包装成 `UserExplicit`（自我认证,非不可伪造）。本地受信 WebView 够用；**0.9 接 AI Provider 勿误以为能防「AI 构造的恶意 invoke」**——它只防后端域越界。
- **AI 永远产 Suggestion,永远不产 `Route.arg`**：类型系统守死「AI 有幻觉不能直接执行」的产品原则。AI 是 Suggestion 域一个 producer,与 KeywordCompletion / ContextGhost 平级。
- **RankingHint 跨轮反馈在 0.9 异步化下失效（已知限制）**：依赖 best_suggestion 同步先于 route 完成。0.9 AI 接入后 best_suggestion 变异步（云端往返）,hint 滞后不止一轮、追移动靶。0.9 需改「route 内预留 boost 槽 + 异步 hint 到达触发增量重排 emit `blink://results`」。`last_ranking_hint` 字段与 boost merge 逻辑已为此留扩展位。
- **Execution 域 0.8.4 不做物理收敛**：执行逻辑仍散在 `commands.rs::run_builtin_action` + `plugin/engine.rs` + `main.rs`,唯一物理抓手是 `ExecArg` 类型墙。物理模块收敛（`domain/execution/`）留 0.9。
- **内置动作走 Routing,翻译走 Suggestion**：参数语义强度不同（URL 强相关 vs 待翻译文本弱相关）。内置动作的参数在 candidate 产出时定型、不再随 snapshot 漂移——Awareness 未跨信任边界直接触发 Execution。
- **VectorRouter / AIRouter 是 Routing 域内部策略升级**：都接受 `(query, history, ranking_hint)`,都不看 snapshot,域边界不变、内部实现替换。

### 5.5 遗留（1.0 前清理,均无害）

- `run_route_with_snapshot` 测试辅助：route 断 snapshot 后其 snapshot 参数被忽略（`_snapshot`）,可改名 / 删。
- `QueryContext` 结构：route 不再用,`#[allow(dead_code)]`,可删。
- `ExecArg::to_run_action_arg`：内置动作不经 Candidate 链（§5.1 决策）,该方法暂无生产调用点（靠 `exec_arg_tests` 覆盖不 warn）,未来内置动作迁移 Candidate 时启用或删。

## 六、Chord 模式底层能力（0.8.5，原 0.8.4）

> **灵感来源**：Quicker + 键盘驱动的全局动作层
>
> **核心理念**：从「按 Alt 唤起→输入搜索」的被动模式，扩展为「按住 Alt→直接触发动作」的主动模式。
>
> **0.8.5 范围界定**：**底层能力**（状态机 + Context 抓取 + 唤起动作编排 + 提示 UI），而非"堆一堆具体动作"。第一批 Chord 动作作为验证载体，但真正沉淀的是**其他 Chord 动作能低成本加入**的注册机制。
>
> **版本重排**：原规划 0.8.3 是 Chord。0.8.2 验收发现 Context 感知交互层问题严重（[[context-as-ghost-suggestion]]），Chord 后延到 0.8.4。0.8.3 收尾后发现四域架构需先立（避免 Chord 加进来时又违反边界）, 0.8.4 改做四域重构（§五）,Chord 顺延至 0.8.5。

### 6.1 交互流程

```
用户按住 Alt（不松开）
     ↓
┌─────────────────────┐
│  Blink 窗口出现        │
│  提示：按住 Alt + ...  │
└─────────────────────┘
     ↓     ↓     ↓
  +A     +Q     +空格...
  截图   划词   语音输入
```

**关键细节**：
- Alt **按住不放**是进入 Chord 模式的信号
- 二次按键在 Alt 按住期间按下，**不需要松开再按**
- 窗口出现时显示可用的 Chord 快捷键提示（如底部状态栏）
- Alt 松开 → 退出 Chord 模式，回到正常搜索输入

### 6.2 第一批 Chord 动作（作为底层能力的验证载体）

| 组合键 | 动作 | 说明 |
|---|---|---|
| `Alt + A` | **区域截图** | 进入截图模式，拖动选择区域 → 自动复制到剪贴板 |
| `Alt + Q` | **智能划词** | 主动触发划词文本抓取（比监听更可靠）+ 翻译/搜索动作弹出 |
| `Alt + C` | **剪贴板历史** | 直接打开剪贴板历史面板（跳过搜索） |
| `Alt + Space` | **语音输入** | 预留（按住期间语音识别，松开结束，实际推理留 0.9） |

### 6.3 底层能力清单（本节的真正范围）

**核心 1：状态机扩展**（`hotkey/windows.rs`）：

```rust
// 当前状态机（三字段）
down_since: Option<Instant>,
armed_key: Option<VKey>,
aborted: bool,

// 扩展 Chord 模式
chord_mode: bool,                    // 是否进入 Chord 模式（Alt 按住超过阈值）
chord_triggered: Option<ChordKey>,   // 已触发的二次键
chord_threshold_ms: u64,             // 配置项,默认 200ms
```

**判定逻辑**：
1. Alt `keydown` → 正常 arm，开始计时
2. **按住超过 200ms**（可配置）→ 标记 `chord_mode = true`，窗口提前出现并显示 Chord 提示
3. Chord 模式期间收到其他键 `keydown` → 匹配 Chord 动作表，触发对应动作
4. Alt `keyup` → 若 `chord_triggered.is_some()` 则不进入搜索；否则焦点到输入框

**与现有逻辑兼容**：
- 快速单击 Alt（< tap_threshold）→ 原有行为：唤起窗口，焦点到输入框
- 长按 Alt（> chord_threshold）→ 进入 Chord 模式，等待二次键
- 长按后松开且未按二次键 → 退化为正常搜索模式

**核心 2：Chord 动作注册机制**（新增 `src/domain/chord/mod.rs`）：

```rust
pub trait ChordAction: Send + Sync {
    fn id(&self) -> &'static str;
    fn key(&self) -> ChordKey;           // VK 码 + 是否需要 shift
    fn label(&self) -> LocalizableText;  // "区域截图"
    async fn execute(&self, ctx: &ChordContext) -> Result<()>;
}

pub struct ChordContext {
    pub snapshot: ContextSnapshot,       // 当前 Context 快照（含选区/剪贴板/前台）
    pub app_handle: tauri::AppHandle,    // 用于窗口操作
}

pub struct ChordRegistry {
    actions: Vec<Arc<dyn ChordAction>>,
}
```

**核心 3：Context 抓取**（进入 Chord 模式的瞬间抓）：

- Chord 模式触发时机（Alt 按住 200ms 那一刻）→ 后台 spawn 一次 Context 抓取（同 §1.1 UIA 划词 + `clipboard_text`）
- 抓取结果灌入 `ChordContext.snapshot`，`execute()` 时可用
- **为什么在这里再抓一次**：Chord 触发时用户可能刚做完选中，划词监听器可能还没来得及触发（拖拽过程中即松开）；主动抓一次做兜底
- **四域约束**（0.8.4 立）：`ChordContext.snapshot` 属 Awareness 域数据，Chord 动作是 Execution 域消费者——参数注入必须显式（走 `ExecArg::UserExplicit`），不能让动作实现无脑读 snapshot 抽参（重蹈 0.8.4 修掉的 bug）

**核心 4：唤起动作编排**：

- 窗口 show：Chord 模式检测到就立即 show（不等 keyup）
- Chord 提示条：window `shown` 事件带 `chord_mode: true` payload → 前端显示底部提示栏（列可用 Chord + label）
- 动作触发：`ChordAction::execute()` 决定是否需要保持窗口打开、切换到某个搜索状态、还是执行完就 hide
- 窗口 hide 时机：`execute()` 返回后按动作声明的 `post_action_behavior`（`hide` / `keep_open` / `switch_to_search { query }`）

**核心 5：提示 UI**：

- 前端底部状态栏：`.chord-hint-bar`，Chord 模式下展示 4 个组合键 + label + icon
- CSS：底部固定条，进入 Chord 模式时 slide-up 淡入，退出 Chord 模式（Alt keyup 且未触发）淡出
- i18n：label 走既有 `LocalizableText` 通道

### 6.6 验收标准

```bash
# 状态机基本行为
→ 快速单击 Alt → 唤起 + 焦点到输入框（保持不变）
→ 按住 Alt 300ms → 窗口显示 + 底部 Chord 提示条出现
→ 按住 Alt 300ms + A → 截图触发, 松开 Alt 后窗口 hide
→ 按住 Alt 300ms 松开（未按二次键）→ 焦点到输入框（退化）
→ 按住 Alt 期间按 F（未注册的 Chord）→ 不触发 + 提示条不消失

# Context 抓取
→ 选中一段文字后按住 Alt → Alt+Q 触发划词 → ChordContext.snapshot.selected_text 有值
→ 复制 URL 后按住 Alt → 底部提示条能显示"当前剪贴板有链接"（可选,视 UI 定案）

# 与既有热键兼容
→ 按住 Alt 后按 Tab（系统 Alt+Tab）→ blink 释放,不干扰系统切换（关键回归）

# 配置生效
→ 设置页关闭 chord_enabled → 长按 Alt 只做普通唤起（不进 Chord 模式）
→ chord_threshold_ms=500 → 300ms 按住 = 普通唤起,500ms+ = Chord
```

### 6.7 产品价值

1. **肌肉记忆更强**：按住 Alt 的同时按 A/Q/C，手指不需要离开主键区
2. **跳过搜索步骤**：常用动作直接触发，不需要输入关键词
3. **扩展性极强**：后续可以加：
   - `Alt + T` 翻译选区
   - `Alt + S` 搜索选区
   - `Alt + M` 数学计算
   - `Alt + D` 词典
4. **差异化竞争**：Wox/Listary/Flow Launcher 都没有这个交互模式

### 6.8 与 0.9 AI 层的接口预留

- `Alt + Space` 语音输入：0.8.5 只做**录音 + 落盘**（wav 文件），0.9 AI Provider 到位后接语音识别
- `ChordContext.snapshot` 是 AI Function Calling 的天然入参（选区/剪贴板/前台应用 → 决定调什么 AI 能力）——但必须经 Suggestion 域产 Suggestion，不能直接喂 Execution（0.8.4 四域信任边界）
