## 二、MCP client（0.13.0）

Blink 作为 MCP client，消费生态里海量 server 提供的 tool，挂进对话窗口的 tool 池。直接用 rig 内置 `rig_core::tool::rmcp::McpTool::from_mcp_server()`，无需自建包装器。

- **配置**：用户在设置页填外部 MCP server 列表（`name / command / args / env`，stdio 模式）
- **启动**：`McpClientManager::start_all()` 拉起外部 server 子进程，握手，拉 tool 列表
- **tool 收集**：`collect_tools()` 从所有在线 server 收集 tool，按 `disabled_tools` 过滤
- **进 tool 池**：通过 `build_agent_tools(external_tools)` 工厂函数进对话窗口 agent 的 tool 池
- **故障与超时**：外部 server 崩溃 → 重试 3 次（间隔 2s），仍失败则标 Offline，不阻塞其他 server；invoke 超时由 rig Agent 错误处理返回给 AI；设置页可手动 `reconnect_server()`

## 三、token-aware context 压缩（0.13.1）

0.12.3 的 `SqliteConversationMemory` 用硬编码条数窗口（`SLIDING_WINDOW_SIZE=20`），不看 token 数。0.13.1 升级为 token 感知 + 接近上限压缩，在 `SqliteConversationMemory` 内部自建策略，不依赖 rig hook。

**token 估算**（启发式，误差 ±20%，压缩阈值留 buffer）：

| 估算方式 | 公式 | 适用 |
|---|---|---|
| 字符数 / 4（默认） | `chars / 4` | 英文为主 |
| 字符数 / 1.5（中文） | `chars / 1.5` | 中文为主 |
| 混合检测 | CJK 占比 > 30% 用中文档 | 自适应 |

**压缩策略**：`load()` 时估算当前窗口总 token，超过 `model_context_limit * 0.8` 则从最旧端逐条移出，压到 `limit * 0.7`。移出的消息归档到 FTS5（0.13.2）。移出后若窗口首条是孤立 ToolResult 则丢弃。**DB 保留完整历史不变**，`load()` 的裁剪是 in-memory 的。

**设置页**：窗口模式切换（固定条数 / token-aware 默认）+ 压缩参数配置 + 当前模型 context size 显示。

## 四、记忆 FTS5 召回（0.13.2）

当滑动窗口/token-aware 裁剪截断旧消息时，不是直接丢弃，而是归档到 FTS5 全文索引。新对话与旧消息关键词相关时，自动召回作为上下文。零嵌入模型依赖。0.14.1 将升级为向量语义召回（需嵌入模型 + zvec），两者共享归档机制和 `<memory>` 注入机制。

**FTS5 虚拟表**（sqlx 的 `libsqlite3-sys` 默认编译时启用 FTS5，零新依赖）：

```sql
CREATE VIRTUAL TABLE memory_fts USING fts5(
  content, conversation_id UNINDEXED, role UNINDEXED,
  content_hash UNINDEXED,  -- 幂等 key（FNV-1a hash）
  tokenize = 'trigram'     -- trigram 分词器，中文友好
);
```

**数据流**：
- **归档**：`load()` 时 TokenAware 裁剪移出的消息 → `archive_to_fts()`（幂等：content_hash FNV-1a 去重）
- **召回**：从最后一条 User 消息提取 query 文本 → `build_fts_or_query()`（拆词 + 过滤 <3 字符 + 双引号转义 + OR 连接）→ FTS5 MATCH 检索 → BM25 排序 → Top-K（默认 3）→ 召回的旧消息以 `<memory>` 标签注入消息列表头部

**OR 语义**：多词 query 任一命中即召回，避免长消息 AND 全命中率低的问题。删除对话时级联清理 `memory_fts`。召回消息未标注时间（`memory_fts` 表未存 `created_at`），0.14 升级时补。

## 五、Skill 约定式（0.13.3）

Skill = 约定式目录包（SKILL.md + 可选资源），通过**注入 preamble** 增强 AI 的知识与行为，**不直接执行**。对齐 agent 届通用的 SKILL.md 模式。

| 维度 | Skill（SKILL.md） | Tool / Capability / MCP tool |
|---|---|---|
| **生效方式** | 注入 preamble | 进 tool 池 |
| **执行性** | 不直接执行，AI 读了之后用现有 tool 去执行 | 直接执行，有副作用 |
| **类比** | 给 AI 看的"操作手册" | 给 AI 用的"工具箱" |

**目录发现**（多 agent 目录聚合，合并不去重，按来源开关）：

| 来源 | 路径（Windows） |
|---|---|
| Blink 自身 | `%APPDATA%\blink\skills\` |
| Claude Code | `%USERPROFILE%\.claude\skills\` |
| ZCode | `%USERPROFILE%\.zcode\skills\` |

**SKILL.md 格式**：YAML frontmatter（`name` / `description` 通用必填，`triggers` 是 Blink 扩展字段）+ Markdown body。手写 YAML 解析器，特有字段忽略不报错。

**渐进式披露**：

| 阶段 | 注入内容 | token 成本 |
|---|---|---|
| 阶段 1（常驻） | 所有 Skill 的 `name + description` 摘要 | 低（~50 token/skill） |
| 阶段 2（按需） | 命中触发条件的 Skill 的完整 SKILL.md | 中（命中才付） |

**触发判定**：关键词匹配 / 正则匹配 / 显式 `/skill <name>` 指令。无 triggers 字段的 Skill 只能靠 `/skill` 显式激活。同名时带来源消歧（如 `/skill rust-debug-workflow@claude`）。

**preamble 注入**：走 0.12.6 已铺好的 preamble 组装链路，`chat_system_prompt_with_skills()` = 基础 prompt + 分组指令 + 阶段 1 摘要 + 阶段 2 全文。preamble 字符串变化 → `hash_preamble()` 变 → AgentProvider cache miss → 重建，无需手工失效。

## 六、MCP server（0.13.4）

Blink 作为 MCP server，把自己的能力（Capability）暴露给外部 MCP client。与 0.13.0 MCP client 对称——client 让 Blink 的 AI 更强，server 让外部 AI 能用 Blink。

```
外部 MCP client（Claude Code / Cursor / 脚本）
    ↓ stdio JSON-RPC
blink mcp-server（子进程，不启动 GUI）
    ↓ rmcp ServerHandler
BlinkMcpServer
    ├─ list_tools()  →  capability_schema_to_mcp_tool() 正向投影
    ├─ call_tool()   →  CapabilityRegistry.invoke() + 审计日志（caller = "mcp_external"）
    └─ get_info()    →  server_info + instructions
```

- **安全优先**：默认不暴露任何能力，用户在设置页显式勾选后才暴露。`call_tool` 时双重校验（`new()` 过滤 + `call_tool` 再校验）
- **CapabilityResult → CallToolResult 投影**：Text → `Content::text`；Items → JSON 序列化；Blob → 文本摘要；Done → `Content::text(summary)`
- **审计日志**：复用 `ai_tool_audit` 表，新增 `caller` 字段区分 `internal`（AI tool call）和 `mcp_external`（外部 MCP client 调用）

## 七、自身 CLI 化（0.13.5）

Blink 自身成为命令行工具，让能力不限于 GUI 窗口。与 MCP server 共享「不启动 GUI、直接调后端函数」的架构。CLI 检测在 Tauri 初始化之前（`main()` 第一行），最小化 Tauri app，共享 `src/domain/` 和 `src/app/` 全部函数。

```bash
blink mcp-server                          # 作为 MCP server 运行（stdio 模式）
blink search <query> [--json]             # 应用搜索
blink run <capability> [--args JSON]      # 调用任意 Capability
blink capabilities [--json]               # 列出所有可用 Capability
blink config get <key>                    # 读取配置项
blink config set <key> <value>            # 写入配置项
blink chat [--model <id>]                 # 终端对话（当前输出引导提示）
```

## 八、0.13.6 体验增强（MCP 导入 + Skill 交互 + 记忆可视化 + CLI 识别）

0.13 基础设施完成后，实际使用中暴露的体验缺口补全。详见 [0.13.6 详细设计](0.13.6-mcp-skill-memory-optimization.md)。

### 8.1 MCP 导入增强

- **多协议支持**：`McpTransport` enum（`Stdio` + `Http { url, headers }`），`try_connect()` 按 transport 分派。HTTP 模式用 rmcp `StreamableHttpClientTransportConfig` + custom headers，Cargo.toml 启用 `transport-streamable-http-client-reqwest` 特性
- **跨 Agent 配置导入**：`McpImportSource` enum 支持 Claude Desktop / Claude Code / Cursor / Windsurf / VS Code + 通用 JSON。`parse_external_mcp_config()` 纯函数解析各格式（VS Code 用 `mcp.servers`，Claude Code 支持 `type: sse/http`），`detect_config_file_path()` 自动探测配置文件
- **JSON 一键导入**：`detect_mcp_config_file` / `import_mcp_from_agent` / `import_mcp_from_json` / `batch_import_mcp_servers` 命令，按 `name` 去重，支持覆盖/跳过策略
- **导入后启停管理**：`batch_set_mcp_enabled` 批量启停，导入只写配置不自动拉起子进程

### 8.2 Skill 导入工作流 + 粒度开关

- **导入**：`import_skill` 命令支持软链接（`std::os::windows::fs::symlink_dir`）和复制两种模式，软链接失败自动降级为 Copy 并提示开启开发者模式
- **粒度开关**：`SkillConfig.disabled_skills` 存储 `name@source` 格式的禁用列表，`summaries()` / `match_triggers()` 过滤禁用 Skill，`all_with_status()` 返回带 `disabled` 标记的列表
- **设置页 UI**：每个 Skill 卡片含复选框（启用/禁用）+ `[导入到 Blink]`（非 Blink 来源）+ `[打开目录]` + 来源标签

### 8.3 记忆策略 UI 对齐 + 上下文窗口指示器

- **设置页样式对齐**：「当前模型上下文窗口」统一为只读数值显示框（`number-input-readonly`），与 `number-input-wrapper` 等宽
- **上下文窗口占用指示器**：composer bar 右侧 SVG 环形进度条，颜色随占比变化（灰 → 黄 → 红），hover 显示 token 明细，压缩触发时显示 ⚡ 标记。`ContextWindowStatus` struct 含 `estimated_tokens / context_limit / usage_percent / last_compressed / last_compressed_count / last_recall_count`
- **数据流**：`load_with_stats()` 返回 `MemoryLoadResult { messages, dropped_count, recall_count }`，`compute_context_status()` 在每次 prompt 前计算并 emit `blink://chat-context-status` 事件
- **主动压缩提示**：token 占用 >80% 时在 composer bar 上方显示可关闭提示条（立即压缩 / 清除对话）

### 8.4 聊天窗口 Skill/MCP 展现优化

- **Skill 激活 Signal**：`resolve_skill_triggers()` 完成后 emit `blink://chat-skill-activated`，前端渲染 IM 式居中 Signal（🎯 显式 / 🔍 自动）
- **MCP 工具卡片增强**：`McpToolSource { tool_name, server_name, transport }`，卡片左边框紫色 + MCP 徽章 + server 名 + transport tooltip
- **记忆召回展示**：`finalizeDone()` 时若 `lastRecallCount > 0`，在 assistant 消息 footer 渲染 `🧠 N 条记忆` badge

### 8.5 CLI 能力识别

纯文本解析，零 LLM 依赖。运行 `<cli> --help` → 启发式解析（子命令 = 行首 2+ 空格 + 单词 + 2+ 空格 + 描述；选项 = `-x, --xxx` + 2+ 空格 + 描述；Usage 行提取）→ 生成 SKILL.md 模板 → 保存到 `%APPDATA%\blink\skills\<tool>\SKILL.md`。与 0.14 AI 生成 Skill 的区别：0.13.6 纯文本解析生成半成品模板，0.14 用 LLM 理解语义生成精准 SKILL.md。

### 8.6 工具卡片类型体系

| 能力类型 | 卡片样式 | 来源标记 | 特殊元素 |
|---|---|---|---|
| 内置 Capability/Action | 默认卡片 | 无标记 | — |
| MCP tool (stdio/http) | 左边框紫色 | MCP 徽章 + server 名 | tooltip: 协议类型 |
| Skill 激活 | Signal 消息 | 🧩 图标 | 激活类型（显式/自动） |
| 记忆召回 | footer 徽章 | 🧠 图标 | 召回条数 |
| 上下文压缩 | 环形指示器 ⚡ | — | 压缩条数 |

## 九、架构优化（顺带清理的债务）

- **统一路径 helper**（`src/infra/utils/paths.rs`）：`%APPDATA%\blink\` 路径获取散落 7+ 处，同一逻辑多份拷贝。抽出统一入口（`app_data_dir()` / `logs_dir()` / `skills_global_dir()` / `python_dir()` / `db_path()`），全项目迁移，`builtin.rs` 大写 B bug 已修复。
- **CapabilityTool.is_dangerous() 读取 sensitive**：`is_dangerous()` 改为 `danger_class == Dangerous || schema.sensitive`，`sensitive` 字段不再死字段。
- **build_agent_tools 扩展 external_tools 入口**：`build_agent_tools` 签名扩展 `external_tools: &[Box<dyn ToolDyn>]` 参数，MCP tool 从此入口进池。
