## 二、两个目标

| | G1 主窗口语音输入 | G2 语音输入法上屏 |
|---|---|---|
| 触发 | tap → 再 hold | hold（无先验 tap） |
| 文字去向 | blink `#query` | 外部前台应用光标处 |
| 流式展示 | 更新 #query | mini overlay 显示 partial |
| 复用 | `chord-fill-query` 链路 | 注入通道 + overlay |

**Hold 判定**：keydown 后起 `SetTimer`，超阈值（~300ms）发 `Hold`，keyup 时若已 fire 发 `HoldRelease`，否则取消 timer 发 `Tap`。

## 三、STT 选型（FunASR）

### 接入形态

- **云端**：OpenAI 兼容 API（`/v1/audio/transcriptions`），供应商 OpenAI / Groq / 小米 Mimo / 自定义。Mimo 走 `chat/completions` + base64 data-URI，其他走标准 multipart。
- **本地**：Blink 自管理 Python 3.12 环境（uv），运行自定义 `blink_stt_server.py`。
- **伪流式**（默认）：hold 期间 VAD 切句 + 累积预览，非自回归 SenseVoice 多次 HTTP 识别。
- **非流式**：hold → 松开 → 一次性 HTTP 识别。

### 模型

| 模型 | 用途 | 体积 | CER | CPU 速度 | 标识 |
|---|---|---|---|---|---|
| **SenseVoice-Small** ⭐ | 伪流式 / 非流式 | ~234MB | **7.81%** | **17×** | `iic/SenseVoiceSmall` |
| **Paraformer-zh (Seaco)** | 非流式（原生热词） | ~880MB+1.1GB | 7.81% | 15× | `paraformer-zh` |

> **为什么默认用 SenseVoice？** 五语种 ASR（中/英/日/韩/粤），非自回归（一次前向出全文，推理快 2-3 倍），自带标点 + ITN + 情感标签，体积小 CPU 友好。伪流式通过 Rust 侧 VAD + 定时预览实现"边说边出字"，不需要模型本身支持流式。

### Python 环境自管理（uv）

Blink 通过 uv 自管理 `%APPDATA%\blink\python\venv\`，用户零手动操作。`--torch-backend=auto` 自动检测 CUDA 选择 PyTorch 变体。进度流式输出到设置页日志窗口。

### 统一服务：`blink_stt_server.py`

自定义 Python server 替换官方 `funasr-server`，仅支持非流式 HTTP + 增强参数：

```
blink_stt_server.py（Blink venv 中，随 Rust 二进制发布）
  ├── POST /v1/audio/transcriptions  ← 非流式（SenseVoice / SeacoParaformer）+ 热词/ITN
  ├── GET  /health                    ← 健康检查（含 model_status: idle/loading/ready/error）
  └── GET  /v1/models                 ← 模型列表
```

HTTP 端点兼容官方 `funasr-server`，`LocalSttEngine` 和 `PseudoStreamingSttEngine` 无需修改。

**文本后处理**（Python server 端统一处理，Rust 侧不再重复）：

| 处理 | 说明 |
|---|---|
| `rich_transcription_postprocess` | 去除 SenseVoice 元数据标签（`<\|zh\|><\|NEUTRAL\|>` 等） |
| Emoji 过滤 | 去除 SenseVoice 幻觉的 emoji（😊😄 等） |
| 事件描述过滤 | 去除 `(大笑)(掌声)` 等非语音事件标签 |
| CJK 空格清理 | 去除 Paraformer 字符级 tokenizer 的字间空格 |

**FunASR 增强参数**（官方 server 未暴露）：`hotword`（热词列表，前端逗号分隔、写入时自动转换行格式，每项 `词 权重`）、`use_itn`（ITN 逆文本归一化，"二零二四年" → "2024年"）。

## 四、伪流式设计（VAD 切句 + 累积预览）

伪流式在非自回归的 SenseVoice 上实现"边说边出字"体感，无需模型本身支持流式。每 500ms 对累积音频做一次 HTTP 识别返回预览，VAD 检测到句尾时对本句音频做定稿识别。0.5s 出预览，句尾 ~80-200ms 出定稿。

### 架构

```text
hold 开始
  ├── 音频采集线程（cpal ~10ms/chunk）
  │     ├── compute_rms() → voice-level 事件（波形动画）
  │     └── VAD 检测（能量阈值 + 静默时长 + 最小句长）
  │           ├── 检测到句尾 → 本句音频范围 → spawn 定稿识别（后台 HTTP）
  │           └── 每 500ms → 未确认音频 → spawn 预览识别（后台 HTTP）
  ↓
  PseudoInner（Arc<Mutex>）
  ├── confirmed_sentences: Vec<String>  ← 已定稿句子
  ├── latest_preview: String            ← 最新预览文本
  ├── pending_confirmed: Option<String> ← 定稿 task 完成后的待收取结果
  ├── preview_generation: u64           ← 代际计数器（防重复影子）
  └── preview_in_flight / finalize_in_flight  ← 并发控制
  ↓
  transcribe_chunk 返回 JSON: {"confirmed":"...","preview":"..."}
  ↓
  voice.rs → emit blink://voice-partial（confirmed + preview 分离）
  ↓
  holdRelease → finalize()
  ├── 定稿剩余未确认音频
  ├── 等待 in_flight 请求（最多 3s）
  └── 收取 pending_confirmed → 拼接 final text
```

### 关键设计

| 设计 | 说明 |
|---|---|
| **VAD 切句定稿** | 能量 VAD（纯 Rust，无神经网络）检测停顿触发句尾定稿。参数可配置：`silence_threshold`（RMS 阈值，默认 0.005）、`min_silence_ms`（静默时长，默认 300ms）、`min_sentence_ms`（最小句长，默认 800ms）。 |
| **累积预览** | 每 500ms 对未确认音频做 HTTP 识别返回预览（灰色半透明）。累积超 8s 自动降频到 1s。 |
| **代际防影子** | VAD 句尾时递增 `preview_generation`，in-flight 的旧预览返回时校验代际不匹配则丢弃，避免预览包含已定稿内容造成重复影子。 |
| **尾部静音裁剪** | 识别前裁剪尾部静音 + 150ms 缓冲，减少 SenseVoice 幻觉英文语气词（`trim_trailing_silence`）。 |
| **语气词剥离** | 文本包含中文时循环剥离尾部英文语气词（Yeah./Okay./Mm. 等），纯英文不剥离（`strip_filler_words`）。 |
| **前缀去重** | 预览文本如以 confirmed 为前缀则剥离（`strip_confirmed_prefix`，50% 阈值避免误剥离短公共前缀）。 |
| **并发安全** | `Arc<std::sync::Mutex>` 保护内部状态。后台 HTTP task clone Arc 完成后短暂加锁写入。`transcribe_chunk` 不跨 await 持有锁。 |

### 与真流式对比（0.10.4 移除依据）

| | 真流式（WebSocket） | 伪流式（HTTP 轮询）⭐ |
|---|---|---|
| 准确率 | 较差（流式模型不如非流式） | 更好（SenseVoice 非流式） |
| 标点 | 无标点 | 有标点（自带） |
| 模型体积 | ~1.4GB（Paraformer-streaming） | ~234MB（SenseVoice） |
| CPU | 15× 实时 | 17× 实时 |
| Python 改动 | 需 WebSocket server | 零改动（HTTP 不变） |
| 复杂度 | WS 连接管理 + 重连 + 心跳 | 简单 HTTP 请求 |

## 五、文本注入通道

### 当前实现（0.10.3 起默认）

`inject_text()` 始终走 **SendInput Unicode**（`KEYEVENTF_UNICODE` 逐字符发送 `WM_CHAR`，不碰剪贴板），失败时自动降级到 **Clipboard+Ctrl+V**。无需用户配置——自动降级覆盖所有兼容性场景。

| 方案 | 流式展示 | 最终注入 | 剪贴板 |
|---|---|---|---|
| SendInput Unicode（默认） | mini overlay 显示 partial | `KEYEVENTF_UNICODE` 逐字符 | ✅ 不碰 |
| Clipboard+Ctrl+V（降级） | mini overlay 显示 partial | 剪贴板 + SendInput(Ctrl+V) | ❌ 污染（备份+恢复） |

### 废弃方案

- **0.10.5.1 TSF Composition**：`ITfThreadMgr::GetFocus()` 是进程本地的，Blink 拿不到前台应用的编辑上下文，跨进程时 TSF 路径静默失败退化成 SendInput。要真正跨进程以"输入法"身份注入需注册 TSF TIP（COM DLL + 注册表 + 用户启用），对一次性上屏场景过重。imekit 依赖与 TSF 实现已移除。

- **0.10.5.2 hook 吞键**：吞 Alt keyup 会污染 `GetKeyState(VK_MENU)` 全局状态，导致 Alt+Tab 异常、应用菜单栏闪烁等不可控副作用。条件再精确，吞掉的瞬间 Alt 状态就是错的。hook 恢复"全程放行，绝不吞键"。改为通过 `VOICE_RECORDING` 标志让 chord 判定逻辑感知录音状态。

### G2 焦点恢复

录音开始时保存前台 HWND（`prev_fg_hwnd`），finalize 期间焦点可能漂移，注入前先 `restore_foreground(hwnd)` + sleep 50ms 再注入，提升 Ctrl+V 成功率。

## 六、服务管理

### 启动流程（`start_funasr_server`）

```text
1. ServerStartParams::from_config()
   ├── ensure_server_script()  ← 释放 blink_stt_server.py
   └── write_hotwords_file()   ← 热词写为 hotwords.txt
2. 检查 Python 环境 → 未就绪自动 setup_with_progress()
3. funasr::start_server()
   ├── is_server_ready() 快速预检
   ├── spawn python blink_stt_server.py --model ... --port ... --device ...
   ├── 管道死锁防范：spawn 两个 task 持续读 stdout/stderr
   └── 返回 (child, log_rx)
4. 转发日志到前端 blink://funasr-server-log
5. spawn 就绪检测 task（带子进程退出检测）
   ├── 轮询 GET /health 的 model_status
   ├── idle/loading → emit loading_model
   ├── ready → emit ready
   └── error / 子进程退出 → emit error
```

**启动超时**：300s（首次需下载 ~234MB 模型）。**管道死锁防范**：子进程 stdout/stderr 设为 piped 但必须持续读取（Windows 管道缓冲 ~4KB），否则子进程会永久阻塞在 write 上。

### 配置（SttConfig）

| 字段 | 说明 |
|---|---|
| `enabled` | 语音总开关（默认关） |
| `mode` | Cloud / Local |
| `cloud_provider` | 云端供应商（kind / model_id / base_url） |
| `local_engine.server_port` | funasr-server 端口（默认 8000） |
| `local_engine.funasr_model` | 模型标识（`iic/SenseVoiceSmall`） |
| `local_engine.device` | 推理设备（cpu / cuda） |
| `local_engine.hotwords` | 热词（逗号分隔，写为 hotwords.txt） |
| `local_engine.use_itn` | ITN（默认 true） |
| `local_engine.vad` | VAD 切句参数（silence_threshold / min_silence_ms / min_sentence_ms，均可配） |
| `local_engine.auto_start_server` | Blink 启动后懒加载（延迟 3s） |
| `audio_device_id` | cpal 设备名（None = 系统默认） |
| `streaming_mode` | Pseudo（默认）/ Off |
| `local_model_id` | 模型注册表 id（如 `sensevoice-small`） |

> **兼容性**：旧配置中的 `streaming: bool` 和 `streaming_mode: "true"`（真流式）自动迁移为 `Pseudo`。旧 `streaming_model` 字段保留仅为反序列化兼容。旧模型名 `paraformer-zh-streaming` 自动归一化为 `iic/SenseVoiceSmall`。

## 八、P0 不回归保证

| 新增物 | 威胁 | 保证 |
|---|---|---|
| Python 子进程 | 启动加载若进热路径 | lazy-link，进程启动不加载 STT |

## 十、0.10.7 — Chord 交互统一化（已实现）

> **背景**：0.10.5 收尾后，chord 交互存在四块历史欠账——
> 1. **chord 键位硬编码**：`ChordAction::key()` 返回固定字符（`' '`/`'a'`/`'c'`），前端 `keyboard.js` 的 `CHORD_KEYS = new Set(["a","c"])` 也硬编码，设置页无法改键。
> 2. **G1 语音 chord 开关失效**：`VoiceInputAction` 是 display-only 条目，Alt+Space 触发走 native hotkey 的 hold 状态机（`HotkeyEvent::Hold → start_recording`），而 `start_recording` 只检查 `SttConfig.enabled`，不检查 `chord_enabled` 或 `disabled_chord_actions`。设置页关掉 voice_input 开关只是不显示提示，**Alt+Space 仍能触发录音**。
> 3. **chord 模式被其他软件抢键**：hook 全程放行不吞键（0.10.5.2 教训），其他应用注册的 Alt+A 全局热键会抢先，导致 chord 触发失败。
> 4. **chord 设置页简陋 + 剪贴板配置未暴露**：只能总开关 + 提示可见性 + 动作开关；`ClipboardConfig` 的 `retention_days` / `max_items` / `blacklist_keywords` 设置页未暴露。
>
> **目标**：把语音输入纳入 chord 交互统一治理，补齐键位可配置 / 主窗 Alt 独占 / 设置页展开式配置三块欠账，同时保持「不吞键」铁则与四域架构不变。

### 10.1 需求拆解

| # | 需求 | 现状 | 目标 |
|---|---|---|---|
| R1 | 语音输入可抽成 chord 快捷键 | `VoiceInputAction` display-only，触发走 hotkey hook 硬编码 Alt+Space | chord 配置统一描述，voice_input 作为 `semantic=hold` 的普通 chord |
| R2 | chord 快捷键提供热键设置 | 键位硬编码在 Rust 注册表 + 前端 `CHORD_KEYS` | 每个 chord 动作可在设置页录制改键 |

| R4 | chord 设置页可展开配置 | 只有总开关 + 提示可见性 + 动作开关 | 每个 chord 动作行可展开：键位录制 + 启用开关 + 动作专属配置（如剪贴板保留天数） |

### 10.2 方案设计

#### 一、chord 键位配置化（R2）

**配置分片扩展**（`app.chord` KV）：

```rust
pub struct ChordConfig {
    pub chord_enabled: bool,
    pub chord_hint_visible: bool,
    #[serde(default)]
    pub bindings: ChordBindings,  // 新增
}

pub struct ChordBindings {
    #[serde(default)]
    pub voice_input: ChordBinding,
    #[serde(default)]
    pub screenshot: ChordBinding,
    #[serde(default)]
    pub clipboard_history: ChordBinding,
}

pub struct ChordBinding {
    pub key: String,           // " " / "a" / "c" / ...
    pub modifiers: Vec<String>, // ["alt"]
    pub semantic: ChordSemantic,
}

pub enum ChordSemantic {
    Tap,   // 瞬间触发（截图 / 剪贴板）
    Hold,  // 长按触发（语音录音）
}
```

**默认值**保持现状键位（voice_input=`' '`+hold / screenshot=`'a'`+tap / clipboard_history=`'c'`+tap）。旧 `ChordConfig` 缺 `bindings` 字段时 serde default 兜底，老配置零迁移。

**`ChordAction` trait 调整**：
- `key()` → `default_key()`：返回默认键，仅用于配置缺失兜底 + 设置页"恢复默认"。
- 新增 `default_semantic() -> ChordSemantic`。
- 注册表 `list` / `list_all` / `trigger` / `action_id_for_key` 都改为先读 `ChordConfig.bindings`，配置缺失才回落 `default_key()`。

**前端 `keyboard.js` 改造**：
- 删除硬编码 `CHORD_KEYS = new Set(["a","c"])`。
- `chord.refresh()` 拉取的 `chordActions` 已含 `key` + `semantic` 字段，`onChordTrigger` 改为遍历 `chordActions` 匹配 `e.key`，且只触发 `semantic == "tap"` 的动作。
- `semantic == "hold"` 的动作（语音）不从前端 keydown 触发，由 hotkey hook 处理（见 §10.2 二）。

#### 二、语音 chord 化（R1 + R6）

**核心改动**：`VoiceInputAction` 从 display-only 升级为 `semantic=hold` 的真 chord action。Alt+Space 不再由 hotkey hook 硬编码识别，而是 hook 读 chord 配置判断。

**hotkey hook 改造**（`windows.rs::ll_proc`）：
- 当前逻辑：`config.key == " " && modifiers_satisfied(config)` → arm → hold timer → `HotkeyEvent::Hold`。
- 新逻辑：hold 事件触发时，先查 chord 配置——若当前主键+修饰键匹配某个 `semantic=hold` 的 chord binding，且该 chord 未被 disable，则发 `HotkeyEvent::Hold`（语音录音）；否则保持原 tap/hold 行为（主热键 toggle 主窗）。
- **关键**：主热键（Alt+Space）和 hold-语义 chord（voice_input）共享同一个物理键，通过 chord 配置统一描述。不再有"Alt+Space 由 native hotkey 处理"的特殊分支——它就是 voice_input chord 的物理实现。

**`start_recording` 增加门禁**：
```rust
pub async fn start_recording(&self) {
    // ── 总开关检查 ──
    let stt_config = crate::app::stt_config::get_stt_config();
    if !stt_config.enabled { return; }

    // ── 0.10.7 新增：chord 门禁 ──
    let pool = self.app.state::<sqlx::SqlitePool>().inner().clone();
    let chord_cfg = crate::app::config::get_config(&pool).await;
    if !chord_cfg.chord_enabled { return; }  // chord 总开关
    if chord_cfg.disabled_chord_actions.iter().any(|d| d == "voice_input") {
        return;  // voice_input chord 被禁用
    }
    // ... 后续逻辑不变
}
```

**架构统一收益**：
- 语音不再是"特殊 chord"，而是 `semantic=hold` 的普通 chord。
- chord 总开关 / disabled 列表 / 键位配置对所有 chord（含语音）统一生效。
- 设置页关掉 voice_input chord 开关 → Alt+Space 真正不触发录音（R6 达成）。

#### 三、主窗 Alt 独占——hook 条件吞键（R3）

**方案**：主窗可见 + Alt 按住 + `chordEligible()` 期间，LL hook 对 **chord 键的 keydown** 条件吞键（`return LRESULT(1)`），其他软件收不到 → Blink 独占。离开 chord 模式即恢复全程放行。

**与 0.10.5.2 回滚的本质区别**：

| | 0.10.5.2（已回滚） | 0.10.7 新方案 |
|---|---|---|
| 吞什么 | Alt **keyup** | Alt+字母的**字母 keydown** |
| 影响 `GetKeyState(VK_MENU)` | ✅ 污染（keyup 被吞 → 永远"按下"） | ❌ 不影响（Alt 的 down/up 都放行） |
| 影响 `GetAsyncKeyState(VK_MENU)` | ❌ 不影响（硬件态） | ❌ 不影响（硬件态） |
| 副作用 | Alt+Tab 异常 / 菜单栏闪烁 | 无（字母 keydown 被吞只影响前台应用，而前台就是 Blink 自己） |

**关键安全保证**：
- **绝不吞 Alt 的 keydown/keyup**——只吞 Alt+字母组合中的字母 keydown。Alt 物理态由 `GetAsyncKeyState` 读，逻辑态由 `GetKeyState` 读，两者都不受吞字母键影响。
- **现有先例**：`VOICE_RECORDING` 期间已条件吞 Space+Alt keydown（`windows.rs` line 381-390），录制期间吞 Alt+Space（line 373-375）。0.10.5.2 回滚的是"吞 Alt keyup"，不是"条件吞 keydown"。

**全局状态**（`hotkey/mod.rs`）：
```rust
/// chord 模式激活标志。前端 setAlt(true)+chordEligible 时通过 IPC 设置。
/// hook 读此标志决定是否吞 chord 键。
static CHORD_MODE: AtomicBool = AtomicBool::new(false);

/// chord 键 VK 码缓存。启动时 + 配置变更时刷新。
/// hook 是同步 C 回调，不能做 async DB 读，必须用内存缓存。
static CHORD_KEYS: RwLock<HashSet<u32>> = RwLock::new(HashSet::new());

pub fn set_chord_mode(active: bool) {
    CHORD_MODE.store(active, Ordering::SeqCst);
}
pub fn is_chord_mode() -> bool { CHORD_MODE.load(Ordering::SeqCst) }

pub fn refresh_chord_keys(keys: &[String]) {
    let vk_set: HashSet<u32> = keys.iter().filter_map(key_to_vk).collect();
    *CHORD_KEYS.write().unwrap() = vk_set;
}
```

**hook 改造**（`windows.rs::ll_proc`，在现有 tap/hold 状态机**之前**插入）：
```rust
// 0.10.7: chord 模式期间吞 chord 键 keydown，独占触发
if is_chord_mode()
    && is_down
    && !is_modifier_key(vk)          // 不吞 Alt/Ctrl/Shift 本身
    && unsafe { GetAsyncKeyState(VK_MENU.0 as i32) } < 0  // Alt 物理按下
{
    let chord_keys = get_chord_keys();  // 读 RwLock 缓存
    if chord_keys.contains(&vk) {
        // 吞键 + 发 ChordTrigger 事件（后端直接 trigger_chord）
        if let Some(key) = vk_to_key(vk) {
            send_event(HotkeyEvent::ChordTrigger(Instant::now(), key));
        }
        return LRESULT(1);  // 吞，不放行 → 其他软件收不到
    }
}
// ... 现有 tap/hold 状态机逻辑不变 ...
```

**HotkeyEvent 新增变体**：
```rust
pub enum HotkeyEvent {
    Tap(Instant),
    Hold(Instant),
    HoldRelease(Instant),
    VoiceCancel(Instant),
    ChordTrigger(Instant, String),  // 新增：chord 键被吞后触发
}
```

**service.rs 路由**：
```rust
HotkeyEvent::ChordTrigger(_, key) => {
    // 复用现有 trigger_chord 逻辑，但绕过前端 keydown（已被 hook 吞）
    let _ = crate::app::commands::trigger_chord(app.clone(), key).await;
}
```

**触发链路对比**：

| | 现有（Alt+A/C） | 0.10.7 chord 模式期间 |
|---|---|---|
| 链路 | 前端 keydown → `onChordTrigger` → `invoke("trigger_chord")` | hook 吞键 → `HotkeyEvent::ChordTrigger` → 后端直接 `trigger_chord` |
| 其他软件 | 收到 Alt+A，可能抢先 | **收不到**（被吞） |
| 前端 preventDefault | 需要 | 不需要（键没到前端） |

**hold-语义 chord（Alt+Space 语音）的处理**：
- Space 不进 `CHORD_KEYS` 缓存（hold 语义键不吞），继续走现有 tap/hold 状态机。
- chord 模式期间 Alt+Space 的 tap 语义（窗口已开时）→ no-op（不 toggle 隐藏），hold 语义 → 语音录音。
- 这样 hold 和 tap 两类 chord 互不干扰：tap chord 走吞键直达，hold chord 走状态机。

**进入/退出 chord 模式的时机**（与现有 `chord-visible` 同源）：

| 进入 | 退出 |
|---|---|
| 主窗 visible + Alt down + chordEligible() | Alt up（`is_alt_down()` 轮询检测） |
| | 主窗隐藏（ESC / toggle / 失焦） |
| | 用户开始输入（chordEligible false） |

**清除的多重兜底**（防"设了 true 没清除"导致永久吞键）：
1. 前端 `setAlt(false)` → `invoke("set_chord_mode", false)`
2. 前端 `stopAltPoll()` / `clearAlt()`（lifecycle hidden 时调）→ `setAlt(false)`
3. hook 自身兜底：`is_chord_mode()` 为 true 但 `GetAsyncKeyState(VK_MENU)` 已松开 → 不吞键（双保险）
4. 主窗失焦看门狗 → 主窗 hide → lifecycle hidden → `stopAltPoll` → `setAlt(false)`

**为何不用 RegisterHotKey**：
- `RegisterHotKey` 注册失败时无 fallback（其他软件已占用同热键）。
- hook 吞键 100% 可靠（LL hook 是最早拦截点，比任何应用级热键注册都早）。
- 不需要 `WM_HOTKEY` 消息路由，链路更短。
- **唯一代价**：更新 AGENTS.md 铁则——从"全程不吞键"细化为"chord 模式期间条件吞 chord 键 keydown，绝不吞 Alt 本身"。

| **hook 吞键的副作用** | 0.10.5.2 因吞 Alt keyup 污染 `GetKeyState` 回滚 | 新方案只吞字母 keydown，不碰 Alt 任何事件。`GetAsyncKeyState`（硬件态）和 `GetKeyState`（逻辑态）都不受影响。现有 `VOICE_RECORDING` 已有条件吞键先例，风险可控 |
| **CHORD_MODE 未清除导致永久吞键** | 若 `set_chord_mode(true)` 后清除路径全部失效，用户 Alt+字母 永久失效 | 多重兜底：①前端 `setAlt(false)` ②lifecycle hidden → `stopAltPoll` ③hook 自身检查 `GetAsyncKeyState(VK_MENU)` 已松开则不吞 ④看门狗失焦 → hide → lifecycle hidden。四重保险 |
| **hold-语义 chord 键与主热键冲突** | 主热键默认 Alt+Space，voice_input chord 默认也是 Alt+Space | 这是设计意图：主热键的 hold 语义就是语音。配置化后用户可改主热键（如 RightAlt），voice_input 仍保持 Alt+Space，两者不再冲突 |
| **chord 模式吞键的时序窗口** | Alt down → 前端 `setAlt(true)` → IPC `set_chord_mode(true)` 有 ~10-20ms 延迟，期间用户极快按 Alt+A 可能漏吞 | 可接受：①人类按 Alt 后到按字母通常 >50ms ②漏吞时 fallback 到现有前端 `onChordTrigger` 路径（不独占但仍能触发），不会"完全不工作" ③`ALT_POLL_GRACE_MS=300` 宽限期已覆盖 Alt 状态检测 |
| **剪贴板配置迁移** | `ClipboardConfig.enabled` 从 context tab 迁回 chord tab | **实际**：context tab 的 clipboard_enabled 总开关保留不动（兼容习惯），chord tab 的 clipboard_history 展开页配置详细项（max_items / retention_days / blacklist / search_enabled）。两个 tab 配合：context 管总开关，chord 管参数 |
| **hold-语义 chord 的可发现性** | 语音 chord 的 hold 语义在提示条如何展示 | 提示条已有「Alt+Space 语音输入」展示，保持不变。设置页展开后额外标注「语义: 长按」 |
| **AGENTS.md 铁则更新** | "热键不吞键"铁则需要细化 | 改为"hook 全程放行 Alt 修饰键本身；chord 模式期间条件吞 chord 键 keydown（非修饰键），离开模式即恢复"。这是对铁则的精确化，不是放松 |
