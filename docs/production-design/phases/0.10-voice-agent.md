## 三、STT 选型（FunASR）

### 接入形态

- **云端**：OpenAI 兼容 API（`/v1/audio/transcriptions`），供应商精简为 OpenAI / Groq / 自定义（任何 OpenAI 兼容端点）。
- **本地**：Blink 自管理 Python 3.12 环境（uv），运行自定义 `blink_stt_server.py`。
- **伪流式**（默认）：hold 期间 VAD 切句 + 累积预览，非自回归 SenseVoice 多次 HTTP 识别。
- **非流式**：hold → 松开 → 一次性 HTTP 识别。

### 模型

| 模型 | 用途 | 体积 | CER | CPU 速度 | 标识 |
|---|---|---|---|---|---|
| **SenseVoice-Small** ⭐ | 伪流式 / 非流式 | ~234MB | **7.81%** | **17×** | `iic/SenseVoiceSmall` |
| **Paraformer-zh (Seaco)** | 非流式（原生热词） | ~880MB+1.1GB | 7.81% | 15× | `paraformer-zh` |

> **为什么默认用 SenseVoice？** 五语种 ASR（中/英/日/韩/粤），非自回归（一次前向出全文，推理快 2-3 倍），自带标点 + ITN + 情感标签，体积小 CPU 友好。伪流式通过 Rust 侧 VAD + 定时预览实现"边说边出字"，不需要模型本身支持流式。

### Python 环境自管理（uv）

Blink 通过 uv 自管理 `%APPDATA%\blink\python\venv\`，用户零手动操作。`--torch-backend=auto` 自动检测 CUDA 选择 PyTorch 变体。进度流式输出到设置页日志窗口。

### 统一服务：`blink_stt_server.py`

自定义 Python server 替换官方 `funasr-server`，仅支持非流式 HTTP + 增强参数：

```
blink_stt_server.py（Blink venv 中，随 Rust 二进制发布）
  ├── POST /v1/audio/transcriptions  ← 非流式（SenseVoice / SeacoParaformer）+ 热词/ITN
  ├── GET  /health                    ← 健康检查
  └── GET  /v1/models                 ← 模型列表
```

HTTP 端点兼容官方 `funasr-server`，`LocalSttEngine` 和 `is_server_ready_http()` 无需修改。

**文本后处理**（Python server 端统一处理，Rust 侧不再重复）：

| 处理 | 说明 |
|---|---|
| `rich_transcription_postprocess` | 去除 SenseVoice 元数据标签（`<\|zh\|><\|NEUTRAL\|>` 等） |
| Emoji 过滤 | 去除 SenseVoice 幻觉的 emoji（😊😄 等） |
| 事件描述过滤 | 去除 `(大笑)(掌声)` 等非语音事件标签 |
| CJK 空格清理 | 去除 Paraformer 字符级 tokenizer 的字间空格 |

**FunASR 增强参数**（官方 server 未暴露）：`hotword`（热词列表，每行 `词 权重`，存为 `hotwords.txt`）、`use_itn`（ITN 逆文本归一化，"二零二四年" → "2024年"）。

## 四、伪流式设计（VAD 切句 + 累积预览）

伪流式在非自回归的 SenseVoice 上实现"边说边出字"体感，无需模型本身支持流式。每 500ms 对累积音频做一次 HTTP 识别返回预览，VAD 检测到句尾时对本句音频做定稿识别。0.5s 出预览，句尾 ~80-200ms 出定稿。

### 架构

```text
hold 开始
  ├── 音频采集线程（cpal ~10ms/chunk）
  │     ├── compute_rms() → voice-level 事件（波形动画）
  │     └── VAD 检测（能量阈值 + 静默时长）
  │           ├── 检测到句尾 → 本句音频 → HTTP POST → confirmed 文本
  │           └── 无句尾 → 每 500ms 累积音频 → HTTP POST → 预览文本
  ├── emit "blink://voice-partial" { confirmed, preview }
  └── release → finalize()：定稿剩余音频 + 拼接 confirmed + 最后 preview
```

### VAD 切句（Rust 侧纯能量 VAD）

不需要 fsmn-vad——只需要知道"用户停顿了"。基于 RMS 能量 + 静默时长判定，每个 ~10ms chunk 调用 `process_chunk()`，返回 `VadEvent::SentenceEnd`。

| 参数 | 默认值 | 调优方向 |
|---|---|---|
| `silence_threshold` | 0.005（~-46dB） | 嘈杂环境调高（0.01），安静环境调低（0.003） |
| `min_silence_ms` | 300ms | 快速口述调低（200ms），慢速思考调高（500ms） |

> 最小句子长度保护：<800ms 的声音不切句，避免短促语气词被误切。

### 关键设计

- **in_flight 原子标志**——上一轮 HTTP 未返回就跳过，不堆积请求（最多 1 个飞行请求）
- **音频快照 clone**——后台识别不阻塞音频累积，仅触发时 clone
- **超 8s 自动降频**——间隔从 500ms 拉长到 1000ms（SenseVoice CPU 17× 实时，10s 音频识别 ~590ms 会超出周期）
- **finalize 容错**——等待最多 3s，超时用已有结果
- **预览 vs 定稿**——灰色半透明区分预览文本，定稿文本不再变化

### 两种模式对比

| 维度 | 伪流式 (Pseudo) ⭐ | 非流式 (Off) |
|---|---|---|
| 首字延迟 | ~500ms（预览） | finalize 后 |
| 句尾延迟 | **~80-200ms** | — |
| 文本稳定性 | 高（定稿不变） | 最高 |
| 最佳场景 | 通用 ⭐ | 短指令 |

### SendInput Unicode 的局限



0.10.3 起，G2 文本注入走 `SendInput` + `KEYEVENTF_UNICODE`：将文本编码为 UTF-16，逐码元构造 `INPUT` 结构体发送 `WM_CHAR`，绕过剪贴板。

但 SendInput 模拟的是**硬件键盘事件**（`WM_KEYDOWN` → `WM_CHAR`），而现代 Windows 文本输入的正确管线是 **TSF**——所有 IME、语音输入、手写识别都走 TSF。应用只认 TSF 的 Composition / Commit 事件，不认裸 `WM_CHAR`。已知失败场景：

| 场景 | 根因 |
|---|---|
| Windows Terminal / cmd.exe | Console Host 不走 `WM_CHAR`，走控制台输入队列 |
| Electron 应用（VS Code 等）+ IME 激活 | Chromium 的 IME 模块把 Unicode 输入当候选词处理 |
| UWP / WinUI 3 应用 | 现代 XAML 文本控件走 TSF 管线，不直接处理 `WM_CHAR` |
| Office（Word / Outlook） | Office 有自己的 TSF 文本管线，SendInput 产出被丢弃 |
| 部分 WPF 应用 | WPF TextBox 在 IME 激活时优先处理 `WM_IME_*` 而非 `WM_CHAR` |

### ~~TSF Composition~~（0.10.5，已废弃）

> **废弃原因**：0.10.5 曾引入 imekit 做 TSF Composition 注入，实测发现核心 API
> `ITfThreadMgr::GetFocus()` 是**进程本地的**——每进程有自己的 `ITfThreadMgr`，
> `GetFocus()` 只返回本进程注册的焦点文档上下文。Blink 在自己进程创建的 TSF 管理器
> 拿不到前台应用（记事本/Word/VS Code）的 `ITfContext`，TSF 路径静默失败，最终退化
> 成 SendInput，与不引入 imekit 完全等价。要真正跨进程以"输入法"身份注入需要注册
> TSF TIP（COM DLL + 注册表 + 用户启用），对语音转文字一次性上屏场景过重。
>
> imekit 依赖、`imekit_impl.rs`、`InjectMethod::Tsf` 变体已全部移除。旧配置中的
> `"tsf"` 值自动降级为 `SendInput`。

### ~~hook 层吞键~~（0.10.6，尝试失败）

> **失败原因**：在 LL hook 的 arm 场景吞掉 Space keydown 能阻止 Alt+Space 弹系统菜单，
> 但 Space 被吞后 Windows 判定 Alt keydown→keyup 期间无其他键到达应用 → 触发 Alt tap
> 激活菜单栏。补上"条件吞 Alt keyup"（复用 `aborted` 标志判断 arm 期间无其他键时才吞）
> 理论上能从源头阻止系统菜单和菜单栏激活，但实测发现**吞 Alt keyup 会动到用户的 Alt 键**，
> 导致 Alt 修饰键状态紊乱、Alt+Tab 异常、部分应用菜单栏反复闪烁等不可控副作用。
>
> **根因**：Alt 是系统级修饰键，吞掉 keyup 等于告诉系统"Alt 还按着"或"Alt 没松开"，
> 会污染 `GetKeyState(VK_MENU)` / `GetAsyncKeyState(VK_MENU)` 的全局状态，
> 影响所有依赖 Alt 状态的系统和应用行为。这不是"条件吞"能规避的——条件再精确，
> 吞掉的瞬间 Alt 状态就是错的。
>
> 代码已回滚。hook 恢复"全程放行，绝不吞键"。

### 焦点恢复

`finalize()` 是 async HTTP（1-3s），期间前台焦点可能漂移。注入前保存的 HWND → `restore_foreground`（Alt 欺骗 + `SetForegroundWindow`）→ 等 50ms 再注入。

## 六、配置

`SttConfig` 配置分片（`ConfigKey::KEY = "stt:config"`），与 `AIConfig` 同级独立 opt-in。复用 AIConfig 的 Credential Manager 体系（云端 STT 的 API Key 存在 CM 里，secret_ref 约定 `stt:{provider_kind}`）。

```rust
pub struct SttConfig {
    pub enabled: bool,                     // 总开关（默认关）
    pub mode: SttMode,                     // Cloud / Local
    pub cloud_provider: Option<SttCloudProvider>,
    pub local_engine: LocalEngineConfig,
    pub local_model_id: Option<String>,    // 模型注册表 id（如 "sensevoice-small"）
    pub audio_device_id: Option<String>,   // cpal 设备名
    pub streaming_mode: StreamingMode,     // Pseudo（默认）/ Off
    pub inject_method: InjectMethod,        // G2 注入方式（默认 SendInput）
}

pub struct LocalEngineConfig {
    pub server_port: u16,                  // 默认 8000
    pub funasr_model: String,             // 模型标识（"iic/SenseVoiceSmall"）
    pub device: String,                   // "cpu" / "cuda"
    pub num_threads: Option<u32>,         // CPU 线程数（None = 自动）
    pub hotwords: Option<String>,          // 热词列表
    pub use_itn: bool,                    // ITN（默认 true）
    pub auto_start_server: bool,          // Blink 启动后懒加载
}
```

> **兼容性**：旧配置中的 `streaming: bool` 和 `streaming_mode: "true"`（真流式）自动迁移为 `Pseudo`。旧 `streaming_model` 字段保留仅为反序列化兼容。旧模型名 `paraformer-zh-streaming` 自动归一化为 `iic/SenseVoiceSmall`，短名 `sensevoice` 归一化为完整 ModelScope ID。

> **Mock 安全**：`create_engine()` 不再回退 Mock 引擎——未启用 / 未配置 / 服务未就绪时返回 `Err`，由 `VoiceService::emit_voice_error()` 向用户反馈。Mock 仅在 `#[cfg(test)]` 中可用。

## 九、P0 不回归保证

| 新增物 | 威胁 | 保证 |
|---|---|---|
| Python 子进程 | 启动加载若进热路径 | lazy-link，进程启动不加载 STT |
| ~230MB 模型 | 撑爆 <300MB 预算 | lazy-load，按需下载 |
| 麦克风采集线程 | 阻塞 LL hook | 独立线程，绝不进 hook |
| Hold timer | timer 阻塞 hook | timer 仅发事件，不执行逻辑 |
| G2 文本注入 | 触发失焦隐藏 | G2 时主窗不显示，注入不抢前台 |
| 后台 HTTP 识别 task | 阻塞音频采集 | tokio::spawn 独立 task，不阻塞 transcribe_chunk |
| in_flight 并发请求 | Python server 过载 | 原子标志守卫，最多 1 个飞行请求 |
| VAD 误判 | 句子被切断 | 静默阈值可配 + 最小句子长度保护（<800ms 不切） |
