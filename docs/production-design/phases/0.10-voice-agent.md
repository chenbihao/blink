## 一、两个目标

| | G1 主窗口语音输入 | G2 语音输入法上屏 |
|---|---|---|
| 触发 | tap → 再 hold | hold（无先验 tap） |
| 文字去向 | blink `#query` | 外部前台应用光标处 |
| 流式展示 | 更新 #query | mini overlay 显示 partial |
| 复用 | `chord-fill-query` 链路 | 注入通道 + overlay |

**Hold 判定**：keydown 后起 `SetTimer`，超阈值(~300ms)发 `Hold`，keyup 时若已 fire 发 `HoldRelease`，否则取消 timer 发 `Tap`。

## 二、STT 选型（FunASR）

### 接入形态

- **云端**：OpenAI 兼容 API（`/v1/audio/transcriptions`），7 家供应商。
- **本地**：Blink 自管理 Python 3.12 环境（uv），运行自定义 `blink_stt_server.py`。
- **非流式**：hold → 松开 → 一次性 HTTP 识别（SenseVoice）。
- **真流式**（0.10.3）：hold 期间 WebSocket 边说边出 partial text（Paraformer-streaming）。
- **伪流式**（0.10.4）：hold 期间 VAD 切句 + 累积预览，非自回归 SenseVoice 多次 HTTP 识别。

### 模型

| 模型 | 用途 | 流式 | 体积 | CER | CPU 速度 | 标识 |
|---|---|---|---|---|---|---|
| **SenseVoice-Small** ⭐ | 非流式 / 伪流式 | ❌ | ~234MB | **7.81%** | **17×** | `sensevoice` |
| **Paraformer-zh-streaming** | 真流式 | ✅ | ~880MB | 10.18% | 15× | `paraformer-zh-streaming` |

> 两模型 lazy load，互不占用内存。非流式请求不加载 streaming 模型，反之亦然。
>
> **为什么伪流式用 SenseVoice 而非 Paraformer-streaming？**
> - CER 更低（7.81% vs 10.18%，↓23%）
> - 非自回归（一次前向出全文），单次推理速度比自回归快 2-3 倍
> - 自带标点
> - 体积更小（234MB vs 880MB）
> - 伪流式通过 Rust 侧 VAD + 定时预览实现"边说边出字"，不需要模型本身支持流式

### Python 环境自管理（uv）

Blink 通过 uv 自管理 `%APPDATA%\blink\python\venv\`，用户零手动操作。`--torch-backend=auto` 自动检测 CUDA 选择 PyTorch 变体。进度流式输出到设置页日志窗口。

### 统一服务：`blink_stt_server.py`（0.10.3）

自定义 Python server 替换官方 `funasr-server`，统一支持非流式 + 流式 + 增强参数：

```
blink_stt_server.py（Blink venv 中，随 Rust 二进制发布）
  │
  ├── POST /v1/audio/transcriptions  ← 非流式（SenseVoice）+ 热词/ITN
  ├── WS   /ws/stream                 ← 真流式（Paraformer-streaming）
  ├── GET  /health                    ← 健康检查
  └── GET  /v1/models                 ← 模型列表
```

HTTP 端点兼容官方 `funasr-server`，`LocalSttEngine` 和 `is_server_ready_http()` 无需修改。

**FunASR 增强参数**（官方 server 未暴露）：

| 参数 | 说明 |
|---|---|
| `hotword` | 热词列表（每行 `词 权重`），存为 `hotwords.txt` |
| `use_itn` | ITN 逆文本归一化（"二零二四年" → "2024年"） |

### 方案总览

| 方案 | 剪贴板 | 流式 preedit | 状态 |
|---|---|---|---|
| Clipboard+Ctrl+V（0.10.1） | ❌ 污染 | ❌ | 回退兜底 |
| **SendInput Unicode**（0.10.3 默认） | ✅ 不碰 | ❌ | ✅ 当前 |
| TSF Composition via imekit（P1） | ✅ | ✅ | 🔜 试用 |

### SendInput Unicode（当前默认）

`SendInput` 的 `KEYEVENTF_UNICODE` flag 逐字符发送 `WM_CHAR`，绕过剪贴板：
- UTF-16 编码，代理对支持 emoji
- 换行符用 `VK_RETURN`
- 分批发送（Windows 单次上限 ~544 个 INPUT）
- 失败时回退 Clipboard+Ctrl+V

### 焦点恢复

`finalize()` 是 async HTTP（1-3s），期间前台焦点可能漂移。注入前保存的 HWND → `restore_foreground`（Alt 欺骗 + `SetForegroundWindow`）→ 等 50ms 再 SendInput。

## 十、0.10.4 伪流式设计（VAD 切句 + 累积预览）

### 10.1 背景与动机

0.10.3 的真流式（Paraformer-streaming WebSocket）解决了"边说边出字"的体感问题，但存在准确率瓶颈：

| 维度 | Paraformer-streaming | SenseVoice 非流式 |
|---|---|---|
| CER | 10.18% | **7.81%**（↓23%） |
| 标点 | ❌ 无 | ✅ 自带 |
| 体积 | ~880MB | ~234MB |

用户反馈：真流式出字快但错字多，且无法事后纠正；非流式准确但"松开后才出字"体感差。

**调研结论**：Fun-ASR-Nano 的 vLLM 流式虽然概念吸引（LLM 解码器隐式纠错 + 末尾 8 字回溯），但存在致命限制：

- vLLM **无 Windows 预编译 wheel**（全部 `manylinux_x86_64`）
- GGUF 运行时（单二进制 500MB）**不支持流式**——纯离线文件转录
- vLLM 流式 <1.5s 输出为空（官方标注），hold-to-talk 大量短句场景直接废掉
- 累积重编码架构——延迟随说话时长线性增长

**方案选择**：用非自回归的 SenseVoice 做"伪流式"——借鉴 Fun-ASR-Nano 的累积重编码思路，但用快 3 倍的非自回归模型，0.5s 就能出预览结果。加上 Rust 侧 VAD 切句，实现"句尾即出字"的干净体验。

### 10.2 架构总览

```text
hold 开始
  │
  ├── 音频采集线程（cpal ~10ms/chunk）
  │     │
  │     ├── compute_rms() → voice-level 事件（波形动画）
  │     │
  │     ├── VAD 检测（能量阈值 + 静默时长）
  │     │     │
  │     │     ├── 检测到句尾 → 触发"定稿识别"
  │     │     │     ↓ 仅本句音频 → HTTP POST → 确认文本
  │     │     │
  │     │     └── 无句尾 → 每 500ms 触发"预览识别"
  │     │           ↓ 累积全部音频 → HTTP POST → 预览文本
  │     │
  │     └── transcribe_chunk() 返回 {confirmed, preview}
  │
  ├── voice.rs emit "blink://voice-partial"
  │     payload: { confirmed: "已确认句子。", preview: "正在说的预览" }
  │
  └── release → finalize()
        ├── 定稿剩余音频
        ├── 拼接 confirmed + 最后一段 preview
        └── 返回最终文本 → inject / fill-query
```

### 10.3 VAD 切句（Rust 侧纯能量 VAD）

**不需要 fsmn-vad**。我们不需要精确的语音端点检测，只需要知道"用户停顿了"。

```rust
/// 能量 VAD：检测用户停顿，用于切句。
///
/// 基于 RMS 能量 + 静默时长判定。
/// 每个 ~10ms 音频 chunk 调用 `process_chunk()`。
pub struct EnergyVad {
    /// RMS 低于此值视为静默（默认 0.005，约 -46dB）
    silence_threshold: f64,
    /// 静默持续多久判定句尾（默认 300ms）
    min_silence_ms: u32,
    /// 当前已累积的静默样本数
    silence_samples: usize,
    /// 是否正在说话（有声）
    speaking: bool,
    /// 采样率
    sample_rate: u32,
}

impl EnergyVad {
    /// 处理一个音频 chunk，返回是否检测到句尾。
    fn process_chunk(&mut self, samples: &[f32]) -> VadEvent;
}

pub enum VadEvent {
    /// 无事件
    None,
    /// 检测到句尾（静默超过阈值）
    SentenceEnd,
}
```

**参数调优**：

| 参数 | 默认值 | 调优方向 |
|---|---|---|
| `silence_threshold` | 0.005 | 嘈杂环境调高（0.01），安静环境调低（0.003） |
| `min_silence_ms` | 300ms | 快速口述调低（200ms），慢速思考调高（500ms） |

**单测策略**：纯函数化——`process_chunk` 接收 samples 切片，返回 `VadEvent`，无 IO 依赖，可完全单元测试。

### 10.4 累积预览识别

**原理**：每 500ms 对当前累积的全部音频做一次 HTTP 识别，返回逐步完善的预览文本。

```rust
/// 累积预览管理器。
///
/// 每 preview_interval_ms 对累积音频做一次识别。
/// 使用 in_flight 原子标志避免请求堆积——
/// 上一轮 HTTP 还没回来就跳过本轮。
struct PreviewManager {
    /// 累积的音频样本
    samples: Vec<f32>,
    /// 上一次触发预览识别的时刻
    last_trigger: Instant,
    /// 预览识别间隔（默认 500ms）
    interval: Duration,
    /// 是否有识别请求在飞行中
    in_flight: Arc<AtomicBool>,
    /// 最新预览文本
    latest_preview: Arc<Mutex<String>>,
}
```

**延迟分析**（SenseVoice CPU 17× 实时）：

| 累积音频 | 识别耗时 | HTTP 开销 | 总计 | 500ms 周期内完成？ |
|---|---|---|---|---|
| 1s | ~60ms | ~20ms | ~80ms | ✅ |
| 3s | ~180ms | ~20ms | ~200ms | ✅ |
| 5s | ~300ms | ~20ms | ~320ms | ✅ |
| 8s | ~470ms | ~20ms | ~490ms | ⚠️ 刚好 |
| 10s | ~590ms | ~20ms | ~610ms | ❌ 跳过本轮 |

**关键设计**：
- `in_flight` 原子标志——上一轮 HTTP 未返回就跳过，不堆积请求
- 音频快照 clone——后台识别不阻塞音频累积
- 复用 reqwest client（避免每次建连）
- 超过 8s 时自动降频（间隔从 500ms 拉长到 1000ms）

### 10.5 句尾定稿识别

VAD 检测到句尾时，对本句音频做一次"定稿识别"：

```text
VAD 句尾事件
  ↓
取出本句音频 [sentence_start, sentence_end]
  ↓
HTTP POST → SenseVoice 识别
  ↓
返回 confirmed_text（不再变化）
  ↓
追加到 confirmed 区域
  ↓
清空 preview 区域
```

**句子边界管理**：

```rust
struct SentenceBuffer {
    /// 已定稿的句子列表
    confirmed_sentences: Vec<String>,
    /// 当前句子的起始样本索引
    current_sentence_start: usize,
}

impl SentenceBuffer {
    /// 句尾事件：取出本句音频，标记下一句起始
    fn on_sentence_end(&mut self, total_samples: usize) -> Range<usize>;

    /// 拼接所有已确认句子 + 当前预览
    fn compose(&self, preview: &str) -> String;
}
```

### 10.6 PseudoStreamingSttEngine

新建 `pseudo_streaming.rs`，实现 `SttEngine` trait：

```rust
/// 伪流式 STT 引擎。
///
/// 组合 VAD 切句 + 累积预览，在非自回归 SenseVoice 上实现"边说边出字"体感。
///
/// 与 LocalSttEngine 的关系：
/// - 复用 HTTP POST /v1/audio/transcriptions 端点
/// - 复用 wav::pcm_to_wav + wav::transcribe_async
/// - 但 transcribe_chunk 不再空转——而是驱动 VAD + 预览
///
/// 与 StreamingSttEngine（真流式）的关系：
/// - 不需要 WebSocket
/// - 不需要流式模型（用非流式 SenseVoice 即可）
/// - 靠 Rust 侧定时 HTTP 轮询实现 partial
pub struct PseudoStreamingSttEngine {
    /// VAD 切句器
    vad: Mutex<EnergyVad>,
    /// 句子缓冲管理
    sentences: Mutex<SentenceBuffer>,
    /// 累积预览管理
    preview: Mutex<PreviewManager>,
    /// HTTP 转录参数
    server_port: u16,
    funasr_model: String,
    /// 复用 HTTP client（避免每次建连）
    client: reqwest::Client,
}

#[async_trait::async_trait]
impl SttEngine for PseudoStreamingSttEngine {
    async fn transcribe_chunk(&self, samples: &[f32]) -> Result<String, SttError> {
        // 1. 累积音频
        // 2. 喂给 VAD
        // 3. VAD 句尾 → spawn 句尾定稿识别（后台 HTTP）
        // 4. 500ms 定时 → spawn 预览识别（后台 HTTP，in_flight 守卫）
        // 5. 返回 confirmed + preview 组合文本
    }

    async fn finalize(&self) -> Result<String, SttError> {
        // 1. 定稿剩余音频（finalize 识别）
        // 2. 等待所有 in_flight 请求完成（最多等 3s）
        // 3. 拼接 confirmed_sentences + 最后一段 preview
        // 4. 返回最终文本
    }

    fn reset(&self) {
        // 清空 VAD、句子缓冲、预览管理
    }
}
```

**transcribe_chunk 返回值约定**：

返回 JSON 格式字符串（而非纯文本），voice.rs 解析后分别 emit confirmed 和 preview：

```json
{
  "confirmed": "你好世界。今天天气不错。",
  "preview": "适合出去玩"
}
```

> 如果 confirmed 为空、preview 为空，返回空字符串（兼容现有 voice.rs 逻辑）。
> 如果只有 preview，返回 `{"confirmed":"","preview":"你好"}`。

### 10.7 voice.rs 适配

```rust
// voice.rs 音频采集 task 中
match engine_for_task.transcribe_chunk(&chunk.samples).await {
    Ok(text) => {
        if !text.is_empty() {
            // 尝试解析 JSON（伪流式引擎返回 confirmed + preview）
            if let Ok(v) = serde_json::from_str::<serde_json::Value>(&text) {
                let confirmed = v.get("confirmed").and_then(|t| t.as_str()).unwrap_or("");
                let preview = v.get("preview").and_then(|t| t.as_str()).unwrap_or("");
                let _ = app.emit("blink://voice-partial", serde_json::json!({
                    "confirmed": confirmed,
                    "preview": preview,
                    "target": target_str,
                }));
            } else {
                // 纯文本（真流式 / 非流式引擎的兼容路径）
                let _ = app.emit("blink://voice-partial", serde_json::json!({
                    "text": text,
                    "target": target_str,
                }));
            }
        }
    }
    Err(e) => { ... }
}
```

### 10.12 P0 不回归保证

| 新增物 | 威胁 | 保证 |
|---|---|---|
| 后台 HTTP 识别 task | 阻塞音频采集 | tokio::spawn 独立 task，不阻塞 transcribe_chunk |
| in_flight 并发请求 | Python server 过载 | 原子标志守卫，最多 1 个飞行请求 |
| 音频快照 clone | 内存翻倍 | 快照仅在触发时 clone，非每 chunk clone |
| VAD 误判 | 句子被切断 | 静默阈值可配 + 最小句子长度保护（<800ms 不切） |
| 预览文本变化 | 用户困惑 | 灰色半透明区分预览 vs 定稿 |
| finalize 时 in_flight | 请求丢失 | finalize 等待最多 3s，超时用已有结果 |
