## 二、两个目标

| | G1 主窗口语音输入 | G2 语音输入法上屏 |
|---|---|---|
| 触发 | tap → 再 hold | hold（无先验 tap） |
| 文字去向 | blink `#query` | 外部前台应用光标处 |
| 流式展示 | 更新 #query | mini overlay 显示 partial |
| 复用 | `chord-fill-query` 链路 | 注入通道 + overlay |

**Hold 判定**：keydown 后起 `SetTimer`，超阈值（~300ms）发 `Hold`，keyup 时若已 fire 发 `HoldRelease`，否则取消 timer 发 `Tap`。

## 三、STT 选型（FunASR）

### 接入形态

- **云端**：OpenAI 兼容 API（`/v1/audio/transcriptions`），供应商 OpenAI / Groq / 小米 Mimo / 自定义。Mimo 走 `chat/completions` + base64 data-URI，其他走标准 multipart。
- **本地**：Blink 自管理 Python 3.12 环境（uv），运行自定义 `blink_stt_server.py`。
- **伪流式**（默认）：hold 期间 VAD 切句 + 累积预览，非自回归 SenseVoice 多次 HTTP 识别。
- **非流式**：hold → 松开 → 一次性 HTTP 识别。

### 模型

| 模型 | 用途 | 体积 | CER | CPU 速度 | 标识 |
|---|---|---|---|---|---|
| **SenseVoice-Small** ⭐ | 伪流式 / 非流式 | ~234MB | **7.81%** | **17×** | `iic/SenseVoiceSmall` |
| **Paraformer-zh (Seaco)** | 非流式（原生热词） | ~880MB+1.1GB | 7.81% | 15× | `paraformer-zh` |

> **为什么默认用 SenseVoice？** 五语种 ASR（中/英/日/韩/粤），非自回归（一次前向出全文，推理快 2-3 倍），自带标点 + ITN + 情感标签，体积小 CPU 友好。伪流式通过 Rust 侧 VAD + 定时预览实现"边说边出字"，不需要模型本身支持流式。

### Python 环境自管理（uv）

Blink 通过 uv 自管理 `%APPDATA%\blink\python\venv\`，用户零手动操作。`--torch-backend=auto` 自动检测 CUDA 选择 PyTorch 变体。进度流式输出到设置页日志窗口。

### 统一服务：`blink_stt_server.py`

自定义 Python server 替换官方 `funasr-server`，仅支持非流式 HTTP + 增强参数：

```
blink_stt_server.py（Blink venv 中，随 Rust 二进制发布）
  ├── POST /v1/audio/transcriptions  ← 非流式（SenseVoice / SeacoParaformer）+ 热词/ITN
  ├── GET  /health                    ← 健康检查（含 model_status: idle/loading/ready/error）
  └── GET  /v1/models                 ← 模型列表
```

HTTP 端点兼容官方 `funasr-server`，`LocalSttEngine` 和 `PseudoStreamingSttEngine` 无需修改。

**文本后处理**（Python server 端统一处理，Rust 侧不再重复）：

| 处理 | 说明 |
|---|---|
| `rich_transcription_postprocess` | 去除 SenseVoice 元数据标签（`<\|zh\|><\|NEUTRAL\|>` 等） |
| Emoji 过滤 | 去除 SenseVoice 幻觉的 emoji（😊😄 等） |
| 事件描述过滤 | 去除 `(大笑)(掌声)` 等非语音事件标签 |
| CJK 空格清理 | 去除 Paraformer 字符级 tokenizer 的字间空格 |

**FunASR 增强参数**（官方 server 未暴露）：`hotword`（热词列表，前端逗号分隔、写入时自动转换行格式，每项 `词 权重`）、`use_itn`（ITN 逆文本归一化，"二零二四年" → "2024年"）。

## 四、伪流式设计（VAD 切句 + 累积预览）

伪流式在非自回归的 SenseVoice 上实现"边说边出字"体感，无需模型本身支持流式。每 500ms 对累积音频做一次 HTTP 识别返回预览，VAD 检测到句尾时对本句音频做定稿识别。0.5s 出预览，句尾 ~80-200ms 出定稿。

### 架构

```text
hold 开始
  ├── 音频采集线程（cpal ~10ms/chunk）
  │     ├── compute_rms() → voice-level 事件（波形动画）
  │     └── VAD 检测（能量阈值 + 静默时长 + 最小句长）
  │           ├── 检测到句尾 → 本句音频范围 → spawn 定稿识别（后台 HTTP）
  │           └── 每 500ms → 未确认音频 → spawn 预览识别（后台 HTTP）
  ↓
  PseudoInner（Arc<Mutex>）
  ├── confirmed_sentences: Vec<String>  ← 已定稿句子
  ├── latest_preview: String            ← 最新预览文本
  ├── pending_confirmed: Option<String> ← 定稿 task 完成后的待收取结果
  ├── preview_generation: u64           ← 代际计数器（防重复影子）
  └── preview_in_flight / finalize_in_flight  ← 并发控制
  ↓
  transcribe_chunk 返回 JSON: {"confirmed":"...","preview":"..."}
  ↓
  voice.rs → emit blink://voice-partial（confirmed + preview 分离）
  ↓
  holdRelease → finalize()
  ├── 定稿剩余未确认音频
  ├── 等待 in_flight 请求（最多 3s）
  └── 收取 pending_confirmed → 拼接 final text
```

### 关键设计

| 设计 | 说明 |
|---|---|
| **VAD 切句定稿** | 能量 VAD（纯 Rust，无神经网络）检测停顿触发句尾定稿。参数可配置：`silence_threshold`（RMS 阈值，默认 0.005）、`min_silence_ms`（静默时长，默认 300ms）、`min_sentence_ms`（最小句长，默认 800ms）。 |
| **累积预览** | 每 500ms 对未确认音频做 HTTP 识别返回预览（灰色半透明）。累积超 8s 自动降频到 1s。 |
| **代际防影子** | VAD 句尾时递增 `preview_generation`，in-flight 的旧预览返回时校验代际不匹配则丢弃，避免预览包含已定稿内容造成重复影子。 |
| **尾部静音裁剪** | 识别前裁剪尾部静音 + 150ms 缓冲，减少 SenseVoice 幻觉英文语气词（`trim_trailing_silence`）。 |
| **语气词剥离** | 文本包含中文时循环剥离尾部英文语气词（Yeah./Okay./Mm. 等），纯英文不剥离（`strip_filler_words`）。 |
| **前缀去重** | 预览文本如以 confirmed 为前缀则剥离（`strip_confirmed_prefix`，50% 阈值避免误剥离短公共前缀）。 |
| **并发安全** | `Arc<std::sync::Mutex>` 保护内部状态。后台 HTTP task clone Arc 完成后短暂加锁写入。`transcribe_chunk` 不跨 await 持有锁。 |

### 与真流式对比（0.10.4 移除依据）

| | 真流式（WebSocket） | 伪流式（HTTP 轮询）⭐ |
|---|---|---|
| 准确率 | 较差（流式模型不如非流式） | 更好（SenseVoice 非流式） |
| 标点 | 无标点 | 有标点（自带） |
| 模型体积 | ~1.4GB（Paraformer-streaming） | ~234MB（SenseVoice） |
| CPU | 15× 实时 | 17× 实时 |
| Python 改动 | 需 WebSocket server | 零改动（HTTP 不变） |
| 复杂度 | WS 连接管理 + 重连 + 心跳 | 简单 HTTP 请求 |

## 五、文本注入通道

### 当前实现（0.10.3 起默认）

`inject_text()` 始终走 **SendInput Unicode**（`KEYEVENTF_UNICODE` 逐字符发送 `WM_CHAR`，不碰剪贴板），失败时自动降级到 **Clipboard+Ctrl+V**。无需用户配置——自动降级覆盖所有兼容性场景。

| 方案 | 流式展示 | 最终注入 | 剪贴板 |
|---|---|---|---|
| SendInput Unicode（默认） | mini overlay 显示 partial | `KEYEVENTF_UNICODE` 逐字符 | ✅ 不碰 |
| Clipboard+Ctrl+V（降级） | mini overlay 显示 partial | 剪贴板 + SendInput(Ctrl+V) | ❌ 污染（备份+恢复） |

### 废弃方案

- **0.10.5.1 TSF Composition**：`ITfThreadMgr::GetFocus()` 是进程本地的，Blink 拿不到前台应用的编辑上下文，跨进程时 TSF 路径静默失败退化成 SendInput。要真正跨进程以"输入法"身份注入需注册 TSF TIP（COM DLL + 注册表 + 用户启用），对一次性上屏场景过重。imekit 依赖与 TSF 实现已移除。

- **0.10.5.2 hook 吞键**：吞 Alt keyup 会污染 `GetKeyState(VK_MENU)` 全局状态，导致 Alt+Tab 异常、应用菜单栏闪烁等不可控副作用。条件再精确，吞掉的瞬间 Alt 状态就是错的。hook 恢复"全程放行，绝不吞键"。改为通过 `VOICE_RECORDING` 标志让 chord 判定逻辑感知录音状态。

### G2 焦点恢复

录音开始时保存前台 HWND（`prev_fg_hwnd`），finalize 期间焦点可能漂移，注入前先 `restore_foreground(hwnd)` + sleep 50ms 再注入，提升 Ctrl+V 成功率。

## 六、服务管理

### 启动流程（`start_funasr_server`）

```text
1. ServerStartParams::from_config()
   ├── ensure_server_script()  ← 释放 blink_stt_server.py
   └── write_hotwords_file()   ← 热词写为 hotwords.txt
2. 检查 Python 环境 → 未就绪自动 setup_with_progress()
3. funasr::start_server()
   ├── is_server_ready() 快速预检
   ├── spawn python blink_stt_server.py --model ... --port ... --device ...
   ├── 管道死锁防范：spawn 两个 task 持续读 stdout/stderr
   └── 返回 (child, log_rx)
4. 转发日志到前端 blink://funasr-server-log
5. spawn 就绪检测 task（带子进程退出检测）
   ├── 轮询 GET /health 的 model_status
   ├── idle/loading → emit loading_model
   ├── ready → emit ready
   └── error / 子进程退出 → emit error
```

**启动超时**：300s（首次需下载 ~234MB 模型）。**管道死锁防范**：子进程 stdout/stderr 设为 piped 但必须持续读取（Windows 管道缓冲 ~4KB），否则子进程会永久阻塞在 write 上。

### 配置（SttConfig）

| 字段 | 说明 |
|---|---|
| `enabled` | 语音总开关（默认关） |
| `mode` | Cloud / Local |
| `cloud_provider` | 云端供应商（kind / model_id / base_url） |
| `local_engine.server_port` | funasr-server 端口（默认 8000） |
| `local_engine.funasr_model` | 模型标识（`iic/SenseVoiceSmall`） |
| `local_engine.device` | 推理设备（cpu / cuda） |
| `local_engine.hotwords` | 热词（逗号分隔，写为 hotwords.txt） |
| `local_engine.use_itn` | ITN（默认 true） |
| `local_engine.vad` | VAD 切句参数（silence_threshold / min_silence_ms / min_sentence_ms，均可配） |
| `local_engine.auto_start_server` | Blink 启动后懒加载（延迟 3s） |
| `audio_device_id` | cpal 设备名（None = 系统默认） |
| `streaming_mode` | Pseudo（默认）/ Off |
| `local_model_id` | 模型注册表 id（如 `sensevoice-small`） |

> **兼容性**：旧配置中的 `streaming: bool` 和 `streaming_mode: "true"`（真流式）自动迁移为 `Pseudo`。旧 `streaming_model` 字段保留仅为反序列化兼容。旧模型名 `paraformer-zh-streaming` 自动归一化为 `iic/SenseVoiceSmall`。

## 八、P0 不回归保证

| 新增物 | 威胁 | 保证 |
|---|---|---|
| Python 子进程 | 启动加载若进热路径 | lazy-link，进程启动不加载 STT |
| ~230MB 模型 | 撑爆 <300MB 预算 | lazy-load，按需下载 |
| 麦克风采集线程 | 阻塞 LL hook | 独立线程，绝不进 hook |
| Hold timer | timer 阻塞 hook | timer 仅发事件，不执行逻辑 |
| G2 文本注入 | 触发失焦隐藏 | G2 时主窗不显示，注入不抢前台 |
| 后台 HTTP 识别 task | 阻塞音频采集 | tokio::spawn 独立 task，不阻塞 transcribe_chunk |
| in_flight 并发请求 | Python server 过载 | 原子标志守卫，最多 1 个飞行请求 |
| VAD 误判 | 句子被切断 | 参数可配 + 最小句长保护（<800ms 不切） |
