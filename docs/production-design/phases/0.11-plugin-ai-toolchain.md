# Blink 0.11 — 插件通信契约重设计 + AI 调用插件链路完善 + 截图标注增强

> **范围**：修补 0.9.3 Agent 框架的 tool-call 通信契约（主线）+ 补 AI tool 池缺口（应用搜索 / 剪贴板历史 Capability）+ builtin 插件全 Rust 化（翻译插件）+ 截图增强（0.11.7 末班车，与主线正交）。
>
> **主题**：0.9.3 跑通了"插件能被 AI 调用"的骨架，但结果回流 / 元信息 / 提示词三块不严谨。0.11 系统性清这笔债，让 AI 调用插件的链路真正可用。0.11.7 顺手把 0.8.7 截图从"选区→剪贴板"升级为现代截图工具（PixPin 级）交互，同时把散落 6 处的截图入口收敛为 Capability + Backend trait 结构。
>
> **状态**：0.11.0 ~ 0.11.9 完成。测试基线 **747 通过**（+ join_words_smart 9 单测 + rect_union 3 单测；翻译 command / 阅读模式 / 钉图 OCR 属 GUI 层手动验证）。
>
> **原则**：tool-call 契约改不破四域墙；有限多轮不破类型收窄铁则（固定次数 complete，不是 agent loop）；builtin 插件零 Python 依赖；截图不破四域墙 + 前端 Canvas 渲染 + 后端合成/输出。

## 二、核心设计

### 2.1 结果模型统一（0.11.0）

**成果**：
- `PluginItem` 增加 `payload: Option<Value>` 字段——display 语义（title/subtitle）与数据语义（payload）分离，对齐 `CapabilityResult::Items` 的 `ItemResult` 模型
- `PluginActionAdapter` 不再截断——返回全量 items，投影成 `ActionOutcome::Items(Vec<ItemResult>)`
- 统一投影路径 `items_to_entries`，插件 Items 和 Capability Items 走同一条路

**投影规则**：`payload` 优先取 `PluginItem.payload`；缺失时从 action 提取兜底（`Copy→{text}`, `Open→{path}`, `None→{}`），向后兼容老插件。

### 2.2 结果回流 AI（0.11.4）★

**两轮 complete 协议**：

```
Turn 1: complete(messages=[system, user], tools=[all])
       → tool_call_1 → execute → result_1

Turn 2: complete(messages=[system, user, assistant(tool_call_1), tool(result_1)], tools=[safe_only])
       → (a) text answer → 流式输出总结，结束
         (b) tool_call_2(safe) → execute → emit 执行结果，结束
         (c) tool_call_2(dangerous) → emit 确认卡片，结束
```

**关键设计**：
- **不违反类型收窄铁则**：固定次数 `complete()`，不引入 agent loop / prompt / memory
- **Turn 2 tools=[safe_only]**：支持 `search_apps → open_path` 链式调用；Dangerous tool 降级为确认卡片
- **固定上限**：最多 2 次 complete + 1 次 tool 执行
- **三态配置** `ai_tool_result_feedback`：`auto`（本地模型开 + 云端关）/ `on` / `off`
- **Turn 2 独立超时**：从总预算派生，5-15s；超时降级为"展示原始结果"
- **Turn 2 流式**：text 总结走 `provider.stream()` + `emit_ai_stream`，与 Turn 1 文本回答体验一致

**安全边界**：`open_path` 在 Turn 2 保持自动执行（D4）；`open_url` 降级为需确认（防恶意网址）。

**审计日志**：`ai_tool_audit` 表记录 tool 名 / 参数 / 结果摘要 / provider / 轮次。Turn 1/2 自动执行 + 用户确认执行（turn=0）均写入。

### 2.3 工具元信息增强（0.11.1）

**manifest `tools[]` 新增字段**：

| 字段 | 说明 |
|---|---|
| `result_type` | `"text"` / `"items"` / `"done"` — 声明返回类型，帮 AI 预期 |
| `hint` | 给 AI 的额外提示，自动拼入 system prompt |
| `progress_hint` | 占位文案提示词，拼成 `AI 正在{progress_hint}…` |
| `sensitive` | 声明敏感——0.12 MCP server 暴露时需授权 |
| `setting_bindings` | 参数→setting 绑定映射（参数动态注入用） |

**参数动态注入**：构建 AI tool schema 时，若某参数对应插件 setting 已配置，动态调整 `required → optional` + 注入 `default`。运行时 setting 变更下次构建 tools 时自动生效。

### 2.4 提示词统一管理（0.11.3）

`src/domain/ai/prompt.rs` 三函数：

| 函数 | 职责 |
|---|---|
| `routing_system_prompt(tools, lang)` | 主窗口路由 system prompt |
| `tool_result_feedback_prompt(lang)` | Turn 2 结果回流 system prompt |
| `tool_list_section(tools)` | 工具列表文字段（含 name + description + 参数摘要 + hint） |

**token 控制**：工具描述分层详略——system prompt 文字段只含 name + 一句话 description + 参数名（~30 token/工具）；完整 JSON Schema 走 `tools` 协议字段。每次构建估算 token 数，超 1500 有 `warn!` 告警。

### 2.5 应用搜索 Capability（0.11.2）

新增 `search_apps` Capability，包装 `StartMenuEngine`。

- **入参**：`{ "query": "vscode", "max_results": 5 }`
- **出参**：`Items`——payload 含 `{path, name, score}`
- **实例共享**：通过 `AppHandle` 拿 SearchService 的引擎引用，不持实例
- **sensitive**：`true`（读应用列表属隐私敏感数据）
- **与回流联动**：开启回流时 `search_apps`(Turn 1) → `open_path`(Turn 2) → 自动打开

### 2.6 剪贴板历史 Capability（0.11.5）

新增 `search_clipboard_history` Capability。

- **入参**：`{ "query": "", "max_results": 30 }`（query 空=最近 N 条）
- **出参**：`Items`——payload 含 `{id, text, kind}`
- **实现**：直接查 `clipboard` 表
- **sensitive**：`true`
- **与 `read_clipboard` 的边界**：read = 当前剪贴板（快）；search_history = 历史检索（需 DB）

**搜索型抽象评估**：`search_apps` / `search_files` / `search_clipboard_history` 三者数据获取方式差异太大，决定**不抽 trait**，记债等第四个再评估。

### 2.7 翻译插件全量 Rust 化（0.11.6）

翻译插件（571 行 Python）全量 Rust 化，5 引擎 1:1 迁移。

- **源码**：`plugins/examples/translate/`（Cargo.toml + src/main.rs + engine.rs + engines.rs + protocol.rs）
- **产物**：`blink-plugin-translate.exe` → `plugins/builtin/translate/bin/`
- **签名算法**：tencent TC3-HMAC-SHA256 / ali HMAC-SHA1 / baidu MD5 / youdao SHA256 / deepl 无签名
- **HTTP 代理**：复用插件 HTTP 代理协议，Rust 插件不直接联网
- **架构收益**：builtin 插件全 Rust 化，无 Python 依赖

### 2.8 截图标注增强（0.11.7）

0.8.7 截图只有"选区→剪贴板"一条路，0.11.7 升级为对标 PixPin 的现代截图工具（选区停留 + 工具栏 + 标注 + 多输出），同时把散落 6 处的截图入口收敛为 Capability + Backend trait。

**能力清单**：
- **标注**：7 种工具（矩形/椭圆/箭头/铅笔/文本/马赛克/橡皮擦）+ 撤销/重做栈 + 颜色/粗细
- **OCR**：`ocr_image` Capability（Windows.Media.Ocr）+ 结果面板 + 一键复制
- **钉图**：`chord-pin` 独立窗口，置顶/拖拽/滚轮缩放
- **保存**：PNG/JPEG + 系统对话框
- **复制**：有标注走前端合成 PNG；无标注走后端 SESSION 裁剪快路径（省 ~150-250ms 编解码往返）

**架构关键点**：
- **前端合成 PNG**：canvas 2D API 承担标注交互，后端只做写剪贴板/保存/钉图/OCR 的终点动作，不参与合成
- **`ScreenshotBackend` + `OcrBackend` trait**：平台层可 mock，`Fake*` 支撑单测；`list_displays()` 铺多显示器（id 稳定性仅同一进程内——AI 应基于每次 `list_displays()` 返回值即时决策）
- **`Screenshot` Capability**（op=list_displays/capture/crop）统一入口；`capture_screen` / `crop_image` 保留为 alias 至 0.13
- **标注模式互斥**：`begin_session()` 每次首行复位 `ANNOTATION_MODE` 防残留；标注活跃时 AI `capture_screen` 跳过 SESSION 缓存重截一帧
- **异步阻塞隔离**：PNG 解码 / BGRA swap / Win32 剪贴板写入均 `spawn_blocking` 挪出 tokio 工作线程

**扩展口**（0.12+ 评估）：截图→AI 联动 / 高级标注（荧光笔/序号/聚光灯/放大镜/水印）/ 钉图增强（锁定/透明度/多实例）/ 长截图 / 录屏 / PaddleOCR 兜底。数据模型 `AnnotationCommand { type, points, color?, width?, fill?, text? }` 已能表达上述工具，新增仅需 `type` 分支。

### 2.9 OCR word 级链路 + 阅读模式 + 翻译衔接 + 水印独立图层（0.11.9）★

0.11.7 的 OCR 只调了 `OcrResult.Text` 一整块，SDK 已给的 `OcrLine.Words()` 及 word 级 `BoundingRect` 完全没用；0.11.8 的水印被当"命令"push 进撤销栈，多次应用会叠加。0.11.9 把这两笔债清了，同时把 OCR 面板升级为"原图选词 + 双向联动"的阅读模式，并把翻译插件接进 OCR 面板，让"截图 → OCR → 翻译"成为一条龙。

#### 0.11.9-a 水印独立图层

- **动机**：`commitWatermark` 把水印 `push(commands)`，同一水印文字点两次就有两层；且撤销行为不友好（想改水印必须先撤销再重新加）
- **改法**：`annotation-engine.js` 引入 `watermarkConfig` 单例（不进 commands 栈）；`commitWatermark` 覆盖式写入 config；`renderCommandsTo` 尾部 `if (watermarkConfig) drawWatermark(...)`；`executeCommand` 移除 `case 'watermark'` 分支
- **前端**：水印表单加"清除水印"按钮；打开表单时若已有 config 自动回填
- **保存路径不变**：`compositeSelection` 仍走 `drawImage(annotCanvas)`，水印天然一层
- **收益**：换保存格式（PNG/JPEG）不叠水印；水印是"页面配置"而非"操作步骤"

#### 0.11.9-b OCR word 级链路（后端）

**schema 扩展**（`ocr_engine.rs`）：

```rust
pub struct OcrResult {
    pub text: String,                    // 智能拼接（下方规则）
    pub lines: Vec<OcrLine>,             // 保留
    pub words: Vec<OcrWord>,             // ★ 新增,flat 数组便于前端遍历
    pub text_angle: Option<f64>,         // ★ 新增,SDK 顺手给的旋转角
}
pub struct OcrLine {
    pub text: String,
    pub bounding_rect: OcrRect,          // ★ 真填(原来固定 {0,0,0,0}),用 words union
    pub word_indices: Vec<usize>,        // ★ 指回 words 数组的 index 段
}
pub struct OcrWord {
    pub text: String,
    pub bounding_rect: OcrRect,          // SDK 直接给的 word 级 float rect,四舍五入
    pub line_index: usize,
}
```

**WinRT 调用**：`OcrLine.Words()` → `OcrWord.BoundingRect()`（`Rect<x,y,width,height>` float）→ `OcrRect`。

**智能拼接** `join_words_smart(words, lines)`（独立可测）：
- CJK ↔ CJK：不加空格
- CJK ↔ Latin/Digit：不加空格（中英混排贴一起自然）
- Latin/Digit ↔ Latin/Digit：加一个空格
- Line 之间 `\n`

前端"移除空格"按钮**保留为兜底**（清理残余不间断空格等），不再是主力清理手段。

#### 0.11.9-c OCR 阅读模式 + 双向联动

**目标**：OCR 完成后 overlay 不关，进入"阅读模式"—— 原图 word 可鼠标拖选 + 面板可编辑，两侧双向高亮。

**关键实现**：
- 新增 `#ocr-hit-canvas` 层，坐标系与 annot-canvas 一致（物理像素相对裁剪区）
- 全局 `ocrWords[]` + `wordCharRanges[]`（拼接文本时同步累积 `{start, end}` 数组）
- **图上拖选**：mousedown → mousemove 期间按 word 相交实时高亮 + 同步 textarea `setSelectionRange`
- **面板选中**：textarea `selectionchange` → 反查覆盖的 word.rect → 图上高亮反光
- **跨行拖选按 word 数组顺序取连续段**（PixPin 套路，不是矩形框选）

工具栏加"返回标注"按钮供用户切回；ESC 直接关 overlay。

#### 0.11.9-d 翻译衔接（B1 + 双 tab 面板）

**核心思路**：OCR 面板从"单模式 textarea"升级为"原文 tab | 译文 tab"，OCR/翻译工具栏按钮共用同一个面板。

**新增 `translate_text` tauri command**（`commands.rs`）：

```rust
#[tauri::command]
pub async fn translate_text(
    text: String,
    target_lang: Option<String>,  // None → 读 translate 插件 setting
) -> Result<String, String>
```

内部走 `ActionRegistry` 找 `builtin.translate/translate`，用 `ExecArg::UserExplicit(json_args)` 直调，返 `Items[0].title`。**不走 AI 路径**——翻译是确定性动作，走 tool 直调链路更快更稳。

**面板双 tab 行为**：
- 首次打开 tab=原文
- 点面板顶栏「翻译」→ 调 `translate_text` → 结果填译文 tab → 自动切到译文 tab
- 已翻译再切回原文 tab → 译文缓存不丢，切回译文 tab 直接看
- 用户改原文 textarea → 译文标"过期"（灰色 + 提示"原文已改,点翻译按钮更新"）

#### 0.11.9-e 工具栏翻译按钮 + 一条龙

工具栏加「翻译」按钮（与「OCR」并列）：

```
点「OCR」        → OCR         → 面板 tab=原文
点「翻译」       → OCR + 翻译   → 面板 tab=译文
面板内「翻译」    → 只翻译       → 面板 tab=译文
```

#### 0.11.9-f 钉图窗口带 word 层

- `screenshot_pin` command 参数扩展：可选 `words: Vec<OcrWord>` + `crop_rect`
- pin 窗口加载时若带 word 数据 → 挂载 word 层脚本 → 支持右键菜单「选中区域 OCR」「翻译」
- **两态处理**：钉图前已 OCR → 直接传 words；钉图前未 OCR → pin 窗口右键菜单"识别文字"按需触发

**架构影响**：Capability 层 `OcrResult` schema 增字段（非破坏——旧消费方读 `text`/`lines` 仍可用）；无域边界穿墙。

## 三、产品体验规范

### 3.1 AI 结果项视觉形态

| 形态 | 标记位 | 视觉 | 场景 |
|---|---|---|---|
| AI 总结项 | `is_ai_summary` | `.ai-item` pre-wrap + 24px 徽章 | 情况 A/B/C 的 item[0] |
| AI 工具结果项 | `is_ai_tool_result` | nowrap 单行 + 12px 小号 AI 图标 | 情况 C 的 item[1..] |
| 普通结果项 | 两者 false | nowrap 单行 | 查询路径结果 |

**首席位(item[0])永远归 AI**。工具 items 上限 5 条，超出展示"还有 N 条结果"文字提示。

### 3.2 占位文案规范

| 阶段 | 文案 |
|---|---|
| 初始 | `AI 正在回答…` |
| Turn 1 工具执行中 | `AI 正在{progress_hint}…` |
| Turn 1→Turn 2 过渡 | `AI 正在思考…` |
| Turn 2 工具执行中 | `AI 正在{progress_hint}…` |
| Turn 2 流式总结 | 流式输出总结文本 |
| Turn 2 超时降级 | `AI 回答较慢,已展示原始结果` |

### 3.3 结果排布（情况 A/B/C）

| 情况 | Turn 2 产出 | 前端展示 |
|---|---|---|
| A. 纯总结 | text answer | item[0] = AI 总结 |
| B. 纯 tool chain | tool_call(safe) | item[0] = 执行结果 |
| C. 总结 + 列表 | text + items | item[0] = 总结 + item[1..] = 工具 items |

### 3.4 错误展示

错误走"情况 C"变体——AI 总结（橙色）+ 原始错误（橙色）。回流关闭时直接 emit 原始错误 item，无 AI 总结。

## 四、架构校验（不破四域墙）

| 改进 | 穿墙？ | 说明 |
|---|---|---|
| 结果模型统一 | 否 | Execution 域内部重构 |
| 结果回流 + tool chain | 否 | AI 在 Routing 域读 Tool 消息，Turn 2 调 safe tool 仍走 `ExecArg::UserExplicit` |
| 元信息增强 | 否 | manifest 解析层 + schema 投影层 |
| 提示词管理 | 否 | `domain::ai` 内部模块化 |
| 应用搜索 Capability | 否 | 只返回数据不执行打开 |
| 剪贴板历史 Capability | 否 | 只读历史，不写入 |
| 翻译 Rust 化 | 否 | 纯插件实现语言迁移 |
| 截图标注 + 能力化重构 | 否 | Capability 域 + 平台层 + 前端 UI；SESSION 状态语义不变 |
| OCR word 级 + 阅读模式 + 翻译衔接 + 水印独立图层 | 否 | `OcrResult` schema 非破坏扩展；`translate_text` 走 `ActionRegistry` 走的还是 `ExecArg::UserExplicit` 类型墙；前端 canvas 与 command 层无穿墙 |
