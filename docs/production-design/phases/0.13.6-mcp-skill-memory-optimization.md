# Blink 0.13.6 — MCP 导入增强 + Skill 交互重设计 + 记忆窗口可视化

> **范围**：① MCP 多协议 + 跨 agent 配置导入 + JSON 一键导入 + 导入后启停管理 + ② Skill 导入工作流（软链接/复制）+ ③ 记忆策略 UI 对齐 + 上下文窗口占用指示器 + ④ Skill/MCP 调用聊天窗口展现优化 + ⑤ CLI 能力识别（从 `--help` 生成 SKILL.md 模板）。
>
> **前置**：0.13.0-0.13.5 全部完成（MCP 双向 + CLI 化 + Skill + 记忆召回 + token-aware 窗口）。
>
> **核心原则**：不引入新依赖，复用 rmcp 已有 transport 特性 + rig McpTool 适配层。

---

## 一、背景与问题

0.13 完成了 MCP 双向通信、Skill 发现、记忆 FTS5 召回、token-aware 压缩等基础设施，但在实际使用中暴露了以下体验缺口：

| # | 问题 | 影响 |
|---|---|---|
| 1 | MCP 仅支持 stdio 协议，不支持 Streamable HTTP | 无法接入远程 MCP server（如云端 API、Docker 容器内 server） |
| 2 | MCP 配置只能手动逐个填写，无法从其他 agent 导入 | 用户在 Claude/Cursor 已有 MCP 配置，到 Blink 要重新填一遍 |
| 3 | Skill 只做发现扫描，没有导入工作流 | 用户想在 Blink 目录管理 Skill，但只能手动复制文件 |
| 4 | 设置页"召回条数"与"当前上下文窗口"样式未对齐 | 视觉割裂，右控件宽度不一致 |
| 5 | 聊天窗口无上下文窗口占用指示 | 用户不知道当前对话占了多少 token，何时触发压缩 |
| 6 | Skill 激活在聊天窗口无视觉反馈 | 用户发了 `/skill xxx` 但看不到哪个 Skill 被激活了 |
| 7 | MCP 工具调用与内置工具卡片样式无区分 | 无法快速辨别工具来源 |
| 8 | 用户想让 AI 学会使用本地 CLI 工具（git/docker/kubectl），但没有 Skill | AI 不知道这些工具的用法，无法生成正确的命令 |

## 二、MCP 导入增强

### 2.1 多协议支持

#### 现状

当前 `McpClientManager::try_connect()` 仅使用 `TokioChildProcess`（stdio transport）。

#### rmcp 已有的 transport 特性

| 特性 | 用途 | 当前 Cargo.toml |
|---|---|---|
| `transport-child-process` | stdio 子进程 | ✅ 已启用 |
| `transport-io` | 通用 async read/write | ✅ 已启用 |
| `transport-streamable-http-client` | Streamable HTTP client | ❌ 未启用 |
| `transport-streamable-http-client-reqwest` | HTTP client（reqwest 后端） | ❌ 未启用 |

> **注意**：MCP 规范 2025-03-26 版本用 Streamable HTTP 替代了旧版 SSE transport。rmcp 1.8 已跟进，无单独 SSE 特性。启用 `transport-streamable-http-client-reqwest` 即可支持远程 HTTP MCP server。

#### 设计

**McpServerConfig 扩展 `transport` 字段**：

```rust
pub struct McpServerConfig {
    pub name: String,
    /// 传输协议类型。
    #[serde(default = "default_transport")]
    pub transport: McpTransport,
    // ── stdio 模式字段 ──
    pub command: String,
    #[serde(default)]
    pub args: Vec<String>,
    #[serde(default)]
    pub env: std::collections::HashMap<String, String>,
    // ── 通用字段 ──
    #[serde(default = "default_enabled")]
    pub enabled: bool,
    #[serde(default)]
    pub disabled_tools: Vec<String>,
}

/// MCP 传输协议类型。
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "snake_case", tag = "type")]
pub enum McpTransport {
    /// stdio 子进程（当前唯一支持的类型）。
    Stdio,
    /// Streamable HTTP（远程 server）。
    /// `url` 字段必填，`headers` 可选（如 Authorization）。
    Http {
        url: String,
        #[serde(default)]
        headers: std::collections::HashMap<String, String>,
    },
}
```

**`try_connect()` 分支**：

```rust
async fn try_connect(&self, config: &McpServerConfig) -> Result<Vec<McpToolInfo>, String> {
    match &config.transport {
        McpTransport::Stdio => self.try_connect_stdio(config).await,
        McpTransport::Http { url, headers } => self.try_connect_http(config, url, headers).await,
    }
}
```

**HTTP 连接**：

```rust
async fn try_connect_http(
    &self,
    config: &McpServerConfig,
    url: &str,
    headers: &HashMap<String, String>,
) -> Result<Vec<McpToolInfo>, String> {
    // rmcp Streamable HTTP client transport
    let transport = rmcp::transport::StreamableHttpTransport::from_streamable_http_requable(
        url,
        headers.clone(),
    );
    let client_info = ClientInfo::default();
    let service = client_info.serve(transport).await
        .map_err(|e| format!("HTTP MCP 握手失败: {e}"))?;
    // 后续与 stdio 一致：拉 tool 列表 + 存入连接表
    ...
}
```

**Cargo.toml 变更**：

```toml
rmcp = { version = "1.8", features = ["client", "server", "transport-child-process", "transport-io", "transport-streamable-http-client-reqwest"] }
```

> `transport-streamable-http-client-reqwest` 已含 `transport-streamable-http-client` 和 `transport-worker`，无需重复声明。reqwest 已在 rig-core 的 default features 中引入（rustls 后端），零新依赖。

`command` 字段对 HTTP 模式可为空字符串。

### 2.2 跨 Agent 配置导入

#### 目标 Agent 配置格式

各 agent 的 MCP 配置格式高度统一——都是 `mcpServers` 对象，key 为 server 名称：

| Agent | 配置文件路径（Windows） | 格式 |
|---|---|---|
| Claude Desktop | `%APPDATA%\Claude\claude_desktop_config.json` | `{ "mcpServers": { "<name>": { "command", "args", "env" } } }` |
| Claude Code | `%USERPROFILE%\.claude.json` | `{ "mcpServers": { "<name>": { "command", "args", "env", "type" } } }` |
| Cursor | `%USERPROFILE%\.cursor\mcp.json` | `{ "mcpServers": { "<name>": { "command", "args", "env" } } }` |
| Windsurf | `%USERPROFILE%\.codeium\windsurf\mcp_config.json` | `{ "mcpServers": { "<name>": { "command", "args", "env" } } }` |
| VS Code | `%APPDATA%\Code\User\settings.json`（mcp.servers 节） | `{ "mcp": { "servers": { "<name>": { "command", "args", "env" } } } }` |

**统一适配**：定义 `McpImportFormat` enum，各 agent 对应一个解析器，输出 `Vec<McpServerConfig>`：

```rust
/// 可导入的 MCP 配置来源。
#[derive(Debug, Clone, Copy, Serialize)]
#[serde(rename_all = "lowercase")]
pub enum McpImportSource {
    ClaudeDesktop,
    ClaudeCode,
    Cursor,
    Windsurf,
    Vscode,
    /// 通用 JSON（用户粘贴或选择文件）
    Json,
}

/// 解析外部 agent 的 MCP 配置文件。
///
/// 各 agent 格式大同小异，核心差异在：
/// - 配置文件路径不同
/// - Claude Code 支持 `type: "sse"` / `type: "http"` 字段
/// - VS Code 用 `mcp.servers` 而非 `mcpServers`
pub fn parse_external_mcp_config(
    source: McpImportSource,
    json: &str,
) -> Result<Vec<McpServerConfig>, String> {
    let servers = match source {
        McpImportSource::Vscode => {
            let v: serde_json::Value = serde_json::from_str(json)?;
            v["mcp"]["servers"].as_object()
        }
        _ => {
            let v: serde_json::Value = serde_json::from_str(json)?;
            v["mcpServers"].as_object()
        }
    };

    let Some(servers) = servers else {
        return Err("配置中未找到 mcpServers 字段".into());
    };

    let mut configs = Vec::new();
    for (name, cfg) in servers {
        let config = parse_single_server(name, cfg)?;
        configs.push(config);
    }
    Ok(configs)
}
```

**Claude Code `type` 字段适配**：

```rust
fn parse_single_server(name: &str, cfg: &serde_json::Value) -> Result<McpServerConfig, String> {
    // Claude Code 格式：type: "stdio" | "sse" | "http"
    let transport_type = cfg.get("type").and_then(|v| v.as_str()).unwrap_or("stdio");

    let transport = match transport_type {
        "sse" | "http" => {
            let url = cfg.get("url")
                .and_then(|v| v.as_str())
                .ok_or("HTTP/SSE 模式缺少 url 字段")?
                .to_string();
            let headers = cfg.get("headers")
                .and_then(|v| v.as_object())
                .map(|m| m.iter()
                    .filter_map(|(k, v)| v.as_str().map(|s| (k.clone(), s.to_string())))
                    .collect())
                .unwrap_or_default();
            McpTransport::Http { url, headers }
        }
        _ => McpTransport::Stdio,
    };

    let command = cfg.get("command").and_then(|v| v.as_str()).unwrap_or("").to_string();
    let args = cfg.get("args").and_then(|v| v.as_array())
        .map(|a| a.iter().filter_map(|v| v.as_str().map(String::from)).collect())
        .unwrap_or_default();
    let env = cfg.get("env").and_then(|v| v.as_object())
        .map(|m| m.iter()
            .filter_map(|(k, v)| v.as_str().map(|s| (k.clone(), s.to_string())))
            .collect())
        .unwrap_or_default();

    Ok(McpServerConfig {
        name: name.to_string(),
        transport,
        command,
        args,
        env,
        enabled: true, // 导入后默认启用
        disabled_tools: Vec::new(),
    })
}
```

### 2.3 JSON 一键导入

设置页新增「导入」按钮，支持两种导入路径：

**路径 A：从已有 agent 配置文件导入**

```
点击「导入」→ 下拉选择来源（Claude Desktop / Claude Code / Cursor / Windsurf / VS Code）
  → 后端自动探测配置文件路径
  → 读取并解析
  → 返回待导入列表（含去重检查）

```

```
  → 文本框粘贴 MCP 配置 JSON
  → 后端解析（通用格式 `mcpServers` 对象）
  → 返回待导入列表
  → 用户确认
  → 批量 upsert
```

## 三、Skill 导入工作流

### 3.1 问题

当前 Skill 只做**发现**（扫描 3 个固定目录），没有**导入**工作流。用户在 Claude 目录有 Skill，想在 Blink 目录也有一份，只能手动 `Ctrl+C` / `Ctrl+V`。

### 3.2 设计

**Skill 导入 ≠ MCP 导入**：
- MCP 导入 = 导入配置（JSON 数据，写 DB）
- Skill 导入 = 导入文件（SKILL.md + 资源，写文件系统）

**两种导入方式**：

| 方式 | 实现 | 适用场景 |
|---|---|---|
| 软链接（Symbolic Link） | `std::os::windows::fs::symlink_dir()` | 开发者：源目录受版本控制，双向同步 |
| 复制（Copy） | `std::fs::copy()` 递归复制 | 普通：独立副本，不受源目录变化影响 |

**后端 Command**：

```rust
/// 导入 Skill 到 Blink 目录。
///
/// `source_path` = 源 SKILL.md 所在目录
/// `mode` = "symlink" | "copy"
/// 导入后在 `%APPDATA%\blink\skills\<name>\` 创建软链接或副本。
#[tauri::command]
async fn import_skill(
    source_path: String,
    mode: SkillImportMode,
) -> Result<String, String> { ... }

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum SkillImportMode {
    Symlink,
    Copy,
}
```

**软链接注意事项（Windows）**：
- 需要 Developer Mode 或管理员权限才能创建符号链接
- 失败时自动降级为 Copy + 提示用户开启路径
- 提示文案：「软链接创建失败（需要开发者模式）。已降级为复制。如需软链接，请在 Windows 设置 → 隐私和安全性 → 开发者选项 中开启开发者模式。」
- 软链接目标不存在时标灰（Skill 卡片显示 ⚠ 标记）

### 3.3 Skill 启用/禁用

当前 Skill 只有来源级别的开关（`source_blink` / `source_claude` / `source_zcode`），没有单个 Skill 粒度的开关。

```
每个 Skill 卡片：
```

### 4.2 聊天窗口上下文窗口占用指示器

**目标**：类似 ChatGPT / Claude 的上下文占用指示器，让用户知道当前对话窗口的 token 使用量。

#### 位置

composer bar 右侧（`chat-composer-bar-right` 区域），在现有 `chat-tool-pool` 旁边新增 `chat-context-indicator`。

#### 视觉设计

```
composer bar 右侧：
[🛠 12 tools] [◯ 45%]  ← tool 池指示器 + 上下文占用环
```

- **环形进度条**：SVG circle，随 token 占比变化颜色
  - 0-60%：`var(--text-faint)`（灰色，安全区）
  - 60-80%：`var(--warning)`（黄色，接近压缩阈值）
  - 80-100%：`var(--danger)`（红色，压缩已触发或即将触发）
- **数字**：环中央显示百分比 `45%`
- **tooltip**：hover 显示 `当前 ~3,200 / 8,192 tokens（窗口模式: Token 感知）`
- **压缩标记**：当 `load()` 触发了 token_aware_truncate 时，环旁显示 ⚡ 标记，tooltip 显示 `已自动压缩 N 条旧消息`

#### 数据流

```rust
/// 聊天窗口上下文窗口状态（每次 prompt 前/后返回）。
#[derive(Clone, Debug, Serialize)]
pub struct ContextWindowStatus {
    /// 估算的当前窗口 token 数。
    pub estimated_tokens: usize,
    /// 模型 context window 上限。
    pub context_limit: usize,
    /// 占用百分比（0-100）。
    pub usage_percent: u8,
    /// 上次 load() 是否触发了压缩。
    pub last_compressed: bool,
    /// 上次压缩移出的消息数。
    pub last_compressed_count: usize,
    /// FTS5 召回的消息数（上次 load()）。
    pub last_recall_count: usize,
}
```

**获取时机**：

1. 每次 `chat_prompt` 前调 `memory.load()` 后，估算窗口 token → 通过 `blink://chat-context-status` 事件推送到前端
2. 切换模型时（context_limit 变化）→ 重新计算并推送
3. 前端也可主动调 `get_context_window_status` command 查询

**后端实现**：

在 `ChatService::prompt()` 中，`memory.load()` 完成后、`provider.stream_prompt()` 之前，插入上下文估算：

```rust
// 在 prompt task 内部，provider 构造后
let context_status = self.compute_context_status(&conversation_id).await;
let _ = self.app.emit_to("chat", "blink://chat-context-status", context_status);
```

```rust
async fn compute_context_status(&self, conversation_id: &str) -> ContextWindowStatus {
    let cfg = self.memory.config_handle().read().await;
    let context_limit = cfg.context_limit.unwrap_or(DEFAULT_CONTEXT_LIMIT);

    // 从 DB 加载当前窗口的消息（与 load() 逻辑一致，但不注入 memory block）
    let messages = /* load_recent_messages + token_aware_truncate */;
    let estimated_tokens = estimate_messages_tokens(&messages);

    ContextWindowStatus {
        estimated_tokens,
        context_limit,
        usage_percent: (estimated_tokens * 100 / context_limit) as u8,
        last_compressed: /* 从上次 load() 结果获取 */,
        last_compressed_count: /* ... */,
        last_recall_count: /* ... */,
    }
}
```

> **实现方案**：在 `SqliteConversationMemory` 上新增 `load_with_stats()` 方法（不影响 rig `ConversationMemory` trait 签名），返回 `MemoryLoadResult { messages, dropped_count, recall_count }`。`ChatService::prompt()` 内部调用 `load_with_stats()` 获取消息 + 统计，rig 的 `ConversationMemory::load()` 仍调原始 `load()`。

```javascript
  if (!el || !status) return;

  const percent = status.usage_percent;
  const color = percent < 60 ? "var(--text-faint)"
    : percent < 80 ? "var(--warning)"
    : "var(--danger)";

  // SVG 环形进度条
  const circumference = 2 * Math.PI * 10; // r=10
  const offset = circumference * (1 - percent / 100);

  el.innerHTML = `
    <svg class="context-ring" viewBox="0 0 24 24" title="${percent}% · ~${status.estimated_tokens} / ${status.context_limit} tokens">
      <circle cx="12" cy="12" r="10" fill="none" stroke="var(--border)" stroke-width="2"/>
      <circle cx="12" cy="12" r="10" fill="none" stroke="${color}" stroke-width="2"
        stroke-dasharray="${circumference}" stroke-dashoffset="${offset}"
        transform="rotate(-90 12 12)"/>
    </svg>
    ${status.last_compressed ? '<span class="context-compressed" title="已自动压缩">⚡</span>' : ''}
  `;
}
```

## 六、CLI 能力识别

### 6.1 问题

用户有大量本地 CLI 工具（`git` / `docker` / `kubectl` / `ffmpeg` / `magick` 等），想让 AI 学会使用这些工具。当前没有机制让 AI 了解这些 CLI 的用法——AI 只能靠训练数据里的通用知识，对版本特定参数、自定义子命令等一无所知。

### 6.2 设计思路

**纯文本解析，零 LLM 依赖**：运行 `<cli> --help` 获取帮助文本，用启发式解析提取命令/子命令/参数，生成 SKILL.md 模板。用户 review 后手动编辑完善。

与 0.14「AI 生成 Skill」的区别：
- **0.13.6 CLI 能力识别**：纯文本解析，零模型依赖，生成「半成品」模板供用户编辑
- **0.14 AI 生成 Skill**：用 LLM 理解 `--help` 语义，生成更精准的 SKILL.md（需 chat 模型）

### 6.3 解析流程

```
用户指定 CLI 路径（如 C:\Program Files\Git\bin\git.exe）
  ↓
Blink 运行 <cli> --help，捕获 stdout + stderr
  ↓
退出码 != 0？→ 尝试 <cli> help
  ↓
启发式解析：
  ├─ 工具名 = 可执行文件名（去扩展名）
  ├─ 描述 = 首行非空文本
  ├─ 子命令 = 缩进行中「word  描述」模式
  ├─ 全局选项 = --flag / -f 行
  └─ 用法行 = `Usage: ...` 行
  ↓
生成 SKILL.md 模板
  ↓
保存到 %APPDATA%\blink\skills\<tool-name>\SKILL.md
  ↓
提示用户 review 编辑
```

### 6.4 启发式解析规则

`--help` 输出格式千差万别，但常见的结构有规律可循：

**子命令识别**（最常见的 `git` / `docker` / `kubectl` 风格）：
```
  add        Add file contents to the index
  commit     Record changes to the repository
  push       Update remote refs along with associated objects
```
模式：行首 2+ 空格 + 单词 + 2+ 空格 + 描述文本。

**选项识别**（GNU getopt 风格）：
```
  -v, --verbose    Increase output verbosity
  -q, --quiet      Suppress output
      --config FILE  Configuration file path
```
模式：行首 2+ 空格 + `-x, --xxx` 或 `--xxx` + 空格 + 描述。

**Usage 行**：
```
Usage: git [--version] [--help] [-C <path>] [-c <name>=<value>]
```
提取为 SKILL.md 的用法示例。

**多级探测**：部分 CLI 有子命令树（如 `git remote --help`），0.13.6 只做顶层探测（`--help`），子命令深度探测推到后续版本。

**解析核心逻辑**（纯函数，可单测）：

```rust
/// 解析 --help 文本，提取结构化信息。
pub fn parse_help_output(output: &str) -> ParsedHelp {
    let mut subcommands = Vec::new();
    let mut options = Vec::new();
    let mut usage_line = None;
    let mut description = String::new();

    for line in output.lines() {
        let trimmed = line.trim();

        // Usage 行
        if trimmed.starts_with("Usage:") || trimmed.starts_with("usage:") {
            usage_line = Some(trimmed.to_string());
            continue;
        }

        // 首行非空文本作为描述
        if description.is_empty() && !trimmed.is_empty()
            && !trimmed.starts_with('-') && !trimmed.starts_with("Usage")
        {
            description = trimmed.to_string();
        }

        // 子命令：行首 2+ 空格 + 单词 + 2+ 空格 + 描述
        if let Some(cmd) = parse_subcommand_line(line) {
            subcommands.push(cmd);
        }

        // 选项：行首 2+ 空格 + -x / --xxx
        if let Some(opt) = parse_option_line(line) {
            options.push(opt);
        }
    }

    ParsedHelp { description, subcommands, options, usage_line }
}
```
