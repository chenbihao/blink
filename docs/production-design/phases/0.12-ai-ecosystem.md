### 1.2 产品边界

- 本地模型只对接外部 ollama / lmstudio，不内嵌推理引擎，不负责模型下载。
- ollama 走 rig 原生 Provider；lmstudio 和其他兼容服务走 `OpenAICompatible`。
- 0.12 不引入 MCP / RAG / 向量库。
- 安装包保持轻量，不因 AI 运行时显著膨胀。

### 1.3 两条 AI 路径严格隔离

| 维度 | 主窗口 | 对话窗口 |
|---|---|---|
| 抽象 | `AIProvider` | `AgentProvider` |
| 交互 | 单轮快路径 | 多轮对话 |
| 模型能力 | `complete` / `stream` | rig `AgentBuilder` / memory / tool loop |
| 工具调度 | 外部调度，固定回流 | Agent 内部循环，最大 50 turns |
| 记忆 | 无 | 按 `conversation_id` 隔离 |

**铁则**：主窗口 `AIProvider` 不暴露 `AgentBuilder`、memory 或 agent loop；对话能力只存在于 `agent_provider.rs` 和 chat 服务路径。

### 2.2 数据布局

SQLite 位于 `%APPDATA%\blink\`（四库独立）：

| 数据库 | 表 | 语义 |
|---|---|---|
| `blink_config.db` | `config` | 用户配置；未来同步只需处理此库 |
| `blink_history.db` | `history` / `clipboard_history` | 用户行为历史 |
| `blink_ai.db` | `ai_tool_audit` / `conversations` / `messages` | AI 对话与审计 |
| `blink_cache.db` | `performance_metrics` / `icon_cache` | 可删除、可重建缓存 |

### 2.3 Agent Tool 适配层

```text
Capability / Action
        ↓
CapabilityTool / ActionTool (ToolDyn)
        ↓
build_agent_tools()
        ↓
rig Agent tool loop
```

- `ai_eligible() == false` 的 Action 不进入 Agent tool 池。
- Dangerous tool 在 `ToolDyn::call` 内等待用户确认，不会先返回"已执行"的假结果。
- MCP tool 在 0.13 复用同一适配层，不改现有 Capability / Action 契约。

### 3.4 数据表

```sql
CREATE TABLE conversations (
  id TEXT PRIMARY KEY,
  title TEXT,
  created_at INTEGER NOT NULL,
  last_active_at INTEGER NOT NULL
);

CREATE TABLE messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  conversation_id TEXT NOT NULL,
  role TEXT NOT NULL,
  content TEXT NOT NULL,        -- 序列化的 rig Message
  created_at INTEGER NOT NULL,
  FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE
);
CREATE INDEX idx_messages_conv ON messages(conversation_id, id);
```

### 5.2 主窗口功能引导泡泡

**目标**：用户打开主窗口时，空 query 状态下展示主打功能的引导泡泡（如"帮我打开微信"），点击预填充到输入框，降低发现成本。

#### 5.2.1 确认方案

- **显示策略**：每次空 query 都显示（用户输入后消失，清空后恢复）。
- **点击行为**：只预填充到输入框，不自动执行（用户按 Enter 确认）。
- **泡泡内容**：预设 4 个示例 prompt：
  - "帮我打开微信"（演示应用搜索 + AI 执行）
  - "翻译 hello world"（演示翻译插件）
  - "截取屏幕"（演示截图 chord 能力）
  - "今天天气怎么样"（演示 AI 对话）
- **视觉**：圆角胶囊气泡，弱色背景，hover 高亮，与主窗口风格统一。

#### 5.2.2 实现

- 复用主窗口结果区（`#results`）的空白态：当 query 为空且无搜索结果时，渲染引导泡泡区域。
- 泡泡数据硬编码（方便后续扩展为配置化自定义快捷指令）。
- 点击泡泡 → 填入 `#query` + dispatch input 事件（触发搜索，用户看到结果后按 Enter 执行）。

**涉及文件**：
- `frontend/index.html` / `frontend/js/lifecycle.js`（空状态渲染引导泡泡 + 点击预填充）
- `frontend/css/views/main.css`（泡泡样式）

### 5.3 对话标题 LLM 自动生成

**目标**：0.12.4 的截断标题基础上，0.12.5 增加可选的 LLM 自动命名——后台异步调模型生成 6-10 字语义化标题，生成完成后替换截断标题。

#### 5.3.1 确认方案

- **混合方案**：首条消息发送后立即用截断标题（0.12.4 已实现），同时后台异步调 LLM 生成更好标题，完成后替换。
- **设置控制**：用户可在设置页开关 LLM 命名功能。
- **模型选择**：设置页可选命名用的模型档位——主档 / 轻量档 / 路由档（复用现有 `Tier` 枚举）。

#### 5.3.2 实现

- 后端新增 IPC `generate_conversation_title(conversation_id, first_message) -> String`：
  - 读取设置中的命名开关和模型档位。
  - 构造精简 prompt："请用 6-10 个字概括以下用户消息，作为对话标题，只输出标题文本：{message}"。
  - 调对应档位的 `AIProvider::complete()`（非 Agent 路径，单轮补全）。
  - 生成成功后更新 `conversations.title` 并 emit `blink://chat-title-updated` 事件。
- 前端监听 `chat-title-updated`，更新 header 标题 + 刷新侧边栏。
- 生成失败静默降级（保持截断标题）。

**涉及文件**：
- `src/domain/ai/chat_service.rs` 或 `src/app/commands.rs`（`generate_conversation_title` IPC）
- `src/app/ai_config.rs`（命名开关 + 模型档位配置项）
- `frontend/js/chat/main.js`（监听 `chat-title-updated` + 更新标题）
- `frontend/js/chat/ipc.js`（新增 IPC 封装）

### 5.5 消息编辑重发

**目标**：点击已发送的用户消息可编辑后重发，重新生成 assistant 回复（类似 ChatGPT）。

#### 5.5.1 方案

- 用户消息 hover 显示「编辑」按钮。
- 点击编辑 → 消息气泡变为 textarea（预填原消息），用户修改后按 Enter 重发。
- 重发时：截断该消息之后的所有消息（从 `messages` 表删除），重新调 `chat_prompt`。
- assistant 回复重新生成。

**涉及文件**：
- `frontend/js/chat/components.js`（用户消息 hover 编辑按钮 + 编辑态 textarea）

- `src/infra/data/conversations.rs`（按 conversation_id + message_id 截断）

### 5.7 代码块语法高亮

## 六、0.12.6 对话分组（📋 规划中）

> 从 0.12.5 拆出，规模较大且独立性强。

### 6.1 功能设计

**参考**：元宝网页端的对话分组——可将对话归入不同分组，每个分组可指定系统提示词（system prompt），方便按场景管理对话。

- **分组层级**：侧边栏增加分组层级，对话列表按分组折叠展示。区分文件夹与对话的样式。
  ```
  📁 工作
    ├─ 周报整理
    ├─ 会议纪要
  📁 学习
    ├─ Rust 异步编程
  📁 默认
    ├─ 新对话
  ```
- **分组操作**：新建分组、重命名分组、删除分组（删除时对话移至"默认"组，不级联删除）。
- **拖拽**：文件夹可直接拖动排序；对话可拖拽到不同分组。
- **系统提示词**：每个分组可配置一段系统提示词，该分组下新对话自动携带。
- **管理入口**：侧边栏内联管理（分组右键 / hover 按钮触发操作菜单）。
- **默认分组**：未指定分组的对话归入"默认"组，无系统提示词。

### 6.2 数据模型

AI 库新增表：

```sql
CREATE TABLE conversation_groups (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  system_prompt TEXT,           -- 分组级系统提示词
  sort_order INTEGER DEFAULT 0,
  created_at INTEGER NOT NULL
);

-- conversations 表加列
ALTER TABLE conversations ADD COLUMN group_id TEXT REFERENCES conversation_groups(id) ON DELETE SET NULL;
```
