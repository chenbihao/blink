## 插件系统（已完成 ✅）

### 模块职责

| 文件 | 职责 |
|---|---|
| `manifest.rs` | JSON manifest 解析，schema_version 兼容校验，permissions 不解析（自用阶段） |
| `protocol.rs` | JSONL 协议 struct：Query/Cancel/Response/Item/Action |
| `process.rs` | PluginProcess（tokio 子进程 + 三路并发 reader）+ PluginHandle（懒启动 + 崩溃重启） |
| `engine.rs` | PluginEngine：keyword 匹配 → 命中插件 query → 结果转 SearchItem |
| `mod.rs` | load_builtin_plugins 扫描 manifest |

### 关键设计决策

1. **插件动作透传**：`SearchAction` 带 payload，前端 actions.js 优先读 → 插件可复制/打开/执行动作
2. **keyword 不独占**：命中只决定是否查该插件，sync lane 照常出应用/计算（独占语义留给 0.4 RuleRouter）
3. **进程懒启动 + 常驻复用**：`Mutex<Child>` 支持 `is_alive` 非阻塞检测，多 query 并发 in-flight
4. **超时 cancel**：best-effort `send_cancel`（200ms）+ 删 pending，避免孤儿响应堆积

## 热键触发判定重构（已完成 ✅）

### 问题

旧方案维护「累积按键镜像」，被系统注入的合成事件打乱后无法自愈 → Alt+Space 残留误触发

### 解决方案

**物理态查询**：不在应用层累积镜像，只在主键 down/up 边界用 `GetAsyncKeyState` 现查修饰键物理态。

状态机仅 3 字段：`down_since` / `armed_key` / `aborted`

**精确 bitmask 匹配**：配置修饰键「消耗」物理按下的位，最后要求无剩余位 → `Ctrl+Alt+空格` 不误触发 `Alt+空格`

**AltGr 修正**：RAlt+LCtrl 同按时视 LCtrl 为合成（代价：真实 `LCtrl+RAlt+key` 无法触发，极少见）

### 测试

8 个纯函数单测（mask 映射 / 精确匹配边界 / AltGr 修正 / standalone 判定），cargo test 41 全过
