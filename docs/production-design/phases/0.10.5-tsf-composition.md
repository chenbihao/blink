# Blink 0.10.5 — TSF Composition 文本注入方案（via imekit）

> **范围**：G2 语音输入法上屏的注入通道升级——从 SendInput Unicode 升级到 TSF Composition，解决部分应用文字无法上屏的问题。
>
> **主题**：引入 [imekit](https://crates.io/crates/imekit) crate，用其封装的 TSF Composition + IMM32 + SendInput 三级回退链替代当前手写的 SendInput，让语音文字像 IME 组字一样上屏。
>
> **前置**：0.10.4 完成（伪流式 VAD 切句 + SendInput Unicode 注入）。
>
> **状态**：方案设计阶段。

---

## 一、问题分析：SendInput Unicode 为什么不够

### 1.1 当前方案回顾

0.10.3 起，G2 文本注入默认走 `SendInput` + `KEYEVENTF_UNICODE`：将文本编码为 UTF-16，逐码元构造 `INPUT` 结构体发送 `WM_CHAR`，绕过剪贴板。

```
STT 文本 → UTF-16 编码 → 逐码元 SendInput(KEYEVENTF_UNICODE) → WM_CHAR → 应用文本框
```

### 1.2 已知失败场景

| 场景 | 根因 | 表现 |
|---|---|---|
| **Windows Terminal / cmd.exe** | Console Host 不走 `WM_CHAR`，走控制台输入队列 | 文字完全不上屏 |
| **Electron 应用（VS Code 等）+ IME 激活** | Chromium 的 IME 模块把 Unicode 输入当候选词处理 | 文字被吞或变成乱码候选 |
| **UWP / WinUI 3 应用** | 现代 XAML 文本控件走 TSF 管线，不直接处理 `WM_CHAR` | 文字不上屏 |
| **Office（Word / Outlook）** | Office 有自己的 TSF 文本管线，SendInput 产出被丢弃 | 文字不上屏或闪烁 |
| **部分 WPF 应用** | WPF TextBox 在 IME 激活时优先处理 `WM_IME_*` 而非 `WM_CHAR` | 中文输入法下失败 |

### 1.3 核心矛盾

`SendInput` 模拟的是**硬件键盘事件**（`WM_KEYDOWN` → `WM_CHAR`）。但现代 Windows 文本输入的正确管线是 **TSF**——所有 IME、语音输入、手写识别都走 TSF。应用只认 TSF 的 Composition / Commit 事件，不认裸 `WM_CHAR`。

**一句话**：SendInput 是在模拟「敲键盘」，而我们需要的是模拟「输入法出字」。

## 二、为什么选 imekit

### 2.1 imekit 是什么

[imekit](https://github.com/SergioRibera/imekit)（crates.io `imekit = "0.2"`）是一个跨平台 Rust 库，封装了各平台的原生 IME 协议：

| 平台 | 协议 | 状态 |
|---|---|---|
| Linux/Wayland | `zwp_input_method_v2` / `zwp_text_input_v3` | ✅ |
| Linux/X11 | XIM + XTest | ✅ |
| Linux/IBus | D-Bus engine | ✅ |
| **Windows** | **TSF（`ITfInsertAtSelection` / `ITfContextComposition`）** | **✅** |
| macOS | Input Method Kit (IMK) | ✅ |

> README 明确写道：*"This is **not** a text insertion library. It implements the actual IME protocols."*

Blink 定位是 Windows-only，当前只需要 Windows 后端，但 imekit 的跨平台抽象让 API 极简——后续若跨平台零成本。

### 2.2 imekit 的 Windows 实现（`src/windows.rs`）

imekit 在 Windows 上封装了完整的 TSF Composition 操作，**且自带三级回退链**：

```
commit_string(text)
  ├── Path A: 有 active composition
  │     → CommitCompositionSession (ITfComposition::EndComposition)
  ├── Path B: 无 composition
  │     → CommitSession (ITfInsertAtSelection::InsertTextAtSelection)
  └── Fallback: SendInput Unicode  ← 和我们现有实现一样

set_preedit_string(text, cursor_begin, cursor_end)
  ├── TSF: StartPreeditSession / UpdatePreeditSession
  │     (ITfContextComposition::StartComposition + ITfRange::SetText)
  └── Fallback: IMM32 (ImmSetCompositionStringW)
```

**核心机制**：
- `InputMethod::new()` → `CoInitializeEx(STA)` + `CoCreateInstance(CLSID_TF_ThreadMgr)` + `ITfThreadMgr::Activate()`
- `focused_context()` → `ITfThreadMgr::GetFocus()` → `ITfDocumentMgr::GetTop()` → `ITfContext`
- 所有文本修改通过 `ITfEditSession` + `RequestEditSession(TF_ES_SYNC | TF_ES_READWRITE)` 同步执行

imekit 已经把以下 COM 接口的 Rust 实现全部封装好了：
- `CommitSession`（直接在光标处插入文本）
- `StartPreeditSession`（创建组字 + 设置初始文本）
- `UpdatePreeditSession`（更新组字 range 文本）
- `CommitCompositionSession`（替换组字文本 + EndComposition 提交）
- `NullCompositionSink`（`ITfCompositionSink` 空实现）

**这正是我们需要的**——不用自己手写任何 TSF COM 代码。

### 2.3 对比：手写 TIP DLL vs imekit

| 维度 | 手写 TIP DLL（原方案） | imekit |
|---|---|---|
| COM 代码量 | ~500 行（ITfTextInputProcessor + ITfEditSession + IClassFactory + Dll exports） | **0 行**（库内已封装） |
| 独立 DLL | 需要 `blink_tsf.dll`（cdylib crate） | **不需要** |
| COM 注册 | 需要写注册表 CLSID + TIP 配置 | **不需要** |
| 跨进程通信 | 需要 Named Pipe IPC | **不需要**（直接进程内调用） |
| DLL 加载到目标进程 | 是（安全风险） | **否** |
| 注册表残留 | 需要退出清理 | **无** |
| 回退链 | 需自己实现 TSF → SendInput → Clipboard | **内置** TSF → IMM32 → SendInput |
| 包体积 | +DLL ~200KB | +crate 依赖（编译进二进制） |
| 复杂度 | 高 | **低** |

imekit 在所有维度上都优于手写 TIP DLL。

### 2.4 跨进程有效性说明

imekit 的 TSF 路径依赖 `ITfThreadMgr::GetFocus()` 获取前台编辑上下文。Blink 作为外部进程在自己的 STA 线程创建 `ITfThreadMgr`，`GetFocus()` 能否返回前台应用的 `ITfContext` 需要实测验证。

- **如果有效**：TSF Composition 直接在目标应用光标处创建组字 / 插入文本，解决所有 TSF-aware 应用（UWP / Office / Electron / WPF）的上屏问题。
- **如果无效**（GetFocus 返回 None）：imekit 自动回退到 IMM32（`ImmSetCompositionStringW`），再回退到 SendInput——**不会比现在差**，且多了一条 IMM32 路径（在 IME 激活的应用中可能比 SendInput 更可靠）。

> **结论**：接入 imekit 是纯增量改进，最差情况和现在一样（走 SendInput），最好情况完全解决上屏问题（走 TSF/IMM32）。零风险升级。

## 三、方案设计

### 3.1 整体架构

```
VoiceService::stop_recording()
  → finalize() 得到 final_text
  → spawn_blocking（专用 STA 线程）:
      → InjectMethod::Tsf?
          → ImekitInjector::commit_string(final_text)
              ├── imekit TSF Path B: ITfInsertAtSelection  ← 目标
              ├── imekit IMM32 fallback: ImmSetCompositionStringW
              ├── imekit SendInput fallback: KEYEVENTF_UNICODE
              └── Blink 外层兜底: Clipboard + Ctrl+V  ← 最终保险
          → 失败则回退现有 SendInput Unicode → Clipboard
```

### 3.2 线程模型

`ITfThreadMgr` 是 `!Send`/`!Sync`（COM STA 线程亲和），必须在创建它的线程上使用。imekit 的 `InputMethod` 内部持有 `ITfThreadMgr`，因此也不是 `Send`。

Blink 的语音注入当前在 `tokio::task::spawn_blocking` 中执行，但 `spawn_blocking` 不保证固定线程。方案：

**专用 STA 注入线程**：创建一个长期存活的 OS 线程，所有 TSF/imekit 操作通过 channel 发到该线程执行。

```rust
// 伪代码
struct ImekitInjector {
    /// 专用 STA 线程的指令发送端
    tx: std::sync::mpsc::Sender<InjectCommand>,
    /// STA 线程句柄
    handle: Option<std::thread::JoinHandle<()>>,
}

enum InjectCommand {
    Commit { text: String, resp: oneshot::Sender<Result<()>> },
    StartPreedit { text: String, resp: oneshot::Sender<Result<()>> },
    UpdatePreedit { text: String, resp: oneshot::Sender<Result<()>> },
    CommitPreedit { text: String, resp: oneshot::Sender<Result<()>> },
    Abort { resp: oneshot::Sender<Result<()>> },
    Shutdown,
}
```

STA 线程内部：
```rust
fn sta_thread_main(rx: Receiver<InjectCommand>) {
    // 线程启动时初始化 COM STA + imekit
    let mut im = imekit::InputMethod::new().expect("imekit init");

    while let Ok(cmd) = rx.recv() {
        match cmd {
            InjectCommand::Commit { text, resp } => {
                let r = im.commit_string(&text);
                let _ = resp.send(r);
            }
            InjectCommand::StartPreedit { text, resp } => {
                let r = im.set_preedit_string(&text, 0, 0);
                let _ = resp.send(r);
            }
            // ... 其他命令
            InjectCommand::Shutdown => break,
        }
    }
    // 线程退出时 COM 自动 CoUninitialize
}
```

### 3.3 接口设计

```rust
// src/infra/platform/inject/imekit_impl.rs

/// imekit TSF 注入器。
///
/// 封装专用 STA 线程 + imekit InputMethod 实例。
/// 所有方法阻塞等待 STA 线程执行完毕（同步语义，调用方在 spawn_blocking 中）。
pub struct ImekitInjector {
    tx: std::sync::mpsc::Sender<InjectCommand>,
    handle: Mutex<Option<std::thread::JoinHandle<()>>>,
}

impl ImekitInjector {
    /// 懒初始化（首次 TSF 注入时创建 STA 线程）。
    /// 全局单例（OnceLock），进程生命周期内复用。
    pub fn instance() -> &'static ImekitInjector;

    /// Phase 1：一次性注入文本。
    /// 走 imekit commit_string（TSF → IMM32 → SendInput），
    /// 失败时由外层 inject_text_with_method 回退到 Clipboard。
    pub fn commit_string(&self, text: &str) -> Result<(), InjectError>;

    /// Phase 2：开始组字会话（创建空 composition + 设置初始文本）。
    pub fn start_preedit(&self, text: &str) -> Result<(), InjectError>;

    /// Phase 2：更新组字文本（流式预览）。
    pub fn update_preedit(&self, text: &str) -> Result<(), InjectError>;

    /// Phase 2：提交组字（替换为最终文本 + EndComposition）。
    pub fn commit_preedit(&self, final_text: &str) -> Result<(), InjectError>;

    /// Phase 2：取消组字（EndComposition 不提交）。
    pub fn abort_preedit(&self) -> Result<(), InjectError>;
}
```

### 3.4 注入路由与回退链

```rust
// src/infra/platform/inject/mod.rs

pub fn inject_text_with_method(text: &str, method: InjectMethod) -> Result<(), InjectError> {
    match method {
        InjectMethod::Tsf => {
            // imekit 内部已有 TSF → IMM32 → SendInput 三级回退
            match imekit_impl::ImekitInjector::instance().commit_string(text) {
                Ok(()) => Ok(()),
                Err(e) => {
                    tracing::warn!(%e, "imekit TSF 注入失败，回退 Clipboard+Ctrl+V");
                    windows_impl::inject_text_clipboard(text)
                }
            }
        }
        InjectMethod::SendInput => { /* 现有 */ }
        InjectMethod::Clipboard => { /* 现有 */ }
    }
}
```

完整回退链：
```
InjectMethod::Tsf
  → imekit commit_string
      → TSF ITfInsertAtSelection        ← 目标（解决 UWP/Office/Electron）
      → IMM32 ImmSetCompositionStringW   ← 回退 1（IME 激活的应用）
      → SendInput Unicode                ← 回退 2（和现有一样）
  → Clipboard + Ctrl+V                   ← 外层最终兜底
```

### 3.5 配置

`InjectMethod` 枚举已预留 `Tsf` 变体（0.10.3），无需新增字段。设置页增加 TSF 选项：

```html
<select id="voice-inject-method-select">
  <option value="tsf">TSF Composition（推荐，兼容性最好）</option>
  <option value="sendinput" selected>SendInput Unicode</option>
  <option value="clipboard">Clipboard + Ctrl+V</option>
</select>
```

默认仍为 `SendInput`，TSF 作为可选启用（验证稳定后改默认）。

### 3.6 依赖

```toml
# Cargo.toml
[dependencies]
imekit = "0.2"
```

imekit 0.2.3 依赖 `windows = "0.59"`（自带 `Win32_UI_TextServices` / `Win32_UI_Input_Ime` features），与 Blink 的 `windows = "0.62.2"` 可共存——两者是不同版本的独立依赖，互不影响。Blink 只调 imekit 公开 API，不直接使用 TSF COM 类型，因此 Blink 自己的 windows features 不需要改动。

> imekit 是纯 Rust（无 C 依赖），编译进二进制，无额外打包步骤。


### Phase 2（0.10.6）：流式组字更新

**目标**：伪流式预览期间，组字文字在应用文本框中原位更新，替代 overlay 浮层。

| 任务 | 说明 |
|---|---|
| `start_preedit` / `update_preedit` / `commit_preedit` / `abort_preedit` | 封装 imekit set_preedit_string + commit_string 组合 |
| VoiceService 管线改造 | `transcribe_chunk` 返回 partial 时，调用 update_preedit |
| overlay 策略调整 | TSF 模式下不显示 overlay（文字已在文本框中）；非 TSF 模式仍用 overlay |
| 生命周期管理 | start → update × N → commit/abort，cancel_recording 时 abort |

**注入流程（Phase 2）**：

```
VoiceService::start_recording()
  → ImekitInjector::start_preedit("")  ← 创建空组字

VoiceService::transcribe_chunk()
  → partial 文本
  → ImekitInjector::update_preedit(partial)  ← 异步更新组字

VoiceService::stop_recording()
  → finalize() 得到 final_text
  → ImekitInjector::commit_preedit(final_text)  ← 替换组字并提交

VoiceService::cancel_recording()
  → ImekitInjector::abort_preedit()  ← EndComposition 不提交
```

## 五、风险与缓解

| 风险 | 影响 | 缓解策略 |
|---|---|---|
| 跨进程 `GetFocus` 返回 None | TSF 路径不生效 | imekit 自动回退 IMM32 → SendInput，不比现在差 |
| imekit 0.2.x 不够稳定 | 偶发 panic | 外层 catch_unwind + 回退 SendInput；持续关注上游更新 |
| windows crate 版本冲突 | 编译失败 | 锁定兼容版本，必要时 fork imekit 对齐版本 |
| STA 线程阻塞 | 注入延迟 | 同步调用 + 超时保护（3s），超时回退 SendInput |
| IME 冲突（用户当前输入法） | 组字状态混乱 | 注入前不主动切换 TIP；imekit 不注册 TIP，直接操作上下文 |
| 管理员权限应用 | TSF 无法注入 elevated 进程 | 检测目标进程权限，elevated 时直接走 SendInput |

### P0 不回归保证

| 新增物 | 威胁 | 保证 |
|---|---|---|
| imekit crate 依赖 | 编译时间 / 包体积 | 纯 Rust 无 C 依赖，体积增量小（<100KB） |
| 专用 STA 线程 | 线程泄漏 | 全局单例 + Shutdown 命令，Blink 退出时 join |
| COM STA 初始化 | 线程模型冲突 | 独立线程，不与 Tauri 主线程 / tokio 线程交叉 |
