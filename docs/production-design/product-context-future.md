## 7. Context 层与主动建议

### 7.1 环境感知(CurrentUser Context)

**定位**:系统级"环境感知层"。让 Blink 从被动启动器(输入→执行)升级为智能操作入口(自动感知上下文→智能动作)。

**感知维度与实现状态**:

| 维度 | 含义 | 采集方式(Windows) | 实现状态 |
|---|---|---|---|
| 前台应用 | 用户当前在哪个应用 | `GetForegroundWindow` + 进程名 | ✅ 0.4 |
| 选中文本 | 用户选中了什么 | UI Automation(UIA) + 鼠标钩子 | ✅ 0.8 |
| 剪贴板 | 最近复制内容 | Clipboard API + SQLite 持久化 | ✅ 0.7 |
| 活跃上下文 | 当前页面 URL / 编辑器文件 | 浏览器扩展 / 编辑器插件 | ⬜ 远期 |
| 系统状态 | 时间、网络、电源等 | 系统 API | ⬜ 远期 |

**设计要点**:
- 低频采集 + 按需快照:唤起时取快照，不每次按键采集
- 敏感内容不持久化(不入 SQLite)，仅驻留内存
- 敏感应用(银行、密码管理器)默认关闭感知

来源:MVP §13.7

### 7.1.1 选中文本感知(UIA 划词，0.8)

**问题**:复制了代码/英文后还得手动输入「翻译/解释」；90% 的用户在选中文本后下一步就是操作它。

**方案**:全局监听选词动作，在用户**按下 Alt 之前**就把选中文本抓下来。

**实现路径演进**:
1. ❌ invoke 后抓取 → 失败：Blit 抢焦点后原应用选区丢失(UIA GetSelection 为空)
2. ✅ **选词瞬间抓取**(最终方案):全局鼠标钩子监听 `左键 up`，在选词发生的黄金时机抓取

**抓取策略(分层兜底)**:
| 层 | 技术 | 覆盖率 | 说明 |
|---|---|---|---|
| L1 | UIA TextPattern | 高 | 记事本/Office/VS Code/Chrome 网页/Edge，实测覆盖 80%+ 场景 |
| L2 | 控件特化消息 | 中 | Scintilla `SCI_GETSELTEXT`(救 Notepad++)，0.8 后续可补 |
| L3 | Java Access Bridge | 低 | 救 IntelliJ，远期 |

**缓存与隐私**:
- 选中文本仅存内存 `OnceLock<RwLock>`，TTL 10 秒，不入 SQLite
- 成功只记长度不记内容(debug 级)，完整内容仅 trace 级记前 100 字符
- 敏感应用黑名单生效时，抓取直接跳过

**与剪贴板的配合**:
- 划词未复制 → UIA 抓取走 ContextSnapshot.selected_text
- 已复制 → clipboard_text 走剪贴板历史
- 两条链路并行，无需自动 Ctrl+C(避免污染剪贴板历史)

**下一步(0.8+)**:Context 感知路由 — 选中英文→翻译插件置顶，选中路径→打开目录动作置顶

来源:0.8-ai-intent-router.md §1.1

### 7.2 主动建议(Proactive Suggestion)

**目标**:基于 Context 快照预测用户下一步，**直接把动作推到面前**，零输入即可执行。

| Context 快照 | 主动建议动作 |
|---|---|
| 选中英文文本 + 浏览器在前台 | 翻译 / 总结 |
| 选中代码 | 解释 / 重构 / 查文档 |
| 剪贴板是报错日志 | 分析原因 / 搜解决方案 |
| 终端前台且输入框空 | 最近命令 / 补全 |
| 复制了文件路径 | 打开 / 在资源管理器定位 |

**设计要点**:
- 唤起时由 ContextService + IntentService 联合产出"Top-N 建议"，作为结果的零号位
- 建议来源可配置、可学习(基于历史采纳率调整)
- **默认克制，避免打扰**
- 敏感 context 字段参与本地规则建议，发云需开关

来源:MVP §13.8

---

### 7.3 主动建议的雏形:空 query 历史常用

0.4.2 可选:空 query 显示历史 top-N(按使用频率)。这是 Proactive Suggestion 的低成本雏形——不需要 Context 层，只依赖历史权重。来源:0.2 §7 A1

## 8. 隐私与安全

### 8.1 默认全本地

- 选中文本 / URL 等敏感字段**绝不默认发往云端**
- 发 AI 前需用户开关 + 脱敏
- 敏感内容仅驻留内存，不入 SQLite

来源:MVP §13.7

---

### 8.2 代码签名

- 开发期可忽略(但需预判杀软误报)
- 分发前必须代码签名(OV/EV)，否则 SmartScreen 拦截 + 杀软误报对常驻+全局热键应用是致命的

来源:MVP §13.3
