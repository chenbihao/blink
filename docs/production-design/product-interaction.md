## 1. 产品定位

### 1.1 Universal Action Layer(统一操作层)

Blink 不是「启动器(launcher)」,而是**Universal Action Layer**——感知用户上下文、主动推荐动作,让任何操作都比原来的路径更快。搜索只是入口之一,动作执行才是终点。

### 1.2 核心原则

| 原则 | 含义 | 来源 |
|---|---|---|
| **任何操作都比原来快** | 唤起 → 输入 → 执行,全程<1秒,比鼠标/菜单快 | MVP §1.1 |
| **最小操作路径(更快 · 更丝滑 · 更智能)** | 每个新功能加入前先答"这条路径变短了吗"——**优先更快 → 再更丝滑 → 最后更智能**;弱意图信号 pull 不 push,永远保留 escape hatch | [product-principles §13](./product-principles.md#13-最小操作路径横切设计准则) |
| **可辨识度优先** | UI 是功能面不是装饰面;中文不用斜体,主题走对比度过 AA 底线,弱信号不撑布局 | [product-principles §14](./product-principles.md#14-可辨识度与视觉一致性横切设计准则) |
| **P0 至上** | 如果用户按快捷键后不能立即输入,其他所有功能都没有意义 | MVP §11 |
| **MVP 验证基础交互,而非功能数量** | 0.1 只验证「右 Alt → 窗口 → Focus → 输入 → ESC 隐藏」这条链路;AI/Agent/工作流不做 | MVP §11 |
| **配置化优先** | 可选行为(默认值用户可能想改的)做成配置项 + 合理默认,纯内部参数不暴露 | 0.2 §6 / CLAUDE.md §7 |

### 1.3 技术-产品边界

- **后端 Rust + 前端纯静态 HTML/CSS/JS**:技术栈服务于"零构建步骤",降低维护成本
- **无 npm / 无 bundler**:前端薄到只剩渲染层,业务逻辑全在 Rust——产品要求 UI 尽量薄

## 2. 核心交互体验

### 2.1 唤起方式:右 Alt 单击(tap)

**决策**:默认唤起键 = **右 Alt 单击**(`tap`, 不是双击/长按)。

| 为什么 | 细节 |
|---|---|
| **不吞键** | hook 回调全程 `CallNextHookEx` 放行,右 Alt 仍可作系统修饰键。做得差的产品在 keydown 就吞掉右 Alt(独占式) |
| **tap/hold 区分** | keydown 记录时刻,keyup 时若期间无其他键且时长≤阈值 → tap(唤起);否则 hold(系统组合键正常放行) |
| **提前预热** | keydown 即异步预热窗口(加载/置顶),keyup 确认 tap 后立即 focus + 显示,唤起延迟压到接近 0 |

**来源**:MVP §13.1, CLAUDE.md §5

### 2.2 焦点与失焦

| 问题 | 方案 | 来源 |
|---|---|---|
| 某些窗口(IDEA 终端子进程)不发失焦通知 | 看门狗每 150ms 轮询 `GetForegroundWindow()`,按**进程 PID**判定前台是否属自己(非死比单个 HWND) | MVP §13.1, 0.3 §三 |
| 焦点真空(子进程拉起等瞬态) | `fg == NULL` 跳过本轮不隐藏,避免误隐藏 | 0.3 §三 |
| 唤起后焦点抖动 | invoke 后设 grace period(500ms),覆盖焦点切换的瞬态 | 0.1-base |

### 2.3 输入法

**IME 必须支持**:唤起时输入法状态必须就绪,用户直接敲中文。已验证微软拼音/搜狗/微信输入法。唤起后自动 focus 输入框,IME 跟随。这是 P0 的硬要求——不支持中文输入法的 launcher 对中国用户不可用。

### 2.4 Chord 模式:按住修饰键+二次快捷键(0.8.1)

**定位**:从「被动搜索入口」到「主动动作触发器」的交互跃迁。让 Blink 不只是"按 Alt 搜东西",而是"按住 Alt 直接做事"。

**交互流程**:
```
用户按住 Alt(不松开)
     ↓
┌─────────────────────┐
│  Blink 窗口出现        │
│  提示:按住 Alt + ...  │
└─────────────────────┘
     ↓     ↓     ↓
  +A     +Q     +C...
  截图   划词   剪贴板
```

**核心设计原则**:

| 原则 | 说明 |
|---|---|
| **向后兼容** | 快速单击 Alt(< tap_threshold)=原有行为:唤起窗口,焦点到输入框。用户肌肉记忆不受影响。 |
| **渐进揭示** | 长按 Alt(> chord_threshold,默认 200ms)才进入 Chord 模式,窗口底部显示可用快捷键提示 |
| **无感降级** | 长按后松开且未按二次键→自动退化为正常搜索模式,焦点到输入框 |
| **肌肉记忆** | 按住 Alt 的同时按 A/Q/C,手指不需要离开主键区 |

**第一批 Chord 动作**:

| 组合键 | 动作 | 说明 |
|---|---|---|
| `Alt + A` | 区域截图 | 进入截图模式,拖动选择区域→自动复制到剪贴板 |
| `Alt + Q` | 智能划词 | 主动触发 UIA 划词抓取(比被动监听更可靠)+翻译/搜索动作弹出 |
| `Alt + C` | 剪贴板历史 | 直接打开剪贴板历史面板(跳过搜索) |
| `Alt + Space` | 语音输入 | 预留(按住期间语音识别,松开结束) |

**产品价值**:
- **跳过搜索步骤**:常用动作直接触发,不需要输入关键词
- **差异化竞争**:Wox/Listary/Flow Launcher 都没有这个交互模式
- **扩展性极强**:后续所有高频动作都可以接入 Chord(翻译/词典/计算等)

来源:0.8 规划,Quicker 交互灵感

## 3. 搜索体验

### 3.1 渐进式多路搜索(sync/async 双 lane)

**决策**:搜索分两条 lane,不是 `join_all` 等全部引擎:

| lane | 引擎 | 行为 |
|---|---|---|
| **Sync(紧 budget≈16ms)** | CalcEngine, StartMenuEngine | 同步返回首批,用户立即看到结果 |
| **Async(不阻塞)** | PluginEngine 等 | 完成后 `emit("blink://results")` 增量推送,前端 merge |

**理由**:插件/网络查询可能超时,不能拖垮整次搜索。"首个结果 <20ms" 是 P1 硬指标。来源:0.2 §2.3

### 3.2 搜索匹配策略

| 策略 | 实现 | 来源 |
|---|---|---|
| **fuzzy 子串** | nucleo 匹配原名 + 拼音首字母,取最高分 | CLAUDE.md §5 |
| **历史加权** | `ln(hit+1)*100` 频率加权,常用应用排前面 | CLAUDE.md §5 |
| **空 query 显示历史常用** | 未实现(0.4.2 可选),是 Proactive Suggestion 雏形 | 0.2 §7 A1 |

### 3.3 计算结果

- **本地计算**,不经过 AI(`1+1` → `2`)
- 整数转浮点避免截断
- 回车自动复制到剪贴板

### 3.4 右键上下文菜单（0.5.3）

**问题**:主窗口右键现为 WebView2/Edge 原生浏览器菜单(刷新、另存为、打印、检查、
表情符号、书写方向等),与「快捷入口」定位割裂,毫无产品感。

**决策**:抑制原生菜单,全自定义右键,**按区域 + 按结果类型**提供差异化动作。
来源:0.4 收尾时提出,0.5.3 落地。

#### 3.4.1 技术前提:抑制原生菜单

- **前端拦截**:`contextmenu` 事件 `preventDefault()` + 自定义 DOM 菜单(推荐——
  灵活、可按区域分别定制)。
- ~~WebView2 `AreDefaultContextMenuEnabled=false`~~:备选,但会连输入框拼写菜单一起禁掉,
  灵活性差,不采用。
- **「原生菜单」展开入口不实现**:一旦抑制原生菜单,无官方 API 再唤起;全自定义已覆盖
  需求,放弃此项。

#### 3.4.2 分区域菜单

| 区域 | 菜单内容 |
|---|---|
| 输入框 | 粘贴 / 剪切 / 复制 / 全选(输入场景最小集) |
| 列表空白处 / 卡片留白 | 打开设置 / 刷新索引 / 重新探测 Everything(0.5) / 退出 |
| 结果项 | 按 source 类型动态(见 3.4.3) |

#### 3.4.3 结果项按类型动作

| source | 动作 |
|---|---|
| **file**(文件搜索) | 打开 / 打开所在文件夹 / 复制路径 / 复制文件名 / 重置该项记录 / 优先级置底 |
| **app**(开始菜单应用) | 打开 / 打开所在文件夹 / 复制路径 / 以管理员运行 / 重置该项记录 / 优先级置底 |
| **calc**(计算结果) | 复制结果 / 复制完整表达式 |
| **plugin**(插件结果) | 由 manifest 声明的 actions 透传(复用 0.4 surface 模型) |

#### 3.4.4 历史权重操作(核心痛点驱动)

当前 history `ln(hit+1)*100` 频率加权,被误点几次的应用会长期霸占顶部,用户无清除手段。
右键菜单首次提供手动干预能力:

- **重置该项记录**:`hit_count` 归零 / 删除该 history 行。轻量,复用现有表,0.5.3 即做。
- **优先级置底**:**需新数据结构**(降权标记 / 负权重 / 黑名单表),非简单清历史。
  重置只回到初始分,其他高频项仍可能压不过来;真正置底要持久降权。
  ⚠️ 待决策:建议拆到 0.5.x 进阶,0.5.3 先做「重置记录」。

#### 3.4.5 后端命令需求

- `open_containing_folder(path)`:`explorer.exe /select,<path>`(新增)。
- `reset_item_history(lnk_path)`:history 表清零/删除(新增 history 方法)。
- 复制路径/文件名:前端 `navigator.clipboard`,不必后端。

### 3.5 下拉项数量自适应屏幕高度（0.5.x）

**问题**:`window-size.js` 测 `#app` 真实高度后直接 resize,**完全不看屏幕高度**;
`clamp_to_work_area`(windows.rs) 只是事后补救——底部溢出时整体上移,但 `new_y.max(work.top)`
只保证**顶部不越界**。当窗口本身高于屏幕可用区(小屏展开满页)时,上移后**底部仍溢出**,
clamp 失效 → 结果被截断在屏幕外。

**决策**:反过来——**按唤起所在显示器的可用垂直空间,动态计算每页容量**,
而不是无脑 resize 再挪窗口。

| 屏幕 | 每页条数 |
|---|---|
| 大屏(可用高度充足) | 9(满页,对齐 Alt+1~9) |
| 中屏 | 8 / 6 |
| 小屏(可用高度紧张) | 4(下限) |

**实现要点**:
- 后端 `GetMonitorInfoW` 取唤起显示器**工作区**(`rcWork`,已排除任务栏),
  可用高度 = `work.bottom - work.top`。
- 可用条数 = `(可用高度 - 固定开销) / 单项高度`,向下取整,clamp 到 `[4, 9]`。
  固定开销 = 输入框 + 内外边距 + statusbar;单项高度由 CSS 决定。
- 唤起时算一次(显示器/缩放变化时重算),随 `blink://shown` 事件下发给前端。
- 前端 `PAGE_SIZE` 由模块常量改为**运行时可变量**(results.js),接收后端容量。
- clamp 下限 4:保证最少可见行数;上限 9:对齐 Alt 数字快捷键语义。
- 与 `clamp_to_work_area` 互补:自适应控"显示几项",clamp 兜底"窗口别出屏"(自适应后极少触发)。

**来源**:0.5 整理时发现的小屏溢出 bug。

## 9. i18n 与本地化

### 9.1 最小化但架构留口子

- **UI 文案**:MVP 中文硬编码,但统一走 i18n key(后端 `fluent`/前端 i18n 库),后期补英文
- **Intent 触发关键词**:必须支持多语言(中文用户期望 `翻译`/`查IP`,英文用户期望 `translate`/`ip`),规则表按语言配置
- **本地化格式**:日期/数字/计算结果按 locale 格式化

来源:MVP §13.4
